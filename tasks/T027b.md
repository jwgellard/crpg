# T027b — N-INTEREST projection machinery (`crpg-net`)

## Task / Crate(s) / Purpose

Sole crate: `crpg-net`, Phase 4. **D14 selected; T027a's approved facts or
sufficiency proof, T021/T024 and exact projection API remain.** Produce whole-area/perceived-component
filtered views; explicit filtering existed in T018, production interest did not.

## Interface

Append approved public `InterestSet`/projection-context input, field-mask types,
mapping lifecycle, per-peer view/cursor and delta/snapshot projection functions
with exact errors/counts/order. Context is supplied by the authoritative host;
no net ownership/LOS oracle is fabricated. Raw complete World serialization is
never a projection interface. Reuse versioned T021/T024 facts; new facts/fields
require their own reviewed protocol version before implementation.

## Behaviour

Generate enter plus permitted initial state before any reference, leave when
interest/permission revokes, retire ids for the epoch and revoke actionable
mapping before a subsequent request. Hidden spawns consume no visible id or
sequence; disclosable despawns use approved notice, otherwise cause-neutral
leave. Death remains distinct from despawn. Omit undisclosed fields, never
zero-fill them or leak them through cached receipts/counts/sequences.

Per-field changes and snapshot replacement use a coherent viewer context at
the approved cutover. Store only bounded view/mapping/retired-id metadata;
define exhaustion→resync/new epoch in D14 without id reuse. Apply B5 hard maxima
and tightening-only policy. Phase 4 whole-area interest does not authorize
within-area AOI indexing.

## Constraints

[Standing rules](POST-T018-RULES.md) apply; net only. No gameplay legality,
host credentials, new sim facts, net→rules/script dependencies or implicit
testkit integration. T018 tables remain test fixtures, not runtime perception.

### Decision

- **D1. New module `interest`; output is ops, not frames.** `InterestView`
  returns `protocol::DeltaOp` lists and T024 `SnapshotBody` values. The host
  keeps frames, chunking, `server_tick` and `event_seq`, because the same
  sequence numbers receipts and history
  (`crates/crpg-net/src/projection_v2.rs:34-37`,
  `crates/crpg-server/src/host.rs:1330`). Rejected: net-owned frames and
  `event_seq`.
- **D2. Identity is `(area, full EntityId)`.** Two areas can mint equal ids,
  and T027a says mapping scopes by both (`tasks/T027a.md:141-143`). Keying on
  `EntityId` alone would hand a viewer who changes area the old `NetId` for a
  different entity, with no leave and no enter. Rejected: `EntityId` keys.
- **D3. Net applies D14's same-area rule; the host supplies every value.** A
  fact is visible when its area equals the viewer's area and its presence grant
  is set. A foreign row is suppressed, not an error, so a host mistake fails
  closed and the two-area test is real. Rejected: `AreaMismatch` as an error,
  and a net `visible_to` oracle (`tasks/T027b.md:13`). One view is one viewer in
  one area; single viewer means constructing one view, with no extra type.
- **D4. Disclosure needs a value and a grant.** `FieldMask::default()` denies
  everything, so an unknown field or entity is absent
  (`tasks/POST-T018-DECISIONS.md:332`). Masks are per row because the host's
  grants are per entity (`crates/crpg-server/src/host.rs:140`). Plain `bool`
  fields, not bits: nothing here reaches the wire, so `from_bits` and `union`
  would be dead API. No `action_result` bit: action results stay per-field on
  `EventCandidate` and no state op carries one.
- **D5. Each op has exactly one owner.**

  | Op | Owner |
  |---|---|
  | `EntityEnter`, `Health`, `Turn`, `EntityLeave`, `Despawned` | `InterestView` |
  | `Spawned`, `Died`, `ActionResolved`, `TurnStarted`, `EncounterEnded` | `project_events`, ids from `net_id` |
  | `Receipt` | host |

  `Spawned` and `Died` stay in history because their journal position is pinned
  (`crates/crpg-server/tests/host_capture.rs:1168`, `:1524`: `Died` between
  `ActionResolved` and `EncounterEnded`/`TurnStarted`). `Despawned` belongs to
  the view because a removal must be exactly one op: leave or notice, never
  both. Rejected: the view emitting all three notices, which reorders V2
  journals and breaks those tests.
- **D6. A page has a fixed layout and a history slot.** Enters come first, so
  history can name them. Removals come last, so history can still name what is
  leaving. `StateProjection::enters` marks the slot. Rejected: removals first.
- **D7. Retirement is derived, not stored.** Ids are minted monotonically and
  only when disclosed, so an id is retired exactly when it is below `next_id`
  and not live. There is no grave table to bound or to overflow. Rejected:
  capped graves, which force a resync after 1,024 ordinary leaves.
- **D8. `project_snapshot` is the only replacement primitive.** Narrowing,
  `Resync` and resume all replace state through it. Rejected: `revoke`,
  `revoke_all`, `reseed` and a grant generation: a mapping change with no op
  and no snapshot desynchronises the client, and no row could carry the
  generation.
- **D9. Turn enters by key and leaves by `NetId`.** The active actor may be
  entering in this same page, so the host cannot know its id. A hidden active
  actor renders `active: None`, matching the host and its pinned oracle
  (`crates/crpg-server/src/host.rs:2421`,
  `crates/crpg-server/tests/host_capture.rs:472`). Rejected: omitting the whole
  op (client keeps a stale actor) and a "view must be non-empty" guard, which
  only the T018 test fixture has.
- **D10. `ViewCursor` is view state, never wire.** `revision` orders
  projections within one tick; `tick` is the context tick. T024's
  `BeginTransfer.cursor` stays the host's last issued `event_seq`
  (`crates/crpg-server/src/host.rs:1559`). Rejected: reusing `event_seq`, and a
  tick-regression error (area clocks need not match, `tasks/T027a.md`,
  "Source/destination clocks need not match").
- **D11. No limits parameter.** Caps are `MAX_VISIBLE_ENTITIES` and one derived
  constant. A host-supplied limit would be a loosening path
  (`tasks/T027b.md:29`). Host tightening stays in the host.
- **D12. T027c can adopt this without editing a T022 test.** The layout,
  ordering and id minting reproduce the host's `plan_map`, `full_state_ops`,
  `widening_ops` and `snapshot_body` exactly. T022 frames resend unchanged
  `Health` and `Turn` for a command's involved entities
  (`crates/crpg-server/tests/host_capture.rs:1170-1172`), so a change-only diff
  alone would break them. Two one-page `resend` flags cover it. No existing
  test may be weakened, so this is a requirement, not a convenience.

### Interface (`crates/crpg-net/src/interest.rs`)

```rust
use core::fmt;
use std::collections::BTreeMap;

use crpg_core::{EntityId, Ulid};

use crate::protocol::{DeltaOp, NetId, SessionEpoch, MAX_VISIBLE_ENTITIES};
use crate::protocol_transfer::{HealthFact, SnapshotBody, SnapshotEntity, TurnFact};

/// Largest `ops` length of one `project_delta` result:
/// 1024 enters + 1024 `Health` + 1 `Turn` + 1024 removals.
pub const MAX_PAGE_OPS: usize = 3 * MAX_VISIBLE_ENTITIES + 1;

/// Runtime identity of one entity. Order: area, then `EntityId`.
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
pub struct EntityKey {
    pub area: Ulid,
    pub entity: EntityId,
}

/// Tier-1 interest: exactly one area.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct InterestSet {
    pub area: Ulid,
}

/// Per-row grants. `Default` denies everything.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub struct FieldMask {
    pub presence: bool,
    pub health: bool,
}

/// One authoritative row for one viewer.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct EntityFact {
    pub key: EntityKey,
    pub fields: FieldMask,
    /// The value; disclosure still needs `fields.health`.
    pub health: Option<HealthFact>,
    /// This page only: emit `Health` even if unchanged.
    pub resend_health: bool,
}

/// The encounter's turn fact in authority terms.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct TurnState {
    /// The area whose encounter this is.
    pub area: Ulid,
    pub active: Option<EntityId>,
    pub round: u64,
}

/// One coherent viewer context for one call. Field order is contract.
#[derive(Debug, Clone, Copy)]
pub struct ViewerContext<'a> {
    pub epoch: SessionEpoch,
    /// The authoritative tick this context reflects.
    pub tick: u64,
    pub interest: InterestSet,
    /// At most `MAX_VISIBLE_ENTITIES`; order does not matter.
    pub facts: &'a [EntityFact],
    /// Keys whose removal this page may read as `Despawned`. At most
    /// `MAX_VISIBLE_ENTITIES`; order and repeats do not matter.
    pub despawned: &'a [EntityKey],
    pub turn: Option<TurnState>,
    pub turn_granted: bool,
    /// This page only: emit `Turn` even if unchanged.
    pub resend_turn: bool,
}

/// View position. Not wire and not `event_seq`.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub struct ViewCursor {
    pub tick: u64,
    pub revision: u64,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct StateProjection {
    /// At most `MAX_PAGE_OPS`, in the Behaviour item 5 layout.
    pub ops: Vec<DeltaOp>,
    /// `ops[..enters]` are the `EntityEnter`s; history goes at this index.
    pub enters: usize,
    pub cursor: ViewCursor,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct SnapshotProjection {
    pub body: SnapshotBody,
    pub cursor: ViewCursor,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum InterestError {
    /// `context.epoch` is not this view's epoch.
    WrongEpoch,
    /// `facts` or `despawned` is longer than `MAX_VISIBLE_ENTITIES`.
    TooManyFacts,
    /// Two rows of `facts` share one `EntityKey`.
    DuplicateFact,
    /// The epoch's `NetId` space cannot cover this call's entering keys.
    IdExhausted,
}
// Display: "<Variant> at projection/interest", no payload.
impl fmt::Display for InterestError { /* ... */ }
impl std::error::Error for InterestError {}

/// Per-peer mapping, remembered image and cursor. Not `Serialize`: a saved
/// view would restore stale authorization (`tasks/T027c.md:23`).
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct InterestView {
    epoch: SessionEpoch,
    next_id: u64,                              // 1 at `new`
    live: BTreeMap<EntityKey, LiveEntry>,
    index: BTreeMap<NetId, EntityKey>,
    last_turn: Option<TurnFact>,               // last rendered, else None
    cursor: ViewCursor,                        // default at `new`
}

#[derive(Debug, Clone, PartialEq, Eq)]
struct LiveEntry {
    net: NetId,
    last_health: Option<HealthFact>,           // last rendered, else None
}

impl InterestView {
    pub fn new(epoch: SessionEpoch) -> Self;
    pub fn epoch(&self) -> SessionEpoch;
    pub fn cursor(&self) -> ViewCursor;
    pub fn len(&self) -> usize;                // live mappings
    pub fn is_empty(&self) -> bool;
    pub fn net_id(&self, key: EntityKey) -> Option<NetId>;
    pub fn entity(&self, net: NetId) -> Option<EntityKey>;
    pub fn project_delta(&mut self, context: &ViewerContext<'_>)
        -> Result<StateProjection, InterestError>;
    pub fn project_snapshot(&mut self, context: &ViewerContext<'_>)
        -> Result<SnapshotProjection, InterestError>;
}
```

`src/lib.rs` gains `pub mod interest;` after `codec_v2` and one crate-doc
sentence. Every public item is documented (`#![warn(missing_docs)]`).
`HealthFact` and `TurnFact` are reused unchanged. No other existing item
changes.

Terms used below, for one call with context `c`:

- **Visible:** `f.key.area == c.interest.area && f.fields.presence`.
- **Rendered health** of a visible `f`: `f.health` when `f.fields.health`,
  otherwise `None`.
- **Rendered turn:** `Some(TurnFact { active, round })` when `c.turn_granted`,
  `c.turn == Some(t)` and `t.area == c.interest.area`, otherwise `None`.
  `active` is the post-minting `NetId` of `EntityKey { area: t.area, entity }`
  when that key is visible, otherwise `None`.
- **Entering:** a visible key not in `live`. **Removed:** a `live` key not
  visible.

### Behaviour

1. **Precedence.** Both functions check, in order, before any mutation:
   (a) `c.epoch != self.epoch` is `WrongEpoch`; (b) `facts` or `despawned`
   longer than `MAX_VISIBLE_ENTITIES` is `TooManyFacts`; (c) two rows with one
   key, among all rows whether visible or not, is `DuplicateFact`; (d) more
   entering keys than `u64::MAX - next_id` is `IdExhausted`.
2. **Atomicity.** `Err` changes nothing. `Ok` commits mapping, remembered image
   and cursor together. Neither function panics on any input.
3. **Input order never matters.** Equal row sets give equal results.
4. **Minting.** Entering keys take `next_id` upward in ascending `EntityKey`
   order, once each. `NetId`s run `1..=u64::MAX - 1`
   (`crates/crpg-server/src/host.rs:2214`).
5. **Delta layout.** `project_delta` returns, in order, every section ascending
   `NetId`:
   1. one `EntityEnter` per entering key (`enters` is this count);
   2. `Health` per item 6;
   3. at most one `Turn` per item 7;
   4. one removal op per removed key per item 8.

   It never returns `Spawned`, `Died` or `Receipt`.
6. **Health.** For each visible key, including entering keys: emit `Health`
   when rendered health is `Some` and either differs from `last_health` or the
   row has `resend_health`. Then `last_health` becomes rendered health, so a
   later grant emits the current value even if unchanged. `resend_health` never
   overrides a missing grant or value. A cleared grant emits nothing and
   retracts nothing (ADR-0022 item 2).
7. **Turn.** Emit `Turn` when rendered turn is `Some` and either differs from
   `last_turn` or `resend_turn` is set. Then `last_turn` becomes rendered turn.
   A turn that stops rendering emits nothing. `Turn` precedes removals and
   never names a removed key.
8. **Removal.** A removed key listed in `c.despawned` emits `Despawned`; every
   other removed key emits `EntityLeave`. The op carries no cause: a leave from
   a hidden despawn, an area move and a revoked grant are identical. A listed
   key that is visible, or not live, has no effect.
9. **Retirement.** On return a removed key's mapping is gone: `net_id` and
   `entity` report `None`, for that key and that id, before any later request.
   `entity` reports `None` alike for a retired, hidden, foreign and
   never-issued id. A re-entering key gets a new `NetId`; no id is reissued in
   the view.
10. **Hidden consumes nothing.** An invisible row that is not live allocates no
    id and has no effect on `ops`, `next_id`, `len` or `cursor`. Its `health`
    and `resend_health` are never read. Results differ only through visible
    keys, removed keys and the rendered turn.
11. **Death is not removal.** `HealthFact::dead` never removes or hides a key.
    A dead visible key stays mapped. `dead` travels with the `health` grant,
    because `Health` has no form without it; the `Died` notice stays a separate
    history decision.
12. **Snapshot.** `project_snapshot` applies items 1, 3, 4 and 9, then returns
    `SnapshotBody` with one `SnapshotEntity` per visible key, ascending
    `NetId`, `health` equal to rendered health, and `turn` equal to rendered
    turn. Live visible keys keep their ids. Removed keys retire with no op: the
    body replaces the client's whole view. `despawned`, `resend_health` and
    `resend_turn` are ignored. Every result passes `codec_transfer::encode_body`
    and `plan_transfer`: at most 1,024 entities in ascending order, an `active`
    always inside the body, and at most `MAX_ENCODED_BODY_BYTES`.
13. **Cutover.** A snapshot sets `last_health` and `last_turn` to exactly what
    the body says. The next `project_delta` emits only differences from the
    body, whether or not earlier pages were delivered.
14. **Cursor.** `project_delta` with non-empty `ops`, and every successful
    `project_snapshot`, sets `cursor = { tick: c.tick, revision: previous + 1 }`
    (saturating). An empty page leaves it unchanged. Both results carry the
    cursor after the call.
15. **Bounds.** After any call `len() <= MAX_VISIBLE_ENTITIES`, because `live`
    equals the visible set. `ops.len() <= MAX_PAGE_OPS`. Stored state is one
    `LiveEntry` per live key, one index entry, one `TurnFact`, two counters: no
    retired-id table, no history, no receipts.
16. **Exhaustion.** With fewer ids left than entering keys, the call fails with
    `IdExhausted` and changes nothing. Pages with no entering key still
    succeed. The D14 remedy is a new `SessionEpoch` and a fresh view; a resync
    frees no ids and an id is never reused.
17. **No derived authority.** Net compares supplied areas only. It reads no
    `World`, RNG or events, derives no area, ownership, LOS or legality, and
    adds no dependency.

### Wire impact

**None. No new protocol version, tag, field, fact or code.** Output is existing
v1 `DeltaOp` values, wrapped by the host in `protocol_v2::DeltaOp::Legacy` for
V2 sessions, and the existing T024 body. v1 bytes, fixtures, decode precedence
and the B5 maxima are untouched. `Despawned` (tag 3) is already a valid v1 op.

**What this does cross, stated rather than absorbed:**

- `interest` is a new public surface, so it needs an ADR
  (`docs/architecture/crpg-net.md:39-40`). The implementer files it from this
  contract, as T024h1 filed ADR-0031.
- T027c owns every host change (below). This package edits no `crpg-server`
  code, so nothing calls `InterestView` in production until T027c lands.
- The wire carries no entity name or kind, no statement of which `NetId` a
  player controls, and no option list. T027b neither needs nor adds these, and
  a client cannot get them from a `NetId`. Any wire form is a new reviewed
  protocol version in its own task. See user decision 2.

### Tests (new `crates/crpg-net/tests/interest.rs`)

No new dependency. Ids come from `crpg_core::GenerationalArena<()>` (two arenas
give equal ids; remove then insert gives slot reuse), areas from
`Ulid::from_u128`. Expected values are hand-written literals or computed by a
test-local `Mirror` plus an independent oracle with its own id counter, never
by production projection (`tasks/POST-T018-RULES.md:54`). `Mirror` applies ops
and bodies and fails on an unknown id, a repeated enter, or a reused id. Each
rejection compares the view with a pre-call `clone`.

- **I1 (3, 10). Two viewers, two areas.** One shared `facts` slice with rows in
  X and Y. Viewer X enters only X rows, Y only Y rows, each with ids from 1.
  *Control:* move one row to the other area and exactly one `EntityEnter`
  appears there.
- **I2 (D2, 3, 9). Keys.** Equal `EntityId`s in X and Y get distinct mappings.
  A viewer moving X to Y gets a leave for the X row and an enter with a new id
  for the equal Y row. A reused slot (same index, higher generation) is a leave
  plus an enter.
- **I3 (6, 10, D4). Field by field.** All combinations of `presence`, `health`
  and `turn_granted` over one row with a distinctive secret `health`: exact ops
  per combination. *Control per suppression:* setting the one bit makes exactly
  the one op appear at its fixed index. `FieldMask::default()` shows nothing.
- **I4 (4, 5, 6, 9). Enter, update, leave, re-enter.** Shuffled input gives the
  literal page; one change gives one `Health`; leave retires; re-entry takes a
  new id; the old id stays `None`.
- **I5 (10). Hidden spawn.** A hidden row emits nothing, and the next visible
  entrant takes the id it would have taken anyway. Feeding
  `EventCandidate::Spawned { entity: view.net_id(key), disclose: true }`
  through `project_events` yields nothing. *Control:* with `presence`, the page
  has the enter and the same candidate yields `Spawned`, placed at `enters`.
- **I6 (11, D5). Death.** A dead row stays mapped with no removal op. `Died`
  through `project_events` needs both the mapping and `disclose`; a hidden row
  yields nothing. *Control:* mapped and disclosed yields `Died`. Health without
  a disclose flag shows `dead: true` and no `Died`.
- **I7 (8). Despawn.** Hidden despawn, area move and presence revoke give equal
  ops for one key. *Control:* listing the key in `despawned` gives `Despawned`
  and no `EntityLeave`. A listed key that is visible, hidden or never live
  emits nothing.
- **I8 (9). Same-tick revoke and request.** Project a removal, then with no
  other call resolve the old id through a test-local copy of the host's
  resolution: it denies, and identically for hidden, foreign, retired and
  never-issued ids. *Control:* a still-visible id resolves.
- **I9 (7, D9). Turn.** Visible active, hidden active (`active: None`), active
  entering this page (its new id), active leaving this page (`None`, and `Turn`
  before the removal), foreign area (no op), no grant (no op), `active: None`.
  An unchanged turn emits nothing. *Control:* the grant makes the op appear.
- **I10 (6, 7, D12). Resend.** `resend_health` and `resend_turn` re-emit
  unchanged values, once, for that page only, and never override a missing
  grant. A page of involved rows with both flags equals a literal
  `[Health asc NetId.., Turn]`.
- **I11 (5, D12). T022 layout.** Literal pages for a fresh view
  (`full_state_ops` order: enters, healths, turn) and a widening
  (`widening_ops` order). The body equals a literal `snapshot_body`.
- **I12 (12, 13, 14). Snapshot and cutover.** Mid-epoch snapshot: ascending ids
  with live ids kept, health only where granted, turn present with a hidden
  active as `None`, dropped keys retired. The next delta re-emits nothing
  unchanged. A key dropped by a snapshot re-enters with a new id. `revision`
  steps once per snapshot and per non-empty page, and not for an empty page.
- **I13 (15, 12). Bounds.** 1,024 rows pass and 1,025 fail; the same for
  `despawned`. A maximal page has exactly `MAX_PAGE_OPS` ops and chunks at
  `MAX_DELTA_OPS` into frames that all pass `codec::encode_delta`. 10,000
  enter/leave cycles leave `len() == 0` and ids strictly rising. A 1,024-entity
  all-health body passes `encode_body` and `plan_transfer`.
- **I14 (1, 2). Errors.** Each of `WrongEpoch`, `TooManyFacts`, `DuplicateFact`
  is provoked on both functions, the view equals its clone, and a valid context
  then gives the expected page. Combined faults report in item 1 order. Display
  strings are exact.
- **I15 (16, unit test in `src/interest.rs`).** `u64` cannot be counted out and
  no public setter may exist, so this is the single public-API carve-out,
  following `crates/crpg-core/src/entity.rs:483`: a `#[cfg(test)]` private
  `force_next_id`. With `next_id == u64::MAX`, one entering key fails unchanged;
  with `u64::MAX - 1`, one succeeds and two fail; no-entry pages still succeed.
  At `u64::MAX - 1024`, a worst-case body encodes to at most
  `MAX_ENCODED_BODY_BYTES`.
- **I16 (10). Hidden invariance.** Two scripted 50-step runs differ only in
  hidden inputs: secrets on ungranted rows, extra hidden and foreign rows, a
  hidden `active`. Encoded pages, cursors and `len` are byte-identical.
  *Control:* the same difference on a visible, granted row changes the bytes.
- **I17 (5, 13). Convergence.** A 2,000-step schedule from
  `DeterministicRng::from_seed(27).stream("interest")` over two viewers and two
  areas with enters, leaves, health, grant changes, area moves and snapshots.
  `Mirror` matches the oracle after every step.
- **I18 (corrupt and drop).** Each must fail the oracle loudly: drop an
  `EntityEnter`; move `Health` before its enter; alter a health value; drop a
  page; duplicate a removal. *Control:* untouched pages converge.
- **I19 (Wire impact).** A fixed page encodes through `codec::encode_delta` to
  literal bytes, and through `codec_v2::encode_delta` wrapped in `Legacy` to the
  same bytes except byte 0. `--test codec` and `--test conformance` pass
  unmodified.

### What T046 may rely on

T046 reads the wire, not `InterestView`, and needs T027b's rules, not its code.
It may use `InterestView` to generate test input, never as its oracle.

- **N1.** No op names an id before its `EntityEnter` or its presence in a
  published snapshot. An unknown id is a protocol fault, not a value to invent.
- **N2.** A removal is exactly one `EntityLeave` or `Despawned`. Nothing names
  that id afterwards in the epoch, apart from frames superseded by a snapshot.
- **N3.** Ids are never reused in an epoch. A new epoch starts an empty
  replica. A re-entering character is a new id, and the client cannot link the
  two.
- **N4.** Absent health means unknown, never zero. `Health` replaces the whole
  fact. An entity stays after death.
- **N5.** A snapshot replaces the whole replica including the turn, and an id
  missing from it is gone with no op.
- **N6.** Delta mode never clears `Health` or `Turn`. Queries return the last
  disclosed value until replaced. V2 `EncounterEnded` is the end-of-fight
  signal.
- **N7.** `Turn { active: None }` means no disclosed active actor. "None" and
  "hidden" are deliberately indistinguishable.
- **N8.** A page may split across frames at any op boundary, so an entity can
  be present with no health yet. `Spawned` and `Died` are notices, not state.
- **N9.** V1 sessions receive no `Spawned` or `Died` (ADR-0022 item 7). T022's
  lane-0 narrowing reset restarts `event_seq` at 1 with fresh enters on
  retained ids, so that path empties the replica first.

## Decisions for the user

**1. Approve what a player is allowed to see (the H-filter gate).** This
contract is the code that decides what each player's game client receives, so
anything it lets through can be read by a player with a modified client. It
sets how the filter behaves; who gets which permissions comes later in T027c.
As written:

- A player sees nothing about a character unless both are true: they share an
  area, and the server has marked that character as visible to them.
- Health is a separate permission. Holding it also reveals when the character
  is dead, because the network message has no form without that flag. To hide
  death you must hide health.
- If it is the turn of a character the player cannot see, the player is told
  "someone you cannot see is acting", with the round number. The alternative
  is to tell them nothing, but then their screen keeps showing the previous
  actor, and it would mean editing existing approved server tests.
- When a character disappears for a secret reason, the player sees only
  "left", with no reason given.
- A character who leaves and comes back looks like a new one to the client, so
  players cannot track a hidden character by its id.
- An area with more than 1,024 characters visible to one player disconnects
  that player rather than silently hiding some. The spec expects hundreds, so
  this is a safety stop, not a normal case.

*Options:* approve as written; or name any rule to change, which changes this
contract and possibly T027c. **Recommendation: approve.** These match the
server behaviour you approved in T022 and the choices delegated in D14.

**2. How does the demo know names, and which character is yours?** To stop
cheating, the network only sends each client an anonymous number per character,
plus health and turn. It sends no name, no art choice and no "this one is
yours". T027b does not need these and does not add them, but the Godot demo
does.

- *Option A, demo table:* when the game starts, the Godot bridge builds a
  number-to-name table from the campaign data, using the promise here that
  numbers are handed out in a fixed order (item 4). No network change. It works
  for one local player in `combat_basic`. Anything that appears later, and any
  real multiplayer, gets no name.
- *Option B, new network version now:* add a small "here is what this character
  is" message. It is the right long-term answer and works for multiplayer, but
  it needs a reviewed protocol version, new tests and a filtering rule of its
  own, which delays the demo.

**Recommendation: Option A for the demo**, deciding it in T045 where the
question already sits, with Option B as a separate task before multiplayer.
T027b and T046 are the same either way, so this does not hold up approval.
