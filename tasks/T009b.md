## Task
Give `crpgc` its first real subcommand: `crpgc replay` loads a replay and
its golden, plays through the T009a API, and exits 0 on equality, nonzero on
a typed failure with the structured divergence (or I/O, or validation error)
printed to stderr. No replay semantics live in `crpg-cli` — it is a thin
consumer of `crpg-testkit`'s `play_and_verify`, nothing more.

## Crate(s)
`crpg-cli` (only). `crpg-testkit` is consumed, never modified.

## Purpose
T009a built the replay semantics once, behind `play_and_verify`, so every
consumer gets the same input→tick→hash interleaving and the same exact-tick
divergence report (ADR-0009 scope, ADR-0010 mismatch, ADR-0012 target
baselines). The only missing link is a binary that drives it. `crpgc replay`
is that binary: the first real code in `crpg-cli`, and therefore also the
task that opens the crate (writes `docs/architecture/crpg-cli.md` and the
crate's `AGENTS.md`, and moves the architecture-README row from "due with
T013" to T009b). It is deliberately not a rebless or recording tool:
golden generation stays a reviewed re-baseline event on its genuine native
target (testkit's no-rebless rule), so T009b ships verify-only.

`play_replay` needs an `ApplyInput` to interpret payloads, and testkit owns
no payload vocabulary by invariant 8 — the caller owns what a payload means.
There is no game intent vocabulary yet (that is T014/T016 territory), so
`crpg-cli` defines a small **provisional reference-intents** apply over
public `World` APIs, explicitly documented as superseded when real intents
land. That is the caller-owns rule working as designed: testkit's
`tests/support` is one caller-side example; the binary's apply is a second,
and testkit still owns nothing.

## Decision already made
Hand-rolled argument parsing for this subcommand; **revisit clap at T013**.
T009b has one subcommand and one optional flag, so a parser framework and
its ~13 transitive packages (mostly coloured-help/terminal machinery) are
dead weight now. T013 is the first task that needs five-plus subcommands
(`new`, `schema`, `explain`, `fmt`, `lock`, `run`) with real flags; that is
the point where a standard parser pays. Recorded here so the decision is
re-examined there, not silently inherited.

Exit codes follow clap's convention so a later swap stays compatible:
`0` success, `1` domain failure (any `ReplayError`), `2` usage error.

## Interface

```
crpgc replay <replay-path> [--golden <golden-path>]

  <replay-path>   .replay file to read, validate, and play.
  --golden <path> golden to compare against. Default: replay-path with its
                  extension replaced by `.golden` (foo.replay -> foo.golden).

exit 0  sequence matches the golden (also prints nothing on stdout; the
        hashes go nowhere — the CLI is a verification tool, not a recorder).
exit 1  any crpg-testkit::ReplayError, printed by its single-pathed Display
        to stderr: Io (missing file stays distinguishable from divergence),
        Malformed, UnsupportedVersion, UnorderedSchedule, OutOfRange,
        TooLarge, ApplyFailed, Divergence.
exit 2  usage error: unknown subcommand, missing replay path, unknown flag,
        missing --golden value.
```

The binary calls `crpg_testkit::play_and_verify(&replay_path, &golden_path,
apply)` and maps the result. `ReplayDivergence`'s Display already carries
identity, the exact tick, and the truthfully-present `Mismatch` sides;
there is no second divergence format in the CLI.

The provisional apply (`src/apply.rs`, `pub(crate)`) interprets the
reference payloads `spawn_at`, `timeline`, `draw`, `despawn` over public
`World` APIs only, byte-for-byte the same semantics the checked-in
`fixtures/replay_basic.replay` was generated against, so `crpgc replay` can
verify the checked-in fixture against its native-scoped golden. It is
superseded when T014/T016 define real intents; nothing outside
`crpg-cli` may import it.

## Behaviour

- **Thin.** The binary owns file paths, argument parsing, and exit codes. It
  does not read JSON, does not interleave, does not construct a divergence —
  `read_replay`/validation/interleaving/comparison all live in testkit
  (`play_and_verify`) or in the apply. A change to replay semantics happens
  in testkit and the CLI picks it up unchanged.
- **Verify-only.** No `--write`, no rebless, no recording. Golden generation
  is a reviewed re-baseline event per target (ADR-0012). This is a
  deliberate scope line drawn here so `crpgc replay --write` cannot become an
  accidental bless-by-command.
- **Target scope is ADR-0012 exact-build, not cross-platform.** The CLI never
  compares cross-platform hash equality. The checked-in golden for the
  fixture is named per native target; the tests select it at compile time
  with the same cfg guard testkit uses (never runtime detection, never a
  skipped-green placeholder). The portable cases (divergence, malformed,
  missing file, usage) run on every target.
- **Exit status and diagnostics are the test contract.** Tests assert the
  exit code and that stderr carries the expected single-pathed diagnostic,
  without string-matching scene internals.
- **Exit code mapping is stable.** `0/1/2` above are a public-facing contract
  for CI and scripts from the first version.
