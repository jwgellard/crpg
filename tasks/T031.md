# T031 — Native preflight command runners

## Status / owner / purpose

**Specified; no implementation predecessor.** Tooling-only under D18 and the
BACKLOG scaffolding obligation. Implement `tools/preflight.ps1` (PowerShell 7)
and `tools/preflight.sh` (Bash) plus `tools/tests/test_preflight.py` and a short
usage document `tools/README.md`. No Rust crate, dependency or CI policy change.

The scripts run the existing local native gates reproducibly. They do not
provision toolchains, install packages, generate schemas/goldens, select a WSL
distro or claim to replace GitHub's protected-path/secrets checks.

## Exact invocation

```text
pwsh -NoProfile -File tools/preflight.ps1 [-Crate <package>] [-CheckOnly]
bash tools/preflight.sh [--crate <package>] [--check-only]
```

Default is the full workspace. Crate mode takes exactly one existing member
package name, not a directory/glob/free-form Cargo fragment. Discover membership
from `cargo metadata --no-deps --format-version 1 --locked`; require an exact
match among workspace_members (never accept transitive package names). Reject
unknown/duplicate/empty arguments with exit 2 before running a modifying gate.
Support `-Help` / `--help` with exit 0 and no tool invocations. No passthrough or
skip-lint/test/deny flag. Unknown option/extra positional argument exits 2.

Resolve root from the script's location, independent of caller working directory.
Check root Cargo.toml, rust-toolchain.toml and tools/lint files before running.
Invoke all tools with argument arrays, never eval or concatenated shell commands.
Paths containing spaces must work. Restore caller location on success/failure;
do not alter environment variables persistently or read shell profiles.

## Command sequence / output / errors

Execute in this order, stopping at first failure:

1. `rustc -vV` (show actual native host/toolchain provenance).
2. Metadata package validation as above (also in workspace mode).
3. `cargo fmt --all` unless check-only, then always
   `cargo fmt --all -- --check`.
4. Workspace: `cargo clippy --workspace --all-targets --locked -- -D warnings`;
   crate mode: `cargo clippy -p <package> --all-targets --locked -- -D warnings`.
5. Workspace: `cargo test --workspace --locked`; crate mode:
   `cargo test -p <package> --locked`.
6. `python tools/lint/deps.py`.
7. `python tools/lint/determinism.py`.
8. `python -m unittest discover -s tools/lint -p "test_*.py"`.
9. `cargo deny check` (workspace graph even in crate mode).
10. `git diff --check`.

On Bash/Linux use `python3` for steps 6–8; PowerShell uses `python`. Require
Python >=3.11 before step 3; no fallback to an unavailable/interpreter-too-old
command, and no dependency installation. Check required executables before
step 3. Report missing prerequisite or malformed metadata with exit 2; failed
gate with exit 1 and the exact failed command plus its native exit code. Success
exits 0. PowerShell must inspect `$LASTEXITCODE`; Bash must not accidentally lose
pipeline exit status. Pass tool stdout/stderr through without parsing “passed”
strings or suppressing warnings. Print a final success line only after all gates
actually run and pass. A crate run says “crate gates”, never “workspace gates”.

Never add `--target` to fake native execution. Crate mode does not satisfy
POST-T018's full-workspace or second-native-target acceptance; document this
explicitly. Both modes are local checks, not a remote CI result. CheckOnly is
read-only formatting, not a dry run of other gates.

## Acceptance

Python stdlib unittest harness launches scripts as subprocesses against temporary
fake executable tools on PATH and a minimal fake repository root. Keep fixture
scripts in test-owned temporary directories; never shadow or edit real lint
files. Assert exact argv/order, package validation, early failure propagation,
exit values, no later command after failure, complete success output, spaces in
root, invocation from another directory and help/invalid-argument no-gate paths.
Metadata fixture covers a nonmember dependency with a plausible crate name.
Use executable sh shims on Linux and suitable PowerShell/native-command shims
on Windows; native applicable launcher cases are required, not skipped because
a shim format is inconvenient. Test process exit, not just string matching.

Run on native Windows and Linux:

```text
python -m unittest discover -s tools/tests -p "test_preflight.py"
```

Linux uses python3. Then real stopping commands, respectively:

```text
pwsh -NoProfile -File tools/preflight.ps1 -CheckOnly
bash tools/preflight.sh --check-only
```

Also exercise real crate mode once with `crpg-core`; fake-tool tests alone do
not prove the scripts can run the actual gates. Existing lint tests must remain
unchanged. No CI workflow activation or self-hosted runner provisioning here.
Document gate limitations and add attribution to every edited Markdown file.
