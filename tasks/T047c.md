### Decision

- **D1. Files (all of them).** `.github/workflows/ci.yml` (one step in
  `check`, one new job `client`); `deny.toml` (the T047.md text, verbatim);
  new `apps/client/THIRD_PARTY_NOTICES` (plain text, no extension); appends to
  `docs/architecture/crpg-godot.md` and `crates/crpg-godot/AGENTS.md` (signed).
  Nothing under `crates/*/src`, `tests`, `Cargo.toml`, `Cargo.lock`,
  `tools/`, `rust-toolchain.toml` or the other `apps/client` files.
- **D2. BR-21 is one `cargo tree` query over the whole default graph.**
  `--workspace -e normal,build,dev --target all` covers every member, every
  edge kind `cargo test --workspace` compiles, and every target, so the same
  command is stronger than "per target" and identical on both runners. Its
  control, in the same step, is that query with `--features crpg-godot/engine`,
  which must resolve `godot v0.5.5`; otherwise the absence proves nothing
  (e.g. a broken pattern). Both commands only resolve; nothing is built
  (open question 1).
- **D3. Godot is the official 4.7.2-stable win64 editor zip, checked twice.**
  The job verifies SHA-256 (ADR C2) and SHA-512 (the digest upstream itself
  publishes) before unpacking, then checks `--version`. It runs the bundled
  `_console.exe`: the plain exe is a GUI-subsystem program, and PowerShell
  neither waits for it nor sees its exit code (measured locally 2026-11-02:
  `& godot4.exe --version` returned no output and no `$LASTEXITCODE`). The
  console wrapper finds its engine by file name (a renamed local copy
  failed: `Main executable …\Godot.exe not found.`, exit −1), so neither exe
  is renamed. No cache: the zip is about 86 MB.
- **D4. `client` runs E1 as well as C1's list.** `--import` first (T047.md D9),
  then E1 `load.gd` (the load proof `--import` is not), then BR-22
  `smoke.gd`, and both negative controls. The controls also prove that the
  console wrapper passes the script's exit code through. This adds steps to
  C1 and removes none.
- **D5. The notice is checked against the graph.** A step compares the
  godot-family packages `cargo tree` resolves for `crpg-godot --features
  engine` with the package lines in the notice. A `godot` bump that forgets
  the notice fails CI.
- **D6. Artifact = a runnable slice.** It holds the DLL, the client project,
  the fixture campaign the client opens by default (T047.md Interface,
  `res://` + `../../campaigns/fixtures/combat_basic`), and the workspace
  licence files, laid out as in the repository so both relative paths resolve
  (open question 2).
- **D7. Action pins.** `actions/checkout@v7` and `Swatinem/rust-cache@v2` as
  in `ci.yml:109`, `:148`. C3 needs `actions/upload-artifact`, which `ci.yml`
  does not use yet: `@v7` (major tag, `using: 'node24'`, v7.0.2 published
  2026-10-07), by the file's own policy for GitHub's JavaScript actions
  (`ci.yml:14-22`) (open question 3).

### Interface

**`ci.yml` — BR-21 step in `check`.** Insert between `ci.yml:149` (the
rust-cache `if:`) and `ci.yml:150` (`cargo fmt`). The rest of `check` is
unchanged.

```yaml
      # T047c (ADR-0033 C4, BR-21): the default-feature graph -- every member,
      # edge kind and target -- holds no godot-family package. The second
      # query is the control: with the engine feature it must find godot, or
      # the first proves nothing. Both only resolve the graph; nothing builds.
      - name: BR-21 (no godot package in the default-feature graph)
        if: steps.scope.outputs.rust == 'true'
        shell: bash
        run: |
          set -euo pipefail
          family='^(godot(-[a-z]+)?|gdextension-api) v'
          graph() {
            cargo tree --workspace --locked -e normal,build,dev --target all \
              --prefix none --format '{p}' "$@"
          }
          default_graph="$(graph)"
          if grep -E "$family" <<<"$default_graph"; then
            echo "BR-21 failed: the default-feature graph holds the godot packages above"
            exit 1
          fi
          engine_graph="$(graph --features crpg-godot/engine)"
          if ! grep -qE '^godot v0\.5\.5([^0-9.]|$)' <<<"$engine_graph"; then
            echo "BR-21 control failed: --features crpg-godot/engine does not resolve godot v0.5.5"
            exit 1
          fi
          echo "BR-21 passed: no godot package by default; the engine control resolves godot v0.5.5"
```

**`ci.yml` — job `client`.** Insert after the `check` job (after `ci.yml:160`),
before `deny:`. No `name:` key, so the check context is `client` (C7). It
inherits the workflow's triggers, `permissions: contents: read` and
concurrency. Its comments must not contain the strings `features engine` or
`godotengine` outside the steps below (W10 scans for them).

```yaml
  # T047c (ADR-0033 §15 C1-C3): the Windows client build. Windows only
  # (ADR-0012; ADR-0033 platform scope): no Linux job compiles the engine.
  # The job always runs and reports, so the ruleset can require it (C7). Its
  # scope step is a byte-identical copy of the one in `check`; keep them equal.
  # Godot comes from one exact release asset, checked before it is unpacked.
  client:
    runs-on: windows-latest
    timeout-minutes: 60
    steps:
      - uses: actions/checkout@v7
        with:
          fetch-depth: 0
      - name: Classify the change (documentation-only pull requests skip the client gates)
        id: scope
        # >>> ci.yml:126-147 copied byte for byte (shell: bash + run block) <<<
      - uses: Swatinem/rust-cache@v2
        if: steps.scope.outputs.rust == 'true'
      - run: cargo clippy -p crpg-godot --features engine --all-targets --locked -- -D warnings
        if: steps.scope.outputs.rust == 'true'
      - run: cargo build -p crpg-godot --features engine --locked
        if: steps.scope.outputs.rust == 'true'
      - name: Licence notice names exactly the resolved godot packages
        if: steps.scope.outputs.rust == 'true'
        shell: bash
        run: |
          set -euo pipefail
          notice=apps/client/THIRD_PARTY_NOTICES
          family='^(godot(-[a-z]+)?|gdextension-api) v'
          resolved="$(cargo tree -p crpg-godot --features engine --locked -e normal,build \
            --target x86_64-pc-windows-msvc --prefix none --format '{p}' \
            | tr -d '\r' | sed 's/ (\*)$//' | { grep -E "$family" || true; } | sort -u)"
          listed="$(tr -d '\r' < "$notice" | sed -n 's/^  //p' | { grep -E "$family" || true; } | sort -u)"
          if [ "$resolved" != "$listed" ] || [ "$(grep -c . <<<"$resolved")" -ne 8 ]; then
            echo "notice check failed: resolved packages and $notice differ, or are not eight"
            diff <(printf '%s\n' "$resolved") <(printf '%s\n' "$listed") || true
            exit 1
          fi
          echo "notice check passed:"
          printf '%s\n' "$resolved"
      - name: Fetch Godot 4.7.2 and check its digests
        if: steps.scope.outputs.rust == 'true'
        shell: pwsh
        run: |
          $ErrorActionPreference = 'Stop'
          $ProgressPreference = 'SilentlyContinue'
          $url = 'https://github.com/godotengine/godot/releases/download/4.7.2-stable/Godot_v4.7.2-stable_win64.exe.zip'
          # SHA-256: ADR-0033 C2 (equals GitHub's asset digest). SHA-512: upstream SHA512-SUMS.txt.
          $pins = [ordered]@{
            SHA256 = '731980f9608d61333e5baf54a2ef17210acc7a538446c0cb9969f002aca1e953'
            SHA512 = '83decd58fdf67b9d657958a1ae6bf1929c20785315a81effe245874cdc57acb709bf868e00778a96984338c1b29dafdb453c6847747694621c6ecf5da2259993'
          }
          $zip = Join-Path $env:RUNNER_TEMP 'Godot_v4.7.2-stable_win64.exe.zip'
          $dir = Join-Path $env:RUNNER_TEMP 'godot-4.7.2'
          Invoke-WebRequest -Uri $url -OutFile $zip
          foreach ($alg in $pins.Keys) {
            $got = (Get-FileHash -Algorithm $alg -LiteralPath $zip).Hash.ToLowerInvariant()
            if ($got -ne $pins[$alg]) { throw "Godot zip $alg $got is not the pinned $($pins[$alg])" }
          }
          Expand-Archive -LiteralPath $zip -DestinationPath $dir -Force
          # The console wrapper finds its engine by name: never rename either exe.
          $exe = Join-Path $dir 'Godot_v4.7.2-stable_win64_console.exe'
          $out = & $exe --version
          if ($LASTEXITCODE -ne 0) { throw "godot --version exited $LASTEXITCODE" }
          $version = "$($out | Select-Object -First 1)".Trim()
          if ($version -ne '4.7.2.stable.official.ed1daf0bf') { throw "unexpected Godot version '$version'" }
          "GODOT=$exe" | Out-File -FilePath $env:GITHUB_ENV -Append -Encoding utf8
          Write-Output "Godot $version at $exe"
      # >>> the five Godot steps, table below, in that order <<<
      - name: Stage the client slice
        if: steps.scope.outputs.rust == 'true'
        shell: bash
        run: |
          set -euo pipefail
          stage=_slice
          rm -rf "$stage"
          mkdir -p "$stage/target/debug"
          cp target/debug/crpg_godot.dll "$stage/target/debug/"
          git ls-files -z -- apps/client campaigns/fixtures/combat_basic LICENSE-MIT LICENSE-APACHE \
            | { grep -zv '/\.[^/]*$' || true; } | xargs -0 cp --parents -t "$stage"
          for f in target/debug/crpg_godot.dll apps/client/project.godot apps/client/crpg.gdextension \
                   apps/client/THIRD_PARTY_NOTICES apps/client/scenes/Main.tscn apps/client/tests/smoke.gd \
                   campaigns/fixtures/combat_basic/campaign.json LICENSE-MIT LICENSE-APACHE; do
            test -f "$stage/$f" || { echo "artifact: $f is missing"; exit 1; }
          done
          if find "$stage" -name '.*' | grep .; then echo "artifact: hidden paths above"; exit 1; fi
          find "$stage" -type f | sort

          path: _slice/
          if-no-files-found: error
          retention-days: 14
```

### Behaviour

1. **B1. BR-21 in `check`.** Runs on both matrix legs when
   `rust == 'true'`, before `cargo fmt`. It fails if any line of the default
   query matches the family pattern (printing it), or if the engine query has
   no `godot v0.5.5` line. `crpg-godot v…` never matches (`^godot`). Exit 0
   otherwise.
2. **B2. `client` always reports.** Its scope step is the `check` copy, so on
   a documentation-only PR every later step is skipped and the job is green.
   On push, schedule or any PR touching code (`apps/**` included,
   `docs/adr/0033-godot-bridge.md:453-454`), every step runs.
3. **B3. Order.** checkout → scope → cache → clippy → build → notice check →
   fetch → G1 → G2 → G3 → G4 → G5 → stage → upload. A failing step stops the
   job, so no artifact exists for a red run.
4. **B4. Fetch.** The download goes to `$RUNNER_TEMP`. Both digests are
   compared before `Expand-Archive`, and either mismatch throws. The version
   must equal `4.7.2.stable.official.ed1daf0bf` (ADR-0001 pin,
   `tasks/T047.md:45`). `GODOT` is exported only on success.
5. **B5. Godot steps.** Each passes only on its own expected exit code. G3
   and G5 pass only on 3, so a wrapper that drops exit codes (0 or −1) fails
   them. G4 relies on smoke.gd's own 120 s limit (exit 4); the step's
   5 min timeout is the backstop.
6. **B6. Notice check.** It passes iff the set of `name vX.Y.Z` lines
   resolved for `crpg-godot --features engine` (normal and build edges,
   Windows target) equals the set of two-space-indented family lines in the
   notice, and that set has exactly eight members. `\r` is stripped, because
   Windows checkouts may convert line endings.
7. **B7. Artifact `crpg-client-slice-windows-x86_64`** (C3). Exactly:
   `target/debug/crpg_godot.dll`; every tracked, non-hidden file under
   `apps/client/` (T047b's, T047d's, the notice); every tracked, non-hidden
   file under `campaigns/fixtures/combat_basic/` (14 today); `LICENSE-MIT`;
   `LICENSE-APACHE`. Paths are relative to the repository root. There is no `.godot/`,
   no `.pdb`, no Godot binary and no dotfile. It is kept for 14 days.
8. **B8. `deny`.** With `[graph]`, both `cargo deny` runs in the `deny` job
   (`ci.yml:171`, `:178`) resolve the engine graph. MPL-2.0 passes for exactly
   the eight names and fails for any other package. The job itself is
   unchanged.
9. **B9. Linux stays Godot-free.** No job but `client` contains
   `features engine` or a Godot download. Linux resolves the engine graph
   only in the BR-21 control and `cargo deny`, and compiles none of it.
10. **B10. C7.** After merge, the user adds the `client` context to the
    master ruleset's required checks
    (`docs/adr/0033-godot-bridge.md:451`, `:589`). T047c does not touch
    rulesets.

## Open questions for the user

1. **May the Linux CI machine *look up* the Godot packages without building
   them?** BR-21 proves that the normal build contains no Godot code. Its
   self-check asks Cargo "what would the list be with the Godot feature on?"
   and expects to see `godot`. That is a list lookup, not a build, but ADR
   §15 C4 says "no Linux job ever enables `engine`". (a) Run the self-check
   on both machines. Linux downloads the Godot package sources but compiles
   nothing, which the `deny` job's `[graph]` line already does on Linux.
   (b) Run it on Windows only. Linux's own check then has no self-check. (c)
   Drop the self-check. A broken pattern would then pass silently.
   **Recommend (a)**, reading C4 as "never builds".
2. **May the downloadable build include the test campaign and our licence
   files?** C3 says "DLL plus `apps/client`", but the client opens
   `campaigns/fixtures/combat_basic` by default, and without it the download
   cannot run. (a) Include the 14 campaign files and `LICENSE-MIT`/`LICENSE-APACHE` (a few KB).
   (b) Follow C3 literally. Anyone running the download must then fetch the
   campaign and point `CRPG_CAMPAIGN` at it. **Recommend (a).**
3. **Which pin for the new upload step?** The workflow has never uploaded
   files, so this adds GitHub's own `actions/upload-artifact`. (a) `@v7`, a
   major tag that picks up fixes, as the file already does for checkout and
   setup-python. (b) `@v7.0.2` exactly, as for cargo-deny and gitleaks. The
   cost is manual bumps. **Recommend (a).** It only uploads, so it enforces no policy.
4. **Should the notice also cover the permissive (MIT/Apache/BSD) packages
   compiled into the DLL?** Strictly, those licences also ask for their
   notice in a shipped binary. Your answer to T047 question 2 covered the
   eight MPL packages. (a) Eight only now. Add a backlog item: a generated
   notice for every dependency before the first build reaches anyone outside
   the project (an export task). (b) Generate the full notice now, which
   needs a new tool or dependency. **Recommend (a)**: the artifact is visible
   only to repository users.
