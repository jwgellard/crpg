### 2. What each family is expressed as today

- **minimal-d6 stats.** `stats: Vec<StatDecl>`; `StatDecl { name: String, kind: StatKindWire }`
  (`combat.rs:52–57`), `StatKindWire` is `Int` only (`combat.rs:44–47`). File has four `Int`
  stats — might, guile, resolve, health (`rulesets/minimal-d6/ruleset.json:23–40`) — and
  `health_stat: "health"` (:17), `attributes: [might, guile, resolve]` (:12–16). No derived stat
  and no expression field anywhere in `StatDecl`.
- **srd-lite stats.** Five `Int` stats including `ward` (`rulesets/srd-lite/ruleset.json:33–54`);
  same `StatDecl` shape; still no derived stat.
- **minimal-d6 resolution.** Ability `dice: "2d6"` (`strike.json:19`), `attribute: "might"`
  (:3), one primary-pool `cost: 1` (:4); the `/1` file has no `defense`, so the migration
  supplies `ActorAttribute` (`crates/crpg-data/AGENTS.md:207–210`). Table `roll_under.json`
  is roll-under: band 0 `min_margin: i64::MIN` success, band 1 `min_margin: 1` failure
  (`roll_under.json:2–15`); `OutcomeBandWire { min_margin: i64, outcome: OutcomeWire }`
  (`combat.rs:320–325`).
- **srd-lite resolution.** `heavy.json` uses `defense: target_stat{stat:"ward"}`
  (`heavy.json:25–30`), `dice: "2d6"` (:31), `natural_die: 0` (:36) and three bands
  (`heavy_table.json:2–20`: `i64::MIN` failure, `-2` success, `2` critical_success) plus a
  natural rule `Shift(1)` on face 6 (`heavy_table.json:24–32`, `combat.rs:330–336`).
  `focus.json` uses `defense: actor_attribute` (`focus.json:19–21`), `dice: "1d6"` (:22).
  No constant DC, no actor-stat bonus, no opposed defence, no tiered thresholds: `DefenseWire`
  has exactly `ActorAttribute` / `TargetStat { stat: String }` (`combat.rs:105–113`).
- **damage.** Flat per outcome: `DamageEntry { outcome: OutcomeWire, amount: u32 }`
  (`combat.rs:266–271`). minimal-d6: 2 on success, 0 on failure (`strike.json:5–18`); srd-lite:
  0/3/5 for failure/success/critical_success (`heavy.json:5–24`). The `dice` string is the
  attack roll, never damage; no damage-dice field exists.
- **initiative.** Authored constant `initiative: i32` on `EncounterParticipant`
  (`combat.rs:376`), e.g. 10 and 9 (`campaigns/fixtures/combat_basic/encounters/first-blood.json:6`, `:10`).
  No initiative dice/stat/derivation field.
- **effects.** `Effect { aim, mod_type: String, policy: PolicyWire, modifiers: Vec<EffectModifierWire>,
  duration_rounds: u32 }` (`combat.rs:192–213`); `EffectModifierWire { id, target, op, value: i32,
  priority: i16, name: Option<String> }` (`combat.rs:171–187`). Minimal-d6 has no effect file
  (glob `rulesets/minimal-d6/**`); srd-lite `focusing.json` aims `slf`, `mod_type "focus"`,
  `policy stack_all`, two `Add`/`Roll` modifiers (2 and 1, priorities 0 and 1, `name: null`),
  `duration_rounds: 2` (`focusing.json:2–39`). `EffectTargetWire` is `Roll`/`Dc` only
  (`combat.rs:139–144`): no stat target, no tag grant, and lifetime is only `duration_rounds`
  (`combat.rs:212`).
- **combatant sides/tags.** Neither exists: `EncounterParticipant { placement: Ulid,
  initiative: i32 }` (`combat.rs:371–377`) and sim `Combatant` carries no side or tag field
  (`crates/crpg-sim/src/combat.rs:74–88`: placement, initiative, attributes, health, pools,
  attached effects only).
- **round/turn timing.** Pools: `ActionPoolTemplate { id, max: u32, refresh: RefreshWire }`
  (`combat.rs:92–100`) with `on_turn_start` / `on_round_start` / `on_rest` / `on_tick` / `never`
  (`combat.rs:62–73`). minimal-d6: one pool, max 1, `on_turn_start` (`ruleset.json:5–11`);
  srd-lite: two pools, max 1 `on_turn_start` and max 2 `on_round_start` (`ruleset.json:15–30`).
  Ability `ends_turn: bool` (`combat.rs:301`; `focus.json:24` is false). No `round_ticks`
  anywhere in `Ruleset` (`combat.rs:218–245`).

### 3. Migrations

- Steps: change the Rust shape (`combat.rs`); bump the tag in the `Document` union
  (`document.rs:432–444`) and `document_schema!` (`schema.rs:116–124`); add the family's
  `current` plus one `Edge { from, to, step }` to the single registry (`migrations/mod.rs:77–98`);
  write `pub(super) fn v1_to_v2(&mut Value)` that checks the source tag, mutates only local
  fields and rewrites the tag (`migrations/ruleset.rs:14–35`); add representatives
  (`crates/crpg-data/AGENTS.md:187–189`); add the edge row and fixtures
  (`crates/crpg-data/AGENTS.md:234–240`); regenerate with
  `cargo run -p crpg-data --example generate_schemas -- schemas` (`AGENTS.md:114`).
- The read path migrates a complete registered chain in memory before typed decode
  (`docs/architecture/crpg-data.md:94–96`); `migrate_document` clones then publishes and is
  idempotent (`crates/crpg-data/AGENTS.md:48–50`).
- Gate 7 is schema drift: the read-only test compares the exact 22-file set and exact bytes
  (`docs/architecture/crpg-data.md:82–87`; `crates/crpg-data/tests/schema_drift.rs:10`, `:51`);
  generation is an authoring step, never a blessing (`AGENTS.md:145–146`).
- Last migration added as the example: ruleset and ability `/1 → /2` — registry rows
  `migrations/mod.rs:78` and `:94`; steps `migrations/ability.rs:25–38` and
  `migrations/ruleset.rs:22–34`; v1 source still shipped at
  `rulesets/minimal-d6/strike.json:24` and `ruleset.json:21`.

### 4. Consumers

  `ResourcePoolId`, `StackingPolicy`, `StatBlock`, `StatDefinition`, `StatKind`, `StatValue`,
  `TagSet`, `OutcomeTable`, `RefreshTrigger`.
- The adapter lives inside `start_encounter_tracked` (`crates/crpg-sim/src/combat.rs:932`):
  participants/initiative `:1040–1044`; pool templates `:1047–1057`; per-ability validation
  `:1075–1173`; defense `:1146–1155`, `:1259–1264`; damage map `:1265–1270`; effects
  `:1287–1323`.
- Data→rules mappings: `ability.dice.parse::<DiceExpr>()` (`:1088`); bands/naturals →
  `OutcomeTable::new` (`:1093–1115`); `cost`/`extra_costs` → `Vec<(ResourcePoolId, u32)>`
  (`:1116–1133`); `ActionPoolTemplate` → `ResourcePool::new` (`:1368–1379`);
  `StatDecl` names feed `attribute_names` (`:1337–1350`); the target-stat defence builds a

  (no reference in `crates/crpg-sim/src/combat.rs:1040–1340`).

### 5. ADR-0029 surface gaps (row-3 scope)

- **Typed stats.** Exists: `StatDecl{name, kind}` with `StatKindWire::Int` only
  (`combat.rs:44–57`). Missing: `Fixed`/`Bool`/`Enum`/`Tags`/`Dice` kinds and derived `Expr`
  stats (kernel has them: ADR `:24–25`; gap: ADR `:123`).
- **Resolution shape.** Exists: `dice`, `attribute`, `DefenseWire` (`combat.rs:288–307`,
  `:105–113`). Missing: no bonus-stat list, no constant DC/target number, no opposed defence,
  no tiered threshold list; the actor attribute is not added in the target-stat case
  (ADR `:34–36`, `:119`, `:147–148`).
- **Damage dice.** Exists: flat `DamageEntry.amount: u32` (`combat.rs:266–271`). Missing: a dice
  expression per outcome (ADR `:125`).
- **Initiative spec.** Exists: constant `EncounterParticipant.initiative: i32`
  (`combat.rs:376`; `first-blood.json:6`). Missing: rolled/derived initiative (ADR `:128`).
- **Effects on stats, tag grants, lifetime kinds.** Exists: `Effect` with `Roll`/`Dc` modifiers
  and `duration_rounds` (`combat.rs:139–144`, `:212`). Missing: stat-targeted modifiers, tag
  grants, lifetime kinds other than rounds (ADR `:38`, `:41–43`, `:124`).
- **Combatant tags and sides.** Neither exists (`EncounterParticipant` only placement +
  initiative, `combat.rs:371–377`); the encounter ends on fewer than two alive with no sides
  (ADR `:38–40`).
- **`round_ticks`, `recovery_ticks`, `repeats_in_real_time`.** Absent from `Ruleset`
  (`combat.rs:218–245`) and `Ability` (`combat.rs:276–315`); ADR T2 defines them (ADR `:186–189`).

### 7. Traps already recorded (`crates/crpg-data/AGENTS.md`)

- "Reject unknown fields. Only `_note` may be missing; other nullable fields need a
  required-nullable serde helper and matching schema required annotation." (`:34–35`)
- "Tagged values and IR preserve ordered arrays. Do not persist interned handles." (`:39`)
- "Canonical JSON sorts keys recursively regardless of feature unification, uses two spaces
  and exactly one LF, and rejects non-integer numeric forms." (`:40–41`)
- "Internally `kind`-tagged enums … use hand-written `Deserialize` impls enforcing exact key
  sets per variant … `Serialize`/`JsonSchema` stay derived." (`:58–63`)
- "Never depend on `crpg-rules` for these shapes: the adjacency is a copied convention, and
  the sim adapter maps values explicitly." (`:159–161`)
- "`effect`/`natural_die` are optional-missing; other nullable fields stay required-nullable."
  (`:215–216`)
- "Pools are values, not indexed objects: the `unknown_pool` walk resolves each extra entry
  against its owning ruleset's templates … never the object index." (`:229–233`)
- "Fixed→Int conversion is checked whole-number only (`raw % 65536 == 0`) … so the adapter
  never truncates." (`:183–186`)
