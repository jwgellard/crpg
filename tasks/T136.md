# T136 — `crpg-data` surface schemas (ADR-0029 Follow-on 3)

## Task / Crate(s) / Status
ADR-0029 Follow-on row 3: the authoring surface for the kernel range (K1–K6)
and the time model's RT fields (T2). Sole crate: `crpg-data` (plus its two
docs and the regenerated `schemas/`). **S-set** (`docs/IMPLEMENTATION_PLAN.md`
§1.4: schema versions and migrations). The row allows splitting the RT fields
into a small first task; this contract does, as **T136a** (exact, below) and
**T136b** (the rest of row 3; the frame below binds its later contract).
Status: **contract approved by the user 2026-10-23 (D31, every recommendation).**

## Decision
- **D1. Split.** T138 depends only on the RT fields (ADR row 5). T136a adds
  just those and lands in one short session; T138's contract and code can
  start on it. T136b (typed and derived stats, resolution shape, damage dice,
  initiative, effects, tags and sides) is large, needs its own reading of the
  kernel `Expr`/`Against` surfaces, and should not hold up the RT work.
- **D2. T136a adds optional-missing fields at the current versions, with no
  bump.** Rule (new, for `crates/crpg-data/AGENTS.md`): *a field may join a
  family at its current version, with no tag change and no migration edge,
  when (i) it is optional-missing, (ii) absence means exactly the behaviour
  before the field existed, and (iii) every existing document decodes to the
  same value with an unchanged canonical encoding.* All three RT fields qualify:
  absent `round_ticks` is TB-only, which is today's only mode (ADR T2).
- **D3. One bump per document, all in T136b.** Splitting with a bump in T136a
  would force a second bump of `crpg.ruleset` and `crpg.ability` in T136b, or
  bind T136b to additive-only shapes before its contract exists. D2 avoids
  both: each document's next version is T136b's, once.
- **Trade-off.** `crpg.ruleset/2` and `crpg.ability/2` grow a shape without a
  tag change. A build from before T136a rejects a document that carries a new
  key with an unknown-field `Malformed`, not a version error. Content and
  engine ship from one repository before release, so no such build is a
  supported reader.

## T136a exact contract

### Interface (`crates/crpg-data/src/combat.rs`; nothing else public changes)
Each field is appended as the **last** field of its struct. The doc comments
are verbatim, because they become schema `description` bytes.
```rust
pub struct Ruleset {
    // ...existing fields unchanged...
    /// Ticks per real-time round, nonzero; absent means turn-based only.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub round_ticks: Option<u32>,
}
pub struct Ability {
    // ...existing fields unchanged...
    /// Real-time recovery ticks after use, nonzero; absent means round_ticks.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub recovery_ticks: Option<u32>,
    /// Whether a real-time standing order repeats; absent means false.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub repeats_in_real_time: Option<bool>,
}
```
No new type, function, `DiagnosticCode`, registry row, edge, migration step or
`schemars` attribute. `u32` because RT timeline keys are `i32` (ADR T5) and
T138 owns that bound; data sets no upper cap (crate rule: no cap without a
kernel bound).

### Behaviour
1. **Decode.** Each new key is either absent or present. Present
   `round_ticks`/`recovery_ticks` must be an integer in `0..=u32::MAX` (zero
   then fails item 3). Present `repeats_in_real_time` must be a JSON boolean.
   Negative, too-large, string and non-integer forms fail as they do for the
   existing `u32`/`bool` fields. Explicit `null` decodes as absent, the same
   as `natural_die` today. Unknown keys are still rejected.
2. **Encode.** An absent field writes no key. A present field writes its key,
   placed by the canonical key sort; `repeats_in_real_time: false` is kept,
   not dropped. The canonical encoding of every existing document is
   therefore unchanged.
3. **Read-time checks** (`validate_combat_local`), each appended as the
   **last** check of its arm. Ruleset: `round_ticks == Some(0)` fails with
   `Malformed` and the message `ruleset round_ticks must be nonzero`. Ability:
   `recovery_ticks == Some(0)` fails with `Malformed` and the message
   `ability recovery_ticks must be nonzero`. Because the checks come last, a
   document with several faults reports the earlier fault as it does today.
4. **No semantic rule.** `validate` emits no new diagnostic for any mix of RT
   fields, including RT ability fields under a ruleset without `round_ticks`
   (open question 3).
5. **Versions unchanged.** The tags stay `crpg.ruleset/2` and
   `crpg.ability/2`. The registry, edges, `schema_versions()` and both `1 → 2`
   steps are byte-unchanged. A `/1` source migrates as today, and its result
   has all three fields absent.
6. **Schemas.** After regeneration with the existing generator,
   `ruleset.schema.json` gains exactly the property `round_ticks`, and
   `ability.schema.json` gains exactly `recovery_ticks` and
   `repeats_in_real_time`. None of them is in `required`. The other 20 schema
   files are byte-identical.
7. **Consumers compile unchanged.** No crate outside `crpg-data` builds a
   `Ruleset` or `Ability` by struct literal (checked: only six `crpg-data`
   test sites do). `crpg-sim` reads neither field until T138.

## Open questions (each with a recommendation)
1. **No version bump for additive optional fields (D2)?** Recommend yes. It
   is the only split that gives T138 an early start and still bumps each
   document once. Alternative: bump `/2 → /3` now, which means `/4` later or
   an additive-only T136b.
2. **Is T136a S-set?** It changes the shape of two versioned schemas, but
   not a version or a migration. Recommend yes (Claude implementer). The rule
   exists for this kind of change, and the package is small.
3. **RT ability fields under a TB-only ruleset.** Recommend no diagnostic in
   T136a. T136b's semantic pass should add a `Warning`, and a
   `ruleset.round_ticks` that no ability needs stays clean.
4. **Explicit `null` reads as absent** (the `natural_die` precedent, not the
   crate's required-nullable rule). Recommend keeping the precedent, so all
   optional-missing fields behave alike.
5. **A `/1` source carrying an RT key is accepted.** The `1 → 2` steps do not
   strip later keys, and the same is true for `natural_die` today. Recommend
   accepting it now. T136b's steps may reject keys their source version lacks.
6. **T134/T135 exposure.** ADR row 3 does not list success counting, pool
   `refill` or `set_max`. Recommend leaving them out of T136 and adding each
   with its first consumer (T109 or a later surface row), under the D2 rule
   when additive.
7. **`repeats_in_real_time: Option<bool>`** rather than a defaulted `bool`.
   Recommend `Option`: it reuses the existing optional-missing pattern and
   needs no `skip_serializing_if = is_false` helper. Absent and `false` mean
   the same, and the sim maps both to `false`.
