## Behaviour

- Atomic accepted action emits exactly the approved ordered history; rejected
  actions emit/spend/draw nothing. Damage means reported action damage, not an
  inferred health difference. Death, terminal encounter and release are distinct.
- A production read/ack/retention API replaces clone-and-drain observation for
  the new mode. Define stale cursor, capacity exhaustion, multi-consumer progress,
  ack idempotence and checked sequence exhaustion. No unbounded history or silent
  eviction of needed events; capacity failure must precede gameplay mutation.
- Persist all behavior-affecting history/cursors required for continuation;
  define restart reconstruction. Net delivery sequences remain outside sim.
- **Compatibility gate:** unconditional new emissions change hashed queue bytes
  and break existing B4 combat replays. Recommend an explicit versioned opt-in
  history mode/entry point with legacy path byte-identical, fully hashed when
  enabled. This requires ADR approval; absence-skip cannot hide nonempty state.
  Alternative D08: keep host-only outcome history and supersede this task.
- No hash exclusion or legacy rebaseline workaround. A hash-exclusion proposal
  needs its own ADR and behavior-proof tests, separate from vocabulary approval.

### Exact additive API

Public module `history`, with these items re-exported at the crate root. Types
below use existing core and sim types; no dependencies are added.

```rust
pub const MAX_HISTORY_EVENTS: usize = 4096;
pub const MAX_HISTORY_BYTES: usize = 1_048_576;
pub const MAX_HISTORY_PAGE: usize = 256;
pub const MAX_HISTORY_STRING_BYTES: usize = 256;
pub const HISTORY_VERSION: u32 = 1;

pub enum HistoryEvent {
    Spawned { entity: EntityId },
    Despawned { entity: EntityId },
    Died { entity: EntityId },
    ActionResolved { actor: EntityId, target: EntityId, ability: Ulid,
                     outcome: String, damage: u32 },
    TurnStarted { actor: EntityId, round: u64 },
    EncounterEnded { encounter: Ulid, round: u64 },
}
pub struct HistoryEnvelope {
    pub tick: Tick,
    pub seq: u64,
    pub payload: HistoryEvent,
}
pub struct HistoryWorld { /* private authoritative fields */ }
impl HistoryWorld {
    pub fn new(seed: u64) -> Self;
    pub fn world(&self) -> &World;
    pub fn spawn(&mut self, meta: EntityMeta) -> Result<EntityId, HistoryError>;
    pub fn despawn(&mut self, entity: EntityId) -> Result<bool, HistoryError>;
    pub fn tick(&mut self) -> Result<(), HistoryError>;
    pub fn start_encounter(&mut self, spec: &EncounterSpec<'_>)
        -> Result<(), HistoryError>;
    pub fn perform_action(&mut self, action: &CombatAction)
        -> Result<Option<ActionOutcome>, HistoryError>;
    pub fn end_encounter(&mut self) -> Result<EncounterSummary, HistoryError>;
    pub fn acknowledged(&self) -> u64;
    pub fn last_sequence(&self) -> u64;
    pub fn pending_len(&self) -> usize;
    pub fn pending_bytes(&self) -> usize;
    pub fn read_after(&self, after: u64, limit: usize)
        -> Result<Vec<HistoryEnvelope>, HistoryError>;
    pub fn acknowledge(&mut self, through: u64) -> Result<(), HistoryError>;
}
pub fn history_hash(world: &HistoryWorld) -> [u8; 32];
pub enum HistoryError {
    Combat(CombatError),
    InvalidPageLimit { limit: usize },
    StaleCursor { requested: u64, acknowledged: u64 },
    FutureCursor { requested: u64, last: u64 },
    SequenceExhausted,
    EventLimit,
    ByteLimit,
    StringLimit,
}
```

Event/envelope: `Debug, Clone, PartialEq, Eq, Serialize, Deserialize` with strict
variant/field validation. HistoryWorld: `Debug, Clone, PartialEq, Serialize`,
validated Deserialize; no Eq because World contains spatial floats. HistoryError:
`Debug, Clone, PartialEq, Eq, Display, Error`; Combat delegates Display/source;
all other displays are `<VariantName> at history`, without payloads or source.
`Default` for HistoryWorld means `new(0)`. No mutable-inner access, DerefMut,
AsMut, generic callback transaction, From<World>, into-inner-and-reinsert, raw
queue setter, RNG mutator or low-level pop-only end_turn operation is exposed.
Cloning `world()` cannot mutate or replace the wrapper's authority.

### Mutation-route audit and transaction boundary

Existing World routes are spawn/despawn, free tick/end_turn, transforms_mut,
timeline_mut, events_mut, rng_mut, plus start/perform/end encounter. New mode
exposes only the typed methods above; store/timeline/RNG manipulation is not
part of this first mode. Existing free functions and World methods stay intact.
Serde is a validated load boundary, not an unchecked mutation escape.

For each operation, stage a full wrapper/World clone, call the existing
controller, drain staged `World::events_mut().drain()` exactly once, translate
each legacy event exactly once, collect richer transition facts, validate the
resulting journal, then replace live state. No callback runs after publication.
The authoritative World event queue is empty at every wrapper public boundary;
its legacy `next_seq` is retained, serialized and hashed, never reset by drain.
History uses its own checked sequence. Do not edit core to inspect its counter.

Controllers may gain a private transition result used by both legacy and new
entry points; it must not change legacy emissions, bytes or signatures. Observe
actual refresh/advance branches, not actor-id comparison or arithmetic guesses:
logical turn starts still occur when the same actor returns, including saturated
u32 round rollover. Keep `CombatState.round` and its persisted u32 type and
saturation semantics unchanged; populate history's u64 round with
`u64::from(state.round)`, never a second round counter. No separate combat
implementation in `history`.

Existing gameplay errors win before history errors. After successful staging:
validate event strings, reserve sequence range, event count, then canonical byte
total, in that order. Failure commits **nothing**, including RNG draws,
allocations of entity ids, legacy queue counters and history counters. An absent
despawn returns `Ok(false)` with no event, even when the journal is full. Tick,
release and other zero-event operations need no free journal slot/sequence.

### Emission table (all at the operation's authoritative tick)

| Successful operation | Journal additions, in order |
|---|---|
| spawn | one Spawned |
| start_encounter | Spawned for each participant in authored order, then initial TurnStarted |
| UseAbility | ActionResolved, each actual Died in legacy drain order, then an actual TurnStarted **or** first EncounterEnded, if either occurred |
| EndTurn | actual TurnStarted or first EncounterEnded; no ActionResolved |
| despawn | Despawned, then actual TurnStarted or first EncounterEnded |
| tick | currently none; tick still advances through the existing system list |
| end_encounter | none; explicit release/abort is not natural completion |

ActionResolved uses the returned ActionOutcome, including legal failure and
reported (possibly overkill) damage. Outcome text is exactly `critical_success`,
`success`, `failure`, `critical_failure`, or `custom:<n>` for Custom(u8), with
decimal n and no leading zeros. It never carries roll/margin/DC internals.
Terminal means first active-Some → active-None, or implicit release on removal
of the last participant of a previously nonterminal encounter. Removing the last
participant from an already terminal encounter emits no second end. Capture
encounter/round before last-participant removal. Do not alter the legacy rule
that despawning a non-active participant can leave the active turn unchanged.

### Reader, acknowledgement and bounds

New state: acknowledged=0, next_seq=1, pending empty. Issuable sequences are
1..=u64::MAX-1; u64::MAX is the exhausted next-sequence sentinel. Last sequence
is next_seq-1 even after acknowledgement. Reserve an entire operation's range
with checked arithmetic; partial append is forbidden. An operation emitting no
events still succeeds at sequence exhaustion.

Pending entries are exactly the contiguous suffix `(acknowledged, next_seq)`.
`read_after` checks limit 1..=256, then after<ack (StaleCursor), then after>last
(FutureCursor); returns up to limit cloned envelopes with seq>after, in order.
after==last returns empty. Reading is inert; it grants no automatic ack.
`acknowledge` rejects through>last; through<=ack is an idempotent no-op (not a
stale error); otherwise removes the prefix through that sequence and advances
ack. It may acknowledge unread events because capture is the host's obligation,
not an extra persisted "last read" cursor. One consumer, T022, captures before
acknowledging and fans out independently of the journal. No slow-peer cursor here.

Pending byte accounting is the checked sum of each envelope's compact
`serde_json::to_vec` length, with struct declaration order and existing core
serde; no Vec brackets/commas. Both 4096 and 1 MiB caps apply inclusively. A
bounded counting serializer may avoid temporary encoded allocation; never
redefine canonical accounting. Pending byte count is derived, not persisted.
With the present short outcome vocabulary the byte cap may be redundant under
the count cap. Test it via valid synthetic core-closed event payloads at load
boundaries if reachable; otherwise prove the tighter maximum, rather than add
a fake string-producing gameplay operation just for a test.

### Persistence and full hash

Wrapper JSON field order: `version`, `world`, `acknowledged`, `next_seq`,
`pending`. No omitted/default wrapper fields. Version is integer 1. Pending
envelopes use `tick`, `seq`, `payload`; payload uses serde adjacent tagging
`{"type":"spawned","value":{"entity":...}}`, snake-case variant names and
payload field order from the enum above. No external raw sim enum serialization.

For adjacent-tag payload objects, `type` must precede `value` on input as it
does on output. Reject `value` before `type` immediately, without deserializing
or buffering its value. Decode the selected payload directly with a bounded
visitor/seed; do not use an intermediate `serde_json::Value` or Serde content
buffer. Other wrapper, envelope and payload field order is unrestricted on
input; serialization always uses the canonical order above.

Reject duplicate/unknown/missing wrapper, envelope and payload keys, unknown
version/tag, over-limit string/count/byte shapes, noncontiguous or out-of-range
sequences, ack>=next, next=0, decreasing event ticks, ticks after World tick,
nonempty inner World queue and any World load error. Historical entity references
may legitimately name despawned generations; do not require current liveness.
Validate history outcome strings against the symbolic vocabulary above. Bound
retained journal storage and collection growth with visitors: do not trust
collection size hints or deserialize an unbounded Vec and then count it. Reject
an excess entry before decoding its envelope, check decoded string byte length
before copying it into retained journal storage, and check canonical byte totals
incrementally before retaining each envelope. The 256-byte string cap and journal
caps bound retained history, not all transient allocations inside an arbitrary
Serde deserializer. In particular, serde_json may allocate scratch storage for
an escaped string before invoking the string visitor; generic `Deserialize`
cannot impose a parser-wide memory bound.

T022 must specify and enforce a finite checkpoint input-byte cap before invoking
JSON parsing (and separate compressed/decompressed caps if compression is used),
including for reader-based input. This is a mandatory host loading boundary,
not an optional check after deserialization. Parser scratch is bounded by that
input budget, not by the sim journal string cap. The full World is not capped
by the journal budget; its checkpoint input shares the host byte limit. T020
does not claim globally bounded parsing memory from `Deserialize` alone.

`history_hash` is BLAKE3 over compact wrapper JSON in that exact field order,
after the same transform-finiteness guard as state_hash. Includes World, version,
pending payloads, sequence and ack state, with no exclusions. No opaque hash of
World substituted for the serialized World. Existing state_hash remains exactly
unchanged; its result is not called the full-authority hash in new mode.
