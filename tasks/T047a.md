# T047a — host read API: `legal_intents` and `replica_id` (`crpg-server`)

## Task / Crate(s) / Purpose

Sole crate: `crpg-server`, plan row `docs/IMPLEMENTATION_PLAN.md:250`
(`C → I`). Add the two read-only trusted methods ADR-0033 §7 fixes
(`docs/adr/0033-godot-bridge.md:170-206`, follow-on `:510-512`) so T047 can
offer a player-only option list and build its `NetId`↔`EntityId` table
(`:234-249`) without a second legality source, wire or label. Contract only.

## Exact contract

Status: **approved 2026-11-02 by the user** (H-approved). ADR-0033
is accepted (D41d, 2026-11-02); this pins §7 against the code and changes no
decision. Prerequisites on this branch: `Host` (T022), the session
map/grants/control and `crpg_sim::legal_actions` (T028).

### Decision

- **D1. Placement.** `LegalIntent` is a public value type in
  `crates/crpg-server/src/host.rs`, immediately after `DeliveryEntry`
  (`host.rs:192-202`). Both methods go in the read-only accessor block after
  `is_closed` (`host.rs:650-653`), before the `pub(crate) history` accessor.
  The private mapper `legal_body` goes immediately after `resolve_action`
  (`host.rs:2228-2254`), beside the rule it mirrors.
  `lib.rs` is unchanged: `host` is already `pub mod host` (`src/lib.rs:37`).
- **D2. Shape is the ADR's, verbatim.** `LegalIntent { actor: NetId, body:
  IntentBody }` derives `Debug, Clone, Copy, PartialEq, Eq`; both methods are
  `&self`. `IntentBody`/`NetId` reach it from `crpg_net::protocol`
  (`host.rs:36-40`), `PeerHandle` and `HostError` are module-local
  (`:120-129`, `:320-394`), `EntityId` comes from `crpg_core` (`:31`).
  The one import change is adding `legal_actions` and `LegalActionsError` to
  the `crpg_sim` use list (`host.rs:47-50`). No new module, re-export or
  dependency.
- **D3. No new state.** The methods read `self.sessions` and
  `self.history.world()` only; no map, cache, counter or ledger is added
  (crate invariant 6, `crates/crpg-server/AGENTS.md:66-68`).
- **D4. One legality source.** `legal_intents` calls
  `crpg_sim::legal_actions(world, active)` once. It copies neither
  `validate_action` nor any ability/target/affordability rule
  (`crates/crpg-sim/AGENTS.md` invariant 12). Its only filtering mirrors
  `resolve_action`'s mapping, control and disclosure checks, which admission
  already applies.
- **D5. Errors stay in `HostError`.** No variant is added. The only new
  values are `Closed`, `UnknownPeer` and the pinned
  `Invariant("legal options exceed their bound")`.

### Interface (`crates/crpg-server/src/host.rs`)

```rust
use crpg_core::EntityId;
use crpg_net::protocol::{IntentBody, NetId, /* existing items */};
use crpg_sim::{legal_actions, LegalActionsError, /* existing items */};

/// One action `peer` may request now, in that peer's replica ids.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct LegalIntent {
    /// The acting entity, in `peer`'s replica ids.
    pub actor: NetId,
    /// The wire verb and its ids, ready for `IntentFrame.body`.
    pub body: IntentBody,
}

impl Host {
    pub fn legal_intents(&self, peer: PeerHandle) -> Result<Vec<LegalIntent>, HostError>;
    pub fn replica_id(&self, peer: PeerHandle, entity: EntityId)
        -> Result<Option<NetId>, HostError>;
}

/// `resolve_action`'s mapping/ownership/disclosure test for one sim action;
/// `None` drops it. The actor is the L3-eligible `active`.
fn legal_body(session: &Session, action: &CombatAction) -> Option<IntentBody>;
```

Every public item is documented (`src/lib.rs:2`). `Host` is neither `Clone`
nor `Copy` (`host.rs:518-524`); no client object exists here.

### Behaviour

1. **L1 — common prelude, exact order.** Both methods start with
   `if self.closed { return Err(HostError::Closed); }`, then
   `let session = self.sessions.get(&peer).ok_or(HostError::UnknownPeer)?;`
   (as `Host::epoch`, `host.rs:622-627`); nothing precedes them. `shutdown`
   clears `sessions` before setting `closed` (`host.rs:1965-1989`, `:1985`,
   `:1987`), so after it every handle, bound or not, is `Closed`, never
   `UnknownPeer`.
2. **L2 — no active head.** With the session in hand,
   `let Some(active) = self.history.world().combat().and_then(|c| c.active)
   else { return Ok(Vec::new()) };` (`HistoryWorld::world`,
   `crates/crpg-sim/src/history.rs:489`; `World::combat`,
   `crates/crpg-sim/src/world.rs:1109`; `CombatState.active`,
   `crates/crpg-sim/src/combat.rs:816-822`). This covers no-encounter,
   terminal and real-time state: RT publication sets `active = None`
   (`combat.rs:2160-2175`) and an RT switch clears it (`:3869-3877`).
3. **L3 — ineligible active head.** Return `Ok(Vec::new())` if
   `session.control.binary_search(&active).is_err()` (sorted/deduped by
   `normalize_control`, `host.rs:2120-2128`, checked as `resolve_action`
   does at `:2236`); or `session.map.get(&active)` is `None` (`map` is the
   live `EntityId → NetId` map, `host.rs:456`, installed at `:485-489`,
   built by `plan_map` `:2200-2226`); or `lookup(&session.grants, active)`
   is not `Some` with `present && action_actor` (as `:2231-2235`, `lookup`
   `:2168-2174`). Otherwise `actor_net = session.map[&active]`.
4. **L4 — enumerate once, keep sim order.** Call
   `legal_actions(self.history.world(), active)` exactly once
   (`crates/crpg-sim/src/combat.rs:3157-3228`, exported at
   `crates/crpg-sim/src/lib.rs:35`). `Ok(list)` is traversed in list order;
   no sort, dedup or reordering. Errors map exactly:
   `LegalActionsError::Actor(_) => Ok(Vec::new())`;
   `LegalActionsError::TooManyOptions { .. } =>
   Err(HostError::Invariant("legal options exceed their bound"))`.
   Never truncate a partial list; the whole query already failed
   (`combat.rs:3122-3134`). `Actor(_)` is not reachable through L2/L3: the
   active head is always a live, scheduled, non-dead combatant — start
   publishes the timeline head (`combat.rs:2158-2180`), an advance publishes
   a live head or clears (`:3742`, `:3757`), and removing the head advances
   or releases (`world.rs:981-990`) — so `EndTurn { active }` passes every
   clause of `combat.rs:2986-3011`, and RT returns at L2. The arm stays as
   the ADR's mapping.
5. **L5 — mapping, ownership and disclosure filter.** For each returned
   `CombatAction`, `legal_body` returns the body below, or `None` to drop it.
   The filter never returns an error.

   | `CombatAction` | Kept when | `IntentBody` |
   |---|---|---|
   | `UseAbility { actor, ability, target }` | `session.map.get(&target)` is `Some` and `lookup(grants, target)` is `present && action_target` | `DeclareAction { ability, target: session.map[&target] }` |
   | `EndTurn { actor }` | always (the L3 `actor` checks are the only ones `resolve_action` applies) | `EndTurn` |
   | `Stop { actor }` | never: no wire verb exists (`IntentBody` is only `DeclareAction` and `EndTurn`, `crates/crpg-net/src/protocol.rs:268-279`) | omitted |

   `actor` on every kept `LegalIntent` is `actor_net`; the action's actor is
   always `active`, already eligible by L3. `resolve_action` (`:2230-2253`)
   looks the target up by the frame's `NetId` in `reverse` and requires
   `present && action_target` (`:2240-2250`); `CombatAction` carries the
   `EntityId`, so `legal_body` tests the same pair through `map`, which
   `install_map` makes the exact inverse of `reverse` in one step
   (`host.rs:485-489`), and `session.map[&target]` is the id to declare.
   There is **no**
   `grants.abilities` check: `resolve_action` has none; ability grants govern
   disclosure, not admission, and adding one would drop an admissible option.
   A kept `UseAbility` therefore names a
   mapped, granted target, and `EndTurn` needs only the L3 facts, so
   submitting any kept option at that instant cannot draw `NotAuthorized`
   (`:1110-1113`). Epoch, seq, rate, freshness and later state are the
   caller's problem; options confer no authorization
   (`crates/crpg-sim/src/combat.rs:3173-3176`). `Stop` is unreachable (RT has
   `active = None`, L2), but the exhaustive match keeps the arm so a future
   sim variant cannot be silently mapped.
6. **L6 — `replica_id`, exact.** After the L1 prelude,
   `Ok(session.map.get(&entity).copied())`. `map` holds exactly the entities
   the last installation left: its `present && world.contains` set (`plan_map`,
   `host.rs:2200-2226`; at bind `:736`, `set_grants` `:830`, snapshot
   narrowing `:1631`). Therefore:
   - full grants on the fixture: `a → 1`, `b → 2`, `c → 3`
     (`plan_map` mints in ascending `EntityId` order, `:2207-2222`);
   - absent from those grants, `present: false` then, or not live then is
     `Ok(None)`, never an error;
   - a dead combatant is still live and mapped: `Some` (death is not removal);
   - an entity despawned after installation keeps its id until the next
     bind/`set_grants`: `Some`. The map is a snapshot, not a liveness query,
     and the replica drops the row only when it applies the removal. It
     cannot contradict item 4: a despawned entity can never be
     `combat.active`, so a stale `Some` never reaches `legal_actions`, and
     one declared as a target fails `validate_action` as `IllegalAction`
     (`AbsentTarget`, `combat.rs:3027-3029`), not `NotAuthorized`. Do **not**
     add a `world.contains` check: it would disagree with the map L3 and
     admission use.
   No other error is possible: only L1's `Closed`/`UnknownPeer`.
7. **L6 — nothing moves.** Both methods are `&self` and call only
   `sessions.get`, `history.world` and `legal_actions` (read-only,
   `combat.rs:3157-3176`); no mutating path (`ingest`, `pump`, `bind`/
   `unbind_peer`, `set_grants`/`set_control`, `tick`, `shutdown`,
   `acknowledge_*`, `try_resync`, `cache_insert`, `push_frames`, receipts).
   The state that must not move is:
   - `Host` (`host.rs:524-544`): `history` (the authority), `closed`,
     `last_now_ms`, `next_handle`, `sessions`, `ingress`/`ingress_bytes`,
     `egress_bytes`, `executions`, `last_combat_error`, `captures`/
     `capture_lens`/`capture_bytes`, `capture_acknowledged`, `last_capture`;
     the caps and `rates` are configuration.
   - each `Session` (`host.rs:452-482`): `epoch`, `control`, `grants`, `map`,
     `reverse`, `next_net`, `next_new_seq`, the retry `cache`/`cache_bytes`,
     the four rate tokens `intent_frames`/`intent_bytes`/`fail_frames`/
     `fail_bytes`, the ingress counters, the delivery `log`/`log_bytes`/
     `next_event_seq`/`delivered`/`next_ordinal`/`next_transfer`/`in_flight`,
     and `generation`/`resync_pending`/`snapshot`.

   `authority_hash` is unchanged (it is `history_hash`, `host.rs:641-643`).
   The tests below prove each observable class: both intent rate buckets, the
   failure-frame bucket and the clock. The failure-byte bucket is unobservable
   at v1 caps (ten failure receipts are far below the 4 KiB burst, and a spent
   frame burst hides the drop), so no test claims it; the methods never call
   `try_consume_failure` (`host.rs:2098-2103`), the only spend.

### Tests (new `crates/crpg-server/tests/host_legal.rs`)

No new dependency, no fixture change: the file and fixture ADR-0033 names
(`docs/adr/0033-godot-bridge.md:656`). The existing setup: `include_str!("fixtures/three_combatants.json")` loaded through
sim's validated `Deserialize` plus `acknowledge(last_sequence())` (as
`tests/audit_gaps.rs:13,67-71`); `Host::from_history(fixture(), HostConfig
{ protocol: V2, incarnation: 1 }, 0)`; `a/b/c = EntityId(index 0/1/2,
generation 1)` via `serde_json` and `strike/smite/whiff =
Ulid::from_u128(603/604/605)`; `full`, `full_grants` (those three
abilities), `control`, `all_actors` (`tests/host_capture.rs:81-93,
130-187`). Intents are hand-encoded (`tests/audit_gaps.rs:73-113`). The
active head is `a`; its hand-written list is `JV→b, JV→c, JW→b, JW→c,
JX→b, JX→c, EndTurn`, with `a=1, b=2, c=3`. A separately loaded
`HistoryWorld` through `crpg_sim::legal_actions` is the oracle for that
list, never the filter's source. Every negative case has a positive
control; (4b)'s `crowd` value is built in memory, never written to disk.

- **L1 (1). Precedence.** Bind `p1` and `p2`; both methods succeed on `p1`.
  After `unbind_peer(p2)` both are `Err(UnknownPeer)` for `p2`; after
  `shutdown()`, both are `Err(Closed)` for `p1` (bound at shutdown) and `p2`
  (unbound at shutdown). *Control:* before shutdown `p2` gives
  `UnknownPeer`, so `Closed` first is observed, not assumed.
- **L2 (2). No active head.** `Host::new(7, config, 0)` (no encounter), bind,
  both methods: `legal_intents == Ok(vec![])` and
  `replica_id(peer, a()) == Ok(None)` (there is no entity to map).
  *Control:* the fixture host with active `a` returns a non-empty list and
  maps `a`. Terminal and RT reach the same branch; a scripted fight to
  terminal would only test sim.
- **L3 (3). Ineligible active.** Three separate hosts, each otherwise
  identical: control `[b]` (active not controlled); grants of `b,c` only
  (active not mapped); grants of `a,b,c` with `a.action_actor = false`
  (present but not admissible as actor). Each gives `Ok(vec![])`.
  *Control:* full control and grants give L4's exact list.
- **L4 (4). Exact list and order.** With full control/grants the result is
  exactly the seven hand-written `LegalIntent`s above, order included, and
  equals the hand-mapped oracle list from `crpg_sim::legal_actions`. A
  partial grant (`c.action_target = false`) yields
  `JV→b, JW→b, JX→b, EndTurn` — relative order preserved. *Control:* full
  grants restore the three dropped options.
- **L4b (4). `TooManyOptions` through the public host.** A test-only
  `crowd(participants, abilities)` clones the fixture `serde_json::Value`,
  appending arena slots, combatants (cloned from `a`, distinct placement
  `Ulid`), timeline rows above the head, and abilities with fresh `Ulid`s;
  it sets `allow_self_target = true` on every ability (the fixture's are
  false, one target fewer). It loads through sim's validated `HistoryWorld`
  `Deserialize`, is acknowledged, and enters `Host::from_history`. `crowd(1024, 4)`
  (`MAX_COMBATANTS`, `combat.rs:51`) enumerates 4 × 1024 accepted
  `UseAbility`s, making `EndTurn` the 4,097th accepted candidate
  (`combat.rs:3206-3226`): with only `a` granted and controlled (the query
  fails before mapping), `legal_intents` is exactly
  `Err(HostError::Invariant("legal options exceed their bound"))`, and
  `authority_hash`, `executions` and the delivery log are unchanged.
  *Control:* `crowd(819, 5)` is 5 × 819 + `EndTurn` = exactly 4,096, and
  with `a.action_target = false` (so L5 keeps only `EndTurn`)
  `legal_intents` is `Ok(vec![LegalIntent { actor:
  NetId::new(1).expect("nonzero"), body: IntentBody::EndTurn }])` — the
  bound, not the count, produced the error.
  `crowd`'s arguments are **totals**, fixture rows included: `participants`
  combatants in all, and `abilities` abilities in all. To load, it must also
  set the top-level `combat.definition.allow_self_target = true`, so the
  legacy ability agrees (`world.rs:395-430`). Appended ability `Ulid`s sort
  strictly after the fixture's last one (JX), keeping `definition.abilities`
  ascending (`world.rs:357-363`). Each cloned combatant gets a distinct
  placement, and timeline keys that rise strictly above the head, so `active`
  stays the head.
- **L5 (5). Kept ⇒ not `NotAuthorized`; refused ⇒ dropped.** Three filters,
  each with a control. (a) Full grants: each kept option on a fresh host,
  one `IntentFrame` (that host's epoch, `seq 1`,
  `observed_tick = server_tick()`, exactly `option.actor`/`option.body`),
  `ingest` + `pump`: never `Rejected(NotAuthorized)`; here each is
  `Applied`, recorded beside the inequality. (b)
  `c.action_target = false` (c stays mapped): the list is
  `JV→b, JW→b, JX→b, EndTurn`, each kept option is `Applied` on a fresh
  host, and the hand-built `DeclareAction { strike, target: 3 }` is
  `Rejected(NotAuthorized)` because the grant refuses `action_target`. (c)
  Target absent from the map: grants of `a` and `b` only, so c has no `NetId`
  and the list is the same four; each kept option is `Applied`, and
  `DeclareAction { strike, target: 3 }` is `Rejected(NotAuthorized)` because
  `reverse.get(&3)` is `None`. *Control:* the full-grant host lists the
  three `c` options and accepts that intent as `Applied`, so both omissions
  are grant-/map-caused. `Stop` is unreachable (L2); its arm is the
  exhaustive match, not this file.
- **L6a (7). Observable invariance.** Bind, send one `EndTurn` for `a`,
  `pump`. Snapshot `authority_hash`, `executions`, `server_tick`,
  `incarnation`, `protocol`, `is_closed`, `last_combat_error`,
  `last_capture`, `capture_acknowledged`, `read_captures(0, 64)`,
  `epoch(peer)`, `cached_status(peer, 1)`, `transfer_state(peer)` and
  `take_delivery_entries(peer)`. Call `legal_intents(peer)` and
  `replica_id(peer, a())` 100 times each; all compare equal.
  *Control:* one `pump` of a new valid intent for the new active head
  (`EndTurn` for `b`) changes `authority_hash`, `executions` and the
  captures, so the comparison is not vacuous.
- **L6b (7). Intent frame bucket.** Bind at `now_ms = 0`; ingest 79 frames
  (any bytes ≤ `MAX_INTENT_FRAME_BYTES`; ingest does not decode) → 79
  `Staged`; call both 10 times; the 80th is `Staged`; the 81st is
  `Refused(RateLimited)`. *Control:* a read-free host gives the identical
  80/1 sequence; a token spent by either read would make the 80th
  `RateLimited`.
- **L6c (7). Intent byte bucket.** Bind at 0; ingest 31 frames of exactly
  4096 bytes (126,976 of the 131,072-byte burst) → all `Staged`; call both
  10 times each; the 32nd 4096-byte ingest is `Staged` — one byte
  spent by either read would leave 4,095 and make it
  `Refused(RateLimited)` (`host.rs:923-929`) — then a 33rd 1-byte ingest is
  `Refused(RateLimited)` while the frame bucket (33 of 80) has room.
  *Control:* the same host without the reads gives the identical 32/1
  sequence.
- **L6d (7). Failure frame bucket.** Two identically built hosts at 0. Bind
  with full grants; the bind stages one 7-op full-state frame (3
  `EntityEnter` + 3 health + 1 turn, `host.rs:2436-2457`, under
  `MAX_DELTA_OPS` 256), so take it and `acknowledge_delivery(peer, 1)` as
  `tests/host_capture.rs:611-626` drains before the burst at `:2313-2331`;
  otherwise the unacknowledged log (`host.rs:1695-1714`) still holds it and
  the count is wrong. For
  `seq` 1..=11: the probe calls both reads, then ingests one `NotAuthorized`
  intent (actor NetId 99, valid epoch, tick 0) and pumps; the control ingests
  and pumps only. Both sum to `admitted = rejected = 11`,
  `dropped_replies = 1`, every `cached_status` is
  `Rejected(NotAuthorized)`, and `take_delivery_entries` returns exactly 10
  entries at ordinals 2..=11 (the receipts less the one dropped at the burst
  of 10). A failure token spent by a read would drop the 10th receipt and
  give `dropped_replies = 2`. *Control:* the read-free run.
- **L6e (7). Clock and handles.** Build with `now_ms = 500`, bind, call both
  reads; `pump(500)` is `Ok` with an empty summary and `pump(499)` is
  `Err(TimeRegression)`; `ingest(peer, &[], 499)` is `Err(TimeRegression)`.
  Then `bind_peer` returns handle 2, whose epoch's high half is the
  incarnation and low half 2. This pins `last_now_ms == 500`
  both ways and leaves `next_handle`/`sessions` for the second bind, the only
  mover here. *Control:* that bind.
- **L7 (6, interface). `replica_id` mapping.** Full grants: `a→Some(1)`,
  `b→Some(2)`, `c→Some(3)`; `EntityId(index 99)` → `Ok(None)`; grants
  without `a` → `Ok(None)` for `a`, while `b` is still `Some` (compare with
  `replica_id(b)`, not a literal: a narrowing from full grants keeps 2);
  `present: false` for `b` → `None`; after a
  narrowing `set_grants` that removes `c`, `replica_id(c) == Ok(None)` and a
  re-widen mints a fresh id rather than reusing 3. *Control:* before
  narrowing each is `Some`, and an unbound peer is L1's `UnknownPeer`.
  The despawned-but-mapped case is stated in item 6; it needs a gameplay
  despawn and is not tested here.

  T047 calls them on its own trusted `Host`.
- Real-time/`Stop` behaviour, terminal scripts, full fights, and tests for
  `Actor(_)`, the failure-byte bucket or the unreachable v1 host-wide caps.
- Any new `HostError` variant, `Display` text, public re-export or dependency.
