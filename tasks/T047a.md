# T047a — host read API: `legal_intents` and `replica_id` (`crpg-server`)

## Task / Crate(s) / Purpose

Sole crate: `crpg-server`, plan row `docs/IMPLEMENTATION_PLAN.md:250`
(`C → I`). Add the two read-only trusted methods ADR-0033 §7 fixes
(`docs/adr/0033-godot-bridge.md:170-206`, follow-on `:510-512`) so T047 can
offer a player-only option list and build its `NetId`↔`EntityId`
presentation table (`docs/adr/0033-godot-bridge.md:234-249`) without a second
legality source and without a wire or label. This task is the contract only.

## Exact contract

Status: **proposed 2026-11-02** for user approval. ADR-0033 is accepted
(D41d, 2026-11-02); this document pins §7 against the code and changes no
decision. Prerequisites already on this branch: `Host` (T022), the session
map/grants/control, and `crpg_sim::legal_actions` (T028).

### Decision

- **D1. Placement.** `LegalIntent` is a public value type in
  `crates/crpg-server/src/host.rs`, immediately after `DeliveryEntry`
  (`host.rs:192-202`). Both methods go in the read-only accessor block after
  `is_closed` (`host.rs:650-653`), before the `pub(crate) history` accessor.
  The private mapper `legal_body` goes immediately after `resolve_action`
  (`host.rs:2228-2254`), where its mirror rule is readable in one place.
  `lib.rs` is unchanged: `host` is already `pub mod host` (`src/lib.rs:37`).
- **D2. Shape is the ADR's, verbatim.** `LegalIntent { actor: NetId, body:
  IntentBody }` derives `Debug, Clone, Copy, PartialEq, Eq`; both methods are
  `&self`. `IntentBody` and `NetId` already reach the module from
  `crpg_net::protocol` (`host.rs:36-40`); `PeerHandle` is defined in the
  module (`host.rs:120-129`); `EntityId` comes from `crpg_core`
  (`host.rs:31`); `HostError` is defined in the module (`host.rs:320-394`).
  The one import change is adding `legal_actions` and `LegalActionsError` to
  the `crpg_sim` use list (`host.rs:47-50`). No new module, re-export or
  dependency.
- **D3. No new state.** The methods read `self.sessions` and
  `self.history.world()` only. No map, cache, counter or ledger is added
  (crate invariant 6, `crates/crpg-server/AGENTS.md:66-68`).
- **D4. One legality source.** `legal_intents` calls
  `crpg_sim::legal_actions(world, active)` once. It copies neither
  `validate_action` nor any ability/target/affordability rule
  (`crates/crpg-sim/AGENTS.md` invariant 12). Its only filtering mirrors
  `resolve_action`'s mapping, control and disclosure checks, which admission
  must already apply to a submitted frame.
- **D5. Errors stay in `HostError`.** No variant is added. The only new
  values are `Closed`, `UnknownPeer` and the pinned
  `Invariant("legal options exceed their bound")`.

### Interface (`crates/crpg-server/src/host.rs`)

```rust
use crpg_core::EntityId;
use crpg_net::protocol::{IntentBody, NetId, /* existing items */};
use crpg_sim::{legal_actions, LegalActionsError, /* existing items */};

/// One action `peer` may request now, in that peer's replica ids.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct LegalIntent {
    /// The acting entity, in `peer`'s replica ids.
    pub actor: NetId,
    /// The wire verb and its ids, ready for `IntentFrame.body`.
    pub body: IntentBody,
}

impl Host {
    pub fn legal_intents(&self, peer: PeerHandle) -> Result<Vec<LegalIntent>, HostError>;
    pub fn replica_id(&self, peer: PeerHandle, entity: EntityId)
        -> Result<Option<NetId>, HostError>;
}

/// `resolve_action`'s mapping/ownership/disclosure test, applied to one sim
/// action; `None` drops it. The action's actor is the active entity, already
/// eligible by L3.
fn legal_body(session: &Session, action: &CombatAction) -> Option<IntentBody>;
```

Every public item and field is documented (`src/lib.rs:2`,
`#![warn(missing_docs)]`). The methods are on `Host`, which is neither
`Clone` nor `Copy` (`host.rs:518-524`); no client object exists in this crate.

### Behaviour

1. **L1 — common prelude, exact order.** Both methods start with
   `if self.closed { return Err(HostError::Closed); }`, then
   `let session = self.sessions.get(&peer).ok_or(HostError::UnknownPeer)?;`
   (the same binding lookup as `Host::epoch`, `host.rs:622-627`). Nothing
   else precedes them. `shutdown` clears `sessions` and then sets
   `closed` (`host.rs:1965-1989`, clears at `:1985`, sets at `:1987`), so the
   first check cannot be reversed: after shutdown every handle, bound or
   not, is `Closed`, never `UnknownPeer`.
2. **L2 — no active head.** With the session in hand:
   `let Some(active) = self.history.world().combat().and_then(|c| c.active)
   else { return Ok(Vec::new()) };`
   (`HistoryWorld::world` at `crates/crpg-sim/src/history.rs:489`;
   `World::combat` at `crates/crpg-sim/src/world.rs:1109`; `CombatState.active`
   at `crates/crpg-sim/src/combat.rs:816-822`). This is every no-encounter,
   terminal and real-time state: the publication sets `active = None` for RT
   (`combat.rs:2160-2175`), and an RT switch clears it (`:3869-3877`).
3. **L3 — ineligible active head.** Return `Ok(Vec::new())` if any of:
   (a) `session.control.binary_search(&active).is_err()` — control is sorted
   and deduped by `normalize_control` (`host.rs:2120-2128`) and checked the
   same way by `resolve_action` (`:2236`); (b) `session.map.get(&active)` is
   `None` — `map` is the peer's live `EntityId → NetId` map (`host.rs:456`,
   installed at `:485-489`, built by `plan_map` at `:2200-2226`); or
   (c) `lookup(&session.grants, active)` is not `Some` with
   `present && action_actor` — the same predicate and inclusive fields as
   `resolve_action`'s first check (`:2231-2235`, `lookup` at `:2168-2174`).
   Otherwise let `actor_net = session.map[&active]`.
4. **L4 — enumerate once, keep sim order.** Call
   `legal_actions(self.history.world(), active)` exactly once
   (`crates/crpg-sim/src/combat.rs:3157-3228`, exported at
   `crates/crpg-sim/src/lib.rs:35`). `Ok(list)` is traversed in list order;
   no sort, dedup or reordering. Errors map exactly:
   `LegalActionsError::Actor(_) => Ok(Vec::new())`;
   `LegalActionsError::TooManyOptions { .. } =>
   Err(HostError::Invariant("legal options exceed their bound"))`.
   Never truncate a partial list; the whole query already failed
   (`combat.rs:3122-3134`). `Actor(_)` is not reachable through L2/L3: a
   live, scheduled, non-dead active head makes `EndTurn { active }` valid
   (`combat.rs:2986-3011`), and RT returns at L2. The arm stays as the ADR's
   mapping, not as dead code to remove.
5. **L5 — mapping, ownership and disclosure filter.** For each returned
   `CombatAction`, `legal_body` returns the body below, or `None` to drop it.
   The filter never returns an error.

   | `CombatAction` | Kept when | `IntentBody` |
   |---|---|---|
   | `UseAbility { actor, ability, target }` | `session.reverse.get(&target)` is `Some` and `lookup(grants, target)` is `present && action_target` | `DeclareAction { ability, target: session.map[&target] }` |
   | `EndTurn { actor }` | always (the L3 `actor` checks are the only ones `resolve_action` applies) | `EndTurn` |
   | `Stop { actor }` | never: no wire verb exists (`IntentBody` is only `DeclareAction` and `EndTurn`, `crates/crpg-net/src/protocol.rs:268-279`) | omitted |

   `actor` on every kept `LegalIntent` is `actor_net`. `actor` in the table is
   always `active`; `resolve_action` (`:2230-2253`) looks the actor up in
   `reverse`, requires `present && action_actor`, then control — all already
   true at L3. For `UseAbility` it additionally looks the target up in
   `reverse` and requires `present && action_target` (`:2240-2250`), which is
   exactly the kept-test above. There is **no** check of
   `grants.abilities`: `resolve_action` has none, and ability grants govern
   event disclosure, not intent admission; adding one here would drop an
   option the same frame would be admitted with. Because a kept `UseAbility`
   has a target in `reverse` with the right grant, and `EndTurn` needs only
   the L3 facts, submitting any kept option at that instant cannot draw
   `NotAuthorized` (`:1110-1113`). That is the whole guarantee: epoch, seq,
   rate, freshness and later state changes are the caller's problem, and
   options confer no authorization (`crates/crpg-sim/src/combat.rs:3173-3176`).
   `Stop` is unreachable today because RT has `active = None` (L2), but the
   exhaustive match must still carry the arm so a future sim variant cannot
   be silently mapped.
6. **L6 — `replica_id`, exact.** After the L1 prelude,
   `Ok(session.map.get(&entity).copied())`. `map` holds exactly the entities
   whose normalized `EntityDisclosure.present` was true when the map was last
   installed and which were live in the world then (`plan_map`,
   `host.rs:2200-2226`; called at bind `:736`, `set_grants` `:830`, snapshot
   narrowing `:1631`). Therefore:
   - full grants on the fixture: `a → 1`, `b → 2`, `c → 3`, because
     `plan_map` mints in ascending `EntityId` order (`:2207-2222`);
   - an entity absent from the grants, with `present: false`, or absent when
     the map was installed is `Ok(None)`, never an error;
   - a dead combatant is still live and mapped: `Some` (death is not removal);
   - an entity despawned after the map was installed keeps its id until the
     next bind/`set_grants`: `Some`, matching L3's "not in its map" test and
     the replica, which removes the row only when it applies the removal.
     Do **not** add a `world.contains` check here: it would disagree with the
     map L3 and admission use.
   No other error is possible: only L1's `Closed`/`UnknownPeer`.
7. **L6 — nothing moves.** Both methods are `&self` and call only
   `sessions.get`, `history.world` and `legal_actions` (documented read-only,
   `combat.rs:3157-3176`). They never reach `ingest`, `pump`, `bind`,
   `unbind_peer`, `set_grants`, `set_control`, `tick`, `shutdown`,
   `acknowledge_*`, `try_resync`, `cache_insert`, `push_frames` or any
   receipt path. The complete state that must not move is:
   - `Host` (`host.rs:524-544`): `history` (authority), `closed`,
     `last_now_ms`, `next_handle`, `sessions`, `ingress`, `ingress_bytes`,
     `egress_bytes`, `executions`, `last_combat_error`, `captures`,
     `capture_lens`, `capture_bytes`, `capture_acknowledged`, `last_capture`;
     the caps and `rates` are configuration.
   - each `Session` (`host.rs:452-482`): `epoch`, `control`, `grants`, `map`,
     `reverse`, `next_net`, `next_new_seq`, `cache`, `cache_bytes`,
     `intent_frames`, `intent_bytes`, `fail_frames`, `fail_bytes`,
     `ingress_frames`, `ingress_bytes`, `log`, `log_bytes`, `next_event_seq`,
     `delivered`, `generation`, `resync_pending`, `snapshot`, `next_ordinal`,
     `next_transfer`, `in_flight`.

   `authority_hash` is unchanged (it is `history_hash`, `host.rs:641-643`).
   The tests below prove each observable class, including both intent rate
   buckets, the failure-frame bucket and the clock; the failure-byte bucket
   is unobservable at v1 caps (10 failure receipts at the burst of 10 cost
   well under the 4 KiB byte burst, and after the frame burst is spent the
   drop hides the byte budget), so no test claims it — the read methods never
   call `try_consume_failure` (`host.rs:2098-2103`), which is the only spend.

### Tests (new `crates/crpg-server/tests/host_legal.rs`)

No new dependency and no fixture change. This is the file and fixture ADR-0033
names (`docs/adr/0033-godot-bridge.md:656`). The setup is the existing one:
`include_str!("fixtures/three_combatants.json")` loaded through sim's
validated `Deserialize`, then `acknowledge(last_sequence())` (as
`tests/audit_gaps.rs:13,67-71`); `Host::from_history(fixture(),
HostConfig { protocol: V2, incarnation: 1 }, 0)`; `a/b/c = EntityId(index
0/1/2, generation 1)` via `serde_json` (as `tests/host_capture.rs:81-93`);
`strike/smite/whiff = Ulid::from_u128(603/604/605)`; `full`, `full_grants`
(ability list strike/smite/whiff), `control`, `all_actors`
(`tests/host_capture.rs:130-187`). Intents are hand-encoded, not produced by
the codec under test (`tests/audit_gaps.rs:73-113`). The fixture's active
head is `a`; its legal list is hand-written: `JV→b, JV→c, JW→b, JW→c,
JX→b, JX→c, EndTurn`, with `a=1, b=2, c=3`. `crpg_sim::legal_actions` over a
separately loaded fixture `HistoryWorld` is an oracle for that list, never
the source of the production filter. Every negative case has a positive
control.

- **L1 (1). Precedence.** Bind two peers, `p1` and `p2`. Both methods
  succeed on `p1`. After `unbind_peer(p2)` both are `Err(UnknownPeer)` for
  `p2`. After `shutdown()`, both are `Err(Closed)` for `p1` (bound at
  shutdown) and for `p2` (unbound at shutdown).
  *Control:* before shutdown, `p2` gives `UnknownPeer`, so `Closed` first is
  observed, not assumed.
- **L2 (2). No active head.** `Host::new(7, config, 0)` (no encounter), bind,
  both methods: `legal_intents == Ok(vec![])` and
  `replica_id(peer, a()) == Ok(None)` (there is no entity to map).
  *Control:* the fixture host with active `a` returns a non-empty list and
  maps `a`. Terminal and RT reach the same `active: None` branch; a full
  scripted fight to terminal is not required and would only test sim.
- **L3 (3). Ineligible active.** Three separate hosts, each otherwise
  identical: control `[b]` (active not controlled); grants of `b,c` only
  (active not mapped); grants of `a,b,c` with `a.action_actor = false`
  (present but not admissible as actor). Each gives `Ok(vec![])`.
  *Control:* full control and grants give L4's exact list.
- **L4 (4). Exact list and order.** With full control/grants the result is
  exactly the seven hand-written `LegalIntent`s above, order included, and
  equals the hand-mapped oracle list from `crpg_sim::legal_actions`. A
  partial grant (`c.action_target = false`) yields
  `JV→b, JW→b, JX→b, EndTurn` — relative order preserved. *Control:* full
  grants restore the three dropped options. `TooManyOptions` and `Actor(_)`
  are unreachable on this fixture (3 abilities × 3 combatants, 4096 bound);
  the contract does not claim them tested, and no test hook is added.
- **L5 (5). Kept ⇒ not `NotAuthorized`; refused ⇒ dropped.** For every kept
  option, build a fresh identical host, encode one `IntentFrame` with that
  host's epoch, `seq 1`, `observed_tick = server_tick()`, and exactly
  `option.actor`/`option.body`, `ingest`, `pump`: the receipt is **not**
  `Rejected(NotAuthorized)`. On this unchanged fixture every one is also
  `Applied`, so the test records that stronger value beside the required
  inequality. With
  `c.action_target = false`, every `UseAbility` targeting `c` is absent from
  the list; submitting the hand-built `DeclareAction { strike, target: 3 }`
  to a fresh host with those grants gives `Rejected(NotAuthorized)`.
  *Control:* the full-grant host accepts that same intent as `Applied`, so
  the omission is grant-caused. `Stop` is not reachable (L2); its arm is
  covered by the exhaustive match, not by this file.
- **L6a (7). Observable invariance.** Bind, send one `EndTurn` for `a`,
  `pump`. Snapshot `authority_hash`, `executions`, `server_tick`,
  `incarnation`, `protocol`, `is_closed`, `last_combat_error`,
  `last_capture`, `capture_acknowledged`, `read_captures(0, 64)`,
  `epoch(peer)`, `cached_status(peer, 1)`, `transfer_state(peer)` and
  `take_delivery_entries(peer)`. Call `legal_intents(peer)` and
  `replica_id(peer, a())` 100 times each. Every snapshot field compares equal
  afterwards. *Control:* one `pump` of a new valid intent for the new active
  head (`EndTurn` for `b`) changes `authority_hash`, `executions` and the
  captures (the fixture's world tick stays 0; combat actions do not advance
  it), so the comparison is not vacuous.
- **L6b (7). Intent frame bucket.** Bind at `now_ms = 0`; ingest 79 frames
  (any bytes ≤ `MAX_INTENT_FRAME_BYTES`; ingest does not decode) → 79
  `Staged`; call both methods 10 times; the 80th is `Staged`; the 81st is
  `Refused(RateLimited)`. *Control:* a host that skips the reads gives the
  identical 80/1 sequence. A token spent by either read would make the 80th
  `RateLimited`.
- **L6c (7). Intent byte bucket.** Bind at 0; ingest 32 frames of exactly
  4096 bytes (128 KiB, the byte burst) → all `Staged`; call both methods;
  a 33rd 1-byte ingest is `Refused(RateLimited)` while the frame bucket
  still has room. *Control:* the same host without the reads. A byte spent
  by either read would make the 32nd fail.
- **L6d (7). Failure frame bucket.** Two identically built hosts at 0. For
  `seq` 1..=11: on the probe call both reads, then ingest one
  `NotAuthorized` intent (actor NetId 99, valid epoch, tick 0) and pump; on
  the control ingest and pump only. Across the eleven summaries both give
  `admitted = rejected = 11`, `dropped_replies = 1`, 10 delivery entries and
  equal statuses. A failure token spent by a read would drop the 10th
  receipt and give `dropped_replies = 2`. *Control:* the read-free run.
  (The failure-byte bucket is not separately observable; see item 7 and no
  claim is made.)
- **L6e (7). Clock and handles.** Build with `now_ms = 500`, bind, call both
  reads; `pump(500)` is `Ok` with an empty summary and `pump(499)` is
  `Err(TimeRegression)`; `ingest(peer, &[], 499)` is `Err(TimeRegression)`.
  Then `bind_peer` returns a handle with `get() == 2`, whose epoch's high
  half is the incarnation and low half is 2. This pins `last_now_ms == 500`
  in both directions, and `next_handle`/`sessions` unchanged. *Control:* the
  second bind is the only thing in this case allowed to move them.
- **L7 (6, interface). `replica_id` mapping.** Full grants: `a→Some(1)`,
  `b→Some(2)`, `c→Some(3)`; `EntityId(index 99)` → `Ok(None)`; grants
  without `a` → `Ok(None)` for `a`, while `b` is still `Some` (compare with
  `replica_id(b)`, not a literal: a fresh bind numbers `b` 1, a narrowing
  from full grants keeps 2); `present: false` for `b` → `None`; after a
  narrowing `set_grants` that removes `c`, `replica_id(c) == Ok(None)` and a
  re-widen mints a fresh id rather than reusing 3. *Control:* before
  narrowing each is `Some`, and an unbound peer is L1's `UnknownPeer`.
  The despawned-but-mapped case (item 6) is stated in the contract; it needs
  a gameplay despawn and is not a separate read-API test.

  `seq`/`observed_tick` handling (`docs/adr/0033-godot-bridge.md:208-224`).

## Decisions for the user

None. Every L1–L6 line is implementable as written. Two source facts are
recorded rather than decided: `Stop` and `Actor(_)` cannot be produced
through the public host today (RT publishes `active = None`, so L2 returns
first; a live TB active head makes `EndTurn` valid), so those arms exist for
exhaustiveness and are not claimed tested; and the failure-byte budget cannot
be independently observed at v1 caps, so item 7 says exactly what is and is
not proved. No ADR change is requested.
