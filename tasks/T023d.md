# T023d — close delivery when `Closed` is polled at once

## Task / Crate(s) / Purpose

Filed 2026-10-06 by the user's decision on the T023b blocker (a new
one-crate `crpg-net-quic` task, like T023c and T023v, rather than a T023b
workaround). Crate: `crpg-net-quic` only (source, tests, its architecture
doc and `AGENTS.md`).

Purpose: a refused or `Discard`-closed pending connection must deliver its
close code to the peer even when the host polls the `Closed` event in the
same pump. Today the record that carries the close is deleted before the
connection's control task sends it, so the peer times out.

### L§1. Findings (measured)

1. **Mechanism.** `refuse`, and `close` on a pending connection or with
   `CloseMode::Discard`, set `quinn_close` and call `record_close`. A
   pending connection has no lane reader, so `try_publish` pushes `Closed`
   at once. `poll_event` then removes the record when
   `closed_reported || drained()`, and a pending connection is always
   drained. The control task (`lane_control`) finds the close only by
   looking the record up (`conn.quinn_close.take()`); if the record is
   gone it does `Act::Nothing`, so no `CONNECTION_CLOSE` is sent. The
   client hits its connect timeout (`ConnectError::TimedOut`) and the
   server-side quinn connection lingers until its idle timeout.
2. **Why T023 never saw it.** Case `host_refusals_reach_client_exactly`
   joins the client thread before polling `Closed`, so the control task
   always wins.
3. **Reproduction in `crpg-net-quic` alone** (scratch test, public API,
   one server, refusal or `Discard` close with `AuthRefused`, then
   `next_closed` at once, then join the client): **6 / 6** gave
   `Err(TimedOut)` after 10.088–10.097 s (3 × `refuse`, 3 × `close`
   `Discard`). This is deterministic in practice: the poll always wins.
4. **Prototype (L§3) in the same scratch test:** 6 / 6
   `Err(Refused { code: 5 })` after 94–102 ms. The existing `quic` suite
   with the prototype: 28 / 28 passed; `cargo clippy -p crpg-net-quic
   --all-targets --locked -- -D warnings` clean.
5. **Downstream proof.** The prototype applied under T023b's saved
   work-in-progress (local commit `cd23820`, adapter exactly as T023b's
   contract specifies, no workaround): `host_quic` **25 / 25** passed in
   3 of 3 runs (12.39 s, 11.77 s, 12.41 s).
6. **Same mechanism, not reachable through the public API.** An accepted
   connection whose lane reader has already finished (peer FIN or a reader
   failure) and is then closed with `Discard` publishes at once in the same
   way. The L§3 fix covers it by construction; no public-API test can stage
   it (the client has no half-close), see Q4.

### L§2. Decisions this contract makes

- **Release, then remove.** A connection's API lifetime and its record's
  lifetime are separated. The moment the API forgets a connection is
  unchanged (the record-lifetime rule in the architecture doc). The record
  itself is removed only once no task still needs it to send a close.
- No public API change, no new dependency, no change to `Cargo.toml`,
  `Cargo.lock`, the vendored quinn-proto or any other crate.
- Not chosen: sending the close directly from `refuse`/`close` on the
  caller's thread. The control task is today the one place a connection's
  close is sent, ordered after its welcome and any flush. A second sender
  would break that ordering for a smaller diff.

### L§3. Exact change (`src/queue.rs`, `src/server.rs`)

1. `Conn` gains `pub(crate) released: bool` (initialised `false`), doc:
   "Its `Closed` was polled and reported: the API no longer sees it. The
   record stays only until the control task has taken `quinn_close`."
2. `State` gains `pub(crate) fn release(&mut self, id: u64)`: sets
   `released = true`, then removes the record if `quinn_close.is_none()`.
3. `poll_event` and `try_recv` call `state.release(id)` exactly where they
   call `state.conns.remove(&id)` today. Their conditions do not change.
4. `visible` treats a released record as absent:
   `Some(record) if record.phase != Phase::Hello && !record.released`.
   Every public call therefore answers `UnknownConnection` for a released
   connection, exactly as it does today for a removed one.
5. `lane_control`, in the same lock hold where it takes `quinn_close`:
   if the record is released, remove it, then send the close as today.
6. `lane_control` on exit (after setting `control_done`): clear
   `quinn_close` and remove the record if it is released. This covers a
   close requested after the control task's last check.
7. `FailGuard::drop`, after its `record_close`/`reader_finished` loop:
   clear `quinn_close` on every record (no task is left to send it), then
   drop every released record.

The prototype diff that L§1.4–5 measured is these seven points;
the implementer writes it fresh against `master`, and may change names or
comments only if `rustfmt`/clippy require it.

### L§4. Tests (`crates/crpg-net-quic/tests/quic.rs`, public API only)

Append after case 28, with the module header extended by one sentence for
T023d. Waits are the existing 30 s guards, never oracles.

- **Case 29 `refusal_reaches_client_when_closed_is_polled_at_once`.** One
  server. For each of `AuthRefused`, `VersionRefused`, `ServerBusy`:
  connect asynchronously, `next_hello`, `refuse`, then **`next_closed`
  before joining the client**; assert the event is
  `(conn, Local(code))`; assert `try_recv(conn)` and `stats(conn)` are
  `UnknownConnection` straight away; then join and assert
  `Err(Refused { code })`. Positive control on the same server: a fourth
  client is accepted and exchanges one frame each way.
- **Case 30 `pending_discard_close_reaches_client_when_polled_at_once`.**
  As case 29 with `close(conn, AuthRefused, CloseMode::Discard)` on the
  pending connection; the report has `outbound_frames_discarded == 0` and
  `inbound_frames_discarded == 0`. No fourth client: case 29's positive
  control covers the server.
- **Negative control (completion record, not committed).** With L§3
  reverted, cases 29 and 30 fail with `TimedOut`; record the count and
  the times.
- Case 9 of T023b is the downstream test; it is not added here.
