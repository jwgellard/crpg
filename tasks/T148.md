## Task
ADR-0036 C1 (`:277–284`) with S2's `measure` (`:317–325`): a ruleset may
declare
`movement { speed: Length, measure, turn: { pool, step: Length, step_cost } }`.
`Length` is a constant `Fx16_16 > 0` or the name of a declared `Fixed`
stat. `measure` is optional, closed, and v1 has the one value
`"euclidean"`, which is also the default. `pool` names a pool of the
ruleset, `step_cost >= 1`, and a constant speed is within U7
(`MAX_SPEED_PER_TICK_RAW`, `:124`). Absent means "nothing moves". This task
adds the wire types, the read-time checks, one inventory site, one semantic
rule over encounter creatures, and the regenerated ruleset schema. It gives
the data no runtime meaning: T036 (`crpg-sim`) resolves speed and step and
computes cost (M2, C2).

## Readings of the ADR
1. **No version bump.** C1 says "a new `crpg-data` schema version with a
   migration to absence" (`:283–284`). The crate's standing rule, approved
   by the user as D32c and applied by T136a, T136b and T139d, is that an
   optional-missing field whose absence means the old behaviour joins the
   family at its current version with no tag change and no migration edge
   (`crates/crpg-data/AGENTS.md:40–45`). `movement` meets all three
   conditions, so it joins `crpg.ruleset/2`. A tag-only `/2 → /3` step
   would be exactly the "migration to absence" the rule replaces, and would
   cost the count, tag and golden edits D32c avoided
   (`crates/crpg-data/tests/lifecycle_fields.rs:421` pins
   `crpg.ruleset` at 2). **Recommend: approve.** If the user keeps the bump,
   T148 becomes S-set and gains a ruleset step module, a `migrations.json`
   row, a migration fixture and every `crpg.ruleset/2` pin edit; the
   architect rewrites the contract.
2. **`Length` wire shape** is the crate's adjacent form:
   `{"type":"constant","value":<raw i32>}` or
   `{"type":"stat","value":"<stat name>"}`, like `StatValueWire`
   (`crates/crpg-data/src/combat.rs:90–102`).
3. **`turn` is required inside `movement`; `measure` is optional.** C1
   lists `turn` without "optional". An explicit `"euclidean"` is kept on
   write, and `null` reads as absent and is not written (T139d's rule).
4. **The pool is a template ULID**, because templates have no name
   (`crates/crpg-data/src/combat.rs:215–226`). C1's "names a declared pool"
   means "is the `id` of one of this ruleset's `pools`".
5. **Every C1 rule is a read-time `Malformed` check**, because each is
   decided inside the one ruleset document (the crate's read-time rule,
   `crates/crpg-data/AGENTS.md:178–187`). A `Stat` length may name a
   derived `Fixed` stat; T036 resolves it.
6. **A step constant has no upper bound** (only `> 0`); C2 computes in
   `u64` (`:286–290`). Speed's bound is U7's `1 << 18`.
7. **One semantic rule beyond C1, for authoring:** when speed or step reads
   a non-derived stat, an encounter creature whose value would fail M2 or
   C2 at runtime (`:184–185`, `:289`) gets `invalid_stat_value`, reusing
   the existing code. No new diagnostic code.
8. **The movement pool is inventoried** as a pool-template reference at
   `/movement/turn/pool`, so introspection shows the edge (one inventory,
   `crates/crpg-data/AGENTS.md:84–86`).
9. **The data constant is `MAX_SPEED_PER_TICK_RAW: i32 = 1 << 18`.** U7
   gives it to "sim and data validation" (`:124`); T036 should import this
   constant rather than declare a second one.

## Interface
In `crates/crpg-data/src/combat.rs`, re-exported at the root by the

public item carries the doc comment shown, verbatim (doc comments become

```rust
// After MAX_TAGS (combat.rs:52):
/// Largest movement speed per tick, raw `Fx16_16` (4 m per tick, ADR-0036 U7).
pub const MAX_SPEED_PER_TICK_RAW: i32 = 1 << 18;

// After the EffectsOnExitWire Deserialize impl (combat.rs:472-485), in this order:
/// How a ruleset moves creatures; absent means nothing moves.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize, JsonSchema)]
#[serde(deny_unknown_fields)]
pub struct MovementWire {
    /// Walking distance per tick: a constant or a fixed stat.
    pub speed: LengthWire,
    /// How rule-visible distance is measured; absent means euclidean.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub measure: Option<MeasureWire>,
    /// What a turn-based move costs.
    pub turn: TurnMovementWire,
}

/// The turn-based cost of a move: `ceil(length / step) * step_cost` from `pool`.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize, JsonSchema)]
#[serde(deny_unknown_fields)]
pub struct TurnMovementWire {
    /// Pool template paid from.
    #[schemars(with = "crate::schema::UlidText")]
    pub pool: Ulid,
    /// Distance bought by one step: a constant or a fixed stat.
    pub step: LengthWire,
    /// Pool units per step, at least one.
    pub step_cost: u32,
}

/// A length: a constant or a creature's fixed stat.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize, JsonSchema)]
#[serde(tag = "type", content = "value", rename_all = "snake_case", deny_unknown_fields)]
pub enum LengthWire {
    /// Core's raw fixed-point length.
    Constant(#[schemars(with = "i32")] Fx16_16),
    /// The name of a declared fixed stat.
    Stat(String),
}

/// How rule-visible distance is measured (ADR-0036 S2).
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, JsonSchema)]
#[serde(rename_all = "snake_case")]
pub enum MeasureWire {
    /// Horizontal straight-line length.
    Euclidean,
}
// `impl<'de> Deserialize<'de> for MeasureWire`, hand-written exactly like
// LateJoinWire's (combat.rs:458-470): VARIANTS = &["euclidean"]; a string
// "euclidean" gives Euclidean; another string gives
// de::Error::unknown_variant(other, VARIANTS); a non-string gives
// de::Error::custom("measure must be a measure name").

pub struct Ruleset { /* every existing field unchanged, then, last: */
    /// Movement rules; absent means nothing moves.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub movement: Option<MovementWire>,
}

/// Read-time movement rules of one ruleset (B4-B6).
fn validate_ruleset_movement(ruleset: &Ruleset) -> Result<(), DataError>;
```
`LengthWire` keeps derived decoding: both variants carry a payload, so the
unit-variant trap (`crates/crpg-data/AGENTS.md:68–73`) does not apply, and

last line `validate_ruleset_kernel(ruleset)` (`combat.rs:1439`) becomes

## Behaviour
Read-time rules give `DataError::Malformed` through `read_document` and
`load_campaign`. "Declared fixed stat" means an entry of `ruleset.stats`
with that `name` whose `kind` is `StatKindWire::Fixed`, derived or not.

**Reading and writing**
1. **B1.** A ruleset without `movement` decodes to `movement: None` and
   writes byte-identically. Every existing document under `rulesets/`,
   `campaigns/` and `crates/crpg-data/tests/fixtures/` decodes with
   `movement: None` and re-encodes to its current bytes.
2. **B2.** A ruleset with the wire example reads, and `write_document`
   gives canonical bytes that read back equal. `measure` absent stays
   absent; `"euclidean"` stays present; `"movement": null` and
   `"measure": null` read as absent and are not written.
3. **B3.** Structural rejections are `Malformed`: an unknown key in
   `movement`, `turn` or a `Length`; a missing `speed`, `turn`, `pool`,
   `step`, `step_cost`, `type` or `value`; a `Length` `type` other than
   `constant` or `stat` (serde's `unknown variant`); a non-integer or
   out-of-`i32` constant; a `step_cost` that is negative, above
   `u32::MAX` or not an integer; a `pool` that is not a ULID. `measure`:
   a non-string is exactly `measure must be a measure name`; an unknown
   string is exactly ``unknown variant `<text>`, expected `euclidean` ``.

**Read-time rules** (`validate_ruleset_movement`, run after every existing
ruleset check; the first failure in this order is returned)
4. **B4.** `speed`: a `Constant(v)` with `v.to_raw()` outside
   `1..=MAX_SPEED_PER_TICK_RAW` fails `ruleset movement speed must be
   1..=262144 raw`. A `Stat(name)` that is not a declared fixed stat fails
   `ruleset movement speed stat must name a declared fixed stat`.
5. **B5.** `turn.pool` equal to no `ruleset.pools[*].id` fails
   `ruleset movement pool must be a pool template of this ruleset`.
6. **B6.** `turn.step`: a `Constant(v)` with `v.to_raw() <= 0` fails
   `ruleset movement step must be positive`. A `Stat(name)` that is not a
   declared fixed stat fails `ruleset movement step stat must name a
   declared fixed stat`. Then `turn.step_cost == 0` fails
   `ruleset movement step_cost must be at least 1`.
7. **B7.** `measure` adds no read-time rule (its type is closed).

**Inventory**
8. **B8.** `reference_occurrences`' `Document::Ruleset` arm
   (`crates/crpg-data/src/inventory.rs:779–792`), after the `abilities`
   loop: when `movement` is `Some(m)`, `push_pool(&mut out, path,
   "/movement/turn/pool".into(), Some(v.id), m.turn.pool, "ruleset movement
   pool")`. Validation ignores pool-template sites
   (`crates/crpg-data/src/validation.rs:1913–1915`), so this adds no
   finding; `explain_object` lists the edge.

**Semantic rule** (`walk_combat`)
9. **B9.** In the per-stat loop over an encounter participant's creature
   (`crates/crpg-data/src/validation.rs:853–897`), after the health check
   and inside the same iteration, with `raw = value.to_raw()`, when
   `ruleset.movement` is `Some(m)`:
   - if `m.speed == LengthWire::Stat(stat.name.clone())` and `raw` is
     outside `1..=MAX_SPEED_PER_TICK_RAW`: push `InvalidStatValue` at the
     participant's `/participants/<i>/placement`, message
     `movement speed stat {name:?} on creature {prefab} must be
     1..=262144 raw`, fix `author a speed above zero and at most 4 metres
     per tick`, then `continue` to the next stat;
   - else if `m.turn.step == LengthWire::Stat(stat.name.clone())` and
     `raw <= 0`: push `InvalidStatValue` at the same pointer, message
     `movement step stat {name:?} on creature {prefab} must be positive`,
     fix `author a positive step length`.

   `{prefab}` prints with `Display` (uppercase), as the existing messages
   at `:881` and `:894` do. The loop's existing guards still apply: derived stats
   and stats a creature lacks (`missing_stat`) get no movement finding.
10. **B10.** No other validation changes. `combat_basic`, `combat_srd` and
    every other fixture keep their exact findings.

**Schema**
11. **B11.** `generated_schemas()["ruleset.schema.json"]` gains the
    optional `movement` property (not in `required`) and `$defs` for
    `MovementWire`, `TurnMovementWire`, `LengthWire` and `MeasureWire`.
    The checked-in file equals it. No other schema file changes.

## Tests
`crates/crpg-data/tests/movement_fields.rs` (implementer) and
`crates/crpg-data/tests/movement_fields_contract.rs` (two-keys, written
blind from this file). Helpers as in
`crates/crpg-data/tests/lifecycle_fields.rs:16–80` and `:312–358`
(`srd_ruleset()` reads `rulesets/srd-lite/ruleset.json`; `srd_files()` and
a `validate(mutate)` helper load `campaigns/fixtures/combat_srd` in
memory). `WIRE` below is the wire example. `FIXED_STAT(name)` is
`{"kind":"fixed","name":name}` appended to the ruleset's `stats`. Never
write a file to disk.

- **M-1 `absent_movement_is_unchanged` (B1).** Every ruleset file under
  `rulesets/` and `campaigns/fixtures/` reads through `read_document`
  (a `crpg.ruleset/1` file migrates as today) with `movement == None`.
  Every file already at `crpg.ruleset/2` re-encodes to its exact bytes,
  and no written ruleset contains the text `"movement"`. *Fails if:*
  absence writes a key.
- **M-2 `wire_example_round_trips` (B2).** srd-lite plus `WIRE`: reads;
  `ruleset.movement` equals the literal
  `MovementWire { speed: LengthWire::Constant(Fx16_16::from_raw(16384)),
  measure: Some(MeasureWire::Euclidean), turn: TurnMovementWire { pool:
  <1F>, step: LengthWire::Constant(Fx16_16::from_raw(98304)), step_cost: 1 } }`;
  write then read is equal; the written text contains
  `"measure": "euclidean"`. Without `measure`, the written text has no
  `measure` key. `"movement": null` and `"measure": null` read as absent
  and the written text contains neither key. A `Stat` speed
  (`{"type":"stat","value":"pace"}` with `FIXED_STAT("pace")`) round-trips.
- **M-3 `structural_rejections` (B3).** Each case is `Malformed`; where a
  substring is named in parentheses, the message contains it: unknown key `"speeed"` in `movement`, `"steps"` in `turn`,
  `"extra"` in a `Length` (`unknown field`); missing `turn`, `pool`,
  `step_cost`, a `Length` without `value` (`missing field`);
  `{"type":"metres","value":1}` (`unknown variant`); constant `1.5`
  (`non-integer number`); and, with no substring checked, constant
  `2147483648`, `step_cost` `-1` and `4294967296`, and `pool`
  `"not-a-ulid"`. Exact equality: `measure` `1` and
  `{"type":"euclidean"}` give `measure must be a measure name`;
  `"manhattan"` gives ``unknown variant `manhattan`, expected `euclidean` ``.
  *Control:* `WIRE` reads.
- **M-4 `speed_bounds` (B4).** Constant raw `1` and `262144` read;
  `0`, `-1` and `262145` give exactly `ruleset movement speed must be
  1..=262144 raw`. Stat `"pace"` with `FIXED_STAT("pace")` reads; stat
  `"might"` (an `int` stat), `"nope"` (undeclared) and `""` give exactly
  `ruleset movement speed stat must name a declared fixed stat`. A derived
  fixed stat (`{"kind":"fixed","name":"pace2","derived":{"type":"literal",
  "value":{"type":"fixed","value":65536}}}`) reads as a speed stat.
- **M-5 `pool_must_be_a_template` (B5).** Pool `1E` and `1F` read. Pool
  `00000000000000000000000017` (an ability id) gives exactly
  `ruleset movement pool must be a pool template of this ruleset`.
- **M-6 `step_and_cost` (B6).** Step raw `1` reads; `0` and `-65536` give
  `ruleset movement step must be positive`; step stat `"might"` gives
  `ruleset movement step stat must name a declared fixed stat`;
  `step_cost` `0` gives `ruleset movement step_cost must be at least 1`;
  `step_cost` `4294967295` reads.
- **M-7 `first_failure_order` (B4–B6 order, call order).** speed `0` with
  `step_cost` `0`: the speed message. Pool `…17` with step `0`: the pool
  message. step `0` with `step_cost` `0`: the step message. An enum stat
  with an empty `enum_id` plus speed `0`: the kernel message
  `ruleset enum stat enum_id must be nonempty`.
- **M-8 `pool_edge_in_introspection` (B8).** Load combat_srd with the
  ruleset's `movement` set to `WIRE`'s value in memory;
  `explain_object(&campaign, <ruleset 16>)` parses as JSON; its `outbound`

  "target_location":null}`. `validate` of the same campaign is empty.
  *Fails if:* the edge is missing, or the pool site yields a finding.
- **M-9 `encounter_creature_values` (B9, B10).** On combat_srd in memory:
  add `FIXED_STAT("pace")` and `FIXED_STAT("stride")` to the ruleset, set
  `movement` to speed `Stat("pace")`, step `Stat("stride")`, pool `1F`,
  `step_cost` 1, and give the hero (`…14`, participant 0) and the goblin
  (`…15`, participant 1) both stats. With hero `pace` = `0` and every other
  value `65536`: `validate` is exactly one diagnostic, file
  `encounters/first-blood.json`, pointer `/participants/0/placement`, code

  `movement speed stat "pace" on creature 00000000000000000000000014 must
  be 1..=262144 raw`, fix `author a speed above zero and at most 4 metres
  per tick`. Hero `pace` = `262145`: the same single finding. Hero `pace`
  = `262144`: none. Hero `stride` = `0` (pace `65536`): exactly one, message
  `movement step stat "stride" on creature 00000000000000000000000014 must
  be positive`, fix `author a positive step length`. `stride` = `-1`: the

- **M-10 `schema_holds_the_block` (B11).** In
