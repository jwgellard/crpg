# T098h — one shared constructor for the `Flush` close request (`crpg-net-quic`): contract

## Task / Crate(s) / Purpose

Sole crate: `crpg-net-quic`. Per D44c (a) (`tasks/DECISIONS-D44.md:27`):
all three `CloseMode::Flush` sites build their flush request through **one**
shared constructor (so no site picks the wrong deadline) plus one unit-test
module pinning it — a small private-code change in `src/`.

Status: **draft, awaiting user approval**.

## Exact contract

### Decision

**D0. Why the timing tests were dropped (two-line note).** The previous
draft's three `took < B` tests had at most the 200 ms reserve as margin — a
loaded runner can false-fail correct code. D44c (a) replaced them with the
constructor: the wrong wiring becomes a compile error.

**D1. The three sites, read not inferred (as they are today).**

- (c) `QuicClient::stop` (`src/client.rs:459-508`): `close_deadlines(...)`
  at `:464`; `FlushRequest` at `:474-478`, `flush_end` at `:476`; guard
  `overall + SYNC_GRACE` `:481-484`; `Stop.deadline` `:501-504`.
- (d) `QuicServer::close(.., Flush)`: the call at `src/server.rs:623`;
  `FlushRequest` at `:625-629`, `flush_end` at `:627`; guard `:631-634`.
- (e) `QuicServer::shutdown`: the call at `src/server.rs:713`; one
  `FlushRequest` per accepted connection at `:731-735`, `flush_end` at
  `:733`; guard `:740-743`; `Stop.deadline` `:758-761`.

The three literals are identical except for `code` — the duplication
D44c (a) removes.

**D2. The one constructor.** `FlushClose` and its constructor live in
`queue.rs` beside `FlushRequest` (`src/queue.rs:149-154`), so the
constructor can set the request's now-private fields and `run_flush` keeps
its reads (`started` `:918-920`, `flush_end` `:969`, `code` `:988`, `:998`
— same module). `close_reserve_ms` (`src/teardown.rs:11-14`) and
`close_deadlines` (`:25-33`, one `Instant::now()`, overflow fallback
`:35-38`) unchanged; afterwards only the constructor calls
`close_deadlines`.

**D3. Why this kills the mutants without a timer.** After D4, the request
cannot be built outside `queue.rs`: the previous draft's mutants
(`flush_end: deadlines.overall` at a site) no longer compile. A bug inside
the constructor is pinned by the exact split rows (H1–H5): installing
`overall` as `flush_end` fails `overall − flush_end == R` (any `R > 0`).

### Interface

New private items in `src/queue.rs`; nothing reachable outside the crate:

```rust
/// One `CloseMode::Flush` close's wiring: the request to install and the
/// endpoint's overall deadline, both from one `Instant::now()`.
#[derive(Debug, Clone, Copy)]
pub(crate) struct FlushClose {
    pub(crate) request: FlushRequest,
    /// `start + B`: the sync guard deadline and `Stop.deadline`.
    pub(crate) overall: Instant,
}

impl FlushClose {
    /// The one constructor for every `CloseMode::Flush` close (D44c (a)).
    /// Takes the budget `B` ms (`close_flush_timeout_ms`, valid
    /// `0..=2_000`; `src/limits.rs:126-131`, `:240-245`) and the close
    /// code; reads the wall clock once via `close_deadlines`; carries the
    /// reserve rule exactly once (T098g D2): `R = min(200 ms, B / 4)`,
    /// `flush_end = start + B − R`, `overall = start + B`.
    pub(crate) fn flush_close(budget_ms: u32, code: CloseCode) -> Self {
        let deadlines = close_deadlines(budget_ms);
        FlushClose {
            request: FlushRequest { code, flush_end: deadlines.flush_end, started: false },
            overall: deadlines.overall,
        }
    }
}
```

Changes to existing private items:

- `FlushRequest` (`src/queue.rs:149-154`): all three fields lose
  `pub(crate)`, so `FlushClose::flush_close` is the only constructor of a
  `FlushRequest` anywhere.
- The exact edit at each site:
  - (c) `src/client.rs:459-508`: delete the `let deadlines = …` line
    (`:464`); before `:472` one
    `let close = FlushClose::flush_close(…, code);`, then
    `record.flush = Some(close.request);` instead of `:474-478`; guard and
    `Stop.deadline` read `close.overall`; import `:35` drops
    `close_deadlines`, queue import (`:30`) gains `FlushClose`.
  - (d) `src/server.rs:623-634`: the call before `:624`,
    `record.flush = Some(close.request);` instead of `:625-629`, the guard
    on `close.overall`; imports as in (c).
  - (e) `src/server.rs:713` becomes one call **before** the loop:
    `let close = FlushClose::flush_close(self.limits.close_flush_timeout_ms,
    CloseCode::Shutdown);` — `FlushClose` is `Copy`, so every connection
    gets the same `flush_end` (T098g D4/b4). Each accepted branch sets
    `record.flush = Some(close.request);` (`:731-735`); guard and
    `Stop.deadline` read `close.overall`.

### Behaviour

1. **Reserve rule, stated once.** Only `flush_close` (via the unchanged
   `close_deadlines`) computes it: `R = min(200 ms, B / 4)`,
   `flush_end = start + B − R`, `overall = start + B`, one `Instant::now()`
   (`src/teardown.rs:26-33`; overflow falls back to `start`, `:35-38`).
2. **Per-site wiring.** Each site calls `flush_close` exactly once, installs
   `close.request` on every flushed record, guards with
   `close.overall + SYNC_GRACE` (`src/queue.rs:32-34`), and puts
   `close.overall` in `Stop.deadline` (`:265-270`). `shutdown`'s single
   pre-loop call keeps one shared deadline.
3. **Unchanged.** `run_flush` (`src/queue.rs:961-1000`, order `:986-999`);
   `finish_endpoint_close` and its single `yield_now` before the bounded
   `wait_idle` (`src/teardown.rs:42-54`); the `Drop` paths
   (`src/server.rs:780`); `Pending`/`Discard` closes; report sums.

### Tests

One new `#[cfg(test)] mod tests` in `src/queue.rs`. Every row uses the
T098g test-1 shape
(`before = now(); close = flush_close(b, code); after = now()`):
instants bounded by the bracketing window, the split exact; **no
wall-clock timing anywhere** (nothing measures elapsed time, waits or
sleeps). Assert in every row:
`close.overall.duration_since(close.request.flush_end) == R`,
`close.overall` inside `[before + B, after + B]`,
`request.flush_end <= close.overall`, `request.started == false`,
`request.code == CloseCode::Normal`.

- H1. **`flush_close_budget_2000_stops_200_ms_early`** — `B = 2_000`,
  `R = 200` (cap).
- H2. **`flush_close_budget_400_stops_a_quarter_early`** — `B = 400`,
  `R = 100` (`B/4` under the cap).
- H3. **`flush_close_budget_800_both_rules_give_200`** — `B = 800`,
  `R = 200` (`B/4` equals the cap).
- H4. **`flush_close_budget_0_ends_at_once`** — `B = 0`, `R = 0`; also
  `request.flush_end == close.overall` (the same `Instant::now()`).
- H5. **`flush_close_flush_end_never_passes_overall`** — for
  `0, 1, 3, 4, 100, 101, 400, 800, 1_999, 2_000, u32::MAX`,
  `request.flush_end <= close.overall` and the `overall` window hold.

**How the sites are shown to use it (construction, not a check).** After
D4 the wiring is a compile fact; the reviewer re-runs:

- `rg -n "FlushRequest \{" crates/crpg-net-quic/src` — exactly one match:
  the `flush_close` body in `src/queue.rs`.
- `rg -n "flush_end" src/client.rs src/server.rs` (from
  `crates/crpg-net-quic`) — no matches.
- `rg -n "FlushClose::flush_close" crates/crpg-net-quic/src` — exactly
  three: `stop`, `close`, `shutdown`.
- `rg -n "close_deadlines" src/client.rs src/server.rs` — no matches.

**Mutants** the implementer must apply, run, record `EXIT=101` with the
failing assertion, and restore (all in product code now):
- M1: `flush_close` installs `deadlines.overall` as `request.flush_end`
  (brief (i)). Dead by H1–H3's `split == R`.
- M2: `close_reserve_ms` computes `max` instead of `min` (brief (ii)) —
  dead by H1/H2 (split 500/200 ms); H4's `0 − 200` panics on `u32`
  underflow.
- M3: `flush_close` swaps `deadlines.flush_end` into `overall` (inverse of
  M1). Dead by H1–H3's split (0 ms) and H5's window.
- M4: `flush_close` sets `started: true`. Dead by H1's `started ==
  false`; breaks `run_flush`'s start mark too (`:918-920`).
