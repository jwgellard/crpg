## Interface — owner and exact-API gate

Require an accepted ADR specifying host construction, immutable client-facing
handle, authenticated peer binding, ingress/pump API, monotonic time injection,
ownership/disclosure input, accepted outcome record, queue/cursor acknowledgments,
checkpoint save/load and shutdown/error surfaces. Choose concrete types/errors
and retention byte/count caps in D10; no invented `Host::new` signature here.

Consumer input is T020's real public event reader and existing
`perform_action` result, not T018c's test-only NetDriver. Consumer output is
T021 version-selected permitted receipts/events/post-state. Proposed correlation
identity is authenticated session epoch + lane + sequence, plus approved sim
history cursor; approve its durable representation before implementation.

## Behaviour

Authenticate and cap ingress before sequence/cache; preserve T018's terminal
versus retryable decisions, cache-first exhaustion and 200-tick freshness.
Revalidate gameplay through public sim immediately before execution. Capture
accepted `Some(ActionOutcome)` **and permitted post-state before the next
operation**; capture accepted EndTurn as Applied with no fabricated attack.
Do not discard the returned outcome or infer it later from final health.

Correlate receipts and ordered filtered deltas/history, then acknowledge only
the retained/committed consumer progress. Bound history, delivery logs, dedup
cache and unconsumed work in bytes and entries. Reserve output/retention capacity
before executing an action so a full journal cannot lose an accepted result;
define retryable backpressure without reexecution. Hidden fields never enter
client snapshots or cached detailed replies. In-process clients never receive
mutable World access.

Checkpoint restores World plus required history/cursor/outcome/session ledger
as one consistent continuation. Lost-receipt retry after restore must not spend
again if persisted-session continuation is selected. If D10 chooses session
expiry on process restart, preserve authoritative continuation but explicitly
reject old epochs; do not claim persisted reconnect. A World-only serde
round-trip is insufficient evidence for host save/restart continuation.

All new value structs/enums derive `Debug, Clone, PartialEq, Eq`; opaque
`PeerHandle` additionally derives `Copy, PartialOrd, Ord`. `Host` derives
`Debug` only and is neither `Clone` nor `Copy`. `HostError` implements `Display` as
`<VariantName> at host/admission` and `Error` with no source;
`CheckpointError` implements `Display` as `<VariantName> at host/checkpoint`
and `Error` with no source. Capture types serialize in declaration order;
decode rejects duplicate/unknown/missing fields. `NetId` fields use a
server-local checked nonzero-u64 serde adapter, not a new net serde API.
Checkpoint validation additionally enforces §7. `ProtocolSelection::as_u8`
has the exact signature `pub fn as_u8(self) -> u8` and returns `1`/`2`.
Session epoch bytes are `incarnation.to_le_bytes()` followed by
`PeerHandle::get().to_le_bytes()`. Within one `Host` lifetime handles start
at 1, advance monotonically, never reuse values, and refuse allocation at
the reserved `u64::MAX` sentinel; a restarted host allocates from 1 again
under its strictly greater incarnation, so no epoch repeats.
The epoch is a correlation/fencing identifier, never an authentication secret.
The embedding supplies a strictly increasing incarnation for every new host
of this authority, including restoration of an older checkpoint; secure
credentials remain an adapter responsibility. No per-peer epoch is shared.
`ControlGrant.actors` is stored sorted-ascending and deduped at bind/set time;
the input count is checked before deduplication. More than 1024 entries is
`HostError::InvalidControl`. Grant vector input caps are checked before
sorting; duplicate entries are `InvalidGrants` rather than last-wins.
`DisclosureGrants` implements `Default` as empty vectors and false flags;
unknown entities/fields are denied. `CapturedOutcome` carries only
the symbolic outcome vocabulary of T020 (`critical_success`, `success`,
`failure`, `critical_failure`, `custom:<0..255>` no leading zeros) and the
reported damage; `roll`, `margin`, and `target_died` are never stored —
re-stating them anywhere (capture, delivery, checkpoint, logs) is a defect.
Receipt payloads remain exactly epoch/lane/seq/tick/status in both versions.

Error precedence inside `pump` per staged command is §3. `HostError::Closed`
is returned by `ingest`/`bind_peer`/`set_grants`/`set_control`/`tick` after
shutdown. `shutdown` is an idempotent synchronous fence: return one
`Rejected(SessionExpired)` AdmissionResult for each staged command in FIFO
order (`seq: None`, `cached: false`, `retained_in_ingress: false`), discard
those commands without execution/sequence consumption, close all bindings
and discard their transport queues/caches/maps. It preserves authority and
captures; save and trusted capture reads/acks remain callable, and `pump`
returns an empty summary. Thus full capture/egress cannot deadlock shutdown.
`unbind_peer` applies the same binding fence to that peer only; the trusted
caller explicitly cancels its staged commands. No `NetId` is reused within
a session; a rebind gets a new handle/epoch and fresh ids.
`now_ms` earlier than the last accepted `now_ms` on any time-taking call is
`HostError::TimeRegression` with no state change (injected monotonic
milliseconds only; never `SystemTime`, never `World` tick for budgets).
Unknown/unbound handles on `ingest` yield `Refused` with
`Rejected(Unauthenticated)` (fail-closed wire status, empty reply); on the
trusted transport-signal APIs (`take_delivery`, `acknowledge_delivery`,
`set_grants`, `set_control`, `epoch`, `cached_status`) they yield
`HostError::UnknownPeer`.
`acknowledge_delivery` with `through` at or below the watermark is an
idempotent no-op; past the last issued sequence is `FutureDeliveryCursor`.

All APIs on `Host` are trusted authority/adapter APIs, not a client object.
The client-facing capability is its copyable handle plus the adapter's byte
channel; an in-process client receives neither `&Host` nor the capture/query
methods. Full hashes, typed combat errors, captures and checkpoint bytes stay
on the trusted side. The adapter fences outbound bytes already taken from a
binding before completing a grant change/unbind/shutdown; it must not publish
them afterward. Already published facts cannot be retracted.

### 2. Constants and byte accounting (normative)

Reuse T018a/T020/T021 constants by qualified reference; no divergent numeric
copies. New host constants are §1's capture bounds plus
`MAX_MAPPED_PER_PEER: usize = 1024` (references
`crpg_net::protocol::MAX_VISIBLE_ENTITIES`; per-peer live entity map bound)
and `MAX_CONTROLLED_PER_PEER: usize = 1024` (references the same constant;
`ControlGrant` bound). `MAX_GRANT_IDENTITIES: usize = 1024` is the bound
for each grant vector; `MAX_PEERS` aliases `POLICY_PROOF_PEERS` (8).
These constants live in `host`; §1's capture constants live in `capture`.

| Ledger | Count cap | Byte cap | Byte definition | Retirement |
|---|---|---|---|---|
| sim journal (T020) | 4096 envelopes | 1 MiB | compact `serde_json` envelope length | host `acknowledge` after capture (§4) |
| capture journal | 4096 records | 8 MiB | compact `serde_json` record length, including events and views | trusted consumer `acknowledge_captures` (§4) |
| retry cache per peer/lane | 256 | 2 MiB | canonical intent bytes plus canonical receipt-only delta bytes (event_seq=0 template) | oldest-first eviction; evicted retry is `StaleSeq` |
| egress/delivery per peer | 128 frames | 2 MiB | encoded delta frame length | `acknowledge_delivery` |
| egress host total | — | 16 MiB | sum over peers | same |
| ingress per peer | 128 frames | 256 KiB | staged byte length | `pump` consumption |
| ingress host total | 1024 frames | 2 MiB | staged byte length | same |
| checkpoint input | — | 16 MiB | raw byte length, checked before parsing | n/a |

Cache metadata is fixed-size per entry: command seq, status, original
processed tick, and most recently issued receipt delivery seq (if any).
It is bounded by the count cap; no detailed event/state payload is cached.
Grant/control/map entries have only fixed-size ids and booleans, bounded by
their vector caps and eight peers. No unbounded closed-session set exists:
only current bindings are valid, and monotonic handle/incarnation allocation
prevents reusing retired epochs. Returned pump/shutdown summaries contain at
most 1024 results (one per removed input, plus at most one retained head,
so never more than the queue length at entry); they are not host-retained logs.

Egress/delivery caps reference `QueueCaps::v1_egress` depths; ingress caps
reference `QueueCaps::v1`; rate budgets reference `RateCaps::v1` through
`TokenBucket`, all from `crpg_net::sim` (the specified T018b fabric module,
not the test-only driver). Failure-response budgets additionally gate
rejected-receipt replies exactly as in T018c (fresh and cached rejections
spend frame+byte budgets; drops retain the terminal outcome with an empty
reply; `Applied` never spends them).

### 3. Ingress, admission precedence, terminal versus retryable

`ingest` checks, in order: host open, time monotonic, peer bound, intent rate
budgets, `bytes.len() <= MAX_INTENT_FRAME_BYTES`, ingress per-peer and host
frame+byte room. Any failure yields `Refused` with the matching status
(`Unauthenticated`, `RateLimited`, `FrameTooLarge`, `QueueFull`) and stages
nothing; retries and invalid attempts count toward budgets exactly like first
attempts. `ingest` never decodes and never consumes lane sequence.

`pump` drains staged commands FIFO. Each staged entry carries its submitting
`PeerHandle`; all per-peer state below (epoch, lane seq/cache, rate/fail
budgets, entity map, grants) is that peer's session state. The pipeline
preserves the T018c order with determine-then-reserve-then-commit made
explicit: the terminal reason (if any) is determined without committing,
worst-case room for that outcome class is reserved check-only (§6), and only
then is the outcome committed (sequence advance, cache insert, delivery
staging, capture append, sim ack). Reservation failure leaves the command
staged and stops the pump (head-of-line blocking); the head yields one
`QueueFull` `AdmissionResult` with `retained_in_ingress: true` and no
sequence consumed.

1. Decode with the selected version's codec (`codec` for V1, `codec_v2` for
   V2). First-failure-wins per the codec contract; the codec-to-receipt map
   is the identity (`FrameTooLarge→FrameTooLarge`,
   `UnsupportedVersion→UnsupportedVersion`, `WrongDirection→WrongDirection`,
   `UnknownMessage→UnknownMessage`, `Malformed→Malformed`,
   `LimitExceeded→LimitExceeded`). Undecodable bytes stage no reply;
   the status is observable in `PumpSummary.results` (`seq: None`,
   `cached: false`, `retained_in_ingress: false`). A selected-V1 host refuses
   version byte 2 as `UnsupportedVersion`; the reverse holds for V2. Delta
   tags 8/9/10 are never valid host intent vocabulary: unknown-tag refusal
   is proved by direct decoder tests (§9), not by ingesting delta bytes.
2. Session epoch: the decoded epoch must equal `epoch(staged peer)` exactly
   → else `SessionExpired` with no sequence consumed and no cache insert.
   There is no shared host epoch and no retained closed-session set: each
   binding owns its epoch (`incarnation || handle`), handles never reuse,
   and incarnations strictly increase across hosts of one authority (§7).
   An old-epoch retry on a rebound or restarted authority therefore fails
   this step on the new binding.
3. Seq/cache (cache-first, per peer/lane): same seq with byte-identical
   canonical bytes in that peer's retry cache → cache hit: return the
   retained `(status, processed_tick)` with no re-execution and ensure the
   receipt is deliverable (§5); same seq with different bytes → fence that
   binding only (discard its queues/caches/maps; the handle is retired and
   never reused) and return `SeqConflict` with no sequence consumed; cache
   miss on an exhausted lane (`next_new_seq > SEQ_LAST`) → `SeqExhausted`
   with no sequence consumed and no fencing; `seq > next_new_seq` →
   `SeqGap` (no advance); `seq < next_new_seq` → `StaleSeq`, including
   evicted entries (never reapplied); else new. Conflict fencing affects
   only the offending session; other peers are untouched.
4. Freshness against `server_tick`: `observed_tick > server_tick` →
   `FutureTick`; `observed_tick < server_tick.saturating_sub(200)` →
   `StaleTick` (200-tick window from `POLICY_OBSERVED_TICK_WINDOW`,
   saturating edges). Both are terminal candidates: they commit only after
   §6 reservation, consuming exactly one sequence and caching the outcome.
5. Mapping/ownership/disclosure-gated identity: resolve actor and target
   `NetId`s through the peer's live entity map (whole `EntityId`s with
   generations, never raw arena ids). Failure of any of these → single
   public `NotAuthorized` (missing, hidden, and foreign are
   indistinguishable): actor unmapped or its entry lacks
   `present && action_actor`; target unmapped or its entry lacks
   `present && action_target`; actor outside the peer's `ControlGrant`.
   Terminal candidate like step 4. Grants are evaluated at pump time, so a
   `set_control`/`set_grants` between `ingest` and `pump` applies to the
   staged command. Revoked ids retire before the next admission and no
   `NetId` is reused within the session (`next_net` monotonic per session).
6. Reservation (§6): check-only worst-case room for the determined outcome
   class. Accepted commands reserve the full accepted footprint (one capture
   record, one retry-cache entry, per-peer worst-case delivery across all
   bound peers); terminal rejections reserve one retry-cache entry plus the
   originator's receipt delivery. Failure → retryable `QueueFull` with no
   sequence consumed, no mutation, pump stops with the head retained.
7. Execution through the real public `HistoryWorld::perform_action`
   immediately (no invented legality copy; gameplay precedence stays
   authoritative in sim): `Ok(Some(outcome))` → `Applied`;
   `Ok(None)` (accepted `EndTurn`) → `Applied`; `Err(combat)` →
   `Rejected(IllegalAction)` with the typed error retained in
   `last_combat_error`. Sim capacity failures (`EventLimit`, `ByteLimit`,
   `SequenceExhausted`) commit nothing per T020 and surface as retryable
   `QueueFull` with no sequence consumed (unreachable in this slice because
   §6 reserves the accepted worst case and the sim journal is acked after
   every capture; stated defensively, no production hook added).
   Rejected actions emit/spend/draw/journal nothing in sim.
8. Commit (§4–§5): for terminal rejections, advance `next_new_seq`, insert
   the retry-cache entry `(seq, canonical intent bytes, status,
   processed_tick, receipt delivery ref)` without eviction (reservation
   guaranteed room), and stage the originator's receipt delivery subject to
   fail budgets (drops retain the outcome with an empty reply and count
   `dropped_replies`; `Applied` never spends fail budgets). For accepted
   commands, append the capture record, insert the retry cache entry,
   advance `next_new_seq`, project and stage delivery for every bound peer
   with permitted content (§5), and acknowledge the sim journal through the
   captured range. Cache-hit retries never advance `next_new_seq` and never
   re-execute; they re-ensure receipt delivery (§5).

Terminal outcomes (steps 4, 5, 7-success, 7-gameplay-rejection) consume
exactly one sequence and cache canonical bytes plus the original processed
tick. Codec/session/cache-hit/conflict/gap/stale/exhaustion/reservation
outcomes consume none. Every removed command yields exactly one
`AdmissionResult`; the retained head (if any) yields one additional
`QueueFull` result with `retained_in_ingress: true`.

### 4. Authority, execution, and the capture journal

One serial `Host` owns one `HistoryWorld` privately. No client, test
harness, or adapter ever receives `&mut HistoryWorld`, `&mut World`, stores,
queues, or RNG handles; the only pre-wrap mutation path is
`Host::from_history`, where the embedding constructs and choreographs the
`HistoryWorld` (including `start_encounter`) through public sim APIs before
wrapping it. `from_history` requires an empty sim pending journal
(`pending_len() == 0`), else `HostError::PendingHistory`: the embedding must
not smuggle uncaptured evidence past the wrap. `Host::new` creates an empty
authority with no encounter; starting one requires the `from_history` path,
so a `new`-built host correctly rejects gameplay as `IllegalAction` until
wrapped choreography supplies it. In-process embedding receives the same
host-issued `PeerHandle` bindings, never direct mutation access. Lane-0
`ingest` is the sole post-construction gameplay-mutation path, and it admits
only `DeclareAction`/`EndTurn` intents mapped to
`CombatAction::UseAbility`/`CombatAction::EndTurn`; spawn/start-encounter/
tick/release have no wire form in this slice (`tick()` is a trusted
embedding op that journals nothing).

Each accepted command runs execute→capture→project→cache→acknowledge to
completion before the next staged command starts. The capture record holds
the returned `ActionOutcome`'s symbolic fields (`actor`, `target`, `ability`,
T020 outcome text, reported possibly-overkill damage), the history range
`(history_start, history_end]` read from the journal, a clone of that exact
range (`events`, at most 3, retained before the sim ack), and the permitted
post-state for every bound peer with content for this command (`views`, at
most 8 in ascending epoch-byte order). Each view records only the involved
entities' permitted state: health entries for actor/target/active when each
is disclosed to that peer (at most 3, ascending `NetId`), plus the `Turn`
when `turn_state` is granted. Views are trusted capture evidence, not a
replica transport: full per-peer state is verified through delivery oracles
(§9), while views prove the first command's post-state survived the second
mutation. Accepted `EndTurn` records `outcome: None` with its actual
trailing `TurnStarted`/`EncounterEnded` range and no fabricated
`ActionResolved`. The returned outcome is never discarded or re-inferred
from later health. `executions` counts accepted commands including accepted
`EndTurn`; cached retries never move it. `authority_hash` is `history_hash`,
so the consumer ack schedule stays part of the deterministic input.

Capture records are numbered by monotonic `capture_seq` from 1
(`CounterExhausted` at the reserved `u64::MAX` sentinel; unreachable by
counting, stated not hooked). `read_captures(after, limit)` requires
`1 <= limit <= MAX_CAPTURE_PAGE` else `InvalidPageLimit`; `after` below the
watermark is `StaleCaptureCursor`, past the last sequence is
`FutureCaptureCursor`, equal to the last returns empty; reads are inert and
return clones in order. `acknowledge_captures(through)` past the last
sequence is `FutureCaptureCursor`; at or below the watermark it is an
idempotent no-op; otherwise it advances the watermark and retires the
prefix, freeing capture bytes. Retired captures stay retired across
checkpoints (§7 carries the watermark). Capture retirement is the
trusted-consumer backpressure release that §6 reservation waits on; without
it the journal fills after 4096 accepted commands and reservation blocks
further accepts until the consumer acks. `capture_acknowledged`/`last_capture`
expose the watermark and the last issued sequence.

### 5. Wire, correlation, and delivery

Correlation identity is `(session epoch, lane, command seq)` on the command
side plus the captured history range and per-peer delivery sequences on the
output side. Each session epoch is unique because it embeds an incarnation
and a never-reused handle (§1). `lane` is always `LANE_COMBAT`. Command seqs
are per-session per-lane from `SEQ_FIRST`, never wrap (`SEQ_LAST` then
`SeqExhausted`); delivery `event_seq`s are per-peer from 1, gapless within
the current delivery generation, and never reuse history seqs. A
suppressed-only page produces no frame and consumes no delivery sequence.

Receipts go to the originator only. Events and state fan out to every bound
peer with permitted content for the committed command. Per-peer frame order
is exactly: `Receipt` first (originator only), then permitted event ops in
journal order, then permitted state ops (`Health`, `Turn`, `EntityLeave` for
membership changes). History envelopes map to `EventCandidate`s from the
peer's live map plus its `EntityDisclosure`/ability/encounter/round grants
and project through `project_events`; any missing field/grant omits the
whole event without inspecting hidden payloads further. Event suppression
never suppresses an independently permitted state update. The per-field
mapping is: `Spawned` needs `present && spawn` on that entity;
`Despawned` needs `present && despawn`; `Died` needs `present && died`;
`ActionResolved` needs actor `present && action_actor`, target
`present && action_target`, ability in `abilities`, outcome allowed on both
ends (`action_outcome` on actor and target), and damage allowed on both ends
(`action_damage` on actor and target); `TurnStarted` needs actor
`present && turn_start` plus global `turn_round`; `EncounterEnded` needs the
encounter in `encounters` plus global `encounter_end`. State mapping is:
`Health` needs `present && health` on that entity; `Turn` needs global
`turn_state` (an undisclosed active head is emitted as `active: None`,
preserving turn progress without leaking identity); `EntityLeave` is emitted
for membership loss. Frames chunk at op boundaries (`<=256` ops,
`<=64 KiB`) preserving order; empty op lists are allowed but never emitted
spuriously. Receipts encode with the selected version's codec
(`Legacy(Receipt)` under V2).

Version projection is explicit. A V1 host delivers receipts plus permitted
legacy state ops only; richer history envelopes project to no V1 event op
(the V1 vocabulary has no tags 8/9/10). A V2 host delivers receipts plus
permitted `Legacy`/event ops plus state ops. The acceptance oracles are
therefore version-specific (§9): the V1 oracle expects state convergence
without event ops, the V2 oracle expects the ordered event stream plus
state. Both versions share the same admission, capture, and disclosure
inputs; only the wire projection differs.

`take_delivery(peer)` returns clones of every unacknowledged frame for that
peer in `event_seq` order; repeated calls return the same bytes and
sequences until acknowledged (loss recovery is re-`take`, not re-execution).
`acknowledge_delivery(peer, through)` at or below the watermark is an
idempotent no-op; past the last issued sequence is `FutureDeliveryCursor`;
otherwise it retires the prefix and frees egress bytes. Cache-hit retries
(§3 step 3) reuse the retained `(status, processed_tick)`: when the
receipt's frame is still unacknowledged, delivery is already available via
`take_delivery`; when it was already acknowledged, the host stages a fresh
copy with the next delivery sequence and identical receipt content. Receipt
content therefore always carries the original `processed_tick`, never the
retry tick. Newly bound peers start at delivery seq 1 and first receive
current permitted state (chunked); old secrets are never replayed from
caches.

Narrowing `set_grants` (removing an entity, clearing any flag, removing an
ability/encounter, or clearing a global) returns `RebindRequired`, discards
that peer's unacknowledged delivery log, bumps its delivery generation,
resets its delivery sequence to 1, and stages a fresh filtered state on the
next `take_delivery`. The adapter must fence bytes already taken but not yet
published and must not publish them after the change; already published
facts cannot be retracted. Purely widening changes return `Unchanged` and
preserve delivery continuity. `set_control` affects future admission only
and never resynchronizes delivery. Grant-update egress for the resync state
is reserved as a trusted op; exhaustion yields `HostError::QueueFull` and
leaves the new grants installed with delivery reset pending.

Hidden identities, symbolic outcomes, damage values, and detailed facts must
not enter delivery frames or cached replies: retry caches store only
`(seq, canonical intent bytes, status, processed_tick, receipt delivery
ref)` with no event/state payload, and delivery carries projected ops only.
Receipts and retries therefore disclose nothing beyond
epoch/lane/seq/tick/status. Capture views (§4) stay on the trusted side and
never enter wire bytes.

### 6. Bounded atomic capture

Reservation per new command is check-only against
`MAX_NEW_EVENTS_PER_COMMAND` (3), `MAX_CAPTURE_RECORD_BYTES` (16384),
`MAX_DELIVERY_OPS_PER_COMMAND` (8), and
`MAX_DELIVERY_BYTES_PER_COMMAND_PEER` (2048) across all bound peers, plus
the staged intent length and the receipt-template length for the retry
cache. The implementation proves these bounds with tests: a worst-case
accepted action (kill with overkill damage, longest legal outcome text,
full-disclosure all-peer projection with involved-entity views) must encode
within them, or source stops for re-scope instead of silently widening a
cap. Terminal rejections reserve only their retry-cache entry plus the
originator's receipt frame under the same per-peer/host egress caps;
undecodable, session, cache-hit, conflict, gap, stale, and exhaustion
outcomes reserve nothing beyond the already-bounded summary. After a
successful reservation, the only post-mutation steps are infallible appends
and the capture-then-ack sequence; projection inputs are sim-validated
vocabulary by construction. There is no partial commit: if reservation
succeeds, the accepted result is captured, cached, and delivered-or-logged;
a terminal rejection is cached and its receipt is delivered-or-logged;
retirement happens only through `acknowledge_captures`,
`acknowledge_delivery`, and retry-cache eviction. Backpressure
(`QueueFull`) is always retryable: the client retries identical bytes, which
hit either the still-staged head, the retry cache (if meanwhile accepted),
or a fresh admission — exactly once in every case. Capture-full blocking is
released by the trusted consumer's `acknowledge_captures`, egress blocking
by `acknowledge_delivery`, never by dropping an accepted result.

### 7. Checkpoint and restart

Fresh sessions on restart (D10 selected; persisted-session continuation
explicitly not selected). The checkpoint is a bounded in-memory byte vector:

- `save_checkpoint(&self) -> Result<Vec<u8>, CheckpointError>` encodes
  `{"version":1,"incarnation":u64,"protocol":1|2,"server_tick":u64,`
  `"history":{HistoryWorld JSON},"captured":[...],"capture_acknowledged":u64}`
  in that field order as compact JSON. It fails with `PendingIngress` when
  staged ingress is nonempty (save at quiescence; shutdown refuses staged
  work first per §1). Contents are the full authoritative wrapper (world,
  pending journal, ack/sequence state), the retained capture journal plus
  its watermark, and the incarnation identity — never live transport
  bindings, credentials, lane caches, delivery logs, entity maps, grants,
  grace deadlines, fail-budget state, or per-peer delivery watermarks (all
  peers rebind fresh).
- Input validation enforces `bytes.len() <= MAX_CHECKPOINT_BYTES` before
  JSON parsing, including the reader entry point (read at most cap+1 bytes;
  excess is `TooLarge`; I/O failure is `Io`). Then: no
  duplicate/unknown/missing keys at any level; `version == 1` else
  `UnsupportedVersion`; inner `HistoryWorld` validated by its own rules
  (failure is `AuthorityInvalid`); capture count and recomputed canonical
  bytes within §1 caps; outcome vocabulary and 256-byte bound per record;
  per-record event count (at most 3), view count (at most 8), and
  per-view health count (at most 3) within §1 bounds; history ranges within
  the wrapper's issued sequences and exactly matching the retained events;
  `capture_acknowledged <= last retained capture_seq` with retained records
  exactly the contiguous range `(capture_acknowledged, last_capture]`;
  `server_tick` equal to the wrapped world's tick.
  Parser scratch is bounded by the input cap, not by sim's retained-history
  caps (T020 honesty rule applies unchanged).
- `load_checkpoint(bytes, new_incarnation, now_ms)` builds a temporary host,
  validates fully, then returns it: no partial state on failure.
  `new_incarnation` must be strictly greater than the checkpoint
  incarnation else `EpochReused`. Lane seq/cache/delivery state resets to
  fresh (all peers re-authenticate and rebind under new session epochs; new
  delivery seqs from 1 with a fresh filtered state); sim ack watermarks,
  capture journal plus its watermark, and authority continue unchanged.
  Handle allocation restarts at 1 under the new incarnation, which keeps
  every post-restart epoch distinct from pre-restart epochs. Old-epoch command bytes presented after
  restart are refused as `SessionExpired` and never re-executed; the D10
  lost-receipt clause applies only to persisted-session continuation, which
  is not selected.
- Atomic consistency: save borrows a quiescent host; load swaps only on
  success. A `World`-only serde round-trip is not evidence; acceptance
  requires the save/destroy/recreate/load/continue equivalence test (§9).
- Production persistence (filesystem, crash-atomicity, compression with
  separate compressed/decompressed caps) is a prerequisite `crpg-persist`
  task plus a server adapter, not a T022 second-crate addition. If that task
  needs a different checkpoint shape, it files its own contract.

Independent oracles, never production projection as oracle: a hand-authored
ordered op oracle per schedule and version (drop/duplicate/swap-sensitive,
including same-tick events), a per-peer permitted-state oracle built from
test-side public `history.world()` reads through a separate code path, and
the authority oracle (`authority_hash`, full `read_after` journal
comparison, `executions`, retained capture records plus their watermarks).

complete-state-unchanged assertion (hash + journal length + executions +

- `unknown_version_refused_at_ingress`: cross-version intent bytes through
  the selected host codec → `UnsupportedVersion` with no sequence consumed.
  Unknown delta tags 8/9/10 are proved by direct decoder tests (a valid
  other-version envelope with each new tag is `UnknownMessage`); delta bytes
  are never host ingest vocabulary.
- `hidden_fields_absent_from_snapshots_and_replies`: per-field grant
  removal (actor presence, target presence, ability membership, outcome on
  either end, damage on either end, turn/round/encounter grants each
  individually) → whole-event suppression; unrelated state update still
  delivered; two peers diverge correctly; cached replies, delivery bytes,
  and capture views contain no hidden ids/outcomes/damage.
- `two_peers_share_lane_sequences_safely`: two bound peers submit command
  seq 1 each; both are admitted under distinct session epochs with distinct
  receipts; capture records carry distinct epochs; a byte-swap conflict on
  one peer fences only that session while the other continues.
- `capture_before_second_mutation`: two sequential accepted actions read via
  `read_captures`; the first record (outcome, range, retained events,
  involved-entity views) is intact after the second; accepted `EndTurn` →
  `Applied` with `outcome: None` and no `ActionResolved` in its range.
  `read_captures` paging, stale/future cursors, and invalid limits are
  proved with positive controls.
- `lost_reply_duplicate_delivery_executes_once`: drop delivery frames and
  duplicate them through a byte harness; `take_delivery` repeats identical
  bytes/sequences until acknowledged; re-ingest recovers the cached receipt
  with the original tick; `executions`, journal, captures, and authority
  hash prove exactly-once ordered consumption with no re-execution.
- `narrowing_grants_resynchronize_without_leak`: stage detailed delivery,
  narrow grants, then prove the stale unacknowledged frames are discarded
  (never delivered after fencing), delivery restarts at 1 with a fresh
  filtered state, and no narrowed fact appears in later bytes; widening
  preserves continuity. Already published bytes are excluded from the leak
  claim by adapter fencing.
- `capacity_boundary_no_partial_commit`: fill capture/retry/egress ledgers
  to their bounds; the next new command is retryable `QueueFull` with no
  sequence consumed and no mutation (retained-head result); terminal
  freshness/authorization candidates under full egress prove the same
  reserve-before-commit rule; after `acknowledge_captures`/
  `acknowledge_delivery` the identical retry succeeds. Worst-case action at
  bound-minus-one still fits, including the 16 KiB capture bound.
- `sequence_precedence_and_eviction`: gap/stale/conflict ordering by
  counting, including per-session conflict fencing that leaves the other
  peer admitted; 256/257-entry cache eviction → `StaleSeq` on the evicted
  retry; `next_new_seq` monotonic and never wrapping across the suite. True
  `u64::MAX` exhaustion is unreachable by counting, so no production hook
  is added; the after-cache/before-gap dispatch order is pinned here and
  reviewed, with this limitation stated rather than tested around.
- `checkpoint_continuation_equivalence`: prefix schedule → save →
  destroy → load with a strictly greater incarnation → rebind identical
  operator facts → suffix schedule; authority (hash, journal, capture
  records plus watermark, RNG/event bytes) identical to the uninterrupted
  run modulo session identity; new receipts differ in epoch bytes only.
- `old_epoch_refused_after_restart`: pre-restart command bytes →
  `SessionExpired` with no execution; equal-incarnation reload is
  `EpochReused`; the same logical action under the new epoch succeeds.
- `error_precedence_matrix`: ordered negatives for every §3 step with
  positive controls, including reserve-before-commit for terminal
  freshness/authorization under full egress; failure-budget drop then
  injected-time replenishment recovering the retained receipt with its
  original tick.
- `shutdown_and_pending_ingress`: staged ingress + `shutdown` → staged work
  refused as `SessionExpired` in the returned summary with no execution and

### Interpretations and deviations (review these)

1. **View health bound is 3, not 2.** §1's comment says `CapturedView.health
   // <=2`, while §4 ("at most 3") and §7 ("per-view health count (at most
   3)") say 3. Actor, target and the incoming active head can be three
   distinct entities, so the implementation and checkpoint validation use 3.
2. **`ProtocolSelection` also derives `Copy`.** `as_u8(self)` on a
   non-`Copy` type fails clippy's `wrong_self_convention` under
   `-D warnings`; `Copy` is the only addition to §1's derive list.
3. **Retry-cache eviction is the cache's retirement path.** §3 step 8 says
   "insert ... without eviction (reservation guaranteed room)", but the §2
   table, the 256/257 eviction test and `StaleSeq`-on-evicted require
   oldest-first eviction. The cache therefore never blocks admission; the
   insert evicts to stay within 256 entries / 2 MiB.
4. **Outcome text comes from T020's own `ActionResolved` envelope.** Mapping
   `crpg_rules::Outcome` would need an unapproved `crpg-rules` edge. The
   host captures `actor`/`target`/`ability`/`damage` from the returned
   `ActionOutcome` and the symbolic text from the envelope the same
   `perform_action` journaled, failing closed (`HostError::Invariant`) if any
   field disagrees. Nothing is re-inferred from later state.
5. **Gameplay class is determined with `validate_action` before
   reservation.** That is sim's single legality source (ADR-0018, and the
   first thing `perform_action` runs), so an illegal action reserves only its
   rejection footprint and returns its typed error. Accepted commands still
   execute through `HistoryWorld::perform_action`; a `Combat` error there
   (unreachable) is committed as `IllegalAction` under the accepted
   reservation, which is a superset.
6. **Codec/session/gap/stale/conflict/exhaustion outcomes stage no reply.**
   §6 says they reserve nothing, so their status is reported only in
   `PumpSummary.results` (T018c's test driver did send receipts for some of
   these).
7. **Fenced bindings' staged commands.** After `unbind_peer` or a
   `SeqConflict` fence, commands the binding already staged stay queued and
   are refused as `SessionExpired` at the next pump, never executed.
8. **Cache-hit re-staging is best effort.** A retry whose receipt was
   already acknowledged (or dropped) re-stages it only if egress has room and,
   for rejections, the failure budget allows; otherwise the next identical
   retry recovers it.
9. **Resync-pending peers.** A peer waiting for a fresh state (bind/narrow
   without room) receives no per-command frames or receipts until the fresh
   state is staged; its cached outcomes are recovered by retry.
10. **Binding and widening without room.** `bind_peer` with no room for the
    initial state, and a purely widening `set_grants` with no room, fail with
    `HostError::QueueFull` and change nothing (the contract specified only
    the narrowing case).
11. **Load validation goes beyond the §7 list** where the host's own
    invariants demand it: the wrapped sim journal must be empty
    (`AuthorityInvalid`, mirroring `from_history`'s `PendingHistory`), and
    per record the lane/seq range, monotone history ranges,
    `processed_tick <= server_tick`, strictly ascending view epochs and
    health ids, and `outcome` agreement with the retained `ActionResolved`
    (all `Malformed`). `TooLarge { len }` from the reader entry point reports
    cap + 1.
12. **`executions()` is per host lifetime**: it is not in the §7 field
    list, so a loaded host restarts it at 0 while authority and captures
    continue.
13. **Turn and membership details.** An active head is disclosed in `Turn`
    iff it is mapped (present) for that peer. `EntityLeave` is never emitted
    in this slice: membership changes only through grant narrowing, which
    resynchronizes, and no despawn has a wire path. State frames chunk at 256
    ops; the 64 KiB bound follows from the per-op sizes.

### Fixture provenance

`crpg-server` has no `crpg-data` edge, so the suite cannot author an
encounter. `tests/fixtures/three_combatants.json` was produced once by a
throwaway test placed temporarily in `crates/crpg-net/tests/` (which already
dev-depends on `crpg-data`/`crpg-sim`), run, and deleted before commit: it
authored a ruleset (one pool, abilities strike/smite/whiff with single-band
always-`success`/`critical_success`/`failure` tables), three creatures
(health 10/10/3) and an encounter, ran `HistoryWorld::new(7)` +
`start_encounter`, and wrote the wrapper JSON. The suite loads it through
sim's validated `Deserialize`; the four start envelopes are left pending so
`from_history`'s `PendingHistory` refusal is tested.
