# T137 — `crpg-sim` adapter generalization (ADR-0029 Follow-on 4)

## Task
ADR-0029 Follow-on 4 (`docs/adr/0029-kernel-range-and-time-model.md:483`):
the combat adapter executes the authored surface that T136b added to
`crpg-data`, through the `crpg-rules` kernel, with every existing replay,
history and hash golden byte-identical (`:425-427`). The surface is: typed and
derived stats, the `Constant`/`ActorStat`/`Opposed` defences, ability
`bonus_stats`, damage `dice`, rolled `initiative`, effect `Stat` modifier
targets and tag `grants` (`tasks/T136b.md:80-235`; normative mapping
`:412-428`). T137 deletes the T136c bridge (`tasks/T136b.md:430-461`) and
extends `ability_is_legacy` as T138 hands off (`tasks/T138.md:846-850`).

## Crate(s)
**`crpg-sim` only.** Three packages run one after the other: T137a, T137b,
T137c ("Size budget"). No companion package in another crate ("Companion

## Decision
- **D1. The T136c bridge exists on this base, and T137 deletes it field by
  field.** `CombatError::UnsupportedAuthored` (`crates/crpg-sim/src/combat.rs:793-794`,
  Display `:834`), the start check (`:966-986`), the `unreachable!` arms
  (`:1290-1298`, `:1336-1338`) and `tests/unsupported_authored.rs` are all
  here. T137a narrows the check to the shapes T137b executes; T137b deletes
  the variant, the check and the suite (the T017d precedent,
  `crates/crpg-sim/AGENTS.md` "Generalization to multi-ability…").
  *Rejected:* draft A's D0 ("no bridge on this base"), which described
  pre-T136c code.
- **D2. T134 is not written or landed with T137 (both drafts; confirmed).**
  Every T136b dice field is a sum: initiative, `Opposed`, damage, and the
  `Dice` literal (`tasks/T136b.md:143-145`, `:177-182`, `:199-204`,
  `:209-213`). `Opposed` maps to an opposed *total*
  (`tasks/T136b.md:424`). `DiceExpr` has no mode field
  (`crates/crpg-rules/src/dice.rs:52-57`). No authored field can select a
  counting mode, so T137 cannot be T134's consumer. The ADR row's premise
  ("implement with its first consumer (T137)",
  `docs/adr/0029-kernel-range-and-time-model.md:480`; Q3 `:503-505`) fails.
  T134 returns with the first data shape that selects counting. This
  departs from the ADR table's wording, so it is open question 1.
  *Rejected:* landing T134 now, which adds a `crpg-rules` package for a mode
  nothing can request.
- **D3. Only `Int` stats execute, because only `Int` stats can reach a
  combat outcome.** The kernel has no implicit conversion: binaries need two
  `Int` or two `Fixed` operands (`crates/crpg-rules/src/stats.rs:89-94`).
  Data requires a formula's root kind to equal its stat's kind
  (`tasks/T136b.md:346-351`). Every combat consumer is `Int`: health
  (`:41-43`), attributes (`crates/crpg-data/src/combat.rs:1171`), defence,
  bonus, initiative and `Stat`-target names (`tasks/T136b.md:371-389`,
  `:352-354`). An `Int` formula can therefore read only `Int` stats, and no
  `Fixed`, `Bool`, `Enum`, `Tags` or `Dice` value can affect any margin,
  damage, key or fold. The adapter carries no non-`Int` stat. It still
  checks that a non-derived `Fixed` stat is present, as data's prefab rule
  does (`tasks/T136b.md:390-393`). *Rejected:* draft A's defaults (they
  invent rules). Draft B's rejection of non-derived `Bool`/`Enum`/`Tags`/`Dice`
  stats (data calls them clean, `tasks/T136b.md:494-496`). Storing `Fixed`
  or typed values (A's `secondary`, B's `fixed_stats`): hashed state with no
  reader (`crates/crpg-sim/AGENTS.md:295-297`). Open question 3.
- **D4. Derived `Int` formulas persist as a sim-owned symbolic mirror,
  `IntFormula`, on `CombatDefinition.derived`.** Sim state never holds a
  `crpg_data` wire type. Every adapter enum mirrors its wire
  (`AbilityDefense`, `EffectTarget`, `combat.rs:138-169`), so save bytes
  never follow the data schema. Persisted state holds names, never handles
  (E014, `crates/crpg-sim/AGENTS.md:288-292`). *Rejected:* A's
  `crpg_data::StatDecl` in hashed state, and B's six-kind `StatFormula`/`StatLiteral`
  (narrowed by D3).
- **D5. Every stat read is one kernel query per operation.** It is never
  evaluated once and cached. The value is `ModifierPipeline::query`
  (`crates/crpg-rules/src/modifier.rs:543-578`) over the `Int` definitions.
  The block holds the combatant's base values, with **current** health for
  the health stat. The view holds that combatant's unexpired `Stat`
  modifiers. Values change when a `Stat` effect attaches or health drops.
  *Rejected:* A's D4 (evaluate once at start). It goes stale on the first
  `Stat` effect and the first hit.
- **D6. Stat and tag handles come from a per-operation scratch interner;
  T137 interns nothing into `World`.** Each operation that queries stats or
  projects tags takes `world.interners().clone()` and interns into the
  clone. The roll tag keeps its world handle, because the clone preserves it.
  One exception stays: an accepted `TargetStat` action interns its stat into
  the world interner, as today (`combat.rs:1915`). The `srd_lite` goldens hash
  that entry. *Rejected:* B's staged start-time interning (more hashed
  state, a staged interner commit, and three load checks), and A's
  unspecified handles.
- **D7. One execution path; legacy identity by construction, not by a
  surface switch.** Views keep today's modifier sets and add only `Stat`
  modifiers and the extras a new defence needs (B8). The fully modified value of a
  base stat with no `Stat` modifier is its stored value. So all-`Int`,
  no-derived content computes today's numbers through the same code.
  *Rejected:* B's "kernel surface on/off" (B3), a second path whose trigger
  list must stay in step with the shapes.
- **D8. Defences follow the T136b mapping rows exactly**
  (`tasks/T136b.md:422-424`): `Constant` → `Against::Dc{owner: target}`;
  `ActorStat` → `Against::Stat{entity: actor}`, so the actor's view supplies
  the DC fold (`crates/crpg-rules/src/resolution.rs:303-321`, `:525-549`);
  `Opposed` → `Against::Opposed` with `natural_die: None`, actor dice then
  opposing dice on `combat.roll` (`resolution.rs:612-702`). *Rejected:*
  draft A's B8 ("each side applies its own `natural_die`"), which contradicts
  the row. The `ActorStat` DC owner is open question 5.
- **D9. Bonus stats are synthetic `Roll` `Add` modifiers under one reserved
  type, `combat.bonus_stat`, with `StackAll`.** The mapping requires
  `ModOp::Add` into `ModifierTarget::Roll` (`tasks/T136b.md:421`). The kernel
  requires a policy per type (`modifier.rs:715-721`). Data accepts any
  nonempty `mod_type` (`crates/crpg-data/src/combat.rs:1476-1477`), so the
  name is reserved only in encounters that carry bonus stats. *Rejected:*
  A's unreserved `"bonus_stat"` (an authored effect could re-policy it).
  B's reservation in every encounter (it rejects content that has no bonus
  stats).
- **D10. Damage dice are a parallel `AbilityDefinition.damage_dice`.** They
  are drawn after `resolve` and before `spend_costs`, summed in `i64` and
  clamped once into `0..=u32::MAX` (B). `damage: Vec<(Outcome, u32)>` keeps
  its type and bytes (`combat.rs:240`). *Rejected:* A's `damage_dice` on
  `CombatDefinition`, which is never read: legacy copies exist only for
  legacy shapes. A's "saturating `u32`" leaves a negative dice offset
  undefined.
- **D11. Initiative is rolled once at start, in both modes, and stored in
  `Combatant.initiative`.** TB keys, TB rollover and the RT→TB rebuild read
  the stored value (`task/T138a-rt-policy:…/combat.rs:2416-2441`; T138 B25).
  RT start keys stay `0` (T138 B11, B28). This is T138's "stored
  initiative" (`tasks/T138.md:848-850`). *Rejected:* rerolling per round,
  which would add a draw to rollover. Rolling only on TB entry, which would
  put a mode-dependent draw mid-fight.
- **D12. A derived formula can fail mid-fight, so `validate_action` gains a
  last stage.** The only kernel query failure reachable after start is
  division by zero (`crates/crpg-rules/src/derived.rs:34-37`, `:116-123`). A
  `Stat` modifier or lost health can make a divisor zero after a clean
  start. When `definition.derived` is nonempty, the stage runs the action's
  stat queries; a failure is the new `CombatError::StatEvaluation { stat }`.
  Execution and enumeration inherit it (invariant 12,
  `crates/crpg-sim/AGENTS.md:235-241`). Neither draft covered this. B's start
  preflight leaves a reachable `expect` panic. Open question 2.
- **D13. Tags.** `EffectDefinition.grants` is carried. `Combatant.tags`
  carries `Creature.tags` only in encounters that reference a granting
  effect. The projection (placement tags ∪ grants of unexpired attachments)
  is passed as each view's `QueryContext.tags`. Unconditional carriage moves
  both `srd_lite` goldens, because those creatures carry tags
  (`campaigns/fixtures/combat_srd/creatures/hero.json:15`). T136b fixes the
  mapping (`tasks/T136b.md:25-28`, `:428`, OQ7 `:645-646`). ADR K4 names the
  projection's purpose (`docs/adr/0029-kernel-range-and-time-model.md:104-105`).
  A new `CombatError::TooManyTags` covers a union over `MAX_TAGS`. Open
  question 4.
- **D14. Load coherence extends `World` deserialization** with the exact
  messages of B23, beside the existing checks (`crates/crpg-sim/src/world.rs:149-522`).
  A save that would panic on its next action fails at load. *Rejected:*
  B's interner-membership checks (D6 interns nothing).
- **D15. No new `SimEvent`, `HistoryEvent`, `CombatAction` or tick stage.**
  No companion crate is needed. No crate outside `crpg-sim` matches
  `CombatError` exhaustively or builds a literal of a changed struct (checked:
  `crpg-server`, `crpg-net`, `crpg-script`, `crpg-cli`, `crpg-testkit`).

## Behaviour
Terms. A **base `Int` stat** is a declared `Int` stat without `derived`;
health is one. A **derived `Int` stat** is a declared `Int` stat with
`derived`. A **usable stat** is a non-health `Int` stat, base or derived. For
a definition, the usable names are `attribute_names` ∪ the `derived` names.
Items are marked [a] for T137a or [b] for T137b.

1. **B1 (bridge) [a, b].** In T137a, C2's condition (`combat.rs:966-983`)
   becomes exactly: `ruleset.initiative.is_some()`, or any value in
   `spec.abilities` has an `Opposed` defence or a damage entry with `dice`,
   or any value in `spec.effects` has `grants`. C3's `Opposed` arm stays
   `unreachable!`; the `Constant`, `ActorStat` and `Stat` arms execute. In
   T137b, `UnsupportedAuthored`, its Display arm, the check, the remaining
   arm and the doc-comment entry (`:915`) are deleted. No start rejects a
   T136b shape as unsupported.
2. **B2 (reading stats at start) [a].** For each participant, then each
   declared stat in authored order (replacing `:1035-1057`), the stat is
   handled by kind:
   - A base `Int` stat runs today's checks unchanged: presence
     (`MissingStat`), wholeness (`InvalidStatValue`), checked conversion
     (`ValueOverflow`) and health positivity (`InvalidStatValue`).
   - A non-derived `Fixed` stat must be present (`MissingStat`). Its value,
     fractional or not, is not read.
   - Any other stat is not read: a derived stat of any kind, or a
     non-derived `Bool`, `Enum`, `Tags` or `Dice` stat. Its absence from
     `Creature.stats` is not an error.
3. **B3 (attributes) [a].** `CombatDefinition.attribute_names` and each
   `Combatant.attributes` hold the base usable stats in authored order. For
   an all-`Int`, no-derived ruleset that is today's list and today's values.
4. **B4 (derived carriage) [a].** `CombatDefinition.derived` holds every
   derived `Int` stat in authored order, its `ExprWire` converted node for
   node: `Literal(Int(v))` → `Literal(v)`, `Stat(n)` → `Stat(n)`, and each
   binary to its namesake. Derived non-`Int` stats are not carried. Data owns
   two preconditions: an `Int` formula holds only `Int` literals and names
   only health or usable stats, and the kernel pipeline over the `Int`
   definitions builds. A violation of either panics with exactly `derived
   int stats are validated by data read-time checks`.
5. **B5 (start preflight) [a].** Runs when `derived` is nonempty, after
   B2's loop and the initiative checks (B21). For each participant in
   authored order, then each derived stat in authored order, it queries the
   stat with no modifiers and no tags (B6). The first failure is
   `InvalidStatValue { stat }`, naming that derived stat.
6. **B6 (stat evaluation) [a].** An operation takes one scratch
   `world.interners().clone()` and interns into it, in this order: the
   health stat, `attribute_names`, the `derived` names. The definitions are
   health and each attribute name as plain `Int`, and each derived name as
   `Int` with its formula; `Stat(n)` becomes the handle of `n`. A
   combatant's block is `health → Int(current health)` plus each attribute
   value. A fully modified value is `ModifierPipeline::query(entity, stat,
   view)` (`modifier.rs:543-578`). The world interner is never written by
   this item.
7. **B7 (handles) [a, b].** Every `StatId` and `TagId` that T137 code builds
   comes from that operation's scratch clone. `RollTag` is the world's
   `roll` handle, which the clone preserves. The one world-interner write on
   any action path is B10's, as today.
8. **B8 (views) [a, b].** Each view's modifiers are rebuilt from the
   holder's attachments with `expires_round > round`, in attachment order
   and then authored modifier order (`:1521-1576`). They are filtered by
   target kind:
   - **Actor view:** `Roll`, `Stat`, and `Dc` too when the defence is
     `ActorStat`, then the actor's synthetic bonus modifiers (B14).
   - **Target view:** `Dc` and `Stat`, plus `Roll` and the opposing
     synthetic modifiers when the defence is `Opposed`.
   - **Self-targeted action:** one view with `Roll`, `Dc` and `Stat`, then
     the synthetic modifiers of B14.
   Each view's `stats` is B6's block, and its `tags` is B19's projection.
   With no `Stat` modifier and no synthetic modifier, each fold set equals
   today's (`:1882-1883`, `:1969-1971`). `RollRequest.tags` stays empty on
   both sides.
9. **B9 (`ActorAttribute`) [a].** `Against::Dc { value: the actor's fully
   modified ability.attribute, owner: target, modifier_target: roll_tag }`.
10. **B10 (`TargetStat`) [a].** Before resolution, the accepted action calls
    `world.interners_mut().intern_stat(stat)`, as today (`:1915`;
    T138a `:2190`). The resolution uses `Against::Stat { entity: target,
    stat: <scratch handle>, modifier_target: roll_tag }`.
11. **B11 (`Constant`) [a].** `Against::Dc { value: v, owner: target,
    modifier_target: roll_tag }`; no stat is read.
12. **B12 (`ActorStat`) [a].** `Against::Stat { entity: actor, stat,
    modifier_target: roll_tag }`: the actor's fully modified stat, then the
    actor's `Dc` fold (open question 5).
13. **B13 (`Opposed`) [b].** `ResolutionRequest.target = Some(target)` and
    `against = Against::Opposed(RollRequest { actor: target, roll:
    RollSpec::Dice(dice), bonus_target: roll_tag, natural_die: None,
    stream: COMBAT_ROLL_STREAM, tags: TagSet::new() })`. The actor's dice
    draw first and the opposing dice second, on one stream
    (`resolution.rs:612-702`). There is no DC fold. The margin is actor
    total minus opposing total.
14. **B14 (bonus stats) [a; `Opposed` b].**
    - **Contributions.** The actor's `bonus_stats` add to the actor's roll
      fold for every defence. An `Opposed` defence's `bonus_stats` add to
      the target's opposing roll fold.
    - **Modifier shape.** Each name contributes one modifier, in authored
      order: `target: Roll(roll_tag)`, `op: Add(Int(fully modified value on
      that side's view))`, `mod_type: COMBAT_BONUS_MOD_TYPE`, `name: None`,
      `condition: None`, `priority: 0`, `source: { kind: "bonus_stat", id:
      ability }`.
    - **Ids.** The k-th synthetic modifier of a view takes the k-th smallest
      `Ulid::from_u128(n)`, `n ≥ 1`, that no effect modifier in that view
      uses.
    - **Policy.** The pipeline's policies gain `COMBAT_BONUS_MOD_TYPE →
      StackAll` when the action has at least one synthetic modifier.
    - **Self-targeted `Opposed`.** The actor list and then the opposing
      list share one id sequence in the one view, so both rolls fold both
      lists.
    - **Empty.** An absent or empty list adds nothing.
15. **B15 (stat evaluation stage) [a].** `validate_action` for
    `UseAbility` gains a last stage, after affordability, that runs only
    when `definition.derived` is nonempty.
    - It builds the action plan with a scratch clone and queries, in
      order:
      1. the defence-side stat: `ActorAttribute` reads the attribute on the
         actor, `TargetStat` the stat on the target, `ActorStat` the stat
         on the actor;
      2. the actor's bonus stats;
      3. an `Opposed` defence's bonus stats, on the target.
    - The first failure returns `StatEvaluation { stat }`, naming the
      queried stat.
    - The stage mutates nothing.
    - `perform_action`, T138a order admission and due execution, and
      `legal_actions` inherit it. Execution's `expect` on `resolve` is
      therefore unreachable.
16. **B16 (damage dice) [b].**
    - **Total.** Flat is the first `damage` entry for the decided outcome,
      or 0. When `damage_dice` holds an entry for that outcome, the damage
      is `clamp(i64(flat) + i64(dice.evaluate(rng, COMBAT_ROLL_STREAM).total),
      0, u32::MAX)`. Otherwise it is `flat`, with no draw.
    - **Draw timing.** The draw comes after `resolve` returns and before
      `spend_costs`, as the next draw on `combat.roll`.
    - **Report.** `ActionOutcome.damage` reports that value.
    - **Death.** The saturating subtraction and the exactly-once `Died`
      rule are unchanged (`:2027-2047`).
17. **B17 (initiative) [b].**
    - **Key.** With an initiative rule, each participant's key is
      `dice_total.saturating_add(bonus).saturating_add(participant.initiative)`.
      `bonus` is the saturating sum, in authored order, of the participant's
      fully modified bonus stats at start (B6, no modifiers).
    - **Draws.** There is one `evaluate` per participant on `combat.roll`,
      in authored participant order. The draws come after every start check
      and before the spawn loop, in TB and RT starts alike.
    - **Storage.** The key is stored in `Combatant.initiative`. TB start,
      TB rollover (`:2219-2227`; T138a `tb_round_start`) and the RT→TB
      rebuild insert it. RT start keys stay `0`.
    - **No rule.** The authored key is used verbatim, with no draw.
18. **B18 (`Stat` targets) [a].** `rebuild_modifier` maps `Stat { stat }` to
    `ModifierTarget::Stat(<scratch handle>)` with `Add`/`Set(Int(value))`.
    While attached, it changes every fully modified read of that stat on the
    holder, and of every derived stat depending on it. That covers B9, B10,
    B12 and B14. `Roll`/`Dc` behaviour is unchanged.
19. **B19 (tags) [b].**
    - **Carriage.** When any referenced effect has nonempty `grants`, each
      `Combatant.tags` is its creature's `tags`, sorted ascending and
      deduplicated, and each `EffectDefinition.grants` is the authored
      list. Otherwise both are empty.
    - **Projection.** A view's `tags` is the scratch handles of `{tags} ∪
      {grants of each unexpired attachment}`.
    - **Reader.** No T137 behaviour reads a tag: rebuilt modifiers keep
      `condition: None` (`:1515`), as no data shape authors one. The
      projection is the executed contract (T136b OQ7).
20. **B20 (tag bound) [b].** When any referenced effect grants tags, the
    start fails `TooManyTags` if, for some participant, `|distinct
    Creature.tags ∪ every grant of every referenced effect| > MAX_TAGS`
    (1024, `crates/crpg-rules/src/lib.rs:44`).
21. **B21 (start order and transactionality) [a, b].** This is the pinned
    order, extending today's (`:910-925`) and T138a's.
    1. The opening checks: `EncounterActive`, `ModeUnsupported` (T138a),
       `TooManyParticipants`, `TooManyStats`, the data-owned asserts, and
       (T137a only) the narrowed bridge.
    2. Placements, then `MixedArea`, then `AreaMismatch`.
    3. Per participant: `MissingCreature`, then B2 per stat.
    4. [b] When the ruleset has an initiative rule: its dice
       (`InvalidDice`), then each bonus name, which must be usable
       (`MissingStat`).
    5. [a] The B5 preflight.
    6. Pool templates.
    7. Per ruleset-listed ability, in this order:
       1. the spec entry;
       2. the attribute, which must be in `ruleset.attributes` and usable
          (`MissingStat`);
       3. dice;
       4. outcome table;
       5. costs;
       6. defence: a `TargetStat`/`ActorStat` name must be usable
          (`MissingStat`); for `Opposed` [b], the dice (`InvalidDice`) and
          then each bonus name (`MissingStat`);
       7. [a] each `bonus_stats` name must be usable (`MissingStat`);
       8. [b] each damage entry's `dice`, in authored order (`InvalidDice`);
       9. effect;
       10. natural.
    8. Per referenced effect, ascending:
       1. the empty-shape check;
       2. [a] `InvalidEffect` when its `mod_type` equals
          `COMBAT_BONUS_MOD_TYPE` and any listed ability carries bonus
          stats (its own or its `Opposed` defence's);
       3. per modifier: the two policy checks, then [a] a `Stat` target
          name must be usable (`MissingStat`).
    9. `DuplicateModifier`, then `PolicyConflict`.
    10. [b] B20.
    11. Publication: the definition, [b] the B17 draws, the spawn loop, the
        roll-tag intern (`:1440`), and the head refresh.

    Steps 1–10 mutate nothing: scratch interners only. A rejected start
    leaves no entity, event, RNG stream, interner entry or hash change.
22. **B22 (legacy shape and goldens) [a, b].**
    - **Predicates.** `ability_is_legacy` and `definition_is_legacy` are
      exactly as under "Interface".
    - **Legacy shape.** A single-ability, single-pool, effect-free, all-`Int`,
      no-derived, no-initiative encounter writes the 15-field definition,
      as today.
    - **Vector shape.** Any one of bonus stats, damage dice, a derived stat
      or an initiative rule forces the vector shape. Save then load gives an
      equal `World`.
    - **Goldens.** Every golden under "Goldens and approvals" is
      byte-identical per target.
23. **B23 (load coherence) [a, b].** In `World::deserialize`'s combat arm,
    exact messages:
    - **Relaxed.** "combat definition declares no attributes" (`world.rs:174-178`)
      fires only when `attribute_names` and `derived` are both empty. "combat
      definition names an undeclared checked attribute" (`:189-193`) and
      "combat ability names an undeclared checked attribute" (`:282-286`)
      test membership in the usable names. "combat ability names an undeclared
      defense stat" (`:291-311`) covers `TargetStat` and `ActorStat`, with
      the usable names and not health. A legacy save meets each one exactly
      as today.
    - **L1 [a]**, after the health check (`:194-201`): a derived name that
      is empty, repeated, equal to `health_stat`, or in `attribute_names`
      fails `combat derived stat is misdeclared`.
    - **L2 [a]**: a `ModifierPipeline::new` over B6's definitions, built on
      a fresh `Interners`, that fails, fails `combat derived stats fail their
      kernel validation`. This covers unknown names, cycles, depth, nodes and
      kinds.
    - **L3 [a; initiative and `Opposed` b]**: an ability, `Opposed` or
      initiative bonus name outside the usable names fails `combat bonus
      stat names no declared int stat`.
    - **L4 [a]**, in the effect loop (`:332-366`): a `Stat` target outside
      the usable names fails `combat effect stat target names no declared
      int stat`.
    - **L5 [a]**: a `COMBAT_BONUS_MOD_TYPE` effect while any ability carries
      bonus stats fails `combat effect uses the reserved bonus modifier
      type`.
    - **L6 [b]**, in the combatant loop (`:400-500`): `|tags ∪ every grant
      of the definition's effects| > MAX_TAGS` fails `combatant tags exceed
      their bound`.
24. **B24 (replay) [b].** Two runs of one same-seed script over a fixture
    using every shape give equal per-step `state_hash` sequences. A run that
    saves and reloads mid-script continues to the same hashes.
25. **B25 (neutrality) [a, b].** No production code names a ruleset, stat,
    tag, die size or modifier type. The only new strings are
    `COMBAT_BONUS_MOD_TYPE` and `BONUS_SOURCE_KIND`.

   data accepts still runs. (b) Restrict instead: at start, every `Divide`

   data-clean content.

   combat consumer can read them; non-derived `Fixed` presence is still
   checked. (b) Carry `Fixed` bases and every kind's formula in hashed
   state now (draft B's shape, ≈ +150 lines). That state has no reader
   until T139.
4. **Creature tags** (D13). *Recommend* (a): carry them only in encounters
   that reference a granting effect. This keeps T136b's mapping and every
   golden. (b) Defer creature tags to T139 and project grants only. (c)
   Always carry them, and re-bless both `srd_lite` goldens.
5. **`ActorStat` DC owner.** *Recommend* (a): the actor's own `Dc`
   effects fold, per the approved mapping row
   (`tasks/T136b.md:423`; kernel `resolution.rs:579-611`). The target's
   defensive effects do not touch an actor-stat check. (b) Resolve as
   `Against::Dc { value: actor stat, owner: target }`, so the target's `Dc`
   effects apply, as for `ActorAttribute`. This amends that row.
6. **Surface golden.** *Recommend* (a): T137c with two per-target
   baselines, as ADR-0029 `:425-427` names. (b) Defer it, and rely on R13's
   determinism test and the hand-written oracles.
