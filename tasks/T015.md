## Design decisions

1. Rules remains a typed in-memory kernel. No filesystem, authoring loader,
   campaign adapter, scheduler, entity registry, effect store, or hook dispatcher.
2. A dice expression contains one dice group and an optional integer offset.
   Multiple groups, rerolls, exploding dice, and general arithmetic syntax are
   outside this grammar. Arbitrary supported side counts are data.
3. Querying a dice-valued stat returns an expression, never a random result.
   Randomness is consumed only by explicit evaluation/resolution calls.
4. Callers select named streams on their `DeterministicRng`. Failed calls leave
   the complete RNG unchanged, including the set of created streams.
5. Outcome tables partition signed margins using sorted lower bounds. Natural
   rules are ordered data applied to an explicitly selected raw die.
6. Resource timing is caller-supplied simulation time/events. Pools do not
   subscribe to hooks or own a timeline.
7. No API additions to core are needed. New runtime roll identifiers wrap
   existing tag handles; authored table, pool, and rest identities use ULIDs.
8. The spec's literal-exclusion gate applies to the whole rules crate. Test
   arbitrary die sizes through numeric construction/formatting (including size
   20); do not put the prohibited `d20` text in crate files, comments, or fixtures.
   That text is permitted here outside the crate. This is not a ban on that size.

## 1. Dice expressions

```rust
pub enum DiceSelection {
    All,
    KeepHighest(u32),
    KeepLowest(u32),
    DropHighest(u32),
    DropLowest(u32),
}

pub struct DiceExpr { /* private validated fields */ }
impl DiceExpr {
    pub fn new(count: u32, sides: u32, selection: DiceSelection, offset: i32)
        -> Result<Self, RulesError>;
    pub fn count(&self) -> u32;
    pub fn sides(&self) -> u32;
    pub fn selection(&self) -> DiceSelection;
    pub fn offset(&self) -> i32;
    pub fn evaluate(&self, rng: &mut DeterministicRng, stream: &str)
        -> Result<DiceRoll, RulesError>;
}
// FromStr<Err = RulesError>, Display; structural equality, not distribution equality.
pub struct DieResult { pub value: u32, pub kept: bool }
pub struct DiceRoll {
    pub expression: DiceExpr,
    pub dice: Vec<DieResult>,
    pub total: i32,
}
```

Grammar, ASCII and case-sensitive:

```text
expression = count "d" sides [selection] [offset]
selection  = ("kh" | "kl" | "dh" | "dl") unsigned
offset     = ("+" | "-") unsigned
count, sides, unsigned = one or more ASCII decimal digits
```

No whitespace, omitted count, parentheses, trailing data, decimal points,
Unicode digits, or leading signs on count/sides. Leading zeros are accepted.
Keep values must be `1..=count`; drop values `0..count` (retain at least one).
Count is `1..=MAX_DICE_COUNT`, sides `1..=MAX_DIE_SIDES`. Offset accepts the
full `i32` range, including its minimum through negative magnitude parsing.
Overflow is an error, never a panic. Input length is measured in UTF-8 bytes.

Display uses minimal decimal digits, lowercase syntax, omits a zero offset,
and otherwise preserves the selection variant (even a redundant keep/drop).
`parse(display(expr)) == expr`. Implement DiceExpr serde as this canonical
string with deserialization through the parser; no unchecked field decoding.

Draw all dice in authored index order, including discarded dice. Use core's
`gen_range_u32(NonZeroU32(sides)) + 1`, including for one-sided dice: it consumes
a range draw. Selection ranks values high/low as requested; equal values rank
earlier original indices first, including when selecting dice to drop. Trace
order always stays draw order. Sum kept dice and offset in `i64`, then clamp
once to `i32`. Dice aggregation is separate from T014's per-op modifier folds.

Streams are exact case-sensitive nonempty UTF-8 strings of at most the stream
byte limit. Validate before requesting a stream. No independent RNG, retained
free-standing stream, or implicit seed. An internal evaluator may accept a
borrowed core Pcg32 from the owning named-stream map.

## 2. Dice-valued stats and persistence

Add `StatValue::Dice(DiceExpr)`, `StatKind::Dice`, and the internal value-kind
equivalent. Literal and reference expressions support Dice; arithmetic/min/max
operators still require matching Int or Fixed operands. Dice supports `Set`
only; `Add`, `Multiply`, and `Clamp` fail with `InvalidOperation` when the
operand kinds match and the operation itself is unsupported; mismatched operand
kinds fail with `TypeMismatch`, following T014's validation order. The
existing stacking-policy compatibility rules still apply (an Add-only policy
cannot accept a Dice Set).

Add `SerializableStatValue::Dice(String)` using the DTO's existing enum tagging
convention. Conversion out emits canonical notation. Conversion in parses every
dice value during preflight before interning any symbol; errors leave the
interner unchanged. Other DTO wire forms stay byte-shape compatible. Runtime
StatValue/StatBlock remain non-serde. Keep all T014 validation ordering; handle
Dice at the corresponding existing value/type-validation stage.

## 3. Roll and DC modifier targets

```rust
pub struct RollTag(pub TagId); // Copy, Eq, Ord; no serde
// Extend existing ModifierTarget (retain Copy):
// Roll(RollTag), Dc(RollTag), alongside Stat(StatId).

pub struct NumericModifierBreakdown {
    pub entity: EntityId,
    pub target: ModifierTarget,
    pub base: i32,
    pub value: i32,
    pub contributions: Vec<Contribution>,
}
impl ModifierPipeline {
    pub fn query_numeric(&self, entity: EntityId, target: ModifierTarget,
        base: i32, context: &QueryContext<'_>)
        -> Result<(i32, NumericModifierBreakdown), RulesError>;
}
```

`query_numeric` accepts only Roll/Dc, rejecting Stat with `InvalidTarget`.
It applies modifiers to the supplied integer base, not to a fabricated stat.
Reuse the existing selection/fold helpers; do not maintain a second independent
implementation of stacking. Set/Add/Clamp require Int operands; Multiply uses
T014's full-range fixed scaling. Contributions retain all target-matching
modifiers, including excluded ones, in the existing phase/priority/ID order.

Both query APIs validate the entire supplied context: mismatched entities,
limits, stored values, duplicate modifier IDs, then modifier shape/policy by
ascending modifier ID. Stat modifiers still require declared targets; Roll/Dc
need no stat declaration and are validated as integer targets. Unrelated valid
targets do not contribute; unrelated malformed modifiers still fail validation.
The old stat API retains its earlier stat-existence check. For `query_numeric`,
check entity then target kind before context validation. No declaration lookup
for RollTag, whose issuing interner is the caller's responsibility as with tags.

## 4. Data-driven outcome tables

```rust
pub enum Outcome { CriticalSuccess, Success, Failure, CriticalFailure, Custom(u8) }
pub struct OutcomeTableId(pub Ulid);
pub struct OutcomeBand { pub min_margin: i64, pub outcome: Outcome }
pub enum NaturalEffect { Shift(i16), Override(Outcome) }
pub struct NaturalRule { pub face: u32, pub effect: NaturalEffect }
pub struct OutcomeTable { /* private validated fields */ }
impl OutcomeTable {
    pub fn new(id: OutcomeTableId, bands: Vec<OutcomeBand>,
        natural_rules: Vec<NaturalRule>) -> Result<Self, RulesError>;
    pub fn id(&self) -> OutcomeTableId;
    pub fn bands(&self) -> &[OutcomeBand];
    pub fn natural_rules(&self) -> &[NaturalRule];
    pub fn evaluate(&self, margin: i64, natural: Option<u32>) -> OutcomeDecision;
}
pub struct OutcomeDecision {
    pub band_index: usize,
    pub natural_rule_index: Option<usize>,
    pub outcome: Outcome,
}
```

Bands are nonempty, within the limit, begin at `i64::MIN`, and have strictly
increasing lower bounds in supplied order. Do not silently sort them. Select
the greatest lower bound <= margin; upper bounds are exclusive and implicit.
Natural rules are bounded and each face is `1..=MAX_DIE_SIDES`. Repeated faces
are rejected, keeping priority unambiguous. No requirement to order outcomes
by enum discriminant; band order is the authored degree order.

A matching natural rule shifts the selected **band index**, clamped to the
first/last band, or overrides its outcome. Positive shifts move toward higher
margins. There is at most one rule application and no chaining. Record the
unshifted `band_index` and matched rule index in the decision. No natural value
means no rule; a table rule for a face unavailable on a particular die simply
does not match. Outcome labels have no numeric/critical behavior in the engine.

The table and its component data implement serde. Wire shape is an object
`{id, bands, natural_rules}`; reject unknown fields and run constructor
validation on decode. OutcomeTableId serializes transparently as the ULID
string. Outcome uses adjacent tagging `type`/`value`, snake_case; NaturalEffect
uses the same tagging. Band/rule objects reject unknown fields. No JSON writer
or loader is added; serde_json remains test-only.

## 5. Resolution

```rust
pub enum RollSpec { None, Dice(DiceExpr) }
pub struct RollRequest {
    pub actor: EntityId,
    pub roll: RollSpec,
    pub bonus_target: RollTag,
    pub natural_die: Option<u32>, // zero-based raw draw index
    pub stream: String,
    pub tags: TagSet,
}
pub enum Against {
    Dc { value: i32, owner: EntityId, modifier_target: RollTag },
    Stat { entity: EntityId, stat: StatId, modifier_target: RollTag },
    Opposed(RollRequest),
}
pub struct ResolutionRequest {
    pub roll: RollRequest,
    pub target: Option<EntityId>,
    pub against: Against,
    pub outcome_table: OutcomeTableId,
}
pub struct ResolutionContext<'a> {
    pub pipeline: &'a ModifierPipeline,
    pub entities: &'a BTreeMap<EntityId, QueryContext<'a>>,
    pub outcome_table: &'a OutcomeTable,
}
pub struct ResolvedRoll {
    pub roll: Option<DiceRoll>,
    pub natural: Option<u32>,
    pub total: i32,
    pub modifiers: NumericModifierBreakdown,
}
pub enum AgainstBreakdown {
    Dc(NumericModifierBreakdown),
    Stat { stat: ModifierBreakdown, dc: NumericModifierBreakdown },
    Opposed(ResolvedRoll),
}
pub struct ResolutionResult {
    pub actor: ResolvedRoll,
    pub against: AgainstBreakdown,
    pub against_value: i32,
    pub margin: i64,
    pub decision: OutcomeDecision,
}
pub fn resolve(request: &ResolutionRequest, context: &ResolutionContext<'_>,
    rng: &mut DeterministicRng) -> Result<ResolutionResult, RulesError>;
```

The optional target is contextual identity only; it neither chooses the DC
owner nor changes modifier membership. Require a provided entity view if it is
Some. Each used map key must match its QueryContext.entity; unused views are
ignored. The host owns liveness/authority. Do not recursively nest resolutions.

Evaluation contract:

1. Check table ID equality; actor existence; optional target existence; then
   defender/DC-owner existence. Validate actor roll shape, then opposing roll
   shape if present, then participating contexts in ascending EntityId order.
   Validate each unique context once, even if actor and defender are the same.
2. A RollSpec::None has base zero, requires no natural selector, and requires an
   empty stream. Dice requires a valid nonempty stream and a selector, if any,
   less than dice count. The selected natural value is a raw face even if that
   die is later dropped. It never means the sum or modified total.
3. Actor roll conditions use the union of its entity tags and its request tags.
   Opposing roll conditions use its own corresponding union. Both unions must
   satisfy MAX_TAGS. DC/stat conditions use their owner's original context tags;
   actor/request tags do not leak into them. No persistent tag mutation.
4. Query a stat-based DC through the existing stat pipeline and require Int;
   apply Dc modifiers to that final stat value. Constant DC also receives its
   owner's Dc modifiers. Opposed defense is the opposing roll's final total,
   without an additional Dc fold.
5. Evaluate actor dice, then opposing dice, then the respective Roll modifiers
   on each raw total (or zero). Shared stream names consume consecutive draws
   in that order. Do not roll the opponent twice or apply the table to it.
6. Compute margin as `i64(actor_total) - i64(against_value)` without saturation;
   select the table result with the actor's natural value. Zero margin has no
   hidden tie winner: the table defines its outcome.

Use a staged clone of the owning DeterministicRng, committing it only after
complete success; thus any error, even after provisional draws, preserves the
original exactly. No RNG mutation or stream creation for successful no-roll
resolution unless the opposed side actually rolls. Apart from the successful
RNG commit, resolution mutates nothing. Preflight DC/stat evaluation precedes
draws; reuse the resulting trace rather than querying it again.

## 6. Resource pools

```rust
pub struct ResourcePoolId(pub Ulid);
pub struct RestId(pub Ulid);
pub enum RefreshTrigger {
    OnTurnStart, OnRoundStart, OnRest(RestId), OnTick(u64), Never,
}
pub enum RefreshEvent {
    TurnStart, RoundStart, Rest(RestId), Tick(Tick),
}
pub struct ResourcePool { /* private validated fields */ }
impl ResourcePool {
    pub fn new(id: ResourcePoolId, max: u32, current: u32,
        refresh: RefreshTrigger) -> Result<Self, RulesError>;
    pub fn id(&self) -> ResourcePoolId;
    pub fn max(&self) -> u32;
    pub fn current(&self) -> u32;
    pub fn refresh_trigger(&self) -> RefreshTrigger;
    pub fn can_afford(&self, amount: u32) -> bool;
    pub fn spend(&mut self, amount: u32) -> Result<(), RulesError>;
    pub fn refresh(&mut self, event: RefreshEvent) -> bool;
}
```

Validate current <= max; max zero is valid. OnTick period must be nonzero.
Spending zero succeeds; insufficient funds returns an error without mutation.
Matching refresh resets current to max; return true iff current changed.
Turn/round triggers match their event kinds, rest matches exact RestId, Never
matches nothing. Tick n matches positive ticks divisible by n, with simulation
tick zero as origin but not itself a refresh. Use core Tick accessors.

No event history is stored. Immediate repeated refresh is idempotent; spending
between repeated delivery of the same event allows another refill. The host
must deliver each logical event once and select the appropriate entity's pools.
There is no cross-pool atomic cost API in this task, no implicit clock advance,
no max adjustment API, and no fractional/negative resource counts.

Pools, IDs, triggers and events implement serde with unknown fields rejected;
IDs use transparent ULID strings. Pool wire fields are `id`, `max`, `current`,
`refresh`; decode through new. Triggers/events use adjacent `type`/`value`
snake_case tags. Invalid decoded state is rejected. A pool is rules state,
not a permitted nested hook payload.

## 7. Resolution hook vocabulary

Extend KernelHook, preserving existing wire shapes and Copy:

```rust
BeforeRoll { actor: EntityId, target: Option<EntityId>, resolution: Ulid },
AfterRoll { actor: EntityId, target: Option<EntityId>, resolution: Ulid, total: i32 },
BeforeDamage { source: EntityId, target: EntityId, resolution: Ulid, amount: i32 },
AfterDamage { source: EntityId, target: EntityId, resolution: Ulid, amount: i32 },
```

The host supplies the correlation ULID and owns the hook emission points.
Damage hooks describe caller-computed/caller-applied nonnegative damage; document
that semantic precondition without adding damage calculation or authority here.
These enum fields stay core-closed: do not put DiceExpr, RollTag, Outcome,
resource objects, breakdowns, or stat/tag handles in event payloads.
Keep HookHandler and HookMutation unchanged. resolve does not call handlers or
emit events; this is vocabulary, not a hidden dispatcher or damage engine.

## Errors and validation

Reuse RulesError and its existing Display/location/cycle conventions. Add codes
`InvalidDice`, `InvalidStream`, `InvalidOutcomeTable`, `InvalidResolution`,
`InvalidTarget`, `MissingEntity`, `InvalidResource`, and `InsufficientResource`.
Use existing `LimitExceeded`, type, policy, duplicate, and reference errors
where they already express the fault. Do not add a second error hierarchy.

New diagnostic roots:

- Dice parser: `/dice/input/<byte-offset>`; input length overflow `/dice/input`.
  Report the earliest offending byte (EOF uses input length); valid numeric
  tokens outside a permitted range point at the token start. Lex left-to-right
  with checked numeric accumulation, then validate selection against count.
- Dice constructor: `/dice/count`, `/dice/sides`, `/dice/selection`, in that order.
- Stream: `/stream`.
- Table: `/outcome_table/bands`, indexed band paths ending `/min_margin`, then
  `/outcome_table/natural_rules/<index>/face`. Validate collection limits before
  contents, bands before natural rules, and entries in authored order.
- Resolution: `/resolution/outcome_table`, `/resolution/actor`,
  `/resolution/target`, `/resolution/against`, and roll-field suffixes. Prefix
  forwarded stat/modifier failures with their participant path so two sides can
  be distinguished. Preserve the nested error code and cycle field.
- Resources: `/resource/current`, `/resource/refresh`, `/resource/amount`.

More-specific existing stat/modifier paths remain intact for direct query APIs.
Pin multifault precedence in tests, including errors before any RNG mutation.
For dice strings inside stat DTOs, prefix parser paths with the existing
symbolic stat entry path, using the existing escaping convention.
