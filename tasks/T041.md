## Task
Give the M4 exit criteria 1, 2, 3 and 7 their proofs
(`docs/IMPLEMENTATION_PLAN.md:171–183`):

1. **Scripted headless clients** (T041a): a tests-only client that a test
   wires to the real run loop — `HostLoop<LocalHost>` (the embedded host the
   Windows client runs, D65a) — and that speaks protocol v4 exactly as the
   Godot bridge will: the `0x82` snapshot through `ReassemblyPoolV4`,
   `ReplicaWorldV4`, lane-0 intents, lane-1 `MoveOutbox`, samples. Between
   each client and its link sits a deterministic simulated network with
   loss, latency, jitter, retransmission and datagram duplication. A client
   follows a script that reads only its own replica.
2. **A 5,000-tick loss/jitter desync test** (T041b): two players and an
   intruder over the spec's 3 % loss, with the semantic check ADR-0009
   requires — each replica equals what the server projects for the same
   viewer — plus exactly-once execution against an independent mirror.
3. **Two clients end with identical visible state** (T041b): the same run's
   two players compare equal on the world they see; a separate embedded
   smoke has them connect, move and fight to the death.
4. **The host-level malicious-client cases** T042 handed over (T041c):
   ownership, illegal time, interest, flooding, oversize and malformed
   frames, replay, and the non-canonical retry that must be a cache hit.
5. **The gate-13 dedicated smoke** (T041d, in `crpg-server`'s own tests):
   T040's real binary, two real QUIC clients that fight to identical visible
   state, a rejected message that appears as T040's log line, and a clean
   quit that saves. The embedded smoke is T041b's fight; both run on
   Windows/MSVC and Linux/GNU in the existing workspace test job.

No production source changes in any crate.

## Readings
Design decisions this contract makes. Each needs approval with the contract.
The last line of each says which draft it follows, or neither.

1. **The clients are tests-only and never ship.** Everything lives in
   `tests/` and is included by each suite with
   `#[path = "support/headless.rs"] mod headless;` (the T016c shape,
   `crates/crpg-testkit/AGENTS.md:106–111`, `:152–156`); `src/`, the public
   API (`:29–36`) and `tests/support/mod.rs` are untouched. A production
   client type belongs to the Godot bridge (T046/T047). *Both drafts.*
2. **T027c is not a prerequisite.** The host already carries a per-session
   viewer context: the operator's `ControlGrant`, `DisclosureGrants`,
   `FactGrants` and `PauseRights` at bind (`crates/crpg-server/src/host.rs:1377–1422`),
   projected per session through its own `InterestView`
   (`crates/crpg-server/src/host_v3.rs:152`, `:319`). T027c would compute
   entitlement from authority instead of operator grants
   (`tasks/T027c.md:15–21`); the desync check compares a client with a twin
   holding the *same* grants (Reading 6), so either source of grants gives
   the same proof. *Neither draft raised it.*
3. **The real loop, the real v4 wire.** Every in-process run is
   `HostLoop<LocalHost>` (`crates/crpg-server/src/run.rs:110`, `:332`) over
   `bind_v4_peer` sessions: the snapshot arrives as `0x82` frames through
   `ReassemblyPoolV4` and is answered with `TransferUp::Published`, as
   T037e's client does (`crates/crpg-testkit/tests/host_movement.rs:499–582`).
   `LocalHost` acknowledges an entry when the link's queue accepts it
   (`crates/crpg-server/src/run.rs:689–710`), exactly as `QuicHost`
   acknowledges when the transport accepts it
   (`crates/crpg-server/src/quic.rs:10–13`), so the simulated network sits
   on the client side of the link and plays the transport. *Rejected:* the
   bare `Host` for these runs (skips the loop and the link); in-process real
   QUIC (the T098 flake class, `tasks/BACKLOG.md:169`, `tasks/T098.md:312`).
   *Draft A's `LocalHost`, with draft B's insistence on the real client path.*
4. **The network is QUIC-shaped: reliable streams lose time, datagrams lose
   frames.** Up frames, lane-0 down frames (v4 deltas and `0x82`) and lane-1
   receipts each travel a reliable channel: every frame arrives once, in
   order, after latency plus jitter, and each loss costs one retransmission
   timeout (head-of-line blocking). Samples travel a datagram channel: lost,
   duplicated and reordered. `crpg-net`'s `InMemoryTransport` drops a lost
   reliable frame for good and has no latency or jitter
   (`crates/crpg-net/src/sim.rs:308–330`, `:572–606`), and a QUIC stream
   never shows its reader a gap, so it is not the model here; the client's
   pool already tolerates duplicated and reordered deltas
   (`crates/crpg-net/src/pool_v4.rs:554–642`), which `crpg-net`'s suites
   prove. Draws come from `crpg_core::DeterministicRng` (already a testkit
   dev-dependency). *Neither draft: both used `FaultSchedule`. Rejected:*
   draft B's hand-rolled xorshift (a second generator for no gain).
5. **The spec's numbers.** `Faults::SPEC`: 3 % loss (spec T18,
   `docs/CRPG_ENGINE_SPEC.md:2082`), latency 2 cycles (100 ms), jitter 0–4
   cycles, retransmission timeout 4 cycles, 1 % datagram duplication, at
   most 8 consecutive losses of one frame. *Neither draft. Rejected:* draft
   A's `loss_every: 7` (14 % periodic, no jitter).
6. **The desync oracle is a twin session.** ADR-0009: the replica's visible
   state matches the server's filtered projection
   (`docs/adr/0009-determinism-scope.md:46`). For each faulted client the
   arena binds a twin right after it with identical control, grants and
   rights; the twin is delivered with no faults and never acts, and the host
   projects it through its own view exactly as it projects the client. After
   a settle (Reading 7) the two replicas must be equal. This tests what the
   desync test is for — convergence over a bad network — and D3 proves it
   fails when one frame is lost for good. Whether the projection discloses
   the right things is the H-filter suites' job
   (`crates/crpg-server/tests/host_v3_session.rs`, `host_v4_session.rs`).
   *Neither draft. Rejected:* draft A's hand-written disclosure table fed to
   `InterestView` (re-implements the host's grant rules in the test, and the
   host's per-session view is `pub(crate)`); draft B's op-for-op comparison
   against `project_delta` (the same access problem).
7. **Compare after a settle, and compare state, not timing.** Positions
   change only through anchors and samples (`Moved` stores nothing,
   `crates/crpg-net/src/replica_v4.rs:186`), samples are lossy, and the host
   refreshes every 20 ticks (`crates/crpg-server/src/host.rs:131`, `:4164`).
   A settle pauses every script, switches every channel to `Faults::CLEAN`
   for `SETTLE_CYCLES` (60) cycles and then requires every channel empty.
   `canon` leaves out `server_tick`, `next_event_seq` and each position's
   `tick`, which legitimately differ between sessions. *Neither draft.*
8. **Exactly-once execution is checked against a mirror.** T037e's oracle
   (`crates/crpg-testkit/tests/host_movement.rs:251–484`): a clone of the
   started `HistoryWorld`, driven with the same sim calls. `LocalHost`
   admits in ascending peer order, each peer's frames in arrival order, then
   ticks (`crates/crpg-server/src/run.rs:565–666`), so the arena applies
   each cycle's delivered lane-0 intents to the mirror in that order, then
   `tick_with_movement`, and `authority_hash` must equal the mirror's
   `history_hash`. A lost or doubled command breaks the equality.
   *Both drafts hashed the authority; neither had an independent mirror.*
9. **"Identical visible state" means the world, not the viewer's private
   facts.** The standing-order fact follows control
   (`crates/crpg-server/src/host_v3.rs:425`) and `HostFacts` carries the
   viewer's own pause rights (`crates/crpg-net/src/protocol_v3.rs:267–276`),
   so two players who each control their own hero legitimately differ
   there. `world_view` is `canon` with every `facts.order` set to `None`
   and `host_facts` set to `None`; the two players' `world_view`s must be
   equal. *Draft A's different-control, equal-disclosure pair.*
10. **A script reads only its own replica and acts once per turn value.** On
    a new `TurnFact` naming its actor it sends one action; when that
    action's receipt arrives and the replica still shows the same
    `TurnFact`, it sends `EndTurn` (a successful strike may end the turn by
    itself). `observed_tick` is the replica's `server_tick`. *Neither draft.
    Rejected:* draft A's fixed tick cadence and draft B's per-tick op list
    (under jitter both send out of turn).
11. **The 5,000-tick run patrols; the fight is separate.** `combat_basic`'s
    goblin has 6 health and a strike deals 2 on success
    (`campaigns/fixtures/combat_basic/creatures/goblin.json`,
    `abilities/strike.json`), so a fight ends within a few rounds. D1's
    players each move one step between two points and end the turn, so the
    encounter lives for all 5,000 ticks; the fight is D5 (and G1). Moves
    stay within one 1 m step, the one unit of pool `P` (T037e's in-memory
    movement block, `crates/crpg-testkit/tests/host_movement.rs:190–205`).
    *Neither draft.*
12. **Host-level malicious cases run on `Host` directly.** `LocalHost`
    discards the pump summary (`crates/crpg-server/src/run.rs:654`), and a
    decode failure or an ingress refusal sends no receipt, so the clean
    rejection is visible only in `IngestDisposition` and `PumpSummary`
    (`crates/crpg-server/src/host.rs:1691–1782`). T041c is the index proof on
    the production client wire (v4) over campaign data; deeper per-code
    coverage stays in `crates/crpg-server/tests/host_capture.rs` and
    `host_lane1.rs`. The log line (D67a) is the binary's (`tasks/T040.md`,
    B-13); G1 proves one end to end. *Draft A's case list, draft B's
    "observed, not written" log line.*
13. **Reconnection and save/load are not re-proved here.** M4 exits 4 and 5
    are T025b's (`crates/crpg-server/tests/host_reconnect.rs`,
    `host_quic_resume.rs`) and T039's (`host_save.rs`); v4 sessions have no
    resume yet (`tasks/BACKLOG.md:121`). G1 only checks that T040's quit
    save reloads. *Draft A. Rejected:* draft B's resume test D3 (v4 cannot
    resume; v2 resume needs a `0x81` transfer client).
14. **The dedicated smoke is a `crpg-server` test.** Cargo sets
    `CARGO_BIN_EXE_<name>` only for the package's own binaries; a testkit
    test could reach T040's binary only through a nested `cargo` run or an
    unstable artifact dependency. `crpg-server`'s tests already hold the
    QUIC rig, the v2 replica and its oracle (`R`, `:318–471`). No new edge
    either way. *Neither draft:* draft A put it in testkit behind a new
    `crpg-net-quic` edge; draft B smoked an in-process `QuicHost`, not the
    program.
15. **The smoke speaks what T040 serves.** T040 binds `bind_resumable` over
    a V1/V2 save and has no `/3` movement endpoint (`tasks/T040.md`, Reading
    8). G1's clients use `QuicClient::connect` (`crpg-lane0/1`,
    `crates/crpg-net-quic/src/client.rs:118–124`), which binds with
    `bind_peer`: v2 deltas, no transfers
    (`crates/crpg-server/src/quic.rs:1011–1015`). The save is `R`'s
    three-combatant fixture, whose strike always succeeds for 3 damage and
    ends the turn (`crates/crpg-server/tests/fixtures/three_combatants.json`,
    the `combat.definition.abilities` entry `…JV`), so every outcome is
    hand-computable. Movement over the dedicated server is D71a. *Neither
    draft.*
16. **Wall clock only in G1, and never as an oracle.** The binary paces its
    loop by `SystemClock`; G1's waits use `R::DEADLINE` (30 s) per wait as
    the existing rig does (`R`, `:57`, `:596–631`) and fail only as a guard.
    An intent the server answers `StaleTick` because the machine stalled is
    re-sent with the receipt's `processed_tick` (B-30), so load cannot fail
    G1 short of the guard. In-process suites read no clock
    (`crates/crpg-testkit/AGENTS.md`, invariant 7). *Draft B's guard rule.*
17. **Gate 13 runs inside the existing workspace test job,** on both legs,
    as gate 10 does (`tasks/BACKLOG.md:513`); no new CI job and no
    placeholder. *Draft B.*
18. **No goldens, no `HashMap`, no float.** Every expectation is relational
    or hand-computed; the new files use `BTreeMap`/`BTreeSet` and integers
    (testkit is outside the determinism lint, so the rule is self-imposed,
    invariant 7). *Both drafts.*
