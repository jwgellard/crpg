## Decisions (binding for this contract)

1. **One decode addition, nothing else in production.** The adapter accepts
   `{"combat": 1, "op": "end", "actor": <ULID>}` and calls
   `CombatAction::EndTurn { actor }` through the same two public sim
   operations. Parser, collector, loader, validator, golden default, exit
   codes, and stream conventions stay exactly as T016d left them. If the
   command cannot express the proof without a flag, stop into a finding
   instead of adding one.
2. **Error-string parity with the worked example.** The `end` failure
   strings match T017e's adapter verbatim (see §Interface), so the same
   rejected input reports the same reason through both harnesses. Attack
   strings stay byte-identical.
3. **Black-box first, seams second.** The new suite drives
   `env!("CARGO_BIN_EXE_crpgc")` over private temp copies and asserts exit
   codes plus exact stream bytes, never combat or replay internals.
    `combat_apply.rs` unit tests cover the decode matrix, accepted end
    dispatch, rejected-input rollback, and the private result-shape guard.
    Checked-in inputs stay read-only; no test generates a
   golden or mutates the source tree.
4. **Both campaigns through the same command.** The suite proves
   `combat_basic` (existing coverage, referenced not repeated) and
   `combat_srd` (new coverage) each verify through the identical command
   shape, including one test that runs both golden matches back to back
   outside the repository working directory.
5. **No new dependencies, no ADR.** This task follows the T016d thin-adapter
   precedent: one op decode plus black-box tests need neither.

## Interface (exact shapes)

Production change (in `src/combat_apply.rs` only):

```text
end: {"combat": 1, "op": "end", "actor": <ULID>}
```

Dispatch accepts `init` | `attack` | `end`; anything else stays
`unknown combat op`. Per-op allowed fields stay strict with unknown-field
rejection: `end` allows exactly `combat`, `op`, `actor`. The actor decodes
through the existing `decode_ulid` in field order, so a missing actor
reports `malformed combat end: actor must be a ULID string` and a
non-ULID actor reports `malformed combat end: invalid actor`. The call
first requires the initialized guard (`combat not initialized`), then
resolves the actor through the placement bindings (`unknown combat
identity actor: {actor}`, with the canonical uppercase placement ULID),
exactly like `attack`. Success requires
`Ok(None)` and discards it; an impossible `Ok(Some(_))` reports
`end failed: unexpected outcome`, never silent. Sim rejections report
`end failed: {Display}` verbatim (`NoEncounter`, participant/absence/
death/`OutOfTurn` in controller order; no ability/target/cost checks —
the CLI adds none). No World mutation occurs beyond the two public sim
calls; no winner, health, pool, attachment, or turn observation lives in
production adapter code. Unit tests may inspect public World state to verify
dispatch and rejected-input rollback.

Validation order for `end` (mirroring the adapter): object shape, version,
op membership, unknown-field scan (lexically smallest first), actor ULID
decode, initialized guard, identity resolution, sim turn-holding checks.

The defensive successful-result check uses one private pure helper in this
module, with no injected simulation backend or new public API:

```rust
fn require_end_outcome<T>(outcome: Option<T>) -> Result<(), String>;
```

`None` maps to `Ok(())`; `Some(_)` maps to exactly
`Err("end failed: unexpected outcome".to_owned())`. The adapter calls the
real `perform_action`, formats a sim `Err` as above, then passes its successful
optional outcome to this helper. Unit tests exercise `None::<()>` and
`Some(())`; do not corrupt World or modify sim to force an unreachable return.

Full World/RNG/event and binding rollback is required for ordinary decode,
binding, and sim rejections. An unexpected `Ok(Some(_))` is an internal
post-call contract violation: report it and abort playback, but do not claim
the already-successful call was rolled back. No transaction/cloning machinery
is introduced solely for that defensive branch.

## Behavior

- `crpgc replay <replay-path> --campaign <root> --golden <baseline>` verifies the
  checked-in `combat_srd.replay` against the target-scoped `srd_lite_*`
  golden with exit 0 and empty streams, on both native targets through
  their own baselines. The campaign root may live anywhere: renamed
  directories, spaces in names, absolute or cwd-relative paths, and an
  unrelated working directory are all covered, proving no
  repository-root or directory-name dependency. The replay path is always
  first after `replay`; only the following `--campaign` and `--golden`
  options may swap order. Flags before the replay path remain usage errors;
  do not change the parser to accept the former incomplete shorthand.
- The identical command shape verifies `combat_basic` (existing suite
  keeps that proof; this suite adds one same-command run over both
  campaigns back to back, not a second copy of the basic matrix).
- The pinned private-copy mutation below delays the lethal attack from
  tick 9 to tick 10 and diverges first at hash index/tick 9 with exit 1.
  Invalid `end` inputs instead fail application with exit 1 naming the
  scheduled tick, zero-based input index, and exact reason. Tests distinguish
  application failure from divergence, not just their shared exit code.
  Usage errors retain existing exit-2 diagnostics byte-for-byte.
- Verify-only holds: inputs, campaigns, replays, and baselines are
  byte-identical after every run (snapshot the temp trees before and
  after). Missing baselines report I/O, never a skip; mismatches report
  divergence, never tolerance.

### Pinned negative replay cases

Use B4's checked-in seed-285 replay (`total_ticks = 14`, accepted inputs at
ticks `0..=9`, lethal attack at tick 9). These are private test copies only;
the checked-in replay and both native goldens remain unchanged.

- **Divergence:** change only the final input's scheduled tick from 9 to 10.
  Leave seed, total ticks, payloads, and all other inputs unchanged. The
  schedule remains valid and the final action still succeeds; the first
  differing post-tick hash is index 9. Require the existing exact divergence
  diagnostic, empty stdout, and exit 1 against the native golden.
- **Dead actor:** retain all ten original inputs, append
  `{"combat":1,"op":"end","actor":"00000000000000000000000012"}`
  at tick 10 (input index 10), and retain total_ticks 14. The hero is dead
  after tick 9; require the sim `DeadActor` Display inside the exact
  `ApplyFailed` diagnostic, not divergence or `OutOfTurn`.
- **Out of turn:** in an otherwise unchanged replay, replace the actor on
  the tick-4 `end` (input index 4) with goblin placement
  `00000000000000000000000013`. Hero holds the turn then; require the exact
  `OutOfTurn` application failure at tick/index 4.

For portable malformed/guard rows, construct the smallest private replay:
an end-only input at tick/index 0 for pre-init rows, or the valid encounter-44
init followed by the tested end at tick/index 1 for initialized rows. Supply
an absent golden path: application must fail before golden I/O, with no
native baseline read. These rows run on every target/profile. Use the same
payloads in adapter unit tests to prove World and bindings stay unchanged.

Required end-error precedence rows:

| State/payload | Expected adapter reason |
|---|---|
| Missing actor or non-string actor | `malformed combat end: actor must be a ULID string` |
| Invalid ULID string, including before init | `malformed combat end: invalid actor` (decoding precedes initialized guard) |
| Unknown fields `aa` and `zz` plus invalid actor | `malformed combat end: unknown field aa` |
| Valid actor ULID before init | `combat not initialized` (before binding lookup) |
| Initialized, syntactically valid unbound actor `00000000000000000000000000` | `unknown combat identity actor: 00000000000000000000000000` |
| Initialized, bound actor out of turn | `end failed: {OutOfTurn Display}` |
| Initialized, bound dead actor after the pinned lethal prefix | `end failed: {DeadActor Display}` |

Pin full process stderr with the existing `crpgc replay`/`ApplyFailed`
formatting, including tick/index and one trailing newline. Expected reasons
must be independently specified, not generated by invoking the adapter under
test. Unit tests also cover object/version/op precedence and core ULID alias
normalization. Black-box dead/out-of-turn cases above need no golden read.
