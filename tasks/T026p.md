# T026p — protocol v4: movement on the wire (`crpg-net`)

**Status: draft for user review, 2026-11-14 (UTC).** Written by the Claude
architect from ADR-0036 L1–L6 and its U7 net policies
(`docs/adr/0036-movement-and-navigation.md:387–417`, `:117–130`), after
T036a–c (sim movement, `HistoryEvent::Moved`, D51) and T140a–e plus
T140r1–r2 (protocol v3 and its receiver) merged. It replaces the earlier
gate-only text of this file; that text's binding constraints are kept and
cited under "Readings" (Reading 15), and the one it no longer keeps
(highest-seq-wins intents) is superseded by ADR-0036 itself. It is split into
five parts, **T026p1 → T026p2 → T026p3 → T026p4 → T026p5**, each one
implementer run in `crpg-net`. It is an H-filter contract (it decides who
sees whose position); the user approves it with the "Questions for the
user".

Citation convention (T140's): a bare `:N` or `:N–M` is a line of the file
cited earlier in the same list item or sentence; where none has been cited
there, it is a line of ADR-0036. Every citation was checked at `095ed20`
(`master`, branch `task/T026p-c1`), which holds T036c, T140a–e and
T140r1–r2.

**`<base>`** (used in "Definition of done") is the commit a part's branch is
cut from. It must contain T140r2, checked by
`git merge-base --is-ancestor 21f403b <base>` (or, if squashed, by
`<base>` holding `crates/crpg-net/src/replica_v3.rs` with
`pub struct ReplicaWorldV3`); for T026p2 onward it also contains the previous
part's merge (T026p4 needs only T026p1, see "Routing and size").

Every literal byte below was computed by an independent Python model of the
layouts in "Wire layout" (postcard primitives: raw `u8`/`bool`, LEB128
varints, zigzag `i32`, raw `[u8; 16]`), not by any implementation. Notation,
shared with T140 and T140r: `Z16` is 16 bytes `00`; `U(n)` is
`Ulid::from_u128(n)`; `id(n)` is `NetId::new(n).unwrap()`;
`kN = EntityKey { area: U(10), entity: eN }` with `e1..e4` the first four ids
of one `GenerationalArena::<()>::new()`; `P(x, y, z)` is
`Point::new([x, y, z]).unwrap()` (raw `Fx16_16` values, 65,536 = 1 m);
`A = P(0, 0, 0)`, `B = P(65536, 0, -131072)`; `L = 2^29 = 536,870,912`. All
bytes are hex.

## Task
Add protocol version 4 to `crpg-net`: movement on the wire, as ADR-0036
L1–L6 decided and T140 left to this task (`tasks/T140.md:103–104`, Reading 17
at `:307–313`; ADR-0036 acceptance note 5, `:568–571`). Version 4 is the
first version with two lanes: lane 0 keeps every v3 message and window 1, and
gains the turn-based move verb and two movement ops; lane 1 is new and
carries real-time movement intents, their receipts, and position samples.
v1, v2, v3, `0x81`, `0x82` and `0x91` stay byte for byte. `crpg-net` still
reads no `World`: the host (T037) supplies every route result, position and
grant.

- **T026p1 — lane 0, v4 (S-set).** `protocol_v4` and `codec_v4`: version 4,
  the `Point` type and its bound, intents (the six v3 bodies plus
  `DeclareMove`), deltas (every v3 op by its v3 bytes, plus `Moved` and
  `Position`), and the v4 `frame_spans`.
- **T026p2 — lane 1 (S-set).** `movement_v4`: `MoveTo`/`Halt` intents,
  `MoveReceipt`, `MoveSample`, their codec, the sample splitter, and the U7
  policy constants.
- **T026p3 — position filter (H-filter).** `positions_v4`: the per-viewer
  `PositionView`, the composite `project_page_v4`, `project_samples` and
  `project_snapshot_v4`; `projection_v4`: the `Moved` event candidate.
- **T026p4 — v4 receiver gate.** `pool_v4`: `ReassemblyPoolV4`, T140r1's
  pool transliterated onto v4 deltas.
- **T026p5 — v4 client replica and sender.** `replica_v4`:
  `ReplicaWorldV4` (the v3 replica plus positions and samples); `outbox_v4`:
  `MoveOutbox`, the client's lane-1 sequence state.

## Readings
Design decisions this contract makes. Each needs the user's approval with
the contract (Questions 1 and 2 cover Readings 7 and 8).

1. **One version byte, two lanes, new modules beside v3.** Version 4 is byte
   4 for lane-0 frames and lane-1 messages alike; the lane byte tells them
   apart. Lanes: 0 combat (v1–v4, `crates/crpg-net/src/protocol.rs:34`), 1
   movement (v4; reserved since v1, `:27–33`), 2 snapshot (`0x81`/`0x82`,
   `crates/crpg-net/src/protocol_transfer.rs:22`), 3 session (`0x91`,
   `crates/crpg-net/src/protocol_resume.rs:21`). Every codec refuses another
   version's first byte with `UnsupportedVersion` and a foreign lane with
   `WrongDirection`, as T140 Reading 1 does (`tasks/T140.md:172–176`). There
   is no negotiation; T037 picks the version per session.
2. **Lane-0 v4 wraps the v3 ops; intents are re-declared.** T140 re-declared
   v2's ops because its receipts needed codes 21..=30
   (`tasks/T140.md:177–183`). v4 adds no code (Reading 3), so
   `DeltaOp::V3(op)` carries every v3 op with exactly its v3 bytes, and
   byte identity holds by construction instead of by a 21-variant copy. The
   price is two `pub(crate)` tokens in `codec_v3` (Permissions). Intents have
   no per-body function to call (`crates/crpg-net/src/codec_v3.rs:241–285`)
   and six small bodies, so v4 re-declares them, as T140a did, and adds
   `DeclareMove`. Rejected: re-declaring the 21 delta ops (about 500 copied
   lines and a byte-identity proof to keep); a length-prefixed op layout
   (moves the bytes of tags 0..=20 for nothing).
3. **No new rejection code.** `DeclareMove` and lane-1 refusals reuse v3's
   `RejectionCode` (`crates/crpg-net/src/protocol_v3.rs:525`): `NotAuthorized`
   (17) when the peer does not control the actor, `WrongMode` (22) for a
   `MoveTo` by a turn-based participant or a `DeclareMove` outside turn-based
   mode, `IllegalAction` (18) for every other gameplay or navigation refusal,
   and the existing admission and sequence codes. The client previews the
   path and the cost locally before sending (G3, `:460–464`), and G2
   (`:453–458`) detects a different mesh by revision, so a "no path" code
   would add nothing a player sees.
4. **Per-input reliable intents; latest target per actor per tick.**
   ADR-0036 rejected latest-seq-wins datagram intents (`:522–525`) for a
   reliable ordered stream (L2, `:392–394`) with exactly one receipt per
   admitted intent in `seq` order (L3, `:396–400`). Routes are replaced whole
   (R5, `:163`; `set_route`, `:202–206`), and the host runs at most one
   navigation query per actor per tick, earlier queued intents for that actor
   getting `Superseded` (H2, `:426–432`). This is the "latest-target versus
   per-input" answer the earlier text of this file asked to take from the sim
   contract; it supersedes that text's "highest-seq-wins may be selected for
   movement only".
5. **Receipts carry `epoch` and `processed_tick`** beyond ADR's
   `{ seq, actor, outcome }`. D13 asks for processed-seq and server-tick acks
   (`tasks/POST-T018-DECISIONS.md:318`), and the lane-0 `Receipt` carries
   both fields (`crates/crpg-net/src/codec_v3.rs:834–851`). `seq` is identity;
   `processed_tick` and `Accepted { start_tick }` are time.
6. **Samples are self-contained datagrams of at most 1,024 bytes and 38
   entries.** QUIC guarantees 1,200-byte UDP payloads (RFC 9000 §14); a 1-RTT
   packet spends at most about 44 bytes on its header, AEAD tag and DATAGRAM
   framing, which leaves at least 1,156. 1,024 is a power of two inside that.
   38 is the largest `n` with 24 + 26·`n` ≤ 1,024 (the header and entry
   maxima, "Wire layout"), so a sample within the count cap always fits and
   splitting is fixed chunking. Entries are in strictly ascending `NetId`. A
   sample has no epoch, because datagrams belong to one connection;
   `processed_seq` is the highest lane-1 `seq` receipted to the receiving
   peer (0 before any). The client keeps the newest sample per entity
   (L4, `:402–407`).
7. **Disclosure: a reliable anchor, then unreliable samples.** The lane-0 op
   `Position { entity, position }` carries `Some` when disclosure of an
   entity's position starts (and on a resend page) and `None` when it stops
   while the entity stays visible: the "forget" image of T140 Reading 4.
   Values between those two travel only in samples, so a walking creature
   costs no lane-0 traffic. `project_samples` reads the current grant on
   every call, so a revoked position leaves the samples at once (L5,
   `:409–411`), and the next page's `None` tells the client to forget it.
   An entity that leaves view needs no op: `EntityLeave` removes it.
   Rejected: positions as lane-0 images with change detection (one reliable
   op per mover per tick, which L4 moved to datagrams); samples alone (an
   entity would sit unplaced until a sample arrived, and revocation could
   not be told reliably). Who is granted what is Question 1.
8. **Positions after a reconnect come in the first page after the
   snapshot, not in the `0x82` body.** L5 says resync snapshots carry only
   granted positions. `project_snapshot_v4` meets that by clearing the
   `PositionView`, so the next page, whose `event_seq` is above the
   snapshot's cursor, re-anchors every granted position, and the client's
   pool releases that page right after the snapshot (T140r1 P-10 step 7,
   `tasks/T140r.md:419–431`). This is T140's host-facts pattern
   (`tasks/T140.md:278–281`, H-2 at `:1120–1124`). A body with positions
   would need a `0x83` transfer version with its own frame and body codec,
   and a new publication type through the v4 pool and replica, for about
   16 KB (1,024 × 16 bytes). Question 2.
9. **`Moved` is a lane-0 event at the history slot.** It is projected from
   `HistoryEvent::Moved` like `ActionResolved`, and disclosed under the
   viewer's position grant through a host-set `disclose` flag (the
   `Joined`/`Left` pattern, `crates/crpg-net/src/projection_v3.rs:41–58`).
   Points: 2..=64 (`MAX_ROUTE_POINTS`, U7), each component within U3
   (`:100–102`), and no zero horizontal segment (consecutive points with
   equal `x` and `z`; exactly R4's `ZeroSegment`, because `seg_len` is 0 iff
   `dx = dz = 0`, U4 `:104–107`). Route length is not checked: it needs a
   square root, and sim validated it (R4, `:155–161`). A candidate failing the
   point check is omitted (withheld, T140 Reading 8). In the replica `Moved`
   is a notice: liveness-checked, no state change. Positions come only from
   anchors and samples; G1's animation (`:446–451`) is T049's.
10. **The v4 pool is a third transliteration.** As D54 (a) chose for v3
    (`tasks/T140r.md:1119–1121`), `ReassemblyPoolV4` is `pool_v3` with the
    delta decoder and frame type swapped and its own id and update types.
    `PublicationV3` and `ReceiverStatusV3` are reused unchanged, because v4
    sessions keep `0x82` (Reading 8). Rejected: a generic pool (rewrites
    reviewed T140r1 code whose public types name v3 frames); feeding the v3
    pool transcoded frames (breaks held-byte accounting and `Conflict`
    detection). The `AGENTS.md` trap becomes "a fix to one pool is a fix to
    all three".
11. **The v4 replica wraps the v3 replica.** `ReplicaWorldV4` holds a
    `ReplicaWorldV3` and applies `V3` ops through its `apply_op`
    (`crates/crpg-net/src/replica_v3.rs:258`, one `pub(crate)` token), so
    every v3 rule stays one implementation; the v4 state is positions and the
    sample clock. The sequence and tick advance by applying an empty v3 frame
    to the inner replica (T140r R-4, `tasks/T140r.md:493–495`). Rejected:
    copying `replica_v3` (389 lines that would drift).
12. **The client's lane-1 sender state lives in `crpg-net`.** `MoveOutbox`
    holds the lane-1 rules from the client side (sequence, window 8, one
    receipt per intent in order, resend after a resume), so `crpg-godot`
    (T026, T050) and the host's tests share one tested implementation.
13. **Constants shared with sim are asserted, not imported.**
    `COORD_LIMIT_RAW` and `MAX_MOVED_POINTS` are declared in `protocol_v4`
    (net cannot use sim outside tests), and a test asserts they equal
    `crpg_sim::COORD_LIMIT_RAW` and `crpg_sim::MAX_ROUTE_POINTS`
    (`crates/crpg-sim/src/lib.rs:53–57`), as H5 does for nav (`:439–442`).
14. **Policies (U7, `:128–129`).** `POLICY_MOVE_INTENTS_PER_SEC` 20, burst
    40, and `POLICY_MOVE_IN_FLIGHT` 8 are host-enforced, tightening-only and
    never wire. Lane-1 traffic also counts toward every existing aggregate
    (`POLICY_INTENT_*`, the ingress and egress caps, the failure budgets).
    The interpolation delay is client policy (T049).
15. **The earlier constraints of this file stand**, except the one Reading 4
    supersedes: D13 scope; E017 B3's named-lane evolution (lane 1 arrives as
    a reviewed lane in a new version); v1 APIs and lane-0 window 1 unchanged
    (a larger combat window stays a separate net-only child); acks name the
    processed `seq` and a server tick without using the tick as identity
    (Reading 5); per-lane policy never bypasses aggregate limits, and
    tightening never raises a wire maximum; net never mutates a position or
    manufactures a movement result; no new dependency, v1 field change,
    replay or golden change, or `SimEvent` serialization. Reorder and loss
    control follow the transport decision, whose timing D23 set
    (`tasks/DECISIONS-2026-09-30.md:83–88`): the dedup patch lands with this
    first datagram lane, in `crpg-net-quic` ("Out of scope").

## Interface
Every public item has a doc comment (`#![warn(missing_docs)]`). Every new
struct and enum derives `Debug, Clone, PartialEq, Eq`, plus `Copy` where
marked. No serde, no `Serialize`, no restore constructor, no `HashMap`/
`HashSet`, `f32`/`f64`, `unsafe`, I/O, threads or clocks. Numbers from other
modules are used by path, never copied. Wire errors reuse
`crate::codec::CodecError`.

### T026p1 — `protocol_v4`
```rust
pub use crate::protocol::{NetId, SessionEpoch};
pub use crate::protocol_v3::{EncounterMode, ReceiptStatus, RejectionCode};
pub const PROTOCOL_VERSION: u8 = 4;
pub const INTENT_TAG_DECLARE_MOVE: u8 = 6;   // 0..=5 are crate::protocol_v3::INTENT_TAG_*
pub const DELTA_TAG_MOVED: u8 = 21;          // 0..=20 are v3's tags, carried by DeltaOp::V3
pub const DELTA_TAG_POSITION: u8 = 22;
/// Largest |raw| of any coordinate (2^29, ADR-0036 U3); equals crpg_sim::COORD_LIMIT_RAW (W12).
pub const COORD_LIMIT_RAW: i32 = 1 << 29;
/// Most points in a `Moved`; equals crpg_sim::MAX_ROUTE_POINTS (W12).
pub const MAX_MOVED_POINTS: usize = 64;

/// A position in raw `Fx16_16` metres `[x, y, z]`, every component within U3.
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct Point([i32; 3]);                       // private field
impl Point {
    /// `None` if any component's `unsigned_abs()` exceeds `COORD_LIMIT_RAW as u32`.
    pub fn new(raw: [i32; 3]) -> Option<Self>;
    pub fn raw(self) -> [i32; 3];
}
/// A disclosed position: where the entity is and whether it has a route.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct PositionFact { pub point: Point, pub moving: bool }

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct IntentFrame { pub epoch: [u8; 16], pub lane: u8, pub seq: u64, pub observed_tick: u64, pub actor: NetId, pub body: IntentBody }
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum IntentBody {
    DeclareAction { ability: crpg_core::Ulid, target: NetId }, // 0
    EndTurn,                                                  // 1
    Stop,                                                     // 2
    Pause,                                                    // 3
    Unpause,                                                  // 4
    RequestMode { mode: EncounterMode },                      // 5
    DeclareMove { destination: Point },                       // 6: the header's actor moves (ADR L6)
}
impl From<crate::protocol_v3::IntentBody> for IntentBody { /* same variant, same fields */ }

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct DeltaFrame { pub lane: u8, pub server_tick: u64, pub event_seq: u64, pub ops: Vec<DeltaOp> }
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum DeltaOp {
    V3(crate::protocol_v3::DeltaOp),                              // tags 0..=20, v3 bytes
    Moved { entity: NetId, points: Vec<Point> },                  // 21
    Position { entity: NetId, position: Option<PositionFact> },   // 22: None = withheld from now (forget)
}
impl From<crate::protocol_v3::DeltaOp> for DeltaOp { /* DeltaOp::V3 */ }

/// W-6's point checks: count, then zero horizontal segments.
pub fn check_points(points: &[Point]) -> Result<(), crate::codec::CodecError>;
```

## Wire layout
A coordinate is a zigzag `i32` (1 to 5 bytes); within U3 it is at most 5
(`zigzag(±2^29)` ≤ 2^30 < 2^35). A point is `x`, `y`, `z` in that order.
Brackets hold bytes present only when the flag before them is `true`.

**Lane-0 intent (T026p1):** `4`, `epoch [u8;16]`, `lane u8` (0), `seq u64`,
`observed_tick u64`, `actor u64`, body tag `u8`, then the body: tags 0..=5
exactly v3's (`tasks/T140.md:492–495`); tag 6 `DeclareMove` is one point.

**Lane-0 delta (T026p1):** `4`, `lane u8` (0), `server_tick u64`,
`event_seq u64`, op count `u64` (≤ 256), then each op:

| Tag | Fields after the tag, in order |
|---|---|
| 0..=20 | exactly v3's bytes for the op (`tasks/T140.md:500–511`) |
| 21 Moved | `entity u64`, `count` varint (2..=64), then `count` points |
| 22 Position | `entity u64`, `disclosed bool` [point, `moving bool`] |

**Lane-1 intent (T026p2):** `4`, `epoch [u8;16]`, `lane u8` (1), `seq u64`,
`actor u64`, tag `u8`: 0 `MoveTo` is one point; 1 `Halt` carries nothing.
No `observed_tick` (ADR L2: "There are no other fields").

**Lane-1 downstream (T026p2):** `4`, `lane u8` (1), `kind u8`, then:
- kind 0, receipt: `epoch [u8;16]`, `seq u64`, `actor u64`,
  `processed_tick u64`, outcome tag `u8`: 0 `Accepted` + `start_tick u64`;
  1 `Superseded`; 2 `Rejected` + `code u8` (v3 `RejectionCode`, 1..=30).
- kind 1, sample: `server_tick u64`, `processed_seq u64` (0..=`SEQ_LAST`),
  `count` varint (≤ 38), then per entry `entity u64`, point, `moving bool`.

Sizes: the largest lane-1 intent is 54 bytes, the largest receipt 60, the
largest sample 1,012 (24 + 38 × 26), the largest `Moved` op 972 (1 + 10 + 1
+ 64 × 15), the largest `Position` op 28.

## Behaviour
Normative. Each item names the tests that prove it. "Refused" means the
stated error, no output and no state change. **First failure wins** in every
list.

### T026p1: lane-0 v4
W-1. **Version gate.** `encode_*` writes byte 4 first. `decode_intent` and
`decode_delta` check, in order: (1) input over 4,096 / 65,536 bytes is
`FrameTooLarge`; (2) empty input is `Malformed`; (3) a first byte other than
4 (including 1, 2, 3, `0x81`, `0x82`, `0x91`) is `UnsupportedVersion`. The
v1, v2 and v3 codecs refuse byte 4 with `UnsupportedVersion` (their existing
rule, proven again here). *Tests:* W1.

W-2. **Intent decode order:** T140 A-2 (`tasks/T140.md:767–774`) with byte 4
and body tag 6: cap → version → `epoch` → `lane` (≠ 0: `WrongDirection`) →
`seq` (outside `SEQ_FIRST..=SEQ_LAST`: `Malformed`) → `observed_tick` →
`actor` (0: `Malformed`) → body tag (7..=255: `UnknownMessage`) → body →
trailing bytes (`Malformed`). **A point** (here and wherever one is read) is
`x`, then `y`, then `z`; each is a zigzag `i32` (a varint that overflows
`i32` is `Malformed`) checked against U3 (`unsigned_abs() > 2^29`:
`Malformed`) before the next is read. Truncation anywhere is `Malformed`.
*Tests:* W2, W3.

W-3. **Intent bodies 0..=5 are v3's bytes.** For every v3 `IntentFrame` `f`
with lane 0 and `seq` in range, `codec_v4::encode_intent` of `f` converted
(`From`) equals `codec_v3::encode_intent(f)` with byte 0 changed from 3 to 4,
and decoding those bytes returns the converted frame. For every byte string
`s` starting with 3 whose body tag, if the decoder reaches it, is not 6,
`codec_v4::decode_intent` of `s` with byte 0 set to 4 returns
`codec_v3::decode_intent(s)` (the same error, or the same frame converted).
*Tests:* W2.

W-4. **Intent encode** checks `lane` (`WrongDirection`), then `seq`
(`Malformed`), then writes the layout, then the cap. It never returns
partial bytes. A `DeclareMove` point is valid by its type. *Tests:* W3.

W-5. **Delta decode order:** cap → version → `lane` (`WrongDirection`) →
`server_tick`, `event_seq` (any `u64`) → op count (> 256: `LimitExceeded`,
before any op is read; the vector grows by push) → per op: no byte left is
`Malformed`; a tag of 0..=20 is read, with every v3 check in v3's order
(T140 A-4..A-7, B-1..B-3), by `codec_v3::take_op`; 21 is W-6; 22 is W-7;
23..=255 is `UnknownMessage` → trailing bytes (`Malformed`). *Tests:* W4, W7,
W8.

W-6. **`Moved` (tag 21):** `entity` (0: `Malformed`) → `count` (a varint
overflowing `u64`: `Malformed`; over 64: `LimitExceeded`; under 2:
`Malformed`; both before any point) → each point (W-2) → from the second
point on, a point whose `x` and `z` equal the previous point's is
`Malformed` (`y` may differ; Reading 9). `check_points` applies, in order:
count over 64 `LimitExceeded`, count under 2 `Malformed`, then the
zero-segment rule `Malformed`; it returns exactly the error `encode_delta`
returns for a `Moved` with those points. *Tests:* W5.

W-7. **`Position` (tag 22):** `entity` (0: `Malformed`) → `disclosed` flag (a
byte other than 0/1: `Malformed`) → if 1: the point (W-2), then `moving` (a
byte other than 0/1: `Malformed`). A withheld position has no byte after its
`00` flag. *Tests:* W6.

W-8. **Tags 0..=20 are v3's bytes.** For every v3 `DeltaFrame` `f`,
`codec_v4::encode_delta` of `f` with each op wrapped in `V3` returns
`codec_v3::encode_delta(f)` with byte 0 changed from 3 to 4, or the same
error. For every byte string `s` starting with 3 in which v3 decoding never
reaches an op tag of 21 or 22, `codec_v4::decode_delta` of `s` with byte 0
set to 4 returns `codec_v3::decode_delta(s)` with each op wrapped in `V3`
(or the same error). *Tests:* W4.

W-9. **Delta encode** checks `lane`, then the op count (`LimitExceeded`),
then each op in order (`V3(op)`: `codec_v3::extend_op`'s checks, T140 A-8
and B-4; `Moved`: `check_points`; `Position`: none), then the frame cap
(`FrameTooLarge`). It never returns partial bytes. *Tests:* W5, W8, W9.

W-10. **`frame_spans`** is T140 B-6 (`tasks/T140.md:885–898`) over v4 ops:
it runs W-9's per-op checks over every op in order and returns the first
failure with no spans; otherwise contiguous ranges covering `0..ops.len()`
in order, where a frame closes exactly when adding the next op would make it
hold more than 256 ops or more than `MAX_FRAME_OP_BYTES_V3` (65,512) bytes of
encoded ops, tags included. Empty input gives no spans. Because the v4
header is at most 24 bytes, a lane-0 frame holding one span encodes within
65,536 bytes for every `server_tick` and `event_seq`. For ops that are all
`V3`, the result equals `codec_v3::frame_spans` of the unwrapped ops.
*Tests:* W9.

W-11. **Identity.** Encoding a frame twice gives equal bytes;
`decode(encode(f)) == f` for every variant. A lowercase ULID in
`DeclareAction` decodes and re-encodes as canonical uppercase.
`Point::new(raw)` is `Some` exactly when every component's `unsigned_abs()`
is at most 2^29, and `raw()` returns `raw`. *Tests:* W3, W10.

W-12. **Shared constants** equal sim's: `COORD_LIMIT_RAW ==
crpg_sim::COORD_LIMIT_RAW` and `MAX_MOVED_POINTS == crpg_sim::MAX_ROUTE_POINTS`

### Host requirements (T037; recorded here, proven there)
- HM-1. A session runs one protocol version; a v4 session uses lane-0 v4
  frames, lane 1, `0x82` snapshots, and the client's `ReassemblyPoolV4`,
  `ReplicaWorldV4` and `MoveOutbox`. T140's H-1..H-7 and T141's H-8 (D54) apply to v4 sessions
  unchanged, with `codec_v4::frame_spans` and `project_page_v4` in place of
  their v3 names.
- HM-2. **Lane-1 admission**, per peer and epoch, mirrors lane 0's:
  `seq` equal to the next expected is new; a lower `seq` with cached
  identical bytes gets its cached receipt again, with different bytes
  `SeqConflict`; a higher one `SeqGap`; past `SEQ_LAST` `SeqExhausted`. The
  lane-1 retry cache is its own (`POLICY_RETRY_CACHE_PER_PEER_LANE` is per
  lane). Lane-1 sequence never reads or moves lane 0's, and lane 0 stays
  window 1.
- HM-3. **Limits.** More than `POLICY_MOVE_IN_FLIGHT` unreceipted intents is
  `Rejected(QueueFull)`; the `POLICY_MOVE_INTENTS_PER_SEC`/`_BURST` bucket is
  `Rejected(RateLimited)`. Lane-1 frames also count toward
  `POLICY_INTENT_*`, the ingress caps and the failure budgets.
- HM-4. **Receipts** (ADR H2, `:426–432`): exactly one per admitted intent,
  in `seq` order, on the lane-1 reliable stream; `processed_tick` is the
  server tick at the decision; `Accepted { start_tick: t + 1 }` for an intent
  decided between ticks `t` and `t + 1`; at most one navigation query per
  actor per tick, earlier queued intents for that actor `Superseded`. Codes
  per Reading 3.
- HM-5. **Samples** go only as datagrams, never on a stream and never into
  the lane-0 `event_seq`: each tick, `project_samples` with `refresh` set at
  the refresh interval T037 pins (ADR H4, `:436–437`), split by
  `sample_datagrams`, with `processed_seq` the highest lane-1 `seq`
  receipted to that peer.
- HM-6. **Rows.** One `PositionRow` per visible entity that has a mover,
  `point` from `Mover::position()`, `moving` true exactly when it has a
  route, `granted` per Question 1. A revoked grant is `granted: false` from
  the tick it is revoked.
- HM-7. **Pages.** Every v4 page is built by `project_page_v4`. After every
  `project_snapshot_v4`, the host builds and sends a page in the same tick,
  so the anchors are the first delta above the snapshot's cursor (Reading 8),
  with `Clock` and `HostFacts` (T140 H-2).
- HM-8. **`Moved`.** Each `HistoryEvent::Moved` becomes a
  `projection_v4::EventCandidate::Moved` at the history slot, with points
  converted by `Point::new` and `disclose` equal to that viewer's position
  grant for the entity in that page. This replaces the `Moved` → `None` arm
  (`crates/crpg-server/src/host.rs:2489`) for v4 sessions; v3 sessions keep
  it.
- HM-9. **`DeclareMove`** (ADR H3, `:434`): control check, the H2 path
  computation, then `perform_move`; refusals per Reading 3; retry and
  dedup exactly as every lane-0 verb.
- HM-10. **No combat effect.** Lane-1 traffic, simultaneous with a lane-0
  retry, never spends a resource twice or reorders a lane-0 receipt.

## Errors
No new codec error variant. `CodecError` (six variants,
`crates/crpg-net/src/codec.rs:51–66`) covers every wire refusal:

| Refusal | Error |
|---|---|
| lane-0 intent or lane-1 intent over 4,096 bytes; lane-0 delta over 65,536; lane-1 downstream over 1,024 | `FrameTooLarge` |
| first byte not 4 | `UnsupportedVersion`; empty input `Malformed` |
| lane byte wrong (lane-0 codec: not 0; `movement_v4`: not 1), or a v3 receipt lane | `WrongDirection` |
| intent body tag 7..=255, op tag 23..=255, lane-1 tag 2..=255, kind 2..=255, outcome tag 3..=255, code 0 or 31..=255, and every v3 `UnknownMessage` | `UnknownMessage` |
| op count over 256, `Moved` count over 64, sample count over 38, and every v3 `LimitExceeded` | `LimitExceeded` |
| truncation, trailing bytes, flag byte not 0/1, varint overflow, id 0, `seq` out of range, `processed_seq` above `SEQ_LAST`, coordinate beyond ±2^29, `Moved` count under 2, zero horizontal segment, sample entities not strictly ascending, and every v3 `Malformed` | `Malformed` |

`FactError` (`crates/crpg-net/src/facts_v3.rs:128–138`), `ProjectionError`
and `ReplicaError` (`crates/crpg-net/src/replica.rs`) are reused unchanged;
no variant is added, so the bridge's fatal-53 mapping and every `Display`
text stay. `OutboxError` is new, with five variants (Interface, T026p5):
its `Display` is `<Variant> at movement/outbox` with no payload, and
`source()` is `None`. Gameplay refusals are receipts, never codec errors.

## Questions for the user
1. **Who sees whose position? (Reading 7.)** A player's client is told a
   creature's position, and shown its turn-based moves, only when the host
   grants that player the creature's position; this contract makes the grant
   possible, and the host task (T037) sets the default. Today every player in
   an area sees every creature in it (D14,
   `tasks/POST-T018-DECISIONS.md:326–336`); there is no line of sight,
   stealth or fog of war. (a) **Position goes with visibility:** whoever can
   see a creature sees where it is and watches it move. (b) **Own party
   only:** players see positions of their own party, and other creatures
   are listed but not placed on the map. (c) **Per creature, by a perception
   rule:** needs a stealth or fog-of-war system that does not exist yet.
   *Recommend (a):* a creature you can see but cannot place cannot be drawn,
   so (b) breaks the map. Hiding positions later (fog of war, invisible
   creatures) needs no protocol change, because the grant is already per
   creature and per player.
2. **Positions after a reconnect come right after the reconnect package,
   not inside it. (Reading 8.)** A player who rejoins gets one package with
   everything they can see. This contract leaves positions out of it; the
   next update, sent in the same server tick, carries every position they
   may see, and the client applies the two back to back. (a) **That**
   (recommended): no new package format, and a player sees no difference.
   (b) **Positions inside the package:** a new package version (`0x83`) with
   its own reader, and a matching change in the client's download and
   replica code, for about 16 KB more per package and no visible change. ADR-0036 L5 says
   reconnect packages "carry only granted positions"; (a) meets that through
   the update that follows, and the manager would add a dated note to the
   ADR saying so. *Recommend (a).*
