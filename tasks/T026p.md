# T026p — N-LANES-policy and movement acknowledgments (`crpg-net`)

## Task / Crate(s) / Purpose

Sole crate: `crpg-net`, Phase 4 prerequisite to Phase 5 T026. **D13 scope selected**
(see [decision record](POST-T018-DECISIONS.md#d13--movementprediction-ordered-scope-unchanged-dependency-graph));
authoritative movement/nav contracts and T023 remain. Track E017 B3's named lane
evolution explicitly; a lane byte reserved in v1 is not an implemented movement
channel or permission to relax reliable combat.

## Interface — exact policy/version gate

After sim's authoritative movement API is approved, append exact movement
intent/ack/snapshot types and signatures, finite spatial/area bounds, version,
lane and discriminant assignments, per-lane sequence/epoch rules and queue/
payload maxima. Acknowledgment must identify processed movement seq and server
tick without using tick as command identity. Pin latest-target versus per-input
integration semantics from the sim contract; do not infer them from the spike.

Keep existing v1 APIs and lane-0 window 1. If a larger combat window is desired,
it is a separate net-only policy child with an explicit numeric window and
in-flight/cache/backpressure proof; this task does not select that option.

## Behaviour

Movement uses its own approved lane and sequence domain. Highest-seq-wins may
be selected for movement only; resource-spending lane 0 remains reliable ordered
with canonical command retry/dedup. New closed variants/lanes require a reviewed
wire version; v1 rejects foreign lanes/versions/tags exactly as its existing
codec does. Negotiated peers do not reinterpret old combat fields.

Per-lane policy must not bypass aggregate ingress/egress/peer limits or failure
budgets. Tightening operational windows/rates does not raise wire hard maxima.
Reorder/loss control comes from the accepted ADR-0004/D04 transport decision;
net does not mutate positions or manufacture a successful movement result.

## Constraints

[Standing rules](POST-T018-RULES.md) apply. Net only; authoritative simulation,
navigation, host integration and prediction are separate ordered owners. No
new dependency, v1 field/meaning change, replay/golden change or direct SimEvent
serialization. Preserve window-1 behavior for v1 peers throughout.
