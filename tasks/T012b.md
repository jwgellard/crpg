## Behaviour

### Collection and data flow (S/S12; D Fixed validation order; C Directory collection)

```text
parse args_os
  -> existing T011b read-only collector
  -> load_campaign(files, compile-time package engine version), once
  -> serialize_campaign(loaded), once
  -> compare returned bytes with collected originals
  -> replace differing recognized files in lexical SourcePath order
  -> exit
```

Reuse the collector, including sorted depth-first pre-order, root and entry
symlink rejection, `/` logical paths, `campaign_document_path` classification,
non-Unicode/error handling and ignored-file policy. It stays read-only for
validate; add a separate rewrite phase. No duplicate path-family table or
version parser. The CLI never calls individual migration steps, changes a
schema tag, decodes campaign JSON, recomputes a digest or implements a semantic
check (C; AC Validate flow and boundaries).

T012a alone owns chain semantics and their insertion into T010's fixed read
order. All collection, load and serialization work must succeed for the entire
map before any write starts. Data errors are converted through T011a's
`diagnostic_for_data_error` and printed unchanged. Incompatible engine, unknown
future schema, broken chain, malformed old/current payload, invalid layout,
duplicate id, invalid lock or digest mismatch cannot produce partial output
from preflight (D/V; T012a Behaviour).

This command performs structural migration/save, not a second semantic
validator: do not call `validate_files` to impose a new semantic acceptance
boundary. A structurally valid campaign with T011a findings can be migrated
and still reports those findings through `crpgc validate`. Pin this with the
broken fixture; migration cannot repair dangling references or change its
snapshot (D structural boundary; V Semantic validation).

### Rewrite policy (Stage-2 concretization of S §4.5 and S12)

The save serializes all collected documents through the data writer, including
locks, and writes only byte-different files at their existing logical paths.
Thus noncanonical whitespace/ULID spelling may normalize on explicit save even
when its schema was already current, exactly as D Canonical writer permits.
Canonical current files are not opened for writing. No file renames, deletions,
new documents, source assets, copied schemas, Lua, build output or replay
changes; ignored content remains byte-identical. The returned key set must
equal the collected set; a mismatch is an internal failure before writing.

Use `std` I/O only. For each differing file in lexical logical-path order,
recheck root/ancestor/target metadata without intentionally following symlinks,
then read the target and require its bytes to equal the collected original.
A changed/missing/nonregular target or observed symlink fails before that
file is opened for writing. Write via an existing-file handle with truncation
and `write_all`, then `sync_all`; do not use create-on-missing semantics.
Stop at the first failure. This bounded contract deliberately does **not**
promise atomic replacement, rollback, crash recovery or a whole-directory
transaction: an I/O failure can leave earlier files replaced and the failing
file partially written. Report that limitation in command rustdoc and the
architecture extension. Do not claim portable atomic replacement using
remove-then-rename, which can delete the source on failure. A future atomic
save design is separate scope, not implied by campaign format migration.

As in C Directory collection, std metadata/recheck is not handle-based
no-follow protection; concurrent changes after the check remain unspecified.
No locking or secure live-tree snapshot is introduced. The stable-input path
must work on native Windows and Linux. Test preflight no-write guarantees
separately from these explicitly limited write-phase guarantees.

### Output and errors (C Output contract, extended for an explicit save)

Success is silent: both streams empty, including a second no-op invocation.
Stdout is always empty. Domain/input failures print one data-owned
`Diagnostic::Display` line to stderr, or the CLI-owned I/O diagnostic below,
then exit 1. Usage prints one `crpgc: ...` line and exits 2, as T011b.

Reuse collection diagnostics verbatim. Rewrite failures use the existing
six-field Diagnostic with `Error`, `Io`, logical `file`, empty pointer, no
suggested fix, and exact message form:

```text
cannot <op> <logical>: <kind>
```

Rewrite operations are `check`, `open`, `write`, `sync`; kinds reuse T011b's
stable I/O mapping (`not_found`, `not_a_directory`, `permission_denied`,
`symlink_at_document_path`, `non_unicode_component`, `io_error`) and add
`source_changed` and `not_a_file` for the explicit prewrite checks. Ancestor
failure names the affected target logical path. No raw OS text, absolute paths,
native separators, debug values, progress counts or misleading rollback claim.
No new diagnostic enum variants: these are Io message details owned by CLI.

Compile-time version parse failure prints exactly
`crpgc migrate: internal engine version failure\n`; unexpected key-set mismatch
prints `crpgc migrate: internal document set failure\n`, both exit 1 and before
writes. Serialization `DataError` uses the normal data-error conversion.
Stream-write failures must exit 1 without panic; do not recursively try to
report an unwritable stderr. Existing commands retain their own output policy.

### Golden and gate boundaries (SF; E20; C Gate 8; T012a Behaviour)

The authoritative old campaign is
`crates/crpg-data/tests/fixtures/migration_v1/campaign`; its entire expected
canonical output is the sibling `expected.json` path-to-text map. CLI tests
copy source files to private temporary directories and invoke the shipped
binary, then compare the full resulting file-to-byte map with that checked-in
golden. Never migrate the checked-in source tree itself or generate expected
bytes from actual output in tests.

The no-bump-without-migration/fixture gate is T012a's ordinary
`migration_coverage` suite: it binds current generated/serialized tags,
registry edges and historical fixtures. T012b consumes it, adds no competing
registry/manifest and cannot relax it. Gate 7 schema drift, gate 8 generic
fixture validation, and gate 9 target replay remain live in workspace tests.
New migration black-box tests run there too, without CI workflow changes or
capability placeholders (SG/E20).

   payload, missing required file, layout/engine/index/lock/digest failures
   leave the entire copied source map unchanged during preflight. Include an
   early migratable file followed by a late failing file to prove no streaming
   writes. Assert data-owned diagnostic codes/positions rather than parsing
   serde prose or duplicating data semantics.

   validate snapshot retained. Migration does not acquire semantic validation

8. No permission/symlink test is runtime-skipped. Use private injected seams
