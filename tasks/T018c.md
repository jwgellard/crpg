# T018c — Conformance: malicious clients + filtered desync (`crpg-net`)

## Task

Prove T018a/b with net-local conformance: codec boundaries already pinned in
T018a, plus malicious-client rejection without mutation, filtered replica
convergence with negative controls, and the roadmap 5,000-tick loss/jitter
exercise. `crpg-net`-only single-crate task, ordered after T018a/b. This is
the T018 exit gate; it does not claim host, QUIC, movement, or reconnect
completion.

## Crate(s)

`crpg-net` (only).

## Purpose

Turn Appendix B policies into falsifiable suites: every rejection has a valid
positive control and a complete-state unchanged assertion; every delivered
replica matches its independently projected permitted view; intentional faults
still converge or fail loudly. A test double passing here is not host
integration passing — E012/E018/E022 still own the real host.

## Interface (no new wire; test vocabulary only)

```rust
// crates/crpg-net/tests/support/driver.rs (test-only, never shipped)
pub struct VisibilityTable; // supplied peer → entity → allowed fields
pub struct OwnershipTable;  // peer → controllable actors
pub struct NetDriver {
    pub fn new(world: crpg_sim::World, vis: VisibilityTable, own: OwnershipTable) -> Self;
    pub fn admit(&mut self, peer: PeerId, bytes: &[u8]) -> Vec<u8>; // decode→caps→epoch→seq→freshness→auth→legality→perform→project
    pub fn project(&self, peer: PeerId) -> ExpectedView; // independent permitted projection
    pub fn authoritative_hash(&self) -> [u8; 32]; // state_hash + queue bytes
}
// Driver sequences public sim calls only (start_encounter/perform_action,
// spawn/despawn reads). It observes a detached queue clone with a cursor for
// projection tests; it never drains the authoritative queue and never changes
// hash exclusions. Combat mutation stays crate-private in sim.
```

`ExpectedView` is presence + permitted `Health` + permitted `Turn` + ordered
filtered events with per-client `event_seq`, built independently from the
driver's projection path (separate code path, not a copy). Filtered replica
equality is against this view, never against full World hash.

## Behaviour / suites (`crates/crpg-net/tests/conformance.rs` + support)

1. **Malicious-client matrix** (each with positive control + unchanged
   complete World/RNG/event assertion on rejection):
   forged actor/target ids, cross-client bindings, revoked-visibility ids,
   wrong epoch, replayed seq (same/different bytes), gap, exhausted seq,
   stale/future observed tick, unknown ability, out-of-turn actor, dead
   actor/target, insufficient pool, malformed/oversized lengths, over-rate
   bursts. Rejection codes exactly per T018a/b; terminal rejections consume
   seq but mutate nothing; early frame/rate/queue failures do not consume seq.
2. **Filtered desync oracle**: drive accepted ability + EndTurn schedule from
   two peers with different visibility; deliver through loss/dup/reorder;
   assert each reconstructed replica equals its independent expected view
   after convergence. Negative controls: corrupt or drop a required update and
   prove the oracle fails. Hidden spawn/despawn/death never leaks through
   counts, gaps, or cached receipts. Died never implies despawn.
3. **5,000-tick loss/jitter exercise**: fixed seed campaign encounter,
   scripted valid + rejected inputs, injected loss/jitter per `FaultSchedule`,
   5,000 ticks with per-N hash recording; assert convergence of permitted
   views and authoritative hash equality for identical admitted schedules
   across runs on the same build. This is the roadmap exercise at combat
   scope, not full Phase 4 movement/reconnect acceptance.
4. **Receipt/sequence liveness**: lost receipt retried → cached terminal
   receipt; no second execution; no deadlock on single loss; slow-peer
   termination is `QueueFull`, never silent loss.

All suites deterministic on the same build; no wall clock, no sleep, no
cross-target hash equality. Windows and Linux compare only their own
independently generated baselines where baselines exist; no new goldens are
blessed here and existing goldens stay untouched.

Command that must pass: `cargo test -p crpg-net --test conformance --locked`
