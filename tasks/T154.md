## Task

Give `crpg-server` the loop that runs the world. Today nothing does, in
either hosting: `crates/crpg-server/src/main.rs:9–12` prints and exits 1,
`Host::advance` (`crates/crpg-server/src/host.rs:3739–3760`) is called only
by tests (`:5651`, `crates/crpg-server/tests/host_pause.rs:344`), and the
Godot bridge pumps from its frame poll and never ticks
(`crates/crpg-godot/src/core/authority.rs:508–616`, `docs/adr/0033-godot-bridge.md:124`).
D65a: "Single player should be exactly the same as multiplayer, just the
server is running in the background" — so one loop owns the 20 Hz clock
(`docs/CRPG_ENGINE_SPEC.md:318`) and the per-cycle order (intake, AI,
advance, deliver), and the embedded single-player host and the dedicated
server both run it, on the same background runner. D65b: one `Host` must be
able to serve an in-memory local player and QUIC players at once; the
switch that opens a running campaign to others is built later.

## Readings
Design decisions this contract makes. Each needs approval with the contract.

1. **One loop, two hostings, one runner.** `HostLoop` is generic over a
   `Hosting`: `LocalHost` (a `Host` plus local links) for single player,
   `QuicHosting` (a `QuicHost`) for the dedicated server; both run on the
   same `runner::spawn` thread. D65a; "There is no single-player code path"
   (`docs/CRPG_ENGINE_SPEC.md:175`); "Embedded hosting is not a separate
   single-player simulation" (`docs/adr/0012-windows-primary-platform.md:32`).
   *Rejected:* the bridge owning the thread (T151 Reading 7, withdrawn by
   D65a; the dedicated server would need a second runner); one loop per
   transport.
2. **The cycle order is one function, and it is S-set.** `run_cycle` calls,
   once each: `intake` (every waiting frame, then one `pump`), `drive_ai`,
   `advance`, `deliver`, `retire_captures`. D65a lists "ingest, AI driver,
   advance, deliver" (`DECISIONS-D65.md:9`); T153 puts the driver after
   `pump` and before `advance` (`task/T153-c1:tasks/T153.md:102–110`);
   delivering after `advance` sends a cycle's tick output in that cycle, as
   spec stage 8 follows the simulation stages (`docs/CRPG_ENGINE_SPEC.md:944–956`).
   The spec calls tick order "a rules-visible decision" written "in one
   function" (`:944`); this order decides what the AI sees and when output
   leaves, so T154a is serialized like "tick order in `crpg-sim`"
   (`docs/IMPLEMENTATION_PLAN.md:92–98`; manager edit). *Rejected:* deliver
   before `advance` (T037's samples a cycle late); the AI inside `advance`
   or `pump` (T153 Reading 1).
3. **The cadence is a grid; a late step runs one cycle and skips the rest.**
   Slots are `start_ms + k × period`; game time slows under overload and
   never bursts (the first T151 draft already rejected bursts,
   `28c0550:tasks/T151.md:165–171`). Ticks are journaled, so replay
   does not depend on skipped slots (`docs/adr/0029-kernel-range-and-time-model.md:273–276`).
   Question 1. *Rejected:* running every missed slot; a cycle per call.
4. **Pause stops the tick, never the loop.** Nothing in the loop reads
   `paused()`: a paused host still takes commands, runs the AI stage and
   delivers; only `Host::advance` declines to tick
   (`crates/crpg-server/src/host.rs:3745–3756`; ADR-0029 P1–P2,
   `docs/adr/0029-kernel-range-and-time-model.md:281–286`). D65g: the AI
   decides and queues like a human under pause, with no rule of its own
   (`DECISIONS-D65.md:23`); T153's driver does not read pause
   (`task/T153-c1:tasks/T153.md:399`). *Rejected:* skipping stages while
   paused (a `Restore`-paused load could never deliver or take its unpause).
5. **The AI stage is a hook the embedding supplies.** Sides and the
   controlled set are the caller's facts (`task/T153-c1:tasks/T153.md:123–135`),
   and `crpg-server` has no `crpg-data` edge to build them
   (`crates/crpg-server/AGENTS.md:103`). `LocalHost::set_ai` takes an
   `FnMut(&mut Host, u64)` the embedding builds around T153's
   `Host::drive_ai`; it gets `now_ms`, so the embedding may keep today's
   600 ms NPC pace (`crates/crpg-godot/src/core/authority.rs:29–30`). `run.rs`
   names no `crpg_ai` type, so T154a–c wait for neither T056 nor T153.
   *Rejected:* AI inputs stored in the loop (crpg-ai types in the S-set file).
6. **The local link mirrors a QUIC connection.** Two bounded
   `std::sync::mpsc::sync_channel` FIFOs of whole frames, so the client can
   live on another thread. Up frames are routed by first byte as T151
   Reading 6 does (`task/T151-c1:tasks/T151.md:176–187`). Dispositions are
   `QuicHost`'s: `QueueFull` holds the frame and stops that peer's drain,
   `Unauthenticated`/`Unbound` retires the link, other refusals are counted
   and dropped (`crates/crpg-server/src/quic.rs:870–886`, `:909–921`); at
   most `MAX_DRAIN_PER_CONNECTION` frames per peer per cycle (`:58`);
   delivery is acknowledged through the last accepted entry (`:990–1039`);
   a departed client is unbound (`:566–583`). `LocalClient` implements
   `crpg_net::transport::Transport` (`crates/crpg-net/src/transport.rs:14–23`),
   which the bridge's client half already takes
   (`crates/crpg-godot/src/core/client.rs:315`, `:495`). *Rejected:*
   `crpg_net::sim::InMemoryTransport` (a test fabric with its own clock,
   `docs/adr/0033-godot-bridge.md:481–482`).
7. **Captures are retired every cycle.** No capture consumer runs in either
   hosting, and a full journal stops host operations
   (`crates/crpg-server/src/host.rs:528–531`); the bridge already
   acknowledges every poll (`crates/crpg-godot/src/core/authority.rs:594–598`).
   A recorder attaches before this stage, later.
8. **Operator calls run on the loop thread, between cycles.**
   `RunnerHandle::submit` sends a closure over `&mut HostLoop` that runs
   right after a step; `call` waits for it. Pause, unpause, saving, the AI
   hook and the bridge's legal-options read go this way, so the host keeps
   one serial owner (`docs/adr/0033-godot-bridge.md:17–20`). A closure
   submitted after the injected clock reads `t` runs after a step at
   `now ≥ t`, so tests step the thread with no wall-clock margin.
   *Rejected:* a `Mutex<Host>` (a second owner; lock waits in the frame loop).
9. **Only `runner.rs` reads a clock or owns a thread.** `run.rs` never
   blocks (`try_send`/`try_recv`); `runner.rs` alone reads `Instant`, spawns
   the loop thread and waits on its control channel. Invariant 7
   (`crates/crpg-server/AGENTS.md:87–93`) gains that one fenced exception, as
   it fences file I/O to `save.rs` and network I/O to `quic.rs`; ADR-0029 P8
   keeps wall-clock reads in `crpg-server`
   (`docs/adr/0029-kernel-range-and-time-model.md:314–316`). The determinism
   lint does not scan `crpg-server` (`tools/lint/determinism.py:66`), so a
   source-rule test guards it. D65a supersedes ADR-0033's rejection of "a
   worker thread owning the host" and "a fixed 20 Hz authority tick"
   (`docs/adr/0033-godot-bridge.md:483–486`; manager edit).
10. **One `Host` for local and QUIC players: reachable with this
    Interface by stop and respawn; the combined hosting is built later.**
    A `Hosting` is fixed at `spawn`: `submit`'s closure gets
    `&mut HostLoop<H>` with the same `H`, so no closure can swap in another
    hosting type. The later switch therefore stops the runner at a cycle
    boundary and starts a new one: `RunnerHandle::join` returns the loop;
    `last_ms()` is read and `into_hosting()` returns the `LocalHost` with its
    `Host` and its links, so the local player's `LocalClient` keeps its
    channels (no save, no reload, no new incarnation); the later task builds
    its combined hosting from that `LocalHost` and a QUIC endpoint and
    `spawn`s it with `HostLoop::new(combined, last)` and
    `SystemClock::starting_at(last)`. The gap is one runner restart, during
    which no cycle runs. U10 proves the stop-and-respawn half on a
    `LocalHost`. The "open my campaign to others" task (D65b, after the demo,
    not yet filed) owns the rest: the combined `Hosting` (one `Host`; the
    local links' intake and deliver beside QUIC's phases), `QuicHost::start`
    accepting a host whose only bindings are local (any binding is
    `HostInUse` today, `crates/crpg-server/src/quic.rs:457–475`), and the
    embedding's switch. *Rejected:* a hosting swapped by `submit` (needs a
    boxed `dyn Hosting` in the S-set file for a feature not built yet); a
    fake QUIC connection for the local player.
11. **A single-player save loads into a dedicated server, unchanged.** A
    save is a header (version, campaign id and version, engine version) and
    the checkpoint verbatim (`crates/crpg-server/src/save.rs:163–192`); the
    checkpoint holds no bindings, credentials, grants or delivery state
    (`crates/crpg-server/src/checkpoint.rs:3–10`); `load_host_file`
    (`crates/crpg-server/src/save.rs:287–301`) returns an unbound,
    `Restore`-paused host under a greater incarnation
    (`crates/crpg-server/src/checkpoint.rs:212–224`,
    `crates/crpg-server/src/host.rs:892–901`); `QuicHost::start` refuses only
    a closed host, bindings or staged ingress, or a time regression
    (`crates/crpg-server/src/quic.rs:457–481`). Nothing in a save names its
    hosting. A loaded dedicated host must, as any restore must, be unpaused
    (P7), have its navigation mesh bound again
    (`task/T037b-i1:tasks/T037.md:145–152`) and get its AI hook. Hellos must
    match the saved protocol (`crates/crpg-server/src/quic.rs:618–620`); the
    bridge saves V2 hosts (`crates/crpg-godot/src/core/mod.rs:299`), so `/2`
    clients join. Q3 and Q4 prove it.
12. **The dedicated hosting needs four small `QuicHost` additions.**
    `QuicHost::pump` delivers inside its own phases
    (`crates/crpg-server/src/quic.rs:553–592`), before any `advance`; `flush`
    runs phases 4–7 alone and `pump` runs 1–3 then the same body. `drive_ai`,
    `pause` and `unpause` are pass-throughs like `tick` (`:1335–1340`); a
    loaded host is `Restore`-paused and `QuicHost` cannot unpause it today.
    `QuicHost::advance` is T150c's (`task/T150-c1:tasks/T150.md:311–313`).
    *Rejected:* a second `pump` as the deliver stage (it admits after the tick).
13. **`main.rs` stays T040's** (`docs/IMPLEMENTATION_PLAN.md:240`;
    `docs/architecture/crpg-server.md:26–33`): certificate, invitations,
    save identity and incarnation are its. T154 hands it
    `runner::spawn(HostLoop::new(QuicHosting::new(quic), now), SystemClock::starting_at(now))`,
    where `now` is the time the host was loaded or started at: the clock's
    origin must equal the loop's start, or the first step is a
    `TimeRegression` (B-2) and the runner ends (R-2 (a)); U9 and Q4 prove
    it. Question 2.
14. **Loop state is never saved.** The schedule, links and hook are hosting
    state, like pause (P1); `save_checkpoint` reads only the host.

## Interface
Additions only. Every public item and field has a doc comment
(`crates/crpg-server/src/lib.rs:2`); the comments below are their meaning.
`HostError`, `QuicHostError`, `AdvanceReport` and every existing public item
keep their shape. No `HashMap`/`HashSet`; the link table is a `BTreeMap`
keyed by `PeerHandle` (which is `Ord`, `crates/crpg-server/src/host.rs:152–153`).

### T154a — `crates/crpg-server/src/run.rs`
```rust
//! The run loop (T154): one cycle order, two hostings. No clock, no thread,
//! never blocks.
pub const TICK_PERIOD_MS: u64 = 50;                 // 20 Hz, spec :318
/// The most retirement records a `LocalHost` keeps; the oldest is dropped
/// first (B-9; crate invariant 6, every ledger bounded).
pub const MAX_RETIRED_RECORDS: usize = 64;

/// One hosting of the one `Host`: the five stages of a cycle (Reading 2).
pub trait Hosting {
    type Error: std::error::Error + Send + 'static;
    fn intake(&mut self, now_ms: u64) -> Result<(), Self::Error>;      // frames in, one pump
    fn drive_ai(&mut self, now_ms: u64) -> Result<(), Self::Error>;    // the AI hook, if any
    fn advance(&mut self, now_ms: u64) -> Result<AdvanceReport, Self::Error>;
    fn deliver(&mut self, now_ms: u64) -> Result<(), Self::Error>;     // delivery out
    fn retire_captures(&mut self) -> Result<(), Self::Error>;
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct CycleReport { pub now_ms: u64, pub advance: AdvanceReport }
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct StepReport {
    pub cycle: Option<CycleReport>,   // None: no slot was due
    pub missed: u64,                  // due slots this step skipped (Reading 3)
}
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum LoopError<E> {
    TimeRegression { last_ms: u64, now_ms: u64 },  // nothing changed
    Hosting(E),                                    // later stages did not run
}

pub struct HostLoop<H: Hosting> { /* hosting, period_ms, next_due_ms, last_ms, cycles, missed */ }
impl<H: Hosting> HostLoop<H> {
    pub fn new(hosting: H, start_ms: u64) -> Self;   // period 50, first slot start_ms
    pub fn with_period(hosting: H, start_ms: u64, period_ms: NonZeroU64) -> Self;
    pub fn step(&mut self, now_ms: u64) -> Result<StepReport, LoopError<H::Error>>;  // B-1, B-2
    pub fn period_ms(&self) -> u64;
    pub fn next_due_ms(&self) -> u64;
    pub fn cycles(&self) -> u64;      // cycles run, failed ones included
    pub fn missed(&self) -> u64;      // slots skipped in total
    pub fn last_ms(&self) -> u64;     // the last accepted `now_ms`; `start_ms` before any step
    pub fn hosting(&self) -> &H;
    pub fn hosting_mut(&mut self) -> &mut H;
    pub fn into_hosting(self) -> H;
    // private: fn run_cycle(&mut self, now_ms: u64) -> Result<CycleReport, H::Error> (B-3)
}

/// The AI stage of a `LocalHost` (Reading 5).
pub type AiHook = Box<dyn FnMut(&mut Host, u64) -> Result<(), HostError> + Send>;

/// `#[non_exhaustive]`: T154c adds a field, so code outside `crpg-server`
/// (every integration suite included) reads fields and compares with
/// `LinkStats::default()`, and cannot build one by a struct literal.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
#[non_exhaustive]
pub struct LinkStats {
    pub received: u64,   // frames taken from the up queue (a held frame once)
    pub refused: u64,    // frames refused and dropped
    pub held: bool,      // a lane-0 frame waits for retry (QueueFull)
    pub sent: u64,       // frames the down queue accepted
}
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum LocalError { UnknownPeer, AlreadyAttached }
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum LinkError { Full, Closed }   // Full: nothing queued; Closed: server end gone

/// The in-memory hosting: one `Host`, its local links, its AI hook.
pub struct LocalHost { /* host, links: BTreeMap<PeerHandle, Link>, retired: VecDeque<(PeerHandle, LinkStats)> (≤ MAX_RETIRED_RECORDS), retired_dropped: u64, ai: Option<AiHook> */ }
impl LocalHost {
    pub fn new(host: Host) -> Self;
    pub fn attach(&mut self, peer: PeerHandle, capacity: NonZeroUsize)
        -> Result<LocalClient, LocalError>;                              // B-5
    pub fn set_ai(&mut self, hook: Option<AiHook>);
    pub fn link_stats(&self, peer: PeerHandle) -> Option<LinkStats>;   // None: no link
    /// The links retired since the last call, each with its final stats, in
    /// retirement order, at most `MAX_RETIRED_RECORDS` (the newest); the list
    /// is then empty (B-9).
    pub fn take_retired(&mut self) -> Vec<(PeerHandle, LinkStats)>;
    /// Records dropped because the list was full, in total; never reset.
    pub fn retired_dropped(&self) -> u64;
    pub fn host(&self) -> &Host;
    pub fn host_mut(&mut self) -> &mut Host;   // trusted operator calls between cycles
    pub fn into_host(self) -> Host;
}
impl Hosting for LocalHost { type Error = HostError; /* B-6..B-9 */ }

/// The client end of a link: `Send`, not `Clone`, not `Sync`.
pub struct LocalClient { /* up: SyncSender<Vec<u8>>, down: Receiver<Vec<u8>>, closed: bool */ }
impl crpg_net::transport::Transport for LocalClient { type Error = LinkError; /* B-10 */ }
impl LocalClient { pub fn is_closed(&self) -> bool; }
```

### T154b — `crates/crpg-server/src/runner.rs`
```rust
//! The background runner: the only module that reads a clock, owns a thread
//! or blocks (Reading 9).
pub trait Clock: Send + 'static { fn now_ms(&self) -> u64; }   // never decreases
#[derive(Debug, Clone, Copy)]
pub struct SystemClock { /* start: Instant, origin_ms: u64 */ } // origin + ms since construction
impl SystemClock {
    pub fn new() -> Self;                          // `starting_at(0)`
    /// Reads `origin_ms` at construction: pass the `start_ms` of the loop it
    /// will drive (Reading 13).
    pub fn starting_at(origin_ms: u64) -> Self;
}
impl Default for SystemClock { fn default() -> Self; }   // `new()`
impl Clock for SystemClock { fn now_ms(&self) -> u64; }

pub fn spawn<H, C>(host_loop: HostLoop<H>, clock: C) -> std::io::Result<RunnerHandle<H>>
where H: Hosting + Send + 'static, C: Clock;                   // R-2

/// `Send`; dropping it stops and joins (R-4).
pub struct RunnerHandle<H: Hosting> { /* control: Sender<Msg<H>>, thread: Option<JoinHandle<RunnerExit<H>>> */ }
impl<H: Hosting + Send + 'static> RunnerHandle<H> {
    pub fn submit<R, F>(&self, f: F) -> std::sync::mpsc::Receiver<R>     // R-3
    where R: Send + 'static, F: FnOnce(&mut HostLoop<H>) -> R + Send + 'static;
    pub fn call<R, F>(&self, f: F) -> Result<R, RunnerGone>
    where R: Send + 'static, F: FnOnce(&mut HostLoop<H>) -> R + Send + 'static;
    pub fn stop(&self);
    pub fn is_finished(&self) -> bool;
    pub fn join(self) -> Result<RunnerExit<H>, RunnerPanicked>;
}
pub struct RunnerExit<H: Hosting> {
    pub host_loop: HostLoop<H>,
    pub error: Option<LoopError<H::Error>>,   // the step error that ended it
}
#[derive(Debug, Clone, Copy, PartialEq, Eq)] pub struct RunnerGone;
#[derive(Debug, Clone, Copy, PartialEq, Eq)] pub struct RunnerPanicked;
```

## Behaviour
Normative. Each item names the tests that prove it. **First failure wins**
in every ordered list. "Retire the link" means: `host.unbind_peer(peer)`
(a no-op when already unbound, `crates/crpg-server/src/host.rs:1286–1292`),
drop the link's server ends, remove it (`link_stats` is then `None`), and
push `(peer, its LinkStats at that moment)` onto the back of the retired
list that `take_retired` drains; when the list already holds
`MAX_RETIRED_RECORDS`, its front record is dropped first and
`retired_dropped += 1`. Counters a step changes before it retires a link
(B-6's `refused += 1`) are in that record.

### T154a — the loop
B-1. **Cadence.** `new(h, s)`: period 50, `next_due_ms = s`, last time `s`
(`last_ms()` reads it), `cycles = missed = 0`; `with_period` the same with
its period. `step(now)`:
(1) `now < last` → B-2. (2) last = `now`. (3) `now < next_due_ms` →
`Ok(StepReport { cycle: None, missed: 0 })`. (4) Otherwise `k = (now −
next_due_ms) / period`; `next_due_ms += (k + 1) × period` (saturating);
`missed += k`; `cycles += 1`; then `run_cycle(now)`: `Ok(r)` →
`Ok(StepReport { cycle: Some(r), missed: k })`; `Err(e)` →
`Err(LoopError::Hosting(e))`, with the schedule and counters already moved.
At most one cycle per step. *Tests:* K1, K2.

B-2. **Time.** The loop reads no clock. `now < last` →
`Err(TimeRegression { last_ms: last, now_ms: now })` and nothing changes (no
stage runs, schedule and counters unchanged); `now == last` is accepted.
*Tests:* K3.

B-3. **Cycle order** (`run_cycle`, the only caller of the five stages):
`intake(now)`, `drive_ai(now)`, `advance(now)`, `deliver(now)`,
`retire_captures()`, each exactly once; the first `Err` returns at once and
no later stage runs. `CycleReport { now_ms: now, advance }` holds
`advance`'s report. *Tests:* K4, K5.

B-4. **Pause.** Neither `HostLoop` nor `LocalHost` reads `paused()`. On a
paused host every stage runs; `Host::advance` returns `ticked: false` and
`server_tick` does not move; the AI hook runs and what it does through host
operations is applied (P2, D65g). *Tests:* K6.

### T154a — `LocalHost`
B-5. **`new(host)`** has no links, an empty retired list, `retired_dropped`
0 and no hook.
**`attach(peer, capacity)`**: `host.epoch(peer)` is `Err` →
`UnknownPeer`; a link exists → `AlreadyAttached`; else two
`sync_channel(capacity)` queues (up, down), `LinkStats::default()`, and the
client end. *Tests:* K7.

B-6. **Intake.** For each link in ascending `PeerHandle` order:
(1) if a frame is held, route it (below): `Hold` → it stays held, next peer;
`Retire` → retire the link, next peer; else it is no longer held.
(2) Then at most `MAX_DRAIN_PER_CONNECTION` (`crates/crpg-server/src/quic.rs:58`,
128) times: `up.try_recv()`; empty → stop; disconnected → mark the link
departed, stop; a frame → `received += 1`, route it: `Continue` → go on;
`Hold` → hold it, stop; `Retire` → retire the link, stop.
**Route** by the frame's first byte: `0x81` or `0x82`
(`crpg_net::protocol_transfer::TRANSFER_VERSION`,
`crpg_net::transfer_v3::TRANSFER_VERSION_V3`) → `host.ingest_transfer(peer,
frame, now)?`: `Published`, `Resynced`, `Stale` → `Continue`;
`Refused(Unbound)` → `refused += 1`, `Retire`; any other `Refused` →
`refused += 1`, `Continue`. Anything else, an empty frame included →
`host.ingest(peer, frame, now)?`: `Staged` → `Continue`;
`Refused { Rejected(QueueFull) }` → `Hold`;
`Refused { Rejected(Unauthenticated) }` → `refused += 1`, `Retire`; any other
`Refused` → `refused += 1`, `Continue`.
(3) After every link, exactly one `host.pump(now)?`, links or none.
*Tests:* K8, K9, K10, K11, K12.

B-7. **Deliver.** For each link in ascending order: (1) departed → retire,
next. (2) `host.take_delivery_entries(peer)`: `Err(UnknownPeer)` → retire,
next; other `Err` → return it. (3) In order, `down.try_send(bytes)`: `Ok` →
`sent += 1`, remember the ordinal; full → stop; disconnected → mark
departed, stop. (4) If any entry was accepted,
`host.acknowledge_delivery(peer, last accepted ordinal)?`. (5) Departed now
→ retire. Unaccepted entries stay in the host's log and are offered first
next cycle. *Tests:* K8, K12, K13.

B-8. **The other stages.** `drive_ai(now)`: the hook, if set, is called once
as `hook(&mut host, now)` and its `Err` is returned; no hook → `Ok(())`.
`advance(now)` = `host.advance(now)`. `retire_captures()` =
`host.acknowledge_captures(host.last_capture())`. *Tests:* K6, K8.

B-9. **Links end only by retirement:** a departed client (its `LocalClient`
dropped, seen at intake or deliver), an unbound peer (`Unauthenticated`,
`Unbound`, or `UnknownPeer` at deliver), never otherwise. Every retirement
adds exactly one record; the list never exceeds `MAX_RETIRED_RECORDS`
(64): a record pushed onto a full list drops the oldest and counts it in
`retired_dropped`, so a host that never calls `take_retired` holds at most 64
records (crate invariant 6, `crates/crpg-server/AGENTS.md`). `take_retired`
returns the held records in retirement order and leaves the list empty;
`retired_dropped` is unchanged by it. A retired peer's
staged commands are refused `SessionExpired` by the next pump
(`crates/crpg-server/src/host.rs:1286–1289`). *Tests:* K12, K17.

B-10. **`LocalClient`.** `send(bytes)`: closed flag set → `Err(Closed)`;
`up.try_send(bytes.to_vec())`: `Ok`; full → `Err(Full)`, nothing queued;
disconnected → set the flag, `Err(Closed)`. `recv()`: `down.try_recv()`: a
frame → `Some`; empty → `None`; disconnected → set the flag, `None`.
`is_closed()` reads the flag. Frames sent before the server end went away
are still received, in order. *Tests:* K14.

### T154b — the runner
R-1. **`SystemClock`**: `starting_at(o)` records `o` and `Instant::now()`;
`now_ms` = `o.saturating_add(whole milliseconds since construction)`, the
milliseconds via `Instant::elapsed` and `u64::try_from` saturating to
`u64::MAX`; never decreases. `new()` and `default()` are `starting_at(0)`.
A runner whose clock's first read is below its loop's `last_ms()` ends at
its first step with `TimeRegression` (B-2, R-2 (a)); this is the caller's
error, not the runner's: the runner does not adjust the clock.
*Tests:* U1, U9.

R-2. **The thread.** `spawn` starts a thread named `crpg-server-loop`
(`std::thread::Builder`; its `io::Error` is returned) that repeats:
(a) `now = clock.now_ms()`; `host_loop.step(now)`; `Err(e)` → end with
`error: Some(e)`. (b) If a closure is pending, run it on `&mut host_loop`
and send its result (a dropped receiver is ignored). (c) `wait =
min(next_due_ms − clock.now_ms() (saturating), period_ms)`;
`control.recv_timeout(wait ms)`: a closure → pending (it runs at (b) of the
next pass, after a step); `Stop` → end with `error: None`, no further step;
timeout → next pass; disconnected → end with `error: None`. It ends by
returning `RunnerExit { host_loop, error }`. *Tests:* U2, U5, U7.

R-3. **Rendezvous.** `submit(f)` sends `f` and returns its receiver; `call`
waits on it and maps a disconnect to `RunnerGone`. Because a closure is
received before the clock is read for the step that precedes it, a closure
submitted after the injected clock reads `t` runs after a step at
`now ≥ t`. *Tests:* U2, U3.

R-4. **Stopping.** `stop` sends `Stop` and ignores a send error; `join`
sends `Stop`, joins and returns the exit, or `RunnerPanicked`; dropping an
unjoined handle sends `Stop` and joins, discarding the result.
`is_finished` is the join handle's. The returned `host_loop` is the loop
as the last step left it (hosting, links and schedule), so it can be
taken apart and respawned (Reading 10). *Tests:* U4, U10.

R-5. **Failures.** A step error ends the runner (R-2 (a)); a closure pending
then is dropped, so its `call` returns `RunnerGone`, as does every later
`call`. A panic on the thread makes `join` return `RunnerPanicked`.
*Tests:* U5, U6.

R-6. **Fences.** With `//` comments stripped, the tokens `Instant`,
`SystemTime`, `thread::`, `sleep`, `recv_timeout`, `UdpSocket` and
`TcpListener` appear in `crates/crpg-server/src/*.rs` only in `runner.rs`;
`run.rs` also contains no `.recv()` and no `.send(`. Invariant 7 reads:
"`now_ms` only; no clock, thread, sleep or socket in `crpg-server` source,
except `runner.rs`, which alone reads `Instant` (through `SystemClock`),
spawns the one loop thread and waits on its control channel", the rest of
the invariant unchanged. *Tests:* K16 (`run.rs`), U8.

## Questions for the user
1. **When the server falls behind, should the game slow down or catch
   up?** The server runs the world 20 times a second. If one step takes
   longer than 50 ms (a big fight, a slow disk), it is late for the next.
   (a) **Slow down:** run one step, skip the steps it missed, and carry on
   from now; the game runs a little slower for a moment and never stutters
   forward. (b) **Catch up:** run every missed step back to back; game time
   stays in line with real time, but a stall is followed by a burst of
   movement, which can itself stall. *Recommend (a);* T151 already rejected
   bursts, and nothing in the game depends on matching real time.
2. **Should T154 also make the `crpg-server` program runnable, or leave that
   to T040?** T154 builds everything a dedicated server needs to run the
   loop and proves a single-player save runs on it. A usable program also
   needs a certificate, an invitation file for players, a save to load and
   settings, all already planned as T040. (a) **Leave the program to T040**,
   which then only wires these pieces together. (b) **A bare-bones program
   now** (load a save, listen on a port, test certificate), which T040 later
   replaces. *Recommend (a):* (b) is throw-away work and needs choices (file
   formats, command-line flags) that T040 is meant to make.
