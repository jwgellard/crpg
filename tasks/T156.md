## Task

The user wants a basic combat demo in the Godot client before the editor
(brief, 2026-11-22): (1) the enemy takes its turns through the same
server-side AI the dedicated server uses, in the embedded host; (2) the player
clicks an enemy in the 3D scene to attack it; (3) health bars, floating damage
numbers and a hit flash.

What exists, found in code (two of these correct the brief and the fact sheet):

1. **The enemy already takes its turns in `Main.tscn`, but not by the server's
   AI.** `Main.gd` opens a **v2** session (`session.open(..)`,
   `apps/client/scripts/Main.gd:19`). A v2 session's bridge authority drives
   the non-player side as a peer: every poll it reads the NPC peer's
   `legal_intents`, waits 600 ms (`NPC_ACTION_DELAY_MS`,
   `crates/crpg-godot/src/core/authority.rs:30`, `NpcPacer` `:112–132`) and
   submits "the first attack on a different side, else the first option"
   (`choose_npc`, `:34–52`, used at `:522–564`). Every v4 open does the same
   through `NpcHook` as the run loop's AI hook
   (`crates/crpg-godot/src/core/authority/v4.rs:53–116`, installed at
   `crates/crpg-godot/src/core/mod.rs:596`). The MVP AI (`crpg_ai::decide`,
   `crates/crpg-ai/src/mvp.rs:40`) reaches a host only through
   `Host::drive_ai` (`crates/crpg-server/src/host/ai.rs:84–173`), which only the
   dedicated binary calls (`crates/crpg-server/src/main.rs:778–784`).
2. **`drive_ai` cannot serve a v2 session.** It applies decisions with
   `host_action` (`crates/crpg-server/src/host/ai.rs:262–284`), which sends
   "no frame for a v1/v2 session" (`crates/crpg-server/src/host.rs:4470–4473`),
   so a v2 player would never see the enemy act. The AI session must be v4.
3. **`open_v4`'s NPC driver cannot be swapped in place.** Existing tests pin
   the peer driver: B7 (the NPC acts one cycle after v2) and B8 (it drains the
   NPC delivery), fa_2 (the NPC frame's `observed_tick`), fa_3 (`choose_npc`'s
   sides) and B12 (`open_v4` plays exactly like v2)
   (`crates/crpg-godot/src/core/authority/v4/tests.rs:674–776`, `:1072–1170`,
   `:935–995`). Changing `open_v4` would break them, which AGENTS.md forbids.
4. **Nothing picks a proxy, and nothing draws feedback.** Proxies have no
   collision shape (`apps/client/scripts/SceneSync.gd:80–97`); health is text
   in the HUD only (`apps/client/scripts/CombatHud.gd:111–128`); events reach
   only the log (`:140–149`, `:170–188`). Everything the feedback and the
   click need is already on the view: `option_targets()`
   (`crates/crpg-godot/src/shell.rs:262`), `health()`, `max_health()`,
   `health_known()`, `dead()` (`:214–232`) and `events()` with
   `action_resolved {actor, target, outcome, damage}`
   (`crates/crpg-godot/src/core/client.rs:209–222`).

## Readings
Design decisions this contract makes. Each needs approval with the contract.

1. **The AI session is a new turn-based v4 open, `open_v4_ai`.** Facts 2 and 3
   leave no other place: v2 cannot show host operations, and `open_v4` is
   pinned by its tests. `open`, `open_v4` and `open_v4_rt` keep the peer NPC.
   A private `NpcDriver { Peer, ServerAi }` beside `EncounterMode` selects the
   hook, so a later real-time AI open (T157) is one more wrapper.
2. **The hook is `ServerAiHook`: the dedicated server's call, paced and gated
   as today's NPC.** Each AI stage it (1) answers `Closed` on a shut-down host,
   (2) drains the NPC peer's delivery unread, as `NpcHook` does (`v4.rs:80–83`;
   the NPC peer stays bound because `presentation_tables` needs its replica
   ids, `crates/crpg-godot/src/core/authority.rs:702–742`), (3) reads "is it
   the enemy's turn" as "the NPC peer has legal options" (`Host` has no public
   active-head read; `legal_intents` is empty unless the active head is one of
   the peer's actors, `crates/crpg-server/src/host.rs:1102–1117`), and (4)
   when the pacer fires calls `host.drive_ai(&sides, &actors, MVP_AI_BUDGET)`
   and discards the report, exactly as `main.rs:779–783` does. `drive_ai`
   makes one decision per call (`host/ai.rs:176–224`), so the enemy plays one
   step per `AI_STEP_DELAY_MS`: attack, then end turn, as today's NPC paces it
   (D78b). Pause does not matter: the bridge host keeps multiplayer settings
   with no auto-pause (T050 Reading 8), and `drive_ai` runs while paused
   anyway (T153 Reading 13).
3. **Who the AI controls: every combatant not on the player's side**, the
   NPC peer's existing grant (`prefix.npc_actors`,
   `crates/crpg-godot/src/core/mod.rs:732–740`). Not a user question: it is
   what the enemy is today.
4. **Sides come from the same strings the view shows.** `Presentation::combatant`
   gives each bound combatant its side (faction text, else creature name,
   `crates/crpg-godot/src/core/authority.rs:432–450`). `ai_sides` numbers the
   distinct strings in ascending order from `SideId(0)` and builds
   `crpg_ai::Sides`, so "hostile" means "a different side string", which is
   `choose_npc`'s rule.
5. **The authority is observable: a host operation moves no `executions()`.**
   `host_action` is "never a peer command: no sequence, no receipt, no
   `executions` move" (`crates/crpg-server/src/host.rs:4470–4473`), while the
   peer NPC's intents are counted (`:1076–1079`). The tests use this to prove
   the AI, not the peer, acted.
6. **The crate edge `crpg-godot → crpg-ai` (D78a).** `ServerAiHook` holds a
   `crpg_ai::Sides`, and `crpg-server` does not re-export it. `deps.py` already
   allows the edge (`"crpg-godot": (None, set())`, `tools/lint/deps.py:71`);
   it adds no third-party code (`crpg-ai`'s dependencies are already in the
   build through `crpg-server`).
7. **The default scene evolves (D78d).** `Main.tscn` is the combat demo the
   client opens and the scene CI's `smoke.gd` plays
   (`.github/workflows/ci.yml:313–320`). Switching `Main.gd` to `open_v4_ai`
   keeps every existing client test valid unchanged: a v4 turn-based view
   equals v2's (B12), the AI picks the same Strike-then-End-turn as the peer
   NPC on `combat_basic` (A2 pins it), and the source scans of `Main.gd`
   still find `submit_option`, `poll`, `ClassDB`, `OS`, `_process`, `session`
   and `.revision(` (`apps/client/tests/hud_cases.gd:566–568`,
   `apps/client/tests/scene_sync_cases.gd:585–590`).
8. **Picking is geometry, not physics.** Proxies have no collision body, and
   adding one to `SceneSync.gd`'s proxies would change what its S-cases pin.
   `Pick.gd` casts the camera ray through the click (as `Walk.gd:116–126`
   does) and takes the proxy whose centre (`global_position + (0, 0.6, 0)`)
   lies nearest the ray, within 0.7 m, in front of the camera.
9. **A click submits the host's first option that targets the clicked row
   (D78c).** The client decides no rule: it does not check sides, and
   `End turn`'s target 0 never matches. No option → a HUD notice and nothing
   sent. The same return-code handling as the HUD buttons
   (`apps/client/scripts/CombatHud.gd:223–233`). The buttons stay.
10. **Feedback reads events and health only, and never mutates a proxy.**
    Numbers and flashes come from `action_resolved` events (spec §9.2 rule 2,
    `docs/CRPG_ENGINE_SPEC.md:888`: render events, do not diff health); bars
    from the health columns. Bars and numbers are 2D controls on a
    `CanvasLayer`, placed each frame with `Camera3D.unproject_position` over
    the proxy's current node position, so they follow whoever draws the proxy
    (`SceneSync` here, `Walk.gd`'s `draw_rows` in a walk scene). The flash is
    a separate sphere, because `SceneSync` owns the proxy's materials (the
    side colour and the dead tint, `crates/crpg-godot/AGENTS.md` trap
    "Side colour vs dead tint"). All timing is presentation: nothing waits on
    or changes the session.
11. **`Pick` and `Feedback` are child nodes, not `Main.gd` code.** Godot
    processes a parent before its children, so `Feedback._process` reads
    `main.view` after `Main._process` polled and synced it in the same frame.
    `Main.gd` keeps its T156b bytes, which is what lets T156b and T156c run in
    parallel. No new shell function is needed.

### What T157 ("walk, then fight") must not contradict
`open_v4_ai` is turn-based only: its pacer gates on the NPC peer's legal
options, which are always empty in real time (T050 Reading 1), so a real-time
AI open needs its own gate (for example, call `drive_ai` every cycle, which
`drive_ai`'s own real-time rules already budget) as a new `NpcDriver` variant;
do not reuse `open_v4_ai`'s gate there. The embedded host binds area bounds but
no navigation mesh (`crates/crpg-godot/src/core/mod.rs:540–542`), and without
one `decide` cannot plan an approach and ends the turn (or holds, in real
time) (`crates/crpg-ai/src/mvp.rs:184–186`), so an enemy out of reach will not
walk until T157 binds a mesh. `Pick.gd` matches options by target only, which
is exact while one actor holds all options (turn-based); if T157 offers
options for several actors, it needs an option-actor column and a selected
actor in `Pick`. `Pick` does not consume the input event; a scene that also
moves on left click (`Walk.gd:60–74`) must decide which handler wins, for
example by having `Pick` call `get_viewport().set_input_as_handled()` on a
hit. `Feedback` draws over each proxy's current position, so it works
unchanged over `Walk.gd`'s drawn positions.

```rust
use crpg_ai::{SideId, Sides};
use crpg_core::EntityId;
use crpg_server::host::MVP_AI_BUDGET;

/// How long the server AI waits before each decision (D78b).
pub(crate) const AI_STEP_DELAY_MS: u64 = 600;

/// The server AI's arming and firing state (A-3).
#[derive(Debug, Default, Clone, PartialEq, Eq)]

    due: Option<u64>,
}
impl AiPacer {
    /// Advances the pacer; `true` means call `drive_ai` once now.
    pub(crate) fn step(&mut self, now_ms: u64, ai_turn: bool) -> bool;

/// Numbers the distinct side strings ascending from `SideId(0)` (A-2).
pub(crate) fn ai_sides(rows: &[(EntityId, String)]) -> Result<Sides, Fault>;

/// The server's MVP AI as the run loop's AI hook (A-4).
pub(crate) struct ServerAiHook {
    npc: PeerHandle,
    sides: Sides,
    actors: Vec<EntityId>,
    pacer: AiPacer,
}
impl ServerAiHook {
    /// An unarmed hook for the NPC peer, the sides and the AI's actors.
    pub(crate) fn new(npc: PeerHandle, sides: Sides, actors: Vec<EntityId>) -> Self;
    /// One AI stage (A-4).
    pub(crate) fn run(&mut self, host: &mut Host, now_ms: u64) -> Result<(), HostError>;
    /// The boxed hook `LocalHost::set_ai` takes: `run` on the moved `self`.
    pub(crate) fn into_hook(self) -> AiHook;
}
```

## Behaviour
Normative. "Refused" means the stated code and no state change. **First
failure wins** in every list.

### T156a
A-1. **`open_v4_ai_with`** is `open_v4_with` (T151 B-B1 as amended, T050 W-1)
with two differences, both inside `open_v4_guarded` under
`driver == NpcDriver::ServerAi`: (1) `let npc_actors =
prefix.npc_actors.clone();` before `bind_peer` moves them; after
`presentation_tables` succeeds, `rows` = `prefix.bound` mapped to
`(entity, prefix.presentation.combatant(placement).1)` in `bound` order, and
`ai_sides(&rows)`; an `Err(fault)` returns `self.fail_fault(fault)` (25, no
runner); (2) the AI hook is `ServerAiHook::new(npc, sides,
npc_actors).into_hook()` instead of `NpcHook::new(npc, npc_sides).into_hook()`.
Under `NpcDriver::Peer` nothing runs that did not run before (no `ai_sides`,
no clone), so `open_v4*` keep every byte and behaviour. Argument checks,
`AlreadyOpen`, campaign, side and start failures are `open_v4`'s, in its
order. *Tests:* A1, A3, A7, A8.

A-2. **`ai_sides(rows)`**: collect the distinct side strings in ascending
`String` order; the `k`-th (from 0) is `SideId(k as u32)`; return
`Sides::new(rows mapped to (entity, SideId of its string))`. A
`SidesError` (an entity listed twice) is `Fault { code: StartFailed, detail:
error.to_string() }` (`"Duplicate at sides/<entity:?>"`,
`crates/crpg-ai/src/sides.rs:36–41`). Empty `rows` → `Ok` with no entries.
The open never meets the error (bound entities are distinct); it is tested
directly. *Tests:* A4.

A-3. **`AiPacer::step(now, ai_turn)`**: `ai_turn` false → disarm, `false`.
Unarmed → arm at `now.saturating_add(AI_STEP_DELAY_MS)`, `false`. Armed and
`now >= due` → disarm, `true`. Otherwise `false`. (So the AI acts one delay
after it first sees its turn, and again one delay after each act while the
turn is still its.) *Tests:* A9, A1.

A-4. **`ServerAiHook::run(host, now)`**, in order: (1) `host.is_closed()` →
`Err(HostError::Closed)` before any other call (mirrors `NpcHook`; a
deliberate shutdown is 50); (2) `host.take_delivery_entries(npc)?`, and if
non-empty `host.acknowledge_delivery(npc, last.ordinal)?`; (3) `ai_turn =
!host.legal_intents(npc)?.is_empty()`; (4) if `pacer.step(now, ai_turn)`:
`host.drive_ai(&sides, &actors, MVP_AI_BUDGET)?`, the report discarded;
(5) `Ok(())`. It calls nothing else on the host: no `ingest`, no
`encode_intent`, no NPC sequence. *Tests:* A1, A2, A3, A5, A6.

A-5. **What the player sees.** The AI's attack and turn end reach the player
as host-operation deltas in the same cycle (`host_action` publishes to v3/v4
sessions); the view's events, health, round and end equal a peer-NPC
session's for the same choices (A2). `executions()` counts only the player's
commands (Reading 5).

A-6. **Nothing else changes.** `open`, `open_v4`, `open_v4_rt`, every move
entry point, `controlled()`, `render_positions()`, the error table and every
existing test keep their bytes and behaviour.

### T156c
C-1. **`pick_proxy(camera, proxies, screen)`**: `origin =
camera.project_ray_origin(screen)`, `dir = camera.project_ray_normal(screen)`.
For each child of `proxies` whose name begins with `"proxy_"`: `id =
int(name.substr(6))`; `c = child.global_position + Vector3(0, PICK_HEIGHT,
0)`; `t = (c - origin).dot(dir)`; `t < 0` → skip; `d = (origin + dir *
t).distance_to(c)`; `d > PICK_RADIUS` → skip. Return the id with the least
`d`, the smaller id on a tie; 0 when none. Other children are ignored.

C-2. **`attack_index(view, target)`**: `view == null` or `target == 0` → -1;
otherwise the first `i` with `int(view.option_targets()[i]) == target`, else
-1.

C-3. **`attack(target)`**: `main == null` → 1. `main.session == null` → 1
(nothing chosen). `i = attack_index(main.view, target)`; `i < 0` →
`main.get_node("Hud").show_notice(NO_OPTION % name)` where `name` is
`view.names()[view.net_ids().find(target)]`, or `"-"` when the view is null
or the id is no row; return `NOTHING`. Otherwise `code = main.choose(i)`;
0, 4 and 5 → return it silently; 30 → `show_notice(main.session.last_error())`;
any other → `show_error(main.session.last_error())`; return `code` (the HUD
button rule, `CombatHud.gd:223–233`).

C-4. **`_unhandled_input(event)`**: acts only on an `InputEventMouseButton`
with `pressed == true` and `button_index == MOUSE_BUTTON_LEFT`; `main == null`
→ nothing. Then `input_calls += 1`; `camera =
main.get_node_or_null("Camera3D")`, `proxies =
main.get_node_or_null("Proxies")`, either null → stop; `id =
pick_proxy(camera, proxies, event.position)`; `id == 0` → stop; else
`attack(id)`. Every other event changes nothing, `input_calls` included. It
does not mark the event handled (T157 note).

C-5. **`sync(view)`**: `view == null` or `view.revision()` equals the last
synced revision → nothing; else remember the revision and `show_view(view)`.
(`show_view` therefore runs once per revision, so a revision's events spawn
once.)

C-6. **Bars (`show_view`).** For each row `i` of `view.net_ids()`: a bar
exists exactly when `health_known()[i] == 1` and `max_health()[i] > 0`. The
bar is a `ProgressBar` named `bar_<id>` under `Overlay`, with
`show_percentage = false`, `min_value = 0`, `max_value = max_health()[i]`,
`value = clamp(health()[i], 0, max_health()[i])`, `size =
custom_minimum_size = BAR_SIZE`, `mouse_filter =
Control.MOUSE_FILTER_IGNORE`, and an "alive" flag `dead()[i] == 0` that sets
`visible`. A bar whose row is gone or no longer qualifies is freed with
`remove_child` then `queue_free`. Cosmetic, untested: a `StyleBoxFlat` fill
override of colour `HIT_COLOR`; `Overlay.layer = 0` (below the HUD's 1).

C-7. **Numbers (`show_view`).** For each event, in order, whose `kind` is
`"action_resolved"`: `damage = event.get("damage", 0)`, `outcome =
event.get("outcome", "")`; text is `"-%d" % damage` plus `"!"` when outcome
is `"critical_success"`, if `damage > 0`; else `"miss"` when outcome is
`"failure"` or `"critical_failure"`; else `"0"`. `numbers_spawned += 1`; a
`Label` named `num_<numbers_spawned>` is added under `Overlay` with that text,
`mouse_filter = MOUSE_FILTER_IGNORE`, font colour override `HIT_COLOR` when
`damage > 0` else `MISS_COLOR` (`add_theme_color_override("font_color", ..)`),
age 0, anchored to `event.target`. Other kinds spawn nothing. Cosmetic,
untested: font size 28, outline size 6, black outline.

C-8. **Flash (`show_view`).** For each `action_resolved` event with
`damage > 0`: if a flash for its `target` lives, its age resets to 0;
otherwise a `MeshInstance3D` named `flash_<target>` is added as a child of
`Feedback` with a `SphereMesh` of radius `FLASH_RADIUS` (height twice that)
and an unshaded, alpha-transparent `material_override` of `FLASH_COLOR`, age
0. A target never has two flashes.

C-9. **`advance(ms)`**: every number's and flash's age rises by `ms`. A number
with age `>= NUMBER_MS` and a flash with age `>= FLASH_MS` is freed
(`remove_child` then `queue_free`) and forgotten. A live number's
`modulate.a` is `1.0 - age / NUMBER_MS`. Cosmetic, untested: a flash's albedo
alpha fades the same way.

C-10. **`place(camera, proxies)`**: for each bar, `proxy =
proxies.get_node_or_null("proxy_%d" % id)`, `p = proxy.global_position +
Vector3(0, BAR_LIFT, 0)`; `visible = proxy != null and alive and not
camera.is_position_behind(p)`; when the proxy exists, `position =
camera.unproject_position(p) - BAR_SIZE / 2`. For each number, the same with
its target, `NUMBER_LIFT`, and `position = camera.unproject_position(p) +
Vector2(0, -NUMBER_RISE * age / NUMBER_MS)`; no proxy → `visible = false`.
For each flash: no proxy → `visible = false`; else `visible = true` and
`global_position = proxy.global_position + Vector3(0, FLASH_LIFT, 0)`.

C-11. **`_process(delta)`**: `main == null` or `not ("view" in main)` →
nothing. Otherwise `sync(main.view)`, `advance(delta * 1000.0)`, then, when
`main.get_node_or_null("Camera3D")` and `main.get_node_or_null("Proxies")`
both exist, `place(camera, proxies)`.

C-12. **Authority and scope.** `Pick.gd` sends only through `main.choose`;
`Feedback.gd` sends nothing and reads only the view. Neither touches a proxy
node's children or materials, `SceneSync.gd`, `CombatHud.gd` or `Main.gd`.
