# T051 — cut-down demo HUD, combat log and end screen (`crpg-godot`, `apps/client`)

## Task / Crate(s) / Purpose

Sole crate: `crpg-godot` (plan row `docs/IMPLEMENTATION_PLAN.md:256`, `C → I`;
the cut-down version has no T104/T108 prerequisite). The work is GDScript in
`apps/client`, the crate's client artifact (ADR-0033 §14), plus docs. ADR-0033
scopes it at `docs/adr/0033-godot-bridge.md:522-524`: "GDScript over `view()`:
turn, health, option buttons, log, end screen. It adds no FFI member". T047d's
`apps/client/scripts/CombatHud.gd` already draws a first version
(`CombatHud.gd:63-72`). T051 turns it into a HUD that a person can play to the
end and understand: whose turn it is, everyone's health, the choices, what
happened, and who won. T048 (approved, being implemented) owns proxies and the
grey dead visual; "T051 keeps all text in the HUD" (`tasks/T048.md:391`).
Contract only.

### Decision

- **D1. Scope: rewrite `CombatHud.gd`, add a case file and a runner, add two
  hooks to `smoke.gd`, and update the docs.** `Main.gd`, `Main.tscn` and
  `SceneSync.gd` are unchanged. `Main.gd` already calls `$Hud.sync(next)`
  exactly when the revision changes (`Main.gd:38-43`). `choose(i)` is already
  `session.submit_option(seen, i)` (`Main.gd:45-48`). Both drafts agree.
- **D2. The HUD builds its nodes in `_init`, not `_ready`.** `_ready` only sets
  `main = get_parent()`, as today (`CombatHud.gd:17-19`). **Measured:** in a
  `SceneTree` script's `_initialize`, `root.is_inside_tree()` is false, so a node
  added there gets `_ready` only on the first frame. The cases must run in `_initialize`, before
  `Main.tscn` loads, as T048's do. A panel built in `_init` measured
  `position == Vector2(12, 12)` after entering the tree.
  *Settles a vs b:* both drafts assumed that `_ready` runs in `_initialize`.
- **D3. Every built node has a fixed name.** Tests find them with
  `find_child(name, true, false)`. **Measured:** with `owned = true`, the search
  finds no node created in code. *Settles a vs b:* a named the nodes; b left
  the tests no handle. The names and the order are given under Interface.
- **D4. Turn line: `Turn: <name>`.** This is the CLI's wording
  (`crates/crpg-cli/src/demo.rs:488`). The round line stays
  `Round <round() + 1>` (`docs/adr/0033-godot-bridge.md:280`). The name is the
  `names()` entry at `net_ids().find(active())`, or `-` when the id is not a
  row, which includes `active() == 0`. That is T047d's `_name_for`
  (`CombatHud.gd:143-147`). *Settles a vs b:* a's `Turn:` wording, because
  "Active" is engine vocabulary, but b's single `-` fallback instead of a's
  extra `none` case. One rule means one test.
- **D5. Health lines are unchanged from T047d** (`CombatHud.gd:91-101`). The
  line is `<name>: ?` when `health_known` is 0, otherwise
  `<name>: <health>/<max_health>`, plus ` (dead)` when `dead != 0`. Both
  drafts agree. The producer writes `dead = 0` for an undisclosed row
  (`crates/crpg-godot/src/core/client.rs:421-425`), so `? (dead)` cannot occur
  live, and the HUD does not special-case it.
- **D6. Option buttons: verbatim and in host order, and never disabled.** There
  is one `Button` per `option_labels()` entry, and pressing button `i` calls
  `main.choose(i)` once. `option_targets()` is not read; mapping a clicked
  proxy to an option is T050's job. *Settles a vs b* on disabling, for b. a
  disabled the box after a successful press and waited for the next sync. A
  refused intent at `poll` clears the pending intent
  (`client.rs:392-394`). If no frame arrived, though, the view is unchanged
  and keeps its revision (`client.rs:456-459`), so `Main.gd` never calls
  `sync` (`Main.gd:40`). Under a's rule the buttons would then stay disabled
  forever. A second press while an intent is out returns 5, which is harmless.
- **D7. What each `choose` code does.**
  - `0`, `4` and `5` are silent, as in T047d (`CombatHud.gd:153`).
  - `30` is a notice: `show_notice(last_error)`. ADR-0033's action for 30 is
    "allow another choice" (`docs/adr/0033-godot-bridge.md:338`), and
    `Main.gd:30-32` already treats a 30 from `poll` as a notice.
  - Any other code is `show_error(last_error)`.
  - `last_error` is `main.session.last_error()`, or `NOT_OPEN` when
    `main.session` is null. `Main.choose` returns 1 in that case
    (`Main.gd:46-47`), and T047d would dereference null there
    (`CombatHud.gd:154`).

  *Settles a vs b:* a's 30-as-notice and null guard are kept; a's "on 4,
  resync from `main.view`" is rejected, because `Main.gd` updates `seen` and
  syncs the HUD in the same call (`Main.gd:38-43`), so a resync fixes nothing.
- **D8. The log renders `events()`, then rejected `receipts()`.** Both come
  from the same view, oldest first, and one revision gate covers both. T047d's
  gate is kept (`CombatHud.gd:112-119`). Applied receipts print nothing, because
  their event already describes the action. The HUD never diffs health (spec
  §9.2 rule 2, `docs/CRPG_ENGINE_SPEC.md:880`). Both drafts agree. Turning
  `RejectionCode`s into player text is T051's job
  (`docs/adr/0033-godot-bridge.md:348-349`).
- **D9. The text of each event, from the CLI where the CLI has one:**
  - `action_resolved`: `<actor> | <ability> -> <target>: <verdict>, <damage> damage`.
    The `<actor> | <ability> -> <target>` part is the CLI's (`demo.rs:363-366`).
    `<verdict>` is the CLI's `verdict()` (`demo.rs:546-559`) applied to the
    outcome text:
    - `success` gives `hit (success)`;
    - `critical_success` gives `hit (critical success)`;
    - `failure` gives `miss (failure)`;
    - `critical_failure` gives `miss (critical failure)`;
    - any other string `s` gives `outcome (<s with "_" replaced by " ">)`.

    The wire's outcome set is those four strings plus `custom:<n>`
    (`crates/crpg-server/src/capture.rs:69-70`).
  - `turn_started`: `Turn: <actor> (round <round + 1>)`.
  - `died`: `<entity> dies.`, the CLI's line (`demo.rs:424`).
  - `encounter_ended`: `Encounter ended (round <round + 1>)`.
  - Any other kind prints the `kind` text unchanged.

  Ids resolve to names as in D4.

  *Settles a vs b, on rounds:* event rounds get `+1`. The event's `round` is
  the raw wire round (`client.rs:355-358`, `:365`), the same number as `round()`, which
  ADR-0033 says the HUD shows `+1` (`:280`). The CLI does the same
  (`demo.rs:428`). b's `Turn: Goblin (round 0)` printed under a `Round 1`
  header.

  *Settles a vs b, on the action line:* neither a's `critical hit` nor b's
  `(success; 4 dmg)`; the CLI's verdict wording is reused.
- **D10. Rejection text: `Rejected: <reason> (code <n>)`.** The reason is:
  - code 17 (`NotAuthorized`): `not allowed`;
  - code 18 (`IllegalAction`): `no longer legal`;
  - any other code: `refused by the server`.

  17 and 18 are the only gameplay codes (`crates/crpg-net/src/protocol.rs:426-430`);
  the rest are transport or admission codes, and the number stays visible for
  bug reports. *Settles a vs b:* b's scope (17, 18, default) with the code on
  every line; a's eight-row table advised on codes the slice cannot reach.
- **D11. The log is a line buffer of at most 200 lines.** The private
  `_lines: PackedStringArray` is the single source. On every append, the
  oldest lines beyond `LOG_MAX_LINES = 200` are dropped, then
  `Log.text = "\n".join(_lines)`, with no trailing newline. `Log.bbcode_enabled`
  stays `false`. **Measured:** T047d's `append_text` (`CombatHud.gd:78`, `:81`,
  `:118`) parses BBCode even when it is disabled and leaves `.text` empty, so
  `[b]x[/b]` is mangled and no test can read the log; setting `.text` keeps it
  literal. *Settles a vs b:* a's buffer. Both drafts chose
  200.
- **D12. Waiting line.** It is visible exactly when `ended()` is false and
  `option_labels()` is empty, which ADR-0033 defines as "not the player's turn"
  (`:287`). The text is `Waiting for <name>...`, with D4's name, or
  `Waiting...` when that name is `-`. All text is ASCII. *Settles a vs b:* a's
  wording, which names who is acting. b's `Waiting for the other side…` is
  vaguer and uses a non-ASCII ellipsis.
- **D13. End block.** When `ended()` is true, `End` is visible with exactly
  this text: `Encounter ended\nRounds played: <round() + 1>\nWinner: <w>`.
  When `ended()` is false, `End` is hidden and its text is `""`. `<w>` follows
  the CLI's summary rule (`demo.rs:502-535`):
  - a side is alive when at least one of its rows has `dead == 0`;
  - `<w>` is that side when exactly one side is alive, otherwise `draw`.

  Because the producer writes 0 for an undisclosed row's `dead`, such a row
  counts as alive. The winner text is presentation over rows that were already
  disclosed. It decides nothing (spec §9.2 rule 1, `:879`).

  *Settles a vs b:* a's three lines (T047d's first line, the CLI's other two)
  and a private `_winner`, not b's public `winner(view)`. a's "force
  the option box empty when ended" is dropped: the host already offers nothing
  once the encounter is terminal (ADR-0033 L2,
  `docs/adr/0033-godot-bridge.md:192`), and the HUD renders the view rather
  than second-guessing it.
- **D14. A `clear()` for session boundaries.** It returns the HUD to its
  just-built state and resets the log gate to −1. Nothing calls it yet. A
  future reopen task calls `$Hud.clear()` beside T048's `$Proxies.clear()`
  (`tasks/T048.md:73-80`). Without it, a new session's revision 1 would be
  skipped by the old gate. *Settles a vs b:* a's full reset. b's `clear_log()`
  would leave the previous session's end block on screen.
- **D15. No Rust test.** Existing tests already pin the producer: event and
  receipt keys, op order, no repeat and the `ended` latch
  (`crates/crpg-godot/src/core/client/tests.rs:207-336`), the raw round
  (`:395-414`) and refusal clearing pending (`:416-444`). *Settles a vs b:* a;
  b's R2 duplicates `:210`, and ADR-0033 expects no Rust (`:534`).
- **D16. Tests follow T048:** a fake-view case file, a runner `tests/hud.gd`,
  and `smoke.gd` running the same cases before `Main.tscn`. CI's BR-22 step
  (`.github/workflows/ci.yml:313-320`) therefore gates them with **no workflow
  edit**. Exit codes:
  - the runner exits 6 when a case fails, mirroring T048's runner;
  - `smoke.gd` gains exit 7, the next code after T048's 6. *Settles a vs b:* a
    chose 7; b chose 8 for both.

  `smoke.gd` also gains one real-session check at the end (H20). The fake view
  cannot prove that the HUD renders real events.
- **D17. Sentinel results, never `""`.** Each case returns `"ok"` when it passes
  and a detail otherwise. `run` returns `"PASS"` only if every case returned
  `"ok"`. **Measured:** after a runtime error inside a function declared
  `-> String`, the caller receives `""` (`TYPE_STRING`, not `null`) and keeps
  running. A runner that treats `""` as success therefore passes on a crash.
  The sentinels turn every error into a failure.

### Interface

`apps/client/scripts/CombatHud.gd` is rewritten. The public members are exactly
those below. Private helpers are allowed but must be `_`-prefixed. No
`class_name`, `@export`, signal or autoload.

```gdscript
extends CanvasLayer

const LOG_MAX_LINES := 200

var main: Node = null            # unchanged; _ready sets it to get_parent()

func _init() -> void              # builds the node tree below (D2)
func _ready() -> void             # main = get_parent(); nothing else
func sync(view) -> void           # B2-B9; null is a no-op
func show_error(text: String) -> void
func show_notice(text: String) -> void
func clear() -> void              # B11
```

Private state: `_lines: PackedStringArray`, `_logged_revision: int = -1`, and
node references. The HUD holds no other state.

The node tree is built in `_init` with these exact names. Children appear in
the order listed.

| Name | Class | Parent | Built with |
|---|---|---|---|
| `Panel` | `PanelContainer` | the HUD | `set_anchors_and_offsets_preset(Control.PRESET_TOP_LEFT)`, `position Vector2(12, 12)`, `custom_minimum_size Vector2(420, 0)` |
| `Margin` | `MarginContainer` | `Panel` | margins 12 on all four sides |
| `Column` | `VBoxContainer` | `Margin` | separation 6 |
| `Round` | `Label` | `Column` | text `""` |
| `Turn` | `Label` | `Column` | text `""` |
| `Health` | `VBoxContainer` | `Column` | no children |
| `Options` | `VBoxContainer` | `Column` | no children |
| `Waiting` | `Label` | `Column` | text `""`, hidden |
| `Log` | `RichTextLabel` | `Column` | `custom_minimum_size Vector2(0, 120)`, `scroll_following true`, `bbcode_enabled false`, text `""` |
| `Status` | `Label` | `Column` | text `""`, hidden |
| `End` | `Label` | `Column` | text `""`, hidden |

`Column`'s children are exactly `Round`, `Turn`, `Health`, `Options`,
`Waiting`, `Log`, `Status` and `End`, in that order. Children of `Health`
(`Label`) and `Options` (`Button`) have no fixed names; tests read them by
position. To replace a child, call `remove_child`, then `queue_free`, which is
T047d's idiom (`CombatHud.gd:156-159`). A removed child is therefore gone from
`get_child_count()` immediately.

The view members the HUD may call are exactly these 14. Their getters are at
`crates/crpg-godot/src/shell.rs:107-208`.

| HUD element | Members it reads |
|---|---|
| `Round` | `round` |
| `Turn` | `active`, `net_ids`, `names` |
| `Health` | `net_ids`, `names`, `health`, `max_health`, `health_known`, `dead` |
| `Options` | `option_labels` |
| `Waiting` | `ended`, `option_labels`, `active`, `net_ids`, `names` |
| `Log` | `revision`, `events`, `receipts`, `net_ids`, `names` |
| `End` | `ended`, `round`, `sides`, `dead` |

The HUD never reads `placements` or `option_targets`. On `main` it reads only
`choose(i)` and `session`, and on `session` only `last_error()`.

`apps/client/tests/hud_cases.gd` (new) is the case file:

- `extends RefCounted`.
- Inner `class FakeView extends RefCounted`.
  - Its constructor takes one `Dictionary`.
  - It has exactly the 14 getters above, and nothing else, so a HUD that
    calls `placements()` or `option_targets()` errors.
  - Each getter returns its key's value. The defaults are:
    - `revision`: 1; `active` and `round`: 0; `ended`: `false`;
    - `events` and `receipts`: `[]`;
    - `net_ids`, `health` and `max_health`: empty `PackedInt64Array`;
    - `names`, `sides` and `option_labels`: empty `PackedStringArray`;
    - `health_known` and `dead`: empty `PackedByteArray`.
- Inner `class FakeSession extends RefCounted`, with `var text := ""` and a
  `last_error() -> String` that returns `text`.
- Inner `class FakeMain extends Node`, with:
  - `var session = FakeSession.new()`;
  - `var codes: Array = []`;
  - `var chosen: Array = []`;
  - `choose(index: int) -> int`, which appends `index` to `chosen` and returns
    `codes.pop_front()`, or `0` when `codes` is empty.
- `func run(root: Node)`, untyped. It returns `"PASS"` when every case
  returned `"ok"`. Otherwise it returns `"H<n>: <detail>"` for the first case
  that did not. If `res://scripts/CombatHud.gd` does not load, it returns
  `"H0: CombatHud.gd did not load"`.
- Each case:
  1. creates `host := FakeMain.new()` and calls `root.add_child(host)`;
  2. creates `hud = load("res://scripts/CombatHud.gd").new()`, calls
     `host.add_child(hud)`, then sets `hud.main = host` (D2: `_ready` has not
     run);
  3. on exit, calls `root.remove_child(host)` and `host.queue_free()`.
- Helper `_lines(hud) -> Array`: `[]` when `Log.text == ""`, otherwise
  `Array(Log.text.split("\n"))`. **Measured:** `"".split("\n")` has size 1.

`apps/client/tests/hud.gd` (new) is the runner. It `extends SceneTree`, and in
`_initialize` it does this:

- If `res://tests/hud_cases.gd` fails to load, it prints
  `hud.gd FAIL: hud_cases.gd did not load` and exits **3**.
- Otherwise it calls `run(root)`.
- If the result is not a `String` equal to `"PASS"`, it prints
  `hud.gd FAIL: <result>` and exits **6**.
- Otherwise it prints `hud.gd OK` and exits **0**.

`apps/client/tests/smoke.gd` changes in exactly three places.

1. **The header comment** gains: `7 when a HUD case or the end-of-play HUD

2. **`_initialize`.** After the `ClassDB` check and T048's scene-sync block,

   - load `res://tests/hud_cases.gd` and call `run(root)`;
   - if the file did not load, print `smoke.gd FAIL: hud hud_cases.gd did not

   - if the result is not `"PASS"`, print `smoke.gd FAIL: hud <result>` and

3. **The `ended()` branch.** It runs after the existing proxy-count check

### Behaviour

1. **B1 build.** After `CombatHud.gd.new()`, with no tree and no `_ready`, the
   node table holds exactly: the names, classes, parents, child order and
   initial values listed there. `Health` and `Options` have no children,
   `_lines` is empty and `_logged_revision == -1`.
2. **B2 `sync(null)`** returns immediately and changes nothing.
3. **B3 turn and round.** On every sync:
   - `Round.text == "Round %d" % (view.round() + 1)`;
   - `Turn.text == "Turn: " + name`, with D4's name.

   The name comes from `net_ids().find(id)`, never from arithmetic on the id.
4. **B4 health.** `Health` gets one `Label` per row, in `net_ids()` order,
   with D5's text. The old labels are removed first.
5. **B5 options.** `Options` gets one `Button` per `option_labels()` entry,
   in that order, with `text` equal to the label and `disabled == false`. The
   old buttons are removed first. Pressing button `i` (`pressed`) calls
   `main.choose(i)` exactly once, then applies D7. When `main` is null,
   pressing does nothing. A press never disables a button and never rebuilds
   the box.
6. **B6 waiting.** D12's visibility and text, set on every sync. The text is
   set even while the line is hidden.
7. **B7 log.** When `view.revision() != _logged_revision`:
   1. `_logged_revision` is set to `view.revision()`;
   2. each `events()` entry appends its D9 line, oldest first;
   3. each `receipts()` entry with `applied == false` appends its D10 line,
      oldest first.

   When the revision equals `_logged_revision`, nothing is appended. Every
   append follows D11.
8. **B8 notices and errors.**
   - `show_notice(t)` appends `t`.
   - `show_error(t)` sets `Status.text = t`, sets `Status.visible = true`,
     overrides `font_color` with `Color(1, 0.35, 0.35)`, and appends
     `"ERROR: " + t`.
   - `sync` never touches `Status`.
9. **B9 end.** D13, set on every sync. `Health` keeps the final lines,
   including ` (dead)`.
10. **B10 no authority leak.** `CombatHud.gd` calls only the 14 view members
    and the `main`/`session` members named under Interface. Its identifiers
    include none of: `placements`, `option_targets`, `submit_option`, `poll`,
    `ClassDB`, `instantiate`, `Time`, `OS`, `_process`, `_physics_process`,
    `_input`, `_unhandled_input` or `_gui_input`. It holds no gameplay state
    (spec `docs/CRPG_ENGINE_SPEC.md:310`). No string literal in it contains
    `#`, so H19's comment stripping is exact.
11. **B11 clear.** `clear()` does all of the following:
    - removes and frees every child of `Health` and `Options`;
    - sets `Round`, `Turn`, `Waiting`, `Status` and `End` to `""`;
    - hides `Waiting`, `Status` and `End`;
    - removes `Status`'s `font_color` override;
    - empties `_lines` and sets `Log.text = ""`;
    - sets `_logged_revision = -1`.

    The result equals B1's state. A later sync rebuilds everything from its
    view, including the log of a revision that was already logged.
12. **B12 preconditions.** Parallel columns of unequal length are a caller bug
    and are not defended (`docs/adr/0033-godot-bridge.md:271`).

### Tests

Cases H1–H19 live in `hud_cases.gd` and run under both `hud.gd` and
`smoke.gd`. H20 runs in `smoke.gd` only. Every assertion compares exact values.
A count is never asserted without the content beside it.

`A` is a FakeView with these values:

- `revision 1`;
- `net_ids [4, 9]`, `names ["Hero", "Goblin"]`, `sides ["Hero", "Goblin"]`;
- `health [10, 6]`, `max_health [10, 6]`, `health_known [1, 1]`, `dead [0, 0]`;
- `active 4`, `round 0`, `ended false`;
- `option_labels ["Strike -> Goblin", "End turn"]`;
- no events and no receipts.

`A{k: v}` means `A` with those keys replaced. The ids 4 and 9 are deliberately
not row index + 1, so a lookup by arithmetic fails.

Event dictionaries:

- `AR(a, t, o, d)` is `{kind: "action_resolved", actor: a, target: t,
  ability: "Strike", ability_id: "x", outcome: o, damage: d}`;
- `TS(a, r)` is `{kind: "turn_started", actor: a, round: r}`;
- `DI(e)` is `{kind: "died", entity: e}`;
- `EE(r)` is `{kind: "encounter_ended", encounter: "x", round: r}`;
- `RC(s, ok, c)` is `{seq: s, applied: ok, code: c}`.

`L` means `_lines(hud)`. `texts(box)` is the `text` of each child, in order.
In the table, `\|` stands for a literal `|`.

**For the manager (not the user): a T048 defect found while measuring D17.**
