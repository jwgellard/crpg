# T029b — IR-BINDINGS trusted executable store (`crpg-script`)

## Task / Crate(s) / Purpose

Sole crate: `crpg-script`, Phase 8 or earlier approved MVP consumer.
**D17 selected** (see
[decision record](POST-T018-DECISIONS.md#d17--bindings-synchronous-first-slice-deterministic-later-interpreter));
T029a, E010 numbers and exact context/budget/continuation contract remain.
Bind declarations to trusted implementations; do not implement unspecified
graph/Lua/World features under a registry-shaped task.

## Interface — exact handler/continuation gate

Approve exact immutable binding table constructor, symbolic id lookup, handler
context, argument/result/error types and dispatch function. Table pairs each
trusted Rust handler with the identical T029a declaration/bundle identity.
Pin duplicate/missing/mismatched registration error precedence and failure
before graph execution. Context may expose only approved public sim operations,
never an unrestricted host capability or client-controlled function pointer.

D17/E010 must pin deterministic instruction/node/memory budgets, nested graph
versus Lua charging/abort semantics and rollback/partial-side-effect rules.
If handlers wait/yield, a **separate earlier crpg-sim-only continuation task**
must define world-owned persisted continuation state/API and its hash/ADR
compatibility. A bindings-only task cannot add that state or fake restart via
process-local closures. Alternative: explicitly approve synchronous no-wait
handlers for this slice and leave durable interpreter continuations open.

## Behaviour

Trusted startup assembles/finalizes the store. Missing, duplicate or signature/
version mismatch fails closed before any graph mutates World. Validate calls
through T029a; authored id lookup never installs code. Registration order must
not alter resolution or diagnostics; no mutable hot swap of handler semantics
for old content. Combat ability ids are not converted into IR registry ids.

Execution honors approved public sim transactional boundaries and deterministic
budgeting, with positive authorized invocation controls and unchanged complete
state on pre-execution rejection. If Lua dispatch is included by a later exact
contract, enforce ADR-0005/E010 base-global stripping (`load`, `loadfile`,
`dofile`, plus `loadstring`) and sandbox limits; no wall-clock rule aborts.
The binding table itself neither chooses a Lua dependency nor implements a
native-extension loader. Save/restart behavior must match the selected
synchronous-or-continuation scope honestly.

### Exact API

Public module `bindings`, re-exported at root:

```rust
pub const MAX_BINDING_PROPOSALS: usize = 32;
pub type ActionHandler = for<'a> fn(&InvocationContext<'a>, &ActionCall)
    -> Result<Vec<CombatAction>, HandlerError>;
pub struct InvocationContext<'a> { /* private read-only world and actor */ }
impl<'a> InvocationContext<'a> {
    pub fn world(&self) -> &'a World;
    pub fn actor(&self) -> EntityId;
}
pub struct ActionBinding {
    pub signature: ActionSignature,
    pub handler: ActionHandler,
}
pub struct ActionBindings { /* private immutable store and binding map */ }
impl ActionBindings {
    pub fn new(declarations: ActionSignatureStore,
        identity: ActionBundleIdentity, bindings: Vec<ActionBinding>)
        -> Result<Self, BindingError>;
    pub fn declarations(&self) -> &ActionSignatureStore;
    pub fn contains(&self, action_id: &str) -> bool;
    pub fn dispatch(&self, world: &mut World, actor: EntityId,
        identity: &ActionBundleIdentity, call: &ActionCall)
        -> Result<Vec<Option<ActionOutcome>>, BindingError>;
}
pub enum HandlerError { Refused, UnsupportedWait }
pub enum BindingError {
    BundleMismatch,
    TooManyBindings,
    DuplicateBinding { action_id: String },
    UnknownBinding { action_id: String },
    MissingBinding { action_id: String },
    SignatureMismatch { action_id: String },
    Call(SignatureError),
    Actor(CombatError),
    Handler(HandlerError),
    ProposalLimit,
    ForeignActor { index: usize },
    Apply { index: usize, error: CombatError },
}
```

InvocationContext fields cannot be constructed/mutated externally; no World
mutator, RNG access or host capability is offered. Binding/Bindings need not
implement PartialEq (function-address equality is not semantic equality), serde
or Debug exposing function pointers. HandlerError and BindingError derive Debug,
Clone, PartialEq, Eq and implement Display/Error. Call/Actor/Handler delegate
Display and source; Apply displays `Apply at proposals/<index>` and exposes its
CombatError source. Remaining displays are `<VariantName> at bindings`, no fields.
HandlerError displays its variant name. No arbitrary handler error text on wire.
No mutable lookup, handler registration after construction, hot replacement,
dynamic library/coroutine, serialization of function pointers or From<World>.

### Startup validation

`new` checks supplied identity exactly equals declarations.identity(); then
bindings.len <= MAX_ACTION_SIGNATURES; duplicate ids (lexically first); unknown
ids (lexically first); missing ids (lexically first); exact signature equality
in declaration lexical order. Signature equality includes action id, parameter
name/type/required and **parameter order**. Empty declarations with empty bindings
is valid. Bounds precede sorting or constructing the private BTreeMap; never
silently overwrite duplicates. Registration permutation leaves behavior and
errors unchanged. Binding code is trusted startup input, never installed by
authored ActionCall or deserialization. The declaration digest does not attest
to handler code; a new build is still a new exact-build determinism domain.

### Synchronous dispatch and atomicity

1. Validate identity/call through T029a, returning Call(error); no handler has
   run yet. Do not duplicate its type/coercion/bounds logic.
2. Use T028's `validate_action(world, &CombatAction::EndTurn { actor })` to
   validate the invocation actor in the existing public execution order, mapping
   failure to Actor(error). Do not resolve an action on a clone or duplicate
   the checks in script. T028 is now an explicit implementation prerequisite.
3. Invoke the matched function once with immutable context and validated call.
   Handler failure returns Handler(error) without mutation. A returned
   UnsupportedWait is a real error, never a saved continuation or success.
4. Reject more than 32 proposals (ProposalLimit), then the first proposal whose
   actor differs from the invocation actor (ForeignActor with zero-based index).
   Empty proposals succeed with an empty result and unchanged World.
5. Clone World and execute proposals in returned order using perform_action.
   This is sequential validation against staged state, not prevalidation of
   every action against the initial state. Return Apply at the first rejected
   proposal and discard all staged RNG/events/resources/entity/turn changes.
6. On complete success publish the staged World once and return outcomes in
   proposal order (Some for UseAbility, None for EndTurn). Preserve the complete
   ActionOutcome; no script-created damage values or fake receipts.

The handler's reviewed contract requires deterministic, bounded, side-effect-free
proposal construction from its arguments/context; no globals, I/O, entropy or
interior host mutation. Rust function pointers are **trusted**, not a preemptive
sandbox: a returning Vec bound cannot prevent a trusted function from allocating
or looping before return. No instruction-metering or panic-recovery guarantee is
claimed; panicking handlers are bugs, not script budget errors. Proposal count
bounds applied sim operations only. Do not charge future graph/Lua counters in a
task that runs neither. Host actor authorization and target disclosure remain
outside this library; simulation legality always rechecks current staged state.

### Public acceptance

`tests/action_bindings.rs` must exercise real data declarations and public sim
World/controller APIs with hand-authored trusted handlers:

- exact startup success and every identity/duplicate/unknown/missing/signature
  failure, including parameter-order mismatch and shuffled registration;
- all call-validation failures before a handler that would panic if invoked;
- actor errors before handler invocation, with valid actor control;
- one accepted combat action, accepted legal failed attack and explicit EndTurn;
- 32 legal non-ending proposals versus 33 rejected proposals, and empty success;
- first proposal valid/second invalid causing exact complete-World byte/hash
  rollback, including an initial RNG-consuming attack and its queued death;
- actor substitution rejected before staging, wait refused, retry after a
  rejection identical to a fresh invocation, deterministic output across two
  Worlds initialized from the same bytes;
- immutable-context compile-fail rustdoc proving no mutable World access.

Save/reload the **World** between two completed synchronous invocations and
rebuild identical trusted bindings; compare subsequent outcome and full World
bytes with uninterrupted execution. No binding table or partial call is saved.
This is a continuation-free proof, not persistence of a live interpreter.
