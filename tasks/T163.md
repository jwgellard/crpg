# T163 — Adventure demo polish: mode line, no "Waiting..." while walking, default scene (`apps/client`)

Follow-ups F-hud-mode and F-default-scene of [T157](T157.md) §"Out of scope".
The user chose this wave on 2026-11-28 (session 105: "Polish the demo").
Not S-set: no Rust, no workflow, no schema.

## Exact contract

### Interface
- `apps/client/scripts/CombatHud.gd` gains one public member:
  `var waiting_needs_turn: bool = false`. Nothing else in `CombatHud.gd`
  changes, and it builds no new node (H1's node and column lists stay as
  they are).
- `apps/client/scenes/Adventure.tscn` gains one node, appended after
  `MoveHud/MoveLabel`:
  `[node name="ModeLabel" type="Label" parent="MoveHud"]` with
  `visible = false`, `offset_left = 12`, `offset_top = 652`,
  `mouse_filter = 2`. No other node, resource or property in the scene
  changes.
- `apps/client/scripts/Adventure.gd` gains
  `const MODE_EXPLORING := "Exploring"`, `const MODE_FIGHT := "Fight"` and
  `func mode_text() -> String`.
- `apps/client/project.godot`: `run/main_scene` becomes
  `"res://scenes/Adventure.tscn"`. No other setting changes.

### Behaviour
- **B1 (`CombatHud.sync`).** The Waiting label's visibility becomes
  `not view.ended() and view.option_labels().is_empty() and (not
  waiting_needs_turn or int(view.active()) != 0)`. Its text rule is
  unchanged. With `waiting_needs_turn == false` every output of `sync` is
  byte-for-byte what it was (Main.tscn and H1–H20 are unaffected).
- **B2 (`Adventure._ready`).** Sets `$Hud.waiting_needs_turn = true` before
  the session is opened, so it holds even when the open fails.
- **B3 (`Adventure.mode_text`).** Returns `""` when `session == null`,
  `open_code != 0`, `stop_code != 0` or `view == null`; otherwise
  `MODE_FIGHT` when `in_fight()` is true, else `MODE_EXPLORING`. It reads
  only `view.active()` through `in_fight()`; it decides no rule.
- **B4 (`Adventure._process`).** Every frame, after the existing readout
  lines: `$MoveHud/ModeLabel.text = mode_text()` and
  `$MoveHud/ModeLabel.visible = $MoveHud/ModeLabel.text != ""`. It must
  also run on the frames where the existing early `return` fires (open or
  stop failed, no view), so place it so the label is cleared there; the
  existing lines' behaviour does not change.
- **B5 (default scene).** Launching the project with no scene argument opens
  `Adventure.tscn` over `campaigns/demo/adventure`. `Main.tscn` and
  `Walk.tscn` stay in the project and keep working when named explicitly.

### Tests
- **H21 in `apps/client/tests/hud_cases.gd`** (appended to the case list;
  no existing case edited). With a view `_a({"active": 0, "option_labels":
  []})`: (a) `waiting_needs_turn` false → Waiting visible, text
  `"Waiting..."`; (b) set true and sync the same view → Waiting hidden;
  (c) true with `_a({"active": 9, "option_labels": []})` → Waiting
  visible, text `"Waiting for Goblin..."`; (d) true with
  `_a({"active": 0, "option_labels": [], "ended": true})` → hidden. Each
  value is asserted against the literal above.
- **AD11 checks in `apps/client/tests/adventure.gd`**, written where those
  states already occur and tagged `"AD11 ..."`; no existing `_want`
  removed or loosened:
  - (a) on the first frame with a view and no active turn (AD1_frame or
    AD3): `$MoveHud/ModeLabel` visible with text `"Exploring"`, and the
    Hud's `Waiting` label hidden; `$Hud.waiting_needs_turn == true`.
  - (b) on a frame where a turn is active (inside the fight cases):
    ModeLabel text `"Fight"`.
  - (c) in AD8, once a hero walks again after the fight: ModeLabel text
    `"Exploring"` and Waiting hidden.
  - (d) `ProjectSettings.get_setting("application/run/main_scene") ==
    "res://scenes/Adventure.tscn"`.
  - The scene-shape check in AD1 that lists `MoveHud`'s children (if any)
    gains `ModeLabel`; a new `_want` asserts `MoveHud/ModeLabel` is a
    `Label` with `mouse_filter == 2`.
  - The final reached check stays meaningful: it still requires the last
    case's last line.
- **Controls.** `adventure.gd`'s documented control (missing campaign →
  exit 3) still exits 3. Mutating B1 to ignore `waiting_needs_turn` must
  fail H21 (b); mutating B3 to always return `MODE_EXPLORING` must fail
  AD11 (b); the worker states in the report that it ran both mutants by
  hand and saw each fail, then reverted them.
