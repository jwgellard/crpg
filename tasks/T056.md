## Task
Give the engine its first AI: a read-only function that, for one creature the
server controls in an encounter, says what to do next — attack the nearest
hostile it may legally attack, or walk toward the nearest hostile, or close
its turn — using only the legality the players use (`crpg_sim::legal_actions`,
`crates/crpg-sim/src/combat.rs:3733–3786`, and its one validation path
`validate_action`, `:3453–3455`). Today `crpg-ai` is a four-line skeleton with
no dependency (`crates/crpg-ai/src/lib.rs:1–4`, `crates/crpg-ai/Cargo.toml:7`),
and nothing in sim, rules or core knows who is hostile to whom
(`tasks/T056-facts.md:88–90`, re-checked: `Combatant` has no side field,
`crates/crpg-sim/src/combat.rs:206–236`).

- **T056a — the decision (`crpg-ai`).** `Sides` (who is hostile), `decide`,
  and the two helpers it is built from: `host_route` (the route the host will
  compute for a destination, exactly as T037 A-5 does) and `point_along`.
  Opens the crate: Cargo edges, architecture doc and `AGENTS.md`.
- **T056b — the behaviour tests over real encounters (`crpg-testkit`).**
  `crpg-ai` may not read `crpg-data`, so its own tests cannot start an
  encounter (Reading 13); these tests start turn-based and real-time
  encounters from authored documents, bind a real mesh, apply each decision
  through the sim verbs the host uses, and pin every value.

The AI never mutates the world and never calls a host operation. The host
driver that calls `decide` each turn or tick and applies the result through
T037's `host_move`, `move_to`, `halt` and the existing action path is a
later task (Out of scope).

## Readings
Design decisions this contract makes. Each needs approval with the contract.

1. **Hostility is a caller-supplied side map (`Sides`) in `crpg-ai`.** Sim,
   rules and core have no sides, teams or allegiance; faction exists only as
   authored data (`Placement.faction`, `crates/crpg-data/src/document.rs:122–125`;
   `Faction.relations` with an integer `disposition` no code interprets,
   `:288–311`), and `crpg-ai` may not import `crpg-data`
   (`tools/lint/deps.py:53`). So the caller (the host driver) hands `decide`
   a `Sides`: each listed entity has one `SideId`; two entities are hostile
   exactly when both are listed with different sides; an unlisted entity is
   hostile to no one and no one is hostile to it; an entity is never hostile
   to itself. The driver fills it from authored data (for the MVP:
   faction-else-placement, the grouping `crpgc demo` already prints,
   `crates/crpg-cli/src/demo.rs:123–126`). The alternatives and what each
   changes for later tasks are Question 1. *Rejected here:* (a) a closure
   `Fn(EntityId, EntityId) -> bool` (draft A): not data, so it cannot be
   compared, logged, or shown equal across two calls, and nothing stops it
   being asymmetric or stateful; (b) a per-actor `hostiles: &[EntityId]`
   list (draft B): the same information re-built for every actor and every
   call, with no way to say "these two are allies", which T083's party AI
   needs; (c) a runtime side field on `Combatant` now: a `World` change
   (S-set, every combat hash path) for a fact only the AI reads today;
   (d) "different placement means hostile" (`crates/crpg-cli/tests/play.rs:278–281`):
   a fixture convention; two goblins of one band have different placements.
2. **`legal_actions` is the only source of what the AI does; `validate_action`
   is asked one yes/no question.** Every `CombatAction` `decide` returns is an
   element of `legal_actions(world, actor)` (T028's "the existing
   `CombatAction` is the complete executable option", `tasks/T028.md:112–113`).
   To know whether walking would help, the AI asks `validate_action` whether a
   `UseAbility` against the target fails with exactly `CombatError::OutOfRange`:
   the range stage is the last admission stage
   (`crates/crpg-sim/src/combat.rs:3645`, `crates/crpg-sim/AGENTS.md:631`), so
   that answer means "legal in every respect but distance". Spec §6.3 item 1
   names that shared legality API as the AI's (`docs/CRPG_ENGINE_SPEC.md:723`).
   The AI also reads, as policy and never as legality, the ability's `range`
   and `costs` (`crates/crpg-sim/src/combat.rs:431`, `:460`) and the movement
   pool's balance (`Combatant::action_pool`/`extra_pools`, `:270–278`), to
   choose how far to walk. *Rejected:* re-deriving affordability and range
   from the definition (a second legality source, which T028 forbids,
   `tasks/T028.md:115–117`); walking only after an attack is listed (it is
   never listed while out of range, X2, `crates/crpg-sim/src/combat.rs:3722–3723`).
3. **The AI decides; it never executes.** `decide(&World, …)` returns one
   `Decision`; the host applies it through the trusted operations T037a
   defines (`host_move` for a turn-based move, `move_to` and `halt` for real
   time, `tasks/T037.md:385–398`) and the existing action path, each of which
   revalidates (`tasks/T028.md:20–30`). *Rejected:* `decide(&mut World)`
   calling `perform_action` itself (puts execution, records and publication in
   a crate that cannot see the host).
4. **Moves are destinations the host will accept, checked with the host's
   own route.** T037a's `host_move(actor, destination)` and
   `move_to(actor, destination)` take a destination and compute the route
   themselves: the goal is `nearest_on_mesh(snap(measure, destination))`, the
   path `find_path(mover.position(), goal)`, copied whole (T037 A-5,
   `tasks/T037.md:529–536`, Reading 6, `:168–177`). A turn-based move that
   costs more than the pool is refused whole (`CannotAfford`,
   `crates/crpg-sim/src/movement.rs:871–882`). So the AI takes the bound mesh
   as an argument (`crpg-ai → crpg-nav`, allowed, `tools/lint/deps.py:53`),
   chooses a destination on its own path, and accepts it only if
   `host_route` — the same computation — gives a route that `validate_move`
   (turn-based) or `validate_route` (real time) accepts
   (`crates/crpg-sim/src/movement.rs:858–884`, `:424–441`). Same mesh, same
   world, same integer functions: the host gets the same route and the same
   answer. *Rejected:* the target's own position as the destination (draft B):
   any target farther than one turn's movement is then `CannotAfford` and the
   AI never closes in turn-based play, and in real time it walks into the
   target; returning a `MoveRoute` (draft B): T037's operations take
   destinations, and the host recomputes anyway; no movement at all (draft A):
   not "move to nearest hostile".
5. **"Nearest" is the U4 horizontal distance, ties by `EntityId`.** Distance
   is `crpg_sim::seg_len(actor position, target position)`
   (`crates/crpg-sim/src/movement.rs:310–315`), the measure the range stage
   uses through `within_range` (`:373–381`), so "nearest" and "in range"
   agree. A pair without a mover on both sides has distance `u64::MAX`. The
   minimum of `(distance, EntityId)` wins. *Rejected:* the `f32` `Transform`
   mirror (presentation only, U2/U6, `crates/crpg-sim/src/movement.rs:1–8`);
   tie by store order (`ComponentStore::iter` is insertion-ordered, not
   sorted, `crates/crpg-sim/AGENTS.md:336`).
6. **Attack the nearest hostile you may attack; otherwise walk to the nearest
   hostile.** The attack choice is over the listed `UseAbility` options whose
   target is hostile: least `(distance, target, ability)`. The approach target
   is the nearest hostile overall. "The first affordable ability" (spec
   stage 1) is the least ability ULID among the options against that target:
   `legal_actions` lists only affordable ones (`crates/crpg-sim/src/combat.rs:3593–3634`).
   *Rejected:* draft B's "attack only the single nearest hostile": a hostile
   in reach would be ignored for one out of reach, which reads as a broken AI
   once a fight has two enemies.
7. **The approach stops just inside range.** The *intended ability* is the
   least ability ULID of the definition whose `UseAbility` against the target
   fails exactly `OutOfRange` (Reading 2). The AI walks to the point of its
   path whose remaining path length is `range − STANDOFF_MARGIN_RAW` (64 raw,
   about 1 mm). Integer rounding puts the arrival point at most 3 raw further
   from the target than the remaining path length (U5 truncates each
   coordinate toward the start, `crates/crpg-sim/src/movement.rs:322–336`; U4
   rounds a length up, `:310–315`), so 64 raw is ample and the attack is
   legal on arrival. *Rejected:* walking to the target's position (Reading 4);
   no margin (rounding could leave the actor 1 raw out of range, and the next
   step would spend a whole movement step for 1 raw).
8. **A turn-based approach spends at most what the turn can afford, keeping
   the attack's cost.** Budget: the movement pool's balance less the intended
   ability's total cost in that pool (zero unless the ruleset pays moves and
   attacks from one pool), in whole steps: `floor(budget / step_cost) × step`
   raw, which is exactly the largest length `validate_move` accepts
   (`crates/crpg-sim/src/movement.rs:871–882`). The reserve applies whether or
   not the attack is reachable this turn. *Rejected:* spending the whole pool
   when the attack is out of reach this turn (a second rule and a second
   distance computation, for the MVP's one hostile); no reserve (on a shared
   pool the AI would walk into range and be unable to strike).
9. **One candidate destination, verified, no back-off.** If the checked route
   is refused, the AI does not move (it closes its turn or holds). *Rejected:*
   retrying shorter destinations: on a straight or bent path the recomputed
   route to a point of the path is that path's prefix or shorter (U5
   truncates toward the start), so a retry loop would be a branch no test can
   reach, which a mutant review cannot defend.
10. **One step per call; the driver loops.** A turn-based turn is a sequence
    of calls — typically `Move`, then `Act(attack)`, or `Act(EndTurn)` — and
    `perform_move` keeps the turn (`crates/crpg-sim/src/movement.rs:886–891`).
    Every accepted turn-based `Move` costs at least one pool unit (its length
    is at least 1 raw and `step_cost ≥ 1`, `crates/crpg-data/src/combat.rs:1379`),
    so moves within one turn are bounded by the pool. In turn-based play
    `decide` never returns `Halt` or `Hold` (a turn-based combatant has no
    route, `crates/crpg-sim/src/movement.rs:783–789`); it always returns an
    action or a move. *Rejected:* a returned plan of several steps (the second
    step depends on the first's outcome, which only the host knows).
11. **Real time: halt before striking, never re-issue an order, keep walking
    while the walk still ends in range.** In real time an accepted
    `UseAbility` only stores a standing order (`crates/crpg-sim/src/combat.rs:3851–3867`),
    and an order whose target leaves range is kept and retried every tick
    (X3, `crates/crpg-sim/AGENTS.md:633`). So: with an attack available and a
    route, `Halt` first (so the actor does not walk into the target); with
    the same order already standing, `Hold`; while the current route ends
    within the intended ability's range of the target's current position,
    `Hold` (no path query each tick); otherwise re-plan. With no hostile left,
    a standing order is cleared with `Stop`, then a route with `Halt`.
    *Rejected:* re-issuing the order each evaluation (the host would record
    and publish an action every tick); re-planning every tick (a nav query per
    AI per tick for nothing).
12. **Errors are `legal_actions`' errors, unwrapped.** `decide` returns
    `Result<Decision, LegalActionsError>`: an actor that cannot act
    (`NoEncounter`, `NotParticipant`, `OutOfTurn`, dead, terminal fight,
    `TooManyOptions`) is the caller's to handle, and the caller already knows
    `LegalActionsError` (`crates/crpg-sim/src/combat.rs:3677–3711`). Every
    movement and navigation failure is a defined `Decision` (Reading 9), never
    an error. *Rejected:* a wrapper `AiError` (draft B): one variant carrying
    the same value; `Option` (draft A): drops why the actor cannot act.
13. **Behaviour tests live in `crpg-testkit`.** Starting an encounter needs
    `crpg-data` documents (`EncounterSpec`, `crates/crpg-sim/src/combat.rs:882–897`),
    and `crpg-ai`'s `ALLOWED` row has no `crpg-data` and an empty dev set
    (`tools/lint/deps.py:53`). `crpg-testkit` may depend on every crate but
    `crpg-godot` (`:68`) and already reads authored documents in tests
    (`crates/crpg-testkit/Cargo.toml:17–25`). T056a keeps the tests that need
    no encounter. *Rejected:* a `crpg-data` dev edge for `crpg-ai` (an
    `ALLOWED` change); checked-in JSON `World` snapshots deserialized by
    `crpg-ai`'s tests (draft B: `World` does deserialize,
    `crates/crpg-sim/src/world.rs:150`, but the snapshots need a generator in
    another crate, are unreviewable blobs, break whenever sim's save form
    grows, and need a `serde_json` dev edge).
14. **No aggro radius, line of sight or node budget in the MVP.** Spec stage 1
    lists aggro radius and line of sight (`docs/CRPG_ENGINE_SPEC.md:698`), but
    the MVP scope cut is "no AI beyond move to nearest hostile and attack"
    (`:1531`, D27f) and sim has no line-of-sight query. Being in the
    encounter is the aggro. One call costs one `legal_actions` (bounded by
    `MAX_LEGAL_ACTIONS`, `crates/crpg-sim/src/combat.rs:58`), at most one
    `validate_action` per listed ability, and at most two `find_path`s; when
    to call it (the spec's budget and time slicing, `docs/CRPG_ENGINE_SPEC.md:724`)
    is the driver's.
15. **`crpg-ai` follows the simulation crates' determinism rules by
    contract.** `tools/lint/determinism.py:66` does not scan `crpg-ai`. Its
    `AGENTS.md` therefore states, and the reviewer checks: no `f32`/`f64` or
    float literal, no `HashMap`/`HashSet`, no clock, thread or RNG, no
    interior mutability; all arithmetic in `u64`/`i128` through sim's U4/U5
    functions. Adding `crpg-ai` to the lint is a manager edit ("Manager
    edits").

```rust
/// A side in a fight; entities on different sides are hostile (Reading 1).
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]

/// Who is on which side; built by the caller (Reading 1).
#[derive(Debug, Clone, Default, PartialEq, Eq)]
pub struct Sides { entries: Vec<(EntityId, SideId)> } // ascending EntityId, unique

/// Why `Sides::new` refused its input.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum SidesError {
    /// The entity is listed more than once.
    Duplicate { entity: EntityId },
}
// Display: "Duplicate at sides/{entity:?}"; std::error::Error with source() None.

impl Sides {

    pub fn new(entries: Vec<(EntityId, SideId)>) -> Result<Self, SidesError>;
    /// The entries, ascending EntityId.
    pub fn entries(&self) -> &[(EntityId, SideId)];
    /// The entity's side, if listed.
    pub fn side(&self, entity: EntityId) -> Option<SideId>;
    /// Both listed, different sides (so never `hostile(e, e)`).
    pub fn hostile(&self, a: EntityId, b: EntityId) -> bool;
}
```

```rust
/// One next step for one actor (Readings 3, 10, 11). The driver's mapping:
/// `Act` → the action path; `Move` → `host_move` (turn-based) or `move_to`
```

## Behaviour
Normative. Each item names the tests that prove it. "First failure wins" in
every ordered list. Nothing here mutates the world, draws from its RNG or
interns a string.

### T056a: sides and routes
S-1. **`Sides::new(entries)`** sorts the entries by `EntityId` (stable);
if two adjacent entries share an entity, `Err(Duplicate { entity })` for the
least such entity; else `Ok`. `side` is a binary search; `hostile(a, b)` is
`side(a)` and `side(b)` both `Some` and unequal. *Tests:* U1, U2, U3.

R-1. **`host_route(nav, world, actor, destination)`**, in order:
(1) `world.nav()` is `None` (`crates/crpg-sim/src/world.rs:1228`):
`NavUnbound`; (2) `!world.contains(actor)` (`:1115`): `AbsentEntity { entity:
actor }`; (3) no mover (`:1217`): `NotMover { entity: actor }`;
(4) `goal = nav.nearest_on_mesh(crpg_sim::snap(measure_of(world), destination))`
(`crates/crpg-nav/src/query.rs:92`, `crates/crpg-sim/src/movement.rs:384`);
`nav.find_path(mover.position(), goal)` (`crates/crpg-nav/src/path.rs:203`),
`Err(e)` is `Nav(e)`; (5) `Ok(MoveRoute { revision: world.nav() value, tag:

### T056a: `decide(world, actor, sides, nav)`
Definitions. `L = legal_actions(world, actor)`. `rt` is
`world.combat().mode == EncounterMode::RealTime`. `pos(e)` is
`world.movers().get(e).map(Mover::position)`. `dist(e)` is
`seg_len(pos(actor), pos(e))` when both are `Some`, else `u64::MAX`.
`route()` is the actor's `Mover::route()` (`crates/crpg-sim/src/movement.rs:126–129`),
`order()` its `Combatant::order()` (`crates/crpg-sim/src/combat.rs:285`).
The **fallback** is: turn-based, `Act(EndTurn { actor })`; real time,
`Halt` when `route()` is `Some`, else `Hold`.

M-1. **Legality first.** `L` `Err(e)` is returned as `Err(e)` unchanged and
nothing else is read. *Tests:* U7, G11.

M-2. **Hostiles.** `H` is every `e` in `world.combatants()` with `e != actor`,
`!dead()` and `sides.hostile(actor, e)`, ascending `EntityId`. *Tests:* G3,
G10, G12.

M-3. **No hostile.** `H` empty: turn-based, `Act(EndTurn { actor })`; real
time, `Act(Stop { actor })` when `order()` is `Some`, else `Halt` when
`route()` is `Some`, else `Hold`. *Tests:* G12, G17.

M-4. **Attack.** `K` is the `UseAbility { target, ability, .. }` entries of
`L` with `target ∈ H`. If `K` is non-empty, `k` is its least by
`(dist(target), target, ability)`. Turn-based: `Act(k)`. Real time: `Halt`
when `route()` is `Some`; else `Hold` when `order()` is
`Some(StandingOrder { ability, target, .. })` of `k`; else `Act(k)`.
*Tests:* G1, G2, G3, G4, G5 (second call), G16.

M-5. **Approach target and intended ability.** `T` is the least `e ∈ H` by
`(dist(e), e)`. The intended ability `I` is the least ability ULID of
`world.combat().definition.abilities` (`crates/crpg-sim/src/combat.rs:504`)
with `validate_action(world, &UseAbility { actor, ability, target: T }) ==

absent or negative, `nav` `None`, or `pos(actor)` or `pos(T)` `None`: the
fallback. *Tests:* G9, G10.

M-6. **Real-time hold.** Real time, `route()` `Some`, and

pos(T))` (`crates/crpg-sim/src/movement.rs:373`): `Hold`. *Tests:* G15.

M-7. **Destination.** `goal = nav.nearest_on_mesh(snap(measure_of(world),
pos(T)))`; `path = nav.find_path(pos(actor), goal)`, `Err` → the fallback.
`d = path.length().saturating_sub(r − STANDOFF_MARGIN_RAW, saturating at 0)`.
Turn-based only: with `TurnMovement { pool, step_cost, .. }` the definition's
`movement` (`None` → the fallback), `balance = pool_balance(actor's
combatant, pool)`, `reserve` the sum of `I`'s `costs` amounts whose pool is

`d = min(d, units × step raw)` (`Mover::step`, `crates/crpg-sim/src/movement.rs:121–123`).
`d == 0` → the fallback. `x = point_along(path.points(), d)`. *Tests:* G5,
G6, G7, G14.

fallback. Otherwise `Move { target: T, destination: x }`. *Tests:* G8, G9.

equal inputs give equal results. *Tests:* G13.

## Questions for the user
1. **How does the AI know who its enemies are?** Nothing in the running game
   records sides today: the editor's "faction" is stored with each placed
   creature, but the simulation never reads it. The AI needs to know, for each
   pair of creatures in a fight, "are these enemies". (a) **The caller tells
   the AI (recommended).** The code that runs the AI each turn passes a small
   table "creature → side"; creatures on different sides are enemies. For the
   MVP that code fills it from the authored faction, or from the placement
   when there is none. Nothing else changes; T080 (smarter AI) and T083 (party
   AI) read the same table, and allies are simply "same side". (b) **Store a
   side on each combatant in the simulation now.** Sides become part of the
   saved game and the state hash, so this is a protected (S-set) change to
   the simulation with its own task before T056, and every saved game and
   golden that includes combatants must be checked. It pays off only when
   rules themselves (spells that hit "all enemies", morale, charm) need sides.
   (c) **Interpret faction "disposition" numbers as hostility now** (for
   example "below zero means hostile"): a new authoring rule with its own
   data task, and the AI would still receive the result as in (a).
   *Recommend (a):* it is the smallest change, it does not lock in a meaning
   for disposition numbers before authors use them, and (b) or (c) can later
   fill the same table without changing `crpg-ai`.
2. **May the test crate use the AI crate and the navigation crate in its
   tests?** The AI's real behaviour can only be checked in a started fight,
   and starting one needs the authored-data crate, which the AI crate may not
   use. The test crate (`crpg-testkit`) can. (a) **Approve both test-only
   links (recommended):** nothing ships differently; one more link of the
   kind you approved for T037e. (b) **Decline:** T056b is dropped and the AI
   is tested only on its helpers (sides, routes, distances), with the
   behaviour checked first by the later host-driver task.
   *Recommend (a).*
