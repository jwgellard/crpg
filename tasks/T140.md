# T140 — protocol v3: encounter facts, events, intents and the `0x82` snapshot (`crpg-net`)

**Status: draft for user review, 2026-11-10 (UTC). Not approved.** Written
by the Claude architect from ADR-0029 §4 N1–N4
(`docs/adr/0029-kernel-range-and-time-model.md`, accepted D30c), after
adjudicating two blind drafts (`tasks/T140-draft-a.md`,
`tasks/T140-draft-b.md`) and the fact sheet `tasks/T140-facts.md`. It is
split into four serialized parts, **T140a → T140b → T140c → T140d**, each one
implementer run in `crpg-net`. This is an H-filter contract (it decides what
each player may see); the user approves it with the "Questions for the user".

Citation convention: a bare `:N` or `:N–M` is a line of the file cited
earlier in the same list item or sentence; where no file has been cited
there, it is a line of ADR-0029. Every citation was checked on branch
`task/T140-c1` (base `fd93e4f`). Every literal byte below was computed by an
independent Python model of this contract's layout (postcard primitives: raw
`u8`/`bool`, LEB128 varints, zigzag `i32`, length-prefixed UTF-8, raw
`[u8; 16]`), not by any implementation and not copied from a draft.
`U(n)` below means `Ulid::from_u128(n)`; its wire text is `1A` followed by
26 ASCII bytes (`U(1)` = 25 × `30` then `31`; `U(2)` ends `32`; `U(3)` ends
`33`). `Z16` means 16 bytes `00` (the all-zero epoch).

## Task
Add protocol version 3 to `crpg-net`, carrying ADR-0029 N1 (`:324–331`):
the world facts mode, pending mode, clock, timeline order with keys, pools,
attached effects, standing orders and stat values (round and the active
combatant already travel in the v1 `Turn` op); the host facts pause state and
reason, the viewer's own pause rights, the auto-pause toggles and the turn
timer (the server tick is every frame's header); the events `RoundStarted`,
`ModeChanged`, `OrderEnded` plus T139's `Joined`/`Left`; the intents `Stop`,
`Pause`, `Unpause`, `RequestMode` beside `DeclareAction`/`EndTurn`; the
rejection codes T137, T138 and T139 left here; per-field grants for every new
fact (N2, `:333–336`); the N4 `Clock` heartbeat op (`:342–345`); and the N3
snapshot allowlist extension as transfer version `0x82` (`:338–340`). v1, v2,
`0x81` and `0x91` stay frozen byte for byte. `crpg-net` still reads no
`World`: T141 builds every value and grant.

- **T140a — v3 vocabulary and scalar codec.** `protocol_v3` (version, tags,
  intents, codes, receipts, modes, pause reasons, host facts, the delta enum
  without the three fact ops), `codec_v3` for intents and for delta tags
  0..=10 and 14..=20.
- **T140b — fact ops and event projection.** The fact types, bounds and
  checks; codec for tags 11..=13; `projection_v3`.
- **T140c — fact filtering.** `facts_v3`: `FactView`, the per-row and
  per-encounter grants, change detection, and the composite `project_page`.
- **T140d — the `0x82` snapshot.** `transfer_v3` (body, codec, framing,
  `plan_transfer`) and the composite `project_snapshot_v3`.

## Crate(s)
**`crpg-net` only**, for all four parts. No dependency is added; `crpg-sim`
and `crpg-data` stay dev-only (`crates/crpg-net/Cargo.toml`, ADR-0019 `:10–11`).

**S-set.** A wire version is a schema version, so **T140a, T140b and T140d
are S-set** (they fix bytes): serialized, Claude implementer, Claude reviewer
and a two-keys writer. **T140c** fixes no byte (it decides which existing
fact ops a viewer receives); it is not S-set but is H-filter work and gets
the Claude reviewer.

**Who builds what.** `crpg-sim` holds and hashes the world facts (T138,
T139) and journals the events. `crpg-server` (T141) reads `World` and host
state, builds every `FactRow`, `EncounterInput`, grant, `EventCandidate`,
`Clock`, `HostFacts` and `Receipt`, and sends frames. `crpg-net` (this task)
only defines bytes, filters host-supplied values by grant, remembers what each
viewer was last told, and encodes.

**Left to T141 (`crpg-server`):** P1–P9 (pause, rights, auto-pause, restore,
turn timer); the host's mode-request authorization; reading

peer); the v3 `EventCandidate` mapping that replaces the `None` arm at
`crates/crpg-server/src/host.rs:2484–2489` (`Moved` stays `None`); mapping
sim errors to the new codes; heartbeat timing (H-1); choosing v2 or
v3 per session; sending `HostFacts` and `Clock` after each publication.
**Left to T026p (`crpg-net`):** `DeclareMove`, `Moved`, position grants and
lane 1, as protocol version 4 (ADR-0036 `docs/adr/0036-movement-and-navigation.md:413–417`, `:568–571`).
**Left to a new `crpg-net` receiver task** (manager to file): `ReassemblyPool`
gating of v3 deltas and publication of `0x82` bodies
(`crates/crpg-net/src/reassembly.rs:249–282` are v1/v2/`0x81`-only), and a v3

## Readings of the ADR
Each needs the user's approval with the contract. "Draft a/b" name the blind
drafts; their claims were checked, not trusted.
1. **Version 3, new modules, no negotiation.** v1 is byte 1
   (`crates/crpg-net/src/protocol.rs:25`), v2 byte 2
   (`crates/crpg-net/src/protocol_v2.rs:34`); v3 is byte 3 in new modules, and
   each codec refuses the others' bytes with `UnsupportedVersion`
   (`docs/architecture/crpg-net.md:213–217`). Both drafts agree.
2. **Tags 0..=10 are re-declared natively in v3, not wrapped in `Legacy`.**
   New codes must reach a receipt, and the receipt's code byte is a v1 type
   frozen at 1..=20 (`crates/crpg-net/src/protocol.rs:391–472`). Wrapping v2
   (draft a) leaves two receipt ops (tag 7 and a new tag 21) for one meaning;
   draft b's native re-declaration gives one op per tag. Payload bytes of
   tags 0..=10 are unchanged, and `From` conversions from v1 and v2 ops let
   `InterestView` and `projection_v2` output flow into v3 pages.
3. **Round and active stay in `Turn` (tag 6)** under the existing
   `turn_granted` grant (`crates/crpg-net/src/interest.rs:86–89`). A second
   carrier (draft a's `Encounter.round`/`active`) could disagree with it.
   Draft b is right here.
4. **Facts are images, and absent means withheld.** Each fact op carries the
   viewer's complete current image of its subject: an `Option` that is `None`
   is "not disclosed", never zero (ADR-0029 U7 `:389–391`). A nullable fact
   that is disclosed is `Option<Option<_>>` (for example "granted, and there
   is no pending mode"). An op whose fields are all withheld tells the client
   to forget that subject (for example the encounter ended).
5. **The timeline carries the authority order.** Entries come in ascending
   `(key, EntityId)` (`crates/crpg-sim/src/timeline.rs:27–31`), but the client
   sees `NetId`s, whose order can differ inside a tie. The wire therefore keeps
   input order, and the decoder checks only non-decreasing keys and distinct
   entities. Draft a's "descending `(key, entity)` pair is `Malformed`" would
   reject legal tie orders. Hidden entities have no entry.
6. **One `EntityFacts` op per entity** with five families: pools, effects,
   order, stats, and tags. Tags are not in N1; T139 assigned "record tags" to
   T140 (`tasks/T139.md:1914–1917`). Health stays in the v1 `Health` op
   (draft a duplicated it). Pools are `(id, current, max)` with ULID ids
   (`crates/crpg-rules/src/resource.rs:24`, `:80–87`; draft a's string ids
   are wrong). Effects are `(effect, expires_round)` (`crates/crpg-sim/src/combat.rs:190–198`),
   orders `(ability, target, repeat)` (`:95–104`), and stats are the `Int`
   attributes and `Fixed` stats by name (`:247–250`, `:292–295`).
7. **Change detection lives in a companion `FactView`, not in
   `InterestView`.** Adding fields to `FieldMask`, `EntityFact` or
   `ViewerContext` (draft b) would break the struct literals in
   `crates/crpg-net/tests/interest.rs` and reopen T027b. `FactView` mints
   nothing: it resolves keys through the one `InterestView` of the epoch
   (`crates/crpg-net/AGENTS.md:107–113`). It is driven only through the
   composites `project_page` and `project_snapshot_v3`, which validate
   before the view mutates, so a call is all-or-nothing. Draft a's stateless
   `facts_page` re-sent every fact every page and emitted ops for viewers
   with no grant, which contradicted its own item 17.
8. **Over-limit families are withheld, never truncated or refused.** A
   family whose list or names break a wire bound (Interface, T140b) renders
   as withheld for that row. That fails closed: the client shows "hidden",
   and the session continues. Question 2 asks the user to approve the
   limits.
9. **Orders.** `FactMask::order` defaults to false. T141 sets it only for the
   controlling peer (N2, `:334`). An order whose target has no `NetId` for
   this viewer is withheld as a family, because a hidden target cannot be
   named. T141 grants `OrderEnded` under the same rule.
10. **Codes 21..=30.** `ModeUnsupported`, `WrongMode` (`tasks/T138.md:859–865`);
    `StatEvaluation` (`tasks/T137.md:823`); `EncounterTerminal`,
    `RulesetMismatch`, `PlacementInUse`, `NotCreature`, `AlreadyParticipant`,
    `NoEntrants` (`tasks/T139.md:1914–1916`); and one `NoPauseRight` for P4's
    typed refusal (`:296–297`). The client knows which verb it sent, so one
    code is enough (draft b; draft a's two codes add nothing). A paused host
    still runs commands (P2), so there is no `Paused` code. `TooManyTags`
    stays host-side (`tasks/T137.md:823–824`).
11. **Intents 2..=5 share the v1 header.** `Stop`, `Pause`, `Unpause` carry
    nothing; `RequestMode` carries one mode byte. The header still requires a
    nonzero `actor`. For `Pause`, `Unpause` and `RequestMode` it names the
    requesting peer's bound character, and T141 decides what it authorizes.
12. **`Clock` is an op, and the server tick is the frame header.** A delta
    frame has no kind byte, so a heartbeat is an ordinary delta frame
    holding a `Clock` op. It consumes an `event_seq` like any frame (draft b
    reading 2). N4's `server_tick` is the header's `server_tick`, so it is not
    copied into the op (draft a's copy needed a consistency rule). N4's
    `paused` is carried with its reason: `Clock { paused: Option<PauseReason> }`
    is the only carrier of pause state. `POLICY_CLOCK_HEARTBEAT_TICKS = 100`,
    half the 200-tick window (`crates/crpg-net/src/protocol.rs:159–165`), so
    one lost heartbeat still leaves a fresh tick (both drafts).
13. **`HostFacts` is one op:** the viewer's two rights, the auto-pause
    toggles (optional, because they are operator-owned) and the turn timer as
    remaining milliseconds (optional; `None` = no timer is running). It is
    remaining time, not a host wall-clock deadline, because the client's
    clock is not the host's (P8 keeps wall-clock reads in the server,
    `:314–316`). `PauseReason::Player` carries no peer identity (Question 3).
14. **`0x82` is `0x81` with a new first byte and a wider body.** T024 reserved
    `0x82` for new facts (`tasks/T024.md:333–334`). Frames, tags, caps,
    chunking and `TransferAssembly` are unchanged; only byte 0 and the body
    differ. The body is the `0x81` body (`:321–335`) with a fact set after
    each entity's health, then an encounter block and a timeline block.
    Host facts are not in the body: they are per viewer and not state at the
    cursor, so T141 sends them as ops after publication. Draft b's
    64-chunk/2 MiB envelope would change `BeginTransfer` limits, the
    32-chunk receiver bitmap and staging policy
    (`crates/crpg-net/src/reassembly.rs:139–149`), so it is rejected.
15. **The limits fit the frozen 1 MiB envelope.** With the T140b bounds the
    largest valid `0x82` body is 1,045,548 bytes (computed in T140d), which is
    under `MAX_SNAPSHOT_BYTES` = 1,048,576 and 32 chunks.
16. **Rolls stay off the wire.** No v3 field carries a roll, modifier, DC or
    margin. History never stores them (`crates/crpg-sim/src/history.rs:77–86`,
    `docs/adr/0021-authoritative-host-capture.md:72`), and no ruleset has an
    opt-in flag, so v3 would have nothing to send. Question 1 covers this.
17. **`Joined`/`Left` are in, `Moved` is out.** `Joined`/`Left` are notices
    (tags 17/18) that never mint or retire ids. `Moved` and `DeclareMove` need
    position grants, quantized points and lane-1 rules (ADR-0036 L1–L6). That
    is a second H-filter decision about the size of T026p, so T026p defines
    protocol v4 after this contract closes (ADR-0036 `:568–571`). Both drafts
    left `Moved` out; draft b's question recommended folding it in, and that is
    declined.

## Interface

struct and enum derives `Debug, Clone, PartialEq, Eq`, plus `Copy` where
marked. No serde derive, no `Serialize`, no restore constructor. Numbers
from `crate::protocol` are used by path, never copied. Errors reuse

### Wire layout (T140a and T140b)
**Intent frame:** `3`, `epoch [u8;16]`, `lane u8`, `seq u64`,
`observed_tick u64`, `actor u64`, body tag `u8`, then the body: tag 0 is
`ability` ULID text and `target u64`; tags 1..=4 carry nothing; tag 5 is
`mode u8`.

**Delta frame:** `3`, `lane u8`, `server_tick u64`, `event_seq u64`,
op count `u64`, then each op as its tag and these fields:

| Tag | Fields after the tag, in order |
|---|---|

## Behaviour
Normative. Each item names the test that proves it (`## Tests`). "Refused"
means the stated error, no output and no state change. **First failure wins**
in every list below.

### T140a: version, intents, scalar ops
A-1. **Version gate.** `encode_*` writes byte 3 first. `decode_intent` and
`decode_delta` check, in this order: (1) input over 4,096 / 65,536 bytes is
`FrameTooLarge`; (2) empty input is `Malformed`; (3) a first byte other than 3
(including 1, 2, `0x81`, `0x91`) is `UnsupportedVersion`. The v1 and v2 codecs
refuse byte 3 with `UnsupportedVersion`; no codec guesses or falls back.
*Tests:* A1.

A-2. **Intent decode order:** frame cap → version → `epoch` (16 bytes) →
`lane` (≠ 0: `WrongDirection`) → `seq` (outside `SEQ_FIRST..=SEQ_LAST`:
`Malformed`) → `observed_tick` → `actor` (0: `Malformed`) → body tag (6..=255:
`UnknownMessage`) → body fields → trailing bytes (`Malformed`). Body fields:
tag 0 reads ULID text (length > 256: `LimitExceeded`, checked before the body
bytes; unparsable: `Malformed`) then `target` (0: `Malformed`); tag 5 reads
`mode` (2..=255: `UnknownMessage`). Truncation anywhere is `Malformed`.
*Tests:* A2, A3.

A-3. **Intent encode** checks `lane` (`WrongDirection`), then `seq`
(`Malformed`), then writes the A-2 layout, then the frame cap. It never
returns partial bytes. *Tests:* A3.

A-4. **Delta decode order:** frame cap → version → `lane` (`WrongDirection`)
→ `server_tick`, `event_seq` (any `u64`) → op count (> 256: `LimitExceeded`,
before any op is read; the vector grows by push) → per op: tag (any byte
outside 0..=20 is `UnknownMessage`; in T140a, 11..=13 are as well), then the
fields left to right, each checked when read → trailing bytes (`Malformed`).
*Tests:* A1, A8, A9.

A-5. **Tags 0..=10 are byte-identical to v2.** For every v2 op `o` whose
receipt code (if any) is 1..=20, `codec_v3::encode_delta` of a frame holding
`DeltaOp::from(o)` equals `codec_v2::encode_delta` of the same frame with byte
0 changed from 2 to 3, and decoding it returns `DeltaOp::from(o)`. Tag 7
additionally accepts codes 21..=30. A code byte of 0 or 31..=255 and a status
tag other than 0/1 are `UnknownMessage`. A receipt `lane` ≠ 0 is
`WrongDirection` and a receipt `seq` outside the range is `Malformed`
(`crates/crpg-net/src/codec_v2.rs:455–470`). *Tests:* A4, A5.

A-6. **Codes.** `RejectionCode::from_u8(n)` is `Some` exactly for 1..=30, and
`as_u8` inverts it. `From<protocol::RejectionCode>` keeps the numeric value
for all twenty v1 codes. The v1 `RejectionCode::from_u8(21..=30)` is still
`None`. *Tests:* A5.

A-7. **Scalar ops 14..=20** follow the layout table. A mode byte of 2..=255
is `UnknownMessage`; an `actor`/`entity` of 0 is `Malformed`; a `Clock` reason
byte of 4..=255 or trigger byte of 5..=255 is `UnknownMessage`; a `HostFacts`
`bits` byte with any of `0xE0` set is `Malformed`; a flag byte other than
0/1 is `Malformed` (postcard `bool`). *Tests:* A6, A7.

A-8. **Delta encode** checks `lane`, then the op count (`LimitExceeded`),
then each op in order: receipt `lane` and `seq`; ULID text bound;
`ActionResolved` outcome bound (`LimitExceeded`) then vocabulary
(`Malformed`); (T140b) the fact checks of B-4. Then it checks the frame cap
(`FrameTooLarge`). It never returns partial bytes. *Tests:* A3, A5, A9, B7.

A-9. **Toggles.** `AutoPauseToggles::from_bits(b)` is `Some` for `0..=0x1F`
and `None` for `0x20..=0xFF`. `get`/`with` use bit `trigger.as_u8()`.
`PauseReason::tag` is 0..=3 in declaration order. *Tests:* A7.

A-10. **Identity.** Encoding a frame twice gives equal bytes;
`decode(encode(f)) == f` for every variant. A ULID received in a case alias
decodes and re-encodes as canonical uppercase (the inherited core rule).
*Tests:* A10.

### T140b: fact ops and event projection
B-1. **Encounter (tag 11).** Each of the three fields is a disclosed flag;
`pending_mode` and `clock` add a `some` flag. A mode or pending byte of
2..=255 is `UnknownMessage`. A `round_ticks` of 0 is `Malformed`. An
`elapsed` above `MAX_CLOCK_ELAPSED` is `Malformed`, checked when read. All 36
combinations of `mode` (3 values), `pending_mode` (4) and `clock` (3)
round-trip. *Tests:* B1.

B-2. **Timeline (tag 12).** A disclosed flag of `false` ends the op. Otherwise
the count is read as a bounded varint: over 1,024 is `LimitExceeded`, checked
before any entry (a ten-byte hostile count included), and a varint
overflowing `u64` is `Malformed` (`crates/crpg-net/src/codec_v2.rs:124–143`).
Each entry reads `key`, then `entity` (0: `Malformed`), then checks
`key` ≥ the previous entry's key (`Malformed`), then that `entity` has not
appeared before (`Malformed`). Equal keys may come in any `NetId` order.
*Tests:* B2.

B-3. **Fact set (tag 13 after `entity`; also the `0x82` body).** The families
are read in the order pools, effects, order, stats, tags. Each is a disclosed
flag, then for a list a bounded-varint count (over its cap: `LimitExceeded`,
before any element), then each element with these checks in this order:
- pool: ULID text, `current`, `max`; then `current > max` is `Malformed`;
  then a `pool` equal to an earlier pool's is `Malformed`.
- effect: ULID text, `expires_round`; then an `effect` not strictly greater
  than the previous one (by `Ulid` order) is `Malformed`.
- order: `some` flag, then ULID text, `target` (0: `Malformed`), `repeat`.
- stat: the name's length varint (over 16: `LimitExceeded`, before the body
  bytes; 0: `Malformed`), its body (short: `Malformed`), UTF-8
  (`Malformed`); `kind` (2..=255: `UnknownMessage`); `value` (zigzag `i32`;
  out of range: `Malformed`); then a name equal to an earlier stat's is
  `Malformed`.
- tag: as a stat name; then a tag not strictly greater than the previous one
  (byte order) is `Malformed`.
A withheld family has no bytes after its flag. A disclosed empty list is the
flag `01` plus count `00`, which is distinct from withheld. *Tests:* B3, B4,
B5, B6.

B-4. **Encode-side checks** are the public `check_*` functions, applied in
wire order. A count over its cap is `LimitExceeded`. Then, per element in list
order: a stat or tag name of more than 16 bytes is `LimitExceeded`; an empty
name, `current > max`, a duplicate, an out-of-order element, `round_ticks` 0
and `elapsed` over the cap are `Malformed`. Each function returns exactly the
error that `encode_delta` returns for an op holding the same value.
*Tests:* B4, B5, B7.

B-5. **`project_events`.** More than 256 candidates is `TooManyEvents`, with
no output. Candidates are visited in input order, and one op is appended per
fully disclosed event: no sorting and no deduplication. `V2(c)` yields exactly
the ops `projection_v2::project_events(&[c])` returns, converted with `From`;
its `StringLimit`/`InvalidOutcome` errors fail the whole call. `RoundStarted`
needs `round`, `ModeChanged` needs `mode` and `round`, `OrderEnded` needs
`actor`, and `Joined`/`Left` need `entity` and `disclose == true`. A
candidate missing any of these is omitted without inspecting its other
fields. *Tests:* B8.

### T140d: the `0x82` snapshot
D-1. **Frames.** `transfer_v3::encode_down`/`encode_up` return exactly the

`0x81` to `0x82`. `decode_down`/`decode_up` check, in order: (1) input over
65,536 / 4,096 bytes is `FrameTooLarge`; (2) empty input is `Malformed`;
(3) a first byte other than `0x82` is `UnsupportedVersion`; (4) otherwise they
return what the `0x81` decoder returns for a copy with byte 0 set to `0x81`,

(`tasks/T024.md:350–395`). The `0x81` decoders and `codec_v3` refuse `0x82`

D-2. **Body layout:** `entity_count` varint; per entity `entity u64`,
`health_present bool` [`health u32`, `max_health u32`, `dead bool`], the fact

`round u64`]; the encounter block (tag 11 payload); the timeline block (tag 12
payload). *Tests:* D3.

D-3. **Body decode order:** input over 1,048,576 bytes is `LimitExceeded`;
count over 1,024 is `LimitExceeded` (before growth). Per entity: `entity` 0

health; then the fact set (B-3). After the last entity, each order target in
entity order must be one of the body's entities (`Malformed`). Then turn
(`active` must be an entity: `Malformed`), then encounter (B-1), then
timeline (B-2; each entry's entity must also be an entity: `Malformed`,
checked last for that entry). Trailing bytes are `Malformed`. *Tests:* D3,
D4.

D-4. **Body encode** checks the count (`LimitExceeded`), ascending order, the
fact-set checks per entity (B-4), order-target membership, `active`
membership, the clock, the timeline checks and membership, and then the
length (> 1,048,576: `LimitExceeded`, unreachable within the caps). The
largest valid body is **1,045,548 bytes**: 2 (count) + 1,024 × 1,006 (entity

  publication, `HostFacts` and `Clock` go out before or with the first delta
  above the cursor.
- H-3. The `order` grant and the `OrderEnded` candidate are set only for the
  peer controlling the actor (N2).
- H-4. History events map to v3 candidates in journal order; `Moved` stays
  withheld until T026p.
- H-5. Sim errors map to codes 21..=29, a pause or unpause without the right
  to `NoPauseRight`, and every other gameplay refusal to `IllegalAction` as
  today.

## Errors
No new codec error variant. `CodecError` (six variants,
`crates/crpg-net/src/codec.rs:51–66`) covers every wire refusal:

| Refusal | Error |
|---|---|
| frame over 4,096 (intent, up) / 65,536 (delta, down) bytes | `FrameTooLarge` |
| first byte not 3 (lane 0) / not `0x82` (transfer v3) | `UnsupportedVersion`; empty input `Malformed` |
| lane, receipt lane or transfer direction wrong | `WrongDirection` |
| unknown op, body, status, code, mode, reason, trigger or stat-kind byte | `UnknownMessage` |
| count over cap (ops, timeline, pools, effects, stats, tags, entities), ULID text over 256 bytes, name over 16 bytes, body over 1,048,576 bytes | `LimitExceeded` |
| truncation, trailing bytes, flag byte not 0/1, varint overflow, id 0, `seq` out of range, bad ULID/UTF-8/outcome, empty name, `current > max`, duplicate or out-of-order element, `round_ticks` 0, `elapsed` over cap, toggle bits over `0x1F`, entity not ascending, a referenced entity missing from the body | `Malformed` |

`ProjectionError` (`TooManyEvents`, `InvalidOutcome`, `StringLimit`) is
reused unchanged. `FactError` is new, with four variants (Interface, T140c):
its `Display` texts are `<Variant> at projection/facts`, with no payload, and
`source()` is `None`. Gameplay refusals are receipts, never codec errors.

two-keys suite of its part, written independently from this text. All bytes
are hex. Unless stated: epoch `Z16`; intents use `lane 0, seq 1,
observed_tick 7, actor 1`; deltas use `lane 0, server_tick 100 (64),

## Questions for the user
1. **Should players see their own dice rolls? (ADR-0029 Open question 8.)**
   When a character attacks, the server rolls dice and tells clients only the
   result ("hit", "miss", damage). You accepted in principle (D30) that a
   ruleset may let a player see their own character's roll and bonuses
   ("you rolled 14 + 3"), while target numbers stay hidden unless the
   ruleset makes them public. Today the engine never keeps the roll after
   resolving it: the history stores only the result, and no ruleset has a
   "show rolls" setting. This protocol therefore has nothing to send yet.
   (a) Leave rolls out of v3, and add them in a later protocol version
   together with the history and ruleset changes that produce them. (b)
   Reserve an empty roll message in v3 now, which nothing would fill until
   then. *Recommend (a):* a message with no sender cannot be tested, and the
   later version is needed anyway. Players and authors see no difference
   until the roll work lands.
2. **How much can players see on one creature?** Every fact sent to a
   player has a size limit, so that a player who joins or reconnects
   mid-fight can get the full picture in one bounded package (1 MiB, the
   existing limit). This contract allows, per creature, 8 resource pools, 8
   active effects, 12 stats, 4 tags, and stat and tag names of up to 16
   characters. If a creature has more of one kind (for example 13 stats),
   that whole kind shows as "hidden" for that creature; nothing breaks. (a)
   Keep these limits and the existing 1 MiB package. Later, campaign
   validation can warn authors who exceed them. (b) Raise them (for example
   16 effects, 32 stats, 32-character names). That needs a bigger package
   and a rework of the client's download logic, which T024 sized for 1 MiB.
   *Recommend (a):* today's rulesets use at most 5 stats with names of at
   most 7 characters. Raising later is a new protocol version.
3. **Do other players see who paused the game?** In multiplayer, anyone
   with the pause right pauses everyone (ADR-0029 P4). This contract tells
   clients only "paused by a player", "auto-paused because …", "paused by
   the host" or "paused after loading", never which player. (a) Keep it
   anonymous. (b) Send who paused, which needs a player number on the wire
   that no message has today. *Recommend (a);* it can be added in a later
   version if play-testing asks for it.
4. **Approve the four-part split and its limits on what this version
   includes.** The work is about 1,500 lines of code, in four parts in
   order: (a) message formats for commands and simple events; (b) the
   encounter, turn order and per-creature facts; (c) deciding which of
   those facts each player receives; (d) the reconnect package. Movement
   messages are not included and come next with T026p. The client-side
   reader for the new reconnect package comes in a separate follow-up task.
   *Recommend: approve.*
