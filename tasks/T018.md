# T018 — Lane-0 combat protocol + simulated transport + conformance

## Status and purpose

**Specified at milestone level; implementation and verification are not claimed.**

Deliver the first bounded authoritative-transport proof: a versioned lane-0
combat protocol, a deterministic in-memory simulated transport, and a
conformance suite proving codec round-trip, malicious-client rejection without
mutation, filtered replica convergence, and the roadmap 5,000-tick loss/jitter
exercise. This is Phase 4's earliest gate, not Phase 4 completion. Real QUIC,
movement, reconnection, prediction, and richer event history are named
follow-ons with their own tasks.

This file is the E004 parent. It authorizes no multi-crate branch. Each child
below is a single-crate `crpg-net` task with exact shapes, limits, tests, and
stopping commands. Implementation starts only in the children, in order.

| Work package | Sole crate | Deliverable | Depends on |
|---|---|---|---|
| T018a | `crpg-net` | Versioned lane-0 protocol + `postcard` codec, local `Transport` trait, wire hard maxima, crate opening docs | Approved E017 Appendix B |
| T018b | `crpg-net` | Deterministic simulated transport with bounded queues, injected time, fault schedules | T018a |
| T018c | `crpg-net` | Conformance: codec round-trip, malicious-client suite, filtered desync oracle, 5,000-tick exercise | T018a, T018b |

Each child owns its own tests under `crates/crpg-net/tests/`. T018a owns the
crate opening (`docs/architecture/crpg-net.md`, `crates/crpg-net/AGENTS.md`).
Later children extend those docs rather than starting new ones. No other crate
is touched. No replay fixtures, goldens, hash exclusions, or native target
selection are changed. Testkit stays an integration consumer; no net/host
runtime dependency enters testkit.

## Constraints on all children

- Doc attribution on every edited doc file; never rewrite prior entries.
- `#![forbid(unsafe_code)]`, `#![warn(missing_docs)]`. No `HashMap`/`HashSet`
  in net code or tests (use `BTreeMap`/`IndexMap`); no `f32`/`f64` in wire
  policy paths except explicitly approved spatial fields (none in v1 lane 0);
  no clock, threads, I/O, or unseeded RNG. Deterministic fault schedules use
  `crpg-core` `DeterministicRng` or an explicit seeded counter, never
  `SystemTime` or `rand`.
- No `crpg-contracts` or `rust-toolchain.toml` changes. No dependency added
  without the explicit approval steps written in T018a. No host API invented;
  host-policy checks are exercised through a net-local test double with
  supplied visibility/ownership tables, never claimed as the real host.
- B4-style replay compatibility untouched: no new `SimEvent`, no queue-drain
  semantic change, no hash-exclusion change, no golden rebaseline. Rejected
  inputs leave complete World/RNG/event state byte-identical.
- Gates 9+ remain capability-gated per spec §15.4. Prior green suites prove
  nothing about new protocol claims.
