# T019 — atomic same-pool affordability (`crpg-sim`)

## Task / Crate(s) / Purpose

**Ready specification; implementation not performed.** Sole crate: `crpg-sim`.
Repair the concrete defect recorded in T018c's completion: individually valid
cost entries on one pool jointly exceed its balance, pass validation, then
panic in `spend_costs` after resolution. Restore ADR-0016's atomic-cost promise.

Read T018c lines 149–155, ADR-0016 §2/§4, sim AGENTS, `combat.rs`
`perform_action` and `spend_costs`, and [standing rules](POST-T018-RULES.md).
No C0 decision is required for this existing-API invariant repair.

## Interface (exact, unchanged)

Use existing `start_encounter(&mut World, &EncounterSpec)` and
`perform_action(&mut World, CombatAction) -> Result<Option<ActionOutcome>, CombatError>`
with `CombatAction::UseAbility { actor, ability, target }`. Existing errors:
`InsufficientAction { pool: Ulid, cost: u32, current: u32 }` and
`ValueOverflow`. No public type, method, serde shape, event or error variant
is added. `Display` remains `InsufficientAction at combat/pool`.

## Behaviour

At the existing affordability stage (after actor/target/turn/ability/self-target
validation, before creating/drawing RNG or changing any state), evaluate all
entries for each pool as **one total**. Visit pools in authored template order,
primary first, not ULID-sorted order. For that pool checked-add its u32 amounts;
an unrepresentable sum returns existing `ValueOverflow` before mutation. For a
representable total greater than current, return `InsufficientAction` with
the total cost and original balance. First failing pool in template order wins;
do not let a later pool's overflow replace an earlier pool's insufficiency.

Only after all pools pass may existing resolution/spending run. Accepted
actions spend exactly the sums; zero-cost entries are harmless. Do not
normalize or rewrite persisted definition vectors, change existing cost
order, alter RNG draw order, or replace the panic with an error after partial
mutation. Keep the adapter's existing per-entry validation; even an impossible
total above max must safely reject through `perform_action`. Loaded worlds
using existing public serde must receive the same safe validation.

This chooses summed affordability from T018c's two suggested remedies. Adapter
shape rejection is an alternative requiring a contract amendment because it
would change where the regression fails. No new authored data restriction is
silently introduced.

## Test

Create `crates/crpg-sim/tests/combat_costs.rs`, constructing authored inputs
in memory through existing fixture helpers/public types:

1. Pool max/current 5, costs 3+3 on the same pool: adapter succeeds; action
   returns exact `{pool, cost: 6, current: 5}` without panic. Compare complete
   serialized World bytes and state_hash before/after (RNG/events included).
2. Positive controls: 2+3 succeeds and spends 5; 2+2 leaves 1. Use non-ending
   turns/no-refresh fixture conditions so refresh cannot hide the spend.
   Assert accepted failed attacks also spend once; ordinary single-cost works.
3. Multiple pools: an affordable first pool and insufficient repeated second
   pool mutate neither; both insufficient report first template pool even if
   ULIDs sort differently. Noncontiguous repeats and zero entries are covered.
4. A legal spending action depletes current below max; a repeated-total action
   then rejects although each amount fits individually. Save/reload before the
   rejected action reproduces exact error and no mutation through public serde.
5. Checked overflow using a publicly loadable coherent world when authored
   numeric limits cannot construct it: no wrap/panic, `ValueOverflow`, unchanged
   bytes. Pair with the largest representable valid total; do not access private
   helpers. Earlier actor/turn/ability errors still win over cost errors.
