## Command contract

```text
crpgc replay <replay-path> [--golden <golden-path>] [--campaign <campaign-root>]
```

1. The replay path stays the first argument after `replay`. Flags before that
   path remain usage errors. After the path, `--golden` and `--campaign` may
   appear in either order, at most once each. Values are separate arguments.
2. `--campaign` explicitly selects combat payload semantics and supplies the
   campaign tree. Its absence selects the existing reference adapter unchanged.
   No content sniffing, replay-name special case, implicit campaign search,
   auto-fallback, or mixed vocabulary. A combat replay without the flag reaches
   the reference adapter's ordinary unknown-intent error. A reference replay
   with the flag fails combat payload decoding after campaign preflight.
3. Golden default remains `replay_path.with_extension("golden")`. No target
   detection, fallback to repository fixtures, or implied rebless operation.
4. All paths remain `OsString`/`PathBuf`. Relative paths resolve against process
   working directory, independently: campaign is not relative to the replay.
   The campaign may be outside the repository and its directory may be renamed.
5. Retain existing parser diagnostic behavior for old inputs, except the
   documented usage text now includes `--campaign`. New errors have exactly:
   `crpgc: --campaign needs a value\n` and
   `crpgc: --campaign given more than once\n`, both exit 2. A missing campaign
   value or a next token recognized by `flag_text` as a flag is the former;
   detect that before checking duplicate occurrence. Existing `--golden` value
   parsing is unchanged, including its treatment of flag-looking value tokens.
6. Unknown flags, extra positionals, `--campaign=...`, `--`, recording flags,
   and other unlisted syntax remain usage errors. Parse the whole command
   before I/O. A non-Unicode campaign root parses and reaches the collector's
   exit-1 diagnostic rather than being lossy-converted or rejected as usage.

Extend `Command::Replay` with `campaign_root: Option<PathBuf>`. Keep the
hand-written `args_os` parser and process rendering conventions.

## Execution order and error rendering

Legacy mode retains its current single call to `play_and_verify` with
`apply::reference_intents()` and existing Outcome mapping.

Combat mode, in order:

1. Collect the supplied campaign tree through the existing
   `collect_campaign_files_with` / `RealFs` path. Reuse its sorted traversal,
   classifier, ignored-file, ancestor/symlink, non-Unicode, and portable I/O
   diagnostic behavior. Do not copy T016c's test-only `read_tree` into the CLI.
2. Reuse `load_for_command` with `env!("CARGO_PKG_VERSION")`, calling
   `load_campaign` once. The exact defensive version failure is
   `crpgc replay: internal engine version failure\n` (exit 1). Structural and
   load errors use existing `data_outcome`; collector errors use `io_outcome`.
3. Call `crpg_data::validate(&loaded)` once. Require an empty finding list,
   matching T016c's simulation-input precondition. For any findings, print each
   using the existing diagnostic-line formatter in returned order, stdout
   empty, exit 1. This command's strict precondition also rejects future
   warnings; it does not change `validate` command's warnings-only exit policy.
   Do not sort, reconstruct, or duplicate validation in the CLI.
4. Move the loaded campaign into the private combat adapter and call
   `crpg_testkit::play_and_verify(replay_path, golden_path, apply)` once.
   The harness reads/validates the replay, initializes World, interleaves
   inputs/ticks/hashes, and compares the golden. No extra replay read or parser.
5. Success is exit 0 with both streams empty. Replay/apply/divergence errors
   use the existing `Outcome::cli_error(CliError::Replay(...))` path:
   `crpgc replay: {ReplayError Display}\n`, stdout empty, exit 1.

Error precedence is therefore usage → campaign collection → engine/load →
campaign semantic findings → replay read/validation → application → golden
read/comparison. A bad campaign beats a missing replay. An invalid action beats
a missing golden. Pin these in tests rather than leaving ordering accidental.

Replay metadata remains descriptive, as in T009a: do not equate campaign_id
to a path, compare it to a slug, enforce engine/version equality, or silently
select a campaign from it. Explicit `--campaign` supplies the actual content;
the resolved content enters sim state and is covered by the golden. No package
fetching or separately selected ruleset directory: the supplied campaign
already contains its ruleset, ability, and table documents.

## Private combat adapter

Add `mod combat_apply;` and private entry point:

```rust
pub(crate) fn combat_intents(loaded: crpg_data::LoadedCampaign)
    -> crpg_testkit::ApplyInput;
```

An owned `move` closure satisfies ApplyInput's existing implicit `'static`
lifetime. Own the loaded documents, an initially empty
`BTreeMap<Ulid, EntityId>`, and an initialized flag. Use a private adapter
method to make focused unit testing possible. Do not add observation handles,
World snapshots, trace logs, or printing to the production callback.

Consume T016c's version-1 payload contract exactly:

```json
{"combat":1,"op":"init","encounter":"<encounter ULID>"}
{"combat":1,"op":"attack","actor":"<placement ULID>","ability":"<ability ULID>","target":"<placement ULID>"}
```

First failure wins, in this order:

1. Non-object: `malformed combat payload: expected object`.
2. Missing/noninteger/wrong `combat` (require `as_u64() == Some(1)`):
   `unsupported combat payload version`.
3. Missing/nonstring/unknown op: `unknown combat op`.
4. Unknown fields: lexically smallest extra key gives
   `malformed combat {op}: unknown field {field}`.
5. Required ULIDs: encounter for init; actor, ability, target for attack, in
   that order. Missing/nonstring gives
   `malformed combat {op}: {field} must be a ULID string`; invalid parsing gives
   `malformed combat {op}: invalid {field}`. Use core FromStr, retaining its
   aliases/case acceptance, and canonical Display for diagnostic IDs.
6. Duplicate init: `duplicate combat init`; attack before successful init:
   `combat not initialized`.
7. Missing encounter document: `unknown encounter {id}`. For attack, resolve
   actor before target from the bound placement map, with
   `unknown combat identity {role}: {id}`. Ability is passed to sim, not
   pre-rejected ahead of sim's action validation.
8. Sim errors: `init failed: {CombatError Display}` or
   `attack failed: {CombatError Display}`. Do not recode or reorder them.

The generic replay harness wraps these reasons as ApplyFailed with the actual
tick and input index; the CLI does not manufacture that context.

### Initialization and action binding

- Find the named `Document::Encounter` in loaded documents, then its ruleset.
  Build transient borrowed BTreeMaps of abilities, outcome tables, placements
  with each owning `Placements.area`, and creature prefabs. The T016c worked
  example includes all loaded documents in these maps; follow that shape.
- Assemble the exact borrowed EncounterSpec and call `start_encounter` on the
  World provided by the callback. Do not initialize a second world, tick it,
  generate IDs, or add extra spawn events.
- Build a temporary placement-to-runtime map from `world.combatants()` and
  assert binding against encounter participant order and the selected ability
  exactly as the T016c example does. Publish the map/initialized flag only on
  success. Preserve its `init failed: missing ...` and binding-mismatch reasons
  for defensive failures. No unchecked indexing, unwrap on user content, or
  reliance on hard-coded arena indices.
- For attack, call `perform_action` with CombatAction::UseAbility and discard
  the returned ActionOutcome with `.map(|_| ())`. The controller owns cost,
  RNG, outcome, damage, death, and turn advance. No World mutation occurs in
  CLI code beyond the two public sim calls.
- The callback does not require a particular winner or check final health.
  T016c owns the independent terminal oracle; the CLI verifies the complete
  same-run hash sequence against that reviewed artifact.

Testkit's support module is a worked example, not an importable runtime API.
Do not `include!` it, expose it through testkit, or copy fixture-only checks
(14 files, 11 IDs, fixed package names, canonical source parity, attributes,
seed, or winner) into CLI production code. Decode/bind glue is caller-owned;
combat and replay semantics remain shared through sim and testkit respectively.
