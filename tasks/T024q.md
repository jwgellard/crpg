# T024q — snapshot-transfer channel on the lane stream (`crpg-net-quic`)

Status: **proposed, awaits the user's approval.**

## Task / Crate(s) / Purpose

Sole crate: `crpg-net-quic`. This is the transport follow-on to the approved
T024 contract ([T024](T024.md), D35; [ADR-0028](../docs/adr/0028-snapshot-transfer-subprotocol.md)),

## S§1. Findings (from the code)

1. One ALPN exists, `ALPN_LANE0_V1 = b"crpg-lane0/1"`
   (`src/handshake.rs:11-12`), and both TLS configs advertise only it
   (`src/tls.rs:81`, `:122`). The server re-checks it after TLS
   (`alpn_matches`, `src/server.rs:685-690`); a failure ends the handshake
   through `end_handshake`, which increments `refused_handshakes` with no
   event (`src/server.rs:674-683`, `:728-732`).
2. **An existing test pins `crpg-lane0/2` as foreign.**
   `foreign_alpn_refused` (`tests/quic.rs:692-708`) connects to a server
   built by `bind_server(ServerLimits::v1())` (that is, `QuicServer::bind`)
   offering `b"crpg-lane0/2"` and asserts the handshake fails and is
   counted. If `QuicServer::bind` began accepting `/2`, that test would fail.
   So `bind` must stay `/1`-only, and dual-ALPN must be opt-in (S§4).
3. Framing is a 4-byte big-endian `u32` length (`FRAME_HEADER_BYTES = 4`,
   `src/handshake.rs:16`; `frame_header`/`parse_frame_header`, `:36-60`).
   The direction caps are 4,096 bytes client → server and 65,536 bytes
   server → client, so **the top byte of every valid `/1` header is 0**. A
   `/1` header whose top byte is not 0 declares at least 16,777,216 bytes and
   closes with `FrameTooLarge` (3) before any body read
   (`src/queue.rs:608-625`).
4. The header width is load-bearing: outbound byte accounting subtracts
   `FRAME_HEADER_BYTES` from each queued frame (`src/queue.rs:366-374`), and
   the window floors are `cap + FRAME_HEADER_BYTES` (4,100 / 65,540) with
   compile-time checks (`src/limits.rs:43-49`), which the T023c stall
   formula (crate `AGENTS.md`, "Known traps") also assumes.
5. Queues are one per connection per direction (`Conn.inbound`/`outbound`,
   `src/queue.rs:122-160`), bounded in frames and bytes, accounted in
   payload bytes, and delivered in `try_send` order. A single queue across
   channels is therefore what keeps one total order (T024 S§10.7, S§11
   item 3).
6. **`crpg-server` matches `SendError` and `ServerError` exhaustively**
   (`crates/crpg-server/src/quic.rs:869-893` and `:720-760`, `:655-672`).
   A new variant on either enum would break `crpg-server`'s build, which
   would make this a two-crate task. New failures need a new error type
   (S§6).
7. `tests/quic.rs:271` builds a `ServerEvent::HelloReceived { .. }` literal,
   so adding a field to that variant would break an existing test. The
   negotiated framing is exposed by an accessor instead (S§7).
8. The T024 transfer frames fit the existing caps: the largest downstream
   frame is 32,815 bytes and the largest upstream frame 30 bytes (T024
   S§1.3). `MAX_DOWN_FRAME_BYTES == MAX_DELTA_FRAME_BYTES` and
   `MAX_UP_FRAME_BYTES == MAX_INTENT_FRAME_BYTES`
   (`crates/crpg-net/src/protocol_transfer.rs:46-48`).
9. Close codes are 0–9 (`src/close.rs:10-70`). No new code is needed.
10. At this tip `tests/quic.rs` has 32 `#[test]` functions (the AGENTS.md
    DoD line still says 30) and `tests/quic_gaps.rs` has 7. Both stay
    byte-identical.

## S§2. Decisions this contract makes

1. **A new ALPN `crpg-lane0/2`, opt-in on the server.** `QuicServer::bind`
   is unchanged (`/1` only). A new `QuicServer::bind_dual` advertises
   `[crpg-lane0/2, crpg-lane0/1]`. A client offers **exactly one** ALPN,
   chosen by the caller (`QuicClient::connect` = `/1`, unchanged;
   `QuicClient::connect_framed(.., Framing::V2)` = `/2` only). There is no
   fallback, so a `/2` request never ends up as a `/1` connection (S§4).
2. **The channel selector is the first byte of the 4-byte header under
   `/2`.** The header becomes `[channel: u8][length: u24 big-endian]`.
   Channel `0x00` is lane 0 and `0x81` is the transfer subprotocol. A
   lane-0 frame therefore has **the same bytes under `/1` and `/2`**, the
   header stays 4 bytes, and every window floor, accounting rule and stall
   formula is unchanged (S§5).
3. **One stream, one queue per direction, shared by both channels.** The
   order of `try_send_channel` calls is the order of arrival, across
   channels (S§8).
4. **Purely additive API.** No existing signature, variant, field, cap,
   close code or `Display` text changes. New: `ALPN_LANE0_V2`, `Framing`,
   `Channel`, two header functions, `FrameError::UnknownChannel`,
   `ChannelSendError`, and six methods (S§7).
5. **The crate stays policy-free.** It never decodes a payload, never
   looks at a payload byte to choose a channel, and never mints or checks a
   transfer id. A selector byte outside `{0x00, 0x81}` closes the
   connection with `ProtocolViolation` (2).

## S§4. ALPN and negotiation

### S§4.1 Constants and configs

- `pub const ALPN_LANE0_V2: &[u8] = b"crpg-lane0/2";` beside
  `ALPN_LANE0_V1`, which is unchanged.
- `QuicServer::bind(config)`: TLS `alpn_protocols = [crpg-lane0/1]`, and
  `alpn_matches` accepts only `/1`. **Byte-for-byte today's behaviour.**
- `QuicServer::bind_dual(config)`: the same `ServerConfig` validation and
  `BindError`s in the same order as `bind`, then TLS
  `alpn_protocols = [crpg-lane0/2, crpg-lane0/1]` in that order (rustls
  picks the first entry of the server's list that the client offered), and
  `alpn_matches` accepts `/1` or `/2`.
- `QuicClient::connect(config, server, hello)` is exactly
  `connect_framed(config, server, hello, Framing::V1)`, and offers only
  `/1` as today.
- `QuicClient::connect_framed(.., Framing::V2)` offers only `/2`.
- Hello, welcome, TLS profile (TLS 1.3, ring, no 0-RTT, no resumption, no
  client certificate, SNI `crpg.invalid`), stream mapping (one bidi, zero
  uni, no DATAGRAM), limits and windows are the same under both ALPNs.

### S§4.2 The negotiation matrix (no silent downgrade)

| Client offers | `bind` server (`/1`) | `bind_dual` server (`/2`, `/1`) |
|---|---|---|
| `/1` (`connect`) | `/1`, as today | `/1`; `framing(conn) == V1` |
| `/2` (`connect_framed` V2) | TLS fails: client `ConnectError::Handshake`; server `refused_handshakes += 1`, no event | `/2`; `framing(conn) == V2` |
| anything else (raw client) | TLS fails, counted (today's `foreign_alpn_refused`) | TLS fails, counted |

The server records the negotiated ALPN on the connection record when the
record is created (`src/server.rs:739-742`) and never changes it. The
client's `framing()` is the framing it asked for, because it offered no
other.

### S§4.3 Client check under `/2`

After TLS completes in `connect_framed(.., V2)`, the client reads the
negotiated protocol from `handshake_data()`. If it is not exactly
`Some(b"crpg-lane0/2")`, the client closes with `ProtocolViolation` (2)
and `connect_framed` returns `Err(ConnectError::Handshake)`. The `/1` path
gets no new check (it stays byte-identical). This case cannot be produced
by this crate's servers, so it has no test; the pinned dispatch is the
evidence, as for the crate's other unreachable branches.

## S§5. Framing under `crpg-lane0/2`

### S§5.1 Header layout

| Bytes | `/1` (unchanged) | `/2` |
|---|---|---|
| 0 | length bits 31–24 (always 0 for a valid frame) | channel selector |
| 1–3 | length bits 23–0 | length bits 23–0 |

Under `/2` the length is `u32::from_be_bytes([0, h[1], h[2], h[3]])`,
at most 16,777,215, and counts payload bytes only (the selector is part of
the header). The hello and the welcome are read and written by today's
`/1` code on both ALPNs: a hello header whose first byte is not 0 is over
the 130-byte hello cap and closes with `FrameTooLarge` (3), as today.
The channel byte applies only to lane frames after the welcome.

### S§5.2 Channel values

| Value | Channel | Payload | Codec the caller picks |
|---|---|---|---|
| `0x00` | `Channel::Lane0` | lane-0 intents/deltas | `crpg_net::codec` or `codec_v2`, as the hello's wire version already fixes for the connection |
| `0x81` | `Channel::Transfer` | snapshot-transfer frames | `crpg_net::codec_transfer` (`TRANSFER_VERSION = 0x81`) |
| any other | — | — | none: the reader closes with `ProtocolViolation` (2) |

- The lane-0 wire version is per connection (the hello), so there is one
  lane-0 channel, not one per version. A frame cannot claim a version the
  hello did not select.
- `0x81` equals `TRANSFER_VERSION`, so each channel value names exactly
  one codec. A later transfer version (`0x82`, T024 S§5.4) or any other
  subprotocol needs its own channel value, which is a framing change and
  therefore a new ALPN (ADR-0025 item 2). No value is reserved here.
- The values are an explicit header field. Nothing reads the payload to
  choose, which is the T024 S§4 rule.

### S§5.3 Caps

| Channel | client → server (server reader cap) | server → client (client reader cap) |
|---|---|---|
| `Lane0` | 4,096 (`MAX_INTENT_FRAME_BYTES`) | 65,536 (`MAX_DELTA_FRAME_BYTES`) |
| `Transfer` | 4,096 (`MAX_UP_FRAME_BYTES`) | 65,536 (`MAX_DOWN_FRAME_BYTES`) |

The two channels have the same cap in each direction, so the reader checks
one cap per direction. No new cap or limit is added. The largest transfer
frames (32,815 down, 30 up) are well inside.

### S§5.4 Header functions and their precedence

`channel_frame_header(channel, len, cap)`:

1. `len == 0` → `Err(FrameError::Empty)`;
2. `len > cap` or `len > 0x00FF_FFFF` → `Err(FrameError::TooLarge)`;
3. otherwise `Ok([channel.as_u8(), len bits 23–16, 15–8, 7–0])`.

So `channel_frame_header(Channel::Lane0, n, cap) == frame_header(n, cap)`
for every `n` in `1..=cap` with `cap ≤ 16,777,215`.

`parse_channel_frame_header(header, cap)`, checked in this order:

1. `Channel::from_u8(header[0])` is `None` → `Err(FrameError::UnknownChannel)`;
2. the 24-bit length is 0 → `Err(FrameError::Empty)`;
3. the length is above `cap` → `Err(FrameError::TooLarge)`;
4. otherwise `Ok((channel, len))`.

The channel is checked first, so `[0x05, 0xFF, 0xFF, 0xFF]` is
`UnknownChannel` (close code 2), not `TooLarge` (3). On `/1` the same
header is `TooLarge` (3).

Compile-time checks in `handshake.rs`:

```rust
const _: () = assert!(Channel::Transfer as u8 == crpg_net::protocol_transfer::TRANSFER_VERSION);
const _: () = assert!(crpg_net::protocol_transfer::MAX_DOWN_FRAME_BYTES == crpg_net::protocol::MAX_DELTA_FRAME_BYTES);
const _: () = assert!(crpg_net::protocol_transfer::MAX_UP_FRAME_BYTES == crpg_net::protocol::MAX_INTENT_FRAME_BYTES);
const _: () = assert!(crpg_net::protocol::MAX_DELTA_FRAME_BYTES <= 0x00FF_FFFF);
```

### S§5.5 Literal header bytes

| Call | Result |
|---|---|
| `channel_frame_header(Lane0, 3, 4_096)` | `[00 00 00 03]` (= `frame_header(3, 4_096)`) |
| `channel_frame_header(Lane0, 65_536, 65_536)` | `[00 01 00 00]` |
| `channel_frame_header(Transfer, 30, 4_096)` | `[81 00 00 1E]` |
| `channel_frame_header(Transfer, 32_815, 65_536)` | `[81 00 80 2F]` |
| `channel_frame_header(Transfer, 65_536, 65_536)` | `[81 01 00 00]` |
| `channel_frame_header(Lane0, 16_777_215, usize::MAX)` | `[00 FF FF FF]` |
| `channel_frame_header(Lane0, 16_777_216, usize::MAX)` | `Err(TooLarge)` |
| `channel_frame_header(Transfer, 0, 4_096)` / `(Transfer, 4_097, 4_096)` | `Err(Empty)` / `Err(TooLarge)` |
| `parse_channel_frame_header([81 00 00 1E], 4_096)` | `Ok((Transfer, 30))` |
| `parse_channel_frame_header([00 00 00 03], 4_096)` | `Ok((Lane0, 3))` |
| `parse_channel_frame_header([81 01 00 00], 65_536)` / `([81 01 00 01], 65_536)` | `Ok((Transfer, 65_536))` / `Err(TooLarge)` |
| `parse_channel_frame_header(h, 4_096)` for `h[0]` in `{01, 02, 80, 82, FF}`, `h = [x 00 00 01]` | `Err(UnknownChannel)` |
| `parse_channel_frame_header([05 00 00 00], _)` / `([05 FF FF FF], _)` | `Err(UnknownChannel)` |
| `parse_channel_frame_header([00 00 00 00], _)` / `([81 00 00 00], _)` | `Err(Empty)` |
| `parse_channel_frame_header([00 00 10 01], 4_096)` / `([81 00 10 01], 4_096)` | `Err(TooLarge)` |

## S§6. Errors and the close map

### S§6.1 Error types

- `FrameError` gains `UnknownChannel`, `Display` `UnknownChannel at
  quic/frame`. `frame_header` and `parse_frame_header` never return it.
  The existing variants and texts are unchanged.
- New `ChannelSendError`, returned only by the two `try_send_channel`
  methods:
  - `ChannelUnavailable`: `Channel::Transfer` on a connection that
    negotiated `/1`;
  - `Send(SendError)`: the same refusal `try_send` would give, unchanged.
  - `Display`: `ChannelUnavailable at quic/channel`, `Send at
    quic/channel`. `std::error::Error`, no source.
- `SendError`, `ServerError`, `ConnectError`, `CloseReason`, `CloseCode`
  are unchanged (S§1 item 6).

### S§6.2 Send precedence (no close is sent)

- `QuicServer::try_send_channel(conn, channel, frame)`:
  `Send(UnknownConnection)` → `Send(NotAccepted)` → `Send(Closed(_))` →
  `ChannelUnavailable` → `Send(EmptyFrame)` → `Send(FrameTooLarge)`
  (above 65,536) → `Send(QueueFull)` (retryable; nothing queued).
- `QuicClient::try_send_channel(channel, frame)`: `Send(Closed(_))` →
  `ChannelUnavailable` → `Send(EmptyFrame)` → `Send(FrameTooLarge)`
  (above 4,096) → `Send(QueueFull)`.

### S§6.3 Receive-side close map

Applied through `local_close` (record first, then quinn's close,
first-wins; `src/queue.rs:639-647`).

| What the reader sees on a lane stream | `/1` connection | `/2` connection |
|---|---|---|
| header byte 0 not in `{0x00, 0x81}` | `FrameTooLarge` (3) | `ProtocolViolation` (2), no body read |
| channel known, length 0 | (n/a: `[00 00 00 00]` is 2) | `ProtocolViolation` (2) |
| length above the direction cap | `FrameTooLarge` (3) | `FrameTooLarge` (3), no body read |
| FIN inside a header or body, `RESET_STREAM`, `STOP_SENDING` | `ProtocolViolation` (2) | `ProtocolViolation` (2) (unchanged) |
| FIN exactly at a frame boundary | clean end | clean end (unchanged) |

ALPN failures stay pre-hello: no event, `refused_handshakes += 1` on the
server, `ConnectError::Handshake` on a `QuicClient`. Idle timeout,
transport errors, resets and I/O-thread failure keep their `CloseReason`
mapping. No close code is added; peer codes outside 0..=9 stay raw.

## S§7. Interface (exact public Rust, additive)

```rust
// handshake.rs
/// ALPN identifier: lane framing version 2 (byte 0 of each lane-frame
/// header is a channel selector). Hello/welcome layout as version 1.
pub const ALPN_LANE0_V2: &[u8] = b"crpg-lane0/2";

/// The lane framing a connection negotiated by ALPN; fixed for its life.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Framing {
    /// `crpg-lane0/1`: 4-byte length header, lane 0 only.
    V1,
    /// `crpg-lane0/2`: `[channel][24-bit length]` header, lane 0 and transfer.
    V2,
}
impl Framing {
    /// `ALPN_LANE0_V1` or `ALPN_LANE0_V2`.
    pub fn alpn(self) -> &'static [u8];
    /// Exact match against the two ALPNs, else `None`.
    pub fn from_alpn(alpn: &[u8]) -> Option<Framing>;
}

/// A `crpg-lane0/2` lane channel. The value is the header's first byte.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
#[repr(u8)]
pub enum Channel {
    /// Lane-0 intents and deltas (wire version fixed by the hello).
    Lane0 = 0x00,
    /// Snapshot-transfer frames (`crpg_net::codec_transfer`, version 0x81).
    Transfer = 0x81,
}
impl Channel {
    pub fn as_u8(self) -> u8;
    /// `Some` only for 0x00 and 0x81.
    pub fn from_u8(raw: u8) -> Option<Channel>;
}

pub enum FrameError { Empty, TooLarge, /* new: */ UnknownChannel }

/// S§5.4.
pub fn channel_frame_header(channel: Channel, len: usize, cap: usize)
    -> Result<[u8; FRAME_HEADER_BYTES], FrameError>;
/// S§5.4.
pub fn parse_channel_frame_header(header: [u8; FRAME_HEADER_BYTES], cap: usize)
    -> Result<(Channel, usize), FrameError>;

// close.rs
/// Why `try_send_channel` queued nothing.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ChannelSendError {
    /// `Channel::Transfer` on a `crpg-lane0/1` connection.
    ChannelUnavailable,
    /// The `try_send` refusal for the same frame.
    Send(SendError),
}

// server.rs
impl QuicServer {
    /// As `bind`, but advertising `[crpg-lane0/2, crpg-lane0/1]`.
    pub fn bind_dual(config: ServerConfig) -> Result<QuicServer, BindError>;
    /// The connection's negotiated framing. Error: `UnknownConnection`
    /// (the same visibility rule as `stats`: hello stage and forgotten
    /// records are unknown).
    pub fn framing(&self, conn: ConnectionId) -> Result<Framing, ServerError>;
    /// S§6.2.
    pub fn try_send_channel(&mut self, conn: ConnectionId, channel: Channel, frame: &[u8])
        -> Result<(), ChannelSendError>;
    /// As `try_recv` (same precedence), with the frame's channel. On a
    /// `/1` connection every frame is `Channel::Lane0`.
    pub fn try_recv_channel(&mut self, conn: ConnectionId)
        -> Result<Option<(Channel, Vec<u8>)>, ServerError>;
}

// client.rs
impl QuicClient {
    /// `connect` with an explicit framing; offers exactly `framing.alpn()`.
    pub fn connect_framed(config: ClientConfig, server: SocketAddr, hello: &Hello,
        framing: Framing) -> Result<QuicClient, ConnectError>;
    /// The framing this client asked for and negotiated.
    pub fn framing(&self) -> Framing;
    /// S§6.2.
    pub fn try_send_channel(&mut self, channel: Channel, frame: &[u8])
        -> Result<(), ChannelSendError>;
    /// As `try_recv`, with the frame's channel.
    pub fn try_recv_channel(&mut self) -> Result<Option<(Channel, Vec<u8>)>, CloseReason>;
}
```

## S§8. Behaviour

### S§8.1 Ordering and queues

- Per connection there is still one outbound queue and one inbound queue.
  Frames on both channels share them, and their frame/byte caps, per
  connection and host-wide. So, within a connection and a direction,
  frames arrive exactly once and in `try_send`/`try_send_channel` call
  order **across channels**. That is the single total order T024 S§11
  item 3 needs.
- `QueueFull` is retryable and changes nothing, whichever channel the frame
  is on. A transfer burst applies backpressure to lane-0 frames behind it
  and the reverse. This is intended: separate queues could let a delta
  overtake a `Begin`.
- A full inbound queue parks one complete frame (its channel included) and
  stops reading, as today. Frames received before a close stay drainable,
  with their channels, before `Closed` is published (invariant 7).
- `ConnectionStats` and `QueueTotals` count payload bytes and frames on
  both framings, as today. The selector byte is header, not payload.

### S§8.2 Reading and writing

- On a `/1` connection the reader and writer are today's code paths. Every
  inbound frame is tagged `Channel::Lane0`; every outbound frame is a
  lane-0 frame, so its header equals `frame_header`.
- On a `/2` connection, after the welcome, the reader uses
  `parse_channel_frame_header` with the direction cap (server 4,096,
  client 65,536) and maps `UnknownChannel` and `Empty` to
  `ProtocolViolation`, `TooLarge` to `FrameTooLarge` (S§6.3). The writer
  frames with `channel_frame_header`. The body is allocated only after the
  header is accepted.

### S§8.3 Legacy entry points on a `/2` connection

`try_send`, `try_recv`, `ServerLane` and the `Transport` impls stay lane-0
views, so a lane-0-only caller can never see or send transfer bytes:

- `try_send(frame)` is `try_send_channel(Lane0, frame)`, with
  `Send(e)` returned as `e` (`ChannelUnavailable` cannot occur for
  `Lane0`).
- `try_recv()`: if the head inbound frame is on `Lane0`, it is popped and
  returned as today. If it is on `Transfer`, `try_recv` returns `Ok(None)`
  and leaves it queued; only `try_recv_channel` can take it. While such a
  frame is at the head, `try_recv` never reports `Closed`, and `wait`
  still returns `true`, because a frame is queued. Callers on `/2` use the
  `_channel` methods (T024h2 does).
- On a `/1` connection the legacy methods behave exactly as today.

### S§8.4 What the crate never does

It never decodes a payload, never infers a channel from payload bytes,
never mints, checks or tracks a transfer id, cursor or epoch, and never
sends `Published`, `Resync` or `Cancel`. Those belong to `crpg-net`
(T024) and `crpg-server` (T024h).

## S§9. What T024h2 does with this (the adapter boundary)

`QuicHost` lives in `crpg-server`, so this task does not change it. The
routing rules below are inputs to [T024h2](T024h.md), and the two
contracts state them the same way:

1. The operator binds the server with `bind_dual` to accept `/2` peers.
   `QuicHost::start` takes any bound `QuicServer`, so `bind` keeps working.
2. On `HelloReceived`, the adapter reads `framing(conn)`. A `V2` connection
   is bound as a snapshot session, a `V1` connection as today.
3. Drain uses `try_recv_channel`. `Lane0` frames go to `Host::ingest` with
   today's one-frame hold. `Transfer` frames go to `Host::ingest_transfer`.
   A held lane-0 frame stops the drain, so a transfer frame behind it waits
   in this crate's queue and the order holds.
4. Deliver sends each host delivery entry with `try_send_channel`, on
   `Lane0` for a delta and `Transfer` for a transfer frame, in host order,
   on the one shared queue. The one-frame hold, the slow-consumer fence and
   every close path stay per connection.
5. A `/1` connection's narrowing still fences: it has no transfer channel.

## S§15. Open questions for the user (each with a recommendation)

1. **Opt-in dual ALPN.** Keep `QuicServer::bind` `/1`-only and add
   `bind_dual` for `[/2, /1]`; clients offer exactly one ALPN. Making
   `bind` itself dual would break `foreign_alpn_refused`
   (`tests/quic.rs:692-708`), an existing test, and a dual-offer client
   would make the framing a run-time branch with a downgrade path.
   *Recommendation:* approve as written.
2. **Selector placement and values.** The `/2` header's first byte is the
   channel (`0x00` lane 0, `0x81` transfer) and the length is 24-bit. The
   drafts proposed a 5-byte header (Beam) or a selector inside the payload
   length (Muse), both with values `0x01`/`0x02`/`0x81`. A 5-byte header
   changes `FRAME_HEADER_BYTES`, the window floors and the stall formula;
   a selector counted in the length makes a 65,536-byte delta unsendable
   under `/2`. Separate `0x01`/`0x02` values duplicate the hello's version
   and allow a mismatch. *Recommendation:* approve as written.
3. **Additive errors.** Add `ChannelSendError` and
   `FrameError::UnknownChannel`; add no variant to `SendError` or
   `ServerError`, because `crpg-server` matches both exhaustively
   (S§1 item 6). Both drafts added one, which would make this a two-crate
   task. *Recommendation:* approve.
4. **ADR.** The crate's AGENTS.md requires an ADR for a new ALPN, wire
   byte and public items. File a new ADR (the next free number, 0030 at
   this tip), "Lane framing `crpg-lane0/2`: channel selector", Accepted
   with this approval and filed by the implementation, linking S§4–S§6 as
   authoritative; plus a signed one-line "see ADR-0030 for `/2`" addendum
   in ADR-0025. *Recommendation:* approve. The alternative, an ADR-0025
   addendum only, would mix two ALPNs' decisions in one record.
