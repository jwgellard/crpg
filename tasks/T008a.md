## Task
Give `crpg-sim` its measurement instrument and its loop: `state_hash`, the
fixed-step `tick` with a hand-written ordered system list, and the `Timeline`
advance policy for both play modes. `crpg-sim`-only single-crate task (the
E004 split; the harness half is T008b).

## Crate(s)
`crpg-sim` (only).

## Purpose
Everything behavioural the project will ever test — replays, golden files,
balance sweeps, the "did my change alter the game" bisect — rests on one
claim: same binary + same inputs ⇒ same hash sequence. This task builds the
instrument that makes the claim checkable (`state_hash`), the loop the claim
is about (`tick`), and the turn-order advance rules both play modes share.
T007 built the data; this task builds the first motion.

## Interface

```rust
// crates/crpg-sim/src/hash.rs
/// BLAKE3 over the world's canonical JSON bytes. Queue bytes included
/// (ADR-0008); exclusions documented below, currently none.
pub fn state_hash(world: &World) -> [u8; 32];

// crates/crpg-sim/src/tick.rs
/// One fixed simulation step: tick counter +1 (saturating), then the ordered
/// system list below. The list is the whole point of the function — its order
/// is a rules-visible decision (spec §10), so it lives here, handwritten, not
/// in a scheduler.
pub fn tick(world: &mut World);

/// Turn-based advance primitive: pops and returns the head of the timeline
/// in ascending (key, id) order. Re-queueing the acted entity is the future
/// combat system's job, not this function's — popping without re-queueing is
/// the defined semantic, and ending a turn on an empty timeline returns None.
pub fn end_turn(world: &mut World) -> Option<(InitiativeKey, EntityId)>;

fn run_systems(world: &mut World);     // today: exactly [timeline_system]
fn timeline_system(world: &mut World); // real-time policy step (see Behaviour)
```

`world.rs` gains one method, same crate, no contract break:

```rust
impl World {
    /// Advances the tick counter by one, saturating at u64::MAX. Crate-visible
    /// only: the tick loop calls it; no outer code sets time, so there is
    /// deliberately no public setter (see the T007 trap, which stands).
    pub(crate) fn advance_tick(&mut self);
}
```

## Behaviour
- `state_hash` serializes the world to canonical JSON bytes and returns
  their BLAKE3 digest. Canonical today means: struct fields in declaration
  order, pair-lists in iteration order (store) or canonical order
  (timeline), `BTreeMap`/`BTreeSet` internals in key order — i.e. exactly
  what the T007 serde impls already produce. No second canonicalizer; if a
  future format needs one, that format's task builds it against this
  function's tests.
- **Hash exclusions: there are none, and that is a deliberate list, not an
  omission.** Tick and queue bytes hash (proven by test, not by assertion).
  Adding an exclusion later requires a test proving the excluded field
  cannot affect behaviour — excluded-but-influential state is how golden
  tests go blind.
- `state_hash` on non-finite floats: `serde_json` refuses NaN/infinity, and
  `.expect()` on that failure is correct, not lazy. No sim API can produce a
  non-finite `f32` (no division, no parsing, no FFI input), so a NaN in world
  state means memory corruption or bridge abuse, and panicking is the honest
  response. Say so in the doc comment; do not add a float-scrubbing pass.
- `tick` does exactly two things, in this order: `advance_tick`, then
  `run_systems`. The order is the contract — counter before systems, so a
  system observing `world.tick()` sees the tick it runs under.
- `run_systems` is the hand-written ordered list from spec §10. Today it
  holds one entry, `timeline_system`; later systems append with their tasks,
  each below a comment naming its spec §10 stage. Never a scheduler, never
  parallelism inside one area's tick (spec §2.4 rule 1).
- `timeline_system` is the real-time policy: the standing queue is processed
  in order every tick, and standing order is preserved (no reorder, no
  rekey). The per-entry dispatch loop is already here — it applies no effect
  yet, and its body says which task plugs the first effect in — so the shape
  future systems inherit is the shape tested today. Net observable effect of
  a no-input tick: counter +1, everything else bit-identical (asserted).
- `end_turn` is the turn-based policy primitive. It pops the head; it does
  not re-queue, advance the counter, or run systems. Who calls it (combat
  loop, AI turn start) is T016-era design, not this task.
- Overflow arms are unreachable-by-construction and documented, not tested:
  the tick counter saturates (2^64 ticks is not a workload) exactly as the
  event `seq` counter does (T007 precedent). There is deliberately no public
  setter to make the saturation testable — testability does not outrank the
  no-setter invariant.

## Constraints
- Add `blake3 = "1"` as a **workspace** dependency (root `Cargo.toml`) and
  take it in `crpg-sim` as a normal dependency. This is the one new
  dependency the task authorises — it is what "the blake3 choice lands in
  the task file" (PROJECT_STATE) means. Safe under policy: zero transitive
  dependencies (no `multiple-versions` risk), crates.io-only, and
  `CC0-1.0 OR Apache-2.0` passes the license gate through the Apache-2.0
  alternative (CC0 alone is not in the allow list; dual-license OR means the
  allowed alternative governs). If `cargo deny` disagrees, stop and say so —
  do not widen `deny.toml` (that is an ADR, per the file itself).
- `Cargo.lock` will change; commit it. Verify `--locked` passes after.
- No other new dependency. `serde_json` is already a dev-dependency; the
  hash uses it as a *normal* dependency — promote it (move, not duplicate)
  rather than adding a second serialization path. `serde_json` is already in
  the lockfile and the license set, so promotion is mechanical.
- `#![forbid(unsafe_code)]` and `#![warn(missing_docs)]` stay. No
  `HashMap`/`HashSet`, no `f64`, no clock, no threads, no I/O — the hash and
  the loop are pure functions of the world.
- This task does not write the E011 ADR. It assumes the spec's stated scope
  (replay determinism mandatory per spec :201, cross-platform lockstep
  explicitly out) inline where the tests need it; E011 ratifies separately.
- Amending `world.rs` (`advance_tick`) is same-crate extension, allowed —
  later tasks extend the crate rather than starting new ones.

## Test
Extend `crates/crpg-sim/tests/` (new `tick.rs` file, or extend `world.rs` —
agent's call; one file per concern is the house style).

1. **Hash-sequence identity (10,000 ticks).** Two worlds, same seed, same
   scripted op sequence (spawns, transform writes, timeline inserts, RNG
   draws, interleaved `tick` calls): identical `Vec<[u8; 32]>` of per-tick
   hashes. This is spec §24 T8's test, and it is the backbone assertion of
   the whole project — write it first.
2. **Seed sensitivity.** Different seeds ⇒ different sequences (fixed seed
   pair plus a property over seed pairs with `assume` on inequality).
3. **Queue and tick are hashed.** Draining the queue changes the hash;
   ticking changes the hash; two worlds differing only in drained-vs-queued
   events hash differently. (This is the exclusion-list-being-empty test.)
4. **Counter and order.** N ticks advance the counter by exactly N; no-input
   ticks preserve queue and timeline bytes (hash equality modulo the
   counter is *not* asserted — instead assert the drained queue and timeline
   iteration are unchanged, since the counter legitimately moves the hash).
5. **Advance policies.** Real-time: scrambled-insert timeline iterates
   ascending before and after ticks. `end_turn`: pops ascending `(key, id)`
   with id tiebreak; empty timeline returns `None`; popped entities stay
   live (popping schedules, it does not despawn — assert both).
6. **Trivial-system machinery.** The ordered list contains exactly the
   documented stages; a comment names the spec §10 stage each future entry
   belongs to. Tested by inspection plus test 4 — no mock-system theatrics.

Command that must pass: `cargo test -p crpg-sim`

## Out of scope
- T008b's harness, golden files, replay format. Consumes `state_hash`, does
  not define it.
- Any system beyond `timeline_system`. Movement, timers, effects, AI, event
  graphs, perception, deltas, autosave — each arrives with its task, in spec
  §10 order, appended to `run_systems` with its stage comment.
- Re-queueing after `end_turn`, combat turn structure, AI turn-start hooks.
  T016-era design; `end_turn` pops and stops, deliberately.
- `crpgc run --ticks/--hash-every`. T013 (transferred per E004).
- The E011 ADR itself. Assumed here, ratified there.
- Perf work on hashing (incremental hashing, cached digests, hashing
  subsets). Correct and whole-world first; E019 owns measurability.
- A canonicalizer beyond what the T007 serde impls produce. If JSON bytes
  ever stop being canonical, that task proves it with a failing test first.
