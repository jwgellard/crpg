## Decisions (binding for this contract)

1. **Reuse the landed APIs unchanged.** Content loads through production
   `load_campaign`; gameplay goes only through `start_encounter` /
   `perform_action`; observation uses shared `&World` reads plus read-only
   snapshots and detached clones. If a required observation is impossible
   through that surface, stop into a finding instead of adding a seam.
2. **Accepted-only replay inputs.** A rejected input aborts playback
   (`ApplyFailed`), so the checked-in replay contains accepted inputs only
   (`init`, `attack`, `end`). Rejections (the probed rejected pool spend,
   out-of-turn/dead `EndTurn`) are covered by direct-adapter tests with
   full-world snapshot rollback, exactly like T016c's rejection suite.
3. **Seed pinned by ascending probe, never hand-picked.** Probe seeds
    `0..=1023` ascending through the public sim API with a temporary
    deleted-before-finish helper; the first seed satisfying all §Behavior
    conditions under the fixed schedule below pins `SEED`, its terminal
    prefix, and the trace. If no seed
    satisfies them, stop and report rather than changing content. The helper
    is deleted before finish; the schedule, selection predicates, selected
    seed, and rejection reason for each earlier seed remain reproducible in
    the completion record. Tests consume the pinned seed, not a fresh search.
4. **Goldens generated independently per native target, never copied.**
   Each scoped golden comes from `read_replay` → `play_replay` →
   `write_golden` on its genuine native target through a temporary
   deleted-before-finish helper, reviewed before acceptance and read-only
   afterwards. Missing baselines fail (`Io(NotFound)`), mismatches fail;
   no tolerance, no skips, no cross-target comparison (ADR-0012
   exact-build scope).
5. **No new dependencies, no ADR, no downstream authorization.** This task
    follows the T016c tests-only precedent: fixtures, goldens, and
    tests-only adapters need no ADR and no dependency change. B5 still needs
    its own contract; nothing here grants it.
6. **Observe behavior, not an invented breakdown.** B3's `ActionOutcome`
   exposes raw dice, margin, outcome, and damage, not the kernel's modifier
   breakdown or modified total. B4 proves modifier application and expiry
   through those observable results and public attachment state. It must not
   reconstruct a breakdown and label it an observed sim result. Actual
   contribution-breakdown inspection remains an explicit sim-owned follow-up
   if required by the milestone; B4 does not claim that coverage or authorize
   a new sim observation API.

## Interface (exact shapes)

All helpers are tests-only (never `src/`, never exported). Content
identities are T017a's final map: campaign 31, world 32, area 33,
placements 34/35, creatures 36/37, ruleset 38, abilities 39 (first,
ending, target-defense) / 40 (second, non-ending, self effect), tables
41/42, effect 43, encounter 44, pools 46 (primary, max 1, `on_turn_start`) /
47 (max 2, `on_round_start`), effect modifiers 48/49. Initiatives `[10, 9]`.

```rust
pub const SRD_CAMPAIGN_ID: &str = "combat-srd";
pub const SRD_CAMPAIGN_VERSION: &str = "0.1.0";
pub const SRD_ENGINE_VERSION: &str = "0.1.0";

pub fn srd_root() -> PathBuf;          // campaigns/fixtures/combat_srd/
pub fn srd_ruleset_root() -> PathBuf;  // rulesets/srd-lite/
pub fn srd_replay_path() -> PathBuf;   // fixtures/combat_srd.replay
#[cfg(all(target_os = "windows", target_arch = "x86_64", target_env = "msvc", debug_assertions))]
pub fn srd_target_golden_path() -> PathBuf; // goldens/srd_lite_rust-1.98.0_x86_64-pc-windows-msvc_test-default.golden
#[cfg(all(target_os = "linux", target_arch = "x86_64", target_env = "gnu", debug_assertions))]
pub fn srd_target_golden_path() -> PathBuf; // goldens/srd_lite_rust-1.98.0_x86_64-unknown-linux-gnu_test-default.golden
```

Payload grammar (versioned `{"combat": 1}`, strict unknown-field rejection,
T016c §Payload check order extended with one op):

```text
init:   {"combat": 1, "op": "init", "encounter": <ULID>}
attack: {"combat": 1, "op": "attack", "actor": <ULID>, "ability": <ULID>, "target": <ULID>}
end:    {"combat": 1, "op": "end", "actor": <ULID>}
```

`attack` decodes placement ULIDs (canonical `Display`, core alias
acceptance) and calls `CombatAction::UseAbility`, unwrapping the `Some`
outcome (`None` is impossible for this op; a `None` is an adapter error,
never silent). `end` calls `CombatAction::EndTurn{actor}`, requires
`Ok(None)`, and records an input-transition observation (not an attack
trace). Validation order for
`end`: turn-holding only (`NoEncounter`, participant/absence/death,
`OutOfTurn` in existing order; no ability/target/cost checks), mirroring
the controller. Anything else is `unknown combat op`; malformed version,
fields, or identities fail exactly like T016c.

Observed attack trace (one entry per accepted `attack`, never an instruction
or a container for test-computed expected values):

```rust
pub struct SrdTraceEntry {
    pub tick: u64,
    pub actor: Ulid,         // authored placement
    pub target: Ulid,        // authored placement
    pub ability: Ulid,       // 39 or 40
    pub faces: Vec<u32>,     // raw draws in draw order
    pub total: i32,          // kept sum plus offset
    pub margin: i64,         // actual sim margin, compared to independent arithmetic
    pub outcome: Outcome,    // table decision incl. natural shift
    pub damage: u32,         // {failure 0, success 3, critical 5}, else 0
    pub target_died: bool,
    pub target_health: u32,
    pub active: Option<Ulid>, // post-action turn holder; None after terminal action
}

pub struct ParticipantObservation {
    pub placement: Ulid,
    pub health: u32,
    pub dead: bool,
    pub pools: Vec<(Ulid, u32)>, // template-id sorted, both 46 and 47
    pub attached: Vec<(Ulid, u32)>, // effect-id sorted (effect, expires_round)
}

pub struct SrdStateObservation {
    pub round: Option<u32>, // None only before init in this replay
    pub active: Option<Ulid>,
    pub participants: Vec<ParticipantObservation>, // placement-id sorted
}

pub struct InputObservation {
    pub tick: u64,          // scheduled zero-based replay tick
    pub input_index: usize,
    pub before: SrdStateObservation,
    pub after: SrdStateObservation,
    pub before_bytes: Vec<u8>, // full World, before input (before tick)
    pub after_bytes: Vec<u8>,  // full World, after input (still before tick)
    pub attack: Option<SrdTraceEntry>, // None for init/end, Some for attack
}
```

`Observations` holds input observations for **every** successful `init`,
`attack`, and `end`, plus a detached `last_world` after the latest input.
All observations are read-only and never feed authoritative mutations. Resolve
runtime IDs to placements from World; an unknown ID is an observation failure,
never a fabricated identity. Terminal `active` must be `None`, not the winner
or a sentinel. Snapshot phase is always after input and **before** `tick`.

Expected arithmetic is separate: use literal authored values, pinned raw faces,
and independently tracked expected attachment/round state to compute modified
total, defense, margin, band, natural shift, damage, balances, and lifetimes.
Assert raw faces/total against a reviewed literal trace first; compare actual
margin/outcome/damage to the arithmetic. Never use actual outcomes, actual
attachment membership, `resolve`, or `OutcomeTable::evaluate` to manufacture
expected outcomes. Expected participant state must not be copied from actual
snapshots. A recomputed `+3` explains the expected margin; it is not an observed
breakdown. Pin modifiers 48/49 and their authored values/order separately.

## Behavior

- **Content loading (production path only):** `read_tree` over
  `campaigns/fixtures/combat_srd/` (sorted traversal, `.gitattributes`
  skipped) expects 17 files; `load_campaign` with engine `0.1.0`;
  `validate` yields `[]`; the index holds exactly the 14 T017a identities
  with kinds/paths/pointers; the six campaign combat documents (ruleset 38,
  abilities 39/40, tables 41/42, effect 43) equal the six canonical
  `rulesets/srd-lite/` parses byte-identically (same ULIDs, asserted, never
  hand-diverged).
- **Seed probe:** use the fixed schedule and acceptance predicates below.
  Hand arithmetic follows the checked-in content (e.g. `2d6 [3,2] = 5`
  vs `ward 5` → margin 0 → success → 3 damage; with E1, `5 + 2 + 1 = 8`
  vs 5 → margin 3 → critical → 5 damage; `2d6 [6,1] = 7` vs `ward 7`
  → margin 0 → success, die 0 shows 6 → shift `+1` → critical → 5 damage).
  Focus uses the actor's `might`: goblin 6, hero 8. Its first successful
  use attaches E1 only after resolution, so that roll does not receive its
  newly attached bonus; a subsequent use while attached does. Reapplication
  refreshes the same effect's expiry rather than creating a second `+3`.
- **Replay artifact:** `fixtures/combat_srd.replay` is pretty JSON plus
  trailing newline with the pinned `SEED`, campaign/envelope versions
  above, `TOTAL_TICKS`, and the accepted-only inputs in tick order. A
  structural test pins the file equals the in-memory construction
  (`combat_replay()`-style), so the artifact can never drift from the
  schedule the suite reasons about.
- **Golden generation (per native target):** `read_replay` →
  `play_replay` → `write_golden` with a temporary deleted-before-finish
  helper. Linux GUI is not involved (headless only). After generation the
  helper is gone and the goldens are read-only inputs to
  `play_and_verify`.
- **Mid-replay save/load continuation:** use the exact post-tick-4
  checkpoint and suffix procedure below. Assert the bonus affects tick 5,
  attachment expires on tick 6's round rollover, and tick 7 receives no
  bonus. Invalid saves are not part of this suite (B3 owns load coherence).
- **Terminal/trailing/death:** exactly one dead combatant at the end with
  positive-health survivors; `T = 4` trailing ticks run no inputs and change
  only through `tick`; death notification appears exactly once; trailing
  attacks fail without mutation (dead-target reads, never writes).
- **Neutrality:** no production code is added here, so there is nothing to
  scan; the adapter holds content ULIDs and hand arithmetic only as test
  data, never as engine branches. `combat_basic` replay, goldens, and
  suites pass unmodified.

### Fixed seed-search schedule and acceptance

Let G = placement 35 (goblin, initiative 9) and H = placement 34 (hero,
initiative 10). Use exactly one accepted input at each occupied tick. Tick 0
is init of encounter 44. The candidate action schedule is:

| Tick | Actor | Input | Target |
|---|---|---|---|
| 1 | G | attack, focus 40 | G |
| 2 | G | attack, focus 40 | G |
| 3 | G | attack, heavy 39 | H |
| 4 | H | end | — |
| 5 | G | attack, heavy 39 | H |
| 6 | H | end | — |
| 7, 9, 11 | G | attack, heavy 39 | H |
| 8, 10, 12 | H | attack, heavy 39 | G |

For each seed `0..=1023`, initialize a fresh world through the production
adapter. Apply the scheduled input, then `tick`, in harness order. Stop at
the first terminal action; do not change targets, use health-dependent
tactics, add inputs, change content, or select dice. A rejected scheduled
input disqualifies the seed. `K` is that terminal action's tick, also the
number of accepted non-init inputs because there is exactly one per tick.
Require `7 <= K <= 12`. No later candidate inputs enter the artifact.
Append exactly four input-free ticks `K+1..=K+4`, yielding
`TOTAL_TICKS = K + 1 + 4`. Feasibility is an implementation authoring check,
not a claim made by this specification; no qualifying seed means stop and
report before authoring any golden.

Reject a seed unless all of the following hold under independent oracles:

- At least one heavy has final `Failure` and one has final `Success`.
- At least one heavy rolls 6 on selected raw die 0 and the authored shift
  **changes** the pre-natural outcome. A clamped shift at an already-critical
  band does not qualify.
- G's first focus succeeds in round 0, attaching effect 43 with expiry 2.
  Tick 2 spends the second focus point whether its roll succeeds or fails;
  any reapplication still leaves exactly one attachment expiring at 2.
- Tick 4 ends H's turn and rolls to round 1 with both participants alive;
  G retains the attachment and gets the authored round/turn pool refreshes.
- Tick 5 resolves with G's expected `+3` bonus. Both participants remain alive
  through tick 6, whose explicit end reaches round 2, removes the attachment,
  and refreshes the declared pools. Tick 7 is an accepted, post-expiry heavy
  with no bonus. Assert its independently expected margin even if its outcome
  coincides with what a stale bonus would produce.
- Immediately after tick 2's input, **before** that tick's advance, make a
  detached World clone and reconstruct an initialized adapter's bindings from
  its combatants. Attempt a third G focus at the same tick on this clone.
  It must report insufficiency for pool 47 (balance 0, cost 1), preserving
  full World bytes and adapter bindings. It must not create or advance any
  RNG stream. This probe is not a replay input and cannot affect the candidate.
- The terminal prefix produces exactly one death; its survivor has positive
  health and `active == None`. No further death or gameplay change occurs
  during the four trailing ticks.

Freeze the smallest qualifying seed, literal input prefix, expected raw faces,
and independent per-input expected state before golden generation. Record why
each lower seed fails a predicate (compact grouped ranges are acceptable).
Run ordinary tests using these frozen artifacts; never regenerate expected
values from a fresh run or silently choose a new seed after a regression.

### Exact continuation and observation phases

Run the entire frozen replay through `play_replay` to obtain reference hashes
`H[0..TOTAL_TICKS)`. `H[t]` is the hash **after** input at scheduled tick `t`
and its following `tick`, when `World.tick() == t + 1`.

For the checkpoint, run the same replay prefix through `play_replay` with
`total_ticks = 5` and inputs at ticks `0..=4`. Require its five hashes to
equal `H[0..5]`. The observer's detached `last_world` is from immediately
after the tick-4 `end` input and **before** the harness tick; it has
`World.tick() == 4`. Advance this detached clone exactly once with `tick`.
Now require tick 5, round 1, active G, effect 43 on G expiring at round 2,
and `state_hash == H[4]`. Serialize this post-tick checkpoint and deserialize
it into the resumed World. Require immediate byte and hash equality.

Continue two detached worlds: the checkpoint without serialization, and its
deserialized copy. Reconstruct each tests-only adapter's placement mapping
from `World.combatants()` and the loaded encounter; validate identity coverage
and set its initialized state without calling `start_encounter` or replaying
`init`. These are bindings only, never edits to World or replay semantics.

For `t = 5..TOTAL_TICKS`, apply the frozen input for `t` if present through
the same adapter, call `tick` once, and require both hashes equal `H[t]`.
Compare both worlds' observations to the independent oracle too, including
ticks 5/6/7 (bonus, expiry, no bonus), terminal state, and trailing ticks.
This explicit continuation driver exists only in this test to exercise a
loaded World; it is not a new replay engine/API or a golden-generation path.

Every input observation remains pre-tick. In particular, an `end` must return
`Ok(None)` and preserve RNG bytes, but can legitimately refresh balances,
advance round/turn, and expire effects. Assert those changes against the
expected transition instead of requiring an unchanged World. Rejected inputs
must preserve the entire World and adapter binding state.

For terminal-suffix inspection, the full-run observer's `last_world` is the
detached post-input/pre-tick World at tick K, not the final replay World.
Advance that clone `1 + T` times, matching hashes `H[K..TOTAL_TICKS)` in
order. Observe queued death events only through detached clones; draining
the authoritative replay World would change the hashed state.
