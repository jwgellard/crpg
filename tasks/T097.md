# T097 — `HistoryWorld` mutation cost (`crpg-sim`)

## Task / Crate(s) / Purpose
Make `HistoryWorld` mutations cost O(new envelopes + world clone) instead of
O(retained journal), without changing what they do. Sole crate: `crpg-sim`
(`src/history.rs`, a new test module `src/history/tests.rs`, one
`#[cfg(test)]` line in `src/lib.rs`, and its two docs). **Not S-set**: the
`World` struct and tick order are untouched (`docs/IMPLEMENTATION_PLAN.md`
§1.4). Status: **contract draft, awaiting H approval.**

## Findings (measured, then confirmed by reading)
`T097-MEASURE.md` (OpenCode worker, run T097-m attempt 2). Machine: Windows
x86_64, pinned 1.98.0, warm target dir, `--test-threads=1`, median of 200
iterations, `Instant` ns; journal = unacknowledged pending envelopes, filled
with spawn+despawn pairs.

| ents | journal | dbg tick | dbg clone | dbg perform_action | rel tick | rel clone |
|---|---|---|---|---|---|---|
| 1000 | 0 | 25.9 µs | 25.4 µs | 103.2 µs | 1.6 µs | 1.5 µs |
| 1000 | 1024 | 8.47 ms | 69.6 µs | 5.24 ms | 312.2 µs | 10.7 µs |
| 1000 | 3500 | 28.96 ms | 274.1 µs | 28.97 ms | 633.1 µs | 27.6 µs |
| 10 | 3500 | 28.79 ms | 248.3 µs | 28.88 ms | 635.4 µs | 27.5 µs |

Debug spawn+despawn at 1000/3500 is 58.34 ms (≈ 2 × tick).
`capacity_failure_rolls_back_rng`: 179.66 s debug on that machine.

**Root cause.** `finish` (`src/history.rs:605`), called by every operation
including zero-event `tick`, re-derives the retained byte total by
re-encoding *every* retained envelope: the loop at `src/history.rs:630–638`
calls `envelope_len` (`:761–765`), a heap-allocating `serde_json::to_vec`, per
pending envelope per mutation. The full clone (`:362, 384, 405, 427, 463,
494`) is secondary. The numbers are consistent with this. Debug cost per
retained envelope, (tick − tick at j=0) / j, is 8.0–8.3 µs in four cells
and ≈ 5.0–5.1 µs in two ((100, 3500) and (10, 1024)). That spread is
unexplained noise, but every cell grows with the journal and not with
entities. spawn+despawn (two `finish` calls) is 2.01 × tick at (1000, 3500).
The three capacity fills make ≈ 3 × 4096²/2 = 25.2 M encodings, which
predicts 126–209 s against 179.66 s measured; the clone at those sizes adds
only ≈ 2–3 s.
The check is redundant on every reachable state: append and load both keep the
total ≤ `MAX_HISTORY_BYTES` (`:1432–1442`). No further measurement is needed.

## Decision
- **D1. Cached byte total.** A private `Journal` holds the envelopes and their
  derived canonical byte total. The byte check starts from the cache and
  encodes only the new envelopes. `acknowledge` subtracts the drained prefix.
  T020 already says the count is "derived, not persisted" (`tasks/T020.md:266`).
- **D2. Stage only the `World`.** Operations clone `self.world`. The journal is
  validated against the live wrapper and appended only after every check
  passes. T020 allows a "wrapper/World clone" (`tasks/T020.md:198`), so no
  ADR or T020 change is needed.
- **Rejected:** a `World` undo log (option 1, S-set). After D1 and D2 the
  remaining cost is the world clone: 25.4 µs debug and 1.5 µs release at 1000
  entities, about 0.01% of a 60 Hz frame in release. That is not worth S-set
  risk now. **Rejected:** pre-flight checks (option 3). D1 already makes a
  full-journal `EventLimit` free of encoding.
- **Trade-off.** D1 adds a side value that could drift from the envelopes.
  The crpg-sim AGENTS "untested side table" trap applies, so B7 and T2–T3
  check it after every step. D2 depends on `commit` being the only journal
  writer before validation ends; T5 proves it.

## What must not change
- The T020 contract and ADR-0017: every mutation is transactional. A rejected
  operation (`EventLimit`, or any other error) leaves the wrapper
  byte-identical, including entity allocation, RNG streams and the pending
  journal. The existing tests assert this through full snapshots and
  `history_hash`.
- Emitted events, their order, sequence numbers, the full-wrapper hash, and
  every replay golden. A golden that moves is a stop, not a re-bless.
- The public API, unless the contract says otherwise. (It does not: every
  signature, serialization byte and `Debug` string stays as it is.)
- No existing test in `crates/crpg-sim/tests/history.rs` (or anywhere) is
  weakened, shortened or moved to a slower lane to make this pass.

## Interface (all private; no public change)
```rust
/// The retained journal plus its derived canonical byte total (T097).
#[derive(Clone, PartialEq, Eq)]
struct Journal {
    envelopes: Vec<HistoryEnvelope>,
    bytes: usize, // == Σ envelope_len over envelopes; never serialized
}
impl Journal {
    fn new() -> Self;                                         // empty, bytes 0
    fn from_loaded(envelopes: Vec<HistoryEnvelope>, bytes: usize) -> Self;
    fn as_slice(&self) -> &[HistoryEnvelope];
    fn len(&self) -> usize;
    fn bytes(&self) -> usize;
    fn append(&mut self, envelopes: Vec<HistoryEnvelope>, total: usize);
        // `total` is the new FULL byte total after the append, not a delta;
        // sets `bytes = total`; debug_assert!(total >= self.bytes).
    fn drain_prefix(&mut self, count: usize);
}
impl fmt::Debug for Journal   // fmt::Debug::fmt(&self.envelopes, f)
impl Serialize for Journal    // self.envelopes.serialize(serializer)
// HistoryWorld keeps field name and position: `pending: Journal`.
fn commit(&mut self, world: World, events: Vec<HistoryEvent>, tick: Tick)
    -> Result<(), HistoryError>;                // replaces `finish`
#[cfg(test)] thread_local! { static ENCODINGS: Cell<u64> = const { Cell::new(0) }; }
```
`src/lib.rs` gains `#[cfg(test)] extern crate self as crpg_sim;`, so the unit
module can include `tests/support/mod.rs` with `#[path]`. There is precedent:
`tests/history_golden.rs:19`.

## Behaviour
1. **J1 invariant.** At every public boundary, `pending.bytes` equals the sum
   of `envelope_len` over `pending.envelopes`, and is ≤ `MAX_HISTORY_BYTES`.
2. **Staging.** Each of `spawn`, `despawn`, `tick`, `start_encounter`,
   `perform_action` and `end_encounter` replaces `let mut staged =
   self.clone()` with `let mut world = self.world.clone()`. It runs the same
   controller calls, drain and translation on `world`, in the same order. It
   then calls `self.commit(world, events, tick)?` in place of
   `staged.finish(..)?; *self = staged`. Gameplay errors return before
   `commit`, as today.
3. **`commit` checks**, in the pinned order: strings, then sequence range,
   then event count, then bytes. Each check fails with the same error as
   today. The byte stage starts at `self.pending.bytes()`, not a rescan, then
   adds `envelope_len` of each new envelope with the same `checked_add` and
   `> MAX_HISTORY_BYTES` tests.
4. **`commit` writes nothing before every check passes.** Then, in this order:
   `self.world = world`, `self.pending.append(envelopes, bytes)`,
   `self.next_seq = end`. On `Err`, `self` is untouched.
5. **`envelope_len` calls.** `commit` calls it exactly once per new envelope
   and never on retained ones. Zero-event operations never call it.
6. **`acknowledge`.** If `count == len`: clear the journal and set
   `bytes = 0`, with no encoding. Otherwise subtract `envelope_len` of each
   drained envelope (exactly `count` encodings), then drain. Errors and the
   no-op cases stay as today.
7. **`pending_bytes()`** returns `self.pending.bytes()`, which is O(1). Its doc
   comment says so. `pending_len` and `read_after` read through `as_slice`.
8. **Load.** `PendingSeqVisitor` returns `Journal::from_loaded(out, bytes)`
   with the `bytes` it already computes. Its encoding code, error text and
   order stay as they are. `validate_journal` takes `pending.as_slice()`.
9. **Test counter.** `ENCODINGS` exists only under `#[cfg(test)]`. It is
   bumped inside `envelope_len`, and the loader's inline encode is not
   counted. It must be spelled `thread_local!`, never `std::thread_local!`.
   It is a per-test-thread counter, not a thread.
10. `area.rs`, `history_hash`, every serde impl other than the pending seed,
    and the module docs' bounded-parsing text stay unchanged. The module doc
    at `history.rs:7–9` changes to "stages a clone of the world … validates
    the journal additions against the live wrapper".

## Tests (`src/history/tests.rs`, `#[cfg(test)] mod tests;`)
The oracle is the master `07b3e77` bodies of the six operations,
`acknowledge` and `finish` (`history.rs:361–509, 585–658`), copied as free
functions in `mod reference` that take `&mut HistoryWorld`. Exactly these
substitutions are allowed, nothing else:
- `for envelope in &self.pending` becomes `… in self.pending.as_slice()`.
- `self.pending.extend(envelopes)` becomes
  `self.pending.append(envelopes, bytes)`. Here `bytes` is the oracle's own
  running total: its rescan of the retained envelopes plus the new ones. So
  the oracle sets the cache from a full rescan.
- `self.pending.drain(..drop)` becomes `self.pending.drain_prefix(drop)`.
  The oracle's ack cache therefore comes from new code; J1 rescans check it.

The oracle keeps its full wrapper clone and its rescan. Fixtures come from
`#[path = "../../tests/support/mod.rs"] #[allow(dead_code)] mod support;`.

- **T1. Existing tests.** `tests/history.rs`, `tests/history_golden.rs` and
  every other `crates/crpg-sim/tests/*` file are byte-unchanged and pass.
- **T2. Differential, free play.** proptest, 64 cases, ≤ 48 operations per
  case.
  - Starting state: either `new(seed)`, or a JSON-loaded wrapper with
    `acknowledged = u64::MAX − 4` and `next_seq = u64::MAX − 3`.
  - Operations: Spawn; Despawn of a live id or of an already-despawned id;
    Tick; StartEncounter with `Fixture::standard()`; UseAbility and EndTurn
    with actor and target drawn from live ids; EndEncounter;
    Ack(`acknowledged + k`) with `k` in `0..=pending_len + 1`; RoundTrip
    (each side reloads from its own bytes).
  - Each operation is applied to an oracle twin and a new-path twin. After
    every operation: the results are equal (`Ok` and `Err` alike); the
    `serde_json::to_vec` bytes are equal; `history_hash` is equal; J1 holds
    on both twins.
- **T3. Differential at the cap.** One base, built once by the new path: the
  standard encounter, then spawns until `pending_len() == 4096`, and J1
  checked. proptest, 8 cases. Each case clones the base, acks `k` in `0..=4`,
  then runs ≤ 6 operations from the T2 alphabet. Bytes and hash are compared
  after every step, and J1 is checked at the end of the case. Random cases
  are not required to reach any particular error.
- **T3d. Directed cap cases, oracle vs new.** Bytes and hash are compared
  after each case.
  - (a) Spawn at 4096 pending → `EventLimit`.
  - (b) The active actor's UseAbility at 4096 → `EventLimit`.
  - (c) EndEncounter, ack to 4095, then StartEncounter → `EventLimit`.
  - (d) Order of checks: rewrite the cap base's JSON so `acknowledged =
    u64::MAX − 4097`, the seqs run up to `u64::MAX − 1`, and `next_seq =
    u64::MAX`. Spawn → `SequenceExhausted`, not `EventLimit`.
  - (e) The same with every number one lower (`next_seq = u64::MAX − 1`).
    Spawn → `EventLimit`.

  T1 (`tests/history.rs:418–470`) already covers (a)–(c) on the new path
  alone.
- **T4. Encoding counts (the CI regression guard; no wall clock).**
  `ENCODINGS` deltas on 4095- and 4096-envelope journals: accepted spawn 1;
  `tick`,
  `end_encounter`, absent `despawn`, `EventLimit` spawn at 4096,
  `acknowledge(last_sequence())` and `pending_bytes()` 0 each;
  `acknowledge(acknowledged + 3)` on a non-emptying journal 3; building the
  base by 4096 spawns 4096 in total. Accepted `perform_action` emits 2–3
  envelopes, so it runs at two other sizes: the T2 standard encounter right
  after start, and the cap base acked down to 4090 pending. Each time its
  delta equals its `pending_len()` delta.
  **Limit:** `ENCODINGS` only sees `envelope_len`. T8 closes the gap of a
  direct re-encode.
- **T8. Encoding sites (a source guard, deterministic).**
  `include_str!("../history.rs")` must contain exactly 3 occurrences of
  `serde_json::to_`: in `envelope_len`, `history_hash` and
  `PendingSeqVisitor`. Any new encode site fails this test until the test
  and the contract change together.
- **T5. The journal is not copied.** `tick`, `end_encounter`, absent
  `despawn`, and every `Err` return in T4 leave
  `pending.as_slice().as_ptr()` and `envelopes.capacity()` unchanged.
- **T6. `ByteLimit` rolls back.** Set the private `bytes` to
  `MAX_HISTORY_BYTES − len(next Spawned) + 1`, a deliberately off-invariant
  state. `spawn` then returns `Err(ByteLimit)`. The world bytes, entity
  count, envelopes and cache are unchanged. With the present vocabulary this
  limit cannot be reached through valid states (`tasks/T020.md:267`).
- **T7.** `format!("{:?}", journal) == format!("{:?}", journal.envelopes)`.

## Open questions (each with a recommendation)
1. **Is the `#[cfg(test)]` `thread_local!` counter (B9) acceptable under
   crpg-sim AGENTS rule 8 ("no threads")?** It spawns nothing, and the lint
   pattern `std::thread` does not match it. Recommend yes. The alternative,
   a counter field on `Journal`, needs a hand-written `PartialEq` and differs
   between test and normal builds.
2. **Should the I package also move `transfer_history_entity` to world-only
   staging?** Recommend no: it is a rare operation and no longer encodes
   after D1. Raise it separately if it shows up in a profile.
