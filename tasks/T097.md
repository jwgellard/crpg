## Task
Make `HistoryWorld`'s transactional mutations cost less than a full copy of
the wrapper, without changing what they do.

Status: **contract needed.** Raised by the user on 2026-10-16 for the manager
to route; nothing here is a contract.

## Crate(s)
`crpg-sim` (`src/history.rs`). If the fix needs undo support inside `World`,
it is in the S-set (`docs/IMPLEMENTATION_PLAN.md` §1.4) and is serialized and
human-reviewed.

## Purpose
Every `HistoryWorld` mutation stages on a full clone and swaps it in on
success: `spawn` (`src/history.rs:361`), `despawn` (383), `tick` (403),
`start_encounter` (426), `perform_action` (459) and `end_encounter` (493) all
begin with `let mut staged = self.clone();`. `tick` is included, so a host
pays the copy on every fixed simulation step, not only on player actions. The clone
copies the whole `World` and the pending journal (up to `MAX_HISTORY_EVENTS`
= 4096 envelopes). So each mutation costs time proportional to the world plus
the journal, and filling the journal costs quadratic time.

Measured costs:
- **CI.** `crates/crpg-sim/tests/history.rs` took 104.6 s on Linux and
  138.4 s on Windows in PR #29's run (38875484668): more than half of all test
  runtime on both. Almost all of it is `capacity_failure_rolls_back_rng`,
  which fills the journal three times (about 12,000 mutations) in a debug
  build.
- **Runtime: not measured.** `crpg-server` drives authoritative play through
  `HistoryWorld` (`src/host.rs`, `src/capture.rs`, `src/checkpoint.rs`), so
  every tick and every accepted intent pays the copy. The contract should
  measure per-tick and per-action cost at representative world and journal
  sizes before choosing a design.

## What must not change
- The T020 contract and ADR-0017: every mutation is transactional. A rejected
  operation (`EventLimit`, or any other error) leaves the wrapper
  byte-identical, including entity allocation, RNG streams and the pending
  journal. The existing tests assert this through full snapshots and
  `history_hash`.
- Emitted events, their order, sequence numbers, the full-wrapper hash, and
  every replay golden. A golden that moves is a stop, not a re-bless.
- The public API, unless the contract says otherwise.
- No existing test in `crates/crpg-sim/tests/history.rs` (or anywhere) is
  weakened, shortened or moved to a slower lane to make this pass.

## Options for the contract to weigh (not decided)
1. An undo log: mutations write through and record inverse operations, and a
   failure replays them. Correct only if every piece of state has an inverse,
   RNG streams included, which probably means `World` support (S-set).
2. Copy-on-write staging inside `HistoryWorld`: stage only what an operation
   touches, and append the journal after success instead of cloning it. This
   stays outside `World` but may only halve the cost, since the world copy
   remains.
3. Pre-flight capacity checks so the common "journal full" rejection never
   stages. Cheap, but it covers only one failure path and leaves the copy on
   successful mutations.

## Routing (`docs/AGENT_TEAM_PLAN.md` §4)
- First of a kind, high cost of a subtle bug: the C package goes to the
  `architect` (Opus 5.5). If it touches `World`, it is S-set: implementation
  by the Claude `implementer` (Sonnet 5.5), serialized, Claude `reviewer`,
  plus a "two keys" test writer from another family.
- Suggested acceptance for the contract to make exact: the full
  `history.rs` suite unchanged and passing; a differential property test that
  runs random operation sequences through the old clone path and the new
  path and requires identical bytes and hashes after every step; and the
  capacity test well under 10 s in a debug build on Linux CI.
