## Task
Give `crpg-testkit` its first real code: the hash-sequence harness and the
golden-file convention every later behavioural task builds on. First task in
the crate, so it also writes `crpg-testkit/AGENTS.md` and
`docs/architecture/crpg-testkit.md`.

## Crate(s)
`crpg-testkit` (only).

## Purpose
T008a proved one world hashes deterministically; nobody can *use* that proof
yet. The replay task (T009), headless combat (T016) and every golden file
after them all need the same three operations — run a scripted scenario to a
hash sequence, write it down, compare against it later with a useful failure
— and copy-pasting those into every crate is how harnesses fork. This task
builds the operations once, behind an API whose misuse is a compile error
rather than a convention footnote.

## Interface

```rust
// crates/crpg-testkit/src/harness.rs
use crpg_sim::World;

/// A per-tick script step: mutate the world (spawn, write components,
/// schedule, draw RNG, tick is applied by the harness — see Behaviour).
pub type ScriptStep = Box<dyn FnMut(&mut World)>;

/// Runs `script` for `ticks` ticks from `seed`, hashing after every tick.
/// Returns the hash sequence. Fully deterministic for a fixed script.
pub fn run_hash_sequence(
    seed: u64,
    ticks: usize,
    script: ScriptStep,
) -> Vec<[u8; 32]>;

/// First-diverging-tick report. `Display` prints
/// `diverged at tick {tick}: expected {expected:hex}, got {actual:hex}`.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Mismatch {
    pub tick: usize,
    pub expected: [u8; 32],
    pub actual: [u8; 32],
}

/// Writes `hashes` as lowercase hex, one per line, under `#`-comment scope
/// header lines (see Behaviour). Creates parent directories.
pub fn write_golden(path: &std::path::Path, hashes: &[[u8; 32]]) -> std::io::Result<()>;

/// Reads a golden file and compares against `hashes`. `Ok(())` on full
/// match; `Err(Mismatch)` at the first diverging tick (including length
/// mismatch, reported at the shorter length). `#` lines are skipped, so
/// headers never compare.
pub fn verify_golden(
    path: &std::path::Path,
    hashes: &[[u8; 32]],
) -> Result<(), Mismatch>;
```

## Behaviour
- `run_hash_sequence` builds `World::new(seed)`, then per tick applies the
  script step and calls `tick` + `state_hash` — script first, tick second,
  hash last. That fixed interleaving is the convention: every consumer
  hashes the same way, so sequences are comparable across tasks. The harness
  never touches sim internals; everything goes through the public API
  (`spawn`, stores, `timeline_mut`, `rng_mut`, `tick`, `state_hash`). A
  harness that needs a private seam is proof the sim API is missing
  something — file it, do not reach around.
- Golden format, line by line: `# scope: {os}/{arch}` and
  `# generator: crpg-testkit` header lines the harness writes itself
  (`std::env::consts`), then one lowercase-hex hash per line, no trailing
  spaces, file ends with a newline. Hex is hand-rolled (a dozen lines), not
  a dependency — the `hex` crate is not worth a node in the graph for this.
- ADR-0009 scopes goldens by toolchain + platform + profile, but the
  toolchain and profile are not knowable to a library at runtime, so the
  harness owns format + compare while **scope discipline belongs to the CI
  job** (E020's sequencing): filenames carry the full scope, comparison runs
  on canonical Linux. The harness docs state this split explicitly so a
  future agent does not "fix" cross-platform mismatches inside the compare
  function. Tolerant comparison (fuzzy hashes, per-platform goldens chosen
  at runtime) is rejected: it would re-admit exactly the ambiguity ADR-0009
  removed.
- `verify_golden` distinguishes three outcomes without string matching:
  match, content divergence (`Mismatch`), and I/O failure. The exact error
  type is the implementer's call — either `Result<(), HarnessError>` with
  hand-rolled `io` vs `mismatch` variants, or `io::Result` layered under a
  separate compare step — with the constraints that both call sites stay
  single-pathed and no new dependency (`thiserror` included) is added for
  it. Document the choice in the module doc.
- No network, no clock, no threads, no randomness of its own. File I/O is
  confined to the two golden functions; everything else is pure.

## Constraints
- Normal dependencies: `crpg-sim` (path) only. That edge is a plain
  `testkit -> sim` normal dependency, which the ALLOWED table already
  permits — and it matches the *proposed* E005 one-way rule (testkit may
  reach sim; sim never reaches testkit), which this task follows without
  ratifying. No other dependency: hex is hand-rolled, errors are
  hand-rolled `Display`, temp files in tests use `std::env::temp_dir` with
  unique names plus cleanup, not the `tempfile` crate.
- `crpg-sim` must not change in this task. The done-when asserts it: if the
  harness needs a sim API that does not exist, the task stops and says so
  (that gap is a T008a-follow-up design question, not a drive-by edit).
  `git status -- crates/crpg-sim/` is empty at commit time — state that in
  the commit message.
- `#![forbid(unsafe_code)]` and `#![warn(missing_docs)]` stay (both already
  on the crate root). Every public item gets a doc comment (spec §15.6).
- `lib.rs` declares modules and re-exports the public surface. Keep it to
  `pub mod` / `pub use` and the crate doc comment — and trim the stale stub
  doc (fixture campaigns, replay runner, contract suites do not exist yet;
  claiming them is how docs drift).

## Test
New `crates/crpg-testkit/tests/harness.rs` (plus `src` unit tests where
natural). All tests self-contained; no proptest needed — these are
deterministic wiring tests, not distribution tests.

1. **Harness determinism.** Same seed + same script twice ⇒ identical
   sequences (guards the harness wiring, not the sim — the sim proved
   itself in T008a).
2. **Golden round-trip.** `write_golden` then `verify_golden` on a scripted
   10,000-tick run ⇒ `Ok`. This is spec §24 T8b's test.
3. **Tamper detection.** Flip one hex char / truncate a line / delete the
   file ⇒ `Err` naming the exact tick with expected-vs-actual (or the
   missing-file case, per the decided error shape). Header-only edits
   (reworded `#` lines) still verify — headers never compare.
4. **Script generality.** At least two shapes through one harness: a
   spawn-heavy script and a timeline/RNG-heavy script with despawns. Both
   verify end-to-end. (This is the T009/T016 reusability proof in miniature.)
5. **No-sim-changes.** No new assertion needed beyond the commit itself —
   but the commit message must confirm the empty sim diff (see Constraints).

Command that must pass: `cargo test -p crpg-testkit`
