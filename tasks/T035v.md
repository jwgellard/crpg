## Task
ADR-0036 V1 (`:348–352`) and acceptance note 1 (`:551–555`): `crpg-nav`
uses integers and `Fx16_16` only and no `HashMap`/`HashSet`, and the
determinism lint must enforce that. Today `tools/lint/determinism.py`
scans only `CRATES = ["crpg-core", "crpg-rules", "crpg-sim"]`
(`tools/lint/determinism.py:56`). This task adds `crpg-nav` with the full
float ban, and makes a missing linted crate a failure at a workspace root,
so the scope can never be dropped silently.

## Readings of the ADR
Where ADR-0036 leaves a detail open, this contract decides it. Each needs
the user's approval with the contract.
1. **Absence is a failure only at a workspace root.** A linted crate whose
   directory holds no `.rs` file is a `missing-crate` violation when the
   scanned root holds a `Cargo.toml` file, and is skipped otherwise. The
   repository root always has `Cargo.toml`, so deleting or renaming
   `crates/crpg-nav` (or core, rules, sim) fails CI. The self-test fixture
   roots have no `Cargo.toml`, so every existing one-crate test keeps
   working unchanged. `crates/crpg-nav/src/lib.rs` already exists as a stub
   with no code line (`crates/crpg-nav/src/lib.rs:1–4`), so CI stays green
   before and after T035.
2. **`crpg-nav` gets the full float ban** (`no-float`: `f32`, `f64` and
   float literals), the same scope as core and rules, not sim's `f64`-only
   rule. V1 says "integers and `Fx16_16` only" (`:348`). The `both` rules
   (`no-hashmap`, `no-hashset`, `no-wallclock`, `no-thread`,
   `no-external-rng`) apply to it as to every linted crate.

## Interface
```python
CRATES = ["crpg-core", "crpg-rules", "crpg-sim", "crpg-nav"]   # this order
# Crates under the full float ban (no-float-crates scope).
NO_FLOAT_CRATES = ("crpg-core", "crpg-rules", "crpg-nav")
```
`check_file(crate_name, path)` keeps its signature. Its scope selection
becomes: `crate_name in NO_FLOAT_CRATES` gives `("both",
"no-float-crates")`; `crate_name == "crpg-sim"` gives `("both",
"no-f64-crates")`; anything else gives `("both",)`.

`main(args)` keeps its signature, its output format
(`VIOLATION {path}:{lineno} {rule} {text}`) and its exit codes.

## Behaviour
1. **N1.** `CRATES` is exactly the four names above, in that order, and the
   lint scans every `.rs` file under each present crate exactly as today.
2. **N2.** In `crates/crpg-nav/`, `f32` and `f64` (as type, suffix or
   `to_f32`-style identifier), and unsuffixed float literals, are
   `no-float` violations. Doctest bodies are scanned and `text`/`ignore`
   fences are not, exactly as for core.
3. **N3.** In `crates/crpg-nav/`, every `both` rule applies.
4. **N4.** Before scanning, for each crate in `CRATES` order: the crate is
   *present* when `root/crates/<name>/` is a directory holding at least one
   `.rs` file at any depth (`rglob("*.rs")` non-empty). If it is not
   present and `root/Cargo.toml` is a file, the lint records one violation
   with path `root/crates/<name>`, line number `0`, rule `missing-crate`
   and text `linted crate has no Rust source`. If it is not present and
   `root/Cargo.toml` is not a file, the crate is skipped as today.
5. **N5.** Missing-crate violations print before file violations, in
   `CRATES` order. Any violation still gives exit code 1, and a clean run
   gives 0.
6. **N6.** Nothing else changes: rules, regexes, the escape marker, comment
   and string masking, doctest handling and the existing scopes for core,
   rules and sim.
7. **N7.** The module docstring lists `crpg-nav` with core and rules under
   "f32 / f64", names the four scanned crates, and states N4 in one
   paragraph.

## Tests
All in `tools/lint/test_determinism.py`, reusing `make_crate`, `run_lint`,
`rules_of` and the existing fixture strings. A *workspace root* is a
temporary root with `(root / "Cargo.toml").write_text("[workspace]\n")`.

**Class `TestNavScope(LintCase)`** (fixture roots, no `Cargo.toml`):
- **T-1 `test_nav_bans`.** `subTest` per row; each `lint_one("crpg-nav",
  src)` exits 1 and its rules include the named rule:
  `HASHMAP_SRC` `no-hashmap`; `HASHSET_SRC` `no-hashset`; `WALLCLOCK_SRC`
  `no-wallclock`; `THREAD_SRC` `no-thread`; `RNG_SRC` `no-external-rng`;
  `FLOAT_SRC` `no-float`; `FLOAT_SIM_F32_SRC` `no-float`;
  `FLOAT_LITERAL_SRC` `no-float`; `UNSUFFIXED_FLOAT_SRC` `no-float`;
  `DOCTEST_SRC` `no-hashmap` and `no-float`. *Fails if:* nav is unscanned,
  or gets sim's `f64`-only scope (the `f32` row passes).
- **T-2 `test_nav_clean_passes`.** `CLEAN_SRC`, `COMMENT_SRC`,
  `DOC_PROSE_SRC` and `DOCTEST_TEXT_FENCE_SRC` in `crpg-nav` each exit 0.
- **T-3 `test_nav_stub_passes`.** The stub's exact four lines
  (`#![forbid(unsafe_code)]`, `#![warn(missing_docs)]`, then the two `//!`
  lines of `crates/crpg-nav/src/lib.rs`, copied as a literal) exit 0.

**Class `TestCrateCoverage(LintCase)`**:
- **T-4 `test_workspace_with_all_crates_passes`.** Workspace root, all four
  crates with `CLEAN_SRC`: exit 0, no violation line.
- **T-5 `test_missing_crate_fails_at_workspace_root`.** `subTest` per
  crate: workspace root with the other three only. Exit 1; `rules ==
  ["missing-crate"]`; the single `VIOLATION` line contains
  `crates/<name>` (path separators normalised with `replace("\\", "/")`)
  and ends with `linted crate has no Rust source`.
- **T-6 `test_crate_without_sources_fails`.** Workspace root, all four
  crates present, but `crates/crpg-nav/` holds only `Cargo.toml`
  (`[package]\nname = "crpg-nav"\n`): exit 1, `rules == ["missing-crate"]`.
- **T-7 `test_fixture_root_still_skips_absent_crates`.** No `Cargo.toml`,
  only `crpg-core` with `CLEAN_SRC`: exit 0. *Control for N4's second
  branch; fails if* absence fails everywhere.
- **T-8 `test_missing_crate_reported_before_file_violations`.** Workspace
  root, `crpg-core` with `HASHMAP_SRC`, `crpg-rules` and `crpg-sim` clean,
  no `crpg-nav`: the first `VIOLATION` line's rule is `missing-crate`, a
  later one is `no-hashmap`.

**Class `TestScopeIsPinned(unittest.TestCase)`**:
- **T-9 `test_crates_list_is_exact`.** Load the module with
  `importlib.util.spec_from_file_location("determinism", SCRIPT)` and
  assert `module.CRATES == ["crpg-core", "crpg-rules", "crpg-sim",
  "crpg-nav"]` and `module.NO_FLOAT_CRATES == ("crpg-core", "crpg-rules",
  "crpg-nav")`. *Fails if:* a crate is dropped or nav's scope is weakened
  without editing this test.
- **T-10 `test_repository_passes`.** `run_lint(REPO)` with `REPO =
  HERE.parent.parent` exits 0 (the real tree, stub included).
