command: one object, its inbound references, and its outbound references.

## Interface

Add public module `introspection`, re-exporting this documented function at
the crate root using existing dependencies and types:

```rust
pub fn explain_object(
    campaign: &crate::LoadedCampaign,
    id: crpg_core::Ulid,
) -> Result<Option<Vec<u8>>, crate::DataError>;
```

`Some(bytes)` is a complete canonical JSON report with exactly one final LF.
`None` means a structurally acceptable campaign contains no object with that
identity. `Err` is an existing structural/serialization `DataError`; do not
add a diagnostic code or reinterpret semantic findings as structural errors.
Malformed CLI id text and the process treatment of `None` belong to T013.

Returning data-owned canonical bytes deliberately keeps object extraction,
reference selection, kind names, ordering, and report serialization out of
CLI. No public filesystem API, CLI dependency, or new generic graph API.
Existing public signatures and document schemas remain unchanged.

### Report shape

The report has exactly these members (JSON key order is canonical):

```text
{
  "id": <uppercase ULID string>,
  "kind": <object kind string>,
  "file": <logical SourcePath string>,
  "pointer": <RFC 6901 object pointer>,
  "object": <current serialized object JSON>,
  "inbound": [<reference occurrence>, ...],
  "outbound": [<reference occurrence>, ...]
}
```

Each reference occurrence has exactly:

```text
{
  "file": <logical source file>,
  "pointer": <RFC 6901 pointer to the reference value>,
  "source": <nearest enclosing authored object's uppercase id, or null>,
  "target": <authored target's uppercase id>,
  "target_location": null | {
    "kind": <object kind string>,
    "file": <logical target file>,
    "pointer": <RFC 6901 target object pointer>
  }
}
```

Kind spellings are `campaign`, `world`, `area`, `creature`, `item`,
`dialogue`, `quest`, `faction`, `placement`, `graph`, `node`,
`dialogue_node`, `quest_state`, corresponding one-to-one to `ObjectKind`.
All nullable members remain present. There is no report schema tag or new
persisted document family; this is a query result, not campaign source.

## Behaviour

### Structural boundary and object selection

Pure in-memory operation; no filesystem, environment, clock, or network use.
Do not mutate `campaign`, its documents, or its caller-mutable index.

Before lookup, establish the same structural acceptance boundary and error
precedence as `serialize_campaign`, using existing data-owned checks rather
than a second implementation. This includes layout, duplicate identities,
local lock validity, package coverage, and assets-lock digest. As with that
writer there is no engine-version check; the normal future CLI flow already
loads with its package engine version. Structural failure wins over unknown
id. Semantic errors do not prevent introspection of structurally valid input.

Rebuild authoritative object locations from documents, sharing the loader's
identity enumeration instead of trusting `campaign.index`. An empty, forged,
or stale index cannot change the result, hide duplicates, or redirect lookup.
Support every `ObjectKind`, including placements, aggregate-owned graphs,
graph nodes, dialogue nodes, and quest states.

The `object` value is the subtree at the rebuilt object pointer in the
document's current canonical serialization. Top-level entity objects retain
their schema envelope; nested objects retain their actual nested shape with
no invented schema tag. Preserve authored arrays and `_note`; normalize
identities exactly as the existing writer does. Do not return the enclosing
document in place of a requested nested object.

### Reference inventory and ownership

Collect typed authored ULID reference occurrences, including valid, dangling,
wrong-kind, and foreign-owner references. This is an inventory, not a repair
or second diagnostic pass. A target that exists has `target_location` even
if its kind or ownership is semantically wrong; only an absent identity has
`target_location: null`. No invented target, placeholder zero id, or omitted
bad edge. Existing validation remains the authority for why an edge is bad.

Coverage is every typed object-reference field in the current documents:

- Campaign entry world/area/spawn, world areas, area neighbours, creature
  faction/inventory, faction relations, and placement prefab.
- Dialogue entry, node speaker/next/jump/link targets; quest entry and state
  transition targets; graph start, edge from/to identities, sequence child
  node identities, and call-graph targets.
- Recursive `DataValue::ObjectRef` occurrences in variable defaults, action
  arguments, placement overrides, and asset import settings, including all
  nested lists/maps, graph branch cases and graph locals, and every existing
  graph/dialogue/quest argument site.
- Aggregate ownership fields: placements/triggers `area`, locale/variables
  `campaign`. They appear once as references even though validation reports
  ownership through its specialized check rather than generic `check_ref`.

Identity declarations (`id`), containment itself, package coordinates,
digests, asset paths, locale keys, tags, notes, opaque conditions, symbolic
action/variable/stat names, and ordinary strings are not object-reference
edges. Never scan arbitrary strings for ULID-looking text. Null optional
references contribute no occurrence. No transitive closure or synthetic
reverse/containment edge is introduced.

`source` names the nearest identified enclosing object. Thus a dialogue
node's `next` belongs to that node, a graph edge belongs to its graph, and a
quest state's transition belongs to that state. References outside any
identified object (aggregate owner fields, campaign variable aggregates,
asset import settings) have null source; do not attribute them to the target
owner merely because the aggregate names it.

`inbound` contains all occurrences whose target equals the queried id.
`outbound` contains all occurrences physically within the selected object's
subtree, including references in nested identified children. Match RFC 6901
pointer component boundaries, not textual prefixes (`/nodes/1` must not
include `/nodes/10`). Root objects include their whole document; an area
query does not absorb separate placements/triggers documents. Nested source
ids remain intact when a parent's outbound list includes their references.
A self-reference appears once in each applicable list.

Order each reference array by `(file, pointer, target)` using lexical logical
path/pointer text and ULID order; this is explicitly lexical pointer order,
not numerical array-index order. Keep distinct occurrences to the same
target, with their distinct pointers; do not deduplicate by target. Emit
each physical reference field only once per array. Use existing RFC 6901
escaping for `~` and `/`, including map keys and asset paths.

### One authority, preserved validation

Factor shared private occurrence/reference enumeration within `crpg-data`
where needed so introspection and validation cannot grow independent lists
of reference-bearing fields. Share typed traversal, identity locations, and
pointer construction; validation retains allowed-kind/ownership checks,
diagnostic messages, precedence, reachability, and sort policy. Sharing
enumeration must not convert aggregate ownership into duplicate diagnostics.

Do not derive the inventory from diagnostics or infer references from the
serialized JSON. JSON subtree extraction for the selected object is allowed;
the definition of an edge comes from typed data. Private visitors/sinks are
implementation choices, not new caller registration or public extension APIs.
All existing validation snapshots and loader/migration/writer tests must
remain unchanged and pass. If preserving them requires weakening a test,
stop and report instead.

Required assertions:

1. Complete exact canonical report bytes for independently authored small
   examples: top-level and nested object shapes, kind spellings, required
   null fields, final LF, and empty reference arrays.
2. Coverage of every `ObjectKind` and every reference-bearing family/site
   listed above, with explicit expected source and target locations. Include
   all dialogue variants, standalone and aggregate graphs, and nested tagged
   values in each argument/default/override/import context.
3. Valid incoming references are reported even when validation is clean;
   dangling references remain outbound with null target location; wrong-kind
   and foreign-owner edges retain their actual locations. Unknown query id
   returns `None`, including when some edge targets that absent id.
4. Duplicate-target occurrences, cycles/self-edges, graph edge endpoints,
   nullable fields, aggregate owners with null sources, and references from
   unidentified aggregates have the specified behavior. Parent subtree
   inclusion and `/nodes/1` versus `/nodes/10` are pinned independently.
5. Escaped map keys (`~`, `/`), authored array preservation, lexical pointer
   sorting, insertion-order independence, and repeated-call byte identity.
   ULID-looking strings in notes, text, conditions, and `DataValue::Text`
   are negative controls, never reference occurrences.
6. Forged/empty/stale public indexes produce identical reports; mutated
   documents with duplicate ids or structural layout/lock/digest failures
   return the same errors as the existing writer before lookup. Input maps
   and indexes remain unchanged on success, absence, and failure.
7. Existing `one_area_one_creature`, `broken_references`, and
   `migration_v1/campaign` fixtures are read-only inputs. Preserve the exact
   broken validation snapshot; introspection succeeds for existing objects
   despite semantic findings. Migration-aware loaded objects use current
   serialized shape without rewriting historical files.
8. Shared-enumeration coverage includes positive and negative assertions so
   removing a reference site cannot silently keep both consumers green.
   Expected edges/reports are independently specified, never derived from
   the function under test or blessed from actual output.

Prefer small in-memory typed documents and explicit expected values inside
the new tests; no baseline regeneration or existing fixture/schema changes.
Required fixtures and goldens must exist or tests fail hard. No runtime skip
for missing fixtures, permissions, symlink support, or platform capabilities.
There is no new filesystem traversal here, so no new permission/symlink
capability test is needed.
