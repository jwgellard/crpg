## Interface

Add public module `migrations` at `src/migrations/mod.rs`, re-exporting the
following at the crate root. Every public item and field requires rustdoc
(SG/R/DA). Exact new signatures:

```rust

use crate::DataError;

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct SchemaVersion {
    pub schema_type: &'static str,
    pub current: u32,
}

pub fn schema_versions() -> &'static [SchemaVersion];

pub fn migrate_document(doc: &mut Value) -> Result<(), DataError>;
```

`schema_versions` exposes the immutable production registry's 15 document
families, sorted by `schema_type`, including both locks; names are `crpg.item`,
etc., without a slash/version. Embedded Placement and ActionSignature have no
independent document version (D, Wire representation and schema boundary).
No caller registration, plug-in callbacks or public registry mutation API.

Per-type modules under `src/migrations/` contain private steps of exactly this
shape; `Result<()>` in S is concretized with the existing data error type:

```rust
fn v1_to_v2(doc: &mut serde_json::Value) -> Result<(), crate::DataError>;
```

Keep these existing public signatures (D/V), extending their implementation
through the same migration dispatcher, not creating a second loader:

```rust
pub fn read_document(bytes: &[u8]) -> Result<Document, DataError>;
pub fn write_document(document: &Document) -> Result<Vec<u8>, DataError>;
pub fn load_campaign(
    files: &BTreeMap<SourcePath, Vec<u8>>,
    engine_version: &semver::Version,
) -> Result<LoadedCampaign, DataError>;
pub fn serialize_campaign(
    campaign: &LoadedCampaign,

```

Here `Document`, `LoadedCampaign`, `SourcePath`, and `DataError` are existing
crate types; `BTreeMap` is `std::collections::BTreeMap`. Lock byte readers still
delegate to `read_document`; T011a `validate_files` still calls `load_campaign`
once. Typed `Document` serde/schema describe current output, not historical
wire unions. Migration-aware acceptance is through the byte reader or
`migrate_document`, not a new permissive payload deserializer (D/DA).

## Behaviour

### Chain semantics (S/S12; D's schema boundary)

1. Each of the 15 families starts at version 1. Canonical tags are exactly
   `<registered-type>/<positive-u32-in-decimal>` with no leading zero, sign,
   whitespace or suffix. Missing/non-string `schema` and non-object roots are
   `Malformed`; unknown type, malformed version text, zero, overflow, future
   version and unavailable chain are `UnsupportedSchema` with the original
   tag in `found`. Do not guess, downgrade, skip a gap or fall back to another
   type. Standalone errors carry `path: None`; loader attaches the input path.
2. A registry edge is uniquely `(type, n) -> (type, n + 1)`. Check the entire
   requested chain before applying it. No cycles, duplicate/branch edges,
   cross-type edges, jumps, arithmetic wrap or edges beyond current. Steps
   explicitly change the schema tag to their declared destination; the driver
   checks the object/tag postcondition after every step. Invalid production
   topology is an implementation defect caught by the hard gate; dispatch
   must also return an error rather than panic or loop.
3. Steps are deterministic pure Value-to-Value transformations expressed with
   `&mut Value`. No filesystem, clock, environment, generated id, threads,
   network, registry I/O, OS detection or mutable global state. Preserve ids,
   references, authored array order, notes and unrelated fields unless a
   future versioned edge explicitly specifies a change. They do not run
   gameplay, expressions or semantic validation (D/V).
4. `migrate_document` works on a private clone and publishes it only after the
   full chain and current typed/local validation succeed. Failure leaves the
   caller's Value exactly unchanged. Reject non-integer numbers recursively
   before schema dispatch, using the existing integer-only policy. Duplicate
   keys cannot be recovered from a supplied Value; byte readers must reject
   them before constructing it. Current-version input is validated but is not
   rewritten or normalized as a Value. Repeated successful migration is
   idempotent. Do not round-trip through typed serialization merely to perform
   this mutation, which would normalize unrelated strings (D canonical rules).
5. Step shape/precondition errors and broken postconditions use `Malformed`;
   lock-local failures retain existing lock errors. Final typed decoding
   rejects missing/unknown fields; a migration is not permission to discard
   malformed content. Share private decode/local-check helpers to avoid
   recursion through `read_document`. No new `DataError`, diagnostic code or
   diagnostic wire shape is needed: T011a's existing error conversion remains
   the authority (V Interface).

### Loader integration and authority (D Fixed validation order; V Interface)

`read_document` keeps phases 1–2 unchanged: duplicate-rejecting integer-only
syntax parse, then object/string envelope. Phase 3 now selects a supported
current tag **or a complete registered historical chain and applies it**.
Phase 4 decodes the resulting current document with unchanged strict typed
rules; phase 5 enforces lock-local invariants. Syntax still wins over an
unsupported schema, and unsupported schema still wins over typed-field errors.
All phases are completed for one lexical file before reading the next.

`load_campaign` still completes each whole-input phase before the next:
case collisions/required files → lexical reads (including migrations) → layout
→ engine compatibility → unique-id index → package coverage → assets-lock
digest → result. Migrations occur inside reads, never before required-file
checks or after semantic checks. Engine compatibility uses the caller's
version and campaign requirement; a schema migration cannot erase an engine
requirement or make an incompatible campaign acceptable. T011a semantic
validation happens only after successful loading, with its existing positions,
sort order, codes and exact broken-fixture snapshot.

The returned `LoadedCampaign` contains only current typed documents. The source
map is borrowed and unchanged. `serialize_campaign` performs its existing
layout/local/index/lock checks, ignores caller-mutable index contents, and
emits current canonical bytes. It remains a byte API, not a save operation.
Reading locks and writing locks use the same version policy.

**Locks are not repaired by migration.** Package requirements, resolutions,
checksums and source-asset hashes remain D's authorities; no re-resolution,
asset reads, fabricated digests or packaged manifest. T012's dummy touches
neither lock version nor lock payload, so `assets_lock_digest` is unchanged.
The registry covers locks but ships no lock edge. A future assets-lock format
bump must separately specify compatibility for the digest of its complete
canonical envelope and prove corruption still fails before it can land;
this framework grants no automatic digest-repair exception. A wrong digest
today still fails at T010's phase 6 (D Resolver and lock invariants).

invalid v1 payloads; `/2` is now the sole current Item output/schema tag.

the existing generator. Keep the 17-file schema set; no historical alternatives
in current schemas and no new document kind (D schema contract).

### Hard no-bump-without-migration gate (S/S12; SG/E20)

Add ordinary, unignored `tests/migrations.rs` and `tests/migration_coverage.rs`.
The latter runs in both existing `cargo test --workspace --locked` CI jobs;
no workflow/lint script change, build script, environment opt-in or placeholder.

Use one internal production registry for dispatcher metadata and the public
version view. The read-only coverage test independently extracts each current
document tag from `generated_schemas()` and checks exact equality of the 15
families/versions with `schema_versions()`. Exercise a representative typed
Document of each variant through `write_document` and `read_document` and
require the same current tag. Embedded schemas stay excluded only because
they have no document envelope, not because of a filename whitelist that
could silently miss a new document. Gate 7 independently pins the generated
17-schema baseline (D/AD).

`fixtures/migrations.json` is a canonical array sorted by `(schema_type, from)`.
Each object has exactly `schema_type` (string), `from` (u32), `to` (u32),
`root` (fixture-relative logical string), `document` (campaign-relative logical
string), and `golden` (fixture-relative logical string). The initial entry is:

```json
{
  "schema_type": "crpg.item",
  "from": 1,
  "to": 2,
  "root": "migration_v1/campaign",
  "document": "items/item.json",
  "golden": "migration_v1/expected.json"
}
```

For every family whose current version is N, require exactly one implemented
edge and one manifest entry for each `1 -> 2` through `N-1 -> N`. No duplicates,
extra, gap, empty fixture or nonexistent root/document/golden is accepted.
Version-1 families legitimately have no edges; the overall gate must have the
real Item edge so it cannot pass vacuously. Validate registry topology in
private unit tests and the real registry in ordinary tests. Every listed root
must also appear as clean in the gate-8 manifest.

For each entry, verify the named source document really bears its declared
`from` tag. Execute the registered **single edge** against a checked-in
before/after Value oracle, then execute its whole chain through the normal
loader and compare the complete output map against the campaign golden.
For the initial sole edge, the Item string in `expected.json` is also the
single-edge oracle. When a later bump makes an old edge's destination no
longer current, retain that edge's immediate output as
`tests/fixtures/migration_steps/<schema-type>/<from>-to-<to>.json` (a standalone
canonical document), and use that exact conventional path for its single-edge
comparison. Latest edges use their campaign golden's named document. Historical
campaign goldens advance to current only in reviewed changes; historical input
and immediate-edge oracles never disappear. Files under `migration_steps` are
not campaign roots. Single-edge tests may live inside `migrations` to access
private steps; the coverage suite must enforce their oracle inventory too.

Prove the checker fails on in-memory copies with: a current schema/serde tag
bumped independently of the registry; registry bumped without an edge; edge
without a manifest row; missing/malformed/empty fixture or golden; wrong source
tag; wrong output byte; duplicated/extra edge or row; a gap, jump or cycle.
Exercise a two-edge private test registry to prove ordered composition and
rollback after the second step fails. Do not ship a fake second production
version or accept empty functions as evidence. The actual Item bump, its edge,
its checked-in campaign and exact-byte golden are the positive CI proof.
Tests never alter tracked files to demonstrate failures (D schema-drift precedent).
