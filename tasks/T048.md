# T048 — scene sync and proxy lifecycle (`crpg-godot`, `apps/client`)

## Task / Crate(s) / Purpose

Sole crate: `crpg-godot` (plan row `docs/IMPLEMENTATION_PLAN.md:252`, `C → I`,
prerequisite T047; spec §19.2 #12, `docs/CRPG_ENGINE_SPEC.md:1686`). The work is
GDScript in `apps/client`, the crate's client artifact (ADR-0033 §14), plus one
Godot-free test in the crate's core. T047d's `SceneSync.gd` spawns once from
the first non-empty view and never frees or refreshes a node
(`apps/client/scripts/SceneSync.gd:6-26`). T048 makes the proxy scene a
function of every view it is given: spawn rows that appear, free rows that
leave, refresh what a proxy shows, and show `dead()` (ADR-0033 §16,
`docs/adr/0033-godot-bridge.md:517-518`). Contract only.

## Exact contract

Status: **approved by the user 2026-11-03** (open question answered (a): a dead combatant stays in place, greyed). Adjudicated from blind drafts a and b. ADR-0033 is
accepted; this contract changes none of its decisions. **No S-set file is

### Decision

- **D1. The reconcile is GDScript in `apps/client/scripts/SceneSync.gd`.** Both
  drafts agree. A Rust diff helper or a `#[func]` would add an FFI member, which
  ADR-0033 rules out for T048 (`docs/adr/0033-godot-bridge.md:517-518`, `:534`).
  `Main.gd` is unchanged: it already calls `$Proxies.sync(next)` exactly when
  the revision changes (`apps/client/scripts/Main.gd:40-43`).
- **D2. `SceneSync` keeps no revision state.** `sync(view)` reconciles the
  view's rows against the live proxy map, whatever the revision. Revision gating
  stays in `Main.gd`, which never passes revision 0 (`seen` starts at 0 and the
  gate is `!=`, `Main.gd:8`, `:40`). *Settles a vs b.* Draft a's rule ("skip an
  equal revision; clear on revision 0 or a lower revision") is unsound as a
  session signal. A new session's first view is revision 1 (the view's
  revision becomes `previous + 1` from 0, `docs/architecture/crpg-godot.md:96`;
  `close` resets it to 0, `crates/crpg-godot/src/core/tests.rs:1007`), so after
  an old session that ended at revision 1, a's equal-revision gate would skip
  the new scene. The view has no epoch getter (`crates/crpg-godot/src/shell.rs:107-208`).
  The session owner is the only party that knows a session ended, so session
  boundaries use an explicit `clear()` (D6).
- **D3. One reconcile, three ascending lists.** `plan(ids)` is pure. It returns
  `despawn` (live ids absent from `ids`), `spawn` (ids with no live proxy) and
  `refresh` (ids that keep their proxy), each sorted ascending. `sync` applies
  all despawns, then all spawns, then writes the current facts to every row in
  view order. Facts are written unconditionally; there is no change tracking.
  *Settles a vs b:* b's "update only rows whose facts differ" needs a cache, and
  a stale cache is a new bug class. a's "refresh = every id" makes `refresh`
  overlap `spawn`. Here the three lists are disjoint, and `spawn ∪ refresh = ids`.
- **D4. Inputs are exactly four getters:** `net_ids()`, `names()`, `sides()`,
  `dead()` (`shell.rs:113-130`, `:155-160`). These are ascending and parallel
  (`docs/adr/0033-godot-bridge.md:271`; `docs/architecture/crpg-godot.md:105-108`).
  *Settles b:* b also read `health`/`max_health`/`health_known` to dim unknown
  health. That is rejected: a proxy shows no health (spec §9.2,
  `docs/CRPG_ENGINE_SPEC.md:879-881`), and health text is the HUD's
  (`apps/client/scripts/CombatHud.gd:83-101`).
- **D5. Lifecycle.** The map `_proxies: Dictionary` (int `NetId` → `Node3D`) is
  the lookup. A proxy is named `proxy_<id>`, as in T047d (`SceneSync.gd:37`).
  To free one: `remove_child(node)`, then `node.queue_free()`, then
  `_proxies.erase(id)`. *Settles b* (`queue_free` alone): the dying node stays a
  child until frame end, so `proxy_count()` overcounts. A same-frame
  re-spawn of that id is also renamed by Godot. **Measured on Godot 4.7.2**
  (throwaway probe outside the repo): after `queue_free()` alone, adding a new
  `proxy_2` produced the name `@Node3D@3` and four children. After `remove_child`
  + `queue_free`, the new node kept `proxy_3`, the old one reported
  `is_queued_for_deletion() == true` and `get_parent() == null`, and it was
  invalid two frames later. A reappearing id always gets a fresh node; a freed
  node is never revived. Inside one replica an id never returns
  (`crates/crpg-net/src/replica.rs:291-292` refuses `ReusedEntityId`), so
  reappearance is only reachable through a fake view or across sessions. It is
  still tested (S5), because it is the case that breaks a name-based scene.
- **D6. Session boundary: `clear()`, called by the session owner.** It frees
  every proxy and resets the side order. Nothing in the slice calls it yet:
  `Main.gd` never reopens. A future reopen or reconnect task calls
  `$Proxies.clear()` between `close()` and `open()`, and resets `Main.seen`;
  that is that task's change, not T048's. Bulk replacement (a future snapshot)
  needs no special path, because the same reconcile frees every stale row and
  spawns every new one. Today a `Transfer` fences as 54 (ADR-0033 §8) and
  `apply_snapshot` has no bridge caller.
- **D7. Layout, still client-only (ADR-0033 §14).** The formula is T047d's:
  `x = 3.0 × side index`, `y = 0`, `z = 1.5 × rank within side`
  (`SceneSync.gd:38`). It is recomputed for every row on every sync.
  - **Side index:** the position in `_side_order`. A side is appended the first
    time it appears, in row order, and keeps its column until `clear()`.
  - **Rank:** the 0-based position among the current rows of that side, in
    view order. A leave therefore closes the gap.
  - **Mesh:** side index 0 gives a capsule (radius 0.4, height 1.2); any other
    gives a box (size `(0.8, 1.0, 0.8)`), as in T047d.

  *Settles a vs b:* b rebuilt the side order on every sync. Then, if the first
  side ever left, every survivor would silently swap capsule/box and column.
  a's stable order prevents that. On the fixture the two layouts are identical.
- **D8. Dead visual.** When `dead[i] != 0`:
  - the `Mesh` child's `material_override` is a `StandardMaterial3D` with
    `albedo_color == Color(0.35, 0.35, 0.35)`;
  - the `Label` child's `modulate` is `Color(0.35, 0.35, 0.35)`.

  Otherwise `material_override == null` and `modulate == Color(1, 1, 1)`. The
  change is reversible, and a dead row stays in the scene, because dead is a
  flag, not a leave. *Settles a:* a put `modulate` on the `MeshInstance3D`.
  **Measured:** `MeshInstance3D` has no `modulate` property in 4.7.2;
  `Label3D` has one, and `material_override` exists and round-trips.
  *Settles b:* no `" (dead)"` label suffix, since the HUD already appends one
  (`CombatHud.gd:98-99`), and no hiding, since T050 must still be able to find
  the body. The visual reads only the `dead` column, never a `Died` event
  (`crates/crpg-godot/AGENTS.md:32-33`).
- **D9. Child order equals view row order.** After each sync, row `i`'s proxy is
  child `i` of `Proxies` (`move_child`). `Proxies` has no other children
  (`apps/client/scenes/Main.tscn:22-23`). This makes the scene a deterministic
  function of the sequence of views. Live replicas only append ascending ids,
  so in the slice this changes nothing.
- **D10. Tests: one shared GDScript case file, run two ways, plus one Rust
  test.** *Settles harness and CI:*
  - **Harness:** both drafts use a fake view, and so does this contract. It is
    an inner class in the case file. `smoke.gd` cannot produce a leave on the
    two-row fixture (`campaigns/fixtures/combat_basic/encounters/first-blood.json:4-13`).
  - **Running the cases:** a standalone runner `tests/scene_sync.gd`, and
    `smoke.gd`, which runs the same cases before it loads `Main.tscn`. CI's
    existing BR-22 step (`.github/workflows/ci.yml:313-320`) therefore gates
    despawn with **no workflow edit**.
  - **Rejected:** a's "ungated, run from the completion record", because a test
    no gate runs rots. b's "add `-s` steps to the job" edits an S-set file.
  - **Exit codes:** smoke gains exit 6, used only when a case fails. BR-22's
    ADR text (`docs/adr/0033-godot-bridge.md:655`) still holds.
  - **Rust test:** a's one Godot-free test is kept, reshaped (R1). No checked-in
    fixture ever makes the real view shrink, so R1 is the only proof that the
    producer emits what `SceneSync` consumes: a leave bumps the revision and
    realigns every column, a dead row stays, and a retired id cannot return. It
    is test-only and leaves the library and the FFI untouched. b's "no Rust
    test" leaves the producer side of the despawn path unproved.
- **D11. Dropped from a:** `set_meta("net_id", …)`, which has no consumer
  (T050 decides picking). Also dropped: the per-call revision guard (D2).

### Interface

`apps/client/scripts/SceneSync.gd` is rewritten. Public members are exactly
these four. Private helpers are free but must be `_`-prefixed. No `class_name`,
`@export`, signal or autoload.

```gdscript
extends Node3D

const DEAD_TINT := Color(0.35, 0.35, 0.35)

var _proxies: Dictionary = {}        # int NetId -> Node3D; live proxies only
var _side_order: Array[String] = []  # first-seen order since the last clear()

func plan(ids: PackedInt64Array) -> Dictionary
	# {"despawn": Array, "spawn": Array, "refresh": Array}; untyped Arrays of
	# int, each ascending; pure (mutates nothing)
func sync(view) -> void      # reads view.net_ids/names/sides/dead only
func clear() -> void         # frees every proxy (D5 idiom), empties _side_order
func proxy_count() -> int    # unchanged: children whose name begins "proxy_"
```

A proxy is a `Node3D` named `proxy_<id>`. It has exactly two children:

- `Mesh`, a `MeshInstance3D`;
- `Label`, a `Label3D` at `position == Vector3(0, 1.2, 0)` with
  `billboard == BaseMaterial3D.BILLBOARD_ENABLED` and `text == names[i]`.

The proxy carries no script, metadata or other state.

`apps/client/tests/scene_sync_cases.gd` (new) is the case file:

- `extends RefCounted`.
- Has an inner `class FakeView` whose `net_ids() -> PackedInt64Array`,
  `names()`/`sides() -> PackedStringArray` and `dead() -> PackedByteArray`
  return what the constructor was given.
- `func run(host: Node) -> String` returns `""` when every case passes,
  otherwise `"S<n>: <detail>"` for the first failure. Each case gets a fresh
  `load("res://scripts/SceneSync.gd").new()` added under `host`.
- `var freed: Array` (nodes the cases saw freed) and `var kept: Array` (at least
  one live proxy left under `host`) serve S14.

`apps/client/tests/scene_sync.gd` (new) is the runner:

- `extends SceneTree`. In `_initialize` it calls `run(root)`.
- Exits **6** unless the result is a `String` equal to `""`. A GDScript runtime
  error makes `run` return `null`, which must fail, not hang.
- After 2 process frames: exits **7** if any `freed` node `is_instance_valid`,
  or if any `kept` node is not. Otherwise it exits **0**.
- Exits **3** if a script fails to load.

`apps/client/tests/smoke.gd` changes in one place. In `_initialize`, after the
`ClassDB` check and before `Main.tscn` loads, it runs the same cases under
`root`. If they fail it prints `smoke.gd FAIL: scene sync <detail>` and exits
**6**. The header comment lists 6. Every other line and exit code is unchanged.

`crates/crpg-godot/src/core/client/tests.rs` gains one `#[test]` (R1). No
library item changes.

### Behaviour

1. **B1 plan.** `plan(ids)` is pure.
   - `despawn` = keys of `_proxies` not in `ids`; `spawn` = `ids` not in
     `_proxies`; `refresh` = `ids` in `_proxies`. All three are sorted ascending.
   - `ids` need not be sorted: `plan([3, 1])` on an empty scene gives
     `spawn == [1, 3]`.
   - Calling `plan` twice in a row returns equal dictionaries.
2. **B2 apply order.** `sync(null)` is a no-op. Otherwise `sync` runs, in order:
   1. B1 on `view.net_ids()`;
   2. every `despawn` id, ascending, with the D5 free;
   3. every `spawn` id, ascending, creating the node described under Interface;
   4. for each row `i` in view order, the D7 position and mesh, the
      `names[i]` label and the D8 dead visual, then `move_child(proxy, i)`.
3. **B3 immediate consistency.** When `sync` returns:
   - `proxy_count() == _proxies.size() == net_ids().size()`;
   - for every despawned id, `get_node_or_null("proxy_<id>") == null`.

   The freed node is still a valid object until frame end.
4. **B4 empty view.** A view with no rows despawns every proxy. There is no
   early return on an empty view; T047d's `_spawned` flag and early returns
   (`SceneSync.gd:6-14`) are deleted.
5. **B5 identity.** A kept id keeps the same node object across syncs. A spawned
   id is always a new object, even if that id was freed earlier in the same
   frame, and its name is exactly `proxy_<id>`.
6. **B6 layout.** D7. A side keeps its column until `clear()`. A row's mesh
   follows its current side index in both directions (capsule ↔ box).
7. **B7 dead.** D8, written on every sync, reversible, never despawning.
8. **B8 idempotence.** Two syncs of views with equal columns leave every proxy
   with the same object, name, position, mesh class, label text, override and
   modulate.
9. **B9 clear.** `clear()` frees every proxy with the D5 idiom and empties
   `_side_order`. Afterwards `proxy_count() == 0`, and a sync spawns every row
   fresh with the side order rebuilt. `clear()` on an empty scene is a no-op.
10. **B10 no authority leak.** `SceneSync.gd`:
    - calls no member on `view` other than D4's four;
    - names no session, intent, event, receipt, health, revision, option,
      active, round, `Time` or `OS`;
    - holds no gameplay state (spec `docs/CRPG_ENGINE_SPEC.md:310`).
11. **B11 preconditions.** Columns of unequal length are a caller bug and are
    not defended (BR-14; `docs/architecture/crpg-godot.md:105-108`).
    `sync` returns nothing and produces no `BridgeCode`.
12. **B12 producer facts (Rust, R1).**
    - A leave removes exactly that row from every column, keeps the others
      aligned, and bumps the revision by exactly 1.
    - A health fact with `dead = true` keeps the row.
    - A frame re-entering a retired id is refused with 53 (`ReplicaRejected`),
      and the view `Rc` is unchanged.

### Out of scope

- T049 positions and interpolation.
- T050 camera, picking, selection, active highlight, and node→`NetId`
  metadata.
- T051 HUD changes and event-driven VFX.
- Any health on a proxy.
