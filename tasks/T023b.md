## Task / Crate(s) / Purpose

Sole crate: `crpg-server`, selected in D02; Phase 4. **Blocked** on T022, completed

to the same authority used in-memory; do not put host execution in net.

## Interface

After T023, append exact bind/start/pump/shutdown/error API adapting its byte
endpoints to T022's authenticated session boundary. Pin ownership/threading,
monotonic clock conversion, queue budgets and credential handoff. No host
package or socket/runtime type is silently chosen by this contract.

## Behaviour

QUIC connections confer no gameplay identity until approved authentication
binds them. Real sockets feed the same admission, capture and checkpoint logic
as in-memory sessions. Preserve application seq/cache even when QUIC is
reliable; retry after a lost application receipt never executes twice.
Backpressure and shutdown release resources predictably without silently losing
committed receipts. No localhost, embedded or GM bypass. Native dedicated
adapters share one authority; process/filesystem policy stays above sim.

## Constraints

[Standing rules](POST-T018-RULES.md) apply. Sole host crate; net changes are a
separate child, Godot embedding is a later bridge task. New deps require approval.
NAT is independently chosen in D05 and only required for public reachability.

### B§1. Decisions this contract makes

Each is restated where it applies. Those the user may want to change are
also open questions (B§16).

1. **One new public module, `crpg_server::quic`**, holding one adapter type,
   `QuicHost`. It **owns** the `Host` and the `QuicServer` while it runs, so
   nothing can call `unbind_peer`, `set_grants` or `acknowledge_delivery`
   behind its back. It gives the `Host` back on start failure and on
   shutdown.
2. **Two-step start.** The caller binds the transport with
   `crpg_net_quic::QuicServer::bind` (its own `BindError`; nothing is lost
   on failure), then calls `QuicHost::start(host, server, now_ms)`. "Bind"
   is the transport's, "start" is the adapter's.
3. **The invitation is the principal.** An `Invitation` holds the credential,
   the `ControlGrant` and the `DisclosureGrants` (D03: bound server-side to
   principal, actors and grants). Grant and control changes are made on the
   invitation, so a reconnect cannot bring back revoked disclosure.
4. **Credential content:** exactly 32 opaque bytes
   (`INVITATION_CREDENTIAL_BYTES`), inside ADR-0025's 16..=128 bounds. The
   operator supplies them from secure entropy; `crpg-server` generates
   none (B§4).
5. **Delivery is acknowledged on hand-off.** A host delivery frame is
   acknowledged once `QuicServer::try_send` has accepted it (E§7 mapping
   table). QUIC delivers in order, exactly once, while the connection lives.
   A lost connection ends the session until T025a/T025b.
6. **R5 hold:** one refused frame is held per connection on ingest
   `QueueFull`, and draining that connection stops. Frames refused as
   `RateLimited`, `FrameTooLarge` or `Unauthenticated` are dropped (B§6).
7. **R4 fence:** `SessionFenced` (9) in `Discard` mode on unbind, epoch
   closure, narrowing, revocation, supersession and slow-consumer timeout
   (B§7).
8. **Peer close:** frames fully received before a peer's close are still
   offered to the host, then the binding is unbound (B§8).
9. **Shutdown** follows D02: stop admissions, flush delivery already
   committed, refuse staged work, optional checkpoint, close transports
   (B§9).

### B§3. Interface (exact public Rust)

`quic.rs` starts with `//!` docs and uses only `std`, `crpg_net`,
`crpg_net_quic` and `crate::{host, checkpoint}`. It does not glob-import
and does not re-export any `crpg_net_quic` or `crpg_net` item; callers name

following `crpg-net-quic`'s own no-re-export rule.

#### B§3.1 Constants and identities

```rust
/// Exact v1 invitation credential length (256 bits), inside ADR-0025's
/// 16..=128 transport bounds.
pub const INVITATION_CREDENTIAL_BYTES: usize = 32;
/// Registered invitations per adapter (live and unbound together).
pub const MAX_INVITATIONS: usize = 64;
/// Frames taken from one connection by one pump (references
/// `crpg_net::protocol::POLICY_INGRESS_FRAMES_PER_PEER`, 128).
pub const MAX_DRAIN_PER_CONNECTION: usize = POLICY_INGRESS_FRAMES_PER_PEER;
/// Injected-time budget for a connection whose transport queue refuses
/// delivery before it is fenced as a slow consumer.
pub const STALL_TIMEOUT_MS: u64 = 10_000;

/// Never reused within one `QuicHost`; starts at 1.
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
pub struct InvitationId(u64);
impl InvitationId {
    /// The raw id.
    pub fn get(self) -> u64;
}

/// One operator-provisioned invitation (D03). `Debug` shows the credential
/// only as `Credential(<redacted>)` (its own `Debug`).
#[derive(Debug, Clone)]
pub struct Invitation {
    /// Exactly `INVITATION_CREDENTIAL_BYTES` bytes of operator secret.
    pub credential: crpg_net_quic::Credential,
    /// The actors this principal may act as.
    pub control: ControlGrant,
    /// What this principal may learn.
    pub grants: DisclosureGrants,
}
```

#### B§3.2 The adapter

```rust
/// The real-transport adapter: one `Host` plus one `QuicServer`, driven by a
/// synchronous `pump`. Neither `Clone` nor `Copy`. `Debug` is hand-written
/// (local address, binding and invitation counts) and never prints a
/// credential. `Send` (asserted by a test); no `Sync` requirement.
pub struct QuicHost { /* private */ }

impl QuicHost {
    /// Takes ownership of a host and a bound server. Precedence:
    /// `HostClosed` → `HostInUse` (any binding or staged ingress) →
    /// `TimeRegression` (`now_ms` below the host's last accepted time).
    /// On failure, both are returned unchanged.
    pub fn start(host: Host, server: QuicServer, now_ms: u64)
        -> Result<QuicHost, Box<StartFailure>>;

    /// One serial step (B§5). Errors: `Poisoned`; `TimeRegression` (checked
    /// first, nothing changes); `Host(e)` for an unreachable host failure,
    /// which poisons the adapter (B§12).
    pub fn pump(&mut self, now_ms: u64) -> Result<QuicPumpReport, QuicHostError>;

    /// `QuicServer::wait`: blocks up to `timeout` until a transport event or
    /// inbound frame is queued. Optional; a pump on its own cadence never
    /// needs it.
    pub fn wait(&self, timeout: std::time::Duration) -> bool;

    /// Precedence: `Poisoned` → `InvitationLimit` → `InvalidCredential`
    /// (length ≠ 32) → `Host(InvalidControl)` → `Host(InvalidGrants)` →
    /// `DuplicateCredential`. Control and grants are stored normalized
    /// (B§3.6).
    pub fn register_invitation(&mut self, invitation: Invitation)
        -> Result<InvitationId, QuicHostError>;

    /// Removes the invitation forever and fences its live binding
    /// (`Revoked`). Later hellos with it get `AuthRefused`. Errors:
    /// `Poisoned`, `UnknownInvitation`.
    pub fn revoke_invitation(&mut self, id: InvitationId)
        -> Result<Option<Fence>, QuicHostError>;

    /// Replaces the stored grants (B§7.2). Errors: `Poisoned`,
    /// `UnknownInvitation`, `Host(InvalidGrants)`, `Host(QueueFull)`
    /// (widening without room; nothing changes).
    pub fn set_invitation_grants(&mut self, id: InvitationId, grants: DisclosureGrants)
        -> Result<GrantChange, QuicHostError>;

    /// Replaces the stored control grant and, when bound, calls
    /// `Host::set_control` (future admission only; staged commands are
    /// judged at pump time, T022§3 step 5). Errors: `Poisoned`,
    /// `UnknownInvitation`, `Host(InvalidControl)`.
    pub fn set_invitation_control(&mut self, id: InvitationId, control: ControlGrant)
        -> Result<(), QuicHostError>;

    /// Operator kick: fences a bound connection (`Disconnected`). Errors:
    /// `Poisoned`, `UnknownConnection` (not bound).
    pub fn disconnect(&mut self, conn: ConnectionId) -> Result<Fence, QuicHostError>;

    /// Trusted pass-throughs (the only mutable host access besides `pump`).
    pub fn tick(&mut self) -> Result<(), QuicHostError>;
    pub fn acknowledge_captures(&mut self, through: u64) -> Result<(), QuicHostError>;

    /// Read-only access for trusted oracles, captures and checkpoints.
    pub fn host(&self) -> &Host;
    pub fn binding(&self, conn: ConnectionId) -> Option<PeerHandle>;
    pub fn invitation_binding(&self, id: InvitationId)
        -> Result<Option<(ConnectionId, PeerHandle)>, QuicHostError>;
    pub fn local_addr(&self) -> std::net::SocketAddr;
    pub fn transport_totals(&self) -> QueueTotals;
    pub fn connection_stats(&self, conn: ConnectionId) -> Option<ConnectionStats>;

    /// Graceful D02 shutdown (B§9). Infallible; consumes the adapter.
    pub fn shutdown(self, checkpoint: bool) -> QuicHostShutdown;
}

/// `start` failure: everything handed in comes back.
#[derive(Debug)]
pub struct StartFailure {
    pub host: Host,
    pub server: QuicServer,
    pub error: QuicHostError,
}
```

`Drop` is not implemented on `QuicHost`. Dropping it drops the
`QuicServer`, whose own `Drop` closes every connection with `Shutdown` in
`Discard` mode, and drops the `Host` without a checkpoint.

#### B§3.3 Reports

```rust
/// What one `pump` did, in call order. Bounded per pump: at most
/// `max_connections` hello decisions and closes, and at most
/// `MAX_PEERS × MAX_DRAIN_PER_CONNECTION` ingest calls plus one held retry
/// per peer.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct QuicPumpReport {
    /// Every host call this pump made, in order: the equivalence trace (B§11).
    pub calls: Vec<HostCall>,
    /// One per `HelloReceived` polled.
    pub hellos: Vec<HelloDecision>,
    /// Bindings fenced by this pump.
    pub fences: Vec<Fence>,
    /// `ServerEvent::Closed` events polled (bound, retiring or unmapped).
    pub transport_closes: Vec<(ConnectionId, CloseReason)>,
    /// Delivery frames accepted by `try_send`.
    pub frames_sent: usize,
    /// Inbound frames dropped after a terminal ingest refusal.
    pub frames_refused: usize,
    /// Frames discarded: drained from retiring connections, held frames of
    /// fenced or closed bindings, and delivery frames for closed transports.
    pub frames_discarded: usize,
    /// Bound connections holding a refused frame when the pump ended.
    pub held: usize,
}

/// One host call, with what it returned.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum HostCall {
    BindPeer { conn: ConnectionId, invitation: InvitationId, result: Result<PeerHandle, HostError> },
    UnbindPeer { peer: PeerHandle },
    /// `frame` is the 1-based ordinal of the frame on its connection
    /// (`try_recv` order); a held frame's retries repeat its ordinal.
    Ingest { conn: ConnectionId, peer: PeerHandle, frame: u64, len: usize, result: IngestDisposition },
    Pump { summary: PumpSummary },
    /// `Ok(n)`: `take_delivery` returned `n` frames.
    TakeDelivery { peer: PeerHandle, result: Result<usize, HostError> },
    AcknowledgeDelivery { peer: PeerHandle, through: u64 },
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct HelloDecision { pub conn: ConnectionId, pub outcome: HelloOutcome }

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum HelloOutcome {
    Accepted { invitation: InvitationId, peer: PeerHandle },
    /// The close code passed to `QuicServer::refuse` (5, 6, 7 or 1), or the
    /// transport close found when `accept` failed (B§4.3 step 6).
    Refused { code: CloseCode },
    /// `accept` failed because the connection had already closed.
    Lost { reason: CloseReason },
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Fence { pub conn: ConnectionId, pub peer: PeerHandle, pub cause: FenceCause }

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum FenceCause {
    /// `disconnect`.
    Disconnected,
    /// `revoke_invitation`.
    Revoked,
    /// Narrowing `set_invitation_grants`.
    Narrowed,
    /// A newer connection presented the same invitation.
    Superseded,
    /// The host retired the binding itself (`SeqConflict`), or a host
    /// delivery call failed for it.
    EpochClosed,
    /// Delivery refused by the transport for `STALL_TIMEOUT_MS`.
    SlowConsumer,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum GrantChange {
    /// No live binding: stored for the next bind.
    Stored,
    /// Widening applied to the live binding (`GrantUpdate::Unchanged`).
    Widened,
    /// Narrowing: stored, and the live binding fenced.
    Fenced(Fence),
}

/// What `shutdown` did (B§9).
#[derive(Debug)]
pub struct QuicHostShutdown {
    /// The closed host: authority, captures and save remain available.
    pub host: Host,
    /// `Host::shutdown`'s refusals of staged work (`SessionExpired`, FIFO).
    pub refused: Vec<AdmissionResult>,
    /// Adapter-held frames never staged.
    pub held_discarded: usize,
    /// Host delivery frames the transport could not take before shutdown.
    pub undelivered_frames: usize,
    /// `Some` when requested: `save_checkpoint` taken after the host fence
    /// and before the transport closes.
    pub checkpoint: Option<Result<Vec<u8>, CheckpointError>>,
    /// `QuicServer::shutdown`'s report.
    pub transport: ShutdownReport,
}
```

#### B§3.4 Error

```rust
/// Every adapter failure. `Display` is `<VariantName> at host/quic`; no
/// source. A credential never appears in any variant.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum QuicHostError {
    /// `start` was given a shut-down host.
    HostClosed,
    /// `start` was given a host with a binding or staged ingress.
    HostInUse,
    /// `now_ms` below the last accepted `now_ms`.
    TimeRegression,
    /// An earlier host failure poisoned the adapter; only `shutdown` remains.
    Poisoned,
    /// Credential length is not `INVITATION_CREDENTIAL_BYTES`.
    InvalidCredential,
    /// The credential equals a registered one.
    DuplicateCredential,
    /// `MAX_INVITATIONS` are registered.
    InvitationLimit,
    /// No such registered invitation.
    UnknownInvitation,
    /// No such bound connection.
    UnknownConnection,
    /// A host error passed through.
    Host(HostError),
}
impl std::fmt::Display for QuicHostError { /* "<VariantName> at host/quic" */ }
impl std::error::Error for QuicHostError {}
```

`InvitationLimit at host/quic`, `UnknownInvitation at host/quic`,

(`at host/checkpoint`).

#### B§3.5 Mapping `ConnectionId` to host state

Private, in `BTreeMap`s (no `HashMap`/`HashSet`), each bounded by the
transport's `max_connections` or `MAX_INVITATIONS`:

- `invitations: BTreeMap<InvitationId, InvitationRecord>`, where the record
  holds the credential, the normalized control and grants, and `live:
  Option<ConnectionId>`.
- `conns: BTreeMap<ConnectionId, Conn>` with
  `enum Conn { Bound(Bound), Retiring(Retiring) }`.
  - `Bound`: `peer: PeerHandle`, `epoch: [u8; 16]`, `invitation`,
    `acked: u64` (the last delivery `event_seq` acknowledged; 0 at bind),
    `frames: u64` (the ordinal of the last frame taken), `held:
    Option<Vec<u8>>` (≤ 4,096 bytes), `stalled_since: Option<u64>`,
    `transport_closed: Option<CloseReason>` and `drained: bool`.
  - `Retiring`: a connection this adapter closed, or whose binding ended,
    still being drained and discarded so that `crpg-net-quic` can forget its
    record (E§7 record lifetime), plus `event_seen: bool`.
- A connection is never mapped before `accept` succeeds. Unmapped
  connections' `Closed` events are polled and only reported.
- One invitation has at most one `Bound` connection, and one `PeerHandle` at
  most one connection. Handles and epochs come from the host
  (`incarnation || handle`, T022§1). `ConnectionId`s never enter host state.

#### B§3.6 In-crate visibility (not public surface)

`host.rs` changes visibility only:

- `fn normalize_control` and `fn normalize_grants` become `pub(crate)`.
  Registration validates with the same code that `bind_peer` uses, so
  there is one rule.
- `fn is_narrowing` becomes `pub(crate)`. The adapter decides narrowing
  before it touches the host.
- New `pub(crate) fn session_count(&self) -> usize` (`sessions.len()`) and
  `pub(crate) fn last_now_ms(&self) -> u64`, for `start`'s `HostInUse` and
  `TimeRegression` checks. The existing `pub(crate) fn has_staged_ingress`
  is reused.

No public item, signature, cap, variant or `Display` text of `host`,
`capture` or `checkpoint` changes. `host_capture`'s 31 cases keep passing
unchanged.

### B§4. Credentials and admission

#### B§4.1 Credential content, storage and comparison (D03, ADR-0025 item 6)

- Content: exactly `INVITATION_CREDENTIAL_BYTES` = 32 opaque bytes, with no
  structure, prefix or embedded id. The operator draws them from OS secure
  entropy and hands them to the client out of band, with the certificate
  pin. Simulation RNG is never used, and `crpg-server` generates no
  credential (no CSPRNG dependency, B§16 Q2). Hellos carrying 16..=31 or
  33..=128 bytes pass the transport's format check and are refused here
  with `AuthRefused`, never a distinct code.
- Storage: memory only, in the `InvitationRecord`. Never in a checkpoint
  (the checkpoint encodes the `Host`, which never sees a credential; D10),
  a report, an error, `Debug` output, a close reason or a log
  (`crpg-server` has no logging). Revocation drops the bytes. They are not
  zeroized (no `zeroize` dependency; stated as a limitation).
- Comparison: `Credential::ct_eq` against **every** registered invitation in
  ascending `InvitationId` order. The match flags are folded with `|` and no
  early exit, and the matching id is selected after the loop. Duplicates
  are refused at registration, so at most one matches. The time taken
  depends only on the number of registered invitations, never on the
  credential's content. The length check before the loop depends only on
  the hello's public length byte.

#### B§4.2 Registration

`register_invitation` checks, in order: `Poisoned`; `invitations.len() ==
MAX_INVITATIONS` → `InvitationLimit`; credential length ≠ 32 →
`InvalidCredential`; `normalize_control` → `Host(InvalidControl)`;
`normalize_grants` → `Host(InvalidGrants)`; `ct_eq` against every
registered credential → `DuplicateCredential`. Then it stores the record
and returns the next id. Ids start at 1 and are never reused, even after
revocation.

#### B§4.3 `HelloReceived { conn, hello, .. }` (exact precedence)

1. **Credential.** If its length is not 32, or no registered invitation
   matches (B§4.1): `refuse(conn, AuthRefused)`. Unknown, revoked and
   wrong-length credentials are indistinguishable. The credential is
   checked before the version, so an unauthenticated peer learns nothing
   about the host.
2. **Version.** If `hello.wire_version != host.protocol().as_u8()`:
   `refuse(conn, VersionRefused)`.
3. **Supersession.** If the invitation has a live `Bound` connection, fence
   it with cause `Superseded` (B§7.1). The newest connection wins (B§16 Q3).
4. **Bind.** Call `host.bind_peer(control.clone(), grants.clone(), now_ms)`,
   traced as `BindPeer`.
   - `Err(ServerBusy | QueueFull | CounterExhausted)` → `refuse(conn,
     ServerBusy)`.
   - `Err(InvalidControl | InvalidGrants)` → `refuse(conn, AuthRefused)`.
     This is unreachable, because registration validated both.
   - `Err(Closed)` → `refuse(conn, Shutdown)`. Unreachable.
   - `Err(TimeRegression)` cannot occur: B§5 step 0 already checked time.
5. **Welcome.** Compute `epoch = host.epoch(peer)`, then call
   `accept(conn, Welcome { wire_version: host.protocol().as_u8(), epoch })`.
6. **Result.**
   - `Ok` → map the connection `Bound` (`acked = 0`, `frames = 0`), set the
     invitation's `live`, and record
     `HelloOutcome::Accepted { invitation, peer }`.
   - `Err(Closed(reason))` → `unbind_peer(peer)` (traced) and
     `HelloOutcome::Lost { reason }`. One case is the transport's
     `AuthTimeout` (8) when the pump came more than `decision_timeout_ms`
     after the hello.
   - `Err(UnknownConnection | NotPending)` → `unbind_peer(peer)` and
     `Lost { reason: CloseReason::EndpointFailed }`.
   - `Err(InvalidWelcome)` → `unbind_peer(peer)` and `refuse(conn,
     VersionRefused)`. Unreachable.

A refused hello calls no host method except, in step 4, a failed
`bind_peer`. A `ServerBusy` refusal consumes no handle: `bind_peer` checks
`MAX_PEERS` before it mints one. `refuse` errors are ignored, because the
connection has already ended. Every `refuse`d or `Lost` connection's
`Closed` event is polled later and reported, which releases its slot.

| Condition | Close code | Host call |
|---|---|---|
| Unknown, revoked or wrong-length credential | `AuthRefused` (5) | none |
| Version ≠ host selection | `VersionRefused` (6) | none |
| `MAX_PEERS` bound, egress full or handle sentinel | `ServerBusy` (7) | `bind_peer` → `Err` |
| Host closed (unreachable) | `Shutdown` (1) | `bind_peer` → `Err` |
| Accepted | Welcome `[version][epoch]` | `bind_peer` → `Ok` |

### B§5. The pump (exact order)

`pump(now_ms)` runs these phases in order. Every per-connection loop visits
**ascending `ConnectionId`**.

0. **Preconditions.** If poisoned → `Err(Poisoned)`. If `now_ms <
   last_now_ms` → `Err(TimeRegression)`; nothing is polled or called.
   Otherwise `last_now_ms = now_ms`.
1. **Events.** Call `poll_event()` until `None`. The FIFO is bounded at two
   events per connection by E§7.
   - `HelloReceived` → B§4.3.
   - `Closed { conn, reason }` → `Bound`: set `transport_closed = Some(reason)`.
     `Retiring`: set `event_seen`. Unmapped: nothing more. Always push to
     `transport_closes`.
2. **Drain** (B§6). For each `Bound` connection:
   - first retry its held frame;
   - then take up to `MAX_DRAIN_PER_CONNECTION` frames with `try_recv` and
     `ingest` each one.

   For each `Retiring` connection, `try_recv` and discard up to
   `MAX_DRAIN_PER_CONNECTION` frames (`frames_discarded`). When it returns
   `Err(Closed(_))` or `Err(UnknownConnection)` and `event_seen` is set,
   remove the entry.
3. **Admit.** Call `host.pump(now_ms)`, traced as `Pump { summary }`, even
   when nothing was ingested, so the host's time advances on the same
   schedule in every replay.
4. **Reconcile.** For each `Bound` connection, if `host.epoch(peer) !=
   Ok(epoch)` (the host fenced it for `SeqConflict`, T022§3 step 3), fence
   it with cause `EpochClosed`. That close makes no host call, because the
   binding is already gone.
5. **Deliver.** For each `Bound` connection, call `take_delivery(peer)`
   (traced).
   - `Err(_)` → fence with `EpochClosed`. This is unreachable: narrowing
     fences before any resync can be pending (B§7.2).
   - **Transport closed** (`transport_closed` is `Some`): acknowledge every
     frame returned (`acked += n`) without sending it, counted in
     `frames_discarded`. This keeps a departed peer's log from blocking
     admission for the rest (B§8).
   - **Otherwise:** `try_send` the frames in order and stop at the first
     error.
     - `Ok` → count it.
     - `QueueFull` → stop. If `stalled_since` is `None`, set it to `now_ms`.
     - `Closed(reason)` → set `transport_closed`, stop.
     - `UnknownConnection` → set `transport_closed =
       Some(CloseReason::EndpointFailed)`, stop.
     - `EmptyFrame | FrameTooLarge | NotAccepted` → fence `EpochClosed`.
       Unreachable: host frames are non-empty and at most 65,536 bytes
       (T022§5).

     If `k > 0` frames were accepted, call `acknowledge_delivery(peer,
     acked + k)` (traced), then `acked += k`. If every frame was accepted,
     clear `stalled_since`.
   - **Slow consumer:** if `stalled_since` is `Some(t)` and `now_ms - t >=
     STALL_TIMEOUT_MS`, fence with `SlowConsumer` (B§7.1).

   `acked` mirrors the host's watermark exactly. A binding's log starts at
   `event_seq` 1 and stays gapless (T022§5), and the only generation reset,
   narrowing, never reaches `take_delivery` because the adapter fences
   first. So the first frame `take_delivery` returns is always `acked + 1`.
6. **Retire closed peers.** For each `Bound` connection with
   `transport_closed` set, `drained` set and no held frame:
   - `unbind_peer(peer)` (traced);
   - clear the invitation's `live`;
   - remove the entry if its `Closed` event was already polled, else make it
     `Retiring` with `event_seen = false`.
7. **Report.** Set `held` and return the report.

`pump` never sleeps or blocks. Every transport call it makes is
`crpg-net-quic`'s non-blocking `poll_event`/`accept`/`refuse`/`try_recv`/
`try_send`/`close(.., Discard)`. `close` in `Discard` mode returns at once
(E§3; `Flush` is never used by the pump).

### B§6. Backpressure (R5, exact)

Draining one `Bound` connection in phase 2 works as follows:

1. **Held retry.** If the connection holds a frame, re-`ingest` it with its
   original ordinal.
   - `Staged` → clear the hold and continue to step 2.
   - `Refused { Rejected(QueueFull) }` → keep holding it and go to the next
     connection. The connection is not drained further.
   - Any other `Refused` → apply step 3.
2. **Fresh frames.** `try_recv` up to the per-pump budget:
   - `Ok(Some(f))` → `frames += 1`, then `ingest(peer, &f, now_ms)`, traced
     with `frame = frames`.
   - `Ok(None)` → stop.
   - `Err(Closed(reason))` → set `transport_closed` (if unset) and
     `drained`, stop.
   - `Err(UnknownConnection)` → set `drained`, plus
     `transport_closed = Some(EndpointFailed)` if unset, stop.
   - `Err(NotAccepted | NotPending | InvalidWelcome)` → fence `EpochClosed`.
     Unreachable.
3. **Disposition.**
   - `Staged` → continue.
   - `Refused { Rejected(QueueFull) }` → **hold** this frame (`held =
     Some(f)`) and stop draining this connection. It is the only retryable
     refusal (T022§3).
   - `Refused { Rejected(RateLimited | FrameTooLarge) }` → drop the frame
     (`frames_refused += 1`) and continue draining.
   - `Refused { Rejected(Unauthenticated) }` → drop it, `frames_refused +=
     1`, and fence `EpochClosed`. Unreachable: phase 4 reconciles
     bindings.
   - `Err(Closed | TimeRegression)` from `ingest` → poison and return
     `Err(Host(e))`. Unreachable.

Consequences:

- **Per-connection order is exact.** A connection is never read past a held
  frame, so frame `n + 1` is never offered to the host before frame `n` has
  been staged or terminally refused.
- **The client is pushed back.** While a frame is held, `crpg-net-quic`'s
  per-connection inbound queue fills, its reader parks, and QUIC flow
  control stalls the client (E§7). The client's `try_send` eventually
  returns `QueueFull`. Nothing is lost.
- **Bounded.** One held frame (≤ 4,096 bytes) per bound connection, plus
  the transport's own caps.
- **Fair.** Draining is sequential, in ascending id order. The host's
  per-peer ingress caps (128 frames / 256 KiB, × `MAX_PEERS` = the
  host-wide 1,024 / 2 MiB) mean one connection can never use up another's
  share.
- **Held frames delay the `Closed` event.** A connection with a held frame
  is not drained, so its reader stays parked and its `Closed` event is held
  back as well (T023 completion reading 1). Detection then goes through
  `try_send` → `Closed` in phase 5. Phase 5 acknowledges a closed peer's
  delivery without sending it, so the host is never blocked waiting for
  that peer. Admission therefore progresses, the held frame stages, draining
  resumes and the record is forgotten. A held frame of a fenced connection
  is discarded (`frames_discarded`).

The host side of backpressure is unchanged: T022's head-of-line
`QueueFull` (`retained_in_ingress: true`) holds the head command until
egress room frees. Room frees through phase 5's hand-off and
acknowledgement, or by fencing a slow consumer.

### B§7. Fencing (R4, exact)

#### B§7.1 The fence operation

`fence(conn, cause)` on a `Bound` connection:

1. `host.unbind_peer(peer)`. Skipped for `EpochClosed`, where the host
   already removed the binding. Traced only when called from inside
   `pump`.
2. `server.close(conn, SessionFenced, Discard)`, ignoring `Err(Closed(_))`.
   Queued outbound frames are discarded. Bytes already handed to QUIC
   cannot be recalled, so the peer may receive a prefix (ADR-0025
   consequences).
3. Discard a held frame (`frames_discarded`), clear the invitation's `live`,
   and make the entry `Retiring`.
4. Push a `Fence`.

Commands the fenced binding had already staged are refused as
`SessionExpired` by the next host pump and never executed (T022
interpretation 7).

#### B§7.2 Triggers

| Trigger | Cause | Host calls |
|---|---|---|
| `disconnect(conn)` | `Disconnected` | `unbind_peer` |
| `revoke_invitation(id)` while bound | `Revoked` | `unbind_peer` |
| `set_invitation_grants` that narrows (`is_narrowing(stored, new)`) while bound | `Narrowed` | `unbind_peer` only. `set_grants` is **not** called, so no resync generation ever exists. |
| A hello with an already-bound invitation | `Superseded` | `unbind_peer`, then `bind_peer` for the new connection |
| `SeqConflict` fence by the host, or a failed host delivery call | `EpochClosed` | none (the host already fenced) |
| `try_send` refusing for `STALL_TIMEOUT_MS` of injected time | `SlowConsumer` | `unbind_peer` |

`set_invitation_grants` in full:

1. Normalize the new grants (`Host(InvalidGrants)`).
2. Not bound → store → `Stored`.
3. Bound and narrowing → store and fence → `Fenced`.
4. Bound and not narrowing → `host.set_grants(peer, new)`:
   - `Ok(Unchanged)` → store → `Widened`. The newly permitted state is
     sent by the next pump's phase 5.
   - `Err(QueueFull)` → return `Err(Host(QueueFull))`; the invitation and
     the host are unchanged (T022 interpretation 10).
   - `Ok(RebindRequired)` → store and fence `Narrowed`. Unreachable.

The connection is closed now, so a narrowed principal reconnects with a
fresh epoch and a fresh filtered state. Making narrowing seamless through
snapshot resync is T024/T025a (R4).

Out-of-pump fences (`disconnect`, `revoke_invitation`,
`set_invitation_grants`) make exactly the host calls in this table. They
are not in any `QuicPumpReport.calls`, so a test that replays a trace (B§11)
mirrors them itself.

### B§8. Transport closes and the held `Closed` event

- A **peer close** (`Peer { code }`, `IdleTimeout`, `Reset`, `Transport` or
  `EndpointFailed`) on a `Bound` connection is detected by any of:
  - its `Closed` event (phase 1);
  - `try_recv` → `Err(Closed)` (phase 2);
  - `try_send` → `Closed` (phase 5).

  The first detection sets `transport_closed`. The binding stays until the
  connection is drained (`try_recv` → `Err(Closed)` or
  `UnknownConnection`) and holds no frame. Phase 6 then unbinds it.
- **Frames fully received before a peer's close are admitted.** E§7 keeps
  them drainable, so a client that sends commands and then closes with
  `Flush` has all of them offered to the host, in order. Their receipts and
  any other delivery are discarded and acknowledged in phase 5 (B§16 Q5).
- `crpg-net-quic` publishes a `Closed` event only after the connection's
  reader stops adding frames (T023 completion reading 1). Phase 2 keeps
  draining `Bound` and `Retiring` connections until `try_recv` reports
  `Closed`, and phase 1 polls every event each pump. Between them the
  transport always reaches the point where it forgets the record and
  releases the slot (`QueueTotals::connections`).
- Local closes (`refuse`, `fence`) are `Retiring` or unmapped. Their
  `Closed { Local(code) }` event is reported and causes nothing further.

### B§9. Shutdown (D02 order, exact)

`shutdown(self, checkpoint)`:

1. **Stop admissions.** No further events are polled and no `ingest` or
   `pump` runs. Pending hellos are closed with `Shutdown` by step 7.
2. **Flush committed delivery.** For each `Bound` connection whose
   transport is open, run phase 5 without the stall check: `take_delivery`,
   `try_send`, `acknowledge_delivery`.
3. **Count what could not be sent.** Sum `take_delivery(peer)` lengths over
   every binding into `undelivered_frames`. This is explicit loss, never
   silent: nothing more can be sent.
4. **Refuse staged work.** `refused = host.shutdown()` refuses every staged
   command (`SessionExpired`, FIFO) and closes every binding (T022§1).
5. **Discard held frames.** Count them into `held_discarded`.
6. **Checkpoint.** If `checkpoint` is set,
   `Some(host.save_checkpoint())`. Ingress is empty after step 4, so
   `PendingIngress` cannot occur. This is the consistent boundary D02 asks
   for: the host is fenced and immutable.
7. **Close transports.** `transport = server.shutdown()`: accepted
   connections are flushed (`Flush`, one shared `close_flush_timeout_ms`
   deadline) and closed with `Shutdown` (1); pending ones close with
   `Shutdown` (E§3).
8. Return `QuicHostShutdown { host, .. }`. The caller may still read
   captures, acknowledge them and save.

Steps 2 and 7 together mean that every receipt committed before shutdown is
either handed to QUIC and flushed with the close, or counted in
`undelivered_frames`.

### B§10. Threading and time

- **Synchronous.** `crpg-server` spawns no thread and opens no socket. The
  only threads, the one runtime and the UDP socket belong to the
  `QuicServer` that `crpg-net-quic` started (one `crpg-quic-server` thread,
  R6/R7). The pump calls only non-blocking transport methods (B§5).
  `wait`, `shutdown` and `Drop` are the blocking calls, made only by the
  caller.
- **One owner.** `QuicHost` is `Send` and is driven by one thread. There
  is no shared state, no lock and no callback. D02's "one serial authority
  owner … I/O tasks communicate through bounded queues" is met: the
  bounded queues are `crpg-net-quic`'s.
- **Injected monotonic time.** `crpg-server` reads no clock. `now_ms` is
  milliseconds on the caller's monotonic clock and must not decrease. The
  dedicated binary (T040) converts `std::time::Instant` with
  `origin.elapsed().as_millis()`, saturated to `u64`, plus an offset at or
  above the host's last accepted time (for a host restored from a
  checkpoint: the `now_ms` given to `load_checkpoint`). Tests use a
  synthetic counter. `now_ms` drives the host (rate and failure budgets,
  T022) and `STALL_TIMEOUT_MS`.
- **The transport's timers are separate.** The transport's own timers
  (hello and decision 5 s, idle 60 s, keep-alive 15 s, close flush 2 s;
  R10) run on real time inside `crpg-net-quic`. The pump must therefore
  run more often than `decision_timeout_ms` (5 s), or hellos close with
  `AuthTimeout`. Recommended: pump every ≤ 50 ms, or after `wait` returns.
- `AGENTS.md` invariant 7 ("no `SystemTime`, threads, sleeps or I/O") is
  amended by T023b to read: no clock, thread, sleep or socket in
  `crpg-server` source. The `quic` module reaches the network only through
  `crpg-net-quic`'s API, and `now_ms` stays injected.

### B§11. Determinism and the equivalence test

- The adapter's decisions are a function of four things only: the
  transport observations (events, frames and send results, in the order
  polled), `now_ms`, its own state, and the trusted calls made on it. It
  uses no randomness, reads no clock, iterates only `BTreeMap`s and visits
  connections in ascending `ConnectionId` order.
- Real-network arrival timing decides which frames are present at each
  pump. That is input nondeterminism, the reason T022 captures the
  admitted schedule. `ConnectionId`s are transport-assigned and never
  enter host state. The host sees only `PeerHandle`s minted in bind order.
- **Claim:** the host's state transitions are a function of the
  `HostCall` sequence alone. Feeding the same calls (same frame bytes,
  same `now_ms`) to a fresh host built from the same `HistoryWorld` and
  `HostConfig` produces identical per-call results and an identical final
  state, whether the bytes came over QUIC or from memory.
- **Proof** (B§14 case 5): replay every report's `calls` against an
  in-memory `Host`. The bytes are recovered from each test client's own
  send log, using the per-connection ordinal. Every result is asserted
  equal: `PeerHandle`, `IngestDisposition`, `PumpSummary`,
  `take_delivery` count, and the delivered bytes against what the client
  received. The final `authority_hash`, `executions`, every
  `read_captures` record and `last_capture` must also be equal.
  - A second, lockstep run sends each command only after the previous
    receipt. That fixes the admitted order, so the QUIC run (through an
    impairing relay) and a direct in-memory run with no adapter must
    produce identical captures, authority hash and per-peer decoded
    delivery.
  - Negative controls: a replay with one ingested byte flipped, and a
    replay with one `Ingest` call removed, must each diverge.
- Exact-build only: all comparisons are within one test run. There is no
  golden file, no cross-target hash, and no replay-format, `state_hash` or
  hash-exclusion change.

### B§12. Errors, precedence and poisoning

- Precedence is stated per method in B§3.2. `Poisoned` comes first on every
  `&mut self` method except `shutdown`. The `&self` accessors keep working.
- **Poisoning.** A `HostError` that the contract marks unreachable and
  that leaves state uncertain poisons the adapter: `Invariant`, or
  `Closed`/`TimeRegression` returned inside a pump, or any `Err` from
  `host.pump`. The current `pump` returns `Err(Host(e))`, and every later
  mutating call returns `Err(Poisoned)`. `shutdown` still runs B§9. No
  panic.
- `HostError::QueueFull` from `set_grants` (widening) is a normal error and
  does not poison. Neither does `HostError::FutureCaptureCursor` from
  `acknowledge_captures`, nor `HostError::Closed` from `tick`
  (unreachable).
- `ServerError`/`SendError` never surface to the caller. Each is mapped in
  B§4–B§8.

### B§16. Open questions (each with a recommendation)

1. **ADR-0026 for the adapter's durable choices.** These are: the 32-byte
   credential; newest-wins supersession; acknowledge on hand-off;
   drain-then-unbind; the `SlowConsumer` fence; the D02 shutdown order.
   `crates/crpg-server/AGENTS.md` asks for an ADR when the public surface
   changes, and these choices will bind T025b and T040.
   *Recommendation:* file ADR-0026, "QUIC host adapter: invitation
   credentials, fencing and backpressure", Accepted with this contract's
   approval.
2. **Credentials are exactly 32 operator-supplied bytes; no generation in
   `crpg-server`.** Generating them would need a CSPRNG dependency
   (`getrandom` is already locked for `crpg-net-quic`, but a
   `crpg-server` edge needs its own record).
   *Recommendation:* approve. Credential generation, the invitation file
   format (pin + address + credential) and operator tooling belong to T040,
   with their own dependency record if needed.
3. **A second connection presenting an already-bound invitation.**
   *Recommendation:* the newest wins. Fence the old binding
   (`Superseded`, code 9), then bind the new one. Until T025a, a client
   whose path died would otherwise be locked out for up to the 60 s idle
   timeout. A thief holding the credential can already act as the
   principal, and revocation is the remedy. Alternative: refuse the new
   connection with `ServerBusy`.
4. **Acknowledge host delivery when `try_send` accepts the frame** (E§7
   table), not on an application-level ack (lane 0 has none).
   *Recommendation:* approve. QUIC is reliable and ordered within a
   connection, and a lost connection ends the session (no resume until
   T025a/b). Loss recovery stays retry → cache hit → fresh receipt
   (case 4).
5. **Frames received before a peer's close are still admitted**
   (drain-then-unbind). The departed peer's delivery is
   discarded-and-acknowledged so it cannot block admission.
   *Recommendation:* approve. It makes "what was received" deterministic
   for a `Flush` close (case 15a) and matches E§7's drainability
   guarantee. Alternative: unbind on first detection and discard
   undrained frames. That is simpler, but which commands run would then
   depend on timing.
6. **Slow-consumer fence.** `STALL_TIMEOUT_MS = 10,000` of injected time,
   a constant, closed with `SessionFenced`. ADR-0025 fixes codes 0–9, so a
   new code would need a new ALPN. Until the fence, a stalled peer blocks
   host admission (T022 head-of-line).
   *Recommendation:* approve as a constant. Make it a tightening-only limit
   only when T040 has an operator configuration to put it in.
7. **One adapter owns the whole host.** `start` refuses a host with
   bindings or staged ingress (`HostInUse`), so a listen server mixing
   in-memory and QUIC peers on one host is not supported.
   *Recommendation:* approve. The mixed embedded and remote case needs an
   in-process binding API on the adapter, designed with the Godot bridge
   and T040, not guessed here.
8. **The credential is checked before the version** (`AuthRefused` takes
   precedence over `VersionRefused`).
   *Recommendation:* approve. An unauthenticated peer learns nothing about
   the host's wire version. A legitimate client with the wrong build still
   gets `VersionRefused`.
9. **Shutdown refuses staged work instead of completing it** (D02 permits
   both). It flushes delivery already committed first, and reports what
   could not be sent.
   *Recommendation:* approve. Completing would mean running a pump that
   can block behind a slow peer during shutdown.
10. **DER fixtures by `include_bytes!` from `crpg-net-quic`'s
    `tests/fixtures/`.** Copying them into this crate would need a
    `.gitattributes` line, which is a root file outside the single crate.
    *Recommendation:* approve the path reference. It is test-only, adds no
    build edge, and the pin literal check catches drift.
11. **Widening grants without egress room** returns `Host(QueueFull)` and
    leaves the invitation unchanged. The connection is not fenced.
    *Recommendation:* approve. The operator retries, and nothing is lost
    or leaked.
12. **Serialization with T039**, which also edits `crpg-server`'s
    `lib.rs`, `AGENTS.md` and architecture doc.
    *Recommendation:* land T023b and T039 one after the other, in approval
    order, and rebase the second one's docs. They touch no common source
    file other than `lib.rs`'s module list.
13. **In-crate visibility changes in `host.rs`** (B§3.6, `pub(crate)` only).
    *Recommendation:* approve as an internal change, not a public-surface
    change and not a separate task.

## Implementation blocker and decision — 2026-10-05 (UTC)

The T023b implementer stopped before writing code. Cases 10, 12, 14 and 16
assume a client that stops reading blocks the host within a few hundred
frames. `crpg-net-quic` hardcodes 1,048,576-byte QUIC stream windows
(src/tls.rs), so a stalled client absorbs about 40,000 small delivery
frames before `try_send` reports `QueueFull` (measured: 40,331 frames,
1,048,606 framed bytes).

`crpg-net-quic` only, adds a tightening-only flow-control window limit and
an ADR-0025 addendum. T023b's tests then configure small windows and keep
their designed shape. T023c is also the first attempt at the intermittent
Windows close-code failure (`Reset` instead of `Peer { code: 9 }`), per the
user's choice to try the smaller-windows fix before changing any test
expectation. T023b resumes after T023c lands, and its stall cases are
re-checked against the new limit.

#### A§1.2 B's stall bound over real QUIC

Setup (the `crpg-net-quic` rig):

- B's client: `inbound_frames: 1`, `inbound_bytes: 65_536`,
  `stream_window_bytes = connection_window_bytes = 65_540`.
- The server accepts B with the welcome, then sends A§1.1's B frame sizes
  in order.
- The count is the number of `Ok` sends before a `QueueFull` that persists
  across 150 attempts made 2 ms apart. Each configuration ran 5 times.

| Server `outbound` per connection | `Ok` sends (initial + `EndTurn` frames) | Formula |
|---|---|---|
| 1 frame / 65,536 bytes | **2,642** (5 of 5 runs) | 2,640 + 1 + 1 |
| 128 frames / 2 MiB (v1 egress) | **2,769** (5 of 5 runs) | 2,640 + 1 + 128 |

**Formula.** C§1.3, generalized to a server queue of Q frames:
`N_B = m + 1 + Q`. Here m is the largest number of whole frames with
`21 + Σ framed ≤ min(W, C)`.

- `21 + 34 + 126·23 + 257·24 + 25·(m − 384) ≤ 65,540` gives m = 2,640:
  the initial frame plus `EndTurn`s 1..=2,639.
- `EndTurn` 2,640 is the partly written frame.
- `EndTurn`s 2,641..=2,768 fill a 128-frame queue.
- The no-update condition holds: B reads 21 + 34 + 23 = 78 bytes, which is
  less than 65,540 / 8.
- B's client stats at the bound were `(1, 30, true)` in every run.

With a 1-frame queue each run took 6.0 s, against 0.33 s with 128 frames.
Every send waits for the writer to pop the previous frame (A§2.1).

### A§2. Why C§10 as written is not enough

1. **A 1-frame server outbound queue fences peers that are reading (a false
   `SlowConsumer`).**
   - B§5 phase 5 sets `stalled_since` on the first `QueueFull`. It clears
     `stalled_since` only on a pump in which every frame of the log was
     accepted.
   - With `outbound.per_peer_frames = 1` (case 12 as approved, kept by
     C§10), one pump hands a connection one frame. It can hand more only if
     the writer pops between two `try_send`s, which it normally does not.
   - So any peer that gets more than one frame per pump on average keeps a
     backlog. That includes A's receipts at four commands per pump, and B
     before its window fills. The backlog never clears `stalled_since`, and
     the peer is fenced 10 s of injected time later, long before the
     designed stall.
   - A§1.2's 6 s against 0.33 s shows the per-frame writer hand-off.
   - With the queue at the T022 per-peer log cap (128 frames and 2 MiB, the
     v1 egress values), a pump can always hand off a whole log once the
     transport has drained. The stall therefore clears deterministically
     after B reads.
2. **The rate burst is smaller than one pump's drain.**
   - Rate tokens are charged at `ingest`. The `TokenBucket` has an 80-frame
     burst and refills 40 frames/s. Every successful rate check deducts,
     including a held retry that is then refused `QueueFull`.
   - B§6 drains up to `MAX_DRAIN_PER_CONNECTION` = 128 frames per pump.
   - At server inbound v1, 128 frames queue behind a held frame plus 1
     parked, and on resume they are drained in one pump. At most 80 pass;
     the rest are `RateLimited` and dropped, although the client sent at
     the sustained rate.
   - Case 12 requires `frames_refused == 0` and every ordinal staged once.
     So the backlog behind the held frame must stay below the remaining
     burst, and the server inbound queue is tightened for the stall cases
     (A§3.1).
   - The same mechanism means that B§6's "Nothing is lost" is not true in
     general (A§7 Q6).
3. **The capture ledger binds at 4,096.** Admission blocks once 4,096
   accepted commands are unacknowledged, unless the trusted consumer
   acknowledges captures. The stall schedules below stay under that (at
   most 3,034). Case 10 uses the limit on purpose.
4. **Case 10's "staged just before" needs blocked admission.**
   - The pump handles events (where supersession fences A1) before drain
     and admission.
   - A frame A1 sends in the supersession pump is drained from a `Retiring`
     connection and discarded, never staged.
   - A frame drained in an earlier pump is admitted in that same pump.
   - So an A1 command can be staged and not yet admitted only while
     admission is blocked.
5. **`Host::shutdown` refusals carry `seq: None`.** T022 does not decode at
   shutdown. Case 16's FIFO order is therefore asserted by peer order
   against the trace, not by seq.

#### A§3.1 Limits

```rust
/// Server for the stall cases (12, 14, 16): v1 except a tightened inbound
/// queue, so that the backlog behind a held frame (8 queued + 1 parked)
/// stays inside the 80-frame rate burst (T023b A§2.2). Outbound stays v1
/// egress: 128 frames / 2 MiB, the T022 per-peer log cap (A§2.1).
pub fn stall_server_limits() -> ServerLimits {
    let mut limits = ServerLimits::v1();
    limits.inbound.per_peer_frames = 8;
    limits.inbound.per_peer_bytes = 4_096; // MAX_INTENT_FRAME_BYTES, the floor
    limits
}

/// T023c C§10's non-reading observer B.
pub fn stalled_client_limits() -> ClientLimits {
    ClientLimits {
        inbound_frames: 1,

    }
}
```

Both pass `validate()`. The floors are 4,096 inbound bytes and a 65,540-byte
window, and the host-wide caps stay at v1, at least the per-connection ones.

#### A§3.2 Constants

These are derived in A§1 and asserted where A§4 says so.

```rust
/// EndTurns per paced pump, and the injected step. 4 per 100 ms equals the
/// sustained 40 frames/s, so the 80-frame burst never drains (A§2.2).
pub const PACE: u64 = 4;
pub const PACE_STEP_MS: u64 = 100;
/// B's transport takes event_seq 1..=B_HANDED (initial + EndTurns 1..=2,768).
pub const B_HANDED: u64 = 2_769;
```

#### A§3.3 `end_turn_for(version, epoch, seq) -> Vec<u8>`

This is `host_capture`'s hand encoder with actor NetId `(seq − 1) % 3 + 1`
and `observed_tick` 0. A§1.1 shows that every `EndTurn` applies and that the
tick stays 0. A2 and B use their own epochs.

#### A§3.4 `drive`

`drive(qh, clock, a, conn_a, epoch_a, next_seq, stop) -> Vec<QuicPumpReport>`
runs one **c-pump** per iteration:

1. A `try_send`s the next `PACE` `EndTurn`s, each `Ok`. A's client outbound
   queue is v1.
2. Guard, with no pump (30 s): `qh.connection_stats(conn_a).inbound_frames ==
   PACE`.
3. `clock += PACE_STEP_MS`, then `qh.pump(clock)`.
4. Read every frame A has. A reads normally with `ClientLimits::v1()`.
5. Stop when `stop(&report)`.

The guard fixes how many frames each pump drains. Until a frame is held,
the queue is empty at the start of every iteration, so c-pump i drains
exactly seqs `4i − 3..=4i`. Every count below is therefore a function of the
schedule, not of arrival timing. A guard is a precondition, never an oracle.

#### A§3.5 `StallMirror`

`StallMirror { since: Option<u64>, through: u64 }` is fed every report,
together with that pump's `now_ms` and B's handle. In that pump's `calls`:

- `n` comes from `TakeDelivery { peer: B, result: Ok(n) }`;
- `k = through' − through` comes from `AcknowledgeDelivery { peer: B,
  through' }`, or is 0 if there is none.

If `k < n`, set `since.get_or_insert(now)`; otherwise set `since = None`.
That is B§5 phase 5's rule, recomputed from the public trace, so tests know
`stalled_since` without a new accessor.

**Numbering.** c-pumps are numbered from 1 after both clients have
connected. T is `now_ms` after the connects, so c-pump i runs at
`T + 100·i`. Connect pumps may use any step.

### A§7. Open questions (each with a recommendation)

1. **Server outbound queue for cases 12, 14 and 16.** Use v1 egress (128
   frames / 2 MiB) instead of the approved 1 frame / 65,536 bytes. A§2.1
   shows that a 1-frame queue would fence A, and B before its stall, as a
   `SlowConsumer` 10 s of injected time into any sustained schedule. 128
   equals the T022 per-peer log cap, so a drained transport takes a whole
   log in one pump. B's stall bound becomes 2,769 frames instead of 2,642
   (both measured).
   *Recommendation:* approve.
2. **Server inbound queue tightened to 8 frames / 4,096 bytes** for cases 12,
   14 and 16. Without it, the 129 frames that pile up behind case 12's held
   frame exceed the 80-frame rate burst on resume, so `frames_refused == 0`
   cannot hold (A§2.2).
   *Recommendation:* approve. 8 is at least `PACE` and keeps the
   reader-parked observation.
3. **Assert the derived counts exactly.** The counts are: stall start at
   c-pump 693 (B's event_seq 2,770 refused); first `backpressured: 1` at
   c-pump 725 with head 2,897; held ordinal 3,025; n = 3,034; and, in case
   16, 130 refusals and `undelivered_frames == 128`. These are additions,
   not changes. They rest on T023c's formula, whose exact counts pass on
   both operating systems, and on A§1.2 (5 of 5 runs).
   *Recommendation:* assert them exactly. Alternative: assert only the
   approved shape, with n computed from observation.
4. **How case 10 blocks admission.**
   - (a) The capture ledger: 4,097 commands with A1 reading, then an
     `acknowledge_captures`. This keeps handle 2.
   - (b) A1 as a stalled client with small windows: 1,664 commands, but it
     adds a stall timer and window tuning to a case that C§10 left
     untouched.
   - (c) Pre-filling captures in memory through a peer that is then unbound
     before `start`. This is cheapest, but A2's handle becomes 3, which
     changes an approved value.

   *Recommendation:* (a).
5. **Case 16 readings.**
   - B is the observer and stages two `EndTurn`s it cannot control, sent
     after admission blocks. That is the only way for B to have staged work
     that shutdown refuses.
   - FIFO is checked by peer order, because shutdown refusals have `seq:
     None`.
   - "`held_discarded` matches" is read as "equals the last report's
     `held`" (1).

   *Recommendation:* approve all three readings.
6. **B§6's "Nothing is lost" is not true in general.** Two effects (A§2.2):
   - A held frame's retry spends a rate token on every pump. A pump cadence
     under 25 ms while a frame is held drains the bucket, and the held frame
     is then dropped as `RateLimited`.
   - A backlog behind a hold that is larger than the remaining burst is
     partly dropped on resume, although the client sent at the sustained
     rate.

   Lane-0 recovery stays a retry by seq, which case 13's resend of seq 81
   shows. The options are:
   - (a) correct the B§6 text, and add a `crates/crpg-server/AGENTS.md` trap
     and a completion-record limitation, with no behaviour change;
   - (b) also skip the held retry while the host's ingress has no room, via
     a new `pub(crate)` host accessor of the B§3.6 kind.

   Capping the per-pump drain by the available tokens is not an option: it
   would contradict case 13, which requires `RateLimited` drops.
   *Recommendation:* (a) now; (b) only if T040's operator cadence makes
   pumps under 25 ms likely.
7. **Real-time cost.** Cases 10, 12, 14 and 16 (×2) run about 4,000 paced
   pumps, plus case 16's 2 s flush wait twice. The per-pump cost over real
   QUIC is unmeasured, because the adapter does not exist yet.
   *Recommendation:* accept. If the suite exceeds about 60 s on CI, raise
   `PACE` with a proportional step and an inbound queue to match, keeping
   backlog + held ≤ 79. The seq counts stay the same; the c-pump numbers
   change.
8. **Case 13's guard** (A§4) is a precondition the approved text implies:
   all 100 frames must be queued before the pump.
   *Recommendation:* approve it as a clarification.
