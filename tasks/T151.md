## Task
Give the bridge a protocol v4 session beside its v2 one, so a Godot client
can see positions and `Moved`, move a combatant in turn-based play
(`DeclareMove`, lane 0) and send real-time moves (`MoveTo`/`Halt`, lane 1)
with their receipts, all through the embedded authority. Today every session
is v2: `HostConfig { protocol: V2 }` and `bind_snapshot_peer`
(`crates/crpg-godot/src/core/mod.rs:299–334`), a v2 replica decoding whole
frames itself (`crates/crpg-godot/src/core/client.rs:290–329`), no tick, and a
`Transfer` entry fences 54 (`crates/crpg-godot/src/core/authority.rs:55–77`).

- **T151a — the v4 client half.** `ClientV4` over `ReassemblyPoolV4`,
  `ReplicaWorldV4` and `MoveOutbox`; the view's position columns, `Moved`
  events and move receipts.
- **T151b — the v4 session on the run loop, and `BridgeCore`.** `open_v4`
  (mesh bound from the encounter's area, the player bound with
  `bind_v4_peer`, the host wrapped in T154's `LocalHost` and run by
  `crpg_server::runner`), the NPC driver as the loop's AI hook, `poll` over
  `LocalClient` with legal options read between cycles, and the three move
  entry points.
- **T151c — the GDExtension surface (S-set).** `open_v4`, `declare_move`,
  `move_to`, `halt` and four view getters, proven headless by a new
  `apps/client/tests/movement.gd`.

The v2 session, every existing test and every GDScript script keep every
byte and behaviour they have. T049 interpolation (G1), T026 prediction (G2)
and T050 click-to-move (G3) are later tasks.

## Readings
Design decisions this contract makes. Each needs approval with the contract.

1. **v4 is a second session kind, not a replacement.** `open` keeps the v2
   session byte for byte; `open_v4` opens the v4 one. Both drafts replaced
   v2, but the 45 existing `#[cfg(test)]` cases and `tests/bridge.rs` drive
   v2 bytes (`crates/crpg-godot/src/core/client/tests.rs:7–11` encodes v2
   frames; `crates/crpg-godot/src/core/tests.rs` crafts v2 intents), so
   replacing would rewrite them, which `AGENTS.md` forbids without the user.
   *Rejected:* replacing now (Question 2).
2. **The player binds v4; the NPC stays a v2 `bind_peer`; `HostConfig` stays
   `V2`.** `bind_v3_peer`, and so `bind_v4_peer`, ignores
   `HostConfig.protocol` (`crates/crpg-server/src/host.rs:1177–1179`); the
   NPC reads no delivery (`crates/crpg-godot/src/core/authority.rs:584–592`).
   Draft A's choice. *Rejected:* an NPC v4 session (grants and a transfer
   for bytes nobody reads).
3. **Least-privilege fact grants.** The player binds with
   `FactGrants::default()` (denies every fact family,
   `crates/crpg-server/src/host.rs:252`) and `PauseRights::default()`
   (`crates/crpg-net/src/protocol_v3.rs:257–263`): no view member reads a
   fact, and the bridge sends no pause intent. Health and turn come from the
   disclosure grants, as in v2 (`crates/crpg-godot/src/core/authority.rs:647–675`).
   *Rejected:* draft A's full grants (traffic nothing reads; a later view
   member widens them with one `set_fact_grants` call).
4. **The mesh is bound at open from the encounter's area.** Without a mesh
   every `DeclareMove` is `IllegalAction` (`tasks/T037.md:145–150`), and the
   bridge is the embedding that loads the area. The area is the one owning
   the encounter's first participant placement (the `Placements` document's
   `area`, `crates/crpg-godot/src/core/authority.rs:797–810`), bound with
   `bind_area_bounds(bounds.min, bounds.max)` (`crates/crpg-server/src/host.rs:3412–3422`)
   before any peer binds. v2 sessions bind nothing (the binding changes the
   authority hash the v2 oracle test pins). Neither draft.
5. **A snapshot session needs its `Published` reply.** Until the host ingests
   `TransferUp::Published` for the in-flight transfer, a v3/v4 session gets
   at most one page per 10 ticks (`crates/crpg-server/src/host.rs:226–227`,
   `:3043–3050`; `crates/crpg-server/src/host_v3.rs:107–117`). So the client
   half answers each `TransferOutcome::Published` with
   `transfer_v3::encode_up(&TransferUp::Published { epoch, transfer })`, and
   T154a's `LocalHost` intake feeds `0x82` up frames to `ingest_transfer`
   (`crates/crpg-server/src/host.rs:2985`; T154 B-6). Neither draft.
6. **One FIFO per direction; frames routed by their first byte.** Every
   subprotocol already starts with a distinct version byte: `0x82`
   (`crates/crpg-net/src/transfer_v3.rs:39`), `0xA1`
   (`crates/crpg-net/src/movement_v4.rs:32`) and `4` for lane 0
   (`crates/crpg-net/src/protocol_v4.rs:27`), and each decoder checks it.
   `link.rs` is unchanged. The server side of the same routing, on a v4
   session's `LocalClient`, is T154a's B-6 (`0x82` → `ingest_transfer`,
   anything else → `ingest`) and T154c's B-11 (`0xA1` → `ingest_move`). A
   later QUIC adapter feeds `ClientV4` the frames of its three lanes the same
   way. Draft A's choice. *Rejected:* draft B's "demux by source" (the link
   carries no source; adding a tag or a second link changes `link.rs` and
   its K3 tests).
7. **The server's run loop owns the clock; the bridge never ticks**
   (D65a; supersedes this Reading's first version, "the authority runs the
   clock at 20 Hz in v4 sessions", and withdraws Question 4). Samples
   follow committed ticks (`tasks/T037.md:681–695`) and lane-1 intents are
   decided only in `advance` (`:765–768`), so a v4 session needs ticks; they
   come from T154's `HostLoop` (20 Hz grid, skip-not-burst, T154 Readings 2–3)
   on `crpg_server::runner`'s thread, the same loop a dedicated server runs.
   The bridge calls no `advance`, `pump`, `ingest*`, `take_*` or
   `acknowledge_*` on a v4 host; `shell.rs`'s clock feeds only the client
   half (`ClientV4::step`'s `now_ms`, the pool's timers). *Rejected:* the
   bridge's own pacer (the first version; D65a); the bridge owning the
   thread (T154 Reading 1).
8. **Lane-1 refusals: transient ones are held server-side; others are
   counted.** The client's `MoveOutbox` expects exactly one receipt per sent
   intent, in order (`crates/crpg-net/src/outbox_v4.rs:111–135`), and a
   refused frame gets none (`tasks/T037.md:719–741`). T154c's B-11 holds a
   frame refused `QueueFull` or `RateLimited` and retries it first on later
   cycles. Any other refusal cannot happen to a conforming client half; the
   local link counts it in `LinkStats.refused` and drops it (T154c B-11), and
   the bridge reports a rise of that count as `INTENT_REFUSED` (B-B6), not as
   a fence, because the count does not say which lane refused. *Rejected:*
   dropping a transient refusal (the outbox would wait forever) and client
   resends (a resend of an admitted `seq` re-queues its receipt,
   `tasks/T037.md:758–763`, and breaks `receive`).
9. **Receipts are never dropped; samples may be.** T154c's B-12 keeps
   receipts the down queue cannot take in the link's backlog, flushed before
   new receipts are taken (L3, `tasks/T037.md:785–790`); B-13 takes samples
   every cycle (taking frees host egress, `:697–699`) and drops the ones that
   do not fit. The bridge only reads what arrives.
10. **The client half applies through the pool.** One receiver in
    `GateMode::AwaitSnapshot` of a `ReassemblyPoolV4` built from
    `TransferLimitsV3::v3()` (`crates/crpg-net/src/reassembly_v3.rs:139`);
    each update is applied by `ReplicaWorldV4::apply_snapshot` or
    `apply_delta` (`crates/crpg-net/src/replica_v4.rs:96`, `:135`). Both
    drafts.
11. **Lane-0 intents are `codec_v4`.** `legal_intents` keeps v1 bodies
    (`crates/crpg-server/src/host.rs:286–292`); the client converts
    `DeclareAction`/`EndTurn` to their v4 twins
    (`crates/crpg-net/src/protocol_v4.rs:95–122`) when it encodes. `Offered`
    keeps its fields (client tests build it, `crates/crpg-godot/src/core/client/tests.rs:112–118`).
    Draft A's choice.
12. **Positions are per-row columns.** `positions()` (three raw ints per row),
    `position_known()` and `moving()`, indexed like `net_ids()`, keeping
    ADR-0033 §10's rule that every per-entity array is indexed the same way
    (`docs/adr/0033-godot-bridge.md:271`). A v2 view fills them with zeros.
    Draft A's choice. *Rejected:* draft B's separate `position_ids` list
    (GDScript would join two id lists).
13. **`Moved` is an event of kind `moved`, only for a live row.** The replica
    stores nothing from it (`crates/crpg-net/src/replica_v4.rs:183–184`); a
    presenter treats an id with no row as not visible (`tasks/T026p.md:260–267`).
    Points travel as one flat integer list (`ViewValue::Ints`). Draft B's
    live-row rule, draft A's encoding.
14. **The turn-based move names no actor.** `declare_move(revision, x, y, z)`
    takes the actor of the current options (all options are the active
    actor's, `docs/adr/0033-godot-bridge.md:195–196`), with `submit_option`'s
    revision and pending rules, keeping ADR-0033's "GDScript cannot name an
    actor" for lane 0 (`:304–312`). Neither draft.
15. **Lane-1 moves name the actor by `NetId`.** Real-time control can be a
    party, so `move_to(actor, x, y, z)` and `halt(actor)` take a `NetId`
    (never an `EntityId`, `:236`). The client does not check it against the
    rows: the host decides (`NotAuthorized`, `tasks/T037.md:734–737`).
    *Rejected:* draft B's client-side code 6 for an unknown id. Question 3.
16. **No new code.** Every new refusal maps into the closed table
    (`crates/crpg-godot/src/core/errors.rs:12–53`); 54 stays v2-only. Both
    drafts. *Rejected:* draft B's fatal 51 for `OutboxError::Exhausted`
    (`SEQ_LAST` is `u64::MAX - 1`, `crates/crpg-net/src/protocol.rs:48`; it is
    a refusal like `Full`).
17. **Embedded only.** T150 expects T151 to pin `connect_movement` use
    (`tasks/T150.md:1600–1603`, `:1755–1756`); this contract does not
    (Question 1, answered (a), D65c).
18. **The v2 session stays on today's bridge-driven `Authority`** (Question
    5). Moving it onto the run loop would tick it: every v2 delta frame
    carries `server_tick` (`crates/crpg-net/src/protocol.rs:295–296`), so
    every byte a v2 session sends would change, and the existing cases in
    `src/core/tests.rs` and `src/core/authority/tests.rs` drive
    `Authority::step` and `poll` synchronously at fixed `now_ms`, which a
    background thread cannot satisfy without rewriting them. D65d keeps v2
    beside v4 with new work on v4 only, and the root `AGENTS.md` forbids
    weakening existing tests without the user. So `open` and v2 `poll` keep
    every byte and behaviour (B-B7); only v4 sessions run on the loop.
    *Rejected:* both session kinds on the loop now (the user's call:
    Question 5).
19. **Legal options are read between cycles, never by blocking the frame.**
    Options are the host's (`crates/crpg-godot/AGENTS.md` invariant 10) and
    the host lives on the loop thread. Each v4 `poll` with no read
    outstanding `submit`s one closure to the runner (T154 R-3) that returns
    the player's `legal_intents` and the link's `LinkStats.refused`; a later
    `poll` adopts the reply with `try_recv`. So a view's options are at most
    one poll older than its frames, and `poll` never waits on the loop.
    *Rejected:* `RunnerHandle::call` in `poll` (blocks the frame on the loop
    thread); options pushed by the AI hook (computed before `advance`, so a
    tick that ends a turn would leave them stale); a `Mutex<Host>` (T154
    Reading 8).
20. **NPCs act only through the AI hook; until the switch to `drive_ai`,
    the hook is today's NPC driver.** T153's `drive_ai` needs `crpg_ai::Sides`,
    which needs a `crpg-godot → crpg-ai` edge nobody has approved yet; so
    T151b moves today's driver (`choose_npc`, its 600 ms `NpcPacer`, the v2
    NPC peer, `crates/crpg-godot/src/core/authority.rs:31–51`, `:110–132`, `:522–563`)
    into an `NpcHook` that `LocalHost::set_ai` runs once per cycle with
    `&mut Host` (T154 B-8). The hook also acknowledges the NPC's delivery
    unread each cycle, as today's step does (`:584–592`), so the NPC's log
    never blocks admission. It cannot return a bridge `Fault`, only a
    `HostError` (T154 `AiHook`), so an NPC refusal or rejection no longer
    fences: nothing is staged, and the pacer re-arms. The switch of the
    hook's body to `drive_ai` is a later `crpg-godot` task (Out of scope).
    *Rejected:* the bridge driving the NPC from `poll` (a client-side stand-in
    for a server duty, D65a).

## Interface
Additions only, unless marked. Every public item has a doc comment
(`#![warn(missing_docs)]`, `crates/crpg-godot/src/lib.rs`). No float,
`HashMap`/`HashSet`, clock read, thread spawn or `unsafe` in `crpg-godot` code
below `shell.rs` (`crates/crpg-godot/AGENTS.md:12–15`, `:34–35`); a v4
session's loop thread and `SystemClock` are `crpg_server::runner`'s (B-B9).

`authority` (BR-10, `docs/adr/0033-godot-bridge.md:64–65`).
