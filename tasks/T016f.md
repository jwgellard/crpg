# T016f — Explicit encounter completion and reentry (`crpg-sim`)

pending.** Work package A2 of the
[project gap remediation plan](../docs/reviews/REMEDIATION_PLAN_2026-09-27.md)

## Decisions (proposed ADR-0014 content; binding only once approved)

1. **New release operation.** `end_encounter(world) -> Result<EncounterSummary,
   CombatError>` releases the active encounter and returns its retained
   outcome. `combat = None` fails before any mutation as `NoEncounter`
   (existing variant, stable `Display` — no new error shape). Otherwise the
   operation is infallible: the summary is built first, then state is
   stripped, so there is no partial-failure path.
2. **Release retains results without retaining scheduling.** The summary
   carries `{encounter, ruleset}` ULIDs, the closing `round`, and one
   `ParticipantResult {placement, entity, health, dead}` per combatant in
   store insertion (authored participant) order. Release then removes every
   combatant timeline entry, clears the combatant store, and sets
   `combat = None`. Entities stay live (no despawn, no `Despawned` events);
   death is not equated with despawn. No `Died` is emitted by release —
   deaths were already emitted exactly once at their kills, and repeated
   cleanup emits nothing. Transforms, events (including queued `Died`
   envelopes for consumers), RNG, tick, interners, and outsider timeline
   entries are untouched: no unrelated world state is cleared.
3. **Release is allowed any time the encounter is active** (terminal or
   mid-fight). Aborting an in-progress fight is caller (host/GM) intent;
   the summary reflects the moment of release. The acceptance sequence runs
   release on a terminal encounter; mid-fight release is the same code path
   with partial results. No terminal-only gate and no new error variant.
4. **Despawn of the active combatant advances or terminates, never strands.**
   When `despawn` removes the entity holding `combat.active` (and
   combatants remain), the combat tail runs the same rule as the
   `perform_action` advance via one shared crate-private helper:
   timeline nonempty with two or more alive → `active` = new head with one
   `TurnStart` refresh; timeline empty with two or more alive → round
   rollover (`round + 1`, `RoundStart` refresh of all alive, re-add alive at
   their initiative keys, `active` = head with `TurnStart`); otherwise
   terminal (`active = None`). Despawn of a non-active combatant leaves
   `active` untouched (existing behavior, pinned); despawn of the last
   combatant releases via the T016e rule. Turn logic stays owned by the
   combat module — `despawn` calls the shared helper, it does not
   reimplement the rule.
5. **Second encounters reuse content, never runtime identity.** After
   release, `start_encounter` runs unchanged on a rebuilt `EncounterSpec`
   (same placement/ability ULIDs are fine); new entities are minted by the
   continuing arena with fresh `EntityId`s. A second fight is a deterministic
   continuation (RNG stream and tick carry on), not a byte-repeat of the
   first — behavior is pinned, hash equality across fights is not claimed.
6. **Load-invariant compatibility.** Released worlds are ordinary non-combat
   worlds (`combat = None`, empty combatants) and satisfy the T016e checks
   trivially; stranded states can no longer be produced by public
   operations, but `active = None` remains loadable for saves written
   before this task. `start_encounter`'s empty-timeline caller contract is
   unchanged.

## Public interface (exact shapes; re-export at the crate root)

```rust
/// Terminal per-participant result retained by `end_encounter` (never persisted).
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ParticipantResult {
    /// The authored placement this combatant was instantiated from.
    pub placement: Ulid,
    /// The runtime entity (stays live across release).
    pub entity: EntityId,
    /// Health at release (zero for the dead).
    pub health: u32,
    /// Whether this combatant died (`health == 0` agreement holds).
    pub dead: bool,
}

/// The retained outcome of one released encounter (never persisted).
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct EncounterSummary {
    /// Encounter identity the released fight was built from.
    pub encounter: Ulid,
    /// Ruleset identity governing the released fight.
    pub ruleset: Ulid,
    /// Rounds completed at release.
    pub round: u32,
    /// Per-participant results in authored participant order.
    pub results: Vec<ParticipantResult>,
}

/// Releases the active encounter, retaining its summary for authoritative
/// consumers. `combat = None` fails as `NoEncounter` without mutation;
/// otherwise strips combat scheduling and components, keeps entities live,
/// and emits no events.
pub fn end_encounter(world: &mut World) -> Result<EncounterSummary, CombatError>;
```

`World` gains no new accessor. The advance helper is crate-private
(`pub(crate) fn advance_after_removal(world: &mut World)` in `combat.rs`,
called from `World::despawn` only when `combat` is `Some` and the removed
id held `active`). `CombatError` is untouched.

## Tests

`tests/combat.rs` (turn behavior):

- Despawn-waiter pins `active` (existing single case stays; add the
  three-participant shape where the waiter pool is untouched and the turn
  never moves).
- Despawn-active with two alive remaining (three-participant fixture):
  `active` passes to the new head with exactly one `TurnStart` refresh on
  that head and no other balance touched; the despawned entity is gone with
  one `Despawned` and no `Died`.
- Despawn-active leaving one alive: terminal (`active = None`, no rollover,
  no refresh); despawn-active leaving zero combatants: T016e release.
- Rollover-on-despawn row only where reachable through public operations
  (document if unreachable: timeline-empty-with-two-alive cannot be built
  without manual `timeline_mut` surgery — then the helper arm is covered by
  construction review, not a fabricated world).

`tests/combat_persistence.rs` (lifecycle):

- Full acceptance: start → fight to terminal (exactly one `Died`) → save →
  load → `end_encounter` (summary: encounter/ruleset ULIDs, round, ordered
  per-participant health/dead with the corpse at zero) → save → load as a
  non-combat world (`combat = None`, entities live, events retained) →
  `start_encounter` again with the same content → play → save → reload.
- Release-then-save bytes equal save-then-load-then-release bytes
  (release commutes with save/load).
- `end_encounter` on a non-combat world: `NoEncounter`, byte-identical
  rollback. Repeated `end_encounter`: second is `NoEncounter` with no new
  events. Despawned corpse re-despawn: `false`, no second `Died`.
- Post-release `perform_action`: `NoEncounter` with unchanged bytes.
- Existing suites pass unmodified in intent (the two realigned
  `hash_sensitivity` rows stay as T016e left them).
