## S§1. Findings (from the code)

1. **Narrowing resets the delivery sequence.** `Host::set_grants`
   clears the log, bumps the private `generation`, sets
   `next_event_seq = 1`, `delivered = 0` and `resync_pending`, stages
   `full_state_ops` as delta frames, and returns
   `GrantUpdate::RebindRequired` (`src/host.rs:699-712`). That violates
   T024 S§11 item 2 for any peer that keeps its receiver, which is why the
   QUIC adapter fences instead of calling it (`src/quic.rs:1110-1112`;
   ADR-0026 item 7).
2. **Two existing tests pin that reset.**
   `narrowing_grants_resynchronize_without_leak` asserts `RebindRequired`
   and `event_seq == 1` after narrowing (`tests/host_capture.rs:1491-1508`),
   and `error_precedence_matrix` asserts `RebindRequired` and then drains
   (`tests/host_capture.rs:2283-2286`); its `drain` helper decodes every
   frame as a delta and acknowledges by `event_seq`
   (`tests/host_capture.rs:612-626`). Changing what `set_grants` does for
   `bind_peer` sessions would break both. So the new behaviour is
   per-session and opt-in (S§2 item 1), and those tests stay untouched.
3. **The adapter acknowledges by count.** It acks
   `through = bound.acked + accepted` (`src/quic.rs:899`), which is right
   only while every log entry is one delta and entries leave only by
   acknowledgement. Transfer frames carry no `event_seq` and a snapshot
   clears unsent entries, so the log needs its own position number, the
   ordinal (S§6).
4. **The adapter cannot tell a transfer frame from a delta** without
   reading the first byte, which T024 S§4 forbids; `take_delivery` returns
   bare `Vec<Vec<u8>>` (`src/host.rs:1423-1431`). Delivery entries need a
   kind (S§5).
5. `PeerView` already holds every filter a body needs: `map` (present,
   live entities, `plan_map`, `src/host.rs:1796-1822`), `health`
   (`:1994-2003`), and `turn` with an undisclosed active head read as
   `None` (`:2016-2028`). `full_state_ops` (`:2032-2054`) is the same fact
   set as T024 S§5.4.
6. Sessions are not checkpointed (`src/checkpoint.rs:3-10`), so no
   transfer state can survive a save, and no `CHECKPOINT_VERSION` change is
   needed.
7. At v1 caps a staged snapshot always fits after the log is cleared: per
   peer at most 3 entries and 22,685 bytes (`Cancel` 21 + `Begin` ≤ 56 +
   one `Chunk` ≤ 22,599; T024 S§1.3) against 128 frames / 2,097,152 bytes;
   host-wide, the other 7 peers hold at most 7 × 2,097,152 = 14,680,064
   bytes against 16,777,216 (`POLICY_EGRESS_*`,
   `crates/crpg-net/src/protocol.rs:139-143`; `MAX_PEERS = 8`). The egress
   caps are fixed at `QueueCaps::v1_egress()` (`src/host.rs:482-483`).
8. The adapter's tests match `HostCall` exhaustively in `replay`
   (`tests/host_quic.rs:701-776`) and build `HostCall::BindPeer` literals
   (`tests/host_quic.rs:1340-1360`). New trace variants are possible; new
   fields on existing variants are not (S§13).
9. The existing intent rate buckets (`intent_frames`, `intent_bytes`;
   80-frame burst, 40 frames/s, `crates/crpg-net/src/protocol.rs:108-114`)
   are per session and spent per attempt by `ingest`
   (`src/host.rs:777-783`).
10. **Four more adapter sites assume one channel or count-based acks**
    (review 1). `drain_retiring` reads with the legacy `try_recv`
    (`src/quic.rs:805-823`); a departed peer's delivery is acknowledged
    through `bound.acked + n` (`:852-860`); and the shutdown flush sends
    with `try_send` and acknowledges `bound.acked + accepted`
    (`:1251-1277`), next to the live `deliver` ack of item 3. Under `/2`,
    T024q's legacy calls are views (Q§8.3): `try_send` is
    `try_send_channel(Lane0, ..)`, and `try_recv` returns `Ok(None)` and
    never `Closed` while a `Transfer` frame is at the head of the inbound
    queue, so the transport record (`held_frames`) is never released
    either (`crates/crpg-net-quic/src/server.rs:239-258`). Every one of
    these sites is therefore in T024h2's scope (S§15 items 2a, 3, 3a,
    3b).

## S§2. Decisions (and how the drafts' disagreements were settled)

1. **A snapshot session is opt-in, chosen at bind.**
   `Host::bind_snapshot_peer` binds a peer whose delivery channel also
   carries the `0x81` transfer subprotocol in one total order with lane-0
   frames (T024 S§11 item 3). `Host::bind_peer` is unchanged and keeps the
   T022 reset and `RebindRequired`. This is forced by the transport, not a
   convenience: a `crpg-lane0/1` connection cannot carry transfer frames,
   so its session must keep the old path (S§1 item 2; both drafts changed
   `set_grants` for everyone and would have broken two existing tests).
2. **Smaller, purely additive surface.** One method to bind, one tagged
   delivery view, one upstream handler, one read accessor, two small enums
   and one new `GrantUpdate` variant. No `HostError` variant, no
   `PumpSummary` field, no changed signature, no removed item. DeepSeek's
   `DeliveryFrame` (a changed `take_delivery` type), `TransferStatus`, the
   `PumpSummary` field and three `HostError` variants are not needed:
   refusals are a disposition (as `IngestDisposition` already does), and
   the ack keeps its signature with an ordinal meaning (S§6). It still
   changes the public surface, so it needs an ADR: ADR-0031 (S§22 Q3).
3. **Staging is atomic and immediate.** Narrowing and an honoured `Resync`
   plan the `Cancel`/`Begin`/`Chunk` entries, check room against the
   cleared log, and commit in the same call, or change nothing. There is
   no pending state and no staging point in `pump` or `take_delivery`
   (DeepSeek staged at the pump head, Beam in `set_grants` with a pending
   fallback). By S§1 item 7 the room check cannot fail at v1 caps; it is
   kept as the determine–reserve–commit rule (crate invariant 2).
4. **Segments per chunk: 8**, a private constant. Every valid v1 body
   (≤ 22,552 bytes) is then one chunk, so a transfer is `Begin` + one
   `Chunk` and no delta can sit inside it. The fixture's bodies are 14–20
   bytes, so 1 segment would give one chunk too; multi-chunk reassembly is
   `crpg-net`'s proof (T024 S§12 cases 10, 13, 18). Beam's caller-chosen
   default of 4 adds a parameter with no effect on coverage.
5. **Clear the unacknowledged log on narrowing and on `Resync`.** Every
   cleared entry has `event_seq ≤` the new cursor, and a receiver drops
   held deltas at or below the cursor at publication (T024 S§10.6 step 4),
   so clearing is invisible to the replica. On narrowing it is also what
   keeps unsent pre-narrowing facts and old chunks off the wire (T024 S§11
   item 5). A cleared receipt is re-staged by the client's retry (S§9.4).
6. **Trigger set:** narrowing a snapshot session, and a `Resync` naming an
   issued transfer id or none. Widening stays incremental deltas; binding
   stages delta state from seq 1 as today (the receiver starts `Live`,
   T024 S§10.1); nothing else stages a snapshot. Resume (T025b) adds its
   own trigger later.
7. **Cancel whenever a transfer is in flight.** Staging emits
   `Cancel(in-flight id)` first: reason `Aborted` for narrowing (T024 S§11
   item 5) and `Superseded` for a `Resync`. A `Resync` does not retire the
   in-flight id by itself, so a stale `Resync` that crosses a newer `Begin`
   still produces a clean `Cancel` + `Begin`.
8. **No `Resync` dedupe.** Any `Resync` whose `after` is an issued id, or
   none, is honoured. A dedupe window would deadlock if a client's `after`
   rule differs (a refused `Begin` leaves the receiver's `retired_through`
   below the refused id). The cost of a stale `Resync` is one extra
   transfer, bounded by the shared intent rate budget (S§9.2 step 5).
9. **Overflow policy: nothing new.** The host never appends past its caps
   (admission backpressure, `accepted_room`), never skips a delta, and
   heals a receiver's own overflow through `Resync` (T024 S§10.8 step 7).
   The adapter's slow-consumer fence stays the terminal case. No
   host-side cancel threshold and no host-side transfer deadline.
10. **Narrowing on QUIC keeps fencing until T024h2,** and for any
    `crpg-lane0/1` connection after it. T024h1 changes no adapter
    behaviour.

## S§5. Interface (T024h1, exact public Rust, additive)

```rust
/// What a delivery entry carries, so an adapter picks the channel without
/// reading bytes (T024 S§4).
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum DeliveryKind {
    /// A lane-0 delta frame (the host's `ProtocolSelection`).
    Delta,
    /// A snapshot-transfer frame (`crpg_net::codec_transfer`, first byte 0x81).
    Transfer,
}

/// One unacknowledged delivery entry.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct DeliveryEntry {
    /// Position in this session's delivery order, from 1, never reused
    /// within the session (S§6).
    pub ordinal: u64,
    /// Delta or transfer frame.
    pub kind: DeliveryKind,
    /// The encoded frame.
    pub bytes: Vec<u8>,
}

pub enum GrantUpdate {
    Unchanged,
    RebindRequired,
    /// New. Narrowing of a snapshot session: unacknowledged entries were
    /// discarded and a snapshot transfer staged; delivery continuity kept.
    SnapshotStaged,
}

/// The outcome of [`Host::ingest_transfer`].
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum TransferDisposition {
    /// `Published` for the in-flight transfer: it is retired.
    Published,
    /// `Resync`: a fresh snapshot transfer was staged.
    Resynced,
    /// `Published` for an issued transfer that is no longer in flight.
    Stale,
    /// Refused; nothing changed (rate tokens aside, S§9.2).
    Refused(TransferRefusal),
}

/// Why [`Host::ingest_transfer`] refused a frame.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum TransferRefusal {
    /// The handle is not bound.
    Unbound,
    /// The session was bound with `bind_peer` (no transfer channel).
    NotSnapshotPeer,
    /// The session's intent rate budget is spent.
    RateLimited,
    /// `crpg_net::codec_transfer::decode_up` failed.
    Malformed,
    /// The frame's epoch is not the session's.
    WrongEpoch,
    /// The frame names a transfer id this session never issued.
    UnknownTransfer,
}

/// A snapshot session's transfer ledger.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct TransferState {
    /// The id the next staged transfer will take (1 at bind).
    pub next_transfer: u64,
    /// The issued transfer not yet answered by `Published` or cancelled.
    pub in_flight: Option<u64>,
}

impl Host {
    /// As `bind_peer` (same precedence, errors and first delivery), but the
    /// session is a snapshot session (S§6.1).
    pub fn bind_snapshot_peer(&mut self, control: ControlGrant, grants: DisclosureGrants,
        now_ms: u64) -> Result<PeerHandle, HostError>;
    /// As `take_delivery` (same precedence, same pending-resync staging for
    /// `bind_peer` sessions), with each entry's ordinal and kind.
    pub fn take_delivery_entries(&mut self, peer: PeerHandle)
        -> Result<Vec<DeliveryEntry>, HostError>;
    /// One upstream transfer frame (S§9).
    pub fn ingest_transfer(&mut self, peer: PeerHandle, bytes: &[u8], now_ms: u64)
        -> Result<TransferDisposition, HostError>;
    /// `Ok(None)` for a `bind_peer` session; `Err(UnknownPeer)` if unbound.
    pub fn transfer_state(&self, peer: PeerHandle)
        -> Result<Option<TransferState>, HostError>;
}
```

Changed meaning, same signatures (doc comments updated):

- `acknowledge_delivery(peer, through)`: `through` is a delivery
  **ordinal** (S§6.2). In a `bind_peer` session every ordinal equals its
  entry's `event_seq`, so nothing changes there.
- `take_delivery(peer)`: in a snapshot session it also returns transfer
  frames, in order. Callers that cannot route them use
  `take_delivery_entries`.
- `set_grants(peer, grants)`: narrowing a snapshot session follows S§8 and
  returns `SnapshotStaged`.

## S§6. Sessions and the delivery ledger

### S§6.1 Two session kinds

| | lane-0 session (`bind_peer`) | snapshot session (`bind_snapshot_peer`) |
|---|---|---|
| First delivery | `full_state_ops` as deltas from seq 1 | the same |
| Narrowing | T022: reset to seq 1, `RebindRequired` (unchanged) | S§8: snapshot transfer, `SnapshotStaged`, no reset |
| Widening | incremental deltas | incremental deltas (unchanged) |
| `ingest_transfer` | `Refused(NotSnapshotPeer)` | S§9 |
| `transfer_state` | `Ok(None)` | `Ok(Some(..))` |

The kind is fixed for the session's life. Both kinds share every other
rule (admission, receipts, caches, caps, unbind, shutdown).

### S§6.2 Ordinals

- Every entry pushed to a session's log takes `ordinal = next_ordinal`,
  then `next_ordinal` advances by `checked_add(1)` (starts at 1; overflow
  is `CounterExhausted`). Delta pushes make that check where `push_frames`
  checks `next_event_seq` today (`src/host.rs:1676-1690`), with the same
  error. Snapshot staging refuses earlier, before any change, unless
  `next_ordinal + count < u64::MAX` (S§7 step 5; S§11 case 13).
  A delta also takes `event_seq = next_event_seq` and advances it; a
  transfer entry does not touch `next_event_seq`.
- `delivered` is the highest retired ordinal. `acknowledge_delivery(peer,
  through)`: `UnknownPeer` if unbound; `through > next_ordinal − 1` is
  `FutureDeliveryCursor { requested: through, last: next_ordinal − 1 }`;
  `through ≤ delivered` is an idempotent no-op; otherwise entries with
  `ordinal ≤ through` leave the log and `delivered = through`.
- **Clearing** (S§7 step 6) drops every entry and sets
  `delivered = next_ordinal − 1`: discarded entries count as retired. So
  an acknowledgement of an ordinal taken before a clear never removes an
  entry staged after it.
- In a lane-0 session, the T022 narrowing reset also resets
  `next_ordinal = 1` with `next_event_seq = 1` and `delivered = 0`, so
  ordinal and `event_seq` stay equal in every lane-0 session.
- A retry-cache receipt reference is `(generation, ordinal)` instead of
  `(generation, event_seq)`. A receipt is deliverable while
  `generation` matches and `ordinal > delivered`.

Private shape (recommended, not API): `LoggedFrame { ordinal: u64,
event_seq: Option<u64>, bytes: Vec<u8> }` (`Some` = delta), and new
`Session` fields `snapshot: bool`, `next_ordinal: u64`,
`next_transfer: u64`, `in_flight: Option<u64>`. `generation` and
`resync_pending` keep their T022 meaning and stay `0`/`false` in a
snapshot session.

## S§7. Snapshot staging

One private routine, `stage_snapshot(peer, grants, map, next_net,
cause)`, used by S§8 (cause `Narrowed`, with the new grants and map) and
S§9.3 (cause `Resync`, with the current ones). Steps 1–5 only read; step 6
onwards cannot fail.

1. `next_transfer == u64::MAX` → `Err(HostError::CounterExhausted)`.
2. If `in_flight == Some(old)`: entry `Cancel { epoch, transfer: old,
   reason }` encoded by `crpg_net::codec_transfer::encode_down`, with
   `reason = Aborted` for `Narrowed` and `Superseded` for `Resync`.
3. Body: `PeerView { grants, map }.snapshot_body(world)` (S§7.1).
4. Frames: `plan_transfer(epoch, TransferId(next_transfer),
   server_tick(), next_event_seq − 1, 8, &body)` — `Begin`, then one
   `Chunk` for every v1 body. A `CodecError` is
   `Err(HostError::Invariant("snapshot transfer failed to encode"))`
   (unreachable: at most 1,024 mapped entities).
5. Room against the cleared log: entry count ≤ `per_peer_frames`, their
   bytes ≤ `per_peer_bytes`, and `egress_bytes − log_bytes + bytes ≤
   host_bytes`; `next_ordinal + count` must stay below `u64::MAX`. A
   failure is `Err(QueueFull)` or `Err(CounterExhausted)` with nothing
   changed (unreachable at v1 caps, S§1 item 7).
6. Commit: for `Narrowed`, install the grants and map; clear the log
   (`egress_bytes −= log_bytes`, `log_bytes = 0`,
   `delivered = next_ordinal − 1`); push the entries in order (`Cancel` if
   any, `Begin`, `Chunk`) as `DeliveryKind::Transfer`; set
   `in_flight = Some(next_transfer)` and `next_transfer += 1`.

The private constant is `SNAPSHOT_SEGMENTS_PER_CHUNK: u8 = 8`.

### S§7.1 The body (`PeerView::snapshot_body`, private)

The T024 S§5.4 facts, from the same predicates as `full_state_ops`:

- `entities`: one `SnapshotEntity` per `map` entry, ascending `NetId`;
- `health`: `PeerView::health(world, entity)` mapped field for field to
  `HealthFact { health, max_health, dead }` (so it needs presence, the
  `health` flag and a combatant);
- `turn`: `PeerView::turn(world)` mapped to `TurnFact { active, round }`
  (needs `turn_state` and an encounter; `active` is `None` unless the head
  is mapped).

Nothing else can enter: no events, receipts, rolls, grants, raw
`EntityId`s, World or save bytes.

## S§8. Seamless narrowing (`set_grants` on a snapshot session)

Precedence before anything changes is today's: `Closed` → `UnknownPeer` →
`normalize_grants` errors → `plan_map` errors. Then:

- **Narrowing** (`is_narrowing(old, new)`): `stage_snapshot(.., cause
  Narrowed)` with the new grants and map. `Ok` → `Ok(GrantUpdate::SnapshotStaged)`.
  An error from S§7 steps 1–5 is returned with nothing changed, the grants
  included (unlike the lane-0 path's `QueueFull` with grants installed,
  which stays as it is for lane-0 sessions).
- **Widening or identical:** today's code, unchanged: incremental deltas at
  `next_event_seq`, `Unchanged`, or `QueueFull` with nothing changed. A
  transfer in flight is not touched: the new deltas are above its cursor,
  so the receiver holds them until it publishes.

`next_event_seq`, `next_transfer` and the epoch never go back. The next
delta after the snapshot is `cursor + 1`.

## S§9. Upstream transfer frames (`ingest_transfer`)

### S§9.1 Messages (the T024 S§5.2 upstream set)

`Published { epoch, transfer }` and `Resync { epoch, after, reason }`,
decoded by `crpg_net::codec_transfer::decode_up`. `reason` is not used by
the host.

### S§9.2 Precedence (first failure wins)

1. Host closed → `Err(HostError::Closed)`.
2. `now_ms` below the last accepted time → `Err(HostError::TimeRegression)`;
   otherwise the last accepted time becomes `now_ms` (as `ingest`).
3. Handle not bound → `Ok(Refused(Unbound))`.
4. A `bind_peer` session → `Ok(Refused(NotSnapshotPeer))`.
5. Spend 1 frame and `bytes.len()` bytes from the session's intent buckets,
   both, with no short-circuit (exactly `ingest`'s rule); either short →
   `Ok(Refused(RateLimited))`. These tokens are the only state a refusal
   from here on changes, and `ingest` shares them.
6. `decode_up(bytes)` fails (including input over 4,096 bytes) →
   `Ok(Refused(Malformed))`.
7. `epoch` ≠ the session's → `Ok(Refused(WrongEpoch))`.
8. By message, S§9.3.

### S§9.3 Effects

Let `issued = next_transfer − 1` (0 if none).

- `Published { transfer: t }`: `in_flight == Some(t)` → set
  `in_flight = None`, `Ok(Published)`. Else `t ≤ issued` → `Ok(Stale)`,
  no change. Else → `Ok(Refused(UnknownTransfer))`.
- `Resync { after }`, with `a = after.map_or(0, TransferId::get)`:
  `a > issued` → `Ok(Refused(UnknownTransfer))`. Otherwise
  `stage_snapshot(.., cause Resync)` with the current grants and map:
  `Ok` → `Ok(Resynced)`; an S§7 error is returned as `Err(e)` (unreachable
  at v1 caps).

### S§9.4 Receipts after a clear

A receipt in a cleared entry is no longer deliverable (S§6.2), so the
client's retry of the same `seq` is a cache hit that stages a fresh
receipt-only delta, as T022 already does for an acknowledged receipt. Its
`event_seq` is above the snapshot's cursor.

## S§10. The T024 S§11 rules as server requirements

| T024 S§11 | Met by | Proved by (S§11) |
|---|---|---|
| 1. Ids strictly increasing per epoch from 1, never reused | `next_transfer` per session, `+1` per staging only | 2, 5, 7 |
| 2. `event_seq` never resets; cursor = last issued | snapshot sessions never reset; cursor `next_event_seq − 1` | 2, 9, 11 |
| 3. `Begin` precedes every delta above its cursor; chunks follow `Begin` | one log, entries pushed contiguously, later deltas pushed after; T024h2 sends in log order on one stream | 9, 10 |

## S§15. Adapter behaviour (T024h2)

1. **Hello** (`on_hello`, step 4 "Bind"): read `server.framing(conn)`.
   `Ok(Framing::V2)` → `bind_snapshot_peer`, traced as
   `BindSnapshotPeer`; `Ok(Framing::V1)` → `bind_peer`, traced as
   `BindPeer` (unchanged). `Err(_)` cannot happen (the record stays
   visible until its `Closed` is polled); if it does, the hello is
   `HelloOutcome::Lost { reason: CloseReason::EndpointFailed }` with no
   bind call. Steps 1–3 and 5–6 are unchanged. `Bound` records the
   framing.
2. **Drain** (`drain_bound`): use `try_recv_channel` for every bound
   connection; `bound.frames` counts every frame taken. `Channel::Lane0` →
   today's `ingest_one`, including the one-frame hold and the
   `Unauthenticated` fence. `Channel::Transfer` → `ingest_transfer`,
   traced as `IngestTransfer`, with `?` on `Err` exactly like `ingest_one`
   (an `Err` poisons): `Published`, `Resynced`, `Stale` continue;
   `Refused(Unbound)` counts `frames_refused`, fences `EpochClosed` and
   stops (as `Unauthenticated`); any other `Refused` counts
   `frames_refused` and continues. `Channel::Resume` (the third value,
   Q§7) is unreachable: a server reader closes an upstream `0x91` header
   with `ProtocolViolation` (2) before queueing it, so the server's
   `try_recv_channel` never returns it (Q§8.2). The arm exists so the
   `match` is exhaustive with no panic path (Q§16 F2): no host call and no
   trace entry; it counts `frames_refused`, fences `EpochClosed` and stops,
   as `Refused(Unbound)`. `bound.frames` counts it. Transfer frames never
   hold. A held lane-0 frame stops the drain, so frames behind it,
   transfer frames included, wait in the transport queue. On a `/1`
   connection only `Lane0` frames arrive, so behaviour and trace are
   today's.

   2a. **Retiring drain** (`drain_retiring`): use `try_recv_channel`
   instead of `try_recv`. Every frame taken, whatever its channel, counts
   `frames_discarded`; `Ok(None)` ends the drain; any `Err` marks the
   connection gone, and a gone connection whose `Closed` was polled is
   forgotten, as today. Under the legacy view a `Transfer` frame at the
   head would make `try_recv` return `Ok(None)` for ever (Q§8.3), leaking
   the `Retiring` entry and the transport record, with the frames never
   counted. No framing is needed here: on a `/1` connection
   `try_recv_channel` is `try_recv` with a `Lane0` tag (Q§7), so `/1`
   behaviour is today's.
3. **Deliver** (`deliver`): `take_delivery_entries` (traced as
   `TakeDelivery` with the entry count), then `try_send_channel` per entry
   in order: `Delta` on `Channel::Lane0`, `Transfer` on
   `Channel::Transfer`. `Err(Send(e))` is handled exactly as today's
   `Err(e)`. `Err(ChannelUnavailable)` sets `fence` (`EpochClosed`; it
   cannot occur, since only `/2` sessions hold transfer entries). The
   acknowledgement is `through` = the ordinal of the last accepted entry
   (never `bound.acked + accepted`), and `bound.acked` becomes that
   ordinal. On `/1` these are today's values.

   3a. **Departed peer** (the `transport_closed` branch of `deliver`):
   with `n > 0` entries taken, acknowledge `through` = the ordinal of the
   last entry taken (never `bound.acked + n`, which falls short after a
   clear, S§6.2), then `frames_discarded += n`. With `n == 0` nothing is
   acknowledged, as today.

   3b. **Shutdown flush** (`shutdown`, B§9 steps 2–3): for each bound
   connection with an open transport, `take_delivery_entries`, then
   `try_send_channel(conn, channel, bytes)` per entry in order with the
   item 3 channel rule, stopping at the first `Err` of any kind (today's
   `take_while`); if any entry was accepted, `acknowledge_delivery(peer,
   ordinal of the last accepted entry)`, its result ignored as today.
   Step 3 counts the entries (both kinds) that `take_delivery_entries`
   still returns. Shutdown records no trace, as today, and steps 1 and
   4–7 are unchanged. With legacy `try_send` a transfer entry would go out
   on `Lane0` (Q§8.3), and a count-based ack would leave entries after a
   clear unacknowledged and counted undelivered. On `/1` the sends, ack
   and count are today's.
4. **Grants** (`set_invitation_grants`): narrowing with a live `/2`
   binding calls `host.set_grants(peer, grants)`: `Ok(SnapshotStaged)` →
   store the grants, return `Ok(GrantChange::SnapshotStaged)`; any other
   `Ok` is `Err(self.host_error(HostError::Invariant("snapshot session
   narrowed without a snapshot")))`; `Err(e)` → `Err(self.host_error(e))`
   with nothing stored. Narrowing with a live `/1` binding fences
   (`Narrowed`), as today. No live binding: `Stored`. Widening: unchanged.
   `revoke_invitation`, supersession, `disconnect`, epoch reconcile and
   the stall fence decide exactly as today for both framings; the
   connection each one fences retires through item 2a, and shutdown
   follows item 3b.
5. **Server binding** is the operator's: `QuicHost::start` takes a server
