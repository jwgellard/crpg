## Purpose

The validator's semantic authority belongs in `crpg-data`; operating-system
path traversal and process behavior belong above it. `crpgc validate` joins
those boundaries for humans, CI, the future editor, and the documented
generate-validate-repair loop. JSON output must be directly consumable without
prose parsing, while ordinary output remains readable and positioned.

This task does not reopen the T013 parser-framework decision. Extend the current
hand-rolled parser for one command and one boolean flag. T013 must still decide
whether the broader command set justifies clap.

## Interface

```text
crpgc validate <campaign-root> [--json]

  <campaign-root>  directory containing campaign.json
  --json           emit one canonical JSON diagnostic array to stdout

exit 0  campaign loads and has no Severity::Error diagnostic
exit 1  I/O, structural load, or semantic Error failure
exit 2  usage error
```

`--json` may appear once either before or after `<campaign-root>`. Exactly one
root is required. Unknown flags, duplicate `--json`, extra positional arguments,
missing root, and malformed subcommand syntax are usage errors. Existing replay
syntax and behavior remain byte-for-byte and exit-for-exit compatible.

The selected exit codes are binding and preserve the T009b public contract:
`0` no `Severity::Error` diagnostic, `1` any `Severity::Error` domain/input
failure (including unreadable files and a T010 `DataError`), `2`
command-line usage. `Severity::Warning` diagnostics never fail the command:
plain mode still prints them to stderr and JSON mode still includes them, but
the exit stays `0` when no `Error` is present. T011a emits only `Error`, so
warnings-only behavior is a forward-compatibility contract pinned by tests with
synthetic values, not by a current fixture. A missing campaign root is exit 1
when the path argument was supplied but cannot be read; it is exit 2 only when
the argument itself is absent.

The CLI obtains the engine version from its compile-time Cargo package version
(`env!("CARGO_PKG_VERSION")`) and parses it for T011a's `validate_files` call.
If that compile-time version fails to parse as semver (a release-process bug,
not user input), exit 1 with exactly
`crpgc validate: internal engine version failure\n` on stderr and empty stdout,
without panic. There is no runtime executable probing, network check,
environment override, platform branch, or hard-coded second version authority.

## Directory collection

Filesystem traversal lives in `crpg-cli`, using `std` only. It produces the
`BTreeMap<SourcePath, Vec<u8>>` consumed by `validate_files`. Argument handling
uses `std::env::args_os`; a non-Unicode `<campaign-root>` argument never panics
and is reported as one exit-1 `io` diagnostic (see below), not as usage.

1. Require `<campaign-root>` to be a directory. Walk sorted depth-first
   pre-order: list a directory, sort its entries by byte representation of the
   file name, then visit each entry in that order, recursing into subdirectories
   before advancing to the next sibling. The first collection failure in this
   order wins; when two failures are reachable, the walk order plus the
   per-entry operation order in step 4 decides deterministically.
2. Never intentionally follow symlinks. Observe each entry with
   `symlink_metadata` (or `DirEntry::file_type`, which must not follow links);
   when the observed type is a symlink, do not recurse into it or read through
   it. A symlink occupying a recognized document path is one input diagnostic.
   No handle-based no-follow guarantee is promised with `std` only: a live-tree
   race that replaces an entry between observation and read is unspecified and
   may surface as an I/O or data diagnostic. Do not add a dependency for secure
   traversal here.
3. Build root-relative logical text from path components joined by `/`; never
   use a platform separator in a diagnostic or data key. When any component on
   the entry's relative path is non-Unicode, stop handling that entry and emit
   one `io` diagnostic with `file: None`, empty pointer, and a portable message
   naming the operation (`list`, `classify`, or `read`) without lossy-converting
   the component or calling `campaign_document_path`. `SourcePath` is ASCII-only,
   so non-Unicode can never become a valid data key.
4. Per file entry in walk order: check symlink status, then classify the
   logical text with `crpg_data::campaign_document_path`, then read bytes.
   Read and insert only `Some(path)` regular files. `None` means non-document
   content and is ignored after a successful listing: source assets, copied
   schemas, Lua, replays, build output, `.gitattributes`, and unrelated files.
   "Ignored" never prunes a directory: an unreadable directory still fails even
   when it would have contained only ignored files, because the CLI has no
   data-owned directory-pruning predicate and must not duplicate the path-family
   list to guess.
5. Preserve classifier `DataError`s through
   `crpg_data::diagnostic_for_data_error` unchanged (`invalid_path` with its
   data-owned position). Reserve `DiagnosticCode::Io` strictly for filesystem
   failures, symlinks at recognized document paths, and non-Unicode components.
   Do not duplicate the T010 path-family list, infer a document from JSON,
   extension-guess beyond the classifier, or parse document bytes in CLI.
6. Do not panic, lossy-convert, or escape the root.

An `io` diagnostic is a one-element T011a `Diagnostic` with
`Severity::Error`, `DiagnosticCode::Io`, empty pointer, a logical `file` when
one is known and `None` for root/directory/non-Unicode failures, no fabricated
suggested fix, and a portable message of the exact form
`cannot <op> <logical-or-<campaign-root>>: <kind>` where `<op>` is
`open root`, `list`, `classify`, or `read`, `<logical>` is the `/`-joined
relative text (or `<campaign-root>` when no logical path exists), and `<kind>`
is a stable snake_case mapping of the failure (`not_found`,
`not_a_directory`, `permission_denied`, `symlink_at_document_path`,
`non_unicode_component`, or `io_error`). Never embed raw
`std::io::Error` display text, native separators, or absolute paths. I/O
remains CLI-owned; all source-format and semantic failures come unchanged from
`validate_files`.

The collector must not mutate, canonicalize, create, delete, or lock source
files. `validate` is read-only. Files changing concurrently may yield an I/O or
data diagnostic; snapshotting/locking a live directory is not introduced here.

## Output contract

Plain mode:

- Success (no `Error`) prints warnings, if any, to stderr, one
  `Diagnostic::Display` per line in returned order; a clean run prints nothing
  to either stream. Stdout stays empty in both cases.
- Exit-1 diagnostics are printed to stderr, one `Diagnostic::Display` per line,
  in the exact order returned by data. Stdout stays empty.

JSON mode:

- Serialize the complete `Vec<Diagnostic>` with
  `crpg_data::canonical_json`; output is one JSON array with recursively sorted
  object keys, two-space indentation, LF endings, and exactly one final LF.
- Success prints the array to stdout and nothing to stderr: exactly `[]\n`
  when empty, otherwise the warnings-only array with exit `0`.
- Exit-1 validation or I/O prints the nonempty array to stdout and nothing to
  stderr. It does not wrap the array in a CLI-specific envelope.

Usage errors always print one `crpgc: ...` line to stderr and exit 2; `--json`
does not promise JSON for a command line that could not be parsed. Do not mix a
JSON array with a prose prefix, progress message, summary count, color escape,
or debug output. A canonical serialization failure is exit 1 without panic: in
both modes print exactly `crpgc validate: internal serialization failure\n` to
stderr with empty stdout. The diagnostic value set is deliberately serializable,
so tests pin this fallback with a synthetic unserializable-adjacent seam only
if needed and never invent a normal user case for it.

The command's implementation flow is exactly:

```text
parse args (args_os)
  -> collect classified files (sorted depth-first pre-order)
  -> crpg_data::validate_files(files, package engine version)
  -> render the returned diagnostics
  -> map no-Error/any-Error to 0/1
```

No dangling-reference walk, kind table, slug set, graph traversal, locale/asset
lookup, `DataError` parser, diagnostic sort, or duplicate diagnostic shape may
exist in `crpg-cli`.

## Gate 8 and fixtures

Add a black-box integration test driven by T011a's data-owned manifest at
`crates/crpg-data/tests/fixtures/expected.json` (consumed as test data, never
edited here). The test:

1. Reads and parses the manifest; fails on missing file, malformed JSON, or
   entries out of sorted `root` order.
2. Recursively discovers actual campaign roots under
   `crates/crpg-data/tests/fixtures/` by finding directories containing
   `campaign.json`, sorts them lexically by `/`-joined relative text, and
   requires the discovered set to equal the manifest `root` set exactly. No
   vacuous pass (empty set fails) and no silent assumption for unknown roots:
   an undiscovered manifest entry or an unlisted discovered root fails with an
   explicit message. This covers nested campaign roots such as a future
   `migration_v1/campaign` without treating an enclosing version directory as
   one campaign.
3. For each manifest entry invokes
   `env!("CARGO_BIN_EXE_crpgc") validate <root> --json` through the shipped
   binary. The manifest must contain at least `one_area_one_creature`
   (`clean`) and `broken_references` (`diagnostics`).

Expected status comes from the manifest, not from a CLI-owned table:

| Fixture | Exit | Stdout |
|---|---|---|
| `one_area_one_creature` | 0 | exact `[]\n` |
| `broken_references` | 1 | exact bytes from T011a's checked-in diagnostic snapshot |

A future fixture-owning task extends the manifest in `crpg-data` alongside its
fixture and snapshot; this test picks it up generically with no CLI edit,
preserving E004's one-task-one-crate rule.

At T011b there is no repository `rulesets/` directory and no ruleset-specific
source model, so the real gate consists of the manifest-listed campaigns rather
than a skipped/green ruleset placeholder. Do not invent a ruleset package
contract here. The first ruleset-format task extends the manifest convention
(or a parallel ruleset manifest it owns) with its real package contract.

The test uses the actual binary and checked-in source tree read-only. It does not
copy/bless fixtures, call validation in process, hide behind an ignored test, or
depend on process working directory; derive repository paths from
`CARGO_MANIFEST_DIR`.

## Tests

Extend unit tests in `main.rs` only where parser/error mapping is private. Add a
focused black-box integration suite such as `tests/validate.rs`.

Required assertions:

1. Parser accepts one root with `--json` before/after, rejects duplicate flag,
   missing root, extra positional, and unknown flag with exit-code mapping 2.
   Non-Unicode root via `args_os` is exit 1 `io`, never a panic.
2. Contract-conforming replay behavior is preserved byte-for-byte and
   exit-for-exit; all existing replay black-box tests stay green. One latent
   T009b violation is explicitly authorized for repair in this crate:
   `crpgc replay --bogus` (flag in first-position where a path is expected)
   must be usage exit 2, not missing-file exit 1. Add first-position flag tests
   (`replay --bogus`, `replay --golden g`) and keep the existing
   after-path unknown-flag test green.
3. Plain valid validation exits 0 with both streams empty. Synthetic
   warnings-only input exits 0 but still prints warnings to stderr in returned
   order, pinning the non-fatal warning contract.
4. JSON valid validation exits 0 with exact `[]\n` and empty stderr.
   Warnings-only JSON exits 0 with the warnings array on stdout.
5. Broken fixture plain mode exits 1, stdout empty, and stderr is exactly the 15
   data-owned Display lines in returned order.
6. Broken fixture JSON mode exits 1, stderr empty, and stdout byte-equals the
   T011a snapshot without parsing/reformatting in the assertion.
7. Malformed/unsupported/layout/engine/lock examples produce one structural
   diagnostic through `validate_files` with its data-owned code preserved, not
   CLI-authored prose or semantic work. An accepted-family bad logical path
   surfaces as `invalid_path` via `diagnostic_for_data_error`, never as `io`.
8. Missing root, unreadable recognized file, non-directory root, recognized
   symlink, and non-Unicode component are clean exit-1 `io` cases with portable
   `cannot <op> <logical>: <kind>` messages and no raw OS text. Tests that
   cannot portably create an unreadable file or a real symlink (ordinary
   Windows without Developer Mode/elevation) must exercise the collector's
   private/injected error or metadata seam rather than use a runtime skip;
   retain at least one real black-box symlink test where creation is guaranteed
   and cfg-gate the real-symlink case when the platform cannot create it, never
   skipping at runtime.
9. Recursive nested documents are collected in sorted depth-first pre-order;
   source assets, schemas, Lua, replay files, `.gitattributes`, and unrelated
   files are ignored after successful listing (unreadable directories still
   fail). A two-failure oracle through the private collector seam pins which
   failure wins in walk order. A Linux case-collision reaches data and reports
   `layout`; it is compile-time cfg selected if Windows cannot create the
   fixture, never runtime skipped.
10. The gate-8 manifest test fails on missing/malformed/unsorted manifest,
    requires discovered campaign roots to equal manifest roots exactly, checks
    each root against its manifest expectation through the binary, and cannot
    pass with zero fixtures.
11. All JSON outputs are valid canonical arrays with six-field diagnostic
    objects, portable `/` paths, LF only, no BOM, no trailing whitespace, and
    exactly one final LF.

Focused commands from the workspace root:

```text
cargo test -p crpg-cli --test replay --locked
cargo test -p crpg-cli --locked
```
