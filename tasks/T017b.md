# T017b — `crpg-sim` primary-pool compatibility for B1 shapes

## Status and purpose

**Implemented; integration verification pending.** Narrow single-crate
compatibility task unblocking B1 (`tasks/T017a.md`). Adapts the T016b/e/f
combat adapter to the B1 data shapes without generalizing behavior: reads
the primary authored pool from `Ruleset.pools.first()`, preserves the
existing single-pool runtime representation (`Combatant.action_pool`) and
all existing action/turn/damage/RNG/persistence/event semantics for
migrated minimal-d6 content, and rejects new execution requirements
before mutation under accepted ADR-0015. Full multi-pool/effect/
target-defense/natural/turn generalization stays in B3 under its own
reviewed ADR.

This file is the implementation contract. It does not claim source changes
or native gates have run. No commit, push, or PR without separate
instruction.

## Decisions (binding unless the ADR section says otherwise)

1. **Keep the B1 data model.** `Ruleset.pools` replaces authored
   `action_pool`; no duplicate authored field is restored.
2. **Primary-pool compatibility only.** `start_encounter` reads
   `ruleset.pools.first()` and uses that template's `id`/`max`/`refresh`
   for the existing single-pool runtime (`CombatDefinition.pool_*`,
   `Combatant.action_pool` at max, `TurnStart` refresh). Runtime field
   names (`action_pool`) stay unchanged; only the authored-data access
   changes. No global rename.
3. **Legacy-equivalent fixtures.** Test support JSON uses `pools: [single]`,
   `extra_costs: []`, `ends_turn: true`, `effect: null` (omitted),
   `defense: {"type":"actor_attribute"}`, `natural_die: null` (omitted).
   These deserialize the current shapes directly and do not pass through
   document migrations.
4. **No behavior change for legacy content.** Action, turn, damage, RNG
   (`COMBAT_ROLL_STREAM`/`COMBAT_ROLL_TAG`, empty pipeline/views,
   `Against::Dc` on the actor attribute, `natural_die: None`), persistence
   (symbolic strings, absence-skip), and `Died`/release semantics stay
   byte-identical. Existing `combat_basic` goldens stay byte-identical.
5. **Unsupported new content fails before mutation (ADR-0015 Accepted).**
   The old runtime cannot honor plural pools, extra costs, non-ending
   turns, effects, target-stat defense, or natural selection. The adapter
   rejects such specs in `start_encounter` before any World/RNG/event
   mutation under the accepted single-variant gate; no unrelated variant
   is repurposed.

## Interface

No public API change in the primary-compat part: `CombatDefinition`,
`Combatant`, `EncounterSpec`, `CombatAction`, `ActionOutcome`,
`CombatError`, `start_encounter`, `perform_action`, `end_encounter`, and
all constants keep their names, shapes, and `Display` locations. The
adapter internally replaces `ruleset.action_pool.{id,max,refresh}` with
`ruleset.pools.first()` (failing cleanly on empty, which data validation
already rejects; direct struct construction with empty pools must not
panic — return the existing collection-bound error if the crate has an
accurate one, otherwise leave to the ADR-gated boundary).

The support-boundary part (ADR-gated) will add exactly one new
`CombatError` variant with pinned per-field `Display` and precedence,
covering the temporary supported subset below. The variant name, fields,
locations, field order, and full validation order are proposed in the
revised ADR draft and have no effect until finally approved and
implemented.

## Behavior (primary-compat part; no new error)

- `start_encounter` keeps its pinned `CombatError` precedence and
  all-or-nothing publishing. The only change is the pool-template source:
  `let primary = ruleset.pools.first()` (empty → clean failure, never
  panic), then `primary.id`/`max`/`refresh` flow into the existing
  `InvalidCost { cost, max }` check, `CombatDefinition.pool_*`, per-combatant
  `ResourcePool::new`, and the incoming-actor `TurnStart` refresh.
- Cost validation stays primary-only (`ability.cost > primary.max` →
  `InvalidCost`); extra costs are not spent here (B3 owns them) and are
  rejected by the ADR-gated boundary, not silently ignored.
- Ability selection stays first-listed; dice/table/cost validation loops
  stay as-is (attribute, dice parse, table build, primary cost). New
  ability fields are not interpreted here; non-legacy values are rejected
  by the boundary, not executed.
- `perform_action`, `end_encounter`, despawn/release, persistence
  (`action_pool` bytes preserved), events, RNG, and hashing are untouched.

## Support-boundary (ADR-0015 Accepted; implemented)

Temporary supported subset (legacy only): `pools.len() == 1`, and for the
encounter (first-listed, executable) ability — `extra_costs` empty,
`ends_turn: true`, `effect: None`, `defense: ActorAttribute`,
`natural_die: None`. Only the first-listed ability is support-checked;
non-first listed abilities retain existing validation only and stay
non-executable (using one fails the existing `UnknownAbility`).

Specs outside this subset must fail in `start_encounter` before any
mutation (no entity spawned, no RNG stream created, no event enqueued).
Revised proposal (draft, not final until ADR accepted): single
`UnsupportedAuthored { what: String }` with `what` as `"<kind> <ULID>
<field>"` (canonical ULIDs) and `Display` as `"UnsupportedAuthored at
spec/<field>: <what>"` (`pools`, `extra_costs`, `ends_turn`, `effect`,
`defense`, `natural_die`). Pinned validation order: existing
encounter/collection/participant/stat checks; pool cardinality before any
primary-pool dereference; complete existing per-ability loop over all
listed abilities; first-ability support checks in `extra_costs, ends_turn,
effect, defense, natural_die` order; publication. Existing errors win over
unsupported in every multifault combination. Each restriction lifts
individually with B3 execution+validation coverage; variant retirement
belongs to B3's reviewed API decision. Existing variants keep their
meanings, locations, and precedence; otherwise `Display` stays
byte-identical.

  existing error; non-first new fields trigger no unsupported and their
  execution fails `UnknownAbility`; legacy subset still starts.

  assertions, no changed goldens, no new dependencies.
