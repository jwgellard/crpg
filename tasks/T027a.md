## Interface — exact fact gate

Inventory existing public area/perception facts and approve exact missing

plus deterministic iteration and bounds. Client-scoped NetId/peer/capability

producer must be a real approved simulation transition, not a setter for tests.

If an approved policy can use existing facts unchanged, mark this child
superseded by a documented public-API sufficiency proof and let T027b consume
that proof. Do not add fake state solely to populate the ledger.

## Behaviour

Authoritative area/perception changes are observable through read-only public
queries; removed/dead/hidden entities cannot remain accidentally addressable.
Decide whether death itself is disclosable independently of retained health.
Retain pre-removal permitted context where needed by the host without retaining
an actionable entity mapping. No network or account policy in sim.

Any new behavior-affecting fact is world-owned, persisted and hashed. Require
an ADR-compatible opt-in/absence strategy to preserve B4/legacy bytes; never
exclude facts from the hash to keep old goldens. Missing perception semantics
remain a blocker, not a net-only approximation marketed as authority.

### Exact additive API and ownership

```rust
impl World {
    pub fn new_in_area(seed: u64, area: Ulid) -> Self;
    pub fn area(&self) -> Option<Ulid>;
    pub fn area_of(&self, entity: EntityId) -> Option<Ulid>;
}
impl HistoryWorld {
    pub fn new_in_area(seed: u64, area: Ulid) -> Self;
}
pub enum AreaError {
    UnboundSource,
    UnboundDestination,
    SameArea { area: Ulid },
    AbsentEntity { entity: EntityId },
    CombatParticipant { entity: EntityId },
    ScheduledEntity { entity: EntityId },
    InvalidTransform { entity: EntityId },
    SourceHistory(HistoryError),
    DestinationHistory(HistoryError),
}
pub fn transfer_entity(source: &mut World, destination: &mut World,
    entity: EntityId) -> Result<EntityId, AreaError>;
pub fn transfer_history_entity(source: &mut HistoryWorld,
    destination: &mut HistoryWorld, entity: EntityId)
    -> Result<EntityId, AreaError>;
// Add one CombatError variant:
AreaMismatch { expected: Ulid, found: Ulid }
```

Free functions/AreaError live in new public `area` module and root re-exports.
World methods live with World; HistoryWorld constructor lives with history.
AreaError derives Debug, Clone, PartialEq, Eq, implements Error/Display.
Displays are `<VariantName> at area/transfer` without fields; wrapped History
errors are sources. CombatError::AreaMismatch displays `AreaMismatch at spec/areas`.

World remains one loaded area's simulation, not a map of independently ticking
areas. Add private `area: Option<Ulid>` after existing fields, default None and
skip serialization when None. `new`/Default remain unbound and byte-identical.
`new_in_area` starts empty with the given authored area id; no runtime id minting,
content lookup, mutable area setter or late binding of an arbitrary legacy World.
History constructor directly creates the bound inner World; no mutable escape.

`area_of` returns the world's area iff the **full generation-bearing id** is
currently live, otherwise None. Death is not despawn: a dead but retained entity
still has presence/area. Health/death/action disclosure is a separate host grant,
not a sim concealment flag. Iteration uses existing ids() and area_of, with no
per-viewer store or peer entitlement in sim. No duplicate membership index.

Runtime identity across multiple Worlds is `(area ULID, full EntityId)`; two
areas can mint equal arena ids. T027c must scope lookup/mapping by both. This
does not change EntityId's core representation or any v1 wire shape.

### Real producers and transition rules

Spawn into a bound World immediately acquires its area; despawn immediately
loses it; release leaves entities in their area. Encounter start into a bound
World validates that the resolved participant area matches it. Preserve existing
precedence through missing-placement and MixedArea checks; after those, before
creature/stat checks, return AreaMismatch on configured/resolved disagreement.
Unbound legacy Worlds keep their existing behavior and serialize identically.
HistoryWorld start returns HistoryError::Combat(AreaMismatch) transactionally.

`transfer_entity` is an explicit simulation area transition requested by a higher
authorized owner, not automatic navigation or a client operation. It supports
the current **noncombat, unscheduled entity** shape only. Error order:
source bound; destination bound; distinct area ids; source contains entity;
entity has no Combatant; entity has no timeline entry; existing transform, if
any, has finite position/velocity. Reject even a terminal/dead combat participant
until explicit encounter release. No mid-encounter migration, combat state
merging, inventory, quest, continuation or component-loss success is invented.

Stage both Worlds. Copy EntityMeta and optional Transform, despawn from source,
spawn in destination and attach the copied transform to the new destination id.
Publish both only after success; return that new id (which may numerically equal
the old id but belongs to a different area). Source emits Despawned, destination
emits Spawned at their respective unchanged ticks. RNG/interner/encounter state
does not migrate or change. An absent transform stays absent; no synthetic zero
transform. Future per-entity components must extend this move contract before
they can be silently discarded. No entity count cap beyond existing arena rules;
the 1024 **visible** entity limit is not an authority-population cap.

`transfer_history_entity` performs the same preflight, then stages **both full
wrappers** and uses their typed despawn/spawn paths; a crate-private helper can
attach the already-validated transform, never a public mutable-inner method.
Check SourceHistory before DestinationHistory if both journals cannot accept
their event; any failure publishes neither wrapper. No public closure can
inject additional effects into this pair transaction. Source/destination clocks
need not match; ordering within each journal remains T020's contract. There is
no global cross-area event sequence. Host captures both transition results and
retires source actionable mapping before its next admission; the returned pair
of area identities and entity ids identifies that handoff without net ids in sim.

### Persistence, compatibility and consumer handoff

Present area serializes as existing core ULID text and hashes in full through
state_hash and history_hash. Deserialize accepts a missing field as legacy None;
explicit null is also None, and canonical reserialization omits it. Invalid ULID
fails loading. This is an absence compatibility strategy, not hash exclusion.
Area is world-owned and immutable after construction, so no dangling per-entity
membership map can survive despawn or slot reuse.

Host T027c must validate authored area identity against its loaded campaign and
assign viewer-area/control bindings and field grants. Sim cannot validate the
existence of an authored Area from only a Ulid. Net T027b consumes supplied
membership facts and projects whole-area presence. Permission changes or moves
cancel stale in-flight snapshots before publication; that mechanism remains
T024/T027c, not a simulation callback or an incomplete transfer marketed as a
full multiplayer area handoff.
