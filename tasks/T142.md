## Task
ADR-0029 Follow-on 9 (`:488`): the `crpg.ui/1` document that a ruleset may
ship (U1, `:353–355`), its read-time and semantic validation (U2–U4 and U6,
`:357–387`), the pure functions that generate the default UI when a ruleset
ships none or omits a screen (U5, `:378–383`), the reserved kinds (U8,
`:393–395`) and the version rule (U10, `:401–402`).

The document is presentation data. It is never loaded into a `World`, never
hashed, and the server ignores it (`:353–355`). U7 (`:389–391`) is a client
rule. T142 only guarantees that the document holds no value, formula or
number. U9 (`:397–399`, odds) belongs to T143. T142 carries only the
`show_odds` flag that T143's preview and T051's widget read.

## Decision
- **D1. A new campaign document family `crpg.ui/1`, variant `Document::Ui`,
  with no `id`, `slug` or `name`.** The document names its ruleset in a
  required `ruleset` field, the way a locale table names its campaign
  (`crates/crpg-data/src/document.rs:365–379`). Nothing references a UI
  document, so it gets no `ObjectKind` and does not enter the index.
- **D2. Storage is the layout family `ui/`.** It is added to `check_layout`
  (`crates/crpg-data/src/loader.rs:112–157`) and to `campaign_document_path`
  (`crates/crpg-data/src/validation.rs:261–287`) through the shared `family`
  predicate (`crates/crpg-data/src/loader.rs:93–96`). By convention a
  ruleset package ships the file as `rulesets/<package>/ui.json`, and a
  campaign copies it byte-for-byte to `ui/<package>.json`. This is the same
  way `rulesets/minimal-d6/ruleset.json` becomes
  `campaigns/fixtures/combat_basic/rulesets/minimal-d6.json`. T142 ships no
  UI file.
- **D3. Each binding uses the identity its source already has.** A stat is
  bound by `name` (`crates/crpg-data/src/combat.rs:80–88`). A pool is bound
  by its template ULID, because templates have no name
  (`crates/crpg-data/src/combat.rs:216–226`). Abilities and effects are bound
  by ULID (`crates/crpg-data/src/combat.rs:392`, `:548`). An outcome is bound
  by a label string. Tags and groups are bound by string. Slugs are never
  used, because they can be renamed (`crates/crpg-data/src/combat.rs:341`).
- **D4. Every top-level list and every optional entry field is
  optional-missing** (`#[serde(default, skip_serializing_if =
  "Option::is_none")]`). A missing top-level list means "use the generated
  default for this part" (U5). `[]` is accepted and kept as `[]`. The
  smallest valid document is `{"schema":"crpg.ui/1","ruleset":"<ULID>"}`.
- **D5. U6 is met by tolerant closed sets.** Six closed sets decode an
  unknown spelling into an `Unknown` arm instead of failing: screen kind,
  section type, stat format, pool style, target hint and sort. The `Unknown`
  arm round-trips byte-identically. `validate` reports it as `unknown_kind`,
  so a misspelt kind fails campaign validation but never `load_campaign`.
  `load_campaign` is the server's load path
  (`crates/crpg-godot/src/core/mod.rs:221`). Every other structural defect
  (bad JSON, an unknown field, a wrong type, a broken bound) stays
  `Malformed`, as in every other family. The JSON Schema lists the known
  values only. Open question 1 asks whether this line is right.
- **D6. Wire shapes copy the crate's conventions.** Enums with a payload use
  the adjacent `{"type":…,"value":…}` snake_case form, and a unit variant is
  written `{"type":"timeline"}` (`crates/crpg-data/src/combat.rs:487–501`).
  An adjacent enum with a unit variant has a hand-written `Deserialize` that
  enforces exact key sets (`crates/crpg-data/AGENTS.md:68–73`). The six
  tolerant enums also have a hand-written `Serialize`, so `Unknown` writes
  back what it read. The table under "Serde implementations" fixes which
  impls are derived and which are hand-written.
- **D7. Selectors are enums, so "exactly one of" cannot be broken.**
  `stat_group`, `pool_group`, `ability_list` and `item_list` each take a
  selector with an `all` arm. "Explicit ids or a tag filter" (U4, `:374`)
  becomes `ids` or `tag`. `effect_list`, `timeline`, `log` and
  `choice_steps` take no value. U4 gives them none, and the effects that
  `effect_list` shows are runtime facts.
- **D8. Labels are locale keys in authored documents (U2, `:360`).**
  Coverage uses the crate's existing rule: the key must exist in every
  loaded locale table, and with no table every key is missing
  (`crates/crpg-data/src/validation.rs:1294–1326`). Generated labels are
  text, not keys: a stat's name, `pool-<n>`, an outcome spelling. The one
  exception is the ability and effect labels, which reuse the object's
  existing `name` locale key. A client shows the label text itself when the
  key resolves in no table (hand-off to T051).
- **D9. Icons use the crate's existing asset rule.** An icon is a key of
  `assets.lock` (`crates/crpg-data/src/package.rs:94`). A missing key is
  reported as `missing_asset`, exactly as `Area.ambience` is
  (`crates/crpg-data/src/validation.rs:1022–1048`). T101 is the authoring-UX
  ADR, not an asset pipeline (`docs/IMPLEMENTATION_PLAN.md:291`). Asset
  *type* checks wait for the import flow.
- **D10. "Resolves in the same ruleset" (U2, `:358–361`) means the following.**
  A stat is declared in `ruleset.stats`. A pool is a template in
  `ruleset.pools`. An ability is listed in `ruleset.abilities`. An effect is
  applied by a listed ability (`Ability.effect`,
  `crates/crpg-data/src/combat.rs:548`); this is the only link from a
  ruleset to an effect. An outcome is produced by a listed ability's table
  or damage entries. An ability tag is declared by some `abilities` entry of
  the same UI document, because `Ability` has no tag field
  (`crates/crpg-data/src/combat.rs:517–567`) and U3 makes "category tags"
  ability display metadata. A stat group is declared by some `stats` entry's
  `group`. An item tag resolves in the campaign (U2 "or campaign (item)") and
  is a **warning**, not an error. U6's errors are "unresolved ids", a tag is
  not an id, and a ruleset's UI is shared by campaigns that may hold no item
  with that tag.
- **D11. Reserved kinds parse and are reported (U8, `:393–395`).**
  `level_up`, `character_creation` and `choice_steps` decode to known
  variants, and `validate` reports each one as `reserved_kind`. The defaults
  never emit them.
- **D12. Defaults are two pure functions over one borrowed input** (U5):
  `generated_ui(&UiSource)` and `effective_ui(Option<&UiDocument>,
  &UiSource)`. Any caller can build `UiSource`: the editor, an agent, the
  host, or T072's exporter. `UiSource::from_documents` builds it from loaded
  documents.
- **D13. Every non-reserved screen has a default.** U5 says "a screen it
  omits gets a default", and U8 excludes only the reserved ones. The
  defaults are: `character_sheet` all stats; `action_bar` all abilities,
  declared order; `spellbook` all abilities, label order; `inventory` all
  items; `combat_hud` health, all pools, the timeline and the log. The log
  is added beyond U5's list because U3 says the combat log uses the outcome
  labels, and a default HUD with no log would leave them unused.
- **D14. No `$id`.** The 22 existing schemas carry no external identifier
  (`crates/crpg-data/src/schema.rs:91–93`). The identity of a schema is its
  file name plus the `const` tag. Adding `$id` would be a convention change
  across all schemas, which is out of scope.

### Document model
All structs derive `Debug, Clone, PartialEq, Eq, Serialize, Deserialize,
JsonSchema` with `#[serde(deny_unknown_fields)]`. Every `Option` field
carries `#[serde(default, skip_serializing_if = "Option::is_none")]`. Every
`Ulid` field carries `#[schemars(with = "crate::schema::UlidText")]`, and
every `Vec<Ulid>` carries `#[schemars(with = "Vec<crate::schema::UlidText>")]`.
```rust
pub struct UiDocument {
    /// The ruleset this document describes.
    pub ruleset: Ulid,
    /// Stat display entries; absent means generated for every stat.
    pub stats: Option<Vec<UiStat>>,
    /// Pool display entries; absent means generated for every pool.
    pub pools: Option<Vec<UiPool>>,
    /// Ability display entries; absent means generated for every listed ability.
    pub abilities: Option<Vec<UiAbility>>,
    /// Effect display entries; absent means generated for every applied effect.
    pub effects: Option<Vec<UiEffect>>,
    /// Outcome labels; absent means generated for every produced outcome.
    pub outcomes: Option<Vec<UiOutcome>>,
    /// Screens; absent means every non-reserved default screen.
    pub screens: Option<Vec<UiScreen>>,
    /// Preserved author annotation (`#[serde(rename = "_note")]`).
    pub note: Option<String>,
}
pub struct UiStat {
    pub stat: String,                 // declared stat name
    pub label: String,                // locale key
    pub short_label: Option<String>,  // locale key; absent: use `label`
    pub description: Option<String>,  // locale key; absent: none
    pub group: Option<String>,        // locale key naming the group; absent: ungrouped
    pub format: Option<UiFormat>,     // absent: render the replicated value by its own type
}
pub struct UiEnumLabel {
    pub variant: String,              // a variant of the stat's enum
    pub label: String,                // locale key
}
pub struct UiPool {
    pub pool: Ulid,                   // a template id of the ruleset
    pub label: String,                // locale key
    pub icon: Option<String>,         // assets.lock key; absent: none
    pub style: Option<UiPoolStyle>,   // absent: bar
    pub show_on_hud: Option<bool>,    // absent: true
}
pub struct UiAbility {
    pub ability: Ulid,                // listed by the ruleset
    pub label: String,                // locale key
    pub description: Option<String>,  // locale key
    pub icon: Option<String>,         // assets.lock key
    pub category_tags: Option<Vec<String>>, // absent: none; nonempty when present
    pub target_hint: Option<UiTargetHint>,  // absent: no hint
    pub show_odds: Option<bool>,      // absent: false (T143 / T051 read it)
}
pub struct UiEffect {
    pub effect: Ulid,                 // applied by a listed ability
    pub label: String,                // locale key
    pub icon: Option<String>,         // assets.lock key
    pub show_duration: Option<bool>,  // absent: true
}
pub struct UiOutcome {
    pub outcome: String,              // B18 grammar, e.g. "success", "custom:3"
    pub label: String,                // locale key
}
pub struct UiScreen {
    pub kind: UiScreenKind,
    pub sections: Vec<UiSection>,     // required; may be empty; at most 64
}
pub struct UiAbilityList {
    pub select: UiAbilitySelect,
    pub sort: Option<UiSort>,         // absent: declared
}
```
Enums. Every enum derives `Debug, Clone, PartialEq, Eq`, plus the derives
that the next table names. The adjacent enums (`UiFormat`, `UiMeter`,
`UiSection` and the four selectors) carry `#[serde(tag = "type", content =
"value", rename_all = "snake_case", deny_unknown_fields)]`, which those
derives read. The `Unknown` arms of `UiFormat` and `UiSection` carry
`#[schemars(skip)]`. Every `Ulid` payload carries the `UlidText` adapter
named above. The four plain-string enums derive nothing beyond those four
traits and carry no `serde`/`schemars` attribute. Their spellings are the
constants, and `NoTarget` is spelt `none`.

Each of the six tolerant enums (`UiFormat`, `UiSection`, `UiScreenKind`,

### Serde implementations
| Type | `Deserialize` | `Serialize` | `JsonSchema` |
|---|---|---|---|
| structs, `UiMeter` | derived | derived | derived |
| `UiStatSelect`, `UiPoolSelect`, `UiAbilitySelect`, `UiItemSelect` | hand-written: exact keys per variant; unknown `type` is `unknown_variant` | derived | derived |
| `UiFormat`, `UiSection` | hand-written (B3, B4) | hand-written: `{"type": as_str}` plus `"value"` when the variant has one or `Unknown.value` is `Some` | derived, `Unknown` skipped |

## Behaviour
Read-time rules give `DataError::Malformed` (through `decode_current`/
`validate_local`, `crates/crpg-data/src/document.rs:472–509`). Every other
rule is a `validate` diagnostic. Pointers are RFC 6901, index-based and
relative to the file. In this section, "R" means that the document's
`ruleset` resolves to a `Ruleset` in the shared identity table
(`crates/crpg-data/src/validation.rs:888–933`).

**Reading and writing**
1. **B1 (U1).** `read_document` accepts `crpg.ui/1`, and `write_document`
   of the result gives the canonical input bytes exactly. An absent list
   stays absent, `[]` stays `[]`, and an absent `Option` field stays absent.
2. **B2.** As for every family, the following are rejected. An unknown field
   (`id`, `slug` and `name` included), a missing `ruleset`, a missing
   required entry field (`stat`, `pool`, `ability`, `effect`, `outcome`,
   `label`, `variant`, `kind`, `sections`, `select`) and a wrong JSON type
   are `Malformed`. `crpg.ui/2` is `UnsupportedSchema`. A non-integer number
   is `Malformed`.
3. **B3 (U6, D5).** An unknown spelling in one of the six tolerant sets does
   not fail `read_document` or `load_campaign`. It decodes to `Unknown`, and
   it re-encodes byte-identically, `value` included. An unknown section or
   format object must have exactly the keys `{type}` or `{type, value}`; any
   other key set is `Malformed`.
4. **B4.** A known kind with a wrong body is `Malformed` with serde's text
   (`unknown field`, `missing field`). Examples: `{"type":"timeline",
   "value":0}`, `{"type":"stat_group"}`, `{"type":"fraction"}`,
   `{"type":"all","value":[]}` in a selector. An unknown selector or meter
   `type` is `Malformed` (`unknown variant`). Selectors and meters are not
   tolerant.
5. **B5.** Read-time bounds. Every string is 1..=`MAX_UI_TEXT_BYTES` UTF-8
   bytes. This covers every name, key, tag, icon, outcome and `Unknown`
   kind text; `_note` and `Unknown.value` contents are exempt. Each
   top-level list, selector list (`names`, `ids`), `category_tags` and enum
   label list has at most `MAX_UI_ENTRIES` entries. `screens` and each
   `sections` list have at most `MAX_UI_SECTIONS` entries. A selector list,
   an enum label list and a present `category_tags` must not be empty.
   Top-level lists and `sections` may be empty. Order: the document is
   walked in pre-order (`ruleset`, `stats`, `pools`, `abilities`, `effects`,
   `outcomes`, `screens`; within an entry, its fields in declaration order).
   At a list, the count check comes first, then the emptiness check, then
   the entries. The first failure is returned.
6. **B6.** In the same walk, an `Unknown` whose text is a known spelling of
   its set is `Malformed`. A decoder never produces one, so this guards
   `write_document` against in-memory values that would not round-trip.

**Layout and loading**
7. **B7 (D2).** `Document::Ui` is accepted only at a path for which
   `family(p, "ui/")` holds. A `crpg.ui/1` file anywhere else, or another
   kind under `ui/`, is `Layout` with the existing message
   (`crates/crpg-data/src/loader.rs:149–154`). `campaign_document_path`
   returns `Some` for `ui/a.json` and `ui/x/y.json`, and `None` for
   `ui/.json` and `ui.json`.
8. **B8 (U1, U6).** A UI file never changes loading. With and without it,
   `LoadedCampaign.index` is equal, the lock check passes, and
   `serialize_campaign` writes every other file with the same bytes. A
   campaign whose UI file has only B12–B24 defects loads (`Ok`). `validate`
   then reports them, and `validate_files` returns the same list.
9. **B9 (U1).** The library reads `Document::Ui` only in `validate`, in the
   inventory and in `UiSource`/`effective_ui`. No loader, lock, index or
   migration path reads its fields.

**References (inventory)**
10. **B10.** `reference_occurrences` gains these sites, in this order, all
    with `source: None`:
    - `/ruleset`: `Generic`, `ALLOWED_RULESET`, what `"ui ruleset"`.
    - `/stats/<i>/format/value/value` for a `Pool` meter: `PoolTemplate`,
      `"ui pool"`.
    - `/pools/<i>/pool`: `PoolTemplate`, `"ui pool"`.
    - `/abilities/<i>/ability`: `Generic`, `ALLOWED_ABILITY`, `"ui ability"`.
    - `/effects/<i>/effect`: `Generic`, `ALLOWED_EFFECT`, `"ui effect"`.
    - Per screen and section in order:
      `/screens/<i>/sections/<j>/value/value/<k>` for `pool_group` ids
      (`PoolTemplate`, `"ui pool"`), and
      `/screens/<i>/sections/<j>/value/select/value/<k>` for `ability_list`
      ids (`Generic`, `ALLOWED_ABILITY`, `"ui ability"`).

    Sections inside reserved or unknown screens are enumerated too (one
    reference list). `Unknown.value` is never scanned for ULIDs. The generic
    pass then reports `dangling_reference` or `wrong_reference_kind` with
    its existing messages (`crates/crpg-data/src/validation.rs:458–510`).

**Validation** (`walk_ui`, one UI document at a time in path order)

11. **B11.** The checks that need R are marked "(R)". When the ruleset does
    not resolve, only the generic `/ruleset` finding appears for it, and no
    (R) check runs. Checks without (R) always run. Every finding is
    `Severity::Error` except the item-tag warning in B20.
12. **B12 (U1, U6).** (R) Among UI documents whose ruleset resolves, a
    document whose `ruleset` equals an earlier one's (path order) gets
    `duplicate_binding` at `/ruleset`.
13. **B13 (U2, U3).** `stats[i].stat`: if an earlier entry has the same
    name, `duplicate_binding` at `/stats/<i>/stat`; otherwise (R) if the
    stat is not declared, `unknown_stat` there.
14. **B14 (U3).** `stats[i].format`:
    - `Unknown` gives `unknown_kind` at `/stats/<i>/format/type`.
    - (R, stat declared) A known format must suit the stat's kind
      (`crates/crpg-data/src/combat.rs:54–75`); otherwise `format_mismatch`
      at `/stats/<i>/format`. `integer`, `signed`, `fraction` and `percent`
      suit `int` or `fixed`. `boolean` suits `bool`, `enum` suits `enum`,
      `tags` suits `tags` and `dice` suits `dice`.
    - The `fraction` meter at `/stats/<i>/format/value/value`. (R) A `Stat`
      meter that is not declared gives `unknown_stat`. A declared `Stat`
      meter that is not `int` or `fixed` gives `format_mismatch`. A `Pool`
      meter that is not a template gives `unknown_pool`.
    - The labels of `enum` at `/stats/<i>/format/value/<k>/variant`. A repeat
      of an earlier variant gives `duplicate_binding`. Otherwise (R, stat
      declared `enum`) a variant the stat does not declare gives
      `unknown_variant`.
15. **B15 (U3).** `pools[i].pool`: a repeat gives `duplicate_binding` at
    `/pools/<i>/pool`; otherwise (R) a non-template gives `unknown_pool`.
    `style` `Unknown` gives `unknown_kind` at `/pools/<i>/style`.
16. **B16 (U3).** `abilities[i].ability`. If the generic check flagged it,
    nothing more is reported there. Otherwise a repeat gives
    `duplicate_binding`. Otherwise (R) an id that `ruleset.abilities` does
    not list gives `foreign_reference`. A repeated `category_tags` entry
    gives `duplicate_binding` at `/abilities/<i>/category_tags/<k>`.
    `target_hint` `Unknown` gives `unknown_kind` at
    `/abilities/<i>/target_hint`.
17. **B17 (U3, D10).** `effects[i].effect`. If the generic check flagged it,
    nothing more is reported there. Otherwise a repeat gives
    `duplicate_binding`. Otherwise (R) an effect that no ability in
    `UiSource.abilities` names (`effect == Some(id)`) gives
    `foreign_reference`.
18. **B18 (U3).** `outcomes[i].outcome`. A repeat gives `duplicate_binding`
    at `/outcomes/<i>/outcome`. Otherwise (R) a text that is not in
    `UiSource::outcome_labels()` gives `unknown_outcome`. The grammar is
    exactly `critical_success`, `success`, `failure`, `critical_failure` or
    `custom:<n>`, where `<n>` is a decimal `u8` with no sign and no leading
    zero (`custom:0` is allowed). `custom:`, `custom:256`, `custom:01` and
    `Success` are not labels, so they give `unknown_outcome`.
19. **B19 (U4, U8).** `screens[i].kind`. `Unknown` gives `unknown_kind` at
    `/screens/<i>/kind`. `level_up` and `character_creation` give
    `reserved_kind` there. In both cases the screen's sections get no
    further B20 check (B10 still applies). A known non-reserved kind that
    repeats an earlier known non-reserved screen gives `duplicate_binding`
    there, and its sections are still checked.
20. **B20 (U4, U2).** For each section `j` of a screen that B19 does not
    skip, with `S = /screens/<i>/sections/<j>`:
    - `Unknown` gives `unknown_kind` at `S/type`. `choice_steps` gives
      `reserved_kind` at `S/type`.
    - `stat_group` `Group(g)`: if no `stats` entry has `group == Some(g)`,
      `unknown_group` at `S/value/value`.
    - `stat_group` `Names`, each entry at `S/value/value/<k>`. A repeat
      within the screen (see the last item) gives `duplicate_binding`.
      Otherwise (R) an undeclared name gives `unknown_stat`.
    - `pool_group` `Ids`, each entry at `S/value/value/<k>`. A screen repeat
      gives `duplicate_binding`. Otherwise (R) a non-template gives
      `unknown_pool`.
    - `ability_list` `Ids`, each entry at `S/value/select/value/<k>`. If the
      generic check flagged it, nothing more. Otherwise a screen repeat
      gives `duplicate_binding`. Otherwise (R) an unlisted ability gives
      `foreign_reference`.
    - `ability_list` `Tag(t)`: if no `abilities` entry's `category_tags`
      holds `t`, `unknown_tag` at `S/value/select/value`.
    - `ability_list` `sort` `Unknown` gives `unknown_kind` at `S/value/sort`.
    - `item_list` `Tag(t)`: if no `Document::Item` in the campaign has `t`
      in `tags` (`crates/crpg-data/src/document.rs:149`), `unknown_tag` with
      `Severity::Warning` at `S/value/value`.
    - Screen repeats: within one screen, the explicit stat names, pool ids
      and ability ids of all its sections, in order, are compared per class.
      `all`, `group` and `tag` selectors may overlap and are never compared.
21. **B21 (U4, `:376`).** There is no screen–section compatibility rule. A
    `timeline` on an `inventory` screen is valid, because the client draws
    each kind with its own widget.
22. **B22 (U2, D8).** The per-document loop pushes these fields onto
    `locale_refs` with their pointers: each `stats[i]` `label`,
    `short_label`, `description` and `group`; each enum label's `label`;
    each `pools[i].label`; each `abilities[i]` `label` and `description`;
    each `effects[i].label`; each `outcomes[i].label`. The shared coverage
    pass reports `missing_locale_key` with its existing messages.
23. **B23 (U2, D9).** Each `icon` of `pools`, `abilities` and `effects`
    that is not a key of `assets.lock` gives `missing_asset` at its pointer,
    with the `Area.ambience` message and fix
    (`crates/crpg-data/src/validation.rs:1041–1046`).
24. **B24.** One finding per pointer. At a reference pointer, the generic
    finding comes first, then `duplicate_binding`, then the (R) resolution
    finding. Only one of them is emitted. The output is sorted and
    deterministic, as today (`crates/crpg-data/src/validation.rs:1328–1347`).
    The result does not depend on the insertion order of the file map.

**Defaults** (pure, total, deterministic; no I/O, clock or allocation order)

25. **B25.** `UiSource::from_documents(documents, id)` works in this order.
    `ruleset` is the first `Document::Ruleset` with that id (path order);
    if there is none, it returns `None`. `abilities`: for each id of
    `ruleset.abilities` in order, the first `Document::Ability` with that
    id; unresolved ids are skipped. `effects` and `tables`: for each entry
    of `abilities` in order, the first `Effect` or `OutcomeTable` document
    with its `effect` or `outcome_table` id, each one kept only on first
    use; unresolved ids are skipped.
26. **B26.** `ui_outcome_text` spells `CriticalSuccess` as
    `critical_success`, `Success` as `success`, `Failure` as `failure`,
    `CriticalFailure` as `critical_failure`, and `Custom(n)` as
    `custom:<n>`. `ui_outcome` is its exact inverse over the B18 grammar.
    `outcome_labels()` works through `abilities` in order. For each one it
    takes, if its table is in `tables`, the table's band outcomes in order,
    then its `natural_rules` `Override` outcomes in order. It then takes the
    ability's `damage` outcomes in order. Each label is spelt with
    `ui_outcome_text` and kept only on first occurrence.
27. **B27 (U5).** `generated_ui(src)` sets `ruleset = src.ruleset.id` and
    `note = None`. Each of the six lists is `Some`, possibly empty:
    - `stats`: one entry per `ruleset.stats` in declared order, with
      `stat = label = name`.
    - `pools`: one entry per template in order, with
      `label = "pool-<n>"` (`n` is the 1-based position).
    - `abilities`: one entry per `src.abilities`, with `label = ability.name`
      and `target_hint = Some(B29)`.
    - `effects`: one entry per `src.effects`, with `label = effect.name`.
    - `outcomes`: one entry per `outcome_labels()`, with `label = outcome`.

    Every other `Option` is `None`.
28. **B28 (U5, U8, D13).** `screens` is exactly the following, in this order:
    - `character_sheet`: `[stat_group(all)]`.
    - `action_bar`: `[ability_list{select: all}]`.
    - `spellbook`: `[ability_list{select: all, sort: label}]`.
    - `inventory`: `[item_list(all)]`.
    - `combat_hud`: `[stat_group(names: [ruleset.health_stat]),
      pool_group(all), timeline, log]`.

    No reserved kind, `effect_list` or `Unknown` is ever emitted.
29. **B29.** The default `target_hint` is computed from the ability. If
    `requires_target` is false, it is `none`. Otherwise, if
    `allow_self_target` is true, it is `any`. Otherwise it is `enemy`
    (`crates/crpg-data/src/combat.rs:555–557`).
30. **B30 (U5).** `effective_ui(authored, src)` first computes
    `d = generated_ui(src)`. With `None` it returns `d`. With `Some(a)`, it
    sets `ruleset = src.ruleset.id` and `note = None`. For each list, an
    absent authored list gives `d`'s list. A present one gives the authored
    entries unchanged and in authored order, followed by `d`'s entries
    whose key no authored entry has, in `d`'s order. The keys are: stat
    name, pool id, ability id, effect id and outcome text. For screens, the
    authored screens come first, followed by `d`'s screens whose kind no
    authored screen has. Authored reserved and `Unknown` screens are kept.
    `effective_ui` never judges or drops an authored entry.
31. **B31.** For every `src`, `generated_ui` and `effective_ui` (of any
    document that `validate_ui_local` accepts) pass `validate_ui_local` and
    round-trip through `write_document`/`read_document`. Placed as
    `ui/<x>.json` in a campaign whose ruleset, abilities, effects and tables
    validate clean, `generated_ui`'s file has only `missing_locale_key`
    findings: the stat, pool and outcome labels.

**Guards**
32. **B32 (U2, U7).** No known field holds a number or a formula.
    `ui.schema.json` contains no `"integer"` or `"number"` type anywhere.
    An integer can appear only inside `Unknown.value`, which B3 preserves
    and B14/B19/B20 report.
33. **B33 (U10).** The six tolerant sets are exactly the constants. In
    `ui.schema.json`, the string `enum` lists equal `UI_SCREEN_KINDS`,
    `UI_POOL_STYLES`, `UI_TARGET_HINTS` and `UI_SORTS`. The section and
    format `const` values equal `UI_SECTION_TYPES` and `UI_FORMAT_TYPES`. A
    new kind needs a new tag (`crpg.ui/2`) with a registered `1 -> 2` edge.
    `crpg.ui/1` cannot gain one.
34. **B34.** `schema_versions()` has 21 entries, including
    `crpg.ui => 1` with no edge, and `generated_schemas()` has 23 files. The
    22 existing schema files, every fixture, `rulesets/`, `campaigns/` and
    `migrations.json` are byte-identical.

## Errors
No new `DataError` variant. `Malformed` displays as
`malformed document at {path}: {message}`
(`crates/crpg-data/src/error.rs:101–108`). The read-time `message` texts are
exact:
- `ui text at {pointer} must be 1..=128 UTF-8 bytes`
- `ui list at {pointer} exceeds {max} entries` (`max` is 4096 or 64)
- `ui list at {pointer} must not be empty`
- `ui unknown {what} at {pointer} uses a known spelling` (`what` is one of
  `screen kind`, `section type`, `format`, `pool style`, `target hint`,
  `sort`)
- known kind with a wrong body, or an unknown selector or meter: serde's
  own text from `exact_keys`/`field`/`unknown_variant`.

`DiagnosticCode` (`crates/crpg-data/src/validation.rs:37–102`) gains eight
variants, appended after `RealTimeFieldsWithoutRoundTicks` in this order.
Each has an `as_str` arm (`crates/crpg-data/src/validation.rs:105–142`). The existing variants and their
spellings do not change.

| Variant | `as_str` | message | suggested fix |
|---|---|---|---|
| `UnknownKind` | `unknown_kind` | `unknown {what} {text:?}` | `use a kind this schema version defines` |
| `ReservedKind` | `reserved_kind` | `{what} {text:?} is reserved until its data family exists` | `remove it; the generated default omits reserved kinds` |
| `DuplicateBinding` | `duplicate_binding` | `duplicate {what} {value} (first at {file}{pointer})` | `keep one entry` |
| `UnknownOutcome` | `unknown_outcome` | `outcome {text:?} is not produced by ruleset {ruleset}` | `use an outcome the ruleset's tables or damage entries produce` |
| `UnknownTag` | `unknown_tag` | ability: `ability tag {tag:?} is declared by no abilities entry`; item: `item tag {tag:?} is carried by no item in this campaign` | ability: `add the tag to an abilities entry or fix the filter`; item: `add the tag to an item or fix the filter` |
| `UnknownGroup` | `unknown_group` | `stat group {group:?} is the group of no stats entry` | `set the group on a stats entry or fix the selector` |
| `UnknownVariant` | `unknown_variant` | `variant {variant:?} is not declared by enum stat {stat:?}` | `use a variant of the stat's enum` |
| `FormatMismatch` | `format_mismatch` | stat: `format {format} does not suit {kind} stat {stat:?}`; meter: `fraction meter stat {stat:?} is {kind}, not int or fixed` | `choose a format that suits the stat's kind` |

`what` for `unknown_kind` is the B6 list. For `reserved_kind` it is
`screen kind` or `section type`. `{kind}` is one of `int`, `fixed`, `bool`,
`enum`, `tags` or `dice`. `{format}` is the wire spelling. `{ruleset}` and
ULIDs print with `Display` (uppercase). For `duplicate_binding`, `{what}
{value}` is one of: `ui for ruleset {id}`, `stat {name:?}`, `pool {id}`,
`ability {id}`, `effect {id}`, `outcome {text:?}`, `variant {name:?}`,
`tag {tag:?}`, `screen kind {kind:?}`. `{file}{pointer}` locates the first
occurrence, as `duplicate_slug` does (`crates/crpg-data/src/validation.rs:1276–1290`).

Codes that are reused with new messages:

| Code | message | suggested fix |
|---|---|---|
| `unknown_stat` | `unknown stat {name:?} for ui: not declared by ruleset {ruleset}` | `use a stat the ruleset declares` |
| `unknown_pool` | `unknown pool {id} for ui: not a template of ruleset {ruleset}` | `use a pool template id of the ruleset` |
| `foreign_reference` (ability) | `ui ability {id} is not listed by ruleset {ruleset}` | `list the ability in the ruleset or remove the entry` |
| `foreign_reference` (effect) | `ui effect {id} is applied by no ability of ruleset {ruleset}` | `use an effect a listed ability applies or remove the entry` |

`dangling_reference`, `wrong_reference_kind`, `missing_locale_key` and
`missing_asset` keep their existing texts. `diagnostic_for_data_error`
(`crates/crpg-data/src/validation.rs:208–236`) does not change.

## Open questions for the user

**Answered 2026-11-07 (UTC), session 42.** Q1: option (a), a malformed UI
file fails the load like any other document. Q2: the 15 literal test edits
in 11 files are approved.

1. **Should a broken UI file ever be able to stop a campaign from loading?**
   *What:* U6 says UI mistakes "fail campaign validation but never server
   loading". This contract (D5) makes the four mistakes U6 names (unknown
   ids, missing locale keys, unknown kinds, duplicates) non-fatal. A UI file
   that is not valid JSON, has a misspelt *field* name or breaks a size
   limit still fails the load, as every other document does. *Why it
   matters:* in that case the server (single-player included) will not
   start until the UI file is fixed, although the server never uses it.
   *Options:* (a) as written. (b) Every UI defect is non-fatal: the loader
   sets a broken UI file aside as a finding and loads without it. This
   changes `load_campaign`'s fail-fast contract (T010) and the shape of
   `LoadedCampaign`, and needs its own `crpg-data` task first.
   *Recommendation:* (a). The JSON-level mistakes are caught by
   `crpgc validate` and the editor before anyone runs a server, and (b)
   costs a cross-cutting loader change for a rare case.
2. **Approve the literal test edits (15 lines in 11 files)** listed under "Existing-test
   edits"? *What:* existing tests count the families (20) and schemas (22).
   A new family makes them 21 and 23. *Why it matters:* the rules forbid
   editing an existing test without your approval. *Options:* approve, or
   keep the counts and do not add the family (which drops T142).
   *Recommendation:* approve. Each edit changes one number (or adds one
   name or one representative) and keeps the assertion's meaning.
