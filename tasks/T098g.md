# T098g — reserve a slice of the close budget for CONNECTION_CLOSE (`crpg-net-quic`)

## Task / Crate(s) / Purpose

Sole crate: `crpg-net-quic`. Implements the user's answer to D43a (a)
(`tasks/DECISIONS-D43.md:3`): a close still finishes within
`close_flush_timeout_ms`, and a fixed slice of that budget is reserved so the
CONNECTION_CLOSE always goes out. It covers `QuicClient::close(.., Flush)` and
`QuicServer::shutdown`. T098f measured the defect: a client `Flush` close that
spends its whole budget leaves the server waiting for the 60 s idle timeout
(`tasks/T098.md:348-370`). Contract only; adjudicated from blind drafts a and
b and the fact sheet, with every `path:line` below re-read on `19f86a4`.

### Decision

**D1. Why the close is lost (settled from source, no longer UNVERIFIED).**

- `Connection::close` only queues. quinn's `State::close` calls quinn-proto's
  `close`, sets the error and wakes the driver task
  (`quinn-0.11.12/src/connection.rs:435-438`, `:1248-1252`, `:1221-1225`).
  The packet is built and sent only when the spawned `ConnectionDriver` is
  polled (`connection.rs:66`, `:256-283`, `drive_transmit` at `:1016-1070`).
  The vendored quinn-proto only arms the 3×PTO close timer
  (`third_party/quinn-proto/crate/src/connection/mod.rs:1278-1285`,
  `:3499-3501`).
- `Endpoint::close` also only queues: it sends `ConnectionEvent::Close` down
  each connection's channel (`quinn-0.11.12/src/endpoint.rs:299-311`).
  `wait_idle` returns only once the endpoint holds no connection
  (`endpoint.rs:323-335`), that is after each closed connection has drained
  (3×PTO). It is therefore a bounded window in which the runtime keeps polling
  the drivers, not a "close sent" signal.
- With an expired deadline, nothing is polled. `Timeout::poll` polls
  `wait_idle` once (Pending) and then the `Sleep`
  (`tokio-1.53.3/src/time/timeout.rs:211-221`). The `Sleep` registers on its
  first poll (`time/sleep.rs:412-439`), and the wheel fires an entry at once,
  synchronously, when its tick is at or before the wheel's processed time
  (`runtime/time/wheel/mod.rs:94-95`, `runtime/time/mod.rs:426-440`). In
  T098f's probe 2 the same `Instant` had just fired `run_flush`'s
  `sleep_until`, so `timeout_at` returned without yielding. `block_on`
  returned, and dropping the runtime drops the driver unpolled.
- The only yield left on the client was `wait_stop` (`src/queue.rs:652-668`),
  reached after `lane_control` returns (`src/client.rs:671-679`). It yields
  only if the sync thread has not yet stored `Stop`, which is a race. That is
  why the loss is intermittent, and why probe 1 (budget 0, deadline not yet
  processed by the wheel) delivered.
- `yield_now` hands its waker to the scheduler, "which wakes deferred tasks
  only after it has run out of ready tasks and polled the driver"
  (`tokio-1.53.3/src/task/yield_now.rs:38-57`; the current-thread loop is at
  `runtime/scheduler/current_thread/mod.rs:828-882`; the export is behind
  `rt`, `task/mod.rs:276-291`, already enabled).

**D2. Reserve rule.** `R = min(200 ms, B / 4)` with integer milliseconds,
where `B = close_flush_timeout_ms` (valid `0..=2_000`,
`src/limits.rs:126-131`, `:240-245`). `F = B − R`. This is a private constant
and function, not a config field: a field would change the public limits
(ADR-gated, `crates/crpg-net-quic/AGENTS.md:41-43`). Both drafts agree. D43's
own example is "200 ms, or less if the budget is smaller".

**D3. Two fixes, both required.**

- (a) The flush stops at `flush_end = start + F`. The endpoint waits until
  `overall = start + B`, unchanged.
- (b) The I/O thread's exit sequence always yields to the scheduler once
  after `Endpoint::close`, before its bounded `wait_idle`.

  (a) gives the close R of driven time when the I/O thread is on time. (b)
  guarantees at least one poll of every woken driver even when `overall` has
  already passed: when the thread is late, at `B = 0`, or when
  `R = 0` (B ≤ 3). Neither draft had (b). Both left this point UNVERIFIED,
  and without (b) a reserve still loses the close whenever the thread reaches
  the wait after `overall`.

**D4. `QuicServer::close(.., Flush)` also keeps the reserve** (user,
2026-11-07; draft b's D4). Its flush stops at B − R through the same
`close_deadlines` helper, so every `Flush` close has one meaning. Its endpoint
stays alive, so the close goes out after `close_quinn` without an exit
sequence; the cost is that a stalled flush may discard a few more frames.
Quic-gaps #38 (`tests/quic_gaps.rs:229-256`, B = 100, so F = 75 ms) keeps its
`discarded > 0` assertion unchanged, and test 5 adds the peer-side check.

**D5. The server gap is narrower than D43 feared.** In `shutdown`, each
`close_quinn` runs in a spawned control task. The woken drivers are queued in
the same scheduler pass, before `server_main` is polled again
(`current_thread/mod.rs:846-873`). So the loss needs more than 61 ready tasks
or a late thread. The fix still applies there (D43), and test 4 guards it.
The deterministic proof is test 2, because both I/O threads share one exit
helper.

**D6. Reports unchanged.** `CloseReport` (`src/client.rs:92-99`) and
`ShutdownReport` (`src/server.rs:186-195`) keep their fields and meaning.
`outbound_frames_discarded` still counts frames never handed to QUIC
(`src/queue.rs:449-460`). With the earlier cutoff it may grow, and that is
the documented cost of D43a.

### Interface

New private module `crates/crpg-net-quic/src/teardown.rs`, declared
`mod teardown;` in `src/lib.rs` (after `mod server;`, no re-export):

```rust
use std::time::{Duration, Instant};
use crate::close::CloseCode;

/// Ceiling of the slice of `close_flush_timeout_ms` kept for CONNECTION_CLOSE.
pub(crate) const CLOSE_RESERVE_CAP_MS: u32 = 200;

/// `min(CLOSE_RESERVE_CAP_MS, budget_ms / 4)`.
pub(crate) fn close_reserve_ms(budget_ms: u32) -> u32;

/// One close budget's two instants, both taken from one `Instant::now()`.
#[derive(Debug, Clone, Copy)]
pub(crate) struct CloseDeadlines {
    /// A `Flush` stops waiting: now + (budget − reserve).
    pub(crate) flush_end: Instant,
    /// The endpoint stops waiting: now + budget.
    pub(crate) overall: Instant,
}

/// Overflow falls back to `now` for that instant, as `deadline_after` does.
pub(crate) fn close_deadlines(budget_ms: u32) -> CloseDeadlines;

/// I/O-thread exit: `Endpoint::close(code)`, one `yield_now`, then
/// `wait_idle` bounded by `overall`.
pub(crate) async fn finish_endpoint_close(
    endpoint: &quinn::Endpoint,
    code: CloseCode,
    overall: Instant,
);
```

### Behaviour

1. **Reserve arithmetic.** `close_reserve_ms(b) == min(200, b / 4)` for every
   `u32`. `close_deadlines(b)` reads `Instant::now()` exactly once:
   `overall − flush_end == close_reserve_ms(b)` ms exactly, and
   `flush_end <= overall`. (Test 1.)
2. **Client `Flush`.** `QuicClient::stop` (`src/client.rs:457-500`) calls
   `close_deadlines(self.limits.close_flush_timeout_ms)` once, where
   `deadline_after` is now (`:462`).
   - The `FlushRequest` gets `flush_end`.
   - The sync guard is `overall + SYNC_GRACE`.
   - `Stop.deadline` is `overall`.
   - `run_flush` waits for `writer_finished`, a recorded reason, or
     `flush_end`, whichever comes first. It then keeps today's order:
     `record_close` (first-wins, discards the rest), `close_done`,
     `notify_sync`, `close_quinn` (`src/queue.rs:986-999`).

   (Tests 3, 2.)
3. **Client `Discard` and `Drop`.** No flush runs. `Stop.deadline` is
   `overall` (= now + B), exactly as today. (Existing cases.)
4. **`QuicServer::shutdown`.** `close_deadlines` is called once at entry
   (`src/server.rs:706`).
   - Every accepted connection's `FlushRequest` gets the same `flush_end`.
     All are installed before the single wait, and each runs in its own
     control task, so no connection's flush delays another's close.
   - Pending connections still close at once with `Shutdown` (`:719-721`).
     Hello-stage and already-closing records are still skipped (`:715`).
   - The guard is `overall + SYNC_GRACE`, and `Stop.deadline` is `overall`.
   - `connections_closed` and the discarded sums are computed as today
     (`:718`, `:743-747`).

   (Test 4.)
5. **`QuicServer::close(.., Flush)`** (`src/server.rs:596-640`) calls
   `close_deadlines(self.limits.close_flush_timeout_ms)` once, in place of
   `deadline_after` (`:621`). The `FlushRequest` gets `flush_end`, and the
   sync guard is `overall + SYNC_GRACE`. `Pending` and `Discard` closes and
   the `discarded_since` report are unchanged (`:612-619`, `:636-638`). After
   the change, `deadline_after` is used in `src/server.rs` only by `Drop`
   (review: `rg -n "deadline_after" crates/crpg-net-quic/src/server.rs`
   prints only the import and the `Drop` line). (Tests 5, 1.)
5a. **`QuicServer::Drop`** is unchanged: `Stop.deadline = deadline_after(B)`
   (`src/server.rs:765-783`). (Case
   `server_shutdown_and_drop_close_every_connection`.)
6. **Exit sequence.** `client_main` (`src/client.rs:680-685`) and
   `server_main` (`src/server.rs:862-864`) each replace their
   `endpoint.close` + `timeout_at` pair with exactly one
   `finish_endpoint_close(&endpoint, stop.code, stop.deadline).await`. The
   helper does, in order:
   - (i) `endpoint.close(..)`;
   - (ii) `tokio::task::yield_now().await`, exactly once and unconditionally;
   - (iii) `let _ = tokio::time::timeout_at(Instant::from_std(overall),
     endpoint.wait_idle()).await`.

   No `sleep`, no second budget, and no wait past `overall` other than the
   single yield. Guarantee: every connection driver woken by `Connection::close`
   or `Endpoint::close` is polled at least once before the runtime is dropped,
   even when `overall` has passed. A thread that is on time also drives the
   endpoint for up to R more. (Test 2.)
7. **`finish_endpoint`** (connect-failure path, `src/client.rs:688-696`) is
   unchanged.
8. **Bound.** `close`/`shutdown` return no later than today's bound:
   `overall` plus the existing `SYNC_GRACE` liveness guard plus the join. A
   flush that completes early closes early, and nothing waits for the
   reserve. (Review: no sleep in `teardown.rs`.)
9. **Unchanged.** Wire bytes, codes, `CloseReason` mapping
   (`src/queue.rs:89-104`), first-wins publication, frames already received
   staying drainable, and every existing test's assertions. Case 13 is among
   them (Tests 6).

### Tests

The waits are the rig's 30 s guards (`tests/support/quic_rig.rs:32-33`),
never oracles. A lost close panics `deadline: …` within 30 s, which is half
the 60 s idle timeout (`src/limits.rs:27`). `IdleTimeout` therefore can never
pass as a close, and no wall-clock assertion is added. No sleep is used as an
oracle. Tests 1–2 are unit tests in `src/teardown.rs` (`#[cfg(test)] mod
tests`). Tests 3–5 go in a new file, `tests/close_budget.rs`, which starts
`#[path = "support/quic_rig.rs"] mod quic_rig;` and defines
`INTENT_CAP = 4_096` and `DELTA_CAP = 65_536`. Test code must stay clean
under the crate's scope grep (no `println`, `f32`, `f64`, `unsafe`,
`tracing` and so on).

1. **`close_reserve_split_is_exact`.**
   - For each `(budget, reserve)` in `(2_000,200) (800,200) (799,199)
     (100,25) (4,1) (3,0) (0,0) (u32::MAX,200)`, assert
     `close_reserve_ms(budget) == reserve`.
   - For each budget ≤ 2,000:
     `let before = Instant::now(); let d = close_deadlines(budget); let after = Instant::now();`
     - assert
       `d.overall.duration_since(d.flush_end) == Duration::from_millis(reserve)`;
     - assert `d.overall >= before + Duration::from_millis(budget)`;
     - assert `d.overall <= after + Duration::from_millis(budget)`.
   - *Control:* change the cap to 199 or the divisor to 3, and the named row
     fails.
2. **`goodbye_sent_after_the_endpoint_deadline_passed`** (the deterministic
   proof).
   - Fixtures: `include_bytes!("../tests/fixtures/server_a.cert.der")` and
     `server_a.key.pk8.der`.
   - Server: bind a `std::net::UdpSocket` on `127.0.0.1:0` on the test thread
     and move it into a `std::thread`. That thread builds a current-thread
     runtime (`enable_io`, `enable_time`), then:
     - creates a `quinn::Endpoint::new(EndpointConfig::default(),
       Some(tls::server_config(&ServerIdentity::new(cert, key),
       &[ALPN_LANE0_V1], &ServerLimits::v1())?), socket,
       Arc::new(TokioRuntime))`;
     - awaits `accept()` and the `Incoming`;
     - sends `()` on a `tokio::sync::oneshot`;
     - returns
       `tokio::time::timeout(Duration::from_secs(30), connection.closed()).await.ok().map(|e| reason_from(&e))`.
   - Client: on the test thread, a current-thread runtime runs one `block_on`
     that:
     - connects with `tls::client_config(CertificatePin::of_certificate(cert),
       Arc::new(AtomicBool::new(false)), ALPN_LANE0_V1,
       &ClientLimits::v1())` to `TLS_SERVER_NAME`;
     - awaits the oneshot;
     - sets `let passed = tokio::time::Instant::now() + Duration::from_millis(20);`
       and awaits `sleep_until(passed)`. The wheel has now processed
       `passed`;
     - calls `close_quinn(&connection, CloseCode::Normal)`;
     - awaits
       `finish_endpoint_close(&endpoint, CloseCode::Normal, passed.into_std())`.
   - Then `drop(runtime)`, join the server thread, and assert
     `== Some(CloseReason::Peer { code: 0 })`.
   - *Control (deterministic, record it):* replace the helper's body with the
     pre-fix pair (`endpoint.close`, then `timeout_at(overall, wait_idle)`).
     The test must then fail with `None` on every run, by D1's cites.
     Restore the body.
3. **`client_flush_close_over_budget_reaches_peer`** (the D43 regression,
   T098f probe-2 shape).
   - Use one `bind_server(ServerLimits::v1())`. For each
     `(s, budget)` in `[(1, 2_000), (2, 100)]`:
     - set `limits = ClientLimits::v1()` with
       `close_flush_timeout_ms = budget`, then
       `connect_accepted(&mut server, limits, 1, epoch(s))`;
     - send `pattern(s, n, INTENT_CAP)` for n = 1..=10 with `.expect`;
     - `server_recv` the 10 frames and assert each is equal;
     - for n = 11..=128, `until("queue", ..)` retries on
       `Err(SendError::QueueFull)` and panics on any other error;
     - `let report = client.close(CloseCode::Normal, CloseMode::Flush);`
   - Assert:
     - `report.inbound_frames_discarded == 0`;
     - `report.outbound_frames_discarded >= 1`;
     - then loop `server_recv`: each `Ok` is
       `pattern(s, k, INTENT_CAP)` for k = 11, 12, …, and the first `Err`
       equals `ServerError::Closed(CloseReason::Peer { code: 0 })`;
     - `k < 128`;
     - `k + report.outbound_frames_discarded <= 128`;
     - `next_closed(&mut server) == (conn, CloseReason::Peer { code: 0 })`.
   - Why it is deterministic: quinn writes only within the peer's flow credit
     (`third_party/quinn-proto/crate/src/connection/streams/state.rs:842-846`,
     `streams/send.rs:68-72`). The stalled server absorbs about 10 + 64
     queued + 1 parked + 16 in-window frames of 4,100 B, so the FIN is never
     acked, at least about 35 frames stay queued, and the 118 sends fit in
     the 64-frame client queue plus that credit.
   - *Control:* run against pre-fix `src/` 5 times and record the count of
     `deadline: server frame` failures. T098f reproduced it with this shape.
     Zero failures does not block, because the outcome on pre-fix code
     depends on the `wait_stop` race (D1) and test 2 is the deterministic
     proof.
4. **`shutdown_over_budget_reaches_every_client`.**
   - Setup:
     - `bind_server(ServerLimits::v1())`;
     - a *stalled* client: `ClientLimits::v1()` with `inbound_frames = 1`,
       `inbound_bytes = DELTA_CAP`, and stream and connection windows of
       65,540 (the shape of `tests/quic_gaps.rs:233-240`), on `epoch(1)`;
     - a *steady* client: v1, on `epoch(2)`;
     - queue 8 × `pattern(1, n, DELTA_CAP)` to the stalled client and
       3 × `pattern(2, n, 1_000)` to the steady one, each with `.expect`;
     - `let report = server.shutdown();`
   - Assert:
     - `connections_closed == 2`;
     - `inbound_frames_discarded == 0`;
     - `outbound_frames_discarded >= 1`;
     - the steady client gets its 3 frames in order, then
       `Err(CloseReason::Peer { code: 1 })`;
     - the stalled client gets an in-order prefix of k frames, then
       `Err(CloseReason::Peer { code: 1 })`;
     - `k < 8`;
     - `k + report.outbound_frames_discarded <= 8`.
   - *Control:* this is a guard, not a fail-first test. Per D5, pre-fix code
     usually passes. Run it on pre-fix `src/` once and record the result.
5. **`single_close_flush_keeps_the_reserve`** (D4).
   - Setup: `bind_server(ServerLimits::v1())` (B = 2,000, so R = 200).
     Connect one *stalled* client exactly as in test 4, on `epoch(3)`, and
     queue 8 × `pattern(3, n, DELTA_CAP)` with `.expect`.
   - Run:
     `let t0 = Instant::now(); let report = server.close(conn, CloseCode::Normal, CloseMode::Flush).expect("close"); let took = t0.elapsed();`
   - Assert:
     - `took >= Duration::from_millis(1_800)`. This is a lower bound only, so
       it is load-safe: the stalled peer never lets the flush finish before
       `flush_end`;
     - `report.outbound_frames_discarded >= 1`;
     - `report.inbound_frames_discarded == 0`;
     - the client gets an in-order prefix of k frames, then
       `Err(CloseReason::Peer { code: 0 })`;
     - `k < 8`;
     - `k + report.outbound_frames_discarded <= 8`;
     - `next_closed(&mut server) == (conn, CloseReason::Local(CloseCode::Normal))`.
   - No upper wall-clock bound is asserted, because one would be flaky on a
     loaded runner. That the flush stops at B − R rather than B is pinned by
     test 1's exact split together with the Behaviour 5 `rg` check, which
     shows `close` builds its `FlushRequest` from `close_deadlines`.
   - *Control:* this is a guard. Pre-fix code passes too, since it stops at
     B ≥ 1,800 ms and its endpoint keeps running. Record one pre-fix run.
