## Interface — declaration-only approval gate

Reuse existing `ir::ActionCall { action_id: String, args: BTreeMap<String,
DataValue> }`, `ActionSignature { action_id: String, parameters:
Vec<ActionParameter> }`, `ActionParameter { name, value_type, required }`
and `ValueType`/`DataValue` as published. Approve exact immutable store
constructor/lookup/validate-call signatures, versioned declaration bundle,
structured error/diagnostic locations and deterministic first-failure order.

Proposed store is `BTreeMap<String, ActionSignature>`, keyed by exactly the
signature's id, preserving parameter declaration order. Candidate A4 limits:
1024 actions, 32 parameters/action, 128 UTF-8 bytes per nonempty action/parameter
name. D16 must explicitly approve or replace these (B5's network maxima do not
automatically set IR limits). Specify bundle wire/schema version and total
argument/value size/depth policy using existing data validation ownership.

## Behaviour

Caller-supplied trusted declarations assemble once. Reject duplicate ids and
parameter names, missing required args, extra args and mismatched value
categories; no last-wins overwrite, implicit coercion or sorting parameters.
Diagnostics and traversal are deterministic. Validation is read-only and can
be used by editor/schema consumers without linking sim/rules/script.

Version bundle identity with engine/content compatibility. Same action name
with changed parameter meaning is an explicit compatibility/migration decision,
not just a shape match. Pin unknown bundle version behavior, old bundle
acceptance and additive action policy. Campaign declarations cannot register
Rust handlers, load libraries or replace trusted semantics. Combat ability ULIDs
and IR action-id strings remain distinct namespaces.

## Constraints

[Standing rules](POST-T018-RULES.md) apply. Data only; no upward edge, function
pointers, filesystem discovery, native loading or script dependency. If schema

modules. No new dependency, document family, migration or schema-registry entry.

pub struct ActionBundleIdentity { pub bundle: Ulid, pub revision: Digest }
pub struct ActionSignatureStore { /* private immutable fields */ }
impl ActionSignatureStore {

    -> Result<ActionSignatureStore, SignatureError>;

    -> Result<Vec<u8>, SignatureError>;

    pub code: SignatureErrorCode,
    pub pointer: String,
}
pub enum SignatureErrorCode {
    Malformed,
    UnsupportedVersion,
    InvalidIdentifier,
    DuplicateAction,
    DuplicateParameter,
    RevisionMismatch,
    BundleMismatch,
    UnknownAction,
    MissingArgument,
    ExtraArgument,
    TypeMismatch { expected: ValueType, actual: ValueType },

Store, identity and errors derive `Debug, Clone, PartialEq, Eq`. Error implements
Display/Error with no source: `<snake_case_code> at <pointer>`; empty root
pointer displays `/`. TypeMismatch prints only `type_mismatch`; LimitExceeded
prints `limit_exceeded`. No unrestricted Deserialize for Store; byte readers
are its serialized construction boundary. Identity may derive serde, with strict
fields. No mutator, insertion API or mutable references; `iter` is exact
lexical Rust string order, not locale order. `get` is inert and returns None for
any absent spelling (including invalid ids), not a validation operation.

### Declaration construction and deterministic failures

Store is a BTreeMap keyed by exact action_id. Reject more than 1024 before
sorting/cloning entries. Empty bundles and zero-parameter actions are valid.
Action/parameter identifiers are 1..=128 UTF-8 bytes; preserve all characters
exactly, with no normalization, trimming, case folding or slug grammar. This is
symbolic vocabulary, never a path. Do not accidentally use character count.

For constructor errors, use logical JSON pointers under `/actions/<escaped-id>`
and `/actions/<escaped-id>/parameters/<escaped-name>` (RFC 6901 escape `~` and
`/`). These are stable symbolic locations, not source-array offsets. Check
action id validity first in lexical id order, then the lexically first duplicate
action id, then each unique action in lexical order: parameter count, invalid
parameter names in lexical order, duplicate names in lexical order. Parameter
storage preserves original declaration order even though diagnostics sort names.
No overwrite or implicit duplicate removal. Current ValueType is already closed.
Count errors point to `/actions` or that action's `/parameters`; invalid id
errors point to its logical id location. Display never embeds attacker values
except the escaped pointer; callers choose logging policy.

### Exact bundle serialization and compatibility

Canonical integer JSON object with exactly `version`, `bundle`, `revision`,
`actions`. Version=1; bundle uses core canonical ULID text; revision uses existing
Digest lowercase hex; actions is an array in lexical action_id order with
unchanged ActionSignature serde and preserved parameter order. Use existing
`canonical_json` (recursive lexical keys, two-space indent, final LF).

Revision is **derived**, not an arbitrary version label: BLAKE3 over canonical
JSON of exactly `{version:1,bundle:<id>,actions:<canonical ordered array>}`,
excluding only the revision field to avoid self-reference. This is a declaration
identity, not a signature authenticating executable code. `new` calculates it.
Reader recomputes and rejects disagreement. Reordering action input leaves the
revision unchanged; reordering parameters, changing required/type/name, adding
an action or changing bundle id changes revision. Exact identity is required;
no semver or additive compatibility fallback. Handlers must separately bind this
identity in T029b; a same-shaped handler is not automatically trusted.

Reader caps raw input at 32 MiB before UTF-8/JSON parsing; then strict integer
JSON/duplicate-key/trailing-input checks; exact envelope fields and typed version;
unsupported version; typed shapes/ULID/Digest; constructor checks; revision check.
Unknown/missing fields, duplicate JSON keys, null in nonnullable fields, invalid
UTF-8, fractional numbers and trailing bytes are Malformed. Constructor errors
retain logical pointers; parser errors use root `""`, envelope version errors
`/version`, bad revision `/revision`. A syntactically invalid unknown-version
document is Malformed first. Do not route through a last-key-wins Value parser.
Raw input caps bound parsing allocation; declaration count/name limits need not
be claimed to fire before the byte-bounded DOM is built. No input-size cap is
silently inherited from the independent D0 filesystem proposal.

Writer serializes only validated stores with the same 32 MiB output ceiling.
Use a bounded output/counting path; no unbounded allocation from unchecked
constructor data. Current maximum names/counts fit this ceiling, including JSON
escaping. Test the worst escaped-name construction, not just ASCII lengths.

### Call validation, traversal and first failure

`validate_call` borrows caller data; it never clones the entire value tree or
returns a capability to execute later without revalidation. Order:

1. Exact bundle id and revision equality, else BundleMismatch at root.
2. Action id and argument-name byte validity (action first, args lexical), then
   at most 32 args (LimitExceeded Arguments at `/args`).
3. Structural value budgets by depth-first traversal of arguments in lexical
   name order. Every DataValue, including List/Map containers, counts one node;
   each argument's root has depth 1. Lists keep authored index order; maps use
   lexical keys. Global node total covers all arguments. Before visiting a node
   check depth then increment/check node total. Check Text bytes on visit; Map
   key bytes before its child. Limit strings to 4096 UTF-8 bytes, including map
   keys (empty map keys are allowed). An empty container still counts one node.
4. Canonical encoded **ActionCall alone**, with existing canonical_json format,
   must fit 64 KiB including whitespace/final LF. Count with a capped writer
   before retaining output; do not allocate a potential multi-megabyte encoding
   just to discover it is too large. In-memory deeply nested input must fail by
   bounded iterative inspection before any recursive serde traversal.
5. UnknownAction at `/action_id`; extra args in lexical order at
   `/args/<escaped-name>`; then declared parameters **in declaration order**,
   checking missing required and exact category matches. Optional absence is
   accepted; optional supplied wrong type is TypeMismatch. List/Map only constrain
   the root category, not a homogeneous element type. Signed/unsigned/fixed
   stay distinct. ObjectRef category does not resolve an authored object here.

Structural value pointers use the existing DataValue wire path: append `/value`
to enter List/Map/Text payloads, then list index or escaped map key. A map-key
byte error points at that key's value location. Global canonical-size errors
point to root; depth/node errors point to the first offending DataValue.

`read_call`: raw 64-KiB cap first; identity check second; strict JSON parse/shape
third; then the validation stages above. Keep serde_json recursion protection
enabled (32 DataValue levels fit the ordinary limit despite tagged wrappers).
Reject duplicate keys and malformed tags even when an action is unknown. Raw
cap violations are CallBytes, parser failures Malformed at root. `write_call`
validates then emits canonical bytes; rejection leaves store and call unchanged.
No call envelope/bundle field is added to existing authored ActionCall: callers
supply the selected identity explicitly.
