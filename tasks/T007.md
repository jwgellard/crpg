## Task
Give `crpg-sim` its `World`, `ComponentStore<T>`, `Timeline`, `Transform` and
`SimEvent`, plus the generic event substrate in `crpg-core` (ADR-0008 scoped
exception). First task in the crate, so it also writes `crpg-sim/AGENTS.md`
and `docs/architecture/crpg-sim.md`.

## Crate(s)
`crpg-sim` (only), except the substrate module in `crpg-core`, which rides
here under the one-task-one-crate exception stated in ADR-0008 §Decision
(~60 lines, fully generic, no domain content, single consumer). This file is
the "stop and say so" for that exception: it is pre-authorised, not smuggled.

## Purpose
The data structure the entire simulation lives in (spec §2.4). T006a built the
entity arena on purpose so this task would not build a second one: `World`
owns a `GenerationalArena<EntityMeta>` and inherits its property-tested
id-reuse safety, lowest-index reuse, ascending iteration and retirement
semantics. What this task adds is everything around the arena: dense component
storage, the timeline container, the live event queue, the RNG, and the tick
counter — with spawn/despawn/query and skeleton serde as the tested surface.

## Behaviour
- `spawn` stores the given `EntityMeta` as-is and mints through the arena
  (generations from 1, tombstone rules inherited, not reimplemented), then
  enqueues `Spawned` stamped with the world's current tick. `meta` carries
  no information today — it exists so the signature survives the day
  `EntityMeta` gains fields.
- `despawn` on a live id removes the entity, strips its entries from every
  component store and the timeline, enqueues `Despawned`, and returns `true`.
  On a dead id it returns `false` and enqueues nothing. After any despawn,
  no store key and no timeline entry addresses a non-live entity.
- `drain` yields ascending `(tick, seq)` regardless of push order (stable
  sort at drain time) and clears the queue. `seq` is a monotonic `u64`
  assigned at push, saturating on overflow (unreachable in practice;
  wrapping would break the ordering contract, so it must not wrap).
- `ComponentStore` iteration follows `IndexMap` insertion order, which is
  deterministic for identical operation sequences. Document that consumers
  must not assume sorted order — if sorted iteration is ever needed, that is
  a new method with its own test, not a silent change to `iter`.
- `Transform` holds `f32` spatial state only (E006-A). No `f64` anywhere in
  the crate — positions, velocities, or otherwise. The lint enforces it.
- The store accessors do no liveness checking; `World::despawn` is what
  maintains the no-dangling invariant. Say so on the type.
- Serde covers the skeleton only (E014): entities, stores, timeline, event
  queue, RNG, tick. There is no stat data in `World` until T014, so no
  conversion pair is needed here — but the module doc on `world.rs` must say
  that explicitly, so a later agent does not derive `Serialize` on a struct
  containing `StatId` keys without noticing.

## Constraints
- Normal dependencies: `crpg-core` (path), `serde` + `indexmap` (workspace).
  Dev-dependencies: `proptest` + `serde_json` (workspace, authorised by
  ADR-0006 for exactly this kind of round-trip testing). Nothing else. The
  ALLOWED table already permits `crpg-sim -> {crpg-core, crpg-data,
  crpg-rules}`; this task uses only the `crpg-core` edge — do not add the
  others speculatively.
- `#![forbid(unsafe_code)]` and `#![warn(missing_docs)]` stay (both already
  on the crate root). Every public item gets a doc comment (spec §15.6).
- No `HashMap`/`HashSet` — anywhere, including tests. No `f64`, no clock, no
  threads, no I/O. `DeterministicRng` is the only randomness source, reached
  through `World::rng_mut` with explicit stream names.
- `crpg-core/src/event.rs` must not mention any game, ruleset, sim, net or
  script concept — not in types, not in docs, not in tests. If the substrate
  wants domain content, that content is its own task (per ADR-0008).
- `lib.rs` declares modules and re-exports the public surface. Keep it to
  `pub mod` / `pub use` and the crate doc comment.

## Test
Add `crates/crpg-core/tests/event.rs` (substrate) and
`crates/crpg-sim/tests/world.rs` (everything else).

1. **Queue ordering.** Property test: push random `(tick, payload)` pairs
   (ticks out of order, duplicates included); `drain` returns ascending
   `(tick, seq)` and clears (`len() == 0`, second drain empty).
2. **Queue serde round-trip.** `deserialize(serialize(q)) == q`, including a
   drained-then-repushed queue (the `next_seq` counter survives).
3. **Skeleton round-trip (10,000 cases).** `ProptestConfig::with_cases(10_000)`
   over random spawn/despawn/set-transform/timeline-insert/rng-draw
   sequences: `deserialize(serialize(w)) == w` every time (spec §24 T7).
4. **No dangling entries.** After any random op sequence, every
   `transforms` key and every timeline entry addresses a live entity, and
   `transforms.len()` plus `timeline.len()` never exceed the live count.
5. **Despawn contract.** Unit tests: despawn of a dead id returns `false`
   and enqueues nothing; despawn of a live id strips components and timeline
   entries and enqueues exactly one `Despawned`; re-despawn returns `false`.
6. **Determinism across instances.** Two worlds run through the same op
   sequence (including RNG draws) iterate identically and serialize to
   byte-identical output.
7. **Timeline order.** Insertion in scrambled key order still iterates
   ascending `(InitiativeKey, EntityId)`, with `EntityId` breaking key ties.

Command that must pass: `cargo test -p crpg-sim` **and**
`cargo test -p crpg-core` (the substrate lives there).

## Out of scope
- Advancing time, `tick(&mut World)`, systems, `state_hash`. All T008.
- `StatBlock` or any second component type, `SpatialIndex`,
  `DynamicComponentStore`. Deferred per E015 with reservations, not forgotten.
- Rotation in `Transform`, movement integration, collision, LOS. Later tasks.
- `SimDelta` shape, `apply_delta`, `ReplicaWorld`, prediction buffer. T018
  and the bridge (E015 reserves the seam; this task does not design it).
- AI, script hooks, combat, areas, `Campaign` message queue, persistence
  backend. Nothing outside `{core substrate, sim skeleton}`.
- A `remove(entity)` faster than O(n) on `Timeline`, sorted iteration on
  `ComponentStore`, or any other perf work. Correct and deterministic first;
  E019 owns measurability.
