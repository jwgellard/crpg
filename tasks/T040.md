## Task
Replace the refuse-to-run `crpg-server` binary (`crates/crpg-server/src/main.rs:9–12`)
with the dedicated server program for Windows/MSVC and a Godot-free
Linux/GNU build. It reads one configuration file, loads a host save, binds
the area's navigation mesh, starts the resumable QUIC adapter, and runs
T154's run loop on the runner thread (D65a: it hosts the loop, it does not
reimplement it). It writes one server log line for every rejected client
message (D67a) to standard error and, when configured, to a log file. On the
console command `quit` it stops the loop, closes the adapter and saves the
world back to its save file. A small library addition lets the binary see the
rejections the loop's intake stage already produces. A CI job builds and
uploads both server binaries (the server half of gate 12,
`docs/CRPG_ENGINE_SPEC.md:1333`). Gate 13 smokes stay T041's.

## Readings
Design decisions this contract makes. Each needs approval with the contract.

1. **The binary is the OS adapter; the library's fence stays, and the
   binary keeps the token fence.** ADR-0012 puts process, filesystem and
   service concerns above the simulation crates
   (`docs/adr/0012-windows-primary-platform.md:28–29`); the binary is that
   adapter, so `main.rs` may use `std::fs`, `std::io` and `std::sync`
   directly. The library keeps invariant 7 unchanged (`crates/crpg-server/AGENTS.md:135–143`).
   The binary is still in `run_source_rules.rs`'s fenced list
   (`crates/crpg-server/tests/run_source_rules.rs:24`), so `main.rs` names
   none of `Instant`, `SystemTime`, `thread::`, `sleep`, `recv_timeout`,
   `UdpSocket`, `TcpListener` (`:28–37`); that test stays byte-identical and
   passing. Draft A's split, with the token fence kept. *Rejected:* reading
   operator files in the library (spreads OS I/O into the reusable host);
   editing the source-rules test (weakens a test).
2. **The binary never reads a clock: the loop starts at 0.** Load, start and
   loop all use `now_ms = 0` (`START_MS`), and the clock is
   `SystemClock::starting_at(0)`, so the clock origin equals the loop start
   as T154 requires (`tasks/T154.md`, Reading 13). The host's time is
   injected and per process; nothing compares it across processes (a loaded
   host takes `now_ms` fresh, `crates/crpg-server/src/save.rs:287–292`).
   *Rejected:* draft A's "`now_ms` read once at startup" (needs
   `SystemTime`, a fenced token in `main.rs`).
3. **The loop is T154d's, unchanged.** The binary builds
   `runner::spawn(HostLoop::new(hosting, START_MS), SystemClock::starting_at(START_MS))`
   over `QuicHosting` and talks to it only through `RunnerHandle`
   (`crates/crpg-server/src/runner.rs:88`, `:146–188`). Both drafts.
   *Rejected:* a binary-side `Hosting` wrapper that calls `pump` itself to
   see its report (reimplements the intake stage, against D65a).
4. **Rejections reach the binary through one intake observer.** T154d's
   intake is `quic.pump(now)` with the report discarded (`tasks/T154.md`,
   B-14), so no log line is possible without a library change. T040a gives
   `QuicHosting` an optional observer, called with `(now_ms, &report)` after
   every successful intake. Neither draft: draft A's `QuicHost::last_report`
   clones every report, is overwritten by `flush` in the same cycle, and
   makes the AI hook do logging; draft B names no mechanism.
5. **What counts as a rejected client message is the library's, not the
   binary's.** The binary holds no host policy (`crates/crpg-server/AGENTS.md:24–26`),
   so the classification is `QuicPumpReport::rejections`, next to the report
   it reads. A rejection is: a refused hello (`HelloOutcome::Refused`,
   `crates/crpg-server/src/quic.rs:263–276`); a refused resume opening
   (`ResumeOutcome::Refused`, `:326–340`); an ingest refused with a code
   other than `QueueFull` (a `QueueFull` frame is held and retried, not
   rejected, `crates/crpg-server/tests/host_quic.rs:1921–1940`); a refused
   transfer frame (`TransferDisposition::Refused`, `crates/crpg-server/src/host.rs:340–349`);
   a failed `check_frame`; and every admission result with status
   `Rejected` that is not the retained head (`crates/crpg-server/src/host.rs:428–439`).
   Lane-1 traces (T150c) are not read: the resumable endpoint (Reading 8)
   carries no lane 1. Neither draft classified.
6. **One configuration file; the command line is `--config`, `--help`,
   `--version`.** Every setting is a key of one JSON file read with the
   crate's existing `serde_json` (`crates/crpg-server/Cargo.toml`, the
   `serde_json` line); relative paths in it resolve against the file's own
   directory. *Rejected:* both drafts' flag-per-setting with file overlay
   (two sources, a precedence rule and twice the tests, for a program an
   operator configures once); TOML or YAML (a new parser dependency).
7. **No new dependency.** The command line is parsed by hand over
   `std::env::args_os`; logging is a `std::io::Write` line writer; the
   certificate and key are read as DER, which `ServerIdentity::new` takes
   (`crates/crpg-net-quic/src/identity.rs:83`), as the tests' fixtures are
   (`crates/crpg-server/tests/support/quic_host_rig.rs:48–51`). Draft A.
   *Rejected:* draft B's PEM "std-readable" (PEM is base64 text; decoding it
   needs a dependency or a hand-written decoder). D70b asks the user.
8. **The endpoint is `bind_resumable` with `start_resumable`.** The T025b
   manager edit (`tasks/T025b.md:862–863`) and `start`'s own warning
   (`crates/crpg-server/src/quic.rs:560–565`). Both drafts. *Rejected:*
   `bind_movement` (offers only `/3`, takes no resume opening,
   `crates/crpg-net-quic/src/server.rs:244–249`, and saves are V1/V2 hosts,
   `crates/crpg-server/src/host.rs:144–149`); a movement endpoint is a
   follow-up once resume on `/3` exists ("Manager edits").
9. **Start-up order: cheap checks, incarnation, load, mesh, unpause, bind,
   start, invitations, hooks, spawn.** Every file is read and validated
   before the incarnation is spent; the mesh is bound before unpausing
   (a restored host is unbound and `Restore`-paused, `tasks/T154.md`,
   Reading 11); a restored host already carries `HostSettings::multiplayer()`
   (`crates/crpg-server/src/host.rs:480–483`), the dedicated default
   (`docs/adr/0029-kernel-range-and-time-model.md:295`), so no
   `set_settings` call. Invitations are registered after `start_resumable`
   because `register_invitation` is a `QuicHost` method
   (`crates/crpg-server/src/quic.rs:1629`). *Rejected:* draft A's
   registration before start (no such call exists); serving a paused world.
10. **The incarnation is automatic: a sidecar file, spent before the load.**
    The loader needs an incarnation above every one ever used for the
    authority (`crates/crpg-server/AGENTS.md:300–302`) and refuses one not
    above the saved one (`crates/crpg-server/src/checkpoint.rs:212–213`).
    The binary keeps `<save>.incarnation` (decimal, newline), uses
    `last + 1` (absent → `1`) and writes it **before** loading, so a crash
    after clients bound can never reuse it. Draft A's sidecar, changed:
    no `--incarnation` value to supply, and written before the load (draft
    A wrote after it). *Rejected:* draft B's operator-supplied value (the
    trap the AGENTS file names).
11. **Navigation: `bind_area_bounds` at area load; `place` has no call site
    yet.** With no `crpg-data` edge (`crates/crpg-server/AGENTS.md:151–154`),
    the bounds are operator facts, like `SaveIdentity`: an optional `area`
    key, whole world units in `-32768..=32767`, converted with
    `Fx16_16::from_int` (`crates/crpg-core/src/fixed.rs:63`), bound with
    `Host::bind_area_bounds` (`crates/crpg-server/src/host.rs:4611`) before
    unpausing. Binding places every off-mesh mover (T037 Reading 5,
    `tasks/T037.md:160–167`). `place` is for movers created later by a spawn
    or an area transfer, and the host has neither operation
    (`grep "pub fn .*spawn\|pub fn .*transfer" crates/crpg-server/src/host*.rs`
    finds only the snapshot-transfer calls) and the binary makes neither,
    so T040 closes the backlog row's first half and carries `place` to the
    first task that adds a server-side spawn or area transfer. Draft A's
    optional bounds. *Rejected:* draft B's required area file and its
    "spawned mover is placed" test (no spawn exists to place).
12. **AI: an optional operator file of sides, driven once per cycle (D70c).**
    `Host::drive_ai` needs `crpg_ai::Sides` and the controlled set from the
    caller (`tasks/T153.md`, Reading 3), and the server reads no authored
    data. The `ai` key names a JSON file of both; the binary sets a
    `QuicAiHook` that calls `QuicHost::drive_ai(&sides, &controlled, MVP_AI_BUDGET)`
    once per cycle and drops its report. D65a: the server, not a client,
    runs the AI. *Rejected:* draft A's "no AI until campaign loading" (a
    dedicated fight whose monsters never act, which T041's smoke cannot
    pass); a `crpg-data` edge (reverses D20). D70c asks the user.
13. **Stopping: the console line `quit`; end of input keeps serving
    (D70a).** The main thread reads standard input. `quit` stops the runner,
    shuts the adapter down and saves to the `save` path. End of input
    (a service or a detached run, where standard input is empty) does not
    stop the server: the main thread then waits on the runner. A Ctrl-C or
    a kill ends the process at once with no final save. *Rejected:* draft
    A's "end of input stops" (a service with empty input would exit at
    once); draft B's signal stop (a Windows console handler needs `unsafe`,
    forbidden outside `crpg-godot`, root `AGENTS.md`; a Unix handler needs a
    dependency or `unsafe`).
14. **A clean `quit` always saves.** A dedicated world is persistent; the
    save goes through `save_host_file` on the closed host
    (`crates/crpg-server/src/quic.rs:364–378`, `crates/crpg-server/src/save.rs:272`),
    an atomic replace. Draft A. *Rejected:* draft B's opt-in
    `--save-on-shutdown` (losing a session's play by default).
15. **Logs: standard error always, plus a file when configured.** Draft A
    and draft B agree; D67a's "where do logs go" answer. Standard output
    carries only `--help` and `--version`. The file is opened for append and
    created if absent; its parent directory is not created.
16. **Exit codes: 0 clean, 2 command-line usage, 1 everything else.**
    Draft B's buckets (the `crpgc` convention). *Rejected:* draft A's exit 2
    for configuration and load failures (mixes operator data errors with
    usage).
17. **`--headless-deterministic` is not T040's.** It needs a replay format
    of host inputs, which nothing defines (T154 leaves the capture recorder
    out, `tasks/T154.md:962`). Draft A. *Rejected:* draft B's mode (its
    replay file has no format and its test a twin no contract specifies).
18. **Gate 12 is one matrix job; it also runs the built binary.** Draft A's
    single matrix job with the shared scope step, plus draft B's check that
    the built artifact runs (`--version`) and a per-package Godot check on
    every leg. Gate 13 (smokes with a scripted client) stays T041's
    (`docs/IMPLEMENTATION_PLAN.md:246`).

## Interface
Additions only in the library; `main.rs` is replaced. Every public item has
a doc comment (`#![warn(missing_docs)]`). No `HashMap`/`HashSet`, no float.

### T040a — `crates/crpg-server/src/quic.rs`
```rust
/// One rejected client message, read from a pump report (Reading 5).
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Rejection {
    /// A hello refused with `code`.
    Hello { conn: ConnectionId, code: CloseCode },
    /// A resume opening refused with `code`.
    Resume { conn: ConnectionId, code: CloseCode },
    /// A lane-0 frame `ingest` refused (never `QueueFull`).
    Ingest { conn: ConnectionId, peer: PeerHandle, frame: u64, len: usize, code: RejectionCode },
    /// A transfer-channel frame `ingest_transfer` refused.
    Transfer { conn: ConnectionId, peer: PeerHandle, frame: u64, len: usize, refusal: TransferRefusal },
    /// A command the admission pump finalized as rejected.
    Admission { peer: PeerHandle, seq: Option<u64>, code: RejectionCode, cached: bool },
    /// A frame `check_frame` refused.
    Frame { conn: ConnectionId, peer: PeerHandle, error: HostError },
}

impl QuicPumpReport {
    /// Every rejection in this report, in the order of B-1.
    pub fn rejections(&self) -> Vec<Rejection>;
}

impl fmt::Display for Rejection { /* B-2 */ }
```
`RejectionCode` and `ReceiptStatus` are `crpg_net::protocol`'s; `CloseCode`
and `ConnectionId` are `crpg_net_quic`'s; field docs are one line each.

### T040a — `crates/crpg-server/src/run.rs`

### T040b — the command line
```
Usage: crpg-server --config <path>
       crpg-server --help | --version
```
Arguments are read with `std::env::args_os().skip(1)`, in this order of
precedence: any argument equal to `--help` → help; else any equal to
`--version` → version; else exactly `["--config", <path>]` → run. Help
prints the two usage lines above, each ending `\n`, to standard output;
version prints `crpg-server <CARGO_PKG_VERSION>\n` (today `crpg-server 0.1.0\n`).

## Behaviour
Normative. **First failure wins** in every ordered list. "Line" means one
`\n`-terminated UTF-8 line written through `Log` (standard error, and the log
file once open).

### T040a
B-1. **Order of `rejections()`.** First every `hellos` entry with
`HelloOutcome::Refused { code }` → `Hello`, in list order; then every
`resumes` entry with `ResumeOutcome::Refused { code }` → `Resume`; then
`calls` in order, each giving at most: `Ingest { result: Refused { status:
Rejected(code) } }` with `code != QueueFull` → `Ingest`;
`IngestTransfer { result: Refused(r) }` → `Transfer`; `CheckFrame { result:
Err(e) }` → `Frame`; `Pump { summary }` → for each `summary.results` entry in
order with `status == Rejected(code)` and `!retained_in_ingress` →
`Admission { peer, seq, code, cached }`. Every other entry gives nothing.
*Tests:* T1, T2, T3, T4.

B-2. **`Display`** (no trailing newline): `hello conn={c} code={n}`;
`resume conn={c} code={n}`; `ingest conn={c} peer={p} frame={f} len={l} code={k}`;
`transfer conn={c} peer={p} frame={f} len={l} refusal={r:?}`;
`admission peer={p} seq={s} code={k} cached={b}`;
`frame conn={c} peer={p} error={e}`. `{c}` is `ConnectionId::get`, `{p}`
`PeerHandle::get`, `{n}` `code as u32`, `{k}` `code as u8`, `{s}` the
sequence or `-` when `None`, `{b}` `true`/`false`, `{e}` `HostError`'s
`Display`. *Tests:* T2, T3.

B-3. **Observer.** After every intake whose `pump` returned `Ok(report)`, the
observer (if set) is called exactly once with the intake's `now_ms` and that
report, before the AI stage. A failed `pump` calls nothing. Clearing it
stops the calls. The observer changes no host or adapter state.
*Tests:* T5.

### T040b
B-10. **Command line.** As "Interface". Usage failures write exactly one line
`crpg-server: usage: {text}` to standard error (no log file is open yet),
nothing to standard output, and exit 2. `{text}`: no arguments →
`missing --config`; `--config` last → `--config needs a value`; any other
first unexpected argument `a` → `unknown argument {a}` (`a` as
`to_string_lossy`). *Tests:* S1, S2.

B-11. **Start-up**, in this order; a failure writes one line
`crpg-server: error {stage}: {detail}` and exits 1, and nothing after it runs:
1. `config`: read and parse the configuration file (`{detail}` is the I/O or
   `serde_json` error's `Display`); then each `area` value outside
   `-32768..=32767` → `area value out of range`.
2. `log`: open `log_file` (append, create); from here lines go to it too.
3. `certificate`: read `certificate` and `private_key` (I/O `Display`).
4. `invitations`: read and parse the file; an empty array →
   `no invitations`; more than `MAX_INVITATIONS` → `too many invitations`;
   entry `i` whose credential is not exactly 64 characters of `0-9a-f` →
   `entry {i}: credential is not 64 lowercase hex`.
5. `ai` (only when set): read and parse; `Sides::new` refusal → its `Display`
   (`crates/crpg-ai/src/sides.rs:28–36`).
6. `incarnation`: read `<save>.incarnation` if present (its content must be
   a decimal `u64` and optional trailing `\n`, else `unreadable sidecar`);
   `last = u64::MAX` → `exhausted`; write `{last + 1}\n` (absent: `1\n`)
   to it; a write failure → its `Display`.
7. `load`: `load_host_file(save, &identity, n, START_MS)`; `{detail}` is the
   `SaveError` `Display`.
8. `area` (only when set): `host.bind_area_bounds(min, max)`; `HostError`
   `Display`.
9. `unpause`: `host.unpause(START_MS)`; `HostError` `Display`.
10. `bind`: `QuicServer::bind_resumable(ServerConfig { bind: listen, identity,
    limits: ServerLimits::v1() })`; `BindError` `Display`.
11. `start`: `QuicHost::start_resumable(host, server, START_MS)`; the
    `StartFailure`'s error `Display`.
12. `register`: each invitation in file order with `register_invitation`;
    entry `i` refused → `entry {i}: {QuicHostError Display}`.

    (B-13).
14. `spawn`: `runner::spawn(HostLoop::new(hosting, START_MS),
    SystemClock::starting_at(START_MS))`; I/O `Display`.
15. Write `crpg-server: start listen={addr} incarnation={n} pin={hex}
    nav={bound|none} ai={on|off} invitations={count}`, with `pin` the

B-12. **Identity.** `identity` is `SaveIdentity { campaign_id,
campaign_version }` from the file. *Tests:* S4.

B-13. **Rejection lines.** The observer writes, for each element `r` of
`report.rejections()` in order, the line `crpg-server: reject t={now_ms} {r}`.
Nothing else is logged per cycle. *Tests:* S5.

B-14. **AI hook.** With `ai` set, the hook is
`|quic, _now| quic.drive_ai(&sides, &controlled, MVP_AI_BUDGET).map(|_| ())`.
Without it, no hook. *Tests:* S8 (start-up only; the driver's behaviour is
T153's suite).

B-15. **Console.** After the start line the main thread reads standard input
line by line, trimming ASCII whitespace. Before handling each line, if
`handle.is_finished()`, go to B-17. `quit` → B-16. An empty line is ignored.
Any other `t` → line `crpg-server: console: unknown command {t}`. *Tests:* S5.

B-16. **Quit.** `handle.join()`: `Err(RunnerPanicked)` → B-17's panic line;
`Ok(exit)` with `exit.error` `Some` → B-17's error line; else
`exit.host_loop.into_hosting().into_quic().shutdown(false)`, then
`save_host_file(save, &shutdown.host, &identity)`: `Ok` → line
`crpg-server: stop saved={save}` (`Path::display`), exit 0; `Err(e)` → line
`crpg-server: error save: {e}`, exit 1. *Tests:* S5.

B-17. **End of input and loop death.** At end of input the main thread
repeats `handle.call(|_| ())` until it returns `Err(RunnerGone)`, then joins.
A loop that ended by itself (B-15's check, or that wait) is joined:
`Ok(exit)` with `Some(e)` → line `crpg-server: error loop: {e}` (`LoopError`
`Display`), exit 1; `Err(RunnerPanicked)` → line
`crpg-server: error loop: panicked`, exit 1. No save is attempted after a
loop death. *Tests:* S6.

B-18. **No panic.** No input file content, argument or client message makes
the binary panic. *Tests:* S2–S9.
