# T058a — Pointer-addressed document edit and in-memory campaign index (`crpg-data`)

Status: **Contract draft — awaiting user approval (H-contract).** Nothing
here is approved until the user says so. T058 (`crpg-edit`) is blocked on
this task; T058a itself has no predecessor and needs no dependency approval
(§8).

## Task

Add two public primitives to `crpg-data` and nothing else:

1. `edit_document`: apply one RFC 6901 JSON Pointer edit (`Set`, `Insert`,
   `Remove`) to a typed `Document`, parsing the new value with the crate's
   strict JSON parser and re-decoding the result at its **current** schema
   version only. It is pure, never migrates and never retags.
2. `campaign_index`: run the writer's existing structural checks over an
   in-memory document map and return the index the loader would build for
   the same documents. It exposes the existing private `structural_check`;
   it is not a second implementation.

A third, small item, `pointer_tokens`, exposes the pointer decoder that
`edit_document` uses, so T058 never writes its own (§2.1, Q1).

## Crate(s)

`crpg-data` (only).

## Purpose

T058 §1 found that `crpg-data` has no public pointer edit (`canonical::parse`
and `decode_current` are `pub(crate)`) and no public index rebuild
(`structural_check` and `build_index` are `pub(crate)`; the only public index
builder is `load_campaign`, which needs bytes and a `semver::Version`). The
user decided on 2026-10-04 (T058 Decisions, answer 1) that this is a
separate `crpg-data` task, contracted, approved and merged before T058
starts, with T058 §9's signatures as its starting point. Without it,
`crpg-edit` would need `serde_json` and `semver` edges, a second JSON pointer
implementation and a re-serialize-then-load round trip per command.

## 2. Interface (exact public Rust)

### 2.1 New module `pointer_edit`

`crates/crpg-data/src/pointer_edit.rs` (new). `lib.rs` adds
`pub mod pointer_edit;` beside the sibling modules (lexical position, after
`package`) and `pub use pointer_edit::*;` beside the sibling glob
re-exports, so every item below is reachable as `crpg_data::<name>`.

```rust
/// Longest pointer `pointer_tokens` and `edit_document` accept, in bytes:
/// 8 KiB, which covers crpg-edit's 4 KiB caller pointer plus any index
/// pointer prefix (at most 55 bytes).
pub const MAX_EDIT_POINTER_BYTES: usize = 8_192;

/// One RFC 6901 edit of a document's JSON value. `value` is UTF-8 JSON text.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum PointerEdit {
    /// Replace an existing value, or add an absent member of an existing object.
    Set {
        /// RFC 6901 pointer to the target.
        pointer: String,
        /// UTF-8 JSON text of the new value.
        value: Vec<u8>,
    },
    /// Insert into the parent array at the final token: an index `0..=len`, or `-` to append.
    Insert {
        /// RFC 6901 pointer whose final token names the insertion point.
        pointer: String,
        /// UTF-8 JSON text of the inserted value.
        value: Vec<u8>,
    },
    /// Remove an existing object member or array element.
    Remove {
        /// RFC 6901 pointer to the target.
        pointer: String,
    },
}

/// Why a pointer edit was refused. The input document is never changed.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum PointerEditError {
    /// The pointer is longer than `MAX_EDIT_POINTER_BYTES`.
    PointerTooLong,
    /// Not RFC 6901 syntax, a bad `~` escape, or a malformed array index token.
    InvalidPointer,
    /// The empty pointer: whole-document replacement is not a pointer edit.
    RootPointer,
    /// The first reference token is `schema`.
    SchemaTag,
    /// The target, or for `Insert` the parent array or index, does not exist.
    NotFound,
    /// The value text fails the strict parser.
    Value {
        /// `Display` of the parser's `DataError`.
        message: String,
    },
    /// The edited value fails current-tag typed decoding, local invariants,
    /// or the canonical writer.
    Document {
        /// `Display` of the underlying `DataError`.
        message: String,
    },
}

impl std::fmt::Display for PointerEditError { /* §3.4 */ }
impl std::error::Error for PointerEditError {}

/// Decodes an RFC 6901 pointer into its reference tokens, unescaping `~1`
/// and `~0`. The empty pointer yields no tokens. Fails only with
/// `PointerTooLong` or `InvalidPointer`.
pub fn pointer_tokens(pointer: &str) -> Result<Vec<String>, PointerEditError>;

/// Applies one pointer edit to a copy of `document`. Pure; re-decodes at the
/// document's current schema tag only, so it never migrates or retags.
pub fn edit_document(document: &Document, edit: &PointerEdit)
    -> Result<Document, PointerEditError>;
```

### 2.3 Deviations from T058 §9, and why

1. **`PointerEditError::PointerTooLong` and `MAX_EDIT_POINTER_BYTES` added.**
   T058 caps the caller's pointer at 4 KiB *before* prefixing an object's
   index pointer, so the absolute pointer it passes here may be up to
   4,096 + 55 bytes. A `crpg-data` cap of exactly 4 KiB would refuse
   pointers T058 had accepted; 8 KiB leaves headroom with one simple bound
   (Q2).
2. **`pointer_tokens` added.** T058 §5.2 protects `campaign.json` members by
   the "first decoded reference token", while T058 §1 forbids pointer code in
   `crpg-edit`. Exposing the decoder that `edit_document` already needs gives
   T058 one implementation to call (Q1).
3. **`campaign_index` lives in `loader.rs`, not `pointer_edit.rs`.** It is
   the existing private `structural_check` returning the index it already
   builds (§4); moving it would split the loader's private helpers across two
   modules. Its root path `crpg_data::campaign_index` is the one T058 uses.
4. **`InvalidPointer` has two stages.** Syntax (`/` prefix, `~` escapes) is
   checked first, as §9 says. A malformed **array index** token (`01`, `+1`,
   empty) can only be recognised when the traversal reaches an array, because
   `01` is a valid object member name; that check runs in the traversal stage,
   after `Value` (§3.2).
5. **`-` outside `Insert`'s final token, and an index too large for `usize`,
   are `NotFound`, not `InvalidPointer`.** RFC 6901 §4 defines `-` as the
   (nonexistent) element after the last, and a syntactically valid index
   that overflows `usize` names an element no array can have. Both are
   well-formed references to nothing (Q3).
6. **The `Document` stage includes the canonical writer.** §9 named only
   `decode_current`. A value accepted by the strict parser can still be
   nested so deep, once placed, that `write_document`'s re-parse exceeds the
   128-level limit. Running `write_document` as the last step guarantees
   every `Ok` result is writable (§3.3).
7. **`Value` and `Document` messages are the underlying `DataError`'s
   `Display`.** That text can quote the offending token (serde's detail),
   exactly as `DataError::Malformed` already does for files. The fixed
   prefixes carry no caller bytes; §9's "no input bytes" holds for them only
   (Q4).

## 3. `edit_document` behaviour

### 3.1 RFC 6901 parsing (`pointer_tokens`, exact)

In order, first failure wins:

1. `pointer.len() > MAX_EDIT_POINTER_BYTES` (bytes, not characters) →
   `PointerTooLong`. Nothing else is examined.
2. `""` → `Ok(vec![])` (the root; `edit_document` refuses it in §3.2 step 2).
3. A non-empty pointer whose first byte is not `/` → `InvalidPointer`. This
   includes URI fragment form (`#/a`); only the JSON string representation is
   accepted.
4. Split the text after the leading `/` on every `/`. Each piece is one
   reference token, so `/` yields one empty token, `//` two, and `/a/` the
   tokens `a` and `""`. Empty tokens are legal (they name the member `""`).
5. Unescape each token in one left-to-right pass: `~0` → `~`, `~1` → `/`.
   A `~` followed by anything else, or at the end of a token, →
   `InvalidPointer`. One pass means `~01` decodes to `~1`, never `/`.
6. Any other character, including non-ASCII, is literal. The pointer is a
   Rust `&str`, so UTF-8 is already guaranteed.

The token count is bounded by the byte cap (at most 8,192 tokens); there is
no separate token cap (Q2).

**Array index tokens** (checked only when the container being indexed is an
array, §3.2): `0`, or an ASCII digit `1`–`9` followed by ASCII digits.

| Token on an array | Meaning |
|---|---|
| `0`, `7`, `42` | that index |
| digits matching the grammar but greater than `usize::MAX` | `NotFound` (cannot exist) |
| `-` | `Insert` final token: append; anywhere else: `NotFound` |
| `01`, `00`, `+1`, `-1`, ` 1`, `1 `, `1e2`, `0x1`, `""`, non-ASCII digits, any other text | `InvalidPointer` |

### 3.2 Algorithm and precedence (first failure wins)

`(pointer, value)` is taken from the variant; `Remove` has no value.

1. **Pointer limit and syntax.** `tokens = pointer_tokens(pointer)?`
   (`PointerTooLong`, then `InvalidPointer`).
2. **Root.** `tokens` empty → `RootPointer`.
3. **Schema tag.** `tokens[0] == "schema"` (after unescaping) → `SchemaTag`.
   Only the first token is checked: `/strings/schema` in a locale table is an
   ordinary member.
4. **Value.** `Set`/`Insert`: `canonical::parse(value)`; `Err(e)` →
   `Value { message: e.to_string() }`. This refuses invalid UTF-8, any
   non-integer number (`1.5`, `1e3`, `-0.0`), duplicate keys, trailing input,
   empty text and nesting beyond 128 levels.
5. **Current value.** `serde_json::to_value(document)`; `Err(e)` →
   `Document { message }` with the `Display` of `DataError::Malformed { path:
   None, message: e.to_string() }` (unreachable for current types; it exists
   so no path panics).
6. **Traversal.** Walk `tokens[..n-1]` from the root, left to right, on the
   owned value. At each token: an object → the member, absent → `NotFound`;
   an array → the index per §3.1 (`InvalidPointer` for a malformed token,
   `NotFound` for `-`, overflow or out of range); a string, number, bool or
   null → `NotFound`. No intermediate value is ever created.
7. **Final token** `t = tokens[n-1]` against the reached parent:

   | Edit | Parent object | Parent array | Parent scalar or null |
   |---|---|---|---|
   | `Set` | insert or replace member `t` | `t` an index `< len` → replace; else per §3.1 | `NotFound` |
   | `Insert` | `NotFound` | `-` → append; index `<= len` → insert before it; `> len` → `NotFound`; malformed → `InvalidPointer` | `NotFound` |
   | `Remove` | member `t` present → remove; absent → `NotFound` | index `< len` → remove (later elements shift down); else per §3.1 | `NotFound` |

8. **Typed decode.** `decode_current(edited)`; `Err(e)` →
   `Document { message: e.to_string() }`. This is strict serde decoding at
   the value's own tag plus `validate_local` (lock-local and combat-local
   invariants). It never calls `migrate_to_current`.
9. **Canonical writer.** `write_document(&decoded)`; `Err(e)` →
   `Document { message: e.to_string() }`. The bytes are discarded.
10. `Ok(decoded)`.

Member order inside the edited `Value` is never observable: step 8 decodes
into typed fields and every byte form comes from the canonical writer, which
sorts keys whether or not `serde_json`'s `preserve_order` is
feature-unified.

### 3.3 Guarantees

For every `document` and `edit`:

- **Pure.** `document` is borrowed and never changed, on success or error.
  No I/O, clock, environment read, randomness, thread or float. The same
  inputs give the same result on every call.
- **No panic** on any input: index arithmetic is checked, nothing on a
  caller-controlled path is `unwrap`ped.
- **Current tag only.** On `Ok(r)`, `r` is the same `Document` variant as
  `document` (the `/schema` member cannot be edited and step 8 decodes at the
  tag present), so `r` carries the current tag of its family. Historical
  tags can never be produced or consumed here.
- **Canonical.** On `Ok(r)`: `write_document(&r)` is `Ok`, and
  `read_document(&write_document(&r)?)? == r`.
- **Loader-equivalent normalisation.** `r` is what the typed round trip
  makes of the edited value, the same normalisation `read_document` +
  `write_document` already applies to files. For example `Set /_note null`
  yields a document without `_note`, and a semver range is re-printed in
  `semver`'s spelling. The literal edited value is not preserved (Q5).
- **Not identity-aware.** `edit_document` does not police ULIDs: `Set /id`
  succeeds if the new value decodes. Identity and protection rules are
  T058's (T058 §5.2 and §5.3 step 7), using `campaign_index`.
- **Cost.** One `to_value`, one strict parse of `value`, one traversal of at
  most 8,192 tokens, one typed decode and one canonical write: linear in
  document size + value size + pointer length. `edit_document` puts no cap on
  value size or document size; callers cap (T058: 1 MiB value, 4 MiB
  document), consistent with the loader's deferred S001 input caps (Q6).

### 3.4 `Display` (exact)

Lowercase, no trailing punctuation, matching `DataError`.

| Variant | Display |
|---|---|
| `PointerTooLong` | `json pointer exceeds 8192 bytes` |
| `InvalidPointer` | `invalid json pointer` |
| `RootPointer` | `json pointer must not be empty` |
| `SchemaTag` | `the schema tag cannot be edited` |
| `NotFound` | `json pointer target not found` |
| `Value` | `invalid value: {message}` |
| `Document` | `edited document is invalid: {message}` |

## 4. `campaign_index` behaviour

Refactor inside `loader.rs`, and nothing more:

```rust
pub(crate) fn structural_check(
    documents: &BTreeMap<SourcePath, Document>,
) -> Result<BTreeMap<Ulid, IndexEntry>, DataError> {
    check_paths(documents.keys())?;
    check_layout(documents)?;
    for document in documents.values() {
        crate::document::validate_local(document)?;
    }
    let index = build_index(documents)?;
    check_locks(documents)?;
    Ok(index)
}

pub fn campaign_index(
    documents: &BTreeMap<SourcePath, Document>,
) -> Result<BTreeMap<Ulid, IndexEntry>, DataError> {
    structural_check(documents)
}
```

- The check order is unchanged, so `serialize_campaign` and `explain_object`
  (which keep calling `structural_check(..)?;` and ignore the returned index)
  have identical behaviour, errors and precedence. Their source and their
  tests do not change.
- `campaign_index` is therefore **exactly** the writer's acceptance:
  `campaign_index(&d)` is `Err(e)` if and only if
  `serialize_campaign(&LoadedCampaign { documents: d, index })` is `Err` with
  an error of the same variant and `Display`, for any `index`.
- On success it returns `build_index(documents)`, the function
  `load_campaign` calls on its decoded documents. So for every file map `F`
  and engine `v` with `load_campaign(&F, &v) == Ok(c)`:
  `campaign_index(&c.documents) == Ok(c.index)`. This holds for migrated
  campaigns too, since `c.documents` are already current.
- **Precedence versus the loader.** The writer and loader orders differ in
  one documented way (crpg-data AGENTS: the loader runs local invariants
  inside its read phase, before layout; the writer runs them after layout).
  `campaign_index` follows the writer, as T058 §9 asked. On a map with both a
  layout fault and a local-invariant fault, it reports the layout fault.
- **No engine check, no migration, no semantics.** `campaign_index` never
  sees an engine version, never calls `migrate_to_current` and never runs
  `validate`. A dangling reference, missing locale key or unreachable node
  never makes it fail (T058 Decisions, answer 5: only structural failures
  block).
- **Deterministic.** `BTreeMap`/`BTreeSet` only, lexical path order,
  authored order inside documents, as today.

`load_campaign` is not refactored: its phase order (engine between layout and
index, reads with migration first) is part of its contract.

## 6. Test

## 10. Open questions for the user

1. **`pointer_tokens` as public API.** T058 §5.2 needs the first decoded
   token, and T058 §1 forbids pointer code in `crpg-edit`.
   *Recommendation:* approve the public decoder. The alternative, comparing
   the raw first segment in `crpg-edit`, works for `package`, `engine` and
   `requires` (no escapable characters) but is a second, partial RFC 6901
   reading.
2. **Pointer bound.** *Recommendation:* 8,192 bytes, no separate token cap.
   A 128-token cap (the strict parser's depth) would also be sound but adds
   a second limit with no extra protection: traversal stops at the first
   missing token and token count is already at most the byte count.
3. **`-` and overflowing indices are `NotFound`.** *Recommendation:* approve;
   it is RFC 6901 §4's meaning. Malformed index spellings (`01`, `+1`) stay
   `InvalidPointer`.
4. **Messages may quote input.** `Value`/`Document` carry the `DataError`
   text, which can include the rejected token, and is not length-capped.
   *Recommendation:* keep parity with `DataError::Malformed`, which file
   loads already print; callers that log untrusted input (T059) truncate.
   The alternative is a 256-byte cap on `message` here.
5. **Normalising edits.** The result is the typed round trip, so
   `Set /_note null` drops `_note` and semver text is re-printed.
   *Recommendation:* accept; it is exactly what `crpgc fmt` and the
   load-then-write path already do. The alternative, refusing any edit whose
   canonical bytes differ from the literal edited value, would make
   `Set /_note null` an error with no safety gain.
6. **No value or document cap in `crpg-data`.** *Recommendation:* approve;
   T058 caps value (1 MiB) and document (4 MiB) size, and loader-wide caps
   are the deferred S001 item.
7. **`Insert` into an object is `NotFound`.** `Set` already adds absent
   members. *Recommendation:* keep the closed seven-variant error set rather
   than adding a `NotAnArray` variant.
8. **Writer precedence, not loader precedence.** On maps with several faults
   the two differ (local invariants before or after layout).
   *Recommendation:* approve the writer's, as T058 §9 specified; it is the
   precedence `serialize_campaign` and `explain_object` already share, and
   `load_campaign` stays unchanged.
