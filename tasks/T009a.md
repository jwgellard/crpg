## Task
Give `crpg-testkit` the smallest truthful replay abstraction: a versioned
`.replay` format with opaque input payloads, record/parse/validate/playback
through public `World` APIs only, typed errors, an exact-tick structured
divergence report reusing the T008b golden machinery, and a checked-in
canonical-Linux replay + hash golden that makes CI step 9 live.

## Crate(s)
`crpg-testkit` (only).

## Purpose
T008b proved one scripted world hashes deterministically and gave every later
task the same write/compare harness; nothing can yet *record* behaviour as an
artifact. Headless combat (T016), the `crpgc replay` CLI (T009b), and every
regression golden after them all need the same replay semantics — seed plus
ordered inputs in, hash sequence out, exact-tick divergence on mismatch — and
copy-pasting those into every consumer is how replay dialects fork. This task
builds the semantics once, behind an API that keeps game-specific input
vocabulary out of testkit entirely. The determinism scope it operates under
is ADR-0009; the mismatch shape it reuses is ADR-0010; its one-way dependency
direction is E005; its gate sequencing is E020.

## Interface

```rust
// crates/crpg-testkit/src/replay.rs
use std::path::Path;
use crpg_sim::World;

/// Replay format version this crate reads and writes. Files carrying any
/// other version fail with `ReplayError::UnsupportedVersion`, never with a
/// parse error or a silent reinterpretation.
pub const REPLAY_FORMAT_VERSION: u32 = 1;

/// Validation bounds. Absurd files are rejected before allocation or
/// playback; these are CI-practicality caps, not performance claims, and a
/// later task changes them only with a stated reason.
pub const MAX_REPLAY_TICKS: u64 = 1_000_000;
pub const MAX_REPLAY_INPUTS: usize = 1_000_000;

/// One scheduled input: applied before the tick it names, in file order
/// among same-tick inputs. The payload is opaque to testkit — see Behaviour.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct ReplayInput {
    pub tick: u64,
    pub payload: serde_json::Value,
}

/// A recorded run: deterministic seed, campaign/engine identity, tick count,
/// and the ordered input list.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct Replay {
    pub format_version: u32,
    pub seed: u64,
    pub campaign_id: String,
    pub campaign_version: String,
    pub engine_version: String,
    pub total_ticks: u64,
    pub inputs: Vec<ReplayInput>,
}

impl Replay {
    /// Builds a replay, running the full validation below. The only way to
    /// construct a `Replay` that has not been validated is to deserialize
    /// one — and every entry point that consumes one (`play_replay`,
    /// `play_and_verify`) validates before playback.
    pub fn new(
        format_version: u32,
        seed: u64,
        campaign_id: String,
        campaign_version: String,
        engine_version: String,
        total_ticks: u64,
        inputs: Vec<ReplayInput>,
    ) -> Result<Self, ReplayError>;
}

/// Caller-supplied payload application: testkit owns ordering and hashing,
/// the caller owns what a payload *means*. Runs through public `World` APIs
/// only — an input needing a private seam proves the sim API is missing
/// something (file it, do not reach around). `Err(reason)` aborts playback
/// with `ReplayError::ApplyFailed` at that tick and index.
pub type ApplyInput =
    Box<dyn FnMut(&mut World, &serde_json::Value) -> Result<(), String>>;

/// Validates without playing. Check order is fixed so one malformed replay
/// always reports one error: version, then metadata, then counts, then the
/// per-input schedule scan in file order (first failing index wins).
pub fn validate_replay(replay: &Replay) -> Result<(), ReplayError>;

/// Plays `replay` to a hash sequence: `World::new(seed)`, then per tick —
/// every input scheduled for that tick in file order, then `tick`, then
/// `state_hash`. Same replay in, same sequence out (exact-build scope,
/// ADR-0009).
pub fn play_replay(
    replay: &Replay,
    apply: ApplyInput,
) -> Result<Vec<[u8; 32]>, ReplayError>;

/// Writes `replay` as pretty JSON plus a trailing newline. Creates parent
/// directories. Byte-stable: writing the same replay twice, or reading and
/// re-writing it, yields identical bytes.
pub fn write_replay(path: &Path, replay: &Replay) -> Result<(), ReplayError>;

/// Reads and validates a `.replay` file. A missing file is
/// `ReplayError::Io` with kind `NotFound`; unreadable-UTF-8 or bad JSON is
/// `Malformed`; semantic violations are their typed variants below.
pub fn read_replay(path: &Path) -> Result<Replay, ReplayError>;

/// First-diverging-tick report from `play_and_verify`. Replay identity plus
/// the truthful `Mismatch` — never a fabricated world-state diff (a
/// hash-only golden has no expected state to diff against; see Behaviour).
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ReplayDivergence {
    pub campaign_id: String,
    pub campaign_version: String,
    pub engine_version: String,
    pub seed: u64,
    pub mismatch: Mismatch,
}

impl ReplayDivergence {
    /// First divergent tick, when the variant has one (`None` for
    /// `Mismatch::InvalidUtf8`).
    pub fn tick(&self) -> Option<usize>;
}

/// End-to-end gate: reads and validates the replay, plays it, and compares
/// the sequence against the golden with the T008b `verify_golden` semantics.
/// `Ok(sequence)` on full match; `Err(ReplayError::Divergence(..))` naming
/// the exact tick on content divergence; `Err(ReplayError::Io(..))` when
/// either file is missing or unreadable — missing baseline and wrong
/// baseline stay distinguishable without string matching.
pub fn play_and_verify(
    replay_path: &Path,
    golden_path: &Path,
    apply: ApplyInput,
) -> Result<Vec<[u8; 32]>, ReplayError>;

/// Every failure mode, distinguishable without string matching. `Display`
/// is single-pathed per variant.
#[derive(Debug)]
pub enum ReplayError {
    /// Either file could not be read or written (includes `NotFound`).
    Io(std::io::Error),
    /// Not JSON, not UTF-8, or missing/malformed required metadata
    /// (empty campaign/engine identity counts as malformed). Carries detail.
    Malformed(String),
    /// `format_version` is not `REPLAY_FORMAT_VERSION`. Carries the found
    /// version.
    UnsupportedVersion { found: u32 },
    /// `inputs[i].tick < inputs[i-1].tick`. Carries the index, the tick,
    /// and the previous tick. Equal same-tick entries are valid.
    UnorderedSchedule { index: usize, tick: u64, prev_tick: u64 },
    /// `inputs[i].tick >= total_ticks`. Carries the index, the tick, and
    /// the declared count.
    OutOfRange { index: usize, tick: u64, total_ticks: u64 },
    /// `total_ticks` or `inputs.len()` exceeds its `MAX_` bound, or a JSON
    /// number overflows its target integer (the serde failure surfaces as
    /// `Malformed`; this variant is for in-range-but-impossible counts).
    /// Carries what and the offending value.
    TooLarge { what: &'static str, value: u64 },
    /// The caller's apply function failed. Carries the tick, the input
    /// index, and the caller's reason verbatim.
    ApplyFailed { tick: u64, index: usize, reason: String },
    /// Playback succeeded; the golden comparison diverged. Boxed: the
    /// identity strings would otherwise push this error over clippy's
    /// `result_large_err` threshold.
    Divergence(Box<ReplayDivergence>),
}
```

`lib.rs` declares `pub mod replay;` and re-exports the surface above
alongside the existing harness re-exports.

## Behaviour

- **Payloads are opaque; ordering is not.** Testkit never interprets a
  payload — it is a `serde_json::Value` the caller's `ApplyInput` maps onto
  public `World` operations (`spawn`, stores, `timeline_mut`, `rng_mut`).
  No combat, networking, or campaign command enum enters this crate: concrete
  player intents do not exist yet, and a speculative vocabulary is how
  game churn reaches the harness. The checked-in fixture and every test own
  their own miniature vocabularies locally.
- **The interleaving is the T008b interleaving, with inputs in place of the
  script step.** Per tick `t` in `0..total_ticks`: apply every input with
  `tick == t` in file order, call `tick`, call `state_hash`, record. A
  replay hash at index *n* therefore means exactly what a harness hash at
  index *n* means — the world after the *n*-th input step and tick — so
  replay sequences and harness sequences stay comparable. Consumers do not
  reorder it.
- **Replay file schema (JSON, `.replay`, pretty-printed, trailing newline):**

  ```json
  {
    "format_version": 1,
    "seed": 12345,
    "campaign_id": "testkit-basic",
    "campaign_version": "0.1.0",
    "engine_version": "0.1.0",
    "total_ticks": 8,
    "inputs": [{ "tick": 0, "payload": { "spawn_at": [1, 0, 0] } }]
  }
  ```

  Field order is declaration order; unknown fields are ignored on read so a
  future-version file still fails cleanly on its version rather than on its
  first unknown key. `serde_json`'s map ordering (sorted or insertion-order
  depending on the resolver-unified feature set) is byte-stable along the
  read→write path either way, which the round-trip test pins rather than
  assumes.
- **Metadata.** `format_version` must equal `REPLAY_FORMAT_VERSION`.
  `campaign_id`, `campaign_version`, and `engine_version` must be present
  (absent ⇒ serde error ⇒ `Malformed`) and non-empty (empty ⇒ `Malformed`).
  Identity is recorded, never enforced: playback does not compare the
  engine version against the running build — an old replay must still parse
  and play, and version-equality would turn every release into a replay
  migration. `seed` is the `World::new` seed. `total_ticks` is the exact
  tick count played, including trailing ticks after the final input.
- **Validation invariants** (checked by `validate_replay`, hence by `new`,
  `read_replay`, `play_replay`, and `play_and_verify`):
  1. `format_version` supported, else `UnsupportedVersion`.
  2. Metadata present and non-empty, else `Malformed`.
  3. `total_ticks <= MAX_REPLAY_TICKS` and
     `inputs.len() <= MAX_REPLAY_INPUTS`, else `TooLarge`.
  4. Schedule scan in file order: `inputs[i].tick >= inputs[i-1].tick`,
     else `UnorderedSchedule`; every `tick < total_ticks`, else
     `OutOfRange`. Multiple inputs at one tick are valid and keep file
     order. No-input ticks — gaps and trailing ticks alike — are played as
     plain `tick` + `state_hash`.
- **The structured divergence report is truthful about available
  information.** A hash-only golden carries no expected world state, so
  there is no expected-vs-actual state diff to print and this task does not
  fabricate one. `ReplayDivergence` carries the replay identity (campaign
  id/version, engine version, seed), and the exact `Mismatch` (tick plus
  only-present sides per ADR-0010). `Display` renders
  `replay '{id}' v{version} (engine {engine}, seed {seed}): {mismatch}`.
- **Golden reuse, not golden reinvention.** Hash goldens stay in the T008b
  line-hex format with `#` scope headers, written and compared by
  `write_golden`/`verify_golden`. `play_and_verify` maps
  `HarnessError::Mismatch(m)` to `ReplayError::Divergence(..)` (attaching
  replay identity) and `HarnessError::Io(e)` to `ReplayError::Io(e)`.
  No competing hash-comparison semantics enter this crate.
- **Canonical-Linux golden, compile-time gating.** The checked-in pair is
  `crates/crpg-testkit/fixtures/replay_basic.replay` (the portable,
  reviewable input) and
  `crates/crpg-testkit/goldens/replay_basic_rust-1.98.0_linux-x86_64_debug.golden`
  (the approved hash sequence). The filename encodes the full ADR-0009
  scope: toolchain 1.98.0, Linux, x86_64, debug/test profile. The comparison
  test compiles to a real comparison only under
  `cfg(all(target_os = "linux", target_arch = "x86_64", debug_assertions))`;
  on any other platform the same test name compiles to a parse-and-play
  shape check that never touches the golden — so Windows stays green
  without selecting or blessing an alternate golden at runtime, and tolerant
  comparison stays rejected. The toolchain half of the scope is enforced by
  the pinned `rust-toolchain.toml` plus the filename, not by code (a library
  cannot know its toolchain at runtime); a toolchain bump re-blesses the
  golden as a reviewed event per ADR-0009. There is no rebless command:
  golden replacement is a reviewed file replacement.
- **No clock, no threads, no randomness of its own.** File I/O is confined
  to `read_replay`/`write_replay` and the golden functions it reuses;
  everything else is pure. (`state_hash` panics on non-finite `f32` state by
  sim design — an apply function that installs NaN/infinity gets that panic,
  not a `ReplayError`. Document it; do not catch it.)

## Test
New `crates/crpg-testkit/tests/replay.rs` (portable: runs on Windows and
Linux) plus the canonical comparison in
`crates/crpg-testkit/tests/replay_golden.rs` (compile-time gated, see
Behaviour). All tests self-contained and deterministic; no proptest. The
tests own their payload vocabularies locally (e.g. `{"spawn_at": [x,y,z]}`,
`{"timeline": {"slot": n, "key": k}}`, `{"draw": name}`,
`{"despawn": {"slot": n}}` mapped onto public `World` APIs) — those shapes
are test fixtures, not crate vocabulary.

1. **Serialization round-trip with stable output.** Build a replay with
   several inputs (including two at one tick), `write_replay` twice ⇒
   byte-identical files; `read_replay` then `write_replay` ⇒ identical
   bytes; the round-tripped value equals the original.
2. **Playback determinism.** Same replay twice ⇒ identical complete hash
   sequences.
3. **Inputs run before `tick`.** `play_replay` equals a manual
   `World::new` + input-before-`tick` loop, and differs from an
   input-after-`tick` loop (mirrors the T008b order-pinning test).
4. **Same-tick file order preserved.** Two inputs at one tick with distinct
   payloads: playback equals the manual loop applying them in file order,
   and differs from the loop applying them swapped.
5. **No-input ticks replayed.** A replay with gaps and trailing ticks after
   the final input equals the manual loop over all `total_ticks`; a
   zero-input replay over N ticks equals `run_hash_sequence` with a no-op
   script over N ticks (the T008b compatibility proof).
6. **Divergence on different input or seed.** One altered payload, and
   separately one altered seed, each produce a sequence differing from the
   original (and the payload case names the first affected tick).
7. **Golden mismatch names the exact tick.** Temp golden from a played
   sequence; flip one hash char ⇒ `Divergence` whose `tick()` is that index
   with expected/actual sides intact (via the reused `Mismatch::Diverged`).
8. **Malformed and unsupported files ⇒ typed errors.** Non-JSON bytes,
   missing required metadata, empty `campaign_id`, and
   `format_version: 999` each produce their distinct variant
   (`Malformed` / `UnsupportedVersion`) — asserted by matching the variant,
   never by matching strings.
9. **Bad schedules rejected.** An input at `tick == total_ticks` ⇒
   `OutOfRange` with index/tick/count; a decreasing tick pair ⇒
   `UnorderedSchedule` with index/tick/prev; `total_ticks` above
   `MAX_REPLAY_TICKS` and an over-long input list ⇒ `TooLarge`; a JSON
   number overflowing `u64` ⇒ `Malformed`.
10. **Missing files distinguishable from divergence.** `play_and_verify`
    with a missing replay ⇒ `Io(NotFound)`; with a missing golden ⇒
    `Io` with kind `NotFound` (not `Divergence`); with a tampered golden
    ⇒ `Divergence`. Non-UTF-8 golden ⇒ `Divergence` carrying
    `Mismatch::InvalidUtf8` (content divergence, per ADR-0010).
11. **Checked-in canonical-Linux replay and golden compare.** Gated test
    (see Behaviour): on canonical Linux, `play_and_verify` over the
    checked-in pair ⇒ `Ok` with the golden length equal to `total_ticks`.
    Elsewhere the same test name parses the replay, plays it, and asserts
    only shape (length, determinism) — green without a golden.
12. **Altered in-memory input ⇒ useful failure.** Clone the checked-in
    replay (or the test replay), alter one payload in memory, run against a
    temp golden written from the unaltered sequence ⇒ `Divergence` naming
    the exact first affected tick, with a `Display` containing the replay
    identity and that tick. No production source is modified during the
    test.

The checked-in replay is small enough to review (single-digit ticks and
inputs) while exercising more than one tick, more than one input, a
same-tick pair, a gap tick, and trailing ticks. No new 10,000-tick test:
the T008b 10k round trip already proves scale.

Command that must pass: `cargo test -p crpg-testkit --locked`
