## Task
ADR-0029 Follow-on 9 (`docs/adr/0029-kernel-range-and-time-model.md:488`):
the `crpg.ui/1` document that a ruleset may ship (U1, `:353`), its loading and
positioned validation (U6, `:385`), and the pure functions that generate the
default UI when a ruleset ships none or omits a screen (U5, `:378`). The
document is presentation data. It is never loaded into a `World`, never hashed,
and the server ignores it (`:353–355`). U9 (odds, `:397`) is T143: T142 carries
only the boolean `show_odds` field that T143's preview will read.

## Decision
- **D1. A new `Document::Ui(UiDocument)` variant, tag `crpg.ui/1`, with no `id`,
  `slug` or `name`.** The document names its ruleset in a required `ruleset`
  field, the way a locale table names its campaign
  (`crates/crpg-data/src/document.rs:365–379`). It joins the 20 families at version 1 with no edge
  (`crates/crpg-data/src/migrations/mod.rs:77–98`), so the registry grows to 21 and the generated
  schemas to 23 (`crates/crpg-data/src/schema.rs:90`). *Rejected:* (a) a separate `read_ui` API
  outside `Document`: `crpgc validate`, `crpg-edit`, `campaign_index` and
  pointer edits would not see it, and U6 says it must fail *campaign
  validation*. (b) An identified object with a new `ObjectKind`: it has nothing
  that other objects reference, and every `ObjectKind` match would grow.
- **D2. Shipping (U1).** A ruleset package ships `rulesets/<package>/ui.json`,
  copied byte-identically into a campaign as `ui/<name>.json`, the way
  `rulesets/minimal-d6/ruleset.json` becomes
  `campaigns/fixtures/combat_basic/rulesets/minimal-d6.json`. A new layout family
  `ui/` is added to `check_layout` (`crates/crpg-data/src/loader.rs:112–157`) and to
  `campaign_document_path` (`crates/crpg-data/src/validation.rs:261–287`) from the same predicate.
  *Rejected:* (a) a field inside `Ruleset`: the sim adapter reads that family, and
  it would need a `/3` tag with a migration edge (`crates/crpg-data/src/migrations/mod.rs:94`). (b) The existing `rulesets/`
  family: `check_layout` decides by kind (`crates/crpg-data/src/loader.rs:130`), so a UI file under
  it would be indistinguishable by path.
- **D3. Every binding uses the authored identity its source already has:**
  stat by `name` (`crates/crpg-data/src/combat.rs:82`), pool by template ULID (`crates/crpg-data/src/combat.rs:220`),
  ability by ULID (`crates/crpg-data/src/combat.rs:392`), effect by ULID (`crates/crpg-data/src/combat.rs:339`), outcome
  by a label string, tag and group by string. *Rejected:* slugs. They are
  "renameable" (`crates/crpg-data/src/combat.rs:341`), so a rename would silently break a UI file.
- **D4. Every top-level array is optional-missing**
  (`#[serde(default, skip_serializing_if = "Option::is_none")]`), and absent
  means "use the generated default for this part" (U5). `Some([])` is also
  accepted and read back as written. The minimal valid document is
  `{"schema":"crpg.ui/1","ruleset":"<ULID>"}`. This is the usability choice:
  an author writes only what differs. It stays inside the family rule
  (`crates/crpg-data/AGENTS.md:41–45`), which is about existing documents.
  *Rejected:* required arrays, which force an author to write six empty lists.
- **D5. The four U6 error classes never fail `load_campaign`.** Unresolved ids
  and missing keys are already semantic (`validate`, `crates/crpg-data/src/validation.rs:884`). Unknown
  *kinds* would be `Malformed` at read time, which fails the whole load
  (`crates/crpg-data/src/loader.rs:258–265`) and so the server. Therefore each closed set in the
  document has a read-only `Unknown(String)` form (screen kind, section type,
  format type, pool style, target hint, sort). It decodes, round-trips byte-
  identically and is reported by `validate` as `unknown_kind`. The JSON Schema
  stays closed (known values only). *Rejected:* strict enums, which make an
  unknown kind a load failure (breaks U6); see open question 1.
- **D6. Wire shapes copy the existing conventions.** Section, format and
  selector enums are adjacent `{"type":…,"value":…}`, snake_case, with unit
  variants written `{"type":"timeline"}` (`crates/crpg-data/src/combat.rs:488–501`, `crates/crpg-data/src/combat.rs:187–199`).
  Their `Deserialize` is hand-written with exact key sets per variant
  (`crates/crpg-data/AGENTS.md:68–73`, pattern at `crates/crpg-data/src/combat.rs:442–456`), now
  with the extra Unknown arm. `Serialize` is hand-written for the same enums so
  Unknown writes back what it read; `JsonSchema` is hand-written over the known
  variants. Plain structs derive all three and use `deny_unknown_fields`.
- **D7. Selectors are enums, so "exactly one of" cannot be violated.**
  `ability_list` takes `ids` *or* `tag` (U4, `:374`), and `stat_group` takes a
  `group` key *or* explicit `stats`. *Rejected:* two optional fields plus a
  rule, which needs another error code.
- **D8. Labels are locale keys in authored documents (U2, `:357`).** Coverage
  uses the existing rule: the key must exist in every loaded locale table, and
  with no table at all every key is missing (`crates/crpg-data/src/validation.rs:1294–1326`).
  *Generated* defaults carry the raw slug or name as their label text ("slug
  labels", U5), are never passed to `validate`, and the client falls back to the
  text when the key resolves nowhere (hand-off to T051/T072).
- **D9. Icons use the existing asset rule:** the string must be a key of
  `assets.lock` (`crates/crpg-data/src/package.rs:92–98`), reported as `missing_asset` exactly as
  `Area.ambience` is (`crates/crpg-data/src/validation.rs:1030–1047`). T101 is an authoring-UX ADR,
  not a pipeline (`docs/IMPLEMENTATION_PLAN.md:291`); whether a key is the right
  asset *type* is not checkable here (open question 8).
- **D10. Reserved kinds are in the closed sets and rejected by validation (U8,
  `:393`).** `level_up`, `character_creation` and `choice_steps` parse, then
  validate as `reserved_kind`. *Rejected:* leaving them out of the sets, which
  would make a later version's files "unknown" instead of "reserved".
- **D11. Defaults are two pure functions and one input struct** (U5): 
  `generated_ui(&UiSource) -> UiDocument` and
  `effective_ui(Option<&UiDocument>, &UiSource) -> UiDocument`. The input is
  plain borrowed data, so the editor, an agent, the host and the client-side
  exporter all call the same code with no campaign plumbing.
  *Rejected:* taking `&LoadedCampaign` (a client has no campaign).
- **D12. Only three screens have a generated default:** `character_sheet`,
  `action_bar`, `combat_hud`. U5 lists exactly those contents (`:378–383`);
  `spellbook` and `inventory` have no stated default and `level_up` and
  `character_creation` are omitted by U8 (open question 4).
- **D13. No sim, rules, hash or dependency effect.** No new dependency, float,
  `HashMap`, clock or OS code; collections are `BTreeMap`/`Vec`
  (`crates/crpg-data/AGENTS.md:106–115`).

## Behaviour
Read-time rules are `DataError::Malformed` (`crates/crpg-data/src/error.rs:26`, through
`validate_local`); the rest are `validate` diagnostics. Pointers are RFC 6901
(`crates/crpg-data/src/inventory.rs:80`), index-based, relative to the file.

**Reading and writing**
1. **B1 (U1).** `read_document` accepts `crpg.ui/1`; `write_document` of the
   result is byte-identical to canonical input. Absent arrays stay absent and
   `[]` stays `[]`.
2. **B2.** Unknown fields, a missing `ruleset`, a wrong `schema` version and
   non-integer numbers are `Malformed` / `UnsupportedSchema`, as for every
   family (`decode_current`, `crates/crpg-data/src/document.rs:472–476`).
3. **B3.** Read-time checks (`Malformed`, texts under Errors): every string is
   1..=128 UTF-8 bytes (`.len()`, never chars); every array and list has at most
   4096 entries; no list in a selector, `labels`, `tags` or `pool_group`/
   `effect_list` is empty; a screen has at most 64 sections; the document has at
   most 64 screens.
4. **B4 (U6, D5).** An unknown screen kind, section type, format type, pool
   style, target hint or sort **does not fail `read_document` or
   `load_campaign`**. It decodes to `Unknown`, is preserved with its `value`, and
   re-encodes byte-identically. A *known* kind with a wrong body (missing or
   extra key) is `Malformed`.
5. **B5 (D2).** Layout: `Document::Ui` is accepted only under `ui/*.json`; a
   `crpg.ui/1` file elsewhere, or another kind under `ui/`, is `Layout`
   (`crates/crpg-data/src/loader.rs:149–154`). `campaign_document_path("ui/x.json")` is `Some`, and
   `campaign_document_path("ui/x/y.json")` is `Some` too (the shared `family`
   predicate, `crates/crpg-data/src/loader.rs:93–96`, does not forbid a slash) — behaviour copied, not
   invented.
6. **B6 (no effect on loading).** A campaign with a `ui/` file loads with the
   same `LoadedCampaign.index`, the same lock digest and the same
   `serialize_campaign` bytes for every other file as without it. A UI file is
   not in `object_occurrences`.

**Validation** (`validate`; `walk_ui` runs only for a document whose `ruleset`
resolves to a ruleset; otherwise only the generic reference diagnostic is
emitted, never a dependent one, as `crates/crpg-data/AGENTS.md:77–78` requires)

7. **B7 (U6).** `ruleset` not an object → `dangling_reference`; a non-ruleset
   object → `wrong_reference_kind` (generic, `crates/crpg-data/src/validation.rs:458–510`).
8. **B8 (U6).** Two `crpg.ui/1` files with the same `ruleset` → the later (path
   order) gets `duplicate_binding` at `/ruleset`, naming the first file.
9. **B9 (U2).** `stats[i].stat` and every `UiMeter::Stat`/`StatSelect::Stats`
   name must be a declared stat of the ruleset (`crates/crpg-data/src/combat.rs:383`) → else
   `unknown_stat`. `UiMeter::Pool`, `pools[i].pool` and `pool_group` ids must be
   a template of `ruleset.pools` (`crates/crpg-data/src/combat.rs:389`) → else `unknown_pool`.
10. **B10 (U2).** `abilities[i].ability` and `AbilitySelect::Ids` must be in
    `ruleset.abilities` (`crates/crpg-data/src/combat.rs:392`): not an ability → generic
    `wrong_reference_kind`/`dangling_reference`; an ability the ruleset does not
    list → `foreign_reference`.
11. **B11 (U2).** `effects[i].effect` and `effect_list` ids must be an effect
    that some *listed* ability of the ruleset names (`Ability.effect`,
    `crates/crpg-data/src/combat.rs:548`) → else `foreign_reference` (or the generic kinds). (Open
    question 3.)
12. **B12 (U2/U3).** `outcomes[i].outcome` must be a label that occurs in a
    band, a natural-face override, or a damage entry of a table or ability the
    ruleset lists (`crates/crpg-data/src/combat.rs:537–538`, `crates/crpg-data/src/combat.rs:576–597`) → else `unknown_outcome`.
    A malformed label (`custom:`, `custom:256`, `custom:01`, `Success`) is
    `unknown_outcome` too. Omitting an outcome is fine (default label).
13. **B13 (U2).** `AbilitySelect::Tag(t)` must be a tag in some
    `abilities[*].tags` of the same document → else `unknown_tag`. (Ability tags
    live only in the UI document: `Ability` has no tag field,
    `crates/crpg-data/src/combat.rs:517–567`.) `StatSelect::Group(g)` must equal the `group` of at
    least one `stats[*]` → else `unknown_group`. `ItemList.tag` is **not**
    resolved (open question 5).
14. **B14 (U3).** `format` must suit the stat's declared kind
    (`crates/crpg-data/src/combat.rs:54–75`), else `format_mismatch`: `integer` and `signed` need
    `Int` or `Fixed`; `percent` needs `Int` or `Fixed`; `fraction` needs `Int`
    or `Fixed` and its meter must be a numeric stat or a pool; `boolean` needs
    `Bool`; `enum` needs `Enum`, with each `variant` declared by that stat
    (else `unknown_variant`); `tags` needs `Tags`; `dice` needs `Dice`.
15. **B15 (U6).** Duplicates → `duplicate_binding` at the later entry:
    the same stat, pool, ability, effect or outcome twice in its array; the same
    `kind` twice in `screens`; the same id twice in one selector or list; and
    the same explicit id in two sections of one screen (tag/group selectors
    overlap by design and are not compared).
16. **B16 (U2, D8).** Each `label`, `short_label`, `description`, `group`, and
    each `UiEnumLabel.label` is a locale key checked with the shared rule
    (`crates/crpg-data/src/validation.rs:1294–1326`), code `missing_locale_key`, pointer at the field.
17. **B17 (U2, D9).** Each `icon` must be a key in `assets.lock` →
    else `missing_asset` (`crates/crpg-data/src/validation.rs:1030–1047`).
18. **B18 (U6).** Each `Unknown` form → `unknown_kind` at the kind-bearing
    member (`/screens/1/kind`, `/screens/0/sections/2/type`,
    `/stats/3/format/type`, `/pools/0/style`, `/abilities/1/target_hint`,
    `/screens/0/sections/1/value/sort`). Nothing under an unknown section is
    judged further.
19. **B19 (U8, D10).** `level_up`, `character_creation` and `choice_steps` →
    `reserved_kind`, same pointers; the section body of a reserved kind is not
    judged further.
20. **B20.** Screen / section compatibility is not enforced (a `timeline` on an
    `inventory` screen is valid): the client draws each kind with its own widget
    (`:376`). Only `choice_steps` is restricted (B19).
21. **B21.** Output order follows the existing sort (file, pointer, code,
    severity, message, fix; `crates/crpg-data/src/validation.rs:1328–1347`); at most one diagnostic
    per reference; the result is independent of file-map insertion order.
22. **B22 (U6).** Every B7–B19 finding is `Severity::Error`, and none can occur
    from `load_campaign`: a campaign whose only defects are B7–B19 loads
    (`Ok`), then `validate` is non-empty, and `validate_files` returns the same.

**Defaults** (`generated_ui`, `effective_ui`; deterministic, no I/O)

23. **B23 (U5).** `generated_ui(src)` returns a document whose `ruleset` is
    `src.ruleset.id` and in which: `stats` has one entry per `ruleset.stats` in
    declared order (`label` = the stat name, no format); `pools` one per
    template in declared order (`label` = `pool-<n>`, `n` 1-based position;
    style `bar`, `hud` true); `abilities` one per `src.abilities` (`label` = the
    ability `slug`, `target_hint` per B26, `show_odds` false); `effects` one per
    `src.effects` (`label` = the effect `slug`, `show_duration` true);
    `outcomes` the labels of B12 in first-occurrence order (`label` = the label
    text itself). Every `Option` not named is `None`.
24. **B24 (U5).** `screens` is exactly `character_sheet`, `action_bar`,
    `combat_hud`, in the U4 list order (`:371–372`):
    `character_sheet` = one `stat_group(stats: all stat names in declared
    order)`; `action_bar` = one `ability_list(ids = src.abilities in order,
    sort declared)`; `combat_hud` = `stat_group(stats: [health_stat])`,
    `pool_group(all pool ids in order)`, `timeline`. If a ruleset has no
    abilities the `action_bar` is omitted (an empty list is not valid, B3);
    likewise a ruleset with no pools omits `pool_group`.
25. **B25 (U8).** `generated_ui` never emits `level_up`, `character_creation`
    or `choice_steps`, `spellbook`, `inventory`, `log`, `effect_list` or
    `item_list`.
26. **B26.** Default `target_hint` per ability: `requires_target == false` →
    `none`; else `allow_self_target == true` → `any`; else `enemy`
    (`crates/crpg-data/src/combat.rs:555–557`).
27. **B27 (U5).** `effective_ui(authored, src)` per array: authored entries
    first, in authored order and unchanged; then default entries (B23) for ids
    the authored array does not cover, in declared order. Entries for ids the
    ruleset does not know are kept as authored (validation reports them, the
    function does not judge). Screens: authored screens as authored, then the
    B24 screens whose kind is absent. `Unknown` and reserved screens are kept.
    `effective_ui(None, src) == generated_ui(src)`. The `note` is dropped.
28. **B28.** Both functions are pure and total: the same input gives equal
    output; `generated_ui` output passes B1 (canonical round trip) and passes
    every `validate` check **except** `missing_locale_key` (D8) when placed in a
    campaign. `effective_ui` of a valid authored document is valid.
29. **B29 (U7).** The document and the defaults contain no expression, script,
    coordinate or widget name and no stat *value*: no known field holds
    a number (`custom:<n>` is inside a string; `Unknown` forms may hold any
    integer-only JSON and are reported by B18). (Guards U2 and U7: values come
    only from replicated facts.) Tested by walking the JSON Schema.
30. **B30 (U10).** A future version is a new tag (`crpg.ui/2`) with a registered
    edge; `crpg.ui/1` alone cannot gain a screen or section kind. A test pins
    the known kind lists, so adding a variant forces a reviewed edit.

## Errors
No new `DataError` variant; read-time failures use the existing ones
(`crates/crpg-data/src/error.rs:9–93`). `Malformed` display is `malformed document at {path}: {message}`
(`crates/crpg-data/src/error.rs:101–108`); the loader fills `path`. Exact `message` texts:
- `ui text at {pointer} must be 1..=128 UTF-8 bytes`
- `ui array at {pointer} exceeds 4096 entries`
- `ui list at {pointer} must not be empty`
- `ui screen at {pointer} exceeds 64 sections`
- `ui document exceeds 64 screens`
- known kind, wrong body: serde's own text (`unknown field`, `missing field`),
  as `exact_body_keys` produces (`crates/crpg-data/src/document.rs:511–531`).

`DiagnosticCode` gains eight variants appended after
`RealTimeFieldsWithoutRoundTicks` (`crates/crpg-data/src/validation.rs:101–102`), each with its
`as_str` arm (`crates/crpg-data/src/validation.rs:105–143`), all `Severity::Error`:

| Variant | `as_str` | message | suggested fix |
|---|---|---|---|
| `UnknownKind` | `unknown_kind` | `unknown {what} {value:?}` | `use a kind this schema version defines` |
| `ReservedKind` | `reserved_kind` | `{what} {value:?} is reserved until its data family exists` | `remove it; the generated default omits reserved kinds` |
| `DuplicateBinding` | `duplicate_binding` | `duplicate {what} {value} (first at {pointer})` | `keep one entry` |
| `UnknownOutcome` | `unknown_outcome` | `outcome {value:?} is not produced by ruleset {ruleset}` | `use critical_success, success, failure, critical_failure or custom:<0..=255> as the ruleset's tables produce` |
| `UnknownTag` | `unknown_tag` | `ability tag {value:?} is not declared by any ability entry` | `add the tag to an abilities entry or fix the filter` |
| `UnknownGroup` | `unknown_group` | `stat group {value:?} is not the group of any stat entry` | `set the group on a stats entry or fix the selector` |
| `UnknownVariant` | `unknown_variant` | `variant {value:?} is not declared by enum stat {stat:?}` | `use a variant of the stat's enum` |
| `FormatMismatch` | `format_mismatch` | `format {format} does not suit {kind} stat {stat:?}` | `choose a format that suits the stat's kind` |

`what` is one of `screen kind`, `section type`, `format`, `pool style`,
`target hint`, `sort`, `stat`, `pool`, `ability`, `effect`, `outcome`, `screen`,
`ruleset`. Reused unchanged: `unknown_stat` (`unknown stat {name:?} for ui: not
declared by ruleset {ruleset}`), `unknown_pool` (`unknown pool {id} for ui: not a
template of ruleset {ruleset}`), `foreign_reference`, `dangling_reference`,
`wrong_reference_kind`, `missing_locale_key`, `missing_asset`.
`diagnostic_for_data_error` (`crates/crpg-data/src/validation.rs:208–236`) needs no change.

## Open questions (each with a recommendation)
1. **How is U6 kept ("never server loading")?** *Recommend* (a) the `Unknown`
   read form of D5 (cost: hand-written `Serialize`/`JsonSchema` for six enums,
   a reader wider than its schema). (b) Strict enums: an unknown kind is
   `Malformed` and fails `load_campaign`, which contradicts U6 as written.
   (c) UI files outside `Document` with their own API: U6 holds, but `crpgc
   validate` and `crpg-edit` need new calls (other crates).
2. **Fixed-point stats have no format.** The closed set (U3, `:363–366`) has no
   decimal format, yet `StatKindWire::Fixed` exists (`crates/crpg-data/src/combat.rs:61`). *Recommend:*
   allow `integer`, `signed`, `percent` and `fraction` on `Fixed` (B14) and ask
   the user whether a `fixed` format is wanted in `crpg.ui/2`.
3. **"Effect resolves in the same ruleset" (U2).** Effects are separate files
   no ruleset lists. *Recommend:* reachable through a listed ability (B11).
   Alternative: any `Effect` object in the campaign.
4. **`spellbook`/`inventory` defaults.** *Recommend* none (D12); alternative
   `spellbook` = the action bar's list, which duplicates it.
5. **`item_list` tag resolution.** *Recommend:* unresolved (a ruleset's UI
   cannot know a campaign's items). Alternative: warn when no item carries it.
6. **Default pool label.** Templates have no name (`crates/crpg-data/src/combat.rs:216–226`).
   *Recommend* `pool-<n>`; alternative: the ULID text.
7. **`$id`.** The brief asks for one; the repository's 22 schemas have none.
   *Recommend:* none (convention). Alternative: `https://crpg.invalid/schemas/ui.schema.json`.
8. **Icon type.** Only `assets.lock` membership is checkable (D9). *Recommend:*
   accept; type checks wait for the asset-import flow.
9. **Where ability category tags live.** `Ability` has none; they are authored
   in the UI document (B13). *Recommend:* keep, to avoid a ruleset schema bump.
10. **`target_hint` and `sort` value sets** are my choice (ADR lists none).
    *Recommend:* as drafted; the architect may widen them before approval.
11. **`outcome` string versus typed.** *Recommend* string (so a bad label is a
    positioned `unknown_outcome`, not a load failure).
