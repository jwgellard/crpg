1. **Production content, never hand-built encounters.** The adapter loads
   repo-root `campaigns/fixtures/combat_basic/` through `load_campaign`
   (engine `0.1.0`) from `CARGO_MANIFEST_DIR`-relative test-harness I/O —
   the same `read_tree` discipline as `combat_content.rs` (recurse, skip
   `.gitattributes`, forward-slash logical paths). Filesystem collection stays
   in `tests/`, above the OS-neutral data/sim layers, with no OS-specific
   branches. The 14-file map, the 11-id index, empty `validate`, and
   byte-parity of the three combat documents with `rulesets/minimal-d6/` are
   asserted by test. No parallel hand-built encounter exists anywhere in this
   task.
2. **Borrowed spec built transiently.** `EncounterSpec<'a>` borrows data
   documents, so the adapter owns `LoadedCampaign` and assembles the
   `BTreeMap<Ulid, &Ability>` / `&OutcomeTable` / `PlacementAndArea` /
   `&Creature` reference maps on the stack per initialization — never a
   self-referential struct. Resolution walks owned documents: the encounter
   named by the init payload → its ruleset → the ruleset's listed abilities
   → each ability's outcome table; each participant placement → the owning
   `PlacementsDocument.area` → the placement's prefab creature. Authored
   placement/ability ULIDs in later payloads resolve against the bound
   encounter, never against hard-coded arena indices, and runtime `EntityId`s
   are never accepted as authored identity.
3. **Generic replay untouched.** `Replay`, validation, `play_replay`,
   `play_and_verify`, and the input → tick → hash interleaving are reused
   unchanged. The envelope's `campaign_id` (`combat-basic`) is recorded
   identity, never a filesystem path. There is no second playback loop.
4. **Observation without behavior change.** All gameplay goes through the two
   public sim operations. Trace and terminal facts are collected by the
   `ApplyInput` closure with shared `&World` reads plus read-only
   `serde_json::to_vec(&world)` snapshots (see §Observation). The closure
   never drains events, never touches RNG/turn state, and never feeds
   observations back into sim calls. Expected traces are oracles compared
   after playback, never instructions.
5. **Goldens are independent native baselines.** One artifact, two
   target-scoped goldens (§Goldens), each generated on its genuine native
   target through the production replay and golden writer paths, reviewed
   before acceptance, verified read-only afterwards. No copying, no invented
   provenance, no cross-platform equality, no runtime-OS selection, no
   auto-bless/rebless mode, no change to existing goldens.

## Production loading → borrowed spec

`CombatContent::load()` (tests-only) performs, in order: read the 14-file
`combat_basic` tree (assert count 14); `load_campaign(&files, &engine
0.1.0)`; assert `validate(&loaded)` is empty; assert the index holds exactly
ULIDs 11–21 with the T016a kinds/paths/pointers; assert the three campaign
combat documents equal the `rulesets/minimal-d6/` canonical parses. Any
failure is a `String` error naming the step. The init operation then takes an
encounter ULID, checks it names a `Document::Encounter` in the loaded
campaign, and builds the transient reference maps described in Decision 2.
`start_encounter` failures (`MissingPlacement`, `MixedArea`,
`MissingCreature`, …) propagate as adapter reasons — the adapter does not
re-validate data-owned invariants, and sim does not re-run `validate`.

## Payload grammar and error precedence

Every combat payload is a JSON object with `"combat": 1` (payload version)
and `"op": "init" | "attack"`. Replay actions identify actor, ability, and
target only — never rolls, damage, health assignments, or a winner.

```text
init   := {"combat": 1, "op": "init", "encounter": "<ULID>"}
attack := {"combat": 1, "op": "attack", "actor": "<placement ULID>",
           "ability": "<ability ULID>", "target": "<placement ULID>"}
```

Artifacts write canonical Crockford base32 ULIDs. Decoding uses
`Ulid::from_str`, including its existing lowercase and alias acceptance;
actor/target name authored *placements*, ability names the authored ability.
Unknown JSON fields inside a combat payload are rejected as malformed (strict
decode — a misspelled key must fail loudly, not silently default).

Adapter check order per payload (first failure wins; sim errors keep sim
precedence after step 5):

1. Payload is an object, else `malformed combat payload: expected object`.
   Then require `combat.as_u64() == Some(1)`, else
   `unsupported combat payload version` (missing/non-integer/wrong).
2. `"op"` is `"init"`/`"attack"`, else `unknown combat op`.
3. Reject unknown keys first, choosing the lexically smallest extra key:
   `malformed combat {op}: unknown field {field}`. Then check required ULID
   fields in order: `encounter` for init; `actor`, `ability`, `target` for
   attack. Missing/non-string values produce
   `malformed combat {op}: {field} must be a ULID string`; parse errors produce
   `malformed combat {op}: invalid {field}`. Do not include parser debug text.
4. State: `init` after initialization → `duplicate combat init`; `attack`
   before initialization → `combat not initialized` (sim's `NoEncounter`
   backstops with identical meaning; the adapter flag gives the deterministic
   reason without a sim call).
5. Identity: `init` encounter ULID unknown → `unknown encounter {id}`;
    `attack` actor/target placement not bound at init →
    `unknown combat identity {role}: {id}` (actor checked before target).
    Diagnostic IDs use core's canonical Display spelling.
6. Sim call. `start_encounter` / `perform_action` errors map to
   `init failed: {CombatError}` / `attack failed: {CombatError}` using the
   stable `Display` spellings. In particular `UnknownAbility` fires for any
   well-formed ability ULID that is not the encounter ability, and
   `OutOfTurn`/`DeadTarget`/… preserve T016b precedence.

Every adapter failure returns `Err(reason)` from the closure, which
`play_replay` reports as `ReplayError::ApplyFailed { tick, index, reason }`
with truthful tick/input index. Envelope-level problems (bad `format_version`,
unordered/out-of-range schedule) keep their existing typed `ReplayError`
variants — the adapter never masks them.

## Initialization timing and identity binding

Initialization is tick-0 input index 0 of the artifact, applied to the same
`World::new(seed)` the harness hashes: per-tick file-order inputs, then
`tick`, then `state_hash`. There is no warm-up tick, no second world, and no
unrecorded step. Attacks are scheduled at ticks `1..=K`; ticks `K+1..=K+T`
carry no inputs (trailing ticks, `T >= 4`).

After a successful `start_encounter`, the adapter binds authored →
runtime identity by walking `world.combatants()` in iteration order against
`encounter.participants` in authored order (insertion order is the
placement-to-entity mapping per the T016b contract), asserting each bound
`Combatant.placement()` equals the expected participant placement, and
cross-checks the encounter ability against
`world.combat().definition.ability`. Binding failures (order/identity
mismatch) abort the init input loudly rather than guessing. Later attack
payloads resolve placements through this map; the map is lookup-only and
never drives gameplay.

## Adapter ownership and lifetime model

Use this tests-only ownership shape (helper names are binding; private field
organization may vary):

```text
CombatContent { files, loaded: LoadedCampaign }       // owns documents
CombatAdapter { content: CombatContent,               // owns
                entities: BTreeMap<Ulid, EntityId>,   // placement → runtime
                initialized: bool }
Observations { trace: Vec<TraceEntry>,
               snapshots: Vec<Vec<u8>>,
               last_world: Option<World> }           // detached clone
CombatAdapter::apply(&mut self, &mut World, &Value)
    -> Result<Option<TraceEntry>, String>
combat_apply(content: CombatContent)
    -> (ApplyInput, Rc<RefCell<Observations>>)
```

`combat_apply` creates an adapter and observation handle, and returns a
`move` closure owning the adapter and a clone of the handle. This satisfies
the existing `ApplyInput` alias's implicit `'static` lifetime; do not change
the alias or borrow a stack-local adapter into it. Release every RefCell
borrow before returning from the callback; no threads or locks are needed.
Direct-drive rejection tests use `CombatAdapter::apply`, so decoding and
binding are not duplicated. That method executes only the public sim operation
and returns the optional trace; the wrapper observes successful calls.

`EncounterSpec` maps are built transiently inside the init branch and dropped
before it returns — no self-referential state, no borrowed state escaping the
call. After a successful input, capture snapshot bytes and replace last_world
with a detached clone. The trace and snapshots never choose an action or feed
values back into sim. Review for absence of a second dice, outcome, damage,
resource, death, or turn implementation; expected arithmetic in independent
test assertions is allowed and is not an engine implementation.

`TraceEntry` (per accepted attack, recorded post-call from `ActionOutcome`
plus public getters): tick, actor/target placement ULIDs, ability ULID, raw
die faces `Vec<u32>`, roll total, margin, outcome (`crpg_rules::Outcome`),
damage, `target_died`, target health and actor pool balance after. Snapshots
(`serde_json::to_vec(&world)`) are taken after every accepted attack.

## Observation strategy (terminal state, traces, death events)

- **Action traces.** Asserted from the closure's `trace` log against a pinned
  oracle table (actor/target/ability, faces, total, margin, outcome, damage,
  post health/pool). Faces are reviewed against the authored might values
  under inclusive roll-under (`total <= might` succeeds; margin `=
  total - might`; bands `[{MIN: success}, {1: failure}]`); damage against the
  authored `{success: 2, failure: 0}` table. Both hit and miss cases are
  required in the schedule.
- **Terminal state.** Asserted from the *final* callback snapshot (post-last-action,
  pre-tick): `combat.active` null, exactly one combatant with `health == 0`
  and `dead == true`, the other with positive health and `dead == false`,
  `round >= 1`. Soundness chain (documented in code): T016b's
  `no_input_ticks_invent_nothing` proves no-input ticks change only the tick
  counter, so post-action combat state equals terminal combat state; the
   golden sequence additionally pins every trailing hash. Do not describe this
   snapshot as an observation made after the final replay tick.
   To verify the terminal suffix directly, take the detached last_world and
   call public `tick` exactly `T + 1` times (the lethal input's own tick plus
   the `T` trailing ticks). After each step, compare `state_hash` with returned
   replay indices `K..=K+T`, and assert the full serialized state differs from
   the terminal snapshot only in its tick field. This is a focused no-input
   continuation assertion, not an alternative replay executor: it applies no
   inputs and generates no golden. Gameplay playback remains `play_replay`.
- **Death events.** On a separate detached clone, drain `events_mut()` and
   assert exactly two `Spawned` envelopes followed by one `Died { entity }`
   naming the dead combatant, with sequences 0/1/2, spawn tick 0, death tick K,
   and next_seq 3 in the pre-drain serialization. Repeat after the terminal
   suffix on another clone; no new event is permitted. If inspecting JSON,
   the queue is `events.envelopes` plus `events.next_seq`, not an array at
   `events`. Never drain the actual replay World.
- **Non-interference.** Reads and serialization are pure: no `rng_mut`,
   `events_mut`, timeline, or store mutation on the authoritative World from
   the observer. Mutating detached clones for assertions is permitted. Rejected
   actions are covered separately (rejection tests): adapter-level and sim-level
  rejections leave serialized world bytes identical and create no combat RNG
   stream on the fresh-world path. World has only `rng_mut`, not a shared RNG
   getter: inspect serialized RNG state or call `has_stream("combat.roll")`
   on a detached clone via `rng_mut`. Never obtain mutable authoritative RNG
   access from the observer.

## The authored replay

`crates/crpg-testkit/fixtures/combat_basic.replay` (pretty JSON, LF, trailing
newline, via `write_replay` byte discipline):

- Envelope: `format_version` 1, fixed seed `S` (selected during
  implementation — see below), `campaign_id` `combat-basic`,
  `campaign_version` `0.1.0`, `engine_version` `0.1.0`,
  `total_ticks = K + 1 + T` with `T >= 4` trailing ticks.
- Inputs: index 0 at tick 0 is the `init` for encounter `N` (21); ticks
   `1..=K` each carry one `attack` alternating placement `F→E` (goblin acts
   first by initiative 9) and `E→F` (hero retaliates) with ability `K` (19), stopping
  at the lethal action. No adaptive rewriting: the schedule is fixed
  authored-order attacks; the terminating winner is whatever the fixed seed
  produces, recorded — not chosen — in the completion record.
- Seed selection criteria (probed during implementation with a temporary
  test, then pinned): the fixed schedule must contain at least one failed and
  at least one successful attack, progress past round 0, and terminate with
  exactly one dead combatant within a bounded `K` (target `K <= 12`). The
   pinned per-action oracle (§Observation) is reviewed for rules-correctness
   before golden acceptance. Probe seeds in ascending order starting at 0,
   stopping at the first satisfying seed within 0..=1023; if none meets the
   criteria, stop and report rather than change the content. Use the public
   combat API for the probe. Pin seed, K, T = 4, and all trace rows in this
   file before creating goldens. Constants S/K/T are authoring placeholders,
   not runtime seed search, adaptive playback, or self-generated expectations
   in the committed suite. The trace must be independently checked against
   kernel fixed RNG behavior and authored thresholds/damage, not accepted
   merely because it was printed by perform_action.
