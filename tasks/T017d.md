# T017d — Multi-ability/pool/defense/effect/turn controller (`crpg-sim`)

## Status and purpose

**Specified; implementation and verification pending. No source changes
claimed.** Third executable child of [T017](T017.md) (work package B3).
Generalizes the T016b/e/f single-ability/single-pool controller to the B1
shapes through the production data path with no package-name branches:
per-ability definitions addressed by ULID, plural pools with per-pool
costs, target-stat/actor-attribute defense selection, explicit natural-die
selection, lifetime-bearing effects with effect-scoped policies, and
explicit turn completion. Minimal-d6 behavior stays byte-identical (same
RNG draws in the same order, same hashes); existing `combat_basic`
artifacts, goldens, and suites are read-only regression constraints.

This file is the implementation contract; the public-API record is
[ADR-0016](../docs/adr/0016-sim-multi-ability-pools-effects-turns.md)
(Proposed, not accepted). Implementation begins only after ADR-0016 is
accepted. No commit, push, or PR without separate instruction.

## Decisions (binding for this contract; reviewable via ADR-0016)

1. **B2 stays vacuous.** The scenario maps onto existing T014/T015 APIs
   (see T017 kernel mapping); no `crpg-rules` change is authorized. If
   implementation finds a missing primitive, stop into a finding instead
   of hiding rules knowledge in sim.
2. **Hash preservation via absence-skip evolution.** Minimal-d6 combat
   worlds serialize byte-identically to T016-era bytes: new persistence
   fields are skipped when legacy-equivalent (single pool, single ability,
   no attached effects, no extra definitions). New shapes appear in bytes
   only when non-legacy content/behavior occurs. Existing goldens are
   never re-baselined; cross-target hash comparison is never performed
   (ADR-0012 exact-build scope).
3. **No new sim collection bounds.** Abilities/pools/effects/attached
   lists are bounded by data's own bounds where they exist (effect
   modifiers ≤4096 enforced by the kernel at query); sim adds no new
   `MAX_*`. Execution looks up abilities by scan over ascending-ULID
   vectors (counts are small; no hash-order anywhere).
4. **Caller-owned lifetime, sim-owned attached state.** Attached effects
   live in authoritative `Combatant` state as `(effect ULID,
   expires_round)` pairs; modifiers rebuild from the hashed definition on
   every query (never persisted handles). Re-applying one effect refreshes
   its expiry (`R + duration_rounds`); at most one attached entry per
   effect per combatant (this also keeps rebuilt modifier IDs unique
   within each side's fold).
5. **Neutrality holds.** No minimal-d6/srd-lite identifier, name, die
   count, threshold, damage, margin, pool, or policy value in production;
   the neutral-scan test extends to every new/changed file.

## Interface (exact public shapes; ADR-0016 owns the record)

All public items have rustdoc. Existing names keep their meanings unless
re-specified. `CombatAction` gains `EndTurn`; `perform_action` returns
`Result<Option<ActionOutcome>>` (`Some` for attacks, `None` for `EndTurn`;
existing tests unwrap mechanically). `EncounterSpec` gains `effects:
&BTreeMap<Ulid, &AuthoredEffect>`. `InsufficientAction` gains `pool: Ulid`
(`Display` unchanged). New error variants (all with pinned `Display` and
precedence; see Behavior): `MissingEffect { effect }`, `MissingPool {
pool }`, `InvalidEffect { effect }`, `DuplicateModifier { id }`,
`InvalidNaturalDie { index }`, `PolicyConflict { mod_type }`.

```rust
pub struct AbilityDefinition {
    pub ability: Ulid,
    pub dice: DiceExpr,
    pub attribute: String,
    pub defense: AbilityDefense,
    pub outcome_table: OutcomeTable,
    pub damage: Vec<(Outcome, u32)>,
    pub costs: Vec<(ResourcePoolId, u32)>, // template order; primary first
    pub ends_turn: bool,
    pub effect: Option<Ulid>,
    pub natural_die: Option<u32>,
    pub requires_target: bool,
    pub allow_self_target: bool,
}

pub enum AbilityDefense { ActorAttribute, TargetStat { stat: String } }

pub struct EffectDefinition {
    pub effect: Ulid,
    pub aim: EffectAim, // Slf | Target
    pub mod_type: String,
    pub policy: StackingPolicy,
    pub modifiers: Vec<EffectModifier>, // id/target(Roll/Dc)/op(Add/Set of Int)/value/priority/name
    pub duration_rounds: u32,
}

pub struct CombatDefinition {
    // ... encounter/ruleset/health_stat/attribute_names as today ...
    pub abilities: Vec<AbilityDefinition>, // ascending ability ULID
    pub pools: Vec<PoolTemplate>,          // authored template order
    pub effects: Vec<EffectDefinition>,    // ascending effect ULID
    // ... legacy single-ability/pool fields retained populated from the
    // first-listed entry for hash-compat (absence-skip covers the rest) ...
}

pub struct Combatant {
    // ... placement/initiative/attributes/health/max_health/dead ...
    pub action_pool: ResourcePool,          // primary pool (unchanged name/bytes)
    pub extra_pools: Vec<ResourcePool>,    // non-primary, template order; skipped when empty
    pub attached: Vec<AttachedEffect>,     // skipped when empty
}

pub struct AttachedEffect { pub effect: Ulid, pub expires_round: u32 }

pub enum CombatAction {
    UseAbility { actor: EntityId, ability: Ulid, target: EntityId },
    EndTurn { actor: EntityId },
}
```

Serde: new persisted fields use absence-skip (`skip_serializing_if`
empty/`None`) so legacy-equivalent worlds round-trip byte-identically;
`AttachedEffect` and new definition vectors derive `Serialize`/`Deserialize`
with load-time coherence checks (world.rs string messages, T016e-style).
`EffectDefinition`/`AbilityDefinition` internals map data wire explicitly
(`PolicyWire`→`StackingPolicy`, `EffectTargetWire`→`Roll`/`Dc`,
`EffectOpWire`→`Add(Int)`/`Set(Int)`); never depend on data enums as
runtime types beyond the existing authored-document borrows.

`Document`-level data shapes are consumed read-only; this task adds no
data dependency beyond T016b's approved edges.

## Behavior

- **Adapter (`start_encounter`, all-or-nothing, pinned order):**
  existing encounter/collection/participant/stat checks; pool templates
  carried in order; complete per-ability validation over all listed
  abilities in authored order (attribute ∈ attributes else `MissingStat`;
  dice parse else `InvalidDice`; table build else `InvalidOutcomeTable`;
  costs drawn from declared pools else `MissingPool`, each amount within
  its template max else `InvalidCost`; `TargetStat` names a declared
  non-health stat else `MissingStat` at the new defense site... (exact
  locations in ADR-0016); effect refs resolve into `spec.effects` else
  `MissingEffect`; sane durations/nonempty/mod-type coverage else
  `InvalidEffect`; cross-effect modifier-ID uniqueness else
  `DuplicateModifier`; shared mod-type policy agreement else
  `PolicyConflict`; `natural_die` bound against the parsed dice count else
  `InvalidNaturalDie`); missing spec-map abilities → `UnknownAbility`
  (replacing the current `expect`); then publication (entities in authored
  order, every pool at max, timeline at initiatives, `round = 0`, active =
  head, roll tag interned, incoming-actor `TurnStart` refresh). The
  ADR-0015 `UnsupportedAuthored` gate is removed field-by-field as each
  shape gains execution here (per-field retirement; the variant retires
  only when no restriction remains, per B3's API decision in ADR-0016).
- **Resolution (per action):** build one real pipeline per action — actor
  Roll modifiers from unexpired attached effects (`round < expires`),
  target Dc modifiers likewise (same `COMBAT_ROLL_TAG`, empty base blocks
  as today extended with the two modifier sets); target guard via a
  transient `StatBlock` for `TargetStat` defenses; `Against::Stat{entity:
  target, stat, modifier_target}` vs `Against::Dc` for `ActorAttribute`;
  `natural_die` selects the raw face (dropped dice included) or no rule
  when `None`; margin `i64(actor) - i64(against)`; table decision;
  per-outcome damage (unmapped → 0). Malformed/rejected actions spend
  neither resources nor randomness (pre-draw validation; staged-clone
  transactional RNG as in T015).
- **Costs:** check every pool before spending any; first insufficient pool
  in template order reports `InsufficientAction { pool, cost, current }`.
  Accepted-but-failed attacks spend their costs.
- **Turns:** `ends_turn: false` success skips the advance (active stays, no
  refresh, no RNG/event beyond resolution+spend+effect). `EndTurn{actor}`
  validates turn-holding (`NoEncounter`, participant/absence/death/
  `OutOfTurn` in existing order; no ability/target/cost checks) and
  advances with no spend, no draw, no damage, no effect (RNG streams
  identical pre/post; no events).
- **Effects:** on success with `effect: Some`, attach `(effect, round +
  duration_rounds)` refreshing any existing entry for that effect.
  Round rollover additionally drops attached with `expires_round <=
  new_round` (silent: state and hash show it; no event). A save in round 1
  reloads with the identical breakdown; post-expiry breakdowns are empty.
- **Load coherence (world.rs, string messages):** per-pool
  identity/maximum/refresh agreement by index; costs drawn from declared
  pools; effect references resolving with sane durations; attached pairs
  resolving with future expiries (`expires_round > round`); multi-ability
  coherence (every definition ability/pool/effect referenced consistently;
  combatant balances/attributes/health/dead/placement as before;
  active/timeline as before). Invalid saves fail before publishing.
- **Neutrality + determinism:** same seed/content/inputs repeat every
  hash; mutating faces/ward/damage/pools/effect numbers changes behavior
  through content; no package-name branches (neutral scan extended).
