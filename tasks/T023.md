## Interface

Exact patched source/version/features, runtime/TLS approval, local endpoint API,
channel-to-stream/datagram mapping, frame-length prefix, message boundaries,
receive/send caps, connection close/error taxonomy and host integration surface.
Existing v1 Transport and codec remain frozen; new socket/async APIs need their
own ADR and a scoped amendment to net's present no-I/O rule.

## Behaviour to preserve in the later executable contract

Lane 0 combat stays reliable ordered, with application epoch/lane/seq dedup;
QUIC packet dedup is not command idempotency. Movement's highest-seq-wins may
apply only to its separately versioned lane. Snapshot/datagram loss/reorder
semantics must reflect the accepted ADR-0004 resolution, never assumed-free
delivery. Bounded per-peer/host ingress and egress, failure budgets, explicit
backpressure and authenticated host binding remain required. Transport does
not implement gameplay legality or trust in client-supplied identities.

## Constraints

[Standing rules](POST-T018-RULES.md) apply. Net only; host adapter is T023b.
No quinn/runtime/TLS dependencies are approved here. No fork/source allowlist,
deny widening, unsafe exception, NAT scope or wire cap change is granted.

### 1. Decisions made by this contract

| Topic | Decision |
|---|---|
| Surface | One new public module `crpg_net::quic`. It is the only place in `crpg-net` that may do I/O or use threads, tokio, quinn, rustls or `std::time` (§2, §14) |
| Lane-0 mapping | One client-initiated **bidirectional** QUIC stream per connection carries the hello, the welcome and then every lane-0 frame in both directions. There are no other streams and no DATAGRAM frames |
| Framing | 4-byte big-endian `u32` length prefix, then the payload. Caps are checked before any allocation: client→server 4,096 (`MAX_INTENT_FRAME_BYTES`), server→client 65,536 (`MAX_DELTA_FRAME_BYTES`), hello 130, welcome exactly 17. Zero length is a violation |
| Payloads | Net never decodes intent or delta bytes on this path. It is a byte pipe, like the T018b fabric. The host decodes |
| Version selection | ALPN `crpg-lane0/1` pins the framing and handshake layout. The hello names the lane-0 wire version (1 or 2), and the host either accepts that exact version or refuses. Nothing is negotiated or downgraded (ADR-0019) |
| Trust (D03) | Server certificate pinned by the SHA-256 of its DER, checked by a custom rustls verifier. No platform verifier, no webpki roots, no TOFU, no hostname or validity checks. TLS 1.3 only, ring provider, no 0-RTT, no client certificates |
| Credential (D03) | Opaque 16–128 bytes in the hello. Net enforces only the format and the caps. The adapter (T023b) judges validity; net offers a constant-time `ct_eq`. A credential is never printed |
| Privileged control (D03) | Unavailable and fail-closed: the server permits exactly one client-initiated bidi stream and zero uni streams, so a control stream cannot be opened |
| Runtime | Each endpoint owns one dedicated OS thread that runs one tokio **current-thread** runtime. The caller's side is synchronous and non-blocking (except the explicit `wait`, `connect`, `shutdown`, `close` and `Drop`), reached only through bounded queues |
| Backpressure | Bounded per connection and host-wide, in frames **and** bytes, defaulting to the T018a policy and tightening-only. Outbound full → `SendError::QueueFull`: retryable, nothing queued. Inbound full → the reader parks one frame and stops reading, so QUIC flow control pushes back on the peer and nothing is dropped |
| Close | Exact `u32` application close codes 0–9 (§8.1), a `Flush` or `Discard` mode, idle timeout 30 s, keep-alive 10 s |

### 3. Interface (exact public Rust)

Every public item carries a doc comment (`#![warn(missing_docs)]` stays).
The `Debug` derives are as listed. A hand-written `Debug` is called out
where it redacts something.

```rust
// ---- crates/crpg-net/src/quic/mod.rs (re-exports; submodules are private) ----
pub use client::{CloseReport, ConnectError, QuicClient}; // CloseReport is also returned by QuicServer::close
pub use close::{CloseCode, CloseMode, CloseReason, ConnectionStats, SendError};
pub use handshake::{
    frame_header, parse_frame_header, Credential, CredentialError, FrameError, HandshakeError,
    Hello, Welcome, ALPN_LANE0_V1, FRAME_HEADER_BYTES, MAX_CREDENTIAL_BYTES, MAX_HELLO_BYTES,
    MIN_CREDENTIAL_BYTES, TLS_SERVER_NAME, WELCOME_BYTES,
};
pub use identity::{CertificatePin, ServerIdentity};
pub use limits::{ClientConfig, ClientLimits, ConfigError, ServerConfig, ServerLimits};
pub use server::{
    BindError, ConnectionId, QueueTotals, QuicServer, ServerError, ServerEvent, ServerLane,
    ShutdownReport,

// ---- handshake.rs ----
/// ALPN identifier: lane-0 framing + hello/welcome layout version 1.
pub const ALPN_LANE0_V1: &[u8] = b"crpg-lane0/1";
/// SNI sent by clients. Ignored by verification (the pin is the trust root).
pub const TLS_SERVER_NAME: &str = "crpg.invalid";
/// Length-prefix size: one big-endian u32.
pub const FRAME_HEADER_BYTES: usize = 4;
/// Credential length floor (128-bit entropy floor; content is host-defined).
pub const MIN_CREDENTIAL_BYTES: usize = 16;
/// Credential length ceiling.
pub const MAX_CREDENTIAL_BYTES: usize = 128;
/// Hello payload ceiling: wire version + length byte + credential.
pub const MAX_HELLO_BYTES: usize = 2 + MAX_CREDENTIAL_BYTES; // 130
/// Exact welcome payload size: wire version + 16-byte session epoch.
pub const WELCOME_BYTES: usize = 1 + 16; // 17

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum FrameError {
    /// A zero-length frame (every lane-0 frame has at least a version byte).
    Empty,
    /// A length above the direction's cap.
    TooLarge,
}

/// The 4-byte header for a `len`-byte payload under `cap`.
pub fn frame_header(len: usize, cap: usize) -> Result<[u8; FRAME_HEADER_BYTES], FrameError>;
/// The payload length a header declares, checked against `cap` (no allocation).
pub fn parse_frame_header(header: [u8; FRAME_HEADER_BYTES], cap: usize) -> Result<usize, FrameError>;

/// An invitation credential: opaque bytes, `MIN..=MAX_CREDENTIAL_BYTES` long.
/// No `PartialEq`, no `Display`; `Debug` prints exactly `Credential(<redacted>)`.
#[derive(Clone)]
pub struct Credential(Vec<u8>);
impl Credential {
    pub fn new(bytes: Vec<u8>) -> Result<Credential, CredentialError>;
    pub fn as_bytes(&self) -> &[u8];
    /// Constant-time equality over equal lengths (unequal lengths: `false`
    /// without inspecting content). XOR-fold over every byte, no early exit,
    /// result passed through `core::hint::black_box`.
    pub fn ct_eq(&self, expected: &[u8]) -> bool;
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum CredentialError { TooShort, TooLong }

/// Client → server, first frame on the lane stream.
#[derive(Debug, Clone)]
pub struct Hello {
    /// Lane-0 wire version the client speaks: 1 (`protocol`) or 2 (`protocol_v2`).
    pub wire_version: u8,
    pub credential: Credential,
}
impl Hello {
    pub fn encode(&self) -> Result<Vec<u8>, HandshakeError>;
    pub fn decode(bytes: &[u8]) -> Result<Hello, HandshakeError>;
}

/// Server → client, first frame on the lane stream after the host accepts.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Welcome {
    /// Must equal the hello's `wire_version`.
    pub wire_version: u8,
    /// The host-issued session epoch the client puts in every intent.
    pub epoch: [u8; 16],
}
impl Welcome {
    pub fn encode(&self) -> Result<[u8; WELCOME_BYTES], HandshakeError>;
    pub fn decode(bytes: &[u8]) -> Result<Welcome, HandshakeError>;
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum HandshakeError {
    /// Wrong length, truncated, or trailing bytes.
    Malformed,
    /// A wire version other than 1 or 2.
    UnsupportedWireVersion,
    /// A credential length byte outside `MIN..=MAX_CREDENTIAL_BYTES`.
    CredentialLength,
}

    pub fn from_hex(text: &str) -> Result<CertificatePin, ConfigError>;
}

// ---- close.rs ----
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
#[repr(u32)]
pub enum CloseCode {
    Normal = 0, Shutdown = 1, ProtocolViolation = 2, FrameTooLarge = 3, HelloTimeout = 4,
    AuthRefused = 5, VersionRefused = 6, ServerBusy = 7, AuthTimeout = 8, SessionFenced = 9,
}
impl CloseCode {
    pub fn as_u32(self) -> u32;
    /// `None` for any value outside 0..=9 (peer codes are QUIC varints).
    pub fn from_u64(raw: u64) -> Option<CloseCode>;
    /// The variant name; also sent as the QUIC reason phrase (ASCII, ≤ 17 bytes).
    pub fn name(self) -> &'static str;
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum CloseMode {
    /// Write every queued outbound frame, FIN, wait for the peer's ack up to
    /// `close_flush_timeout_ms`, then CONNECTION_CLOSE.
    Flush,
    /// Discard queued outbound frames not yet handed to QUIC; close at once.
    Discard,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum CloseReason {
    /// This side closed with this code.
    Local(CloseCode),
    /// The peer sent an application close (raw varint; see `CloseCode::from_u64`).
    Peer { code: u64 },
    /// QUIC idle timeout.
    IdleTimeout,
    /// Any QUIC transport/crypto error, or a peer CONNECTION_CLOSE of transport type.
    Transport,
    /// Stateless reset or connection lost.
    Reset,
    /// The endpoint's I/O thread ended unexpectedly (panic or runtime failure).
    EndpointFailed,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum SendError {
    UnknownConnection,
    NotAccepted,
    Closed(CloseReason),
    EmptyFrame,
    FrameTooLarge,
    /// Retryable: nothing was queued; retry after the peer drains.
    QueueFull,
}

/// Owns one UDP socket, one I/O thread and one current-thread tokio runtime.
/// `Debug` is hand-written (local address + totals).
pub struct QuicServer { /* private */ }
impl QuicServer {
    pub fn bind(config: ServerConfig) -> Result<QuicServer, BindError>;
    pub fn local_addr(&self) -> SocketAddr;
    pub fn poll_event(&mut self) -> Option<ServerEvent>;
    /// Blocks up to `timeout` until an event or any inbound frame is queued;
    /// `false` on timeout. Never needed by a pump that polls on its own tick.
    pub fn wait(&self, timeout: Duration) -> bool;
    pub fn accept(&mut self, conn: ConnectionId, welcome: Welcome) -> Result<(), ServerError>;
    pub fn refuse(&mut self, conn: ConnectionId, code: CloseCode) -> Result<(), ServerError>;
    pub fn try_recv(&mut self, conn: ConnectionId) -> Result<Option<Vec<u8>>, ServerError>;
    pub fn try_send(&mut self, conn: ConnectionId, frame: &[u8]) -> Result<(), SendError>;
    /// Inbound frames stay drainable after a server-side close, so the
    /// report's `inbound_frames_discarded` is always 0 here.
    pub fn close(&mut self, conn: ConnectionId, code: CloseCode, mode: CloseMode) -> Result<CloseReport, ServerError>;
    pub fn stats(&self, conn: ConnectionId) -> Result<ConnectionStats, ServerError>;
    pub fn totals(&self) -> QueueTotals;
    pub fn lane(&mut self, conn: ConnectionId) -> Result<ServerLane<'_>, ServerError>;
    /// Graceful: stop accepting, close pending with `Shutdown`, flush accepted
    /// connections (`Flush`, one shared deadline), close all with `Shutdown`,
    /// wait for the endpoint to go idle (bounded by the same deadline), join.
    pub fn shutdown(self) -> ShutdownReport;
}
/// Abrupt: every connection closes with `Shutdown` in `Discard` mode, then the
/// endpoint is given up to `close_flush_timeout_ms` to transmit the
/// CONNECTION_CLOSE frames (`wait_idle`), then the thread is joined.
impl Drop for QuicServer { fn drop(&mut self); }

/// One accepted connection viewed as the net-local single-channel `Transport`.
#[derive(Debug)]
pub struct ServerLane<'a> { /* server: &'a mut QuicServer, conn: ConnectionId */ }
impl crate::transport::Transport for ServerLane<'_> {
    type Error = SendError;
    fn send(&mut self, bytes: &[u8]) -> Result<(), SendError>;   // = try_send
    fn recv(&mut self) -> Option<Vec<u8>>;                       // = try_recv(..).ok().flatten()
}

impl crate::transport::Transport for QuicClient {
    type Error = SendError;
    fn send(&mut self, bytes: &[u8]) -> Result<(), SendError>;   // = try_send
    fn recv(&mut self) -> Option<Vec<u8>>;                       // = try_recv().ok().flatten()
}
/// Closes with `Normal` in `Discard` mode, waits up to
/// `close_flush_timeout_ms` for the CONNECTION_CLOSE to go out, joins the thread.
impl Drop for QuicClient { fn drop(&mut self); }
```

`SocketAddr` is `std::net::SocketAddr` and `Duration` is
`std::time::Duration`. No tokio, quinn or rustls type appears in any public
signature, so T023b and the later Godot bridge never name an async type.
**Relation to `Transport`:** the trait is unchanged (D01/E003-B: it stays
net-local, with no `crpg-contracts` edit). `QuicClient` and `ServerLane`
implement it as single-channel endpoints. Their `send`/`recv` never block
and never do I/O on the caller's thread, matching the trait's documented
shape. `InMemoryTransport` keeps its own multi-peer API, as today.

**`Display`** (crate convention since `projection_v2`): every error enum
prints exactly `<VariantName> at quic/<area>`, where `<VariantName>` is the
variant identifier without its payload. The areas are: `FrameError` →
`quic/frame`, `CredentialError` → `quic/credential`, `HandshakeError` →
`quic/handshake`, `ConfigError` → `quic/config`, `SendError` → `quic/send`,
`ServerError` → `quic/server`, `BindError` → `quic/bind`, `ConnectError` →
`quic/connect`. Each implements `std::error::Error` with no `source`.
`CloseCode`, `CloseReason` and the value types have no `Display`.

### 4. Wire (normative bytes)

**ALPN** is exactly `crpg-lane0/1` (12 ASCII bytes) on both sides. Any other
value fails TLS with `no_application_protocol`; the prototype measured QUIC
crypto error `0x178`. **SNI** is `crpg.invalid`.

**Frame** = `len: u32 big-endian` then `len` payload bytes. The reader reads
the 4-byte header, checks it with `parse_frame_header(header, cap)` (`0` →
`Empty`, `> cap` → `TooLarge`), and only then allocates exactly `len` bytes
and reads the body. A header over the cap is **never** followed by a body
read.

| Frame | Direction | Cap | Payload layout |
|---|---|---|---|
| Hello | client → server, first | 130 | `[wire_version: u8][cred_len: u8][credential: cred_len]`; `cred_len` in 16..=128; total length must equal `2 + cred_len` |
| Welcome | server → client, first | exactly 17 | `[wire_version: u8][epoch: 16 bytes]` |
| Lane-0 intent | client → server | 4,096 | opaque bytes (v1 or v2 `encode_intent` output) |
| Lane-0 delta | server → client | 65,536 | opaque bytes (v1 or v2 `encode_delta` output) |

`Hello::decode` precedence: length < 2 → `Malformed`; `wire_version ∉ {1, 2}`
→ `UnsupportedWireVersion`; `cred_len ∉ 16..=128` → `CredentialLength`;
length ≠ `2 + cred_len` → `Malformed`. `Welcome::decode`: length ≠ 17 →
`Malformed`; then `wire_version ∉ {1, 2}` → `UnsupportedWireVersion`.
Encode applies the same `wire_version` check. Literal vectors (§13.2): the
hello for wire 1 with credential `[0x11; 16]` is `01 10` followed by
`11 × 16`, framed as `00 00 00 12 01 10 11…`. `frame_header(3, 4096)` is
`00 00 00 03`.

### 5. Handshake sequence and the D03 mapping

Server, per incoming connection:

1. If live connections (pending included) ≥ `max_connections`, call
   `Incoming::refuse()`. This is QUIC `CONNECTION_REFUSED` before any
   crypto. It increments `refused_at_limit` and emits no event.
2. Run the TLS 1.3 handshake (ring provider, `with_no_client_auth`,
   `with_single_cert(identity)`, ALPN exactly `ALPN_LANE0_V1`,
   `max_early_data_size = 0`). A failure increments `refused_handshakes`
   and emits no event.
3. Assign the next `ConnectionId` and start `hello_timeout_ms`. Accept the
   client's first bidi stream and read one frame with cap 130. The close
   code for each failure, after which the connection ends with no event and
   `refused_handshakes` is incremented:
   - header over 130 → `FrameTooLarge` (3);
   - zero length, `Malformed` or `CredentialLength`, or FIN or reset before
     a complete hello → `ProtocolViolation` (2);
   - `UnsupportedWireVersion` → `VersionRefused` (6);
   - timer expiry → `HelloTimeout` (4).
4. Emit `HelloReceived` and start `decision_timeout_ms`. Lane frames the
   client sent early stay in QUIC buffers. They are **not read** and never
   surface before `accept`, so `try_recv` on a pending connection returns
   `NotAccepted`.
5. `accept(conn, welcome)`: the welcome's `wire_version` must equal the
   hello's (else `InvalidWelcome`, and nothing is sent). Net writes the
   welcome frame, then starts the lane reader (cap 4,096) and writer.
   `refuse(conn, code)` closes at once with `code`; `Closed{Local(code)}`
   follows. If the decision timer expires first, net closes with
   `AuthTimeout` (8), and a later `accept`/`refuse` returns
   `Closed(Local(AuthTimeout))`.

Client: bind the UDP socket on the caller's thread. Build a rustls
`ClientConfig` from `builder_with_provider(ring)`, TLS 1.3 only, through
`.dangerous().with_custom_certificate_verifier(PinnedServerVerifier)` with no
client auth, the ALPN set and `enable_early_data = false`. Connect with SNI
`TLS_SERVER_NAME`, open the bidi stream, write the hello frame, and read
one header that must declare exactly 17 bytes (anything else is
`InvalidWelcome` and a `ProtocolViolation` close). Decode the welcome and
check its version, then return. The whole sequence is bounded by
`connect_timeout_ms` (`TimedOut`, then a `Normal` close).

**Pinning mechanism** (`tls.rs`, private) is
`PinnedServerVerifier { pin, provider, mismatch: Arc<AtomicBool> }`,
implementing `rustls::client::danger::ServerCertVerifier`:

- `verify_server_cert` accepts only when `intermediates` is empty **and**
  the SHA-256 of `end_entity` equals the pin. SHA-256 comes from
  `rustls::crypto::ring::cipher_suite::TLS13_AES_128_GCM_SHA256`'s
  `hash_provider`, so there is no direct `ring` edge. The comparison is a
  constant-time fold, although the pin is not secret. On failure it sets
  `mismatch` and returns
  `Error::InvalidCertificate(CertificateError::ApplicationVerificationFailure)`.
  `connect` maps that flag to `ConnectError::PinMismatch`.
- `server_name` and `now` are ignored. The pin, distributed out of band
  with the invitation, is the whole trust decision (D03), so there is no
  hostname, validity-period or revocation check, and certificate rotation
  means a new invitation.
- `verify_tls13_signature` delegates to `rustls::crypto::verify_tls13_signature`
  with the provider's `signature_verification_algorithms`, so the server
  still has to prove possession of the pinned key.
- `verify_tls12_signature` returns
  `Err(PeerIncompatible(Tls13RequiredForQuic))`; QUIC never uses TLS 1.2.
- `supported_verify_schemes` is the provider's list.

No `platform-verifier`, `rustls-platform-verifier`, `webpki-roots` or
`rustls-native-certs` is used.

**Credential and D03.** The credential travels only inside the
TLS-protected stream, after the pin has been verified. Net checks its format
and caps only. Comparing it, binding it to a principal, campaign, actors and
grants, revoking it, and generating it from secure entropy all belong to the
host adapter (T023b). The credential never appears in a close reason,
`Debug`, error or log; `crpg-net` emits no logs.

### 6. Threading, runtime and the sync boundary

- **Who creates the runtime:** each `QuicServer::bind` and
  `QuicClient::connect` spawns exactly one `std::thread` (named
  `crpg-quic-server` or `crpg-quic-client`). That thread builds
  `tokio::runtime::Builder::new_current_thread().enable_io().enable_time().build()`
  and runs the endpoint inside `block_on`. Nothing is shared with any other
  runtime, nothing is global, and `#[tokio::main]` and the macros are not
  used. The caller's thread binds the `std::net::UdpSocket` and passes it
  to `quinn::Endpoint::new(EndpointConfig::default(), .., socket,
  Arc::new(TokioRuntime))` on the I/O thread. Readiness or a startup error
  comes back over a `std::sync::mpsc::sync_channel(1)`, which is how
  `bind`/`connect` return synchronously.
- **Sync boundary:** shared state lives behind a `std::sync::Mutex`: queues,
  per-connection status, the event FIFO and counters. Async tasks are woken
  with `tokio::sync::Notify`, and sync waiters (`wait`, `connect`,
  `shutdown`) with a `std::sync::Condvar`. The mutex is never held across
  an `.await`. There are no unbounded channels anywhere. A poisoned mutex
  or a panicked I/O thread makes every later call report
  `CloseReason::EndpointFailed`. It never panics the caller.
- **Determinism:** the host or sim side stays synchronous. The pump (T023b)
  decides when to poll events, drain inbound frames (recommended order:
  ascending `ConnectionId`) and queue outbound frames. Within a connection,
  frame order is exact. Arrival timing across connections is real-network
  nondeterminism, and that is why T022 captures the admitted schedule. Net
  touches no `World`, RNG, event queue or simulation clock. quinn's and
  ring's internal randomness (packet numbers, keys) never reaches
  simulation state.
- **Scoped amendment of net's no-I/O rule (needs an ADR, §14).** Threads,
  sockets, tokio, quinn, rustls, `std::time::{Duration, Instant}` and
  `std::sync` are permitted **only under `src/quic/`**. Every other module
  keeps the existing ban, and the DoD grep (§14) enforces it.

### 7. Ordering, backpressure and bounds

**Ordering:** per connection and direction, every frame accepted by
`try_send` is delivered to the peer's `try_recv` exactly once and in
`try_send` order while the connection lives. Nothing is reordered,
duplicated or silently dropped. Across connections there is no ordering
guarantee. QUIC reliability is not command idempotency: application
epoch/lane/seq dedup and the retry cache stay in the host (T022), unchanged.

| Bound (defaults = v1, tightening-only) | Server | Client |
|---|---|---|
| Read cap per lane frame | 4,096 | 65,536 |
| Send cap per lane frame | 65,536 | 4,096 |
| Inbound queue per connection | 128 frames / 262,144 B (`QueueCaps::v1()` per-peer) | 128 frames / 2,097,152 B |
| Inbound host-wide | 1,024 frames / 2,097,152 B (`QueueCaps::v1()` host) | — |
| Outbound queue per connection | 128 frames / 2,097,152 B (`QueueCaps::v1_egress()` per-peer) | 128 frames / 262,144 B |
| Outbound host-wide | `usize::MAX` frames / 16,777,216 B (`v1_egress()` host) | — |
| Parked inbound frame | ≤ 1 per connection (≤ one read cap) | ≤ 1 |
| Connections | `max_connections` 16 (pending included) | 1 |
| Event FIFO | ≤ 2 × `max_connections` by construction: one `HelloReceived` and one `Closed` per connection, and a slot is released only when its `Closed` event is polled | — |

**Outbound (try_send) precedence.** Server: `UnknownConnection` →
`NotAccepted` → `Closed(reason)` (closing or closed) → `EmptyFrame` →
`FrameTooLarge` → `QueueFull`. The client has the same order from `Closed`
onward. `QueueFull` is checked against per-connection frames, then
per-connection bytes, then host-wide frames, then host-wide bytes, using
checked addition that fails closed. It is **retryable and grows nothing**.
A frame leaves the outbound accounting when the writer task hands it to
`SendStream::write_all`. quinn's own buffer is then bounded by `send_window`
(§8.3), and the writer awaits flow control, so a slow peer ends as
`QueueFull` at the producer, never as silent loss.

**Inbound.** The reader task reads one complete frame. If the
per-connection or host-wide inbound room cannot take it, it **parks** that
frame (`reader_parked = true`) and stops reading. QUIC stream and
connection flow control then stalls the peer's sender, which eventually
sees `QueueFull` at its own `try_send`. Parked frames enter in arrival
order as room frees. With several readers parked on host-wide room, the
first to observe room wins: bounded, but not ordered across connections.
Partial frames sit in quinn's receive buffer (≤ `stream_receive_window`),
never in net.

**`try_recv` precedence.** Server: `UnknownConnection` → `NotAccepted` →
`Ok(Some(frame))` if any is queued → `Err(Closed(reason))` if closed and
drained → `Ok(None)`. Frames fully received before any close stay
drainable after it, and they keep counting toward host-wide inbound caps
until drained. A connection's record is forgotten (later calls return
`UnknownConnection`) once its `Closed` event is polled **and** a `try_recv`
has returned `Err(Closed(..))`, or at once if it held no frames.

**`accept`/`refuse`/`close` precedence.** `accept`: `UnknownConnection` →
`Closed(r)` → `NotPending` → `InvalidWelcome`. `refuse`:
`UnknownConnection` → `Closed(r)` → `NotPending`. `close`:
`UnknownConnection` → `Closed(r)` (already closed). Otherwise it is
accepted for pending or accepted connections; on a pending one it equals
`refuse`.

**Mapping to T022 (informative for T023b, which owns the adapter):**

| Net | T022 host |
|---|---|
| `HelloReceived` | adapter checks the credential (`ct_eq`), then `bind_peer` → `accept(conn, Welcome { wire_version: host.protocol().as_u8(), epoch: host.epoch(handle)? })`; `HostError::ServerBusy` → `refuse(ServerBusy)`; bad credential → `refuse(AuthRefused)`; version ≠ host selection → `refuse(VersionRefused)`; `HostError::Closed` → `refuse(Shutdown)` |
| `try_recv` → `Some(bytes)` | `ingest(handle, &bytes, now_ms)`; `Refused{QueueFull}` is T022's retryable ingress refusal (adapter policy: §16 Q8) |
| `take_delivery` frames | `try_send` each unsent frame in order; `acknowledge_delivery` only through frames that returned `Ok`; `SendError::QueueFull` → stop this connection for this pump and retry next pump (the host log retains it; T022 `QueueFull`/head-of-line semantics carry the pressure back to admission) |
| `Closed` event or `SendError::Closed` | `unbind_peer(handle)` |
| unbind / `SeqConflict` fence / `RebindRequired` | `close(conn, SessionFenced, Discard)`: fences frames still queued in net; bytes already handed to QUIC cannot be recalled (§16 Q7) |
| `host.shutdown()` | then `server.shutdown()` (D02 order: stop admissions, refuse staged work, checkpoint, then close transports) |

### 8. Close, timeouts, keep-alive and QUIC parameters

**8.1 Application close codes** (`u32`, sent as QUIC varints with the
`name()` reason phrase):

| Code | Name | Sent by | Meaning |
|---|---|---|---|
| 0 | `Normal` | either | Deliberate end of session |
| 1 | `Shutdown` | server | Server shutting down (`shutdown`, `Drop`) |
| 2 | `ProtocolViolation` | either | Bad framing, zero-length frame, malformed hello/welcome, FIN/reset mid-frame, `RESET_STREAM`/`STOP_SENDING` on the lane |
| 3 | `FrameTooLarge` | either | Length prefix over the direction's cap |
| 4 | `HelloTimeout` | server | No complete hello within `hello_timeout_ms` |
| 5 | `AuthRefused` | server (adapter) | Credential not accepted (unknown and revoked are deliberately indistinguishable) |
| 6 | `VersionRefused` | server | Wire version unknown (net) or not the host's selection (adapter) |
| 7 | `ServerBusy` | server (adapter) | No binding slot |
| 8 | `AuthTimeout` | server | Adapter made no accept/refuse decision within `decision_timeout_ms` |
| 9 | `SessionFenced` | server (adapter) | Host fenced the binding (unbind, epoch closure, narrowing) |

Peer codes outside 0..=9 are kept raw in `CloseReason::Peer { code }`.
quinn's `ConnectionError` maps as follows: `ApplicationClosed` →
`Peer { code }`; `TimedOut` → `IdleTimeout`; `Reset` → `Reset`;
`LocallyClosed` → `Local(code used)`; `TransportError`, `ConnectionClosed`,
`VersionMismatch` and `CidsExhausted` → `Transport`.

**8.2 Lane-stream edge cases (both sides).** A peer FIN exactly at a frame
boundary ends reading. Queued frames stay drainable, and the connection
stays open for the other direction until someone closes it. FIN or reset
mid-frame, `RESET_STREAM`, or `STOP_SENDING` closes with
`ProtocolViolation`. A partially received frame is discarded and never
surfaces.

**8.3 Timeouts and fixed QUIC transport parameters.** Limits are
configurable within ranges, and loosening past v1 is `LoosensPolicy`:

Below a range's floor (or inconsistent) is `InvalidLimits`. Above the v1
value is `LoosensPolicy`, except `keep_alive_ms`, which is not a policy cap
and is only range-checked.

| Limit | v1 | Valid range |
|---|---|---|
| `idle_timeout_ms` | 30,000 | 1,000..=30,000 |
| `keep_alive_ms` (both sides) | 10,000 | 0 (off), or 100..`idle_timeout_ms` (strictly less; never `LoosensPolicy`) |
| `hello_timeout_ms` (server) | 5,000 | 100..=5,000 |
| `decision_timeout_ms` (server) | 5,000 | 100..=5,000 |
| `connect_timeout_ms` (client) | 10,000 | 100..=10,000 |
| `close_flush_timeout_ms` | 2,000 | 0..=2,000 |
| `max_connections` (server) | 16 | 1..=16 |
| queue frames | §7 | ≥ 1, ≤ v1; host-wide ≥ per-connection |
| queue bytes | §7 | ≥ that direction's frame cap (4,096 or 65,536), ≤ v1; host-wide ≥ per-connection |

`validate` walks the fields in declaration order (nested `QueueCaps` fields
as `inbound.per_peer_frames` and so on). For each field it reports
`InvalidLimits` before `LoosensPolicy`, and the first failure wins.

These parameters are fixed in `tls.rs` and are not configurable:

| Parameter | Server | Client |
|---|---|---|
| `max_concurrent_bidi_streams` | 1 | 0 |
| `max_concurrent_uni_streams` | 0 | 0 |
| `datagram_receive_buffer_size` | `None` (DATAGRAM extension off) | `None` |
| `datagram_send_buffer_size` | 0 | 0 |
| `stream_receive_window` | 65,536 | 1,048,576 |
| `receive_window` | 131,072 | 2,097,152 |
| `send_window` | 1,048,576 | 262,144 |
| `max_idle_timeout` / `keep_alive_interval` | from limits | from limits |
| `ServerConfig::migration` | `false` | — |
| `ServerConfig::max_incoming` | `max_connections` | — |
| 0-RTT | off | off |

Everything else is quinn's default. The effective idle timeout is QUIC's
minimum of the two peers' values.

### 10. Explicitly not done in T023

- No unreliable DATAGRAM lane, no movement lane (lane 1), and no snapshot
  stream (T024 adds its own stream under a new ALPN or version).
- No vendored quinn-proto, no `[patch.crates-io]`, no dedup patch, and no

  first; documentation is operational work for the dedicated server).

  grants, admission, rate limits, epochs and checkpoint all stay in
  T022/T023b. No `crpg-server` change.
- No reconnect, resume or session migration (T025a), and no in-band resync

- No privileged or GM control stream (D03: fail-closed by stream limits).
- No certificate generation, file loading, invitation format, or operator
  tooling. T023b/operations decide how the DER bytes and the pin text
  reach the configs.
- No logging or tracing subscriber, and no metrics export beyond
  `ConnectionStats`/`QueueTotals`.

**13.1 Files**

- `tests/quic.rs`: the endpoint suite (§13.2).
- `tests/quic_conformance.rs`: the lane-0 conformance cases over real QUIC
  (§13.3). It reuses `support/driver.rs` and `support/fixture.rs` through
  `#[path]`, as `conformance.rs` does.
- `tests/support/quic_rig.rs` (test-only, starting with
  `#![allow(dead_code)]` plus a reason comment) contains:
  - loopback server/client builders on `127.0.0.1:0` (IPv4 only, so the
    tests do not depend on IPv6);
  - a manual-accept helper and wait helpers with a hard 30 s deadline that
    panic `"deadline"`. These are failure guards, never oracles;
  - a **raw quinn test client**, with its own independently written pin
    verifier, for malformed hellos, foreign ALPN, early lane frames and
    abrupt closes;
  - `UdpRelay`, a std-only `UdpSocket` relay. It has a seeded SplitMix64
    `drop_every`, block-rotation `reorder_depth`, a `blackhole` switch and
    counters `forwarded`/`dropped`/`reordered`. Packets are released when a
    block fills or the read times out (liveness only), with no sleeps.
- `tests/fixtures/quic/server_a.cert.der`, `server_a.key.pk8.der`,
  `server_b.cert.der`, `server_b.key.pk8.der` are test-only self-signed
  ECDSA P-256 certificates with `CN`/`SAN` `crpg.invalid`, generated once
  with:
  `openssl req -x509 -newkey ec -pkeyopt ec_paramgen_curve:prime256v1 -nodes -days 36500 -subj /CN=crpg.invalid -addext subjectAltName=DNS:crpg.invalid`,
  then `openssl x509 -outform DER` and `openssl pkcs8 -topk8 -nocrypt
  -outform DER`. The two SHA-256 pins are recorded as literals in
  `tests/quic.rs` and in the completion record (§16 Q4).

**13.2 `tests/quic.rs`: named cases.** Every rejection has a positive
control on the same server.

1. `frame_and_handshake_bytes_are_exact`: the §4 literal vectors; every
   `Hello::decode`/`Welcome::decode` precedence case; `frame_header(0, _)` →
   `Empty`; `frame_header(cap + 1, cap)` → `TooLarge`;
   `parse_frame_header([0xFF; 4], 4096)` → `TooLarge`.
2. `credential_bounds_and_redaction`: lengths 15 → `TooShort`, 16 and 128
   → ok, 129 → `TooLong`; `format!("{:?}")` is exactly
   `Credential(<redacted>)`, also inside `Hello`'s and `ServerEvent`'s
   `Debug`; `ct_eq` is true, false on content, and false on length.
3. `certificate_pin_hex_and_fixture_values`:
   `of_certificate(server_a)` equals the recorded literal (computed
   independently by `sha256sum`); `to_hex`/`from_hex` round-trip; 63, 65,
   uppercase or non-hex input → `InvalidPin`.
4. `limits_validate_and_refuse_loosening`: `v1()` is valid for both. Each
   field is pushed one step past v1 → `LoosensPolicy { field }`. Zero,
   below one maximal frame, host-wide < per-connection, and keep-alive ≥
   idle → `InvalidLimits { field }`. `bind`/`connect` surface
   `BindError::Config` and `ConnectError::Config`.
5. `loopback_handshake_and_round_trip`: `HelloReceived` carries the exact
   wire version, remote address and a `ct_eq`-equal credential. After
   `accept`, the client's `welcome()` equals what was sent. Intent bytes
   and delta bytes arrive byte-identical, for wire 1 and for wire 2.
6. `wrong_certificate_pin_refused`: pin of `server_b` → `PinMismatch`; no
   `HelloReceived`; `refused_handshakes` +1. Control: the correct pin on
   the same server succeeds.
7. `foreign_alpn_refused`: a raw client with `crpg-lane0/2` fails the
   handshake; no event; counter +1. Control: a raw client with
   `crpg-lane0/1` reaches `HelloReceived`.
8. `malformed_hello_refused_with_exact_codes`: raw-client cases:
   - header 131 → code 3;
   - zero-length → 2;
   - `cred_len` 15 → 2;
   - `cred_len` that disagrees with the frame length → 2;
   - wire version 3 → 6;
   - FIN before a complete hello → 2.

   Each case: exact `ApplicationClosed` code, no event, counter +1. Control:
   16-byte and 128-byte credentials both reach `HelloReceived`.
9. `hello_timeout_closes_silent_client`: `hello_timeout_ms = 200`; a raw
   client opens the stream and stays silent → code 4.
10. `host_refusals_reach_client_exactly`: `refuse` with 5, 6 and 7 gives
    `ConnectError::Refused { code }` exactly, and `Closed { Local(..) }`
    events. With `decision_timeout_ms = 200` and no decision → client
    `Refused { code: 8 }`, server `HelloReceived` then
    `Closed{Local(AuthTimeout)}`, and a late `accept` →
    `Closed(Local(AuthTimeout))`. An `accept` whose welcome version differs
    from the hello → `InvalidWelcome`, and nothing is sent.
11. `pending_connection_never_surfaces_lane_frames`: a raw client sends the
    hello plus one lane frame at once. `try_recv` while pending →
    `NotAccepted`; after `refuse` the frame never surfaces. Control: the
    same choreography with `accept` delivers the early frame
    byte-identical, after the welcome.
12. `lane_frame_caps_enforced_both_directions`: client `try_send` of 4,097
    → `FrameTooLarge` and of 0 → `EmptyFrame`, stats unchanged both times;
    4,096 arrives intact. Server `try_send` of 65,537 → `FrameTooLarge`;
    65,536 arrives intact. After accept, a raw client sends two valid
    frames and then header 4,097 → the server drains the two in order, then
    `Err(Closed(Local(FrameTooLarge)))`, and the client sees code 3. A raw
    zero-length header → code 2.
13. `ordering_preserved_under_concurrent_traffic`: 4 clients on 4 threads,
    each sending 1,000 frames (sizes cycling 1..=4,096, payload =
    client/counter pattern) while the server sends 1,000 frames to each
    (sizes cycling 1..=65,536). Every connection's sequence is exactly
    1..=1,000, in order, both directions, with no extras.
14. `ordered_exactly_once_through_impaired_relay`: client ↔ `UdpRelay` ↔
    server with `drop_every = 13` and `reorder_depth = 4` (seed 23), both
    directions, 2,000 frames each way, delivered exactly once and in order.
    Impairment control: relay `dropped ≥ 1` and `reordered ≥ 1`. Positive
    control: the same transfer through a clean relay with `dropped == 0`.
15. `inbound_backpressure_at_exact_bounds`:
    - **Frames:** per-connection inbound 4 frames; the client sends 6 ×
      4,096 B. Wait until `inbound_frames == 4 && reader_parked`. Drain 1;
      wait until 4 again with `reader_parked`. Drain all; the order is
      1..=6.
    - **Bytes:** per-connection bytes = 10,000 with 4,096 B frames → exactly
      2 queued, then parked.
    - **Host-wide frames = 3:** connection A holds 2, B holds 1 and parks.
    - In every case, no frame is lost or duplicated after the full drain.
16. `outbound_queue_full_is_retryable_and_lossless`: a non-reading client,
    with server outbound limited to 4 frames, and separately to 3 × 65,536
    bytes. `try_send` until `QueueFull`; stats then show exactly the cap. A
    further `QueueFull` changes nothing. The client then drains everything,
    and the next `try_send` succeeds. The received sequence equals exactly
    the `Ok` sends, in order, so the refused frame was never delivered. The
    client-side outbound `QueueFull` is checked the same way, with the
    server not draining.
17. `graceful_close_flushes_and_reports_codes`:
    - Server `close(Normal, Flush)` with 3 queued frames: the client
      receives exactly those 3, then `Err(Closed(Peer { code: 0 }))`, and
      the report shows 0 discarded.
    - `close(SessionFenced, Discard)` with N queued: the client receives an
      in-order prefix of length `k`, then `Peer { code: 9 }`, with
      `k + outbound_frames_discarded ≤ N`. Frames already handed to QUIC
      may be lost by the immediate close, so this is a bound, not
      conservation.
    - Client `close(Normal, Flush)` after 3 sends: the server drains 3, then
      `Err(Closed(Peer { code: 0 }))`, and the `Closed` event agrees.
18. `server_shutdown_and_drop_close_every_connection`: 3 reading clients,
    each with 5 frames queued at the server; `shutdown()` → each client
    receives exactly its 5 frames, then `Err(Closed(Peer { code: 1 }))`,
    with `connections_closed == 3` and `outbound_frames_discarded == 0`. A
    second server dropped without `shutdown` → its client sees
    `Peer { code: 1 }`, not an idle timeout.
19. `peer_abrupt_close_keeps_complete_frames_only`: a raw client sends 2
    frames, half of a third, then `close(0x99)` → `Closed{Peer{code: 0x99}}`;
    `try_recv` yields exactly the 2 frames, then
    `Err(Closed(Peer { code: 0x99 }))`.
20. `idle_timeout_closes_silent_peer`: idle 1,000 / keep-alive 300 through
    `UdpRelay`; switch `blackhole` on after the welcome → server
    `Closed{IdleTimeout}` and client `Err(Closed(IdleTimeout))`. Positive
    control: with the relay passing, wait until the client's
    `keepalive_pings_sent ≥ 5` (longer than the idle period, measured by
    pings, not sleeps), and both sides are still open.
21. `datagrams_and_connection_limit_fail_closed`: a raw client sees
    `max_datagram_size() == None` and `send_datagram` →
    `UnsupportedByPeer`. With `max_connections = 2`, a third `connect` →
    `EndpointFull` and `refused_at_limit` +1. After one `Closed` is polled,
    a new client connects.
22. `transport_trait_round_trip`: a generic `fn exchange<T: Transport>`
    drives `QuicClient` and `ServerLane` (send, recv, `None` when empty).

**13.3 `tests/quic_conformance.rs`: the lane-0 conformance suite over
QUIC loopback.** The bytes go T018c `NetDriver` ↔ `QuicServer` ↔ real QUIC
↔ `QuicClient`. The test accepts each client with
`Welcome { wire_version: 1, epoch: EPOCH_A/B }`, and clients build intents
from `welcome().epoch`, which proves the epoch handoff. The driver is keyed
by `sim::PeerId`, so an `InMemoryTransport` is used **only to mint the two
`PeerId`s**, and no byte flows through it (§16 Q5).

1. `quic_malicious_frames_rejected_without_mutation`: forged and
   cross-client `NetId`s, foreign epoch (`SessionExpired`), replayed seq
   with different bytes (`SeqConflict`), malformed, bad-version and bad-tag
   frames, all sent over QUIC. Receipts return over QUIC and decode to the
   exact codes, undecodable frames get no reply, and each case has a
   positive control and a byte-identical `authoritative_hash`.
2. `quic_filtered_replica_converges_per_peer`: same setup as T018c Suite 2,
   with deltas pumped over QUIC into the `Replica` oracle.
3. `quic_desync_oracle_fails_loudly_on_drop_and_corruption`: the negative
   controls applied in the test after QUIC delivery (QUIC itself never
   drops). The oracle must fail.
4. `quic_lost_receipt_retried_without_reexecution`: the client test code
   discards the first receipt. Retrying the same bytes over QUIC returns
   the cached `Applied`, and `executions() == 1`.
5. `quic_exercise_matches_clean_in_memory_schedule`: the T018c 5,000-tick
   script (seed 42) runs twice: in memory with `FaultSchedule::clean()`,
   and over QUIC through `UdpRelay` (`drop_every = 13`,
   `reorder_depth = 4`). The five per-1,000-tick hashes and both projected
   views are identical, with relay `dropped ≥ 1`. Sensitivity: seed 43
   differs.

The existing `tests/conformance.rs` continues to pass unchanged. Over-cap
intents now behave differently: on QUIC, a length prefix over 4,096 closes
the connection (case 12), whereas the in-memory fabric delivers the frame
to admission (§16 Q14).

### 16. Open questions for the user

1. **Blocker: `rand`/`rand_core` duplicates fail `cargo deny check`
   beyond ADR-0023.** In the combined workspace graph, quinn-proto 0.11.19
   needs `rand` 0.10 (not optional). ADR-0006's dev-only proptest (newest
   1.11.0) needs 0.9.
   *Recommendation:* approve two more dev-side skips, `rand@0.9.5` and
   `rand_core@0.9.5`, recorded as a dated addendum to ADR-0023 in the same
   T023 `deny.toml` edit. They pin the proptest (ADR-0006, never shipped)
   side, so the shipped graph keeps exactly one `rand`. The alternatives
   are worse:
   - quinn 0.11.11 / quinn-proto 0.11.15 (on rand 0.9) would reverse D23's
     audited pins;
   - waiting for proptest to move to rand 0.10 has no date.
2. **A runtime `getrandom` duplicate is hidden by an existing dev-only
   skip.** ring 0.17.14 uses `getrandom` 0.2.17, and rand 0.10.3 uses
   0.4.3. Both are compiled on both x86_64 targets, and `deny.toml`'s
   `getrandom@0.4.3` skip, commented as proptest-only, is what passes it.
   *Recommendation:* accept the duplicate, since no aligned versions exist.
   State it in the ADR-0023 addendum, and correct that skip's comment in
   the same edit (comment only, no policy change). If you prefer T038's
   approach (Q3 there), leave the comment to a later bookkeeping change.
3. **ADR-0023's stated cost is inaccurate for our Windows target.**
   `windows-sys` 0.52 is reached only on aarch64 Windows, so x86_64 MSVC
   does not compile it. The skip is still needed because cargo-deny checks
   all targets.
   *Recommendation:* T023 appends a dated factual note to ADR-0023. Do not
   add a `targets` filter to `deny.toml`.
4. **Test certificates with committed private keys.**
   *Recommendation:* commit the four DER fixtures: test-only, documented
   generation, and pins recorded. The alternative is an `rcgen` dev-dep,
   which is a new dependency and needs approval. If secret scanning
   objects, generate them in a build-free test helper later; do not
   generate them at test time with new crates.
5. **The conformance driver is keyed by `sim::PeerId`**, which only
   `InMemoryTransport::add_peer` can mint.
   *Recommendation:* accept using an `InMemoryTransport` as an id registry
   only, in `quic_conformance.rs`, with no edit to `support/driver.rs`.
   T023b's `host_quic` suite exercises the real host instead.
6. **Credential bounds of 16..=128 bytes, opaque.**
   *Recommendation:* approve. T023b defines the content (for example an
   invitation id plus a secret) inside these bounds. 16 bytes is a 128-bit
   entropy floor.
7. **Narrowing grants (`RebindRequired`) and fencing on a reliable
   stream.** Net can discard what it still holds (`CloseMode::Discard`),
   but it cannot recall bytes already handed to QUIC, and the wire has no
   in-band "delivery restarted" marker.
   *Recommendation:* T023b closes the connection with `SessionFenced`
   (`Discard`) on unbind, epoch closure and narrowing, until a resync
   marker or reconnect (T025a) exists. Do not invent an in-band reset in
   T023.
8. **Host ingest `QueueFull` handling (T023b).**
   *Recommendation:* T023b holds the refused frame (one per connection)
   and stops draining that connection, so the pressure reaches the client
   through QUIC flow control. Drop only frames whose refusal is terminal
   (`RateLimited`, `FrameTooLarge`, `Unauthenticated`). This is T023b's
   decision; T023 provides the parking semantics either way.
9. **Where the pins live.**
   *Recommendation:* put them directly in `crates/crpg-net/Cargo.toml`
   (one crate, smallest diff). T023b repeats the identical `=` pins, and
   Cargo resolves them to one version. The alternative is the root
   `[workspace.dependencies]` (the `postcard` precedent), which touches a
   root file in a single-crate task.
10. **tokio features narrower than the dossier** (`rt`, `net`, `time`,
    `sync`; no `rt-multi-thread`, no `macros`).
    *Recommendation:* approve, as within D23 (narrowing only).
11. **No `quic` cargo feature.** From T023 on, `crpg-server` and the later
    embedded build link QUIC even before T023b uses it.
    *Recommendation:* no feature flag. Gates run with default features
    (ADR-0012), and an optional feature would either go untested or be
    always on.
12. **The ADR for the scoped no-I/O amendment.**
    *Recommendation:* T023 writes it (expected ADR-0024; renumber if taken
    when T023 lands), accepted by approving this contract.
13. **One current-thread runtime per endpoint.**
    *Recommendation:* approve. Lane-0 rates (40 intents/s per peer, 8
    peers) do not need a multi-thread runtime. Revisit with T024 snapshot
    measurements (D06).
14. **Over-cap intent frames close the connection** (`FrameTooLarge`, 3)
    instead of the in-memory fabric's deliver-then-refuse.
    *Recommendation:* accept. On a byte stream, an over-cap length cannot
    be skipped without reading attacker-sized data. T022's ingest
    `FrameTooLarge` stays as defence in depth.
15. **Net refuses an unknown hello wire version itself** (`VersionRefused`)
    before the host sees it.
    *Recommendation:* approve (format check). The host still decides
    between 1 and 2.
16. **`max_connections` 16, pending included** (2 × the 8-peer proof
    population), with v1 timeouts of 5 s hello, 5 s decision, 30 s idle
    and 10 s keep-alive.
    *Recommendation:* approve as v1, tightening-only.
