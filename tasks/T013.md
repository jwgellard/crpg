## Interface

Process interface only: no public Rust API or library facade for the binary.
The new command set is exactly:

```text
crpgc new <type> --slug <s> --id <id> [--entry-id <id>]
crpgc schema <type>
crpgc explain <id> [--root <campaign-root>]
crpgc fmt [<campaign-root>] [--check]
crpgc lock [<campaign-root>] --catalog <catalog-path>
crpgc run --ticks N --hash-every M [--seed S]
```

`explain`, `fmt` and `lock` default their root to `.`. No ancestor search,
environment override, implicit stdin or repository-root lookup. Relative
paths, including the catalog, are relative to the process working directory.
Existing `replay`, `validate` and `migrate` argument/stream/exit contracts stay
exactly as documented in their tasks.

### Parser decision

Retain and organize the hand-rolled `std::env::args_os` parser into private
per-command parsers. A parser library would be useful at this command count,
but no clap or other new dependency is authorized, and adopting one would
also risk changing established error bytes and non-Unicode handling. The
bounded grammar and exhaustive parser/process tests justify this decision;
the draft is not dependency approval.

For new commands, each named option occurs at most once and may appear before
or after positionals. Values use separate tokens, not `--key=value`. Reject
unknown flags, duplicate options, missing values, extra positionals, `--`,
short flags, and unlisted `--help`/`--version` forms with exit 2. Paths starting
with `-` must be spelled with a relative prefix such as `./`. Text arguments
(command/type/slug/id/numbers) must be Unicode; path arguments remain `OsString`
until I/O validation. A supplied non-Unicode path is exit 1, not exit 2.
Parsing completes before any filesystem access or output.

### Argument/output/exit matrix

All success output is UTF-8 with LF, never CRLF or a BOM. `0` means successful
operation, `1` means domain/I/O failure or a failed check, and `2` means usage.
The following streams describe completed writes; a stream failure can leave
a prefix and must return 1 without panic.

| Command | Accepted arguments | Exit 0 / stdout / stderr | Exit 1 / stdout / stderr | Exit 2 |
|---|---|---|---|---|
| `new` | Type is `creature`, `item`, `dialogue`, or `quest`; required slug and id; entry-id required only for dialogue/quest and forbidden otherwise | One canonical document / empty stderr | Serialization failure: empty stdout / one error line | Bad grammar, unsupported type, malformed id, equal object/entry ids, or invalid slug |
| `schema` | Exactly one current schema stem, listed below | Exact data-generated schema bytes / empty stderr | Generation failure: empty stdout / one data error line | Bad grammar or unknown stem |
| `explain` | Exactly one id; optional root | Exact `Some(bytes)` report / empty stderr | Collection/load/query error or `None`: empty stdout / one error line | Bad grammar or malformed id text |
| `fmt` | Zero or one root; optional `--check` | Silent canonical save or clean check: both streams empty | Dirty check or collection/load/serialization/rewrite failure: empty stdout / prescribed stderr | Bad grammar |
| `lock` | Zero or one root; exactly one catalog path | Silent creation/replacement/no-op of `campaign.lock`: both streams empty | Input/resolution/serialization/save failure: empty stdout / one error line | Bad grammar; omitted catalog argument |
| `run` | Required N and M; optional S defaults to 0 | Sampled hash lines / empty stderr | Stream failure: exit 1, no panic | Invalid grammar/numeric range |
| Existing commands | Their landed grammars | Their landed contracts | Their landed contracts | Their landed contracts |

Usage for a recognized new command is exactly
`crpgc: usage: <syntax>\n`, where `<syntax>` is its complete line in the
interface block above. This intentionally uses one message for all its usage
errors and never echoes arbitrary input. Existing top-level unknown/missing
command handling is retained, extending any command inventory as necessary.

Schema stems are `campaign`, `world`, `area`, `creature`, `item`, `dialogue`,
`quest`, `faction`, `graph`, `placements`, `triggers`, `locale`, `variables`,
`campaign-lock`, `assets-lock`, `placement`, and `action-signature`. They map
to `<stem>.schema.json` in `generated_schemas()`. The last two are embedded
schema roots, not new standalone document or scaffold types. No version
selector, schema patching, custom schema or disk-generation mode.

## Behaviour

### Shared ownership and errors

Use the existing read-only collector for whole-campaign operations, including
sorted depth-first pre-order, symlink rejection at root/entries, logical `/`
paths, non-Unicode handling, ignored content and `campaign_document_path` as
the sole classifier. Infer the engine-version type from the existing data
call when parsing `env!("CARGO_PKG_VERSION")`; no semver dependency.

Data errors pass through `diagnostic_for_data_error` and unchanged
`Diagnostic::Display` lines on stderr. Reuse T011b/T012b's portable CLI I/O
diagnostics: `Error`/`Io`, empty pointer, no fix and
`cannot <op> <logical>: <kind>`. No raw OS text, absolute paths, native
separators or debug dumps. Named extra inputs use the stable logical label
`<catalog>`; campaign files use their logical paths. Internal engine-version
failure is `crpgc <command>: internal engine version failure\n`, exit 1.
An unwritable stream returns 1 without recursively reporting to broken stderr.

### `new`: deliberately bounded authoring templates

This Stage-2 draft chooses explicit caller-supplied identities. `--id` is
required rather than manufacturing a fixed, slug-derived, time-only or
pseudo-random identity; dialogue/quest also require a distinct `--entry-id`.
The caller supplies fresh identities and is responsible for campaign-wide
uniqueness. This adds explicit operands to §24's abbreviated `new` spelling;
automatic ULID generation would need a separately approved entropy/dependency
decision. No clock, RNG, registry or filesystem lookup is needed here.

Slug grammar is `[a-z0-9]+(?:-[a-z0-9]+)*`, tested without a regex dependency.
Build existing public typed `Document` variants, then call `write_document`;
never handwrite envelopes, current schema tags or canonical JSON. Templates:

| Type | Fields beyond supplied identity/slug |
|---|---|
| creature | `name = creature.<slug>.name`; empty stats/tags/inventory; faction null |
| item | `name = item.<slug>.name`; empty stats/tags |
| dialogue | `name = dialogue.<slug>.name`; entry is entry-id; one node with that id and `DialogueBody::End` |
| quest | `name = quest.<slug>.name`; entry is entry-id; one terminal state with that id, name `quest.<slug>.state.done`, empty on-enter and transitions |

All notes are absent. Output is a valid minimal current typed document, not
a whole campaign: the author must supply the named locale entries and place
the file in a valid campaign. Do not claim standalone stdout passes
whole-campaign validation without that context. The command writes stdout
only; shell redirection or another caller owns saving, paths and overwrite
policy. Repeated calls with identical operands produce identical bytes.

### `schema`: data-generated bytes

Call `crpg_data::generated_schemas`, select the requested filename, and write
the returned bytes unchanged. It works outside the repository without a
runtime `schemas/` directory. Do not generate or rewrite checked-in schemas
during build, tests or verification; compare them read-only.

### `explain`: exact landed T013a consumer

Use the root-re-exported signature exactly:

```rust
pub fn explain_object(
    campaign: &crpg_data::LoadedCampaign,
    id: crpg_core::Ulid,
) -> Result<Option<Vec<u8>>, crpg_data::DataError>;
```

Parse id text using `str::parse::<crpg_core::Ulid>()`, without trimming,
padding, a CLI alphabet or a JSON detour. Core's case-insensitivity and
`I`/`L`/`O` aliases apply; wrong length, invalid characters, overflow and
non-Unicode text are usage exit 2. The same rule applies to `new` ids. An
all-zero id is syntactically valid; do not invent a NIL prohibition.

Flow: parse all args/id -> collect -> `load_campaign(files, package engine
version)` once -> `explain_object(&campaign, id)` once -> emit bytes. Parsing
failure wins before I/O; for a valid id, structural failure wins over absence.
`Some(bytes)` goes directly to stdout, including its one final LF. Do not
parse, reserialize, sort or decorate the report. `None` returns 1 with exactly
`crpgc explain: object not found: <canonical-uppercase-id>\n` on stderr and
empty stdout; it is neither successful `null` nor a new data diagnostic code.
`Err` uses the data diagnostic conversion.

Do not call semantic validation as a prerequisite. Structurally acceptable
campaigns with dangling/wrong-kind references remain introspectable. Every
object kind, including nested nodes, is selected by data; CLI owns no kind
table, reference walker, inventory derived from diagnostics, JSON subtree
extraction, ULID string scanning, or index-based replacement for this call.
Read-only, including migration-aware loading of historical documents.

### `fmt`: canonical save and read-only check

Reuse migrate's collect -> load -> serialize -> key-set check -> byte-diff
plan. Default mode explicitly saves all differing recognized files using
the T012b writer and its exact preflight/no-op/recheck/error/partial-write
contract. It may persist in-memory migrations, just as `migrate` does; it
does not introduce a second canonicalizer or version decision. Preserve
authored arrays, notes and ignored files through the data writer.

`--check` performs the same preflight without opening files for writing.
On differences, exit 1 and print `crpgc fmt: noncanonical: <logical>\n` for
each differing file in lexical SourcePath order. Otherwise silent exit 0.
Failure before a complete plan emits only that error, not partial dirty
lists. Key-set mismatch is `crpgc fmt: internal document set failure\n`.
Semantic findings do not block formatting; no repairs or lock regeneration.

### `lock`: explicit flat-catalog adapter

Read `campaign.json`, `assets/assets.lock`, and the supplied catalog, in
that order, without following observed symlinks in paths/ancestors. Require
regular files and Unicode path components; reuse the CLI I/O checks. Use
`read_document` and require `Document::Campaign`; use `read_assets_lock` for
assets. Wrong campaign document kind is exit 1 with exactly
`crpgc lock: expected campaign document\n`. The catalog is a JSON array of
existing `PackageCandidate` wire objects (`kind`, `package`, `version`,
`checksum`), with no wrapper/schema tag or new persisted campaign family.
Use existing `serde_json::from_slice::<Vec<crpg_data::PackageCandidate>>`
directly, preserving the existing candidate type's strict field and value
decoding (including duplicate/unknown struct fields). Do not first decode
through `Value`, which could discard duplicate keys. Data's strict generic
JSON parser is private and is not a callable CLI API. Catalog syntax or typed
decoding errors use exactly
`crpgc lock: invalid catalog\n`, exit 1, without serde/OS prose.

Call `make_campaign_lock(&campaign.requires, &candidates, &assets)`, then
`write_campaign_lock(&lock)`. `make_campaign_lock` already delegates to
`resolve_packages` and `assets_lock_digest`: do not separately reproduce or
preempt their conflict order, semver selection, checksums, sorting or hash
authority. Checksums are supplied catalog data, not verified downloads.
Do not call `load_campaign` first: absent or stale `campaign.lock` is exactly
what this explicit operation must support. This bounded lock operation is
not whole-campaign validation or an engine-compatibility gate.

Complete all input/resolve/serialize work before touching the output. Never
read source assets, rewrite assets.lock, migrate campaign.json on disk, query
a registry or repair references. Existing campaign.lock is replaceable even
if malformed; compare its raw bytes, no-op if identical. The new lock's note
is the data constructor's `None`; regeneration intentionally replaces any old
annotation, not a CLI merge policy.

For an existing regular output, reuse T012b's original-byte/recheck/truncate/
write_all/sync_all discipline. For a missing output, recheck ancestors and
use `create_new`, then write_all/sync_all; a concurrently appearing output is
`source_changed`. Never create directories, follow an observed symlink or
replace a nonregular output. Save failures use existing portable I/O kinds;
use `check`, `open`, `write`, `sync` operations on `campaign.lock`. Failure
may leave a partial replaced/new lock; no rollback, atomicity or secure
live-tree snapshot is promised. Concurrent changes after checks remain
unspecified, as in T012b. Test creation and replacement separately.

### `run`: bounded harness, not campaign execution

N and M are ASCII decimal digits only, with `0 <= N <= 1000000` and
`1 <= M <= 1000000`. S is decimal `u64`, default 0. Reject signs, whitespace,
hex, separators and overflow as usage 2 before running. These are CLI resource
limits, not changes to the harness. Leading zeroes are accepted.

Call `crpg_testkit::run_hash_sequence(seed, ticks, Box::new(|_| {}))` once.
The scenario is the empty world's no-op script; no campaign root, gameplay
intent vocabulary or server capability is implied. T008b owns World creation
and script -> tick -> hash interleaving. Never implement a CLI tick/hash loop.

Emit samples after completed ticks M, 2M, ... <= N. For completed tick k use
returned index k-1, printing `<k> <64-lowercase-hex-hash>\n`. No header,
initial-state sample or forced final partial-interval sample. N=0 or M>N
produces empty stdout and exit 0. `--hash-every` filters output only, not
harness execution. No golden file reads/writes, reblessing, replay recording,
wall-clock timing or cross-platform hash-equality promise.

## CI follow-up fix (2026-09-26): byte-pinned trial inputs need `eol=lf`

checkouts keep LF on every native. No test was weakened, no transcript or pin
was touched, and the change stays inside `crpg-cli` scope. Re-polled PR checks
after the fix.
