## Task

Add a `save` module to `crpg-server`. It persists T022 host checkpoints
through T038's `crpg-persist` save envelope and atomic file store, under a
fixed `PayloadKind` and a small binary save-identity header. It also adds the
file-backed save/load continuation suite that activates integration gate 10.

## Crate(s)

`crpg-server` (only). The library gains one module. `host`, `capture`,
`checkpoint` and the binary are not edited.

## Purpose

T022 §7 built bounded in-memory checkpoint bytes and left the filesystem,
compression and the separate compressed and decompressed caps to a
persist-owned task "plus a server adapter". T038 built that persist task: an
opaque-payload envelope and an atomic-replace file store. T038's approval
(answer 5) leaves save identity inside the caller's payload and says T039
decides it. D10 says gate 10 must match the real capability claimed. This
task is that adapter, and that claim.

## 1. Decisions this contract makes

### 1.1 The unit of save is T022's checkpoint, unchanged

The payload carries `Host::save_checkpoint()` output **verbatim** after a
small identity header (§3). `CHECKPOINT_VERSION` stays 1. `host.rs`,
`capture.rs` and `checkpoint.rs` are not edited, so `tests/host_capture.rs`
runs unchanged and remains the compatibility evidence for T022. Loading
always goes through T022's `load_checkpoint`, so every T022 validation rule,
the pre-parse cap and the fresh-session rule apply unchanged.

### 1.2 Save identity (T038 answer 5; spec §8)

Spec §8 names engine version, campaign id and version, and a schema version.
T039 records:

| Spec item | Recorded as | Where | On load |
|---|---|---|---|
| campaign id | `crpg_core::Ulid` (16 bytes) | header | must equal the caller's expected id, else `CampaignMismatch` |
| campaign version | version text, 1–64 bytes | header | must equal the expected text byte for byte, else `CampaignVersionMismatch` |
| engine version | `ENGINE_VERSION` text (this crate's package version) | header | **recorded and returned, not enforced** |
| schema version | three format versions: envelope `SAVE_FORMAT_VERSION` (1), `HOST_SAVE_VERSION` (1), `CHECKPOINT_VERSION` (1) | envelope, header, checkpoint | each must match, else the owning `UnsupportedVersion` |

Why this set, and why it is minimal:

- **Campaign id and version are trusted caller facts.** `crpg-server` has no
  `crpg-data` edge (D20), and `HistoryWorld` carries no campaign identity.
  The embedding that built the authority from campaign data knows
  `Campaign.id` (a `Ulid`) and `Campaign.version` (semver). It passes them in
  as `SaveIdentity`, the same way it passes `HostConfig`. The server
  validates only the text's length and alphabet (§3), which needs no semver
  dependency.
- **Engine version is diagnostic.** Compatibility is decided by the three
  format versions. Refusing on engine version would orphan every save at
  every patch release. Continuation *equivalence* is claimed only for the
  same build (ADR-0012), so a cross-build load is allowed but carries no
  equivalence claim (§5). `ENGINE_VERSION` is `env!("CARGO_PKG_VERSION")`
  of `crpg-server`. The workspace has no shared version yet (§12 Q3).
- **No per-family data schema versions.** Campaign documents are versioned
  per family (`crpg_data::schema_versions`, 20 entries), and they are
  migrated when campaign data is loaded (T012), not when a world is
  restored. A published campaign version fixes its documents, so an exact
  campaign-version match already pins them. Recording the 20 versions would
  duplicate that, and would need a `crpg-data` edge.
- **Not recorded:** incarnation (already in the checkpoint; the new one is a
  caller fact, §12 Q9), wall-clock time, slot names, player names, play
  time. Each of those is product or UI metadata (out of scope).

### 1.3 A binary header in front of the checkpoint

The identity goes in a small, fixed-order binary header (§3), not in the
checkpoint JSON and not in a JSON wrapper:

- Putting it in the checkpoint would be a T022 format change
  (`CHECKPOINT_VERSION` 2) and would reopen T022's acceptance.
- A JSON wrapper around a 16 MiB JSON document would parse the checkpoint
  twice, or need serde_json's `raw_value` feature, which no workspace crate
  enables (a feature expansion needs its own approval).
- A binary header is at most 150 bytes, has exact first-failure-wins
  precedence, and lets load refuse a wrong campaign **before** parsing the
  checkpoint.

**Cost:** `crpg-persist::MAX_PAYLOAD_BYTES` (16,777,216) equals T022's
`MAX_CHECKPOINT_BYTES`. A file save therefore accepts a checkpoint of at most
`MAX_PAYLOAD_BYTES − header_len` bytes, where `header_len` is 22 plus the two
version-text lengths. That is at least 16,777,066 bytes. Larger checkpoints
are refused with `TooLarge` before the filesystem is touched. T022 measured
its worst shapes far below the cap, and the gate-10 schedule's checkpoint is
8,717 bytes (§7). The narrowing is documented, not hidden (§12 Q5).

### 1.4 Payload kind

`HOST_SAVE_KIND` is `PayloadKind` `HOSTCKPT` (ASCII, inside the T038
alphabet). A file written under any other kind is refused by the envelope as
`KindMismatch` before the header is read.

### 1.5 What gate 10 claims

Gate 10 (spec §15.4 step 10) activates as **file-backed host save/load
continuation equivalence**, on each native target against itself:

> A host driven through the public `ingest → pump` boundary is saved to disk
> with `save_host_file`, destroyed, and reloaded with `load_host_file` into a
> fresh host under a strictly greater incarnation. After the same operator
> rebinding, the same subsequent logical commands give the same authority
> (`authority_hash`, the full-wrapper `history_hash`), capture journal and
> watermarks, and decoded delivery, apart from session identity, as an
> uninterrupted run in the same process.

It does **not** claim: crash durability or exactly-once (D10, T038 Q9);
Windows directory-entry durability (T038 Q9); cross-target byte equality or
cross-target load (ADR-0012; §12 Q12); or the spec §8 breadth "every fixture
campaign". `crpg-server` cannot load campaign data, so that breadth moves to
the first task that builds a host from campaign data (§12 Q6).

### `crates/crpg-server/src/save.rs`

```rust
use std::path::Path;

use crpg_core::Ulid;
use crpg_persist::{FileError, PayloadKind};

use crate::checkpoint::CheckpointError;
use crate::host::Host;

/// Envelope payload tag for a host save: ASCII `HOSTCKPT`.
pub const HOST_SAVE_KIND: PayloadKind = match PayloadKind::new(*b"HOSTCKPT") {
    Some(kind) => kind,
    None => panic!("HOSTCKPT is inside the PayloadKind alphabet"),
};
/// The only host save payload version this build writes or reads.
pub const HOST_SAVE_VERSION: u32 = 1;
/// Engine version recorded in every save: this crate's package version.
pub const ENGINE_VERSION: &str = env!("CARGO_PKG_VERSION");
/// Upper bound, in bytes, on each version text (campaign and engine).
pub const MAX_VERSION_TEXT_BYTES: usize = 64;
/// Header bytes besides the two version texts: version, campaign id, two length bytes.
pub const HOST_SAVE_FIXED_BYTES: usize = 22;
/// Largest possible header (150 bytes).
pub const MAX_HOST_SAVE_HEADER_BYTES: usize = HOST_SAVE_FIXED_BYTES + 2 * MAX_VERSION_TEXT_BYTES;

/// Trusted campaign identity supplied by the embedding (spec §8).
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct SaveIdentity {
    /// The campaign's stable authored id (`Campaign.id`).
    pub campaign_id: Ulid,
    /// The campaign's published version text, 1..=64 bytes of `0-9 A-Z a-z . + -`.
    pub campaign_version: String,
}

/// A host restored from a save, plus the engine version that wrote it.
#[derive(Debug)]
pub struct LoadedSave {
    /// The restored host: fresh sessions under the new incarnation (T022 §7).
    pub host: Host,
    /// The saving build's `ENGINE_VERSION`. Recorded, never enforced.
    pub engine_version: String,
}

/// Builds a host save payload: the §3 header, then `checkpoint` verbatim.
/// Pure; never inspects `checkpoint`.
pub fn encode_host_save(identity: &SaveIdentity, checkpoint: &[u8]) -> Result<Vec<u8>, SaveError>;

/// Validates a host save payload (§4.2) and loads its checkpoint with
/// `checkpoint::load_checkpoint(_, new_incarnation, now_ms)`.
pub fn decode_host_save(
    payload: &[u8],
    expected: &SaveIdentity,
    new_incarnation: u64,
    now_ms: u64,
) -> Result<LoadedSave, SaveError>;

/// Saves a quiescent host to `path` through `crpg_persist::save_file` (§4.3).
pub fn save_host_file(path: &Path, host: &Host, identity: &SaveIdentity) -> Result<(), SaveError>;

/// Loads a host from `path` through `crpg_persist::load_file` (§4.4).
pub fn load_host_file(
    path: &Path,
    expected: &SaveIdentity,
    new_incarnation: u64,
    now_ms: u64,
) -> Result<LoadedSave, SaveError>;

/// Every save-adapter failure. First failure wins (§4).
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum SaveError {
    /// A `SaveIdentity` campaign version is empty, longer than
    /// `MAX_VERSION_TEXT_BYTES`, or outside the version alphabet.
    InvalidIdentity,
    /// The payload would exceed (encode) or exceeds (decode) `crpg_persist::MAX_PAYLOAD_BYTES`.
    TooLarge {
        /// Header plus checkpoint length (encode), or the payload length (decode).
        len: usize,
    },
    /// The header is truncated, or a length or text field is out of range.
    Malformed,
    /// Payload offsets 0..4 hold a version other than `HOST_SAVE_VERSION`.
    UnsupportedVersion {
        /// The rejected version.
        version: u32,
    },
    /// The saved campaign id differs from the expected one.
    CampaignMismatch,
    /// The saved campaign version text differs from the expected one.
    CampaignVersionMismatch,
    /// `Host::save_checkpoint` or `checkpoint::load_checkpoint` failed.
    Checkpoint(CheckpointError),
    /// `crpg_persist::save_file` or `load_file` failed.
    Persist(FileError),
}

impl From<CheckpointError> for SaveError { /* SaveError::Checkpoint(e) */ }
impl From<FileError> for SaveError { /* SaveError::Persist(e) */ }
```

`SaveError` implements `std::fmt::Display` by hand and `std::error::Error`
with **no source**, following the crate's convention
(`<VariantName> at host/<location>`, no input bytes):

| Variant | Display |
|---|---|
| `InvalidIdentity` | `InvalidIdentity at host/save` |
| `TooLarge { .. }` | `TooLarge at host/save` |
| `Malformed` | `Malformed at host/save` |
| `UnsupportedVersion { .. }` | `UnsupportedVersion at host/save` |
| `CampaignMismatch` | `CampaignMismatch at host/save` |
| `CampaignVersionMismatch` | `CampaignVersionMismatch at host/save` |
| `Checkpoint(e)` | `e`'s Display unchanged (for example `EpochReused at host/checkpoint`) |
| `Persist(e)` | `e`'s Display unchanged (for example `save checksum mismatch`) |

Private items (pinned, not public):

- `const fn valid_version_text(bytes: &[u8]) -> bool`: true iff
  `1 <= len <= MAX_VERSION_TEXT_BYTES` and every byte is in `b'0'..=b'9'`,
  `b'A'..=b'Z'`, `b'a'..=b'z'`, `b'.'`, `b'+'` or `b'-'` (the semver
  character set).
- `const _: () = assert!(valid_version_text(ENGINE_VERSION.as_bytes()));`
  so an invalid package version fails the build instead of producing saves
  that this build refuses.

No other public item. In particular: no trait, no header struct, no
inspect-only reader, no slot or directory API, no change to any existing
public item.

## 3. Host save payload v1 layout (normative)

The payload is what `crpg-persist` wraps under `HOST_SAVE_KIND`. Integers are
fixed width. There is no padding.

| Offset | Size | Field | Encoding | Rule |
|---|---|---|---|---|
| 0 | 4 | `save_version` | u32 LE | `01 00 00 00` |
| 4 | 16 | `campaign_id` | `Ulid::to_u128().to_be_bytes()` | any value |
| 20 | 1 | `cv_len` | u8 | `1..=64` |
| 21 | `cv_len` | `campaign_version` | ASCII | version alphabet |
| 21 + `cv_len` | 1 | `ev_len` | u8 | `1..=64` |
| 22 + `cv_len` | `ev_len` | `engine_version` | ASCII | version alphabet |
| 22 + `cv_len` + `ev_len` | rest | `checkpoint` | T022 compact JSON, verbatim | validated only by `load_checkpoint` |

`header_len = HOST_SAVE_FIXED_BYTES + cv_len + ev_len` (at most
`MAX_HOST_SAVE_HEADER_BYTES`). The campaign id is big-endian because that is
the ULID canonical binary form: its byte order sorts like its text. Every
other integer is little-endian, as in T038.

**Frozen prefix.** Offsets 0..4 (`save_version`) keep this meaning in every
future host save version, so any build can refuse a foreign version before
reading anything else.

## 4. Behaviour

### 4.1 `encode_host_save` (exact steps)

1. If `!valid_version_text(identity.campaign_version.as_bytes())`, return
   `InvalidIdentity`.
2. Compute `header_len`. If
   `checkpoint.len() > crpg_persist::MAX_PAYLOAD_BYTES - header_len`, return
   `TooLarge { len: header_len.saturating_add(checkpoint.len()) }`.
3. Allocate once with capacity exactly `header_len + checkpoint.len()`.
   Write the §3 fields in order and append `checkpoint`. Never read or
   validate `checkpoint`.

The output is a pure function of `(identity, checkpoint)` and the build.

### 4.2 `decode_host_save` (exact precedence; first failure wins)

1. If `!valid_version_text(expected.campaign_version.as_bytes())`, return
   `InvalidIdentity`. Nothing in `payload` is read.
2. If `payload.len() > crpg_persist::MAX_PAYLOAD_BYTES`, return
   `TooLarge { len: payload.len() }`.
3. If `payload.len() < 4`, return `Malformed`.
4. If `u32::from_le_bytes(payload[0..4]) != HOST_SAVE_VERSION`, return
   `UnsupportedVersion { version }`. This precedes every other header check.
5. If `payload.len() < 21`, return `Malformed`.
6. If `cv_len` is 0 or greater than `MAX_VERSION_TEXT_BYTES`, return `Malformed`.
7. If `payload.len() < 22 + cv_len`, return `Malformed`.
8. If any `campaign_version` byte is outside the alphabet, return `Malformed`.
9. If `ev_len` is 0 or greater than `MAX_VERSION_TEXT_BYTES`, return `Malformed`.
10. If `payload.len() < 22 + cv_len + ev_len`, return `Malformed`.
11. If any `engine_version` byte is outside the alphabet, return `Malformed`.
12. If `campaign_id != expected.campaign_id`, return `CampaignMismatch`.
13. If the `campaign_version` bytes differ from
    `expected.campaign_version.as_bytes()`, return `CampaignVersionMismatch`.
14. Call `checkpoint::load_checkpoint(&payload[header_len..], new_incarnation, now_ms)`.
    On error return `Checkpoint(e)`. An empty remainder reaches T022 and is
    `Checkpoint(Malformed)`; there is no special case.
15. Return `LoadedSave { host, engine_version }`. The engine text is copied
    from the validated ASCII bytes. It is never compared with `ENGINE_VERSION`.

The whole header is structurally validated (steps 3–11) before identity
(12–13), and identity before any JSON is parsed (14). A wrong-campaign save
is refused without parsing up to 16 MiB of checkpoint.

### 4.3 `save_host_file` (exact steps)

1. If `!valid_version_text(identity.campaign_version.as_bytes())`, return
   `InvalidIdentity`. The host is not read and the filesystem is not touched.
2. `host.save_checkpoint()`. On error return `Checkpoint(e)`
   (`PendingIngress`, `TooLarge` or `Malformed`, as T022 defines them).
3. `encode_host_save(identity, &checkpoint)`. On error return it (`TooLarge`).
4. `crpg_persist::save_file(path, HOST_SAVE_KIND, &payload)`. On error return
   `Persist(e)`.

`host` is borrowed immutably, so it is unchanged on every path. Steps 1–3
touch no file. The adapter never retries, sleeps, picks another path, or
removes a file itself.

### 4.4 `load_host_file` (exact steps)

1. If `!valid_version_text(expected.campaign_version.as_bytes())`, return
   `InvalidIdentity`. The path is not opened.
2. `crpg_persist::load_file(path, HOST_SAVE_KIND)`. On error return
   `Persist(e)`. This reads at most `MAX_ENVELOPE_BYTES + 1` bytes and
   checks the envelope's kind, version, lengths, digest and both caps.
3. Return `decode_host_save(&payload, expected, new_incarnation, now_ms)`.

Load never writes, renames or deletes. It ignores any `.crpg-tmp` file.

### 4.5 Behaviour on every error

| Error | Raised by | State after |
|---|---|---|
| `InvalidIdentity` | every entry point, step 1 | nothing read, written or created; host unchanged |
| `Checkpoint(PendingIngress \| TooLarge \| Malformed)` | `save_host_file` step 2 | no file touched; host unchanged (save at quiescence, T022 §7) |
| `TooLarge` (encode) | `encode_host_save` step 2, `save_host_file` step 3 | no output; no file touched |
| `TooLarge` (decode) | `decode_host_save` step 2 (unreachable through `load_host_file`, whose input cap is smaller) | no host |
| `Malformed`, `UnsupportedVersion`, `CampaignMismatch`, `CampaignVersionMismatch` | `decode_host_save` steps 3–13 | no host; checkpoint never parsed; file untouched |
| `Checkpoint(e)` on load (`Malformed`, `UnsupportedVersion`, `AuthorityInvalid`, `EpochReused`, `TooLarge`) | `decode_host_save` step 14 | no host (T022 builds a temporary host and returns it only on success); file untouched |
| `Persist(InvalidPath)` | `save_file` step 1 | nothing created |
| `Persist(Envelope(_))` on save | `save_file` step 2 (`PayloadTooLarge` is pre-empted by §4.3 step 3; `Compressor` is unreachable by test) | no file touched |
| `Persist(Io { CreateTemp })` | `save_file` | destination untouched; no temp created |
| `Persist(Io { WriteTemp \| SyncTemp \| Rename })` | `save_file` | destination untouched (previous save intact); temp removed best effort |
| `Persist(Io { SyncDir })` (Unix only) | `save_file` | **the new save is already in place**; its directory entry's durability is unconfirmed. The caller may treat the save as written-but-unconfirmed and save again |
| `Persist(Io { Open \| Read })`, `Persist(Envelope(_))` on load | `load_file` | no host; nothing written or removed |

## 5. Determinism and the gate-10 claim

- **Per build, per target (ADR-0012).** For a fixed build, a save file's
  bytes are a pure function of `(checkpoint, identity)`: §4.1 is pure, and
  T038 §4.1 is pure for a fixed build. The suite asserts this within one
  process. It never compares a save's bytes, digest or hash with a literal
  produced on another target, and it adds **no golden**. So there is no
  H-golden gate and no target-scoped baseline.
- **Equivalence is in-process.** Each gate-10 case runs the uninterrupted
  and the interrupted schedule in the same test process, so both sides come
  from the same build and target by construction. The only literal byte
  vector (§7 `payload_layout_matches_hand_built_bytes`) is the uncompressed
  header layout, which is target-independent by construction. It is a format
  vector, like T038's.
- **No new time, randomness or OS branch.** `save.rs` and `tests/host_save.rs`
  contain no `HashMap`/`HashSet`, `SystemTime`/`Instant`/`std::time`,
  `std::thread`, `rand::`/`thread_rng`, `std::env::var`, `f32`, `f64`,
  `unsafe`, or `cfg(unix|windows|target_os)`. `env!` is compile-time and
  permitted (`CARGO_PKG_VERSION`, `CARGO_TARGET_TMPDIR`). The only OS branch
  on the save path is T038's own `#[cfg(unix)]` directory sync, inside
  `crpg-persist`. `determinism.py` does not scan this crate, so the
  Definition of done carries an explicit grep.
- **Gate placement.** Gate 10 runs inside the existing
  `cargo test --workspace --locked` job of both native CI legs (Windows/MSVC
  and Linux/GNU), as gate 9 does. No workflow file changes. A failure on
  either target fails that target's gate. There is no skip and no
  missing-baseline path.

## 7. Test

### Harness (`tests/host_save.rs`)

The module doc states the oracles. They are independent of `save.rs`:

- **Uninterrupted run**, same process: the reference for every equivalence
  assertion.
- **Mirror authority**: a test-owned `HistoryWorld` loaded from the same
  fixture, driven through public `perform_action`/`acknowledge`/`tick` with
  every command the host is expected to accept, on the host's schedule.
  `history_hash(&mirror)` must equal `Host::authority_hash`.
- **Hand-built header bytes** for format and rejection cases, written to disk
  with `crpg_persist::save_file`, never with `save.rs`.

Shared harness facts:

- Fixture: `include_str!("fixtures/three_combatants.json")`. Its start
  envelopes are acknowledged before `Host::from_history`, the same pre-wrap
  choreography as `host_capture.rs`. Entities A/B/C are indices 0/1/2
  (generation 1). Replica ids are 1/2/3. `whiff` is
  `Ulid::from_u128(605)`.
- One peer, bound with control of A, B and C and full disclosure (the
  `host_capture.rs` `full_grants()` shape: all three entities fully
  disclosed, abilities 603/604/605, encounter 601, all three booleans true).
- Intent bytes come from `crpg_net::codec::encode_intent` (V1) or
  `crpg_net::codec_v2::encode_intent` (V2). Wire encoding is not under test
  here; T018/T021/T022 prove it.
- `now_ms` starts at 0 and advances 100 per ingest.
- `IDENTITY` is `SaveIdentity { campaign_id: Ulid::from_u128(700), campaign_version: "1.0.0" }`.
- A `both_versions!` macro local to this file runs a case as
  `<case>::v1` and `<case>::v2`.

**The schedule.** Step `k` (0-based) does exactly this, with
`active = 1 + (host.last_capture() % 3)` (every accepted command ends the
turn, so the active replica id follows from the accepted count) and
`next = active % 3 + 1`:

1. If `k % 10 == 9`: ingest and pump `EndTurn` for actor `next` → exactly one
   result, `Rejected(IllegalAction)` (not that actor's turn).
2. Else if `k % 2 == 0`: `DeclareAction { ability: whiff, target: next }` for
   actor `active` → `Applied`.
3. Else: `EndTurn` for actor `active` → `Applied`.
4. `host.tick()` (one trusted tick).
5. `take_delivery`, decode every frame with the selected version's
   `decode_delta`, and `acknowledge_delivery` through the last `event_seq`.
6. If `k % 100 == 99`: `acknowledge_captures(last_capture() − 8)`.

Session `seq` starts at 1 on each binding and increments per ingest. The
mirror applies the same `CombatAction` and `acknowledge(last_sequence())` for
each accepted command, and `tick()` at step 4. Over steps 0..1000 there are
900 accepted commands, 100 rejections and 1000 ticks. Nobody dies, because
`whiff` always fails for 0 damage.

**Measured feasibility.** A discarded 2026-10-04 scratch prototype on
Linux/GNU (not committed) ran this exact schedule with an in-memory save at
step 500, a `crpg_persist` file round trip, a reload under incarnation 2 and
per-step hash comparison, under V1 and V2. Both passed in 0.57 s total
(debug test profile). The checkpoint at step 500 was 8,717 bytes and the save
file about 1.4 KB. `server_tick` reached 1000 and `capture_acknowledged` 892.
No test needs `#[ignore]`.

**Restart procedure** (the save point is after step `s − 1`): the
interrupted run calls `save_host_file(path, &host, &IDENTITY)`, records
`authority_hash`, `last_capture`, `capture_acknowledged` and
`read_captures(capture_acknowledged, 256)`, then **drops the `Host` value**
(no clone or borrow survives; `Host` is not `Clone`). Then it calls
`load_host_file(path, &IDENTITY, new_incarnation, now)` and binds a fresh
peer with identical operator facts. The uninterrupted run calls
`unbind_peer` and binds a fresh peer at the same point, so both continue on
the D10 new-session path with `seq` from 1.

### Gate 10 cases (each `::v1` and `::v2`)

- `file_save_load_equivalence`: steps 0..500 on both runs, restart at
  `s = 500` with incarnation 2, then steps 500..1000.
  - Immediately after load: `engine_version == ENGINE_VERSION`;
    `incarnation() == 2`; `protocol()` unchanged; `authority_hash`,
    `last_capture`, `capture_acknowledged` and the retained records (epochs
    included, because they are history) equal the recorded pre-save values;
    `executions() == 0`; the fresh binding's epoch is incarnation 2,
    handle 1.
  - After **every** suffix step: both runs have equal `authority_hash`,
    `last_capture` and `capture_acknowledged`. That step's decoded frames
    are equal in count, `event_seq` and `server_tick`, and their ops are
    equal once every receipt epoch is replaced by zeros.
  - At the end: `authority_hash` is equal across both runs and equals
    `history_hash(&mirror)`; `server_tick() == 1000`;
    `last_capture() == 900`; `capture_acknowledged() == 892`; retained
    records are equal with every `epoch` and view `epoch` zeroed;
    `executions()` is 900 (uninterrupted) and 450 (interrupted).
- `repeated_restarts_match_uninterrupted_run`: restarts at `s = 250, 500, 750`
  with incarnations 2, 3, 4, all to the **same path** (exercising atomic
  replace). The uninterrupted run rebinds at the same points. Same per-step
  and final assertions; the interrupted `executions()` is 225 (the accepted
  commands since the last load).
- `older_save_resumes_from_its_own_point` (D10: an older checkpoint loses
  later progress, and continuation from it is exact):
  - Run steps 0..250, save to `a`; record the hash `H250`. Run 250..500, save
    to `b`; record `H500`.
  - Load `a` (incarnation 2): hash is `H250` and `last_capture() == 225`.
    Rebind and re-run steps 250..500: the hash equals `H500`.
  - **Negative control:** load `a` again (incarnation 3), rebind, and run
    steps 500..1000, skipping 250..500. The final hash **differs** from the
    uninterrupted run's final hash.
  - Positive control: load `b` (incarnation 4), rebind, and run 500..1000.
    The final hash **equals** the uninterrupted run's.

### Format, identity and refusal cases (version-independent unless noted)

- `payload_layout_matches_hand_built_bytes`:
  `encode_host_save(&SaveIdentity { campaign_id: Ulid::from_u128(0x0102030405060708090a0b0c0d0e0f10), campaign_version: "1.2.3-rc.1+b7" }, b"{}")`
  equals the hand-built bytes

  ```text
  01000000 0102030405060708090a0b0c0d0e0f10 0d 312e322e332d72632e312b6237
  <ENGINE_VERSION.len() as u8> <ENGINE_VERSION bytes> 7b7d
  ```

  (for the as-built `0.1.0`, the engine part is `05 302e312e30`). For a real
  checkpoint, `payload[header_len..]` equals `save_checkpoint()` byte for
  byte, and `decode_host_save` returns a host whose `authority_hash` equals
  the saved one.
- `engine_version_is_valid_and_recorded`: `ENGINE_VERSION == env!("CARGO_PKG_VERSION")`
  and it is valid version text. A hand-built payload with engine text
  `9.9.9-other+x` and a valid checkpoint loads, and reports that text (it is
  recorded, not enforced). A 64-byte engine text also loads.
- `file_bytes_equal_encoded_envelope`: two saves of one quiescent host to two
  paths are byte-identical. Both equal
  `crpg_persist::encode_envelope(HOST_SAVE_KIND, &encode_host_save(&IDENTITY, &checkpoint)?)`.
  File bytes 12..20 are `HOSTCKPT`. `crpg_persist::load_file` returns the
  payload. No `TEMP_SUFFIX` file remains.
- `resave_after_load_differs_only_in_incarnation` (`::v1`, `::v2`): save after
  steps 0..500, load (incarnation 2), and save to a second path. Through
  `crpg_persist::load_file`, the headers are equal, and the checkpoint parts
  are equal after replacing `"incarnation":1,` with `"incarnation":2,` once.
- `identity_validation`: campaign versions `1` and a 64-byte valid text are
  accepted by save and load. `""`, a 65-byte text, `1.0 .0`, `1/0`, `1_0`
  and `é` give `InvalidIdentity`:
  - from `encode_host_save`;
  - from `save_host_file`, after which the test directory holds no file and
    no temp file;
  - from `decode_host_save`;
  - from `load_host_file` on a **nonexistent** path. This proves step 1
    precedes `Io { Open }`.
- `payload_cap_boundaries`: with a 5-byte campaign version, a checkpoint of
  `MAX_PAYLOAD_BYTES − header_len` space bytes encodes to exactly
  `MAX_PAYLOAD_BYTES` bytes, and decoding it passes every header step and
  fails as `Checkpoint(Malformed)`. One more byte gives
  `TooLarge { len: MAX_PAYLOAD_BYTES + 1 }`. `decode_host_save` on
  `MAX_PAYLOAD_BYTES + 1` bytes gives `TooLarge { len: MAX_PAYLOAD_BYTES + 1 }`.
- `header_refusals`: each payload is hand-built, written with
  `crpg_persist::save_file(_, HOST_SAVE_KIND, _)`, loaded with
  `load_host_file`, and also given to `decode_host_save` with the same
  result. The file bytes are unchanged after every failed load.
  - Every strict prefix of a valid header (lengths 0 to `header_len − 1`) →
    `Malformed`. Exactly the header with no checkpoint →
    `Checkpoint(Malformed)`.
  - `save_version` 0, 2 and `u32::MAX` → `UnsupportedVersion { version }`.
    Version 2 followed by `cv_len = 0` is still `UnsupportedVersion`, which
    proves the version wins.
  - `cv_len` 0, 65 and 255, and `ev_len` 0 and 65 → `Malformed`. A space,
    `_` or `0x80` byte in either text → `Malformed`.
  - A wrong campaign id with a malformed engine text → `Malformed`
    (structure precedes identity).
  - Positive control: the same hand-built header with valid fields and a
    real checkpoint loads with the saved `authority_hash`.
- `identity_refusals`: on a valid save file:
  - `campaign_id` + 1 → `CampaignMismatch`;
  - version `1.0.1` → `CampaignVersionMismatch`;
  - both wrong → `CampaignMismatch`;
  - a valid header with the wrong id over a garbage checkpoint →
    `CampaignMismatch` (identity is checked before parsing).

  Positive control: the expected identity loads. The file is unchanged.
- `envelope_refusals_pass_through`:
  - kind `OTHERKND` (via `crpg_persist::save_file`) →
    `Persist(Envelope(KindMismatch))`;
  - envelope bytes 8..10 set to `02 00` →
    `Persist(Envelope(UnsupportedVersion))`;
  - one digest byte flipped → `Persist(Envelope(ChecksumMismatch))`;
  - missing file → `Persist(Io { op: Open, kind: NotFound })`;
  - a `MAX_ENVELOPE_BYTES + 1` byte file → `Persist(Envelope(InputTooLarge))`.

  Each case has a positive control, and file bytes are unchanged.
- `checkpoint_refusals_pass_through`:
  - a valid header over the checkpoint with `{"version":1,` replaced by
    `{"version":2,` → `Checkpoint(UnsupportedVersion { version: 2 })`;
  - incarnation 1 or 0 against a save from incarnation 1 →
    `Checkpoint(EpochReused)`, and 2 loads;
  - checkpoint `{}` → `Checkpoint(Malformed)`.
- `save_refusals_leave_files_untouched` (`::v1`, `::v2`): first a good save
  `B` at path `P`. Then:
  - with staged ingress (ingest without pump), `save_host_file(P)` →
    `Checkpoint(PendingIngress)`. `P` still holds `B`, no temp file exists,
    and the host snapshot (hash, executions, `last_capture`,
    `capture_acknowledged`) is unchanged. After `pump` the same save
    succeeds.
  - `InvalidIdentity` leaves the same unchanged state.
  - A destination that is a non-empty directory →
    `Persist(Io { op: Rename, .. })` (assert the op only). The directory
    remains and the temp file is gone.
  - A missing parent directory →
    `Persist(Io { op: CreateTemp, kind: NotFound })`.
  - Path `""` → `Persist(InvalidPath)`.
- `error_display_strings_are_pinned`: every own variant's Display equals §2.
  `Checkpoint(e)` and `Persist(e)` display exactly `e.to_string()`.
  `source()` is `None` for every variant. Both `From` impls wrap.

That is 20 tests: 3 gate-10 cases and 2 others under both versions (10),
plus 10 version-independent cases.

### Readings (review these)

1. **`older_save_resumes_from_its_own_point`.** One uninterrupted run saves
   `a` before step 250 and `b` before step 500, recording `H250`/`H500` at
   those points, and continues on its first session to step 1000 for the
   uninterrupted final hash (cross-checked against the mirror). The contract
   does not say whether that run rebinds; `authority_hash` does not depend
   on sessions, so it does not.
2. **`save_refusals_leave_files_untouched` order.** `InvalidIdentity` is
   checked while the ingress is still staged, before the pump. So it also
   shows that §4.3 step 1 precedes step 2. The pump and the successful save
   follow.
3. **Version-independent cases** use one quiescent V2 host after 20
   schedule steps.
4. **`payload_layout_matches_hand_built_bytes`** builds the engine part as
   `<ENGINE_VERSION.len() as u8> <ENGINE_VERSION bytes>`, as §7 writes it.
   For the as-built `0.1.0` that is `05 302e312e30`; that literal is not
   asserted separately, so a version bump does not break the vector.
5. **`envelope_refusals_pass_through` controls**: each refused file has a
   sibling control file holding the untampered envelope, which loads with
   the saved hash. The missing-file control writes the good envelope to the
   same path afterwards.
6. **Private imports beyond §2's `use` block**: `save.rs` also imports
   `crpg_persist::MAX_PAYLOAD_BYTES` and `checkpoint::load_checkpoint`. No
   public item beyond §2 exists. The module doc comment repeats the §3 table.

### Limitations (stated, not tested around)

- The §1.5 non-claims hold: no crash durability or exactly-once, no
  cross-target byte equality or cross-target load, no "every fixture
  campaign" breadth (carried to T040/T041 in the BACKLOG activation row).
- Windows directory-entry durability is not made explicit (T038 Q9);
  `Io { SyncDir }` is Unix only and means the save already landed.
- The header narrows the file-save checkpoint ceiling to
  `MAX_PAYLOAD_BYTES − header_len` (at least 16,777,066 bytes; 16,777,184
  for the suite's identity under engine `0.1.0`).
- Native Windows/MSVC verification is outstanding.
