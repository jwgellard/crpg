## Task

Build the first `crpg-edit` code: an in-memory campaign document opened from
a `crpg-data` `LoadedCampaign`, a closed `EditCommand` enum, atomic `apply`
and `apply_batch` returning a receipt with diagnostics, bounded undo/redo
stacks that restore canonical bytes exactly, validation that only calls
`crpg-data`, and a pure save plan built from the canonical writer. Prove it
with the random-command-sequence property test (spec §19.2 #15).

## Crate(s)

`crpg-edit` (only). This task opens the crate. It depends on T058a, a
separate `crpg-data`-only task ([§9](#9-prerequisite-t058a-crpg-data--blocking)).

## Purpose

D18: the headless editor command API comes before any editor UI, and an
optional CLI apply (T059) follows it. Spec §11.2 puts the document model,
undo and validation in Rust, so the GUI (T060–T068), `crpgc apply` (T059)
and AI agents all go through one implementation and cannot bypass the
invariants it enforces. The E022 ledger row "`EditCommand`, receipts,
diagnostics, undo (headless first)" names `crpg-edit` as owner, with the
data APIs (T010–T013, T029a) as prerequisites.

## 1. What `crpg-data` already provides, and what it lacks

T058 builds only on public `crpg-data` items. Checked against `2bcace4`:

| Need | As-built API | Status |
|---|---|---|
| Typed documents by logical path | `LoadedCampaign { documents: BTreeMap<SourcePath, Document>, index }`, `Document`, `SourcePath` | present |
| Load with engine check and in-memory migration | `load_campaign(files, engine_version)` | present (the caller's step, before `open`) |
| Canonical bytes per document / per campaign | `write_document`, `serialize_campaign`, `canonical_json` | present |
| Strict re-read of canonical bytes | `read_document` | present |
| Semantic diagnostics | `validate(&LoadedCampaign) -> Vec<Diagnostic>` | present |
| Structural error as a diagnostic | `diagnostic_for_data_error(&DataError) -> Diagnostic` | present |
| References for a blast-radius view | `explain_object` | present (used by views, not by T058) |
| **Rebuild the index from edited documents, with the writer's structural checks** | `structural_check` and `build_index` are `pub(crate)`; the only public index builder is `load_campaign`, which needs re-serialized bytes and a `semver::Version` | **missing** |
| **Edit one value at an RFC 6901 pointer with strict JSON and typed re-decode** | none; the strict parser `canonical::parse` is `pub(crate)` | **missing** |

The two missing items are the prerequisite T058a (§9). T058 does not work
around them: no JSON pointer code, no second JSON parser, no second index
builder and no `serde_json`/`semver` edge in `crpg-edit`.

## 2. Identity and addressing rules

These restate spec §4.3 and `crpg-data` as they apply to editing.

- **Objects are addressed by ULID.** An object's `id` is supplied by the
  caller when the object is created and never changes afterwards. `crpg-edit`
  never generates an id (no clock, no entropy; T006d puts generation with the
  caller) and never re-keys one. Every edit that would change the id of an
  existing object is rejected (`IdentityChanged`, §5.3 step 7).
- **Documents are addressed by `SourcePath`.** Paths are not identity
  (spec §4.3). `RenameDocument` moves a document's bytes unchanged.
  Aggregate documents (`placements.json`, `triggers.json`, locale tables,
  `variables/campaign_state.json`) have no id and are addressed only by path.
- **Slugs are ordinary fields.** They are renamed with `SetValue` on
  `/slug`. A repeated slug is the existing semantic `duplicate_slug`
  diagnostic, not an apply failure.
- **Package ids are immutable.** `campaign.json` `/package` is protected
  (§5.2), as are `/engine` and `/requires`; package locking stays with
  `crpgc lock`.
- **Object locations come from the document's own index.** `CampaignDocument`
  derives its index with T058a's `campaign_index` after every change and
  ignores the index of the `LoadedCampaign` it is opened from (crpg-data rule:
  a caller-mutable index must not influence output).

### 3.1 `command`

```rust
/// Where a pointer edit applies.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum EditTarget {
    /// A whole document; the pointer is absolute within it.
    Document(crpg_data::SourcePath),
    /// An identified object; the pointer is relative to the object's own
    /// location (its index pointer is prefixed), and may be empty.
    Object(crpg_core::Ulid),
}

/// The closed set of editor mutations. Every mutation goes through one of these.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum EditCommand {
    /// Add a complete new document at an unused path.
    CreateDocument { path: crpg_data::SourcePath, document: crpg_data::Document },
    /// Remove the document at `path`.
    DeleteDocument { path: crpg_data::SourcePath },
    /// Move a document's bytes unchanged from `from` to the unused path `to`.
    RenameDocument { from: crpg_data::SourcePath, to: crpg_data::SourcePath },
    /// Replace the value at a pointer, or add an absent object member.
    /// `value` is UTF-8 JSON text, parsed by crpg-data's strict parser.
    SetValue { target: EditTarget, pointer: String, value: Vec<u8> },
    /// Insert into an array at a final index token (`0..=len`) or `-` (append).
    InsertValue { target: EditTarget, pointer: String, value: Vec<u8> },
    /// Remove an existing object member or array element.
    RemoveValue { target: EditTarget, pointer: String },
    /// Delete an identified object: a root object deletes its document, a
    /// nested object is removed from its containing array.
    DeleteObject { id: crpg_core::Ulid },
    /// Append a placement to the placements aggregate beside the area's
    /// `area.json`, creating that aggregate if it does not exist.
    PlaceInstance { area: crpg_core::Ulid, placement: crpg_data::Placement },
    /// Replace an existing placement's transform.
    MovePlacement { placement: crpg_core::Ulid, transform: crpg_data::Transform },
}
```

Field docs are required on every variant field (`missing_docs`); they repeat
the meaning above.

### 3.2 `document`

```rust
/// Most commands in one `apply_batch` call.
pub const MAX_BATCH_COMMANDS: usize = 1_024;
/// Longest caller-supplied pointer, in bytes (before any object prefix).
pub const MAX_POINTER_BYTES: usize = 4_096;
/// Longest caller-supplied JSON value text, in bytes: 1 MiB.
pub const MAX_VALUE_BYTES: usize = 1_048_576;
/// Largest canonical document a command may create or leave behind: 4 MiB.
pub const MAX_DOCUMENT_BYTES: usize = 4_194_304;
/// Most undo entries kept; the oldest is evicted first.
pub const MAX_UNDO_ENTRIES: usize = 256;
/// Most bytes held by undo plus redo entries: 32 MiB (§6.3 defines the measure).
pub const MAX_HISTORY_BYTES: usize = 33_554_432;

/// An open, editable, always structurally valid campaign.
#[derive(Debug, Clone)]
pub struct CampaignDocument { /* private */ }

impl CampaignDocument {
    /// Opens a loaded campaign for editing (§5.1). The supplied index is ignored.
    pub fn open(campaign: crpg_data::LoadedCampaign) -> Result<Self, EditError>;
    /// The current documents and their freshly derived index.
    pub fn campaign(&self) -> &crpg_data::LoadedCampaign;
    /// Current canonical bytes of every document, by logical path.
    pub fn canonical_files(&self) -> &std::collections::BTreeMap<crpg_data::SourcePath, Vec<u8>>;
    /// 0 at open; +1 for every committed apply, undo or redo.
    pub fn revision(&self) -> u64;
    /// Applies one command atomically. Same as `apply_batch(vec![command])`.
    pub fn apply(&mut self, command: EditCommand) -> Result<CommandReceipt, EditError>;
    /// Applies 1..=MAX_BATCH_COMMANDS commands atomically as one undo entry (§5.3).
    pub fn apply_batch(&mut self, commands: Vec<EditCommand>) -> Result<CommandReceipt, EditError>;
    /// Reverts the newest undo entry (§6).
    pub fn undo(&mut self) -> Result<CommandReceipt, EditError>;
    /// Re-applies the newest redo entry (§6).
    pub fn redo(&mut self) -> Result<CommandReceipt, EditError>;
    /// Number of undo entries.
    pub fn undo_depth(&self) -> usize;
    /// Number of redo entries.
    pub fn redo_depth(&self) -> usize;
    /// Bytes held by undo plus redo entries (§6.3).
    pub fn history_bytes(&self) -> usize;
    /// `crpg_data::validate` over the current campaign; nothing else.
    pub fn validate(&self) -> Vec<crpg_data::Diagnostic>;
    /// The writes and removals that bring the saved baseline to the current state (§7).
    pub fn save_plan(&self) -> SavePlan;
    /// Records that `plan` was written; it becomes the new saved baseline (§7).
    pub fn mark_saved(&mut self, plan: &SavePlan) -> Result<(), EditError>;
}

/// How one path changed across a call.
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
pub enum ChangeKind {
    /// Absent before, present after.
    Created,
    /// Present before and after, with different bytes.
    Modified,
    /// Present before, absent after.
    Deleted,
}

/// One changed path.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct PathChange {
    /// Logical path.
    pub path: crpg_data::SourcePath,
    /// What happened to it.
    pub kind: ChangeKind,
}

/// The result of a committed (or no-op) apply, undo or redo; also the view
/// change notification (spec §11.2).
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct CommandReceipt {
    /// `revision()` after the call.
    pub revision: u64,
    /// Every path whose bytes differ between before and after the call, in
    /// lexical path order. Empty for a no-op.
    pub changes: Vec<PathChange>,
    /// `crpg_data::validate` over the campaign after the call.
    pub diagnostics: Vec<crpg_data::Diagnostic>,
}

/// Pure save instructions; the caller owns all I/O.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct SavePlan {
    /// Revision the plan was computed at.
    pub revision: u64,
    /// Paths to (re)write with these exact canonical bytes.
    pub write: std::collections::BTreeMap<crpg_data::SourcePath, Vec<u8>>,
    /// Paths present in the baseline and absent now.
    pub remove: std::collections::BTreeSet<crpg_data::SourcePath>,
}
```

### 3.3 `error`

```rust
/// Which input cap was exceeded.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum EditLimit {
    /// `MAX_POINTER_BYTES`.
    Pointer,
    /// `MAX_VALUE_BYTES`.
    Value,
    /// `MAX_DOCUMENT_BYTES`.
    Document,
}

/// Every editing failure. A failed call changes nothing (§5.4).
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum EditError {
    /// The opened campaign fails the writer's structural checks.
    Invalid { diagnostic: crpg_data::Diagnostic },
    /// A batch is empty or longer than `MAX_BATCH_COMMANDS`.
    BatchSize { len: usize },
    /// Command `index` exceeds an input cap.
    InputTooLarge { index: usize, limit: EditLimit },
    /// Command `index` names a path with no document.
    MissingPath { index: usize, path: crpg_data::SourcePath },
    /// Command `index` would create or rename onto an occupied path.
    PathExists { index: usize, path: crpg_data::SourcePath },
    /// Command `index` names an id absent from the index.
    UnknownObject { index: usize, id: crpg_core::Ulid },
    /// Command `index` names an object of the wrong kind.
    WrongKind {
        index: usize,
        id: crpg_core::Ulid,
        expected: crpg_data::ObjectKind,
        found: crpg_data::ObjectKind,
    },
    /// Command `index` touches a protected document or member (§5.2).
    Protected { index: usize, path: crpg_data::SourcePath, pointer: String },
    /// T058a's `edit_document` refused command `index`'s pointer edit.
    Pointer { index: usize, path: crpg_data::SourcePath, error: crpg_data::PointerEditError },
    /// Command `index` would change the id of an existing object.
    IdentityChanged { index: usize, path: crpg_data::SourcePath, id: crpg_core::Ulid },
    /// Command `index` leaves the campaign structurally invalid.
    Rejected { index: usize, diagnostic: crpg_data::Diagnostic },
    /// The committed change would exceed `MAX_HISTORY_BYTES` on its own.
    HistoryTooLarge { bytes: usize },
    /// The undo stack is empty.
    NothingToUndo,
    /// The redo stack is empty.
    NothingToRedo,
    /// `mark_saved` received a plan from another revision.
    StaleSavePlan,
    /// A history entry failed to re-read or re-index (unreachable; documented).
    HistoryCorrupt,
}
```

Field docs are required on every field. `EditError` implements
`std::fmt::Display` by hand and `std::error::Error` with no source.
`EditLimit` implements `Display` as `pointer`, `value`, `document`. Display
strings follow the `crpg-data`/`crpg-persist` convention: lowercase, no
trailing punctuation, and they never print caller value bytes. Paths, ULIDs
(uppercase, `crpg-core` `Display`) and the capped pointer may appear.
`Diagnostic` and `PointerEditError` print with their own `Display`.

| `MissingPath` | `command {index}: no document at {path}` |
| `PathExists` | `command {index}: a document already exists at {path}` |
| `UnknownObject` | `command {index}: unknown object {id}` |
| `WrongKind` | `command {index}: object {id} has the wrong kind for this command` |

| `Pointer` | `command {index}: {path}: {error}` |

## 4. Why these nine commands (MVP sufficiency)

The set is the smallest that covers spec §17.2 authoring and the M6 editors
that follow, without a typed command per document family. Generated property
forms (spec §11.4 commitment 3, T061) need a generic path-addressed edit;
everything else is whole-document or identity-level.

| Spec §17.2 / M6 need | Commands |
|---|---|
| #1 create an area, a few props | `CreateDocument` (`area.json`), `PlaceInstance` |
| #2 place player start, NPC, hostile | `PlaceInstance`; `SetValue` on `campaign.json` `/entry/spawn` |
| #3 creatures with `minimal-d6` stats | `CreateDocument` (creature); `SetValue`/`RemoveValue` on `/stats/<name>` |
| #4 dialogue with three nodes and one choice | `CreateDocument` (dialogue); `InsertValue` on `/nodes/-`; `SetValue` on `/nodes/<i>/body/next` |
| #5 quest with two states | `CreateDocument` (quest); `InsertValue` on `/states/-` |
| Localization (spec §4.4: key and text written together) | `SetValue` on locale `/strings/<key>`, batched with the field edit |
| Placement tools (§19.2 #16: move, rotate, snap, duplicate, delete) | `MovePlacement`; duplicate = `PlaceInstance` with a caller-supplied new id; `DeleteObject` |
| Move a placement to another area | `apply_batch([DeleteObject, PlaceInstance])` with the same id |
| Delete with blast radius (spec §11.4 commitment 2) | `DeleteObject`/`DeleteDocument`; the view shows `explain_object` first |
| Reorganise files (spec §4.3: paths are not identity) | `RenameDocument` |

`PlaceInstance` and `MovePlacement` are the only typed conveniences, because
placement is the highest-frequency MVP operation and the GUI should not
build placement JSON by hand. Spec §11.2's illustrative `AddDialogueNode` and
`ConnectGraphNodes` are expressible as `InsertValue`/`SetValue` and are not
added until the dialogue, quest and graph editors (T066, T067, T074) show a
need (§14 Q12). Terrain (T063) is not here.

## 5. Behaviour

### 5.1 `open`

1. Take `campaign.documents`; drop `campaign.index`.
2. `crpg_data::campaign_index(&documents)` (T058a). On `Err(e)` return
   `Invalid { diagnostic: crpg_data::diagnostic_for_data_error(&e) }`.
3. For each document, `crpg_data::write_document`. This cannot fail after
   step 2; if it does, return `Invalid` with the converted diagnostic.
4. The canonical map is the current state and the **saved baseline**.
   Revision 0, both stacks empty.

`open` does not check the engine version (the caller's `load_campaign`
did, and `/engine` is protected), does not require semantic cleanliness, and
does not compare against source bytes (§14 Q8). It enforces no size cap on
the opened campaign; loader input caps are `crpg-data`'s deferred S001 item.

### 5.2 Protection (checked before any mutation)

A command is `Protected` when it would:

1. create, delete, rename from or onto, or edit **`campaign.lock`** or
   **`assets/assets.lock`**, or create a `Document::CampaignLock` or
   `Document::AssetsLock` at any path. Locks are derived artifacts owned by
   `crpgc lock` and the assets pipeline (E016). `pointer` is `""`;
2. pointer-edit `campaign.json` where the first decoded reference token of the
   **absolute** pointer is `package`, `engine` or `requires`. `pointer` is the
   absolute pointer.

The schema tag and the document root are protected by T058a itself
(`SchemaTag`, `RootPointer`), so no edit can retag, migrate or replace a
whole document through a pointer.

### 5.3 `apply_batch` (exact algorithm; first failure wins)

`apply(c)` is `apply_batch(vec![c])`. On entry, if `commands.len()` is 0 or
greater than `MAX_BATCH_COMMANDS`, return `BatchSize`. Otherwise clone the
current documents, index and canonical map into a working state `W`, then for
each command `i` in order:

1. **Input caps.** Pointer longer than `MAX_POINTER_BYTES` → `InputTooLarge{Pointer}`;
   value longer than `MAX_VALUE_BYTES` → `InputTooLarge{Value}`. For
   `CreateDocument`, `write_document(&document)` longer than
   `MAX_DOCUMENT_BYTES` → `InputTooLarge{Document}` (a `write_document`
   error here → `Rejected` with the converted diagnostic).
2. **Resolution** against `W`:
   - `DeleteDocument`, `RenameDocument.from`, `EditTarget::Document`: path
     absent → `MissingPath`.
   - `CreateDocument.path`, `RenameDocument.to`: path present → `PathExists`.
   - `EditTarget::Object`, `DeleteObject.id`: id absent from `W`'s index →
     `UnknownObject`. The absolute pointer is the index entry's pointer
     followed by the relative pointer.
   - `PlaceInstance.area`: absent → `UnknownObject`; kind not `Area` →
     `WrongKind{expected: Area}`. The target aggregate path is the area's
     index path with its final `area.json` replaced by `placements.json`.
   - `MovePlacement.placement`: absent → `UnknownObject`; kind not
     `Placement` → `WrongKind{expected: Placement}`.
3. **Protection** (§5.2) → `Protected`.
4. **Mutation** of `W.documents`:
   - `CreateDocument`: insert. `DeleteDocument`: remove.
     `RenameDocument`: remove and re-insert the same `Document`.
   - `SetValue`/`InsertValue`/`RemoveValue`: `crpg_data::edit_document` with
     the matching `PointerEdit` and the absolute pointer; `Err(e)` →
     `Pointer { path, error: e }`.
   - `DeleteObject`: an index pointer of `""` means `DeleteDocument` of its
     path; otherwise `PointerEdit::Remove` at the index pointer.
   - `PlaceInstance`: if the aggregate exists, `PointerEdit::Insert` at
     `/placements/-` with `canonical_json(&placement)`; otherwise insert
     `Document::Placements(PlacementsDocument { area, placements: vec![placement], note: None })`.
   - `MovePlacement`: `PointerEdit::Set` at `<index pointer>/transform` with
     `canonical_json(&transform)`.
5. **Document cap.** Re-write every document this command touched with
   `write_document`; any result longer than `MAX_DOCUMENT_BYTES` →
   `InputTooLarge{Document}`.
6. **Structure.** `crpg_data::campaign_index(&W.documents)`; `Err(e)` →
   `Rejected { diagnostic: diagnostic_for_data_error(&e) }`. Layout,
   duplicate ids, required files, lock coverage and the assets digest are
   all `crpg-data`'s checks with `crpg-data`'s precedence.
7. **Identity.** For each touched path, compare the set of `(id, kind)`
   entries of the old and new index with that path. `SetValue` and
   `MovePlacement` require equality. `InsertValue` and `PlaceInstance`
   require old ⊆ new. `RemoveValue`, `DeleteObject` and `DeleteDocument`
   require new ⊆ old. `RenameDocument` requires the old set at `from` to
   equal the new set at `to`. `CreateDocument` is checked by step 6
   (`DuplicateId`). A violation → `IdentityChanged` naming the lexically
   smallest ULID in the symmetric difference.
8. Replace `W`'s index with the new one and continue.

After the last command:

9. Diff the pre-batch canonical map against `W`'s. If they are byte-equal,
   the call is a **no-op**: return `Ok` with `changes` empty, `revision`
   unchanged, `diagnostics = validate()`; both stacks are untouched.
10. Build the history entry (§6.1). If its size exceeds `MAX_HISTORY_BYTES`,
    return `HistoryTooLarge { bytes }`.
11. **Commit:** install `W`, clear the redo stack, push the entry, evict
    (§6.3), increment the revision, and return the receipt with the diff and
    `crpg_data::validate` over the new campaign.

Semantic diagnostics never block `apply`, `undo`, `redo` or `save_plan`. A
dangling reference created by a delete is reported, not refused (spec §11.4
Problems panel; §14 Q5, Q10).

### 5.4 Atomicity

Every `Err` from `apply`, `apply_batch`, `undo`, `redo` and `mark_saved`
leaves `canonical_files()`, `campaign()`, `revision()`, both stacks,
`history_bytes()` and the saved baseline exactly as they were. Nothing is
committed until step 11. A batch that fails at command `k` reports `k` and
discards the effects of commands `0..k`.

### 5.5 Schema versions

`crpg-edit` never calls `read_document` on caller input, `migrate_document`
or any migration. Pointer edits re-decode with the current tag only (T058a).
`CreateDocument` takes a typed `Document`, which is always a current
version. Every document `crpg-edit` writes therefore carries its current
tag. A document that the caller's `load_campaign` migrated in memory is
written with its current tag if, and only if, a command changes it (§14 Q8).

## 6. Undo and redo

### 6.1 Entries

An entry is, for every path in the receipt's `changes`, the pair
`(before: Option<Vec<u8>>, after: Option<Vec<u8>>)` of canonical bytes, in
lexical path order. One successful non-no-op `apply_batch` is one entry,
whatever its command count.

### 6.2 Operations

- `undo`: empty stack → `NothingToUndo`. Otherwise, on a working copy, set
  each path to `before` (`read_document` on the stored bytes, or remove for
  `None`), then `campaign_index`. Either failing → `HistoryCorrupt` (stored
  bytes were written by `write_document` and accepted before, so this is
  unreachable; it exists so no path panics). Commit: move the entry to the
  redo stack, increment the revision, and return a receipt whose `changes`
  is the diff (so `Created` and `Deleted` swap) and whose `diagnostics` is
  `validate()`.
- `redo`: the same with `after`, moving the entry back to the undo stack.
  `NothingToRedo` when empty.
- **Redo invalidation:** every committed `apply`/`apply_batch` clears the
  redo stack. A failed or no-op apply does not. `undo`, `redo` and
  `mark_saved` never clear either stack.
- **Exactness:** after `undo`, `canonical_files()` equals the map before the
  undone apply byte for byte; after `redo`, it equals the map after it.

### 6.3 Bounds

- Entry size = Σ over its paths of `before.len()` + `after.len()` (`None` is 0).
  `history_bytes()` = Σ over every undo and redo entry.
- After each commit's push (redo is then empty): while
  `undo_depth() > MAX_UNDO_ENTRIES` or `history_bytes() > MAX_HISTORY_BYTES`,
  drop the **oldest** undo entry. Step 10 guarantees the new entry survives,
  so **every successful apply can be undone at least once**.
- Undo and redo move entries between stacks without changing
  `history_bytes()`, so they never evict.

## 7. Save

- `save_plan()` compares the current canonical map with the saved baseline:
  `write` holds every current path whose bytes differ from the baseline or
  are absent from it, `remove` every baseline path absent now. A fresh
  document, or one undone back to its baseline, has an empty plan.
- `mark_saved(plan)`: `plan.revision != revision()` → `StaleSavePlan`.
  Otherwise the current canonical map becomes the baseline. Revision and
  stacks are unchanged, so saved states stay undoable.
- `crpg-edit` performs no filesystem I/O. Writing, ordering and atomic
  replacement are the caller's (T059, T060). Applying `write` and `remove`
  to the baseline file map and calling `crpg_data::load_campaign` yields a
  campaign whose `open` gives the same `canonical_files()` (tested).
- Spec §11.2 sketches `save(&self) -> Result<Vec<PathBuf>>`; the pure plan
  replaces it because I/O belongs above this crate (§14 Q7).

```rust
// crates/crpg-data/src/pointer_edit.rs; `pub mod pointer_edit;` with a glob
// re-export at the root, like the sibling modules.

/// One RFC 6901 edit on a document's JSON value. `value` is UTF-8 JSON text.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum PointerEdit {
    /// Replace an existing value, or add an absent member of an existing object.
    Set { pointer: String, value: Vec<u8> },
    /// Insert into the parent array at the final token: an index `0..=len`, or `-`.
    Insert { pointer: String, value: Vec<u8> },
    /// Remove an existing object member or array element.
    Remove { pointer: String },
}

/// Why a pointer edit was refused; the input document is never changed.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum PointerEditError {
    /// Not RFC 6901 syntax, a bad escape, or a malformed array index token.
    InvalidPointer,
    /// The empty pointer (whole-document replacement is not a pointer edit).
    RootPointer,
    /// The first reference token is `schema`.
    SchemaTag,
    /// The target (or, for Insert, the parent array or index) does not exist.
    NotFound,
    /// The value text fails the strict parser (UTF-8, integers only, unique keys).
    Value { message: String },
    /// The edited value fails current-tag typed decoding or local invariants.
    Document { message: String },
}

/// Applies one pointer edit to a copy of `document`; pure; never migrates.
pub fn edit_document(document: &Document, edit: &PointerEdit) -> Result<Document, PointerEditError>;

/// The writer's structural acceptance plus the derived index, without I/O,
/// engine check or migration: exactly `serialize_campaign`'s checks and
/// precedence, then the index `load_campaign` would derive for the same documents.
pub fn campaign_index(
    documents: &BTreeMap<SourcePath, Document>,
) -> Result<BTreeMap<Ulid, IndexEntry>, DataError>;
```

T058a behaviour to pin in its own contract:

- `edit_document` precedence: `InvalidPointer` → `RootPointer` →
  `SchemaTag` → `Value` (strict `canonical::parse`) → `NotFound` →
  `Document` (the existing private `decode_current`, which runs
  `validate_local`). It serializes the input with the existing serde shape,
  edits the value, and decodes with the **current** tag only, so it can
  neither migrate nor retag. Array index tokens are `0` or `[1-9][0-9]*`
  fitting `usize`; `-` is valid only as `Insert`'s final token. `Set` on an
  array requires an existing index.
- `PointerEditError` `Display` (lowercase, no input bytes): `invalid json pointer`,
  `json pointer must not be empty`, `the schema tag cannot be edited`,
  `json pointer target not found`, `invalid value: {message}`,
  `edited document is invalid: {message}`.
- `campaign_index` calls the private `structural_check` and `build_index`;
  `serialize_campaign`, `explain_object` and `load_campaign` behaviour and
  their tests are unchanged.
- Focused test `cargo test -p crpg-data --test pointer_edit --locked`, with
  positive controls for every refusal and a check that the input document
  is unchanged.

## 14. Open questions for the user

1. **"Rename id".** Spec §4.3 says an object `id` is never changed. This
   contract therefore offers no ULID re-keying (it is refused as
   `IdentityChanged`); slugs are renamed with `SetValue`, and files with
   `RenameDocument`.
   *Recommendation:* approve. If true re-identification is ever needed, it is
   a whole-campaign refactor tool with its own decision, not an edit command.
2. **Prerequisite T058a.** `crpg-data` has no public pointer edit and no
   public index rebuild. The alternatives are worse: `serde_json` and
   `semver` edges in `crpg-edit` plus a second JSON pointer implementation and
   a re-serialize-then-`load_campaign` round trip per command.
   *Recommendation:* approve T058a as specified in §9, as its own
   `crpg-data` task contracted and merged before T058 starts. It changes no
   schema or fixture, so it is not in the serialized set.
3. **Dependency edges (§10).** *Recommendation:* approve `crpg-core` and
   `crpg-data` (normal) and workspace `proptest` (dev) only. No
   `crpg-rules` edge yet.
4. **Command wire format.** `crpgc apply commands.json` needs a JSON form of
   `EditCommand`. *Recommendation:* defer it to the T059 contract. If T059
   needs the decoder to live in `crpg-edit` (to keep the CLI thin), file a
   small `crpg-edit` task then, with its `serde` edge request, rather than
   adding serde to T058 speculatively.
5. **Structural blocks, semantic reports.** Structural failures (layout,
   duplicate ids, locks, typed shape) refuse the command; semantic findings
   (dangling references, missing locale keys, unreachable nodes) never block
   apply or save. *Recommendation:* approve; it is how the spec §11.4
   Problems panel works, and it keeps every state loadable by `crpg-data`.
6. **Bounds.** *Recommendation:* 1,024 commands per batch; pointer 4 KiB;
   value 1 MiB; document 4 MiB; 256 undo entries; 32 MiB of history. MVP
   documents are kilobytes. Raising any cap later is a deliberate change.
7. **Save is a pure plan.** Spec §11.2 sketches `save -> Vec<PathBuf>`.
   *Recommendation:* approve the plan/`mark_saved` pair: the library stays
   I/O-free like `crpg-data`, and the CLI and bridge own writes.
8. **Opening migrated or non-canonical sources.** The saved baseline is the
   canonical form at `open`, so untouched files are never rewritten, and a
   migrated document is written at its current version only when edited.
   *Recommendation:* callers (T059, T060) refuse to open a campaign that
   fails the `crpgc fmt --check` and migrate preflights, so an editor save
   never mixes migration with edits; T058 does not enforce it.
9. **Protected manifest members.** `campaign.lock`, `assets/assets.lock`,
   and `campaign.json` `/package`, `/engine`, `/requires` are read-only to
   commands. *Recommendation:* approve. `/version` stays editable.
10. **Deletes are not blocked by inbound references.** *Recommendation:*
    approve; the view shows `explain_object`'s inbound edges first and the
    receipt reports the resulting dangling references.
11. **ID generation.** T006d says `crpg-cli` and `crpg-edit` "supply" new
    ids. *Recommendation:* read that as the editing hosts: `crpg-edit` takes
    caller-supplied ULIDs and stays clock- and entropy-free (so the property
    test is deterministic); T059 and T060 own generation from host entropy.
12. **Typed conveniences.** Only placement has typed commands.
    *Recommendation:* approve; add typed dialogue/quest/graph commands only
    when their editors (T066, T067, T074) show the generic form is not enough.
13. **Receipts as change notifications.** No subscribe/callback API.
    *Recommendation:* approve; the bridge (T045/T060) decides how views are
    told.
14. **Per-command cost.** Each command clones the campaign and re-indexes,
    and each call runs the full `validate`. *Recommendation:* accept for
    M6; measure with a D06-style workload before optimizing, and never by
    adding a second validator.
15. **Undo granularity.** Drag operations produce many `MovePlacement`s.
    *Recommendation:* no coalescing in T058. The GUI sends one
