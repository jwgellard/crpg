# T136b — `crpg-data` surface schemas, kernel range (ADR-0029 Follow-on 3, after T136a)

## Task / Crate(s) / Status
The rest of ADR-0029 Follow-on row 3 after T136a: typed and derived stats,
resolution shape, damage dice, initiative, effects on stats with tag grants,
and the version bumps with one migration step each. Crate: `crpg-data` (plus
its two docs, the regenerated `schemas/`, and its test fixtures). **S-set.**
It cannot merge alone: the companion **T136c** (`crpg-sim`, below) must land in
the same batch, because two exhaustive `match`es in `crpg-sim/src` stop
compiling (Decision D10, open question 1).
Frame: `tasks/T136.md` §"T136b frame". Inputs: blind drafts
`tasks/T136b-draft-a.md` and `tasks/T136b-draft-b.md`, adjudicated below.
Status: **contract approved by the user 2026-10-23 (D32, every recommendation).** Open questions settled as recommended: every [bump] item is void (D32c), encounter stays `/1`, T136c lands in the same batch, and sides, lifetimes, tiered thresholds and modifier conditions are deferred.

Items marked **[bump]** exist only because of the version bumps. If open
question 2 is answered (a), delete every [bump] item; nothing else changes.

## Decision
- **D1. Three bumps, all tag-only.** `crpg.ruleset/2 → /3`,
  `crpg.ability/2 → /3`, `crpg.effect/1 → /2`. Every new field is
  optional-missing and every new variant is additive, so each step rewrites
  `schema` only, and every migrated document equals today's value at the new
  tag. *Rejected:* draft B's effect step that moves `duration_rounds` into a
  `lifetime` enum (no kernel type; breaks `crpg-sim/src/combat.rs:1189,1320`).
- **D2. `crpg.encounter` stays `/1`.** T136b changes no encounter shape (D7,
  D9), and a content-free bump is churn. This departs from the frame table
  (open question 3). Combatant tags already have an authored source:
  `Creature.tags` (`crates/crpg-data/src/document.rs:121`), which T137 maps.
- **D3. Typed stats extend `StatKindWire`, externally tagged.** `"int"` stays
  byte-identical; `fixed`, `bool`, `tags`, `dice` are strings and enum is
  `{"enum":{"enum_id":…,"variants":[…]}}`. `Deserialize` is hand-written,
  because the derived one also accepts `{"int": null}`. *Rejected:* adjacent
  `type`/`value` for kinds (rewrites every ruleset's `kind`).
- **D4. Derived stats are `StatDecl.derived: Option<ExprWire>`**, adjacently
  tagged like the kernel's `SerializableStatValue`
  (`crates/crpg-rules/src/stats.rs:497-510`) and the crate's other wire enums.
  Data checks every rule that one ruleset document decides: domain shape,
  limits, references, cycles, chain length and kinds (B5). *Rejected:*
  external `{"add":[l,r]}` (draft B; breaks the crate convention) and
  "data cannot type" (draft A; typing needs only the declarations).
- **D5. Health and attributes are `Int`.** `health_stat` names a non-derived
  `Int` stat; `attributes` name `Int` stats. The sim reads both as `i32`
  (`crpg-sim/src/combat.rs:1010-1030`), and `Against::Stat` needs `Int`.
- **D6. Resolution shape.** `Ability.bonus_stats` (actor stats added to the
  roll fold); `DefenseWire` gains `Constant(i32)`, `ActorStat{stat}`,
  `Opposed{dice, bonus_stats}`. *Rejected:* a threshold field. Tiered
  thresholds are deferred, not covered: bands are constant margins and cannot
  express skill-relative grades (open question 6).
- **D7. Initiative is a ruleset rule.** `Ruleset.initiative:
  Option<InitiativeWire{dice, bonus_stats}>`; the participant's authored
  `initiative` stays and is added as an offset. *Rejected:* per-participant
  dice (draft A; repeats ruleset policy in every encounter and has no stat
  term) and `Stat | Dice` (draft B; cannot express d20 + Dex).
- **D8. Damage is `amount` plus optional `dice`.** `amount: u32` stays
  required, so `1d8+3` is expressible and the sim's `item.amount` reads still
  compile. Crit doubling is a per-outcome dice entry (`"2d8"` on critical).
  *Rejected:* exactly one of `amount` or `dice` (draft A).
- **D9. Effects gain a stat target and tag grants.**
  `EffectTargetWire::Stat{stat}` (an `Int`, non-health stat) and
  `Effect.grants`. Lifetime kinds, sides and modifier conditions are deferred
  (open questions 4, 5, 7).
- **D10. Downstream compile.** New `DefenseWire`/`EffectTargetWire` variants
  break the exhaustive matches at `crpg-sim/src/combat.rs:1259-1264` and
  `:1298-1301`. New fields break test struct literals in `crpg-sim` and
  `crpg-net`. T136c fixes them: the sim rejects every T136b feature with one
  new `CombatError::UnsupportedAuthored`, until T137 implements them
  (T017a/T017b precedent). *Rejected:* a duplicate compat field, or a red
  workspace.
- **D11. One new diagnostic code**, `real_time_fields_without_round_ticks`
  (`Warning`), with a `push_warning` helper; every other new rule reuses
  `unknown_stat`.

## Migration steps per document [bump]
Each step is a private `pub(super) fn(&mut serde_json::Value) -> Result<(),
DataError>` shaped like `migrations/ruleset.rs::v1_to_v2`. It fails with
`Malformed` `expected object with string schema` on a non-object or a
missing or non-string `schema`. On any other tag it fails with the exact
message below. Otherwise it changes only `schema`. It removes, adds and
rejects no other key: keys that the source version lacks are accepted, as the
`1 → 2` steps do (T136 open question 5). The typed decode then judges them.
- **ruleset `2 → 3`** (`migrations/ruleset.rs::v2_to_v3`): needs
  `crpg.ruleset/2`, else `ruleset migration expects schema crpg.ruleset/2`.
  It keeps `round_ticks` present or absent, and every other key, byte for
  byte. Result tag `crpg.ruleset/3`.
- **ability `2 → 3`** (`migrations/ability.rs::v2_to_v3`): needs
  `crpg.ability/2`, else `ability migration expects schema crpg.ability/2`.
  It keeps `recovery_ticks` and `repeats_in_real_time` present or absent,
  and every other key. Result tag `crpg.ability/3`.
- **effect `1 → 2`** (new `migrations/effect.rs::v1_to_v2`, with a module doc
  like its siblings): needs `crpg.effect/1`, else `effect migration expects
  schema crpg.effect/1`. Result tag `crpg.effect/2`.
- `/1` ruleset and ability sources run the full chain `1 → 2 → 3` in memory.
  `rulesets/minimal-d6/` (ruleset and ability at `/1`) and
  `rulesets/srd-lite/` (ruleset and abilities at `/2`, effect at `/1`) stay
  **byte-identical** and migrate in memory, as do their campaign copies. Their
  decoded values equal today's, with every new field absent.

## Behaviour
1. **Decode `StatKindWire`.** A `kind` must be one of the strings `"int"`,
   `"fixed"`, `"bool"`, `"tags"`, `"dice"`, or an object with exactly the
   key `"enum"`. That key's value is an object with exactly `enum_id` (a
   string) and `variants` (an array of strings). Rejected, each as `Malformed`:
   `"enum"`, `"Int"`, `{"int": null}`, `{"enum": {…}, "x": 0}`, an
   inner object with a missing or extra key, and `{"type": "int"}`.
2. **Decode `derived`.** If absent or `null`, it is `None`. If present, it is
   one `ExprWire` object with exactly `type` and `value`. `literal` takes a
   `StatValueWire`. `stat` takes a string. The six binaries take an object
   with exactly `left` and `right`. `StatValueWire` is an object with exactly
   `type` and `value`: `int` takes an `i32`, `fixed` a raw `i32`, `bool` a
   boolean, `enum` an object with exactly `enum_id` and `variant`, `tags` an
   array of strings, and `dice` a string. Unknown type names, extra or missing
   keys at any level, and out-of-range integers are `Malformed`. A tree
   deeper than serde_json's recursion limit fails at parse as `Malformed`
   before item 5 runs.
3. **Decode other shapes.** `initiative`, `bonus_stats`, `DamageEntry.dice` and
   `grants` are optional-missing, and explicit `null` decodes as absent (the
   `natural_die` precedent). Inside `InitiativeWire` and `Opposed`, `dice`
   and `bonus_stats` are both required, and the list may be empty. The
   `DefenseWire` and `EffectTargetWire` forms are exactly:
   `{"type":"constant","value":12}`,
   `{"type":"actor_stat","value":{"stat":"guile"}}`,
   `{"type":"opposed","value":{"bonus_stats":["might"],"dice":"2d6"}}`,
   `{"type":"stat","value":{"stat":"might"}}`. Each of them rejects extra or
   missing keys. Unknown fields stay rejected everywhere.
4. **Encode.** An absent optional writes no key. `variants`, `bonus_stats` and
   `grants` keep their authored order. The canonical writer sorts keys, so
   every existing document's canonical bytes are unchanged apart from
   `schema` [bump].
5. **Read-time ruleset checks** (`validate_combat_local`), appended after the
   `round_ticks` check, in this order (the first failure is returned):
   1. For each stat in authored order whose kind is `Enum`:
      `ruleset enum stat enum_id must be nonempty`;
      `ruleset enum stat variants must be 1..=1024`;
      `ruleset enum stat variants must be distinct and nonempty`.
   2. `ruleset enum stats sharing an enum_id must declare the same variants`
      (compared as sets).
   3. `ruleset health_stat must name a non-derived int stat`.
   4. `ruleset attributes must name int stats` (derived allowed).
   5. For each derived stat in authored order: `ruleset derived expression
      must be at most 4096 nodes and 32 deep` (the root is depth 1).
   6. `ruleset derived expressions must total at most 65536 nodes`.
   7. For each derived stat in authored order, nodes in preorder (node, then
      left, then right). The first failing node decides.
      A `tags` literal: `ruleset derived tags literal must hold at most 1024
      distinct nonempty tags`. A `dice` literal: `ruleset derived dice literal
      must be 1..=128 UTF-8 bytes`. An `enum` literal whose `enum_id` is not
      the domain of an `Enum` stat of this ruleset, or whose `variant` is not
      in that domain: `ruleset derived enum literal must name a declared
      enum variant`. A `stat` node that names no declared stat: `ruleset
      derived expression must reference declared stats`.
   8. `ruleset derived stats must not form a cycle` (self-reference
      included).
   9. `ruleset derived dependency chains must be at most 128 stats`
      (endpoints included).
   10. `ruleset derived expression kind must match its stat`. A literal's
       kind is its variant (an enum literal's kind is its `enum_id`). A
       `stat` node's kind is that stat's declared kind. A binary operator
       needs two `Int` operands (result `Int`) or two `Fixed` operands
       (result `Fixed`). The root's kind must equal the declaring stat's
       kind; for `Enum`, the same `enum_id`.
   11. When `initiative` is present: `ruleset initiative dice must be 1..=128
       UTF-8 bytes`; `ruleset initiative bonus stats must name distinct
       non-health int stats`.
6. **Read-time ability checks.** The existing `ability defense stat must be
   nonempty` check (`combat.rs:816-819`) now also covers `ActorStat`, in the
   same place. Then, appended after the `recovery_ticks` check, in this order:
   when present, `ability bonus_stats must be a nonempty list of distinct
   nonempty names`. For `Opposed`: `ability opposed dice must be 1..=128 UTF-8
   bytes`, then `ability opposed bonus_stats must be distinct nonempty
   names`. Then, for each damage entry in authored order whose `dice` is
   present: `ability damage dice must be 1..=128 UTF-8 bytes`. No dice
   notation is parsed in data.
7. **Read-time effect checks**, appended after the duration check: for each
   modifier in authored order, a `Stat` target with an empty name gives
   `effect modifier stat must be nonempty`. Then, when `grants` is present:
   `effect grants must hold 1..=1024 distinct nonempty tags`.
8. **Order.** Every new check comes after the existing checks of its arm,
   apart from item 6's widened defense check. A document with several faults
   therefore reports the earlier fault, as it does today.
9. **Semantic `unknown_stat`** (`walk_combat`, every ruleset × every ability
   it lists, orphans skipped, all `Error`, fix `use a declared non-health int
   stat of the ruleset`). Below, "valid" means a declared, non-health stat of
   kind `Int` in the owning ruleset.
   (a) Each `bonus_stats[i]` that is not valid, at `/bonus_stats/<i>`:
   `unknown bonus stat {name:?} for ability: not a non-health int stat of
   ruleset {ruleset_id}`.
   (b) `TargetStat` or `ActorStat` naming an undeclared or health stat, at
   `/defense`: the existing message, byte-unchanged. If the stat is declared
   and non-health but not `Int`, at `/defense`: `defense stat {name:?} for
   ability is not an int stat of ruleset {ruleset_id}`.
   (c) Each `Opposed` `bonus_stats[i]` that is not valid, at
   `/defense/value/bonus_stats/<i>`: `unknown opposed bonus stat {name:?} for
   ability: not a non-health int stat of ruleset {ruleset_id}`.
   (d) When the ability's `effect` resolves to an `Effect` document, each
   modifier `i` with a `Stat` target that is not valid, in the effect's file
   at `/modifiers/<i>/target`: `unknown effect stat {name:?} for effect
   {effect_id}: not a non-health int stat of ruleset {ruleset_id}`. This is
   emitted at most once per (effect, modifier, ruleset).
10. **Prefab completeness narrowed.** `missing_stat` applies only to
    non-derived `Int` and `Fixed` stats. The whole-number `invalid_stat_value`
    check applies only to `Int` stats. The health check is unchanged. Codes,
    pointers and messages are byte-unchanged for the existing cases.
11. **The RT warning.** For every ruleset × listed ability where the ruleset
    has no `round_ticks` and the ability has `recovery_ticks` present or
    `repeats_in_real_time == Some(true)`, emit one `Warning`
    `real_time_fields_without_round_ticks`. Its pointer is `/recovery_ticks`
    if that field is present, else `/repeats_in_real_time`. Message: `ability
    {ability_id} declares real-time fields but ruleset {ruleset_id} has no
    round_ticks`. Fix: `add round_ticks to the ruleset or remove the real-time
    fields`. A `round_ticks` that no ability uses stays clean, and orphans skip.
    Warnings never fail validation.
12. **Versions [bump].** `schema_versions()` reports ruleset 3, ability 3,
    effect 2, and 1 or 2 for the others as today. `/4`, `/4`, `/3` and every
    unknown or zero tag are `UnsupportedSchema`, with the original tag kept.
13. **Schemas.** After regeneration with the existing generator, exactly
    `ruleset.schema.json`, `ability.schema.json` and `effect.schema.json`
    change. No new key is in `required`. The other 19 files are byte-identical.
14. **Existing content.** Every document under `rulesets/` and
    `campaigns/fixtures/` reads to today's value, with each new field absent.
    `validate` on `combat_basic` and `combat_srd` stays `Vec::new()`.
15. **Kernel mapping** (normative for T137; `crpg-data` never depends on
    `crpg-rules`):
