## Interface

Approve exact public `legal_actions` signature, `ActionOption` fields, actor/
target enumeration inputs, ability/EndTurn representation, deterministic ordering,
query error precedence and result bound/truncation behavior before code.
Candidate direction: read-only World + actor, returns deterministic executable
combat options using existing `CombatAction` vocabulary. Alternative: a read-only
single-action validation query instead of enumeration. D15 selects, not the agent.

The approved result must distinguish possible execution from later authority:
sim does not know authenticated peer, NetId mapping, hidden-field entitlement
or client capability. Never serialize all sim options directly to a client.

## Behaviour

Query shares the authoritative pure validation path (including T019's summed
per-pool checks) and makes no mutation/RNG stream/event/turn change. Each returned
option is admissible by `perform_action` on a clone of the same world; accepted
failed attacks remain legal. Resources/turns can change after enumeration, so
the host always rechecks execution. Never cache legality across state changes
without an approved invalidation contract. Preserve existing rejection order.

Enumeration order, target identity generation, duplicates, self-target, dead/
absent actors/targets, cost boundaries, EndTurn and terminal encounters are
explicit. Silent truncation is not a valid bound policy. No extra gameplay
effects merely to demonstrate AI consumption.

### Exact public surface

Add to `combat` and re-export at the crate root:

```rust
pub const MAX_LEGAL_ACTIONS: usize = 4096;
pub fn validate_action(world: &World, action: &CombatAction)
    -> Result<(), CombatError>;
pub fn legal_actions(world: &World, actor: EntityId)
    -> Result<Vec<CombatAction>, LegalActionsError>;
pub enum LegalActionsError {
    Actor(CombatError),
    TooManyOptions { limit: usize },
}
```

`LegalActionsError`: `Debug, Clone, PartialEq, Eq`, `Display`, `Error`.
`Actor` displays the wrapped error unchanged and exposes it through `source()`;
the other display is `TooManyOptions at combat/options`, with no source.
No `ActionOption` wrapper, serde, diagnostic collection or new CombatError variant.
The existing `CombatAction` is the complete executable option.

### Single validation path and precedence

Extract the existing pre-mutation validation from `perform_action`; both public
functions use that path. A private borrowed validated-action representation is
allowed; no public prepared action may bypass later validation. Do not validate
by performing an action on a clone: even temporary RNG resolution is unnecessary.

For `UseAbility`, the current order is exactly: NoEncounter; live nonparticipant
actor; live nonparticipant target; AbsentActor; AbsentTarget; DeadActor; DeadTarget;
OutOfTurn; UnknownAbility; SelfTarget; T019 pool affordability (including its
checked overflow and defensive undeclared-pool handling). For EndTurn: NoEncounter;
live nonparticipant actor; AbsentActor; DeadActor; OutOfTurn. Preserve the existing
error fields, Display and multifault precedence, including the target checks
that precede an absent actor. Validation stops before interning defense stats,
creating RNG streams, building resolution inputs, spending or advancing.

`legal_actions` first validates `EndTurn { actor }`. Failure is `Actor(error)`.
This pins invalid-actor precedence without choosing an arbitrary target. On
success enumerate every ability in ascending full ULID order and every current
combatant in ascending full `EntityId::Ord` order, retaining precisely those
UseAbility candidates accepted by `validate_action`. Dead targets are excluded
by that same validation, not a divergent predicate. Append EndTurn last.
Candidate failures, including ValueOverflow, exclude that candidate; they do
not invalidate another ability or suppress a legal EndTurn.

Important as-built rule: `requires_target` does not introduce an optional target
in the current controller. Every UseAbility still names a live combatant;
`allow_self_target` alone governs self-target admissibility. Enumerate exactly
that behavior even when `requires_target == false`; do not invent targetless or
self-only semantics. No duplicates; no newly minted or index-only entity ids.

Check the output limit before a 4097th insertion, **including EndTurn**. Return
`TooManyOptions { limit: 4096 }` and discard the entire result. This is an output
bound, not a claim of bounded running time independent of authored input size.
Do not materialize the entire ability×target Cartesian product. No arbitrary
input-size rejection or new authored ability cap in this task.

### Required acceptance details

`tests/legal_actions.rs` must include named tests for:

- `options_match_independent_execution_matrix`: hand-author candidate actions
  and expected inclusion for targeted, self-allowed/disallowed, target-flag-false,
  multi-pool, target-defense and non-ending abilities; execute each candidate on
  an independent public World clone, not by calling validate_action as oracle.
- `query_and_validation_preserve_complete_state`: compare serialized bytes and
  `state_hash` before/after every success and error; repeat query twice before
  resolution to prove no RNG creation/draw or interner changes.
- `action_error_precedence_is_unchanged`: multifault pairs for both verbs,
  including live nonparticipant target versus absent actor and T019 pool order.
- `full_identity_order_survives_slot_reuse`: deliberately reverse insertion
  order, reuse an arena slot, and assert the literal expected full-id ordering.
- `end_turn_is_last_and_counts_toward_limit`: exactly 4096 succeeds; 4097 fails
  wholly; use four/five abilities and an authored participant population to
  reach the boundary without allocating an unbounded test product.
- `stale_options_revalidate`: spend/advance/despawn after querying, then assert
  the stale action's existing typed error and complete-state nonmutation.
- `actor_errors_and_unaffordable_control`: no encounter, nonparticipant, absent,
  dead and terminal/out-of-turn controls, plus valid actor with only EndTurn.

Use the focused and stopping commands above plus standing native gates. Extend
sim architecture/AGENTS during implementation. Legacy hashes, API behavior and
goldens remain unchanged; no new golden is necessary for a read-only query.
