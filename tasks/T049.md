## Readings

1. **Smoothing is presentation only and lives in the Godot-free core.** The
   buffers are fed from the immutable replica's positions after each frame
   the client half applies; nothing flows back to the replica, the outbox or
   any frame. It is integer arithmetic on raw `Fx16_16` values (ADR-0036 U5's
   formula, `:109–111`), so it is exact, tested by `cargo test` on both
   targets, and keeps invariant 8 (no float in the core,
   `crates/crpg-godot/AGENTS.md`). GDScript divides by 65,536 to draw.
2. **"The newest tick" is read as the estimated server time.** G1 says
   render "at the newest tick minus the U7 delay" (`:446–447`). Taken
   literally the render time freezes between sample arrivals and the proxy
   steps again. So the client keeps a clock offset, the minimum over every
   sample it has received of `arrival_ms − server_tick × 50`, and renders at
   `now_ms − offset − 100`. The minimum is the least-delayed arrival; a late
   or old sample never moves it back. One process (embedded) has no clock
   drift; a remote client's drift policy is the remote task's (Out of scope).
3. **A sample that follows rest moves only in its last tick.** Samples come
   every tick only while an entity moves; at rest it is refreshed every 20
   ticks (`POLICY_SAMPLE_REFRESH_TICKS`, `crates/crpg-server/src/host.rs:131`).
   Interpolating from a rest sample at tick 100 to the first moving sample at
   tick 121 would creep for a second, so when the earlier sample has
   `moving == false` the motion is drawn over the last tick only. Between two
   moving samples the whole gap is used, which also covers a dropped sample.
4. **The buffers follow the replica, not the frames.** After each received
   frame the client compares every disclosed position with its buffer:
   newer tick → append; same tick, new value → replace the newest; older
   tick (the entity was revoked and re-anchored within one frame) → restart;
   no disclosed position → drop the buffer at once (G1's revocation rule,
   `:450–451`; T026's "no hidden entity through interpolation history",
   `tasks/T026.md:38`). The replica stores a sample only for an anchored
   entity and only if strictly newer (`crates/crpg-net/src/replica_v4.rs:143–173`),
   so the buffer never holds what the replica refused.
5. **Bounds.** 8 samples per entity (350 ms of motion at one per tick, more
   than the 100 ms delay plus a tick of jitter); the oldest is dropped. The
   number of buffers is the number of disclosed positions, already bounded by
   the replica. All time arithmetic is `i128`, because `tick × 50` and the
   product `(b − a) × elapsed` overflow `i64` near the coordinate and tick
   limits (U3, `:100–102`).
6. **T049b (the turn-based `Moved` animation) is not written now.** G1's last
   rule animates a turn-based move along its route (`:449–450`). No turn-based
   v4 scene exists: the combat demo is a v2 session (`apps/client/scripts/Main.gd:19`),
   and the walk scene is real time. Until T049b, a turn-based move in a v4
   session slides from start to end over one tick (Reading 3, since the
   pre-move sample is at rest). T049b is contracted together with the
   turn-based click (`DeclareMove`) scene.
7. **One delay for every row.** The player's own Heroes are drawn 100 ms
   late too. In-process that is the whole lag (at most one 50 ms cycle plus
   the delay) and needs no prediction (D77e).

### `core/smooth.rs` (new)
```rust
use std::collections::{BTreeMap, VecDeque};
use crpg_net::protocol::NetId;
use crpg_net::replica_v4::PositionState;

/// Milliseconds per server tick; equals `crpg_server::run::TICK_PERIOD_MS` (S8).
pub(crate) const TICK_MS: u64 = 50;
/// How far behind the estimated server time rows are drawn (ADR-0036 U7: 2 ticks).
pub(crate) const RENDER_DELAY_MS: u64 = 100;
/// Samples kept per entity; the oldest is dropped beyond this.
pub(crate) const SAMPLES_PER_ENTITY: usize = 8;

/// One buffered position.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) struct Sample {
    pub(crate) tick: u64,
    pub(crate) point: [i32; 3],   // `Point::raw()`
    pub(crate) moving: bool,
}

/// Per-entity sample buffers and the sample clock offset.
#[derive(Debug, Clone, Default, PartialEq, Eq)]
pub(crate) struct Smoother {
    buffers: BTreeMap<NetId, VecDeque<Sample>>,
    offset_ms: Option<i128>,
}

impl Smoother {
    /// An empty smoother: no buffer, no offset.
    pub(crate) fn new() -> Self;
    /// B-S1: one sample's server tick, received at `now_ms`.
    pub(crate) fn observe_clock(&mut self, server_tick: u64, now_ms: u64);
    /// B-S2: brings the buffers in line with the replica's disclosed positions.
    pub(crate) fn observe(&mut self, positions: &BTreeMap<NetId, PositionState>);
    /// B-S3: where to draw `entity` at `now_ms`; `None` without a buffer.
    pub(crate) fn render(&self, entity: NetId, now_ms: u64) -> Option<[i64; 3]>;
    /// Test seam.
    #[cfg(test)] pub(crate) fn buffer(&self, entity: NetId) -> Option<&VecDeque<Sample>>;
    /// Test seam.
    #[cfg(test)] pub(crate) fn offset_ms(&self) -> Option<i128>;
}
```

## Behaviour
Normative. Time values are `i128`. `ms(s) = s.tick × TICK_MS`.

B-S1. **`observe_clock(t, now)`**: `o = now − t × TICK_MS`; `offset_ms =
Some(o)` if it was `None`, else `Some(min(offset_ms, o))`. *Tests:* S2, S5.

B-S2. **`observe(positions)`**, for each `(id, state)` in ascending `id`,
with `s = Sample { tick: state.tick, point: state.point.raw(), moving:
state.moving }`: no buffer → a buffer `[s]`; the buffer's newest has a lower
tick → push `s` at the back, then while its length exceeds
`SAMPLES_PER_ENTITY` pop the front; same tick and `s` differs from the newest
→ replace the newest with `s`; same tick and equal → nothing; a higher tick →
the buffer becomes `[s]`. Then every buffer whose id is not a key of
`positions` is removed. *Tests:* S6.

B-S3. **`render(id, now)`**: no buffer → `None`. Else, with buffer `b`
(ascending ticks, non-empty), first that applies:
(1) `offset_ms` is `None` → the newest point;
(2) `R = now − offset_ms − RENDER_DELAY_MS`; `R >= ms(newest)` → the newest
point (hold; never extrapolate);
(3) `R <= ms(oldest)` → the oldest point;
(4) else the unique adjacent pair `a`, `c` with `ms(a) <= R < ms(c)`;
`start = ms(a)` if `a.moving`, else `max(ms(a), ms(c) − TICK_MS)`; `R <=
start` → `a.point`; else per component `a + ((c − a) × (R − start)) /
(ms(c) − start)` with Rust's truncating `/` (U5's formula). Each result is
returned as `i64` (it lies between `a` and `c`). *Tests:* S1–S4, S7.

B-S4. **`ClientV4`.** In `step`, the `MoveDown::Sample(sample)` arm calls
`self.smooth.observe_clock(sample.server_tick, now_ms)` right after
`apply_sample` (`crates/crpg-godot/src/core/client_v4.rs:136–138`), and the
body of the `while let Some(bytes) = link.recv()` loop (`:99–148`) ends with
`self.smooth.observe(self.replica.positions())`, after its update drain. A
fault returns at once, as today: the frames of the same step completed
before it stay observed (the replica keeps them too), and the faulting frame
observes nothing. Observing once after the loop instead is wrong (C1, C3). `render_positions(now)`: for each row
`i` of `self.view`: `position_known()[i] == 1` and `render(row id, now)` is
`Some(p)` → `p`; otherwise `positions()[3i..3i + 3]`. *Tests:* C1, C2, C3.

B-S5. **`BridgeCore`.** `poll(now_ms)` stores `last_poll_ms = now_ms` as its
first statement, before the panic guard and in every state (one unconditional
line). Only the `OpenV4` arm reads it, so outside a live v4 session it has no
observable effect and no test. `render_positions()`: `OpenV4(live)` →
`live.client.render_positions(self.last_poll_ms)`; every other state keeps
T050a's `self.view.positions().to_vec()`, including `Fenced`, where the view
is the last revision before the fault. *Tests:* E1, E2, and T050a's W4
unchanged.
