## Task

Implement deterministic, positioned campaign validation in `crpg-data`: a
collected semantic pass over `LoadedCampaign`, one machine-readable diagnostic
model shared by library and CLI consumers, and a deliberately broken fixture
whose exact 15-diagnostic result is checked in as a byte snapshot.

## Crate(s)

`crpg-data` (only). Consume `crpg-core` without modifying it. The only permitted
implementation artifacts outside this crate are the documentation updates named
below. Do not edit `crpg-cli`; T011b is the separate thin-wrapper task required
by E004's one-task-one-crate decision.

This is a Stage-2 specification, not a completion record. Drafting T011a/T011b
creates only those two task files; none of the source, fixtures, snapshots, or
documentation changes below are implemented by the drafting change.

## Dependencies and sequencing

T010 is committed on `master` as `15ac9fb`. T011a is the first half of spec T11
and must land before T011b starts implementation. T011a supplies all semantic
decisions and serializable diagnostic values; T011b may then own filesystem
collection, process output, and exit codes without reimplementing them.

E020 gate 8 becomes fully live only when T011b drives this API against every
current fixture. T011a proves the lower API and fixture snapshot directly but
does not add a CLI, workflow job, or placeholder gate.

## Purpose

T010 deliberately stops after fail-fast structural acceptance: syntax, schema,
layout, engine compatibility, an unambiguous ULID index, lock coverage, and the
assets-lock digest. It explicitly leaves dangling references, wrong kinds,
duplicate slugs, aggregate ownership, graph consistency, reachability, locale
coverage, asset references, and variable defaults to T011.

This task adds that semantic layer without weakening T010. Structurally invalid
input still produces one typed `DataError`; semantic validation runs only after
`load_campaign` succeeds and returns every independent finding. Both paths are
represented by the same stable `Diagnostic` wire shape so an editor or thin CLI
does not need to parse prose.

## Interface

Add public module `validation` and re-export its public items from `lib.rs`.
These signatures and variants are the required API; helper names and private
implementation structure are not prescribed.

```rust
use std::collections::BTreeMap;

use semver::Version;
use serde::{Deserialize, Serialize};

use crate::{DataError, LoadedCampaign, SourcePath};

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord,
         Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum Severity {
    Error,
    Warning,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord,
         Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum DiagnosticCode {
    Io,
    InvalidPackageId,
    InvalidPath,
    InvalidDigest,
    Malformed,
    UnsupportedSchema,
    Layout,
    EngineIncompatible,
    DuplicateId,
    PackageKindConflict,
    CandidateConflict,
    UnresolvedPackage,
    InvalidLock,
    AssetsLockMismatch,
    DuplicateSlug,
    DanglingReference,
    WrongReferenceKind,
    ForeignReference,
    AggregateOwnerMismatch,
    GraphPortMismatch,
    DuplicateGraphPort,
    UnreachableNode,
    QuestNoCompletionPath,
    MissingAsset,
    MissingLocaleKey,
    ValueTypeMismatch,
}

impl DiagnosticCode {
    pub const fn as_str(self) -> &'static str;
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
#[serde(deny_unknown_fields)]
pub struct Diagnostic {
    pub file: Option<SourcePath>,
    pub pointer: String,
    pub severity: Severity,
    pub code: DiagnosticCode,
    pub message: String,
    pub suggested_fix: Option<String>,
}

impl std::fmt::Display for Severity { /* stable lowercase text */ }
impl std::fmt::Display for DiagnosticCode { /* delegates to as_str */ }
impl std::fmt::Display for Diagnostic { /* stable positioned text */ }

pub fn diagnostic_for_data_error(error: &DataError) -> Diagnostic;

pub fn validate(campaign: &LoadedCampaign) -> Vec<Diagnostic>;

pub fn validate_files(
    files: &BTreeMap<SourcePath, Vec<u8>>,
    engine_version: &Version,
) -> Vec<Diagnostic>;

pub fn campaign_document_path(value: &str) -> Result<Option<SourcePath>, DataError>;
```

All public items, fields, and variants require useful rustdoc. `Diagnostic` and
its enums use their field names and snake_case enum names verbatim in JSON. The
machine object therefore always has exactly these six keys: `file`, `pointer`,
`severity`, `code`, `message`, and `suggested_fix`. `file` and `suggested_fix`
serialize as explicit `null` when absent; they are never omitted. Diagnostics
are not campaign documents and do not implement `JsonSchema`; the 17 generated
campaign schemas and gate-7 baseline remain unchanged.

`file` is the portable logical source path of the object containing the bad
value. It is `None` only when no source file truthfully exists, such as a missing
required file or root-level I/O failure supplied later by a caller. `pointer` is
an RFC 6901 pointer into that file; the empty string means the document root.
Escape map keys (`~` to `~0`, `/` to `~1`) at every dynamically named segment.
Position a reference diagnostic at the field containing the reference, not at
the referenced object or merely its containing document.

`Severity::Warning` reserves the stable wire value for later non-fatal policy.
Every T011a code is emitted with `Severity::Error`; clean validation is an empty
vector. `DiagnosticCode::Io` is available for filesystem-owning consumers such
as T011b, but this pure crate never performs I/O and does not emit it itself.

`Diagnostic::Display` is single-pathed and exact:

```text
<file-or-<campaign>><pointer>: <severity>[<code>]: <message>
<file-or-<campaign>><pointer>: <severity>[<code>]: <message>; suggested fix: <fix>
```

Use the second form only when `suggested_fix` is `Some`. Do not print JSON,
debug formatting, `Some(...)`, or `None` from `Display`.

`diagnostic_for_data_error` maps every existing `DataError` variant to its
same-named structural `DiagnosticCode`, error severity, stable `Display` text,
and the most precise path already carried by the error. For `DuplicateId`, use
the second path and root pointer because T010's public error does not retain a
nested pointer. Do not parse strings to recover information that `DataError`
does not carry. Suggested fixes for structural errors are optional and must not
claim a repair that is not known.

`validate_files` is the file-map entry point for T011b. It calls the existing
`load_campaign` exactly once. On error it returns a one-element vector from
`diagnostic_for_data_error`; on success it returns `validate(&loaded)`. It does
not create a second loader or collect past T010's fixed structural fail-fast
boundary.

`campaign_document_path` is the data-owned bridge between a caller's directory
walk and T010's accepted logical layout. Its input is a campaign-root-relative
string already joined with `/`, never an OS path. It returns `Some(SourcePath)`
only for the exact T010 document path families and the three required lock/root
paths, `None` for source assets, copied schemas, Lua, replays, build output, and
unrelated files, and `InvalidPath` for an accepted-family candidate whose
logical path violates `SourcePath`. Non-Unicode `OsStr` components never reach
this function; the OS-owning caller rejects them before classification (see
T011b) without lossy conversion. Refactor the loader's path predicates so
classification and layout acceptance share one implementation rather than two
lists that can drift. The function is pure and case-sensitive. Callers must
preserve classifier failures through `diagnostic_for_data_error` unchanged
(`invalid_path`); `io` is reserved for filesystem, symlink, and non-Unicode
collection failures owned by the caller, never for a classifier rejection.

## Semantic validation

`validate` is pure, deterministic, non-mutating, panic-free for public model
values, and exhaustive over all T010 model variants. It does not read files,
detect a platform, use a registry, or execute expressions/scripts/actions.

Do not trust `LoadedCampaign.index`: its fields are public and caller-mutable.
Rebuild validation-local occurrence and ownership tables from `documents` in
lexical `SourcePath` order and authored array order. The first occurrence wins
only for subsequent lookup; every later occurrence gets `duplicate_id` at its
own `/id` pointer and names the first location. A normal `load_campaign` result
cannot contain duplicate ids because T010 rejects them, but this defensive pass
pins `validate` to document truth and satisfies direct API callers. T011b still
reports T010's first duplicate-id load failure as one structural diagnostic.

Collect all independent findings, then sort the final vector by:

```text
(file, pointer, code.as_str(), severity, message, suggested_fix)
```

`None` sorts before `Some(file)`. Do not rely on enum declaration order, hash
iteration, document insertion order, or diagnostic discovery order. Do not
deduplicate distinct occurrences. Identical diagnostics from the same bad value
must not be emitted twice by overlapping walkers.

### References and ownership

Every typed ULID reference is checked at its exact pointer. A missing id emits
`dangling_reference`. An existing id outside the allowed `ObjectKind` set emits
`wrong_reference_kind`. A local node/state id with the right kind but owned by a
different dialogue, quest, or graph emits `foreign_reference`. Do not also emit
wrong-kind or dangling diagnostics for the same reference.

Required kind rules:

| Reference | Allowed kind |
|---|---|
| `Campaign.entry.world` | World |
| `Campaign.entry.area` | Area |
| `Campaign.entry.spawn` | Placement |
| `World.areas[*]` | Area |
| `Area.neighbours[*]` | Area |
| `Creature.faction` | Faction |
| `Creature.inventory[*]` | Item |
| `Faction.relations[*].faction` | Faction |
| `Placement.prefab` | Creature or Item |
| dialogue NPC speaker | Creature or Placement |
| dialogue `Link.target` | Dialogue |
| `NodeBody::CallGraph.graph_id` | Graph |
| `DataValue::ObjectRef` | any indexed authored-object kind |

Dialogue entry/next/jump/player-choice targets must be `DialogueNode`s owned by
that dialogue. Quest entry and transition targets must be `QuestState`s owned
by that quest. Graph start, edge endpoints, and sequence children must be Nodes
owned by that graph. The same graph rules apply to standalone Graph documents
and graphs embedded in Triggers documents.

Walk `DataValue` recursively everywhere T010 permits one: placement overrides;
world, campaign, and graph-local variable defaults; branch cases; all action,
script, and graph-call argument maps; dialogue and quest action arguments; and
asset import settings. Locate an object reference at its tagged value's
`/value` member, including escaped map-key and list-index segments.

Aggregate owner fields have one specialized check and do not also produce a
generic reference diagnostic. `PlacementsDocument.area` and
`TriggersDocument.area` must equal the id in their sibling `area.json`.
`LocaleDocument.campaign` and `VariablesDocument.campaign` must equal the root
`campaign.json` id. Missing sibling/root, wrong kind, or unequal id emits one
`aggregate_owner_mismatch` at `/area` or `/campaign`.

### Slugs and typed defaults

Slugs are unique within `ObjectKind`, across the entire loaded campaign and
regardless of path: root entities, placements, and standalone/embedded graphs
all participate. Sort occurrences by `(path, pointer)`; retain the first and
emit `duplicate_slug` at `/slug` for each later occurrence, naming the first
location. Equal text in different object kinds is valid. Dialogue nodes and
quest states do not acquire synthetic slugs.

For every `VarDecl`, the outer `DataValue` variant must match `ValueType`.
`List` and `Map` describe only the outer container, as in T010; there is no
homogeneous element rule. A mismatch emits `value_type_mismatch` at that
declaration's `/default`. Do not evaluate expression strings or validate
symbolic stat, tag, action, script, or custom-trigger vocabularies.

### Event graphs

After reference checks, validate each edge against its resolved local source
node:

| Source body | Allowed edge port |
|---|---|
| `Condition` | `True`, `False` |
| `Branch { cases }` | `Case { index }` where `index < cases.len()` |
| every other `NodeBody` | `Next` |

An incompatible/out-of-range port emits `graph_port_mismatch` at
`/edges/<i>/port`. At most one edge may use the same `(from, port)` in a graph;
each later one emits `duplicate_graph_port` at its port. Missing outbound edges
are valid, including the one-node Wait graph in T010's fixture.

When `start` resolves to a local node, traverse local edges plus Sequence child
references from it. Emit `unreachable_node` at each unreachable node object's
pointer. If start is invalid, suppress graph reachability findings because the
positioned start-reference diagnostic is the actionable root cause. Do not run
nodes, enforce a budget, infer implicit edges, or inspect opaque expressions.

### Dialogue and quests

When a dialogue entry resolves locally, traverse `NpcLine.next`,
`PlayerChoice.next`, and `Jump.target`; `End` and `NpcLine { next: None }` stop,
and `Link` leaves the local dialogue. Emit `unreachable_node` at each unreachable
dialogue-node object. Suppress this analysis when the entry itself is invalid.

For a quest with a valid local entry, follow transitions and ask whether any
reachable state has `terminal == true`. If not, emit exactly one
`quest_no_completion_path` at `/entry`. Invalid transitions retain their own
reference diagnostics and may also leave the currently authored quest without
a completion path. If the entry is invalid, suppress the completion diagnostic.
T011a does not add quest execution semantics or require every state reachable.

### Locale and assets

Every T010 `name` field, every `QuestState.name`, and every dialogue `text_key`
is a locale key. For each referring field, require that key in every loaded
LocaleDocument. Emit one `missing_locale_key` per missing `(reference, locale)`
and identify the locale in message/fix text. If there are no locale documents,
emit one missing-key diagnostic per unique referring field, stating that no
locale table exists. Unused strings are valid. Aggregate owner errors do not
silence coverage checks in other valid locale tables.

`Area.ambience`, when present, is the only T010 asset-reference field. It must
exactly match a `SourcePath` key in `AssetsLock.assets`; absent or invalid text
emits `missing_asset` at `/ambience`. Validation checks lock membership, not OS
file existence or content hashes; T010 already owns lock syntax and digest
integrity.

## Constraints

- One task = one crate. No `crpg-cli`, testkit, rules, sim, core, contracts,
  workflow, lint, root manifest, deny policy, or toolchain edit.
- Add no dependency. Existing serde/serde_json, semver, core primitives, and
  ordered standard collections are sufficient. `Cargo.lock` must not change.
- Preserve `#![forbid(unsafe_code)]` and `#![warn(missing_docs)]`.
- Apply data's T010 discipline to source, tests, and doctests: no
  `HashMap`/`HashSet`, `f32`/`f64`, floats, runtime OS branches, clocks, threads,
  generated ids, filesystem access, or nondeterministic iteration.
- Do not alter campaign wire models or generated schemas to carry diagnostics.
  A diagnostic points into source; it is not persisted in source.
- Do not turn T010 structural failures into a collected best-effort parser,
  weaken its validation order, trust its mutable index, or silently skip a
  broken snapshot.
- Do not invent expression evaluation, symbolic registries, geometry checks,
  source-asset I/O, ruleset validation, migrations, or runtime conversion.
- Windows/MSVC is primary and Linux/GNU headless is fully supported. Diagnostics
  and snapshot bytes are portable and identical; there is no target baseline.
