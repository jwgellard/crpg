# T025a — N-RECONNECT resync mechanisms (`crpg-net`)

Status: **contract proposed, awaits the user's approval.**

## Task / Crate(s) / Purpose

Sole crate: `crpg-net`, Phase 4. **D12 selected** (see
[decision record](POST-T018-DECISIONS.md#d12--reconnect-30-second-same-process-grace));
exact resume/authentication/version contract plus T024 remain. Supply mechanisms for host-owned grace;
net does not decide who may reclaim a session.

## Interface

Before code append exact versioned resume request/result shapes: proof-bearing
opaque credential representation/limit (never identity by claimed epoch alone),
session epoch, per-lane receipt progress, snapshot replacement/cutover and
connection-fencing generation. Pin errors, direction, tags, byte/count caps,
token redaction and encode/decode/reassembler signatures in the protocol ADR.
Keep existing v1 lane-0 codecs and seq meanings unchanged. No implicit token
format, crypto dependency or “trusted reconnect” test hook is approved.

## Behaviour

Mechanisms carry host-approved resumption decisions and install a full filtered
snapshot atomically before post-cutover deltas. Commands in flight retain their
original epoch/lane/seq/canonical bytes; no rewritten observed tick on retry.
Do not reset sequence/dedup state at reconnection. Reject cross-epoch snapshots,
unknown versions and replay from fenced connections. Obsolete partial transfer
cannot overwrite a later resync. Token lifetime/control/grace belongs to T025b.

## Constraints

[Standing rules](POST-T018-RULES.md) apply. Net only; no host auth/control/AI,
persisted ledger or new dependency. If T024 already supplies a required shape,
reuse it; additional closed variants need their own reviewed version. Preserve
B3 per-lane identity and B5 tightening-only policy versus hard-max distinction.

## Test

Public `reconnect_wire`: exact approved messages round-trip; unknown/oversized/
truncated/cross-epoch/stale-fencing rejections each with valid controls;
snapshot/delta cutover and command retry identity; duplicate/late/old-transfer
delivery; independent filtered replica oracle with corruption negative control.
Use an explicit decision input from a host stand-in, never claim it proves auth.

```text
cargo test -p crpg-net --test reconnect_wire --locked
cargo test -p crpg-net --test snapshot_transfer --locked
cargo test -p crpg-net --test codec --locked
cargo clippy -p crpg-net --all-targets --locked -- -D warnings
```

Common native gates then stopping command: `cargo test -p crpg-net --locked`.

## Definition of done

- [ ] D12 exact mechanism/version approved; v1 compatibility retained.
- [ ] Atomic resync and retry identity tests pass on both native targets.
- [ ] Common DoD; docs distinguish mechanism from authenticated host policy.

## Out of scope

Grace timer policy, AI takeover, persistence across process restart,
credentials issuance/verification implementation and authoritative gameplay.

### S§1. Findings (from the code)

1. **Nothing for resume exists.** `lib.rs` declares ten modules
   (`crates/crpg-net/src/lib.rs:28-37`), and none of them has a resume type,
   byte, tag or credential. `SessionEpoch`'s doc says "session reattachment
   is not supported in v1" (`protocol.rs:202-207`). That stays true of the
   lane-0 v1 wire, so `protocol.rs` is not edited. Reattachment arrives as a
   separate subprotocol.
2. **The epoch is inside every command's identity.** `IntentFrame.epoch`
   is encoded in every intent (`protocol.rs:244-258`), and the retry cache
   compares whole canonical bytes (`tests/support/driver.rs:433-445`). A
   resume that rotated the epoch could never return a cached receipt: the
   retried bytes still carry the old epoch. **So the epoch must be
   retained, and connection fencing needs a separate generation.**
3. **Rebinding a driver peer resets the ledger.** `NetDriver::bind_peer`
   replaces the peer's `PeerState` (`tests/support/driver.rs:277-287`).
   `PeerState::new` starts `next_new_seq` at 1 with an empty cache and full
   budgets (`sim.rs:253-271`). Nothing in this contract calls either.
4. **The receiver pool has no rebind.** `add_receiver` starts a receiver
   with `next_event_seq = 1`, `retired_through = 0` and `published = None`
   (`reassembly.rs:491-523`). `remove_receiver` only frees accounting
   (`:524-533`). Remove-then-add therefore drops the two floors that refuse
   obsolete transfers: `StaleTransfer` (`id ≤ retired_through`, `:641-644`)
   and `BehindReplica` (`:649-660`).
5. **Rebind can be built from two existing behaviours.** A `Cancel`
   discards the in-flight transfer, retires the id and sets
   `AwaitSnapshot` without setting `resync` (`handle_cancel`,
   `:852-883`). The `Overflow` failure drops held deltas
   (`fail_in_flight`, `:563-580`). T024 S§10.4 keeps already-queued updates
   "because they were valid when released".
6. **A credential precedent exists one crate up.**
   `crpg_net_quic::handshake::Credential` is 16..=128 opaque bytes, with no
   `PartialEq` and no `Display`. Its `Debug` prints exactly
   `Credential(<redacted>)`, and `ct_eq` is an XOR fold with no early exit,
   passed through `core::hint::black_box`
   (`crates/crpg-net-quic/src/handshake.rs:17-20`, `:62-105`). `crpg-net`
   cannot depend on `crpg-net-quic` (the dependency goes the other way), so
   the resume proof is its own type with the same bounds and rules.
7. **`0x82` is taken.** T024 S§5.4 reserves it for transfer version 2, and
   `snapshot_transfer` pins it as `UnsupportedVersion` on the transfer
   decoders (`tests/snapshot_transfer.rs:1141-1142`, `:1275`). The first
   bytes in use are 1, 2 and `0x81`. Lanes 0 and 2 are in use, and lane 1
   is reserved for D13 movement (`protocol.rs:27-34`).
8. **The `/2` channel set is closed.** T024q gives `crpg-lane0/2` the
   channel values `{0x00, 0x81}`. Each value names exactly one codec, and
   "any other subprotocol needs its own channel value, which is a framing
   change and therefore a new ALPN" (Q§5.2, Q§13). The `/2` hello is read
   by the `/1` code (Q§5.1). `crpg-server` matches `ServerEvent`
   exhaustively (`crates/crpg-server/src/quic.rs:481-492`), as it does
   `SendError` and `ServerError` (Q§1 item 6). A new variant on any of the
   three breaks `crpg-server`'s build.
9. **Driver retry facts.** A cached retry returns its original status with
   no execution. `executions` counts only a successful `perform_action`
   (`tests/support/driver.rs:532-536`). Different bytes at a cached seq give
   `SeqConflict`, which closes the epoch (`:448-451`). An `EndTurn` by the
   actor that does not hold the turn is `Rejected(IllegalAction)`.
10. **Test baseline at this tip:** 165 `#[test]` functions in
    `crates/crpg-net/tests/` (audit_gaps 1, codec 28, conformance 22,
    events_v2 6, snapshot_transfer 31, snapshot_transfer_contract 46,
    token_bucket_regression 3, transport 28), and none in `src/`.

### S§2. Decisions, and how the drafts' disagreements were settled

1. **A separate resume subprotocol, first byte `0x91`, lane 3.** The high
   nibble names a subprotocol family and the low nibble its version: `0x8_`
   is transfer (`0x81` now, `0x82` reserved by T024 S§5.4), `0x9_` is
   resume. Both drafts used `0x82`, which collides with the T024
   reservation. Lane byte `LANE_SESSION = 3` (DeepSeek's lane; Beam's lane
   0 would make lane 0 mean two vocabularies). Tags are disjoint from every
   existing tag: downstream `0x30` Ticket, `0x31` Accepted, `0x32`
   Rejected; upstream `0x40` Request.
2. **Over QUIC, resume frames take a third `/2` channel value, `0x91`**
   (one value, one codec, as in Q§5.2). The request replaces the hello on a
   resume connection, and the result replaces the welcome (S§20). This
   needs an amendment to T024q before it is approved, not a follow-on ALPN
   (S§26 Q2). `tasks/T024q.md` is not edited here.
3. **Epoch retained; a separate per-session `ConnectionFence`.** The fence
   starts at 1 for a session's first connection, and each accepted resume
   grants `current + 1`. It never appears on a lane-0 or transfer frame,
   so those bytes stay identical: the host keeps it per connection. The
   request presents the last fence the client held. Grants are never
   re-issued, which fixes DeepSeek's "replay returns the same grant" (that
   leaves two live connections with the same tag). Beam's saturating
   generation fails the same way at `u64::MAX`. A lost result is
   recoverable through the window rule of S§15.
4. **Explicit decision input; net never authorises.** `SessionFence::resolve`
   takes a `ResumeDecision` (`Accept { progress }` or `Reject(reason)`) that
   the caller builds after authenticating. Net checks only epoch, fence
   order and shape. There is no trusted flag, no test hook, and no API that
   produces `Accepted` without `Accept`.
5. **An opaque proof, `ResumeProof`,** 16..=128 bytes (the crpg-net-quic
   credential bounds, S§1 item 6), with a raw `u8` length. It has no
   `PartialEq`, `Eq`, `Ord`, `Hash` or `Display`, its `Debug` is exactly
   `ResumeProof(<redacted>)`, and it has the same `ct_eq`. The drafts used
   1..=256 with a length-revealing `Debug` (Beam) and 1..=64 with no
   `ct_eq` (DeepSeek); a 1-byte proof is too weak to accept. **A downstream
   `Ticket` message carries the proof to the client.** Neither draft had
   one, so T025b would have needed a second net task to deliver
   server-issued proofs (D12).
6. **Advisory claims in, authoritative progress out.** The request carries
   one `LaneClaim { lane, receipted_through }` per command lane, and the
   accepted result carries `LaneProgress { lane, finalized_through }`,
   taken from the host's decision. Both are keyed by lane (B3). Lane 0 is
   the only assigned lane in resume version 1. A claim never changes any
   state or result. Beam's per-lane `last_event_seq` mixed the delta
   cursor with command identity. DeepSeek's `next_new_seq` +
   `retained_from` are replaced by "through" values (0 = none), matching
   the `cursor`/`after` precedent of T024.
7. **Two cause-neutral rejections: `Denied` (1) and `Busy` (2).** There is
   no `Expired` (it would tell an unauthenticated caller that a session
   existed) and no per-cause codes (Beam's six). Any net refusal is
   answered by the host as `Denied` (S§21 H4).
8. **`rebind_receiver` keeps the floors and fails closed.** It keeps the
   epoch, wire, `published`, `next_event_seq`, `retired_through` and the
   already-queued updates. It discards and retires the in-flight transfer,
   drops held deltas, sets `AwaitSnapshot` and clears `resync`. DeepSeek
   also dropped queued updates, which contradicts T024 S§10.4. Beam had no
   rebind, which leaves a stale partial transfer live and the receiver in
   `Live` mode.
9. **No new `TransferError` or `CodecError` variant.** Codec errors are the
   six existing `CodecError` variants; mechanism errors are a new closed
   `ResumeError`.
10. **v1, v2 and `0x81` stay byte-identical.** No existing codec, tag, cap,
    seq meaning or test changes; the only edit to an existing source module
    is the additive `rebind_receiver` in `reassembly.rs`.

### S§5. Version, lane, direction and tags

| Item | Value | Rule |
|---|---|---|
| First byte | `RESUME_VERSION = 0x91` | any other byte is `UnsupportedVersion`; the v1, v2 and transfer decoders already refuse `0x91` the same way |
| Lane | `LANE_SESSION = 3` | any other byte is `WrongDirection` |
| Downstream (host → client), ≤ 4,096 B | `0x30` Ticket, `0x31` Accepted, `0x32` Rejected | `decode_request` reads these tags as `WrongDirection` |
| Upstream (client → host), ≤ 4,096 B | `0x40` Request | `decode_down` reads it as `WrongDirection` |
| Any other tag | — | `UnknownMessage` |

The channel or transport chooses the codec (D11, T024 S§4). No decoder
inspects a frame to guess its protocol, and none falls back to another.
Compile-time checks in `protocol_resume.rs`:

```rust

const _: () = assert!(RESUME_VERSION != crate::protocol_v2::PROTOCOL_VERSION);
```

### S§6. Wire layout (exact field order)

Encoding uses the existing `postcard` primitives, as `codec_transfer`
does: a raw byte for `u8`, an LEB128 varint for `u64`, and `[u8; 16]` raw.
Each frame starts `0x91`, `0x03`, then the tag.

#### S§6.1 Upstream

| Tag | Fields after the tag, in order |
|---|---|
| `0x40` Request | `epoch [u8;16]`, `fence u64` (≥ 1), `proof_len u8` (16..=128), `proof_len` bytes, `lane_count u8` (1..=4), then `lane_count` × (`lane u8`, `receipted_through u64` (≤ `SEQ_LAST`)) |

#### S§6.2 Downstream

| Tag | Fields after the tag, in order |
|---|---|
| `0x30` Ticket | `epoch [u8;16]`, `proof_len u8` (16..=128), `proof_len` bytes |
| `0x31` Accepted | `epoch [u8;16]`, `granted u64` (≥ 2), `lane_count u8` (1..=4), then `lane_count` × (`lane u8`, `finalized_through u64` (≤ `SEQ_LAST`)) |
| `0x32` Rejected | `epoch [u8;16]`, `reason u8` (1 `Denied`, 2 `Busy`) |

`granted` is at least 2 because a session's first connection holds fence 1
and every grant is above the fence it replaces.

#### S§6.3 The lane-list rules ("L-rules")

These apply to request claims, accepted progress and decision progress
alike, in this order:

1. `lane_count` 0 is `Malformed`; above `MAX_RESUME_LANES` (4) it is
   `LimitExceeded`. On decode, both are checked before any entry is read.
2. For each entry in order:
   - (a) a lane other than `LANE_COMBAT` (0) is `UnknownMessage` (the
     unassigned-value precedent);
   - (b) at index > 0, a lane ≤ the previous lane is `Malformed`;
   - (c) the `u64` is read (on decode); a value above `SEQ_LAST` is
     `Malformed`.

In resume version 1 a valid list therefore has exactly one entry, lane 0.
The count field lets D13's movement lane join later at the same layout,
but accepting lane 1 is still a new resume version and its own review
(B5).

#### S§6.4 Literal examples (`Z` = 16 × `00`, `P` = 16 × `AA`)

| Id | Value | Bytes | Len |
|---|---|---|---|
| L1 | Request { Z, fence 1, P, [(0, 0)] } | `91 03 40` Z `01` `10` P `01 00 00` | 40 |
| L2 | Request { Z, fence 300, P, [(0, 900)] } | `91 03 40` Z `AC 02` `10` P `01 00 84 07` | 42 |
| L3 | Ticket { Z, P } | `91 03 30` Z `10` P | 36 |
| L4 | Accepted { Z, granted 2, [(0, 0)] } | `91 03 31` Z `02 01 00 00` | 23 |
| L5 | Accepted { Z, granted 301, [(0, 900)] } | `91 03 31` Z `AD 02 01 00 84 07` | 25 |
| L6 | Rejected { Z, Denied } | `91 03 32` Z `01` | 20 |
| L7 | Rejected { Z, Busy } | `91 03 32` Z `02` | 20 |

Bounds:

- Largest request: 170 bytes (epoch `FF`×16, fence `u64::MAX` = `FF`×9
  `01`, a 128-byte proof with length byte `80`, one claim
  `(0, SEQ_LAST)` = `00 FE` `FF`×8 `01`).
- Smallest request: L1, 40 bytes.
- Ticket: largest 148 bytes, smallest L3 (36).
- Accepted: largest 41 bytes (granted `u64::MAX`, `(0, SEQ_LAST)`),
  smallest L4 (23).
- Rejected: always 20 bytes.

Every frame is far below 4,096.

### S§7. Codec rules and error precedence

The errors are the six existing `CodecError` variants, re-exported (the
`codec_transfer` precedent). First failure wins:

1. **Whole-frame cap, before any read.** Input over 4,096 bytes is
   `FrameTooLarge`, in both decoders.
2. Empty input is `Malformed`. A first byte other than `0x91` is
   `UnsupportedVersion`.
3. A missing lane byte is `Malformed`; a lane other than 3 is
   `WrongDirection`.
4. A missing tag is `Malformed`. The other direction's tag is
   `WrongDirection`; any other unknown tag is `UnknownMessage`.
5. **Fields left to right, each checked when read:**
   - A missing or truncated field is `Malformed`, including `epoch`.
   - `u64` fields are read with postcard's `u64` (`take::<u64>`). A
     ten-byte varint whose last byte exceeds 1 (`FF`×9 `02`, T024's
     `overflow_varint`) is `Malformed`.
   - A `fence` of 0 is `Malformed`. A `granted` of 0 or 1 is `Malformed`.
   - `proof_len` (raw `u8`): below 16 (0 included) is `Malformed`; above
     128 is `LimitExceeded`. Both are checked **before** body availability.
     Then fewer than `proof_len` bytes remaining is `Malformed`. The proof
     is copied from an already-bounded slice.
   - Lane lists follow the L-rules (S§6.3). The count is a raw `u8`
     compared before anything is read, and the vector grows by push.
   - A `reason` byte other than 1 or 2 is `UnknownMessage`.
6. Trailing bytes are `Malformed`.

**Encode** checks the same rules in the same field order, then the frame
cap, and never returns partial bytes. The types make most invalid values
unrepresentable: `ConnectionFence` is never 0, `ResumeProof` is always
16..=128, and `ResumeRejection` is closed. So encode can fail only on:

- a lane list (L-rules);
- an `Accepted` whose `granted` is 1 (`Malformed`), checked before its
  progress list.

`ResumeRequest::validate` and `ResumeResult::validate` are exactly those
routines, shared by encode and by T025a2.

Implementation notes for the cheap path:

- The private `take`/`extend` helpers are duplicates written for this
  module, as `codec_transfer` did (`codec_transfer.rs:11-21`); `codec.rs` is
  not touched.
- One private `check_lanes(entries: &[(u8, u64)]) -> Result<(), CodecError>`
  implements the L-rules for encode, `validate` and T025a2.
- Tags are matched as explicit `u8` values, never derived serde tags
  (crate trap 1).

#### S§9.1 `protocol_resume`

```rust
use crate::codec::CodecError;

pub const RESUME_VERSION: u8 = 0x91;
pub const LANE_SESSION: u8 = 3;
pub const RESUME_TAG_TICKET: u8 = 0x30;
pub const RESUME_TAG_ACCEPTED: u8 = 0x31;
pub const RESUME_TAG_REJECTED: u8 = 0x32;
pub const RESUME_TAG_REQUEST: u8 = 0x40;
pub const MAX_RESUME_FRAME_BYTES: usize = crate::protocol::MAX_INTENT_FRAME_BYTES;
pub const MIN_RESUME_PROOF_BYTES: usize = 16;
pub const MAX_RESUME_PROOF_BYTES: usize = 128;
pub const MAX_RESUME_LANES: usize = 4;
// plus the S§5 compile-time checks.

/// A session's connection generation. A session's first connection holds
/// `FIRST`; each accepted resume grants the next value. Never 0. Not a
/// secret and not a credential: it orders connections, it proves nothing.
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct ConnectionFence(u64);
impl ConnectionFence {
    pub const FIRST: ConnectionFence = ConnectionFence(1);
    pub fn new(raw: u64) -> Option<ConnectionFence>; // None for 0
    pub fn get(self) -> u64;
}

/// Host-issued, session-bound resume proof: opaque bytes, 16..=128 long.
/// No format and no meaning here. No `PartialEq`/`Eq`/`Ord`/`Hash`/`Display`.
#[derive(Clone)]
pub struct ResumeProof(Vec<u8>);
impl ResumeProof {
    /// Below 16 bytes (0 included): `Err(Malformed)`; above 128: `Err(LimitExceeded)`.
    pub fn new(bytes: Vec<u8>) -> Result<ResumeProof, CodecError>;
    pub fn as_bytes(&self) -> &[u8];
    /// Constant-time equality over equal lengths (unequal lengths: false
    /// without reading content); XOR fold, no early exit, `black_box`.
    pub fn ct_eq(&self, expected: &[u8]) -> bool;
}
impl core::fmt::Debug for ResumeProof {} // writes exactly "ResumeProof(<redacted>)"

/// Advisory: the highest seq on `lane` for which the client holds a
/// terminal receipt (0 = none). Never changes host state.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct LaneClaim { pub lane: u8, pub receipted_through: u64 }

/// Authoritative: the highest seq on `lane` the host finalized (0 = none).
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct LaneProgress { pub lane: u8, pub finalized_through: u64 }

/// Upstream `0x40`. `Debug` is redacted through `ResumeProof`.
#[derive(Debug, Clone)]
pub struct ResumeRequest {
    /// The retained session epoch the client claims (not identity by itself).
    pub epoch: [u8; 16],
    /// The last fence the client held on this session.
    pub fence: ConnectionFence,
    pub proof: ResumeProof,
    pub claims: Vec<LaneClaim>,
}
impl ResumeRequest {
    /// The L-rules on `claims`.
    pub fn validate(&self) -> Result<(), CodecError>;
}

/// Downstream `0x30`: the proof a later resume of `epoch` must present.
#[derive(Debug, Clone)]
pub struct ResumeTicket { pub epoch: [u8; 16], pub proof: ResumeProof }

#[repr(u8)]
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ResumeRejection {
    /// Resumption is impossible: start a new session.
    Denied = 1,
    /// Not now: the session is retained; the same request may be retried.
    Busy = 2,
}
impl ResumeRejection {
    pub fn as_u8(self) -> u8;
    pub fn from_u8(raw: u8) -> Option<ResumeRejection>; // Some only for 1, 2
}

/// Downstream `0x31`.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ResumeAccepted {
    pub epoch: [u8; 16],
    /// The fence this connection now holds.
    pub granted: ConnectionFence,
    pub progress: Vec<LaneProgress>,
}

/// Downstream `0x32`.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct ResumeRejected { pub epoch: [u8; 16], pub reason: ResumeRejection }

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum ResumeResult { Accepted(ResumeAccepted), Rejected(ResumeRejected) }
impl ResumeResult {
    pub fn epoch(&self) -> [u8; 16];
    /// Accepted: `granted` ≥ 2 (`Malformed`), then the L-rules on `progress`.
    /// Rejected: always `Ok`.
    pub fn validate(&self) -> Result<(), CodecError>;
}

/// Every downstream resume frame.
#[derive(Debug, Clone)]
pub enum ResumeDown { Ticket(ResumeTicket), Answer(ResumeResult) }
```

`ResumeDown::Answer` holds `Accepted` (tag `0x31`) or `Rejected` (`0x32`).
The variant is not named `Result`, so a `use ResumeDown::*` cannot shadow
`std::result::Result`.

### S§10. The resume proof

| Rule | Decision |
|---|---|
| Representation | `ResumeProof(Vec<u8>)`, private field; `new` enforces 16..=128; `as_bytes` for the host's verifier |
| Format | None: no UTF-8, prefix, version, embedded epoch, expiry, parsing or normalisation. `00 FF 80 7F …` is as valid as ASCII |
| Identity | Never the claimed epoch alone. A request without a proof cannot be built or decoded, and `Accepted` comes only from an explicit `ResumeDecision::Accept` (T025a2). The host authenticates with the proof it issued (S§21 H3) |
| Redaction | `Debug` writes exactly `ResumeProof(<redacted>)`: no bytes and no length. `ResumeRequest`, `ResumeTicket` and `ResumeDown` derive `Debug` and are redacted through it. There is no `Display`. `CodecError` and `ResumeError` carry no bytes. Net logs nothing |
| Comparison | No `PartialEq`/`Eq`/`Ord`/`Hash`; `ct_eq` only, the reviewed crpg-net-quic algorithm (ADR-0026 item 3). Tests compare `as_bytes()` |
| Zeroisation | Not performed and not claimed: no `zeroize`, and `unsafe` is forbidden. The host must not log, print, checkpoint or persist proofs (ADR-0026 item 2's rule) |
| Issuance | Not here. The host generates proof bytes (T025b/T040) and sends them in a `Ticket` |

### S§15. Session fence behaviour

State: `epoch`, current fence `c`, confirmed fence `k`, and `max_fence`,
with `1 ≤ k ≤ c ≤ max_fence`. `k` is the highest fence on which a frame
has been checked; the window `[k, c]` is the set of fences a request may
present.

#### S§15.1 `check_frame(tag)`

| `tag` | Result | Change |
|---|---|---|
| `== c` | `Ok(())` | `k = c` |
| `< c` | `Err(Fenced)` | none |
| `> c` | `Err(UnknownFence)` | none |

#### S§15.2 `check_request(request)`, first failure wins

1. `request.epoch != epoch` → `WrongEpoch`.
2. `request.fence > c` → `UnknownFence`.
3. `request.fence < k` → `StaleFence`.
4. `c == max_fence` → `FenceExhausted`.
5. `Ok(c + 1)`.

#### S§15.3 `resolve(request, decision)`

1. `check_request`. On an error, return it; nothing changes.
2. `Reject(reason)` → `Ok(ResumeResult::Rejected(ResumeRejected { epoch,
   reason }))`; nothing changes.
3. `Accept { progress }`: if `progress` breaks the L-rules →
   `Err(InvalidProgress)`; nothing changes.
4. Set `c = c + 1` (leaving `k` unchanged) and return
   `Ok(ResumeResult::Accepted(ResumeAccepted { epoch, granted: c,
   progress }))`.

The request's claims are never read. They are advisory input for the
host's own policy (S§21 H3).

#### S§15.4 `check_result(epoch, presented, result)`

1. `result.epoch() != epoch` → `WrongEpoch`.
2. `Accepted` with `granted ≤ presented` → `StaleFence`.
3. Otherwise `Ok(())`. A `Rejected` with the right epoch is `Ok`.

#### S§15.5 What the window guarantees

- **Grants strictly increase and are never re-issued.** Each grant is a new
  `c`. Combined with H2 (the host tags only the connection a grant was
  issued to), at most one connection of a session can pass `check_frame`
  at any time.
- **A lost result is recoverable.** Suppose the client presents `n`, `c`
  becomes `n + 1`, and the result dies with its connection. No frame was
  ever checked on `n + 1`, so `k ≤ n`, and the client's retry presenting
  `n` is inside the window. It is granted `n + 2`, which fences the lost
  `n + 1`.
- **Racing attempts converge.** Once any connection's frame confirms its
  grant, `k` rises past every older presented fence, so older attempts get
  `StaleFence`.
- **Nothing lowers `c` or `k`.** There is no restore or reset API. A host
  that built a second `SessionFence` for a live session would un-fence its
  old connections, and H1 forbids it.

### S§16. Receiver rebind (`rebind_receiver(id, now_ms)`)

In one call, in this order:

1. Clamp `now_ms` to at least the pool's last value and run the pool-wide
   expiry sweep (T024 S§10.5). This may itself fail this receiver's
   in-flight transfer as `Expired`.
2. Unknown `id` → `Err(UnknownReceiver)`. Nothing else changes.
3. If a transfer is in flight, discard it: free its reservation, set
   `retired_through = max(retired_through, its id)`, and set
   `discarded = Some(id)`.
4. Drop every **held** delta. Subtract its encoded length from the
   receiver's held bytes and from the pool's `held_delta_bytes`, and set
   `dropped_deltas` to the count.
5. Set mode `AwaitSnapshot` and `resync = None`.
6. Keep `epoch`, `wire`, `published`, `next_event_seq`, `retired_through`
   (apart from step 3), and every already-queued update with its
   accounting.
7. Return `Ok(Rebound { discarded, dropped_deltas })`.

Consequences:

- A second rebind is an idempotent no-op apart from the mode.
- Late chunks of the discarded transfer are `StaleTransfer`.
- The resume snapshot's `Begin` passes `BehindReplica` exactly when its
  cursor is at least `next_event_seq − 1` and its base tick at least the
  published one, which the host guarantees by S§21 H5.
- Held deltas from the old connection are at or below the resume
  snapshot's cursor, so dropping them is invisible to the replica.
- No delta from the new connection is applied before the snapshot
  publishes.

### S§17. Command retry identity and no reset

| Net never | Why |
|---|---|
| rotates the epoch on resume | the retried canonical bytes carry it (S§1 item 2; D12) |
| touches `PeerState`, the retry cache, `next_new_seq`, `TokenBucket`s or `event_seq` | D12 retains them, and budgets are not replenished; this contract has no API that could |
| re-encodes an intent | a retry is the original canonical bytes, `observed_tick` included (D12); a rewritten byte at a cached seq is `SeqConflict` (S§1 item 9) |
| treats a `LaneClaim` as authority | only the host's `LaneProgress` is reported (S§15.3) |

The client rule (S§21 C4) is to resend each pending intent's stored bytes
unchanged after `Accepted`:

- If its seq is at or below `finalized_through`, the host returns the
  cached receipt with no execution.
- Otherwise the command is admitted as new, and freshness is judged on its
  original `observed_tick`.

### S§20. Carriage over QUIC (requirements on T024q)

`crpg-net` moves no bytes, so this section states what the transport must
do:

1. **TR1, channel.** A resume frame is one opaque frame on the `/2` lane
   stream under channel value **`0x91`** (= `RESUME_VERSION`; one value,
   one codec, as in Q§5.2). No reader chooses a channel from payload bytes.
2. **TR2, resume-first connection.** On a new connection, the client's
   first lane-stream frame is either today's hello (bytes unchanged) or
   **one** `[0x91][len24]` frame of at most 4,096 bytes carrying a
   `ResumeRequest`. Any other first header byte is refused as today.
3. **TR3, answer.** The server answers a resume frame with exactly one
   `[0x91][len24]` frame carrying the `ResumeResult`, in place of the
   welcome. After a `Rejected` it closes the connection; T025b picks the
   code (recommended: `AuthRefused` (5) for `Denied`, `ServerBusy` (7)
   for `Busy`).
4. **TR4, one total order.** After an `Accepted`, the connection carries
   `0x00`, `0x81` and `0x91` frames in one total order per direction, so
   the result precedes the resume snapshot's `Begin`, and the `Begin`
   precedes every later delta (T024 S§11 item 3). Tickets ride `0x91`
   downstream after a welcome or an `Accepted`. An upstream `0x91` frame
   after the first frame is a protocol violation (close 2).
5. **TR5, caps.** The `0x91` channel uses the shared direction caps (4,096
   up, 65,536 down, Q§5.3). The net decoders refuse anything above 4,096.
6. **TR6, no new variant** on `ServerEvent`, `SendError` or `ServerError`,
   because `crpg-server` matches all three exhaustively (S§1 item 8). A
   resume-first arrival therefore needs its own poll method or event type.

**What T024q must change if S§26 Q2 is approved** (an amendment before its
approval; `tasks/T024q.md` is not edited here):

- Q§5.2 gains the row `0x91` `Channel::Resume`, with

### S§21. Host and client requirements (inputs to T025b and T046)

Net can only check what its calls see. The host (T025b, `crpg-server`)
must:

- **H1.** Create one `SessionFence` per session at bind, with the
  session's epoch. Retain it with the session through the D12 grace, drop
  it only at expiry or unbind, and never re-create it for a live session.
- **H2.** Tag the session's first connection `FIRST`, and a resumed
  connection with exactly the `granted` fence. Call `check_frame(tag)` on
  every inbound frame of a bound connection before any other processing.
  On `Fenced` or `UnknownFence`, discard the frame and close that
  connection (`SessionFenced`, 9).
- **H3.** Decode with `decode_request`, then build the `ResumeDecision`
  only after its own checks:
  - the proof authenticated with `ct_eq` against the proof it issued for
    that session;
  - grace not expired (`< 30,000` ms of injected time);
  - the session's invitation still registered and not revoked;
  - its own use of the advisory claims.

  It never builds `Accept` without authenticating.
- **H4.** Call `resolve` once per request and send its result as the
  connection's first frame. On `Err(_)` from `resolve`, send `Rejected {
  epoch: request.epoch, reason: Denied }` (cause-neutral) and close.
- **H5.** On `Accepted`, before anything else:
  - fence the session's previous connection if it is still open;
  - send the result;
  - then stage the resume snapshot before any later delta on the new
    connection. That means `Cancel(in-flight, Superseded)` if one is in
    flight, then a `Begin` with a transfer id above every id issued in the
    epoch, `cursor` = the last `event_seq` issued, `base_tick` = the
    current server tick, and a body built from the current grants. The
    unacknowledged log is cleared (H§7 `stage_snapshot`, with a new cause
    `Resume`).
- **H6.** Never reset the epoch, `PeerState`, the retry cache,
  `next_new_seq`, `event_seq`, ordinals, transfer ids or rate budgets at
  resume. Report `Accept { progress }` from the retained ledger
  (`finalized_through` = `next_new_seq − 1` per lane).
- **H7.** Issue a `Ticket` after each welcome, and optionally rotate it
  after each `Accepted`. Proofs are never logged, printed, checkpointed or
  persisted. A restart issues fresh epochs (D12).
- **H8.** A `Busy` or `Denied` never moves the fence, and a resume attempt
  never extends the grace deadline (D12).

The client (T046 or any client) must:

- **C1.** Keep `epoch`, its current fence (`FIRST` after a welcome), the
  latest ticket's proof, and each pending intent's encoded bytes.
- **C2.** On disconnect, call `rebind_receiver(id, now_ms)` at once, and
  never remove and re-add a receiver for a retained session.
- **C3.** Send a request with its current fence, the latest proof, and
  claims of `receipted_through` per lane.
- **C4.** Accept only a result that passes `check_result`. On `Accepted`,
  set fence = `granted` and resend every pending intent's **stored** bytes
  unchanged.
- **C5.** On `Denied`, drop the session and start fresh with a hello. On
  `Busy`, retry the same request later with the same fence.
- **C6.** Ignore every frame of a closed connection.

### S§26. Open questions for the user (each with a recommendation)

1. **Wire identity.** A separate resume subprotocol: first byte `0x91`
   (the `0x9_` family; `0x8_` stays transfer, so `0x82` remains transfer
   version 2), lane 3, downstream tags `0x30`/`0x31`/`0x32`, upstream
   `0x40`.
   - Alternatives: `0x82` (collides with T024 S§5.4, the drafts' choice);
     `0x83` (reads as transfer version 3); resume tags inside a transfer
     version 2 (mixes vocabularies); a main-protocol v3 (D11 rejected that
     shape).

   *Recommendation:* approve as written.
2. **QUIC carriage.** Amend T024q **before its approval** so that `/2`
   carries a third channel `0x91` and a resume-first connection (TR1–TR6;
   S§20 lists every T024q section that changes), with no new
   `ServerEvent`/`SendError`/`ServerError` variant. The resume connection
   presents the session-bound proof instead of the invitation credential.
   The host still checks that the invitation is registered and not revoked
   (H3).
   - Alternative: approve T024q as written and file T025q under
     `crpg-lane0/3` before T025b. That costs a third ALPN, a second dual
     bind and another negotiation matrix.

   *Recommendation:* amend T024q.
3. **Proof and ticket.** `ResumeProof` is 16..=128 opaque bytes with a raw
   `u8` length, `Debug` exactly `ResumeProof(<redacted>)`, no
   `PartialEq`/`Eq`/`Ord`/`Hash`/`Display`, and the reviewed `ct_eq`. A
   downstream `Ticket` delivers it.
   - Alternatives: 1..=256 with a length-revealing `Debug` (Beam);
     1..=64, no `ct_eq` and no ticket (DeepSeek), which leaves T025b with
     no net shape for delivering a server-issued proof.

   *Recommendation:* approve.
4. **Epoch and fence.** Retain the epoch, and add a per-session
   `ConnectionFence` (from 1, never on a lane-0 or transfer frame). The
   request presents the last fence held, and the window `[confirmed,
   current]` accepts it. Every grant is `current + 1` and is never
   re-issued. `with_max` is a tightening-only grant limit.
   - Alternatives:
     - rotating the epoch per connection breaks every cached retry (S§1
       item 2);
     - DeepSeek's replay re-issues a grant to a second connection;
     - strict compare-and-swap (`presented == current`) loses the session
       on one lost result.

   *Recommendation:* approve.
5. **Lane progress.** Advisory `receipted_through` claims in,
   authoritative `finalized_through` progress out. Lists are keyed by lane
   with 1..=4 entries, and lane 0 is the only assigned lane in resume
   version 1.
   - Alternative: a fixed single field. That needs a new layout for D13's
     lane rather than only a new version.

   *Recommendation:* approve.
6. **Rejections.** A closed set: `Denied` (1) and `Busy` (2), with every
   net refusal answered as `Denied` (H4). There is no `Expired` and no
   per-cause code, which would tell an unauthenticated caller that a
   session existed or that a grant was revoked (ADR-0026 item 3's single
   `AuthRefused` rule). *Recommendation:* approve.
7. **Reassembler rebind.** Add `ReassemblyPool::rebind_receiver` (S§16),
   the only edit to an existing source file. It is additive, with no new
   `TransferError` variant.
   - Alternatives: remove-then-add, which loses the `StaleTransfer` and
     `BehindReplica` floors (case 16(h)); or also dropping queued updates
     (DeepSeek), which contradicts T024 S§10.4.

   *Recommendation:* approve.
8. **Split.** T025a1 (wire) then T025a2 (mechanisms), both `crpg-net`, both
   before T025b. T025a1 can run beside T024q and T024h1, and it must merge
   before an amended T024q. *Recommendation:* approve.
9. **ADR.** File one new ADR, "Resume subprotocol and connection fencing"
   (the next free number when filed: 0032 if T024q's 0030 and T024h's 0031
   are filed first). It is Accepted with this approval, filed by T025a1,
   records S§2 and H1–H8 in the ADR-0028 shape, and links this contract as
   authoritative. T025a2 appends a signed one-line addendum when the fence
   and rebind land. The alternative, an ADR-0028 addendum, would mix two
   subprotocols' decisions in one record. *Recommendation:* approve.
