- **D4. Layout and spelling.** ADR §1's six files. Unit tests are child
  modules (`src/core/tests.rs`, `src/core/{authority,client,link,errors}/tests.rs`),
  declared `#[cfg(test)] mod tests;`. Integration tests: `tests/bridge.rs` (public API only:
  K15's public assertions, K30) and `tests/source_rules.rs` (K31, K32). `lib.rs`: `#![allow(unsafe_code)]`,
  `#![warn(missing_docs)]`, the doc, `pub mod core;`, and in T047b
  `#[cfg(feature = "engine")] mod shell;`. Shell is **private**, so
  macro-generated items cannot trip `missing_docs`. The `core` module shadows the
  `core` crate at the crate root, so crate code writes `std::`, never `core::`.
  `lib.rs` has no `use`, and `shell.rs` imports items
  (`use crate::core::{BridgeCore, …}`), never the bare name `core`.
- **D5. One time source.** `shell.rs` takes `Instant::now()` when `open`
  returns 0 and passes `u64::try_from(elapsed().as_millis()).unwrap_or(u64::MAX)`
  to `BridgeCore::poll`. Tests script `now_ms`. `Host::tick` is never called
  (ADR §5).
- **D6. Engine version for loading.** `env!("CARGO_PKG_VERSION").parse()`,
  type inferred from `crpg_data::load_campaign(&files, &engine)`
  (`crates/crpg-data/src/loader.rs:251-254`), as the CLI does
  (`crates/crpg-cli/src/main.rs:1869-1879`). This adds no `semver` edge. An
  unparsable version is code 21.
- **D7. Grants and control (ADR §2.7 "full disclosure").** Both peers get the
  same `DisclosureGrants` (`host.rs:168-184`): one `EntityDisclosure` per bound
  combatant with all ten flags `true` (`:141-165`); `abilities` = the encounter
  ruleset's `abilities` **collected through a `BTreeSet`**, because duplicates
  are `InvalidGrants` (`host.rs:2217-2220`); `encounters = [encounter.id]`;
  `turn_round = encounter_end = turn_state = true`. Player
  `ControlGrant.actors` = combatants whose side equals the chosen side; NPC
  = every other combatant (may be empty). Player binds with
  `bind_snapshot_peer` (`:776`), NPC with `bind_peer` (`:763`), both at
  `now_ms = 0`.
- **D8. Presentation rule = a private copy of `crates/crpg-cli/src/demo.rs:129-232`.**
  The name is the creature (prefab) name key, else the placement name key,
  else the placement ULID text. The side is the creature's faction name key
  when that faction exists, else the creature name key, else the name. A key
  is resolved through the merged locale strings, else printed as itself.
  Ability display = name key resolved, else ULID text. `combat_basic` yields
  `Hero`/`Goblin` for both names and sides.
- **D9. Engine proof.** `--import` writes `.godot/` (needed before any `-s`
  run, **unverified**), but its exit code is not a load proof. Load is proved
  by a script that checks `ClassDB.class_exists("CrpgSession")` and exits 2
  if the class is missing. Scripts are run as `-s res://tests/<name>.gd`,
  an explicit form of the ADR's `-s tests/smoke.gd`.

### Behaviour

1. **B1. Open, in order, all-or-nothing, on the calling thread.**
   (1) Arguments: `seed < 0`, or non-empty `encounter_id` that is not a ULID
   (`crpg-core/src/ulid.rs:67`), → 3. (2) State `Open`/`Fenced` → 2.
   (3) Walk `campaign_dir` with `collect_campaign(&RealFs, ..)`, a copy of
   `crates/crpg-cli/src/main.rs:1050-1278`. It is copied, not reused, because
   `crpg-cli` is bin-only (`crates/crpg-cli/Cargo.toml:26-28`), and reusing it
   would pull `crpg-testkit` and `same-file` into the DLL
   (ancestor and root checks with `symlink_metadata`, sorted encoded-byte DFS,
   non-UTF-8 names, document-path symlinks, `campaign_document_path`
   classification, `Ok(None)` ignored). Any filesystem failure → 20, a
   classifier `Err` → 21. (4) Engine parse (D6), `load_campaign`, `validate`
   (`validation.rs:884`). Any `Err` or any finding → 21. (5) Encounter: empty →
   first `Document::Encounter` in `documents` order, none → 22; else the
   matching id, none → 23 (`crates/crpg-cli/src/play.rs:66-77`, `:262-282`).
   (6) Assemble `EncounterSpec` as `crates/crpg-cli/src/combat_apply.rs:211-285`.
   (7) `HistoryWorld::new(u64::try_from(seed)?)` then `start_encounter`
   (`crates/crpg-sim/src/history.rs:425`, `:634`, turn-based). (8) Record
   `(EntityId, placement)` from `world().combatants()` and check it against
   `participants` with `check_binding` (as `combat_apply.rs:286-306`). (9) Side: empty → side (D8) of
   the first combatant in that order (`play.rs:84-98`); otherwise that exact
   text, and no combatant with it → 24. (10) `acknowledge(last_sequence())`
   (`history.rs:744`, `:810`); `Host::from_history(history, HostConfig {
   protocol: V2, incarnation: 1 }, 0)` (`host.rs:566`). (11) Bind (D7).
   (12) Tables: for every recorded entity, `replica_id(player, e)` and
   `replica_id(npc, e)` must be `Some`, giving the player
   `PresentationTable` and the NPC side map. (13) Client half:
   `ReplicaWorld::new(SessionEpoch(host.epoch(player)?))`, seq 1. A failure in
   steps 6-8 or 10-13 → 25. On any non-zero result nothing is retained, and
   the state is unchanged for codes 2 and 3 and `Closed` otherwise. On 0:
   `Open`, view = empty revision 0, `last_error` cleared.
2. **B2. Poll precedence.** `Fenced(c)` → `c`; `Closed` → 1; else the step below
   inside the guard (B20). Its result is 0, 30, or fatal.
3. **B3. Authority step, in this order (ADR §6).** (1) Drain the up queue.
   Each frame goes to `ingest(player, bytes, now_ms)`, and `Refused { status }`
   sets `report.refused`. (2) NPC (B8). (3) `pump(now_ms)`. Apply B9 to the NPC
   results. If `dropped_replies > 0`, set `report.refused`: B9 has already
   fenced any NPC rejection, so a dropped reply in a live pump is the
   player's. `backpressured` is not an error. (4) Player
   `take_delivery_entries` → `hand_off` → if `Some(o)`,
   `acknowledge_delivery(player, o)`. Then NPC `take_delivery_entries`, and if
   it is non-empty, `acknowledge_delivery(npc, last.ordinal)`, unread.
   (5) `acknowledge_captures(last_capture())`. (6) `report.options` =
   `legal_intents(player)` mapped to `Offered`. Any `HostError` → `host_fault`.
4. **B4. `hand_off`.** Walk the entries in order: `Transfer` → `Err(54)`
   (ADR §8); `Delta` → `send`; at the first `LinkFull`, stop. Return the last
   ordinal accepted, or `None`. It never returns an ordinal that the link
   refused.
5. **B5. Link.** Each direction is a FIFO of whole frames with capacity `cap`.
   `send` on a full queue is `Err(LinkFull)` and changes nothing. `recv`
   returns the oldest frame, or `None`. Each `RefCell` borrow lasts one queue
   operation. The client never acknowledges.
6. **B6. Client step.** Drain the down queue. `decode_delta`
   (`crates/crpg-net/src/codec_v2.rs:595`) `Err` → 52; `apply_delta`
   (`replica.rs:188`) `Err` → 53. A bad frame is never skipped. For each
   applied frame, walk `ops` in order: `ActionResolved`, `TurnStarted`,
   `EncounterEnded` and `Legacy(Died)` become `ViewEvent`s, and
   `Legacy(Receipt)` becomes a `ViewReceipt`, whose code is `0` for `Applied`
   and `RejectionCode::as_u8` otherwise (`protocol.rs:439`). Every other op is
   state only. `EncounterEnded` latches `ended`. A receipt whose seq equals the
   pending seq clears pending; `report.refused` also clears it.
7. **B7. Revision.** After B6 the core builds the candidate rows, active,
   round, ended and options. It bumps the revision by exactly 1 when this step
   collected any event or receipt, or when the candidate differs from the
   current view in rows, active, round, ended or options. Otherwise the
   current `Rc<SessionView>` is kept unchanged, including its events and
   receipts. The revision bumps at most once per poll. The new view carries
   only this step's events and receipts, oldest first.
8. **B8. NPC driver (trusted, ADR §7).** Every poll: `opts = legal_intents(npc)`,
   `fire = NpcPacer::step(now, !opts.is_empty(), inflight.is_some())`.
   The pacer, first matching arm: `inflight` → `due = None`, false (a held move
   re-arms a full delay once it finishes); no options → `due = None`, false; `due == None`
   → `due = now + 600`, false; `now >= due` → `due = None`, true; else false.
   When it returns true, `i = choose_npc(&opts, &npc_sides)`, then encode
   `IntentFrame { epoch: host.epoch(npc)?, lane: LANE_COMBAT, seq: next, observed_tick:
   host.server_tick(), actor, body }` with `codec_v2::encode_intent`
   (`codec_v2.rs:242`) and `ingest(npc, …)`. `Refused` → fatal 51; `Staged` →
   `inflight = Some(next)`, `next += 1` (from `SEQ_FIRST` = 1). At most one NPC
   ingest per poll.
9. **B9. `npc_results`.** Player results are ignored. An NPC result with
   `retained_in_ingress == true` (the head-of-line hold, reported as
   `Rejected(QueueFull)`, `host.rs:1047-1056`) keeps `inflight`. A non-retained
   `Rejected(_)` → `Err(51)`. A non-retained `Applied` whose seq is `inflight`
   → `Ok(None)`. Otherwise it is unchanged.
10. **B10. `choose_npc`.** The first index whose body is `DeclareAction {
    target, .. }`, where `sides[target]` and `sides[actor]` both exist and
    differ; else `0` when there are options; else `None`
    (`crates/crpg-cli/src/play.rs:210-229`). It reads no health: the list
    holds live targets only.
11. **B11. Rows.** From `replica.entities()` in ascending order, the columns
    are: `net_ids`; `names`/`sides`/`placements` (the ULID text) from the table,
    with `""` for a missing row, never a panic; `health`/`max_health` from
    `HealthFact`, `0` when `None`; `health_known` `1` iff `Some`; `dead` from
    `HealthFact.dead`, `0` when unknown. `Died` never sets it.
12. **B12. Turn.** `active` = `turn().active` if that id is a live row, else
    0 (T046 item 8, `tasks/T046.md:238-241`). `round` = `turn().round`
    unadjusted, 0 without a turn.
13. **B13. Options.** Kept in host order. The label is `"<ability> -> <target
    name>"`, or the ability alone when the target has no row, or
    `"End turn"`; `option_targets` is the target id, or 0 for `EndTurn`
    (`play.rs:186-200`). Empty means it is not the player's turn.
14. **B14. `submit_option` precedence.** 3 (negative `revision` or `index`)
    → `Fenced(c)` → `c` → 1 → 4 (`revision != view.revision`) → 6 (`index >=
    len`) → 5 (pending) → encode `IntentFrame { epoch, LANE_COMBAT, seq,
    observed_tick: replica.server_tick(), actor, body }` and `send` up:
    `LinkFull` → 30, else pending = seq, seq += 1, 0. Only the final branch
    sends.
15. **B15. Errors.** Every non-zero return sets `last_error` to `NAME` or
    `NAME: detail`. The detail is the source's `Display`, a diagnostic summary,
    or the panic text. Repeated fatal codes keep the first text. Only a
    successful `open` clears it. The text is never control flow (tests check
    the prefix only). A gameplay rejection is a receipt, and `poll` returns 0.
16. **B16. Fatal fence.** On a 50-55 fault: set state `Fenced(code)` and
    `last_error` from the fault first, then call `Host::shutdown()` and drop the
    `Live` inside one `catch_unwind` whose result is ignored. A panic during that
    teardown changes nothing: the fault's code and text stand. The view stays
    at its last revision.
17. **B17. Thread.** Nothing spawns a thread. `BridgeCore` is `!Send` (it
    holds `Rc`). `experimental-threads` is off. With default safeguards
    (dev: strict; release: balanced, `godot-0.5.5/src/lib.rs:193-199`), gdext
    panics on binding access off the main thread
    (`godot-ffi-0.5.5/src/binding/single_threaded.rs:125-145`). Whether that
    fires before a `#[func]` body runs is **unverified**, and T047b records
    it.
18. **B18. No rule input from presentation.** The client half decides
    nothing. Options come only from `legal_intents`, and the core contains no
    float, `HashMap`/`HashSet`, `Instant` or `SystemTime`.
19. **B19. Unsafe (H-unsafe item).** The crate has exactly one hand-written
    `unsafe` token: the `unsafe impl` above, in `shell.rs`. The
    `#[gdextension]` macro requires it (`gdextension.rs:21-26`). Macro
    expansion adds `#[unsafe(no_mangle)] unsafe extern "C" fn gdext_rust_init`
    (`:62-73`), and `GodotClass`/`godot_api` are expected to add more
    (**unverified**). That is why the root keeps `allow(unsafe_code)`.
    `core/mod.rs` begins with `#![forbid(unsafe_code)]`, which binds every
    `core` submodule. Any other `unsafe` needs an ADR-0033 amendment.
20. **B20. Panic policy.** (a) Each `CrpgSession` `#[func]` converts its
    arguments and makes exactly one `BridgeCore` call. The shell does no
    indexing, `unwrap`/`expect` or arithmetic on GDScript values, and its only
    arithmetic is D5's saturating milliseconds. (b) `BridgeCore::open`/`poll`/
    `submit_option`/`close` run their `Live` work inside
    `std::panic::catch_unwind(AssertUnwindSafe(..))`. `AssertUnwindSafe` is
    sound because a `Live` that panicked is never observed again. (c) On a
    panic caught in `open`, `poll` or `submit_option`: state `Fenced(Panicked)`;
    the old `Live` (if any) is dropped as in B16; `last_error` =
    `PANICKED: <&str or String payload, else "non-string payload">`; return
    55. A panic caught in `close` (its shutdown or the `Live` drop) does not
    fence: the state is `Closed` as B21 says, and `last_error` becomes the same
    `PANICKED: …` text, which is the only report, since `close` returns
    nothing. (d) `CrpgView` getters read an
    immutable `Rc` snapshot and never reach the core, so a panic there cannot
    half-update a session. gdext's handler catches it at the boundary
    (`godot-core-0.5.5/src/private.rs:431-445`, `:465`, `:484`), and the
    GDScript call aborts. (e) Nothing calls back into GDScript, so gdext's
    re-entrancy `bind_mut` panic (`gd.rs:185-186`) is unreachable. (f) There is
    no `panic = "abort"`. (g) gdext's hook prints panic text to the Godot
    console (`private.rs:324-325`).
21. **B21. Close and drop.** `close` is idempotent. When `Open`, it calls
    `Host::shutdown`, drops the `Live` under the guard, and sets `Closed`. When
    `Fenced`, it sets `Closed`. The view becomes empty revision 0, and
    `last_error` is kept, except that a panic caught during the teardown sets it to `PANICKED: …` (B20c) while the state is still `Closed`. `Drop` runs `close`, and no panic escapes it. After
    `close`, `poll`/`submit_option` return 1 and `open` may follow, starting
    again at revision 0.

## Open questions for the user

1. **When a computer-controlled enemy's move is put on hold, should the game
   wait rather than crash?** The server can tell an action "wait your turn,
   the queue is busy". It reports this with a *rejection* label plus a "kept
   for retry" flag (`host.rs:1047-1056`). Read word for word, ADR §6 ("npc
   result Rejected ⇒ fatal") would end the session on a harmless wait. It also
   lets the enemy submit a second move while the first is on hold. **Recommend:**
   approve B8/B9 as written. Holds are ignored, and the enemy waits for its
   held move to finish. This clarifies ADR §6/§7 and changes nothing else.
2. **Must the eight-package licence notice ship with the CI build?** D41c's
   cost was "a licence notice in the shipped game"
   (`tasks/DECISIONS-D41.md:41-43`). T047c's C3 uploads the DLL as a build
   artifact, and no task owns the notice. **Recommend:** T047c adds a short
   `THIRD_PARTY_NOTICES` file to the artifact. It would name the eight
   packages, MPL-2.0, and where their source is. It is required once
   anyone outside the project gets a build.
3. **May T047b use the lighter build switches if the full build is too
   heavy?** Less generated code builds faster and uses less memory.
   **Recommend:** yes, by D2's ladder, with measurements recorded.
4. **Routing.** **Recommend:** approve D1 (T047d to an OpenCode worker with
   `Godot4`; T047b's one `unsafe` line comes to you).
5. **May the "bad number" check live in the Godot-free core?** ADR §10 says a
   negative number from GDScript is `BAD_ARGUMENT` "with no core call". This
   contract runs that check first thing inside `BridgeCore`, before any session
   code, so it can be tested without Godot (K28 proves no session code runs).
   Out-of-range indexes stay `NO_SUCH_OPTION` (ADR §10's check order); no
   `i64` is oversized for `u64`/`usize` on 64-bit targets.
   **Recommend:** accept; GDScript sees the same behaviour. The alternative,
   a shell-side check, is testable only under Godot.

ADR points raised as questions, not changes. (a) The ADR still says "Proposed"
(`docs/adr/0033-godot-bridge.md:4`) despite D41d: bookkeeping. (b) BR-2 asks for code 25 "from a bad
input", but a campaign that passes validation may never fail `start`, `wrap`
or `bind`. K16 covers 20-24, and 25 is asserted only where reachable; is that
acceptable? (c) §15 fears that `deny` sees the engine graph today. Without
`[graph]` it likely does not, so licence coverage starts only with T047c.
