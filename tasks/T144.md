# T144 — terminal combat demo (`crpg-cli`)

Approved direction: user, 2026-11-01 ("Terminal demo first"). Reading a fight should not need Godot; this is the first thing a person can watch.

## Task / Crate(s) / Purpose
`crpg-cli` only. Add `crpgc demo`, which plays a combat replay through a campaign and prints a readable fight to stdout. It is a viewer: it adds no rules, and `crpg-sim`, `crpg-rules`, `crpg-testkit` and every golden stay untouched.

## Interface
`crpgc demo <replay> --campaign <dir> [--delay-ms N]`

- `<replay>` and `--campaign` take the same values `crpgc replay --campaign` takes.
- `--delay-ms` (default 0) sleeps N ms after each printed action, so a person can follow along.
- New private module `crates/crpg-cli/src/demo.rs`. Reuse `combat_apply.rs` decode and bind glue; `main.rs` gets parsing, dispatch and the usage line only.

## Behaviour
1. Print a header naming the campaign and each combatant with authored name, side and starting health.
2. For each intent in the replay order, print one block: acting combatant, action, target, dice result and hit or miss when the sim's result exposes them, damage, target health after. Print a line when a round or turn changes and when a combatant dies.
3. End with a summary: rounds played, survivors with health, and which side won.
4. Names come from the campaign documents; a raw id is printed only if a document has no name.
5. Read results only through existing public `crpg-sim` API. If a printed fact needs a new public API, leave that fact out and list it in the report.

## Errors
Usage errors exit 2 with one stderr line, as `crpgc replay`. A missing or invalid replay or campaign exits with the same code and line `crpgc replay` gives for it.

## Test
In new `crates/crpg-cli/tests/demo.rs`, as subprocess tests in the style of `tests/combat_replay.rs`, over `combat_basic` and `combat_srd`:
- exit 0, and two runs give byte-identical stdout;
- output has the header, at least one action block for every attack intent, exactly one death line per combatant that dies, and the summary;
- the fight's final health values in the summary equal those `crpg-sim` reaches in the same replay, computed in the test by another route (not by parsing the demo's own output twice);
- a missing `--campaign`, an unknown flag, and a non-number `--delay-ms` each exit 2;
- `crpgc replay` output on the same inputs is unchanged by this task.
No `--delay-ms` above 0 in tests.

## Definition of done
Gates pass for `crpg-cli`; `docs/architecture/crpg-cli.md` and `crates/crpg-cli/AGENTS.md` mention the command.

## Out of scope
Interactive play, choosing actions, new seeds, colour or a TUI, new dependencies, any other crate, any golden, new fixtures.
