## Task
ADR-0036 V1–V7 (`:346–385`), U3 (`:100–102`) and U4 (`:104–107`): a pure,
integer navigation crate. It validates convex horizontal polygon meshes,
bakes a rectangle minus rectangular holes, writes and reads a canonical byte
form, answers `locate` and `nearest_on_mesh`, and finds paths with A* over
polygons and an integer funnel. Every returned segment lies inside the
mesh (V5). Nav knows nothing of `crpg-sim`: it returns `NavPath`, and the
host (T037) copies points into sim's `MoveRoute` (A2, `:68–72`) and hashes
the canonical bytes into a `NavRevision` (R2, `:147–150`).

## Readings of the ADR
Where ADR-0036 leaves a detail open, this contract decides it. Each needs
the user's approval with the contract.
1. **Holes are in.** V3 allows leaving them out (`:363–364`); this contract
   bakes them, so paths are tested on real obstacles. The bake is a full
   grid: the sorted distinct `x` and `z` edges of the outer rectangle and
   every hole cut the box into cells, and every cell no hole covers is one
   4-vertex rectangle. Cells are never merged, so no T-junction ever arises
   and adjacency is exact. Holes may overlap and may touch the outer edge,
   but not cross it. At most `MAX_BAKE_HOLES = 32` holes (at most 65 × 65
   cells, under `MAX_NAV_POLYGONS`).
2. **`bake_box` takes a height and two rectangles,**
   `bake_box(y, outer: NavRect, holes: &[NavRect])`. H1's "`bake_box` from
   `Area.bounds`" (`:421`) maps to `y = bounds.min[1]` and the `x`/`z` of
   `bounds.min`/`bounds.max` in the host; nav cannot import `crpg-data`.
3. **Vertices are 3D and pairwise distinct.** A polygon's height is its
   vertices' common `y`. Convexity is: every vertex on or left of every
   edge, collinear neighbours continuing in the same direction, and at
   least one strict left turn (B-M7). Overlapping polygons are not
   detected (an all-pairs test is `O(P²)` at 16,384 polygons); `locate`
   returns the lowest id, so an overlap stays deterministic.
4. **A directed edge appears in at most one polygon**; two polygons are
   adjacent through an edge that one holds as `(a, b)` and the other as
   `(b, a)` (V2's "same two vertex indices", `:357–358`).
5. **`nearest_on_mesh` rounding.** Off the mesh, the answer is a lattice
   point on or inside the nearest polygon edge's polygon (four-candidate
   rule, B-Q5), so `locate` of the answer is always `Some`. Ties go to the
   lowest polygon id, then the lowest edge index, then candidate order.
6. **A\* is pinned:** nodes are polygons; a node's point is `from` for the
   start, the goal point for the goal, and otherwise the floor centroid of
   its vertices; edge cost is U4 length between node points; the open set
   pops the least `(f, h, PolyId)`; closed nodes never reopen; a
   neighbour's cost changes only on strict improvement; neighbours are
   visited in edge order.
7. **The funnel is the "simple stupid funnel"** with exact `i128` cross
   products, written out in B-P5. A portal's left end is the end, and its
   right end the start, of the shared edge as the polygon being left holds
   it; when two polygons share several edges, the lowest edge index is the
   portal.
8. **One error beyond V4's list:** `Unreachable`, for a goal in a part of
   the mesh the start cannot reach (a wall can split a box in two). V4
   lists only five (`:373–374`).
9. **Heights of path points.** The first point is `from` exactly (its `y`
   included); a corner takes its mesh vertex's `y`; the last point takes
   the goal polygon's `y`. `AlreadyThere` compares `x` and `z` only.
10. **Length arithmetic.** `seg_len` squares in `u128` and takes
    `ceil_sqrt` over `u128`; within U3 (`:100–102`) it equals U4's `u64`
    formula exactly, and outside U3 it cannot overflow. Cross products and
    distances use `i128` on raw values.
11. **Canonical bytes** (V6, `:380–382`): magic `CNAV`, version byte `1`,
    `u32` counts, `i32` little-endian `x, y, z` per vertex, then per polygon
    a `u8` vertex count and `u32` indices. Adjacency is derived, not
    stored.
12. **The shared limits keep sim's values under nav's names**
    (`COORD_LIMIT_RAW`, `MAX_PATH_POINTS`, `MAX_PATH_LENGTH_RAW`), so T037
    can assert equality at compile time (H5, `:439–442`).

## Shared definitions
For points `o`, `a`, `b` (raw `x`, `z` widened to `i128`):
- `cross(o, a, b) = (a.x - o.x) * (b.z - o.z) - (a.z - o.z) * (b.x - o.x)`.
  Positive means `b` is left of the line `o → a` (counter-clockwise when
  `x` is read as the first and `z` as the second axis of a standard plane).
- `dot(o, a, b, c) = (a.x - o.x) * (c.x - b.x) + (a.z - o.z) * (c.z - b.z)`.
- `same(a, b)` is `a.x == b.x && a.z == b.z`.
- `contains(P, q)`: for every edge `i` of polygon `P` (vertex `v[i]` to
  `v[(i + 1) % n]`), `cross(v[i], v[i + 1], q) >= 0`.
- `d2(a, b) = (a.x - b.x)^2 + (a.z - b.z)^2` in `i128`.

## Behaviour

### T035a: lengths
1. **B-G1 (U4).** `ceil_sqrt(n)` is `s + (s * s < n) as u128` with
   `s = n.isqrt()`. `seg_len(a, b)` is `ceil_sqrt(dx * dx + dz * dz)` with
   `dx`, `dz` the raw differences as `u128` magnitudes, returned as `u64`
   (always fits: `n < 2^66`). `y` is ignored.

### T035a: mesh validation (`NavMesh::new`; the first failure is returned)
2. **B-M1.** `vertices.len()` outside `3..=MAX_NAV_VERTICES`:
   `VertexCount { count }`.
3. **B-M2.** `polygons.len()` outside `1..=MAX_NAV_POLYGONS`:
   `PolygonCount { count }`.
4. **B-M3.** In index order, a vertex with any component whose raw
   magnitude (`to_raw().unsigned_abs()`, never `abs()`, which overflows on
   `i32::MIN`) exceeds `COORD_LIMIT_RAW`: `VertexOutOfBounds { vertex }`.
   `±COORD_LIMIT_RAW` is allowed. B-B1 measures magnitude the same way.
5. **B-M4.** In index order, a vertex equal in all three components to an
   earlier vertex: `DuplicateVertex { vertex }` (the later index).
6. **B-M5.** Then per polygon in id order, B-M5 to B-M7 (all checks of one
   polygon before the next): a vertex count outside
   `3..=MAX_POLYGON_VERTICES` is `PolygonSize { poly, count }`; an index
   `>= vertices.len()` is `VertexIndex { poly, index }` (the first in list
   order); an index appearing twice, or two of its vertices with equal `x`
   and `z`, is `RepeatedVertex { poly }`.
7. **B-M6.** Vertices whose `y` differs from the polygon's first vertex:
   `NotHorizontal { poly }`.
8. **B-M7 (V2).** `NotConvex { poly }` unless all three hold, with
   `v[i]` taken cyclically: (a) for every edge `i` and every vertex `k`,
   `cross(v[i], v[i + 1], v[k]) >= 0`; (b) for every `i` with
   `cross(v[i - 1], v[i], v[i + 1]) == 0`,
   `dot(v[i - 1], v[i], v[i], v[i + 1]) > 0`; (c) some `i` has
   `cross(v[i - 1], v[i], v[i + 1]) > 0`. So the polygon is convex,
   counter-clockwise, collinear vertices are allowed, and a clockwise,
   reflex, self-crossing, back-tracking or flat polygon is rejected.
9. **B-M8.** Then for each polygon in id order and each edge `i` in order,
   the directed pair `(v[i], v[i + 1])` of vertex indices: a pair already
   seen is `DuplicateEdge { poly }` (the later polygon).
10. **B-M9 (V2).** `neighbours(P)[i]` is `Some(Q)` exactly when polygon
    `Q` holds the reversed pair of `P`'s edge `i`; otherwise `None`. A
    vertex-only touch is not adjacency.
11. **B-M10.** No method panics for any input. `polygon`, `polygon_y` and
    `neighbours` return `None` for an id `>= polygon_count()`.

### T035a: canonical bytes (V6)
12. **B-C1.** `to_canonical_bytes` writes, in order: `NAV_MAGIC`;
    `NAV_FORMAT_VERSION`; vertex count `u32` LE; polygon count `u32` LE;
    each vertex as raw `x`, `y`, `z`, each `i32` LE; each polygon as its
    vertex count `u8` then each index `u32` LE. Nothing else (no
    neighbours, no padding).
13. **B-C2.** `from_canonical_bytes` checks, in order: fewer than 4 bytes
    is `Truncated`; the first 4 not `NAV_MAGIC` is `BadMagic`; no byte 4 is
    `Truncated`; byte 4 not `NAV_FORMAT_VERSION` is
    `UnsupportedVersion { version }`; fewer than 13 bytes is `Truncated`.
    A vertex count above `MAX_NAV_VERTICES` is
    `Invalid(VertexCount { count })` and a polygon count above
    `MAX_NAV_POLYGONS` is `Invalid(PolygonCount { count })`, both before
    reading further. It then reads every vertex and every polygon (any
    `u8` count, then that many indices); running out of bytes is
    `Truncated`; bytes left over are `TrailingBytes`. Finally
    `NavMesh::new` runs and its error is `Invalid(..)`. For every mesh `m`,
    `from_canonical_bytes(&m.to_canonical_bytes()) == Ok(m)`.

### T035b: bake (V3)
14. **B-B1.** `bake_box` checks, in order: `holes.len() >
    MAX_BAKE_HOLES` is `TooManyHoles { count }`; any of `y`, the outer's
    four values, then each hole's four values (hole order, field order
    `min_x, min_z, max_x, max_z`) with raw magnitude above
    `COORD_LIMIT_RAW` is `OutOfBounds`; `outer.min_x >= outer.max_x` or
    `outer.min_z >= outer.max_z` is `EmptyOuter`; then per hole `h` in
    order: `min >= max` on either axis is `EmptyHole { hole: h }`, and a
    hole not within the outer (`outer.min_x <= min_x`, `max_x <=
    outer.max_x`, and the same for `z`) is `HoleOutside { hole: h }`.
15. **B-B2.** `xs` is the sorted distinct set of `outer.min_x`,
    `outer.max_x` and every hole's `min_x` and `max_x`; `zs` likewise for
    `z`. Cell `(i, j)` is `[xs[i], xs[i+1]] × [zs[j], zs[j+1]]`. It is
    covered when some hole has `min_x <= xs[i]`, `xs[i+1] <= max_x`,
    `min_z <= zs[j]` and `zs[j+1] <= max_z`. For `i` ascending, then `j`
    ascending, each uncovered cell becomes one polygon with corners, in
    this order, `(xs[i], zs[j])`, `(xs[i+1], zs[j])`, `(xs[i+1], zs[j+1])`,
    `(xs[i], zs[j+1])`. A corner's vertex index is assigned on its first
    appearance in that emission order; every vertex has height `y`. No
    uncovered cell is `NoWalkableArea`.
16. **B-B3.** The result is `NavMesh::new(vertices, polygons)`; an error
    there is `Mesh(..)` (it cannot occur for inputs passing B-B1).

### T035b: queries (V4)
17. **B-Q1.** `locate` and `nearest_on_mesh` accept any `[Fx16_16; 3]`,
    inside U3 or not, without panic or overflow (`i128`).
18. **B-Q2.** `locate(p)` is the lowest `PolyId` with `contains(P, p)`, or
    `None`.
19. **B-Q3.** `nearest_on_mesh(p)`: when `locate(p)` is `Some(id)`, it is
    `[p.x, polygon_y(id), p.z]`.
20. **B-Q4.** Otherwise, for each polygon in id order and each edge `i`
    in order, with `a = v[i]`, `b = v[i + 1]`, compute the edge candidate
    `c` (B-Q5) and `d2(c, p)`; keep the first strictly smallest. The result
    is `[c.x, y of that polygon, c.z]`.
21. **B-Q5.** Edge candidate, all `i128`: `ex = b.x - a.x`,
    `ez = b.z - a.z`, `t = (p.x - a.x) * ex + (p.z - a.z) * ez`,
    `l2 = ex * ex + ez * ez`. If `t <= 0` it is `a`; if `t >= l2` it is
    `b`. Otherwise `fx = a.x + (ex * t).div_euclid(l2)`,
    `cx = fx + ((ex * t).rem_euclid(l2) != 0) as i128`, and `fz`, `cz` the
    same with `ez`. Of `(fx, fz)`, `(fx, cz)`, `(cx, fz)`, `(cx, cz)` in
    that order, keep those with `contains(P, ·)`; the candidate is the one
    with the least `d2` to `p`, the first on a tie. If none is contained,
    it is `a` when `d2(a, p) <= d2(b, p)`, else `b`. So
    `locate(nearest_on_mesh(p))` is always `Some`.

### T035c: paths (V4, V5)
22. **B-P1.** `find_path(from, to)`: `locate(from)` is `None`:
    `StartOffMesh`; then `locate(to)` is `None`: `GoalOffMesh`; then
    `same(from, to)`: `AlreadyThere`. Let `s = locate(from)`,
    `g = locate(to)` and `goal = [to.x, polygon_y(g), to.z]`.
23. **B-P2.** If `s == g` the corridor is `[s]`. Otherwise it is the A*
    result (B-P3), or `Unreachable` when the goal is never popped.
24. **B-P3 (A*).** `pt(P)` is `from` if `P == s`, `goal` if `P == g`, and
    otherwise the floor centroid `[Σx.div_euclid(n), 0, Σz.div_euclid(n)]`
    of its `n` vertices (sums in `i64`). `h(P) = seg_len(pt(P), goal)`.
    Start with `cost(s) = 0` and the open set
    `{(h(s), h(s), s)}`, ordered ascending by `(f, h, PolyId)` (a
    `BTreeSet<(u64, u64, u32)>`). Repeat: pop the least entry `P` and mark
    it closed; if `P == g`, stop; for each edge `i` of `P` in order with
    `neighbours(P)[i] == Some(Q)` and `Q` not closed, let
    `c = cost(P) + seg_len(pt(P), pt(Q))`; if `Q` has no cost or
    `c < cost(Q)`, remove `Q`'s old open entry if any, set `cost(Q) = c`,
    `parent(Q) = P` and insert `(c + h(Q), h(Q), Q)`. The corridor is `g`
    back through `parent` to `s`, reversed.
25. **B-P4 (portals).** `portals[0] = (from, from)`. For each consecutive
    pair `(P, Q)` of the corridor: `e` is the lowest edge index of `P` with
    `neighbours(P)[e] == Some(Q)`, `a` is `P`'s vertex `e` and `b` its
    vertex `e + 1` (3D vertex values); the portal is `(left, right) =
    (b, a)`. The last portal is `(goal, goal)`.
26. **B-P5 (funnel).** Exactly:
    ```text
    apex = portals[0].0; left = portals[0].0; right = portals[0].1
    apex_i = 0; left_i = 0; right_i = 0
    raw = [apex]; i = 1
    while i < portals.len():
        (l, r) = portals[i]
        if cross(apex, right, r) >= 0:
            if same(apex, right) or cross(apex, left, r) < 0:
                right = r; right_i = i
            else:
                raw.push(left); apex = left; apex_i = left_i
                left = apex; right = apex; left_i = apex_i; right_i = apex_i
                i = apex_i + 1; continue
        if cross(apex, left, l) <= 0:
            if same(apex, left) or cross(apex, right, l) > 0:
                left = l; left_i = i
            else:
                raw.push(right); apex = right; apex_i = right_i
                left = apex; right = apex; left_i = apex_i; right_i = apex_i
                i = apex_i + 1; continue
        i += 1
    raw.push(portals[portals.len() - 1].0)
    ```
    It terminates: after a restart both tighten branches fire on the next
    portal, so `left_i` and `right_i` exceed `apex_i` before any restart,
    and `apex_i` strictly increases.
27. **B-P6 (points).** `points = [raw[0]]`, then each later `raw` point is
    appended unless `same` as the last appended one. So `points[0] ==
    from` exactly, the last point is `same` as `goal`, there is no
    zero-length segment, and `points.len() >= 2`.
28. **B-P7 (V5).** Every segment of `points` lies inside the mesh (closed:
    on a boundary counts). The tests prove it on baked meshes with C-8's
    oracle. Shortest paths are not promised.
29. **B-P8.** `points.len() > MAX_PATH_POINTS` is
    `PathTooComplex { points }`; then the sum of `seg_len` over segments
    above `MAX_PATH_LENGTH_RAW` is `TooLong { length }`. Otherwise
    `Ok(NavPath)` with that `length`. The same mesh and arguments always
    give the same result.

## Errors
`Display` texts, exact:

| Value | Text |
|---|---|
| `VertexCount { count }` | `navmesh vertex count {count} is outside 3..=65536` |
| `PolygonCount { count }` | `navmesh polygon count {count} is outside 1..=16384` |
| `VertexOutOfBounds { vertex }` | `navmesh vertex {vertex} is outside the coordinate limit` |
| `DuplicateVertex { vertex }` | `navmesh vertex {vertex} repeats an earlier vertex` |
| `PolygonSize { poly, count }` | `navmesh polygon {poly} has {count} vertices, outside 3..=8` |
| `VertexIndex { poly, index }` | `navmesh polygon {poly} names missing vertex {index}` |
| `RepeatedVertex { poly }` | `navmesh polygon {poly} repeats a vertex position` |
| `NotHorizontal { poly }` | `navmesh polygon {poly} is not horizontal` |
| `NotConvex { poly }` | `navmesh polygon {poly} is not convex and counter-clockwise` |
| `DuplicateEdge { poly }` | `navmesh polygon {poly} repeats a directed edge` |
| `Truncated` | `navmesh bytes end early` |
| `BadMagic` | `navmesh bytes do not start with CNAV` |
| `UnsupportedVersion { version }` | `navmesh format version {version} is not supported` |
| `TrailingBytes` | `navmesh bytes continue after the last polygon` |
| `Invalid(e)`, `Mesh(e)` | the inner error's text |
| `TooManyHoles { count }` | `bake has {count} holes, more than 32` |
| `OutOfBounds` | `bake coordinate is outside the coordinate limit` |
| `EmptyOuter` | `bake outer rectangle is empty` |
| `EmptyHole { hole }` | `bake hole {hole} is empty` |
| `HoleOutside { hole }` | `bake hole {hole} is not inside the outer rectangle` |
| `NoWalkableArea` | `bake holes cover the whole outer rectangle` |
| `StartOffMesh` | `path start is off the navmesh` |
| `GoalOffMesh` | `path goal is off the navmesh` |
| `AlreadyThere` | `path start and goal are the same point` |
| `Unreachable` | `path goal cannot be reached from the start` |
| `PathTooComplex { points }` | `path needs {points} points, more than 64` |
| `TooLong { length }` | `path length {length} exceeds 268435456` |
