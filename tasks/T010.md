## Task
Implement the first campaign-data format in `crpg-data`: typed entity and
aggregate documents, generated schemas, canonical JSON, flat package resolution,
lock APIs, a deterministic ULID index, and serializable event-IR definitions.

## Crate(s)
`crpg-data` (only). Consume `crpg-core` without modifying it. The only permitted
implementation artifacts outside this crate are `schemas/`, the resulting
`Cargo.lock` changes, and the documentation updates listed below.

This is a Stage-2 specification, not a completion record. The drafting task
changes **only `tasks/T010.md`**; all implementation requirements below describe
the subsequent execution of T010.

## Purpose
Provide the shared, headless campaign representation required by later rules,
editor, and CLI work, following spec §4, §19.1 #11, and §24 T10. E016 governs
document categories, identity domains, lock authorities, and tick waits;
ADR-0008/ADR-0011 assign authored event IR to data while leaving live events and
kernel hooks in their owning crates.

T009a/T009b/T009c are merged and T010 is next. This task opens `crpg-data` under
spec §15.6 and activates the real schema-drift gate under §15.4 gate 7/E020.

## Interface

All signatures below are the required public API. Bodies, private serde/schema
helpers, and public-item doc comments are omitted from the sketches, not from
the implementation. Declare public modules `types`, `ir`, `document`,
`canonical`, `package`, `loader`, `schema`, and `error`; re-export their public
items from `lib.rs`. Do not add a workspace-wide trait.

### Shared values and identities (`types.rs`)

```rust
use std::{collections::BTreeMap, str::FromStr};
use crpg_core::{Fx16_16, Ulid};
use crate::DataError;

pub struct PackageId(String);
impl PackageId {
    pub fn as_str(&self) -> &str;
}
impl FromStr for PackageId {
    type Err = DataError;
    fn from_str(value: &str) -> Result<Self, Self::Err>;
}

pub struct SourcePath(String);
impl SourcePath {
    pub fn as_str(&self) -> &str;
}
impl FromStr for SourcePath {
    type Err = DataError;
    fn from_str(value: &str) -> Result<Self, Self::Err>;
}

pub struct Digest([u8; 32]);
impl Digest {
    pub const fn from_bytes(bytes: [u8; 32]) -> Self;
    pub const fn as_bytes(&self) -> &[u8; 32];
}
impl FromStr for Digest {
    type Err = DataError;
    fn from_str(value: &str) -> Result<Self, Self::Err>;
}

pub enum DataValue {
    Bool(bool),
    Integer(i64),
    Unsigned(u64),
    Fixed(Fx16_16),
    Text(String),
    ObjectRef(Ulid),
    List(Vec<DataValue>),
    Map(BTreeMap<String, DataValue>),
}

pub enum ValueType {
    Bool, Integer, Unsigned, Fixed, Text, ObjectRef, List, Map,
}

pub enum VariableScope { Campaign, World, Area, Graph }
pub struct VarDecl {
    pub name: String,
    pub value_type: ValueType,
    pub default: DataValue,
    pub scope: VariableScope,
}

pub struct Transform {
    pub position: [Fx16_16; 3],
    pub rotation: [Fx16_16; 3],
    pub scale: [Fx16_16; 3],
}
pub struct Bounds {
    pub min: [Fx16_16; 3],
    pub max: [Fx16_16; 3],
}
```

`PackageId`, `SourcePath`, and `Digest` have private fields and implement
`Debug`, `Clone`, `PartialEq`, `Eq`, `PartialOrd`, `Ord`, `Display`, string
`Serialize`/validated `Deserialize`, and data-local `JsonSchema`. `Digest` also
implements `Copy`. Package ids match `[a-z0-9]+(?:[.-][a-z0-9]+)*` exactly;
they are immutable publication coordinates, never renameable slugs or ULIDs.
Digest text is exactly 64 lowercase hex characters; uppercase is rejected.

`SourcePath` is a portable campaign-relative logical path, not an OS path.
It consists of nonempty `/`-separated ASCII components using only
`[A-Za-z0-9._-]`; components `.` and `..` are forbidden. Leading/trailing `/`,
empty components, backslashes, drive colons, and absolute paths are rejected.
No filesystem access, normalization, case folding, or platform detection occurs.
Paths differing only in ASCII case cannot coexist in a loaded campaign.

`DataValue` is adjacently tagged with `type` and `value`, using snake_case
variant names: e.g. `{"type":"fixed","value":65536}`. Thus signed and unsigned
integers round-trip without ambiguous untagged-enum decoding. List/map values
recurse; there is no arbitrary `serde_json::Value` escape hatch in campaign
models. `ValueType::List`/`Map` describe containers of these tagged values,
not homogeneous containers. Expressions below are opaque strings, not an
expression interpreter introduced by T010.

These are initial structural models, not complete gameplay models. All `name`
fields and `text_key` fields contain locale keys, not display prose. `ambience`
is an optional asset-key string (not a world/entity reference). `entry.spawn`
references a placement ULID whose transform supplies the spawn point; this
pins the schematic §4.6 `"spawn":"start"` example to the E016 object-reference
rule before any version-1 data is shipped. Placement remains an aggregate
entry, not a standalone `placement.json` document.

`EventGraph` may be an independently stored entity at `scripts/graphs/*.json`
or an identified entry owned by a triggers aggregate. Either representation
indexes its graph and node ULIDs; publishing both copies is a duplicate id.
No additional aggregate categories are implicitly permitted.

### Event IR and action signatures (`ir.rs`)

```rust
use std::collections::BTreeMap;
use crpg_core::Ulid;
use crate::{DataValue, ValueType, VarDecl};

pub struct EventGraph {
    pub id: Ulid,
    pub slug: String,
    pub name: String,
    pub note: Option<String>,
    pub entry: Trigger,
    pub start: Ulid,
    pub nodes: Vec<Node>,
    pub edges: Vec<Edge>,
    pub locals: Vec<VarDecl>,
}
pub enum Trigger {
    AreaEnter, AreaExit, Interact, DialogueNode, QuestStateChange,
    Timer { ticks: u64 },
    CombatStart, CombatEnd, Death, ItemAcquired,
    Custom { id: String },
}
pub struct Node {
    pub id: Ulid,
    pub body: NodeBody,
}
pub enum NodeBody {
    Condition { expr: String },
    Action { call: ActionCall },
    Branch { expr: String, cases: Vec<DataValue> },
    Sequence { nodes: Vec<Ulid> },
    Wait { ticks: u64 },
    CallScript { script_id: String, args: BTreeMap<String, DataValue> },
    CallGraph { graph_id: Ulid, args: BTreeMap<String, DataValue> },
}
pub enum Port {
    Next, True, False, Case { index: u32 },
}
pub struct Edge {
    pub from: Ulid,
    pub port: Port,
    pub to: Ulid,
}
pub struct ActionCall {
    pub action_id: String,
    pub args: BTreeMap<String, DataValue>,
}
pub struct ActionSignature {
    pub action_id: String,
    pub parameters: Vec<ActionParameter>,
}
pub struct ActionParameter {
    pub name: String,
    pub value_type: ValueType,
    pub required: bool,
}
```

The static graph `start` names its first node; `entry` is the initiating trigger.
Condition has true/false ports, Branch has zero-based case ports, and the other
nodes have next ports. Sequence stores ordered references to nodes in the same
graph. Edges, cases, and sequence children retain authored order. T010 stores
these contracts; T011 checks graph consistency and later script work executes
them. No scheduling, dispatch, builtin action implementations, hook functions,
or continuation component is added here.

Action signatures are declarative schema-able descriptions, not function
pointers or a global registry. Action/custom-trigger/script names are symbolic
vocabulary keys; they are not authored-object ids. `CallGraph`, graph edges,
and other authored-object references use `Ulid`. Never serialize runtime
`StatId`/`TagId` handles, components, or rules/sim types in IR payloads
(ADR-0008 as clarified by ADR-0011).

Wait and timer tick counts are relative `u64`, including zero and `u64::MAX`.
They are never seconds, rounds, turns, or absolute timestamps. Future execution
uses core `Tick` for absolute scheduling and its checked arithmetic; T010 must
not create another Tick type or promise that every relative wait fits every
current tick. No duration conversion occurs here.

## Behaviour

### Wire representation and schema boundary

1. Each file is exactly one JSON object. `Document` is internally tagged by
   `schema`, with the explicit variant strings listed below. Its payload
   fields are in that same object, not under `data` or the Rust variant name.
   Entity/aggregate payload structs do not themselves contain `schema`;
   persistence uses `Document`, never a bare payload serializer.
2. Initial schema ids are all `/1`. Do not infer `/3` from the illustrative
   creature example in §4.3. Unsupported ids or versions fail before typed
   payload decoding; there is no migration, fallback, or implicit downgrade.
3. Map field names are snake_case. Every `note` is serialized as `_note`,
   omitted for `None`, and otherwise preserved byte-for-byte as string content.
   Loader semantics ignore it. Other Option fields are required on input and
   serialize as explicit `null` for `None`. All non-note fields are required;
   empty collections must be present. All shapes reject unknown fields.
   Serde's ordinary Option derive accepts missing fields: use a private
   required-nullable deserializer and `schemars(required)` for non-note
   Options so runtime acceptance and generated required lists agree.
4. `DialogueBody`, `Trigger`, `NodeBody`, and `Port` use internal `kind` tags
   with snake_case variants, including unit variants as objects (e.g.
   `{"kind":"end"}`). `PackageKind`, `ValueType`, and `VariableScope` are
   snake_case strings. No `flatten`/`deny_unknown_fields` combination that
   accidentally rejects the outer schema tag: use private wire helpers where
   necessary and test the complete document encoding.
5. Existing core serde remains authoritative: ULID string output is canonical
   uppercase Crockford base32; input accepts the aliases core already accepts.
   Fixed point is raw `i32`, not decimal JSON. Absolute ticks, if described in
   helpers, are `u64`. No core edits to add schema traits. Use data-local
   `schema_with` adapters or equivalent derive surrogates for core and semver
   fields, including nested collections. ULID schema describes the accepted
   case-insensitive alphabet/aliases and 128-bit overflow limit (decoded first
   digit `0..7`, including aliases for zero/one), not just its canonical output.
   Version/requirement schemas are
   strings with descriptions; semver parsing remains the runtime authority.
6. `name`, locale keys, tags, stat names, expression strings, and symbolic
   action/script keys are stored as strings. Do not intern at this boundary.
   Reuse core `Interner`/`Interners` later at the T014 conversion boundary,
   not a duplicate interner or serialized runtime handles in T010.
7. Bounds/transform coordinates are fixed-point authored data. Rotation is
   Euler XYZ in degrees and scale is dimensionless; no conversion to sim's
   spatial representation occurs here. Geometry, rules checks, and rendering
   settings beyond these fields remain later schema extensions.

root schema must enforce its single supported schema tag, not accept the whole
Document union. Private one-variant internally-tagged derive wrappers around
the existing payload types are the prescribed way to achieve this without
maintaining hand-written copies of field schemas. Public `Document` may derive
the full union independently. Root titles equal their Rust payload names;
embedded schemas use `Placement`/`ActionSignature`. Keep each file self-contained
with local `$defs`; do not add external `$id` URLs. Emit through `canonical_json`.
No timestamps, absolute build paths, or nondeterministic metadata.

### Canonical writer

- Recursively sort object keys by Rust string lexical order (UTF-8 byte order),
  independent of serde_json's unified `preserve_order` feature. Preserve every
  array's order; sorting a map is not permission to sort an authored array.
- Use serde_json-compatible escaping, two-space pretty indentation, LF only,
  no BOM, no trailing whitespace, and exactly one final LF. Nonempty arrays
  place each element on its own line/group; nested objects are multiline.
  Empty objects/arrays are `{}`/`[]`. No custom line-width wrapping.
- Accept JSON integers representable as `i64` or `u64`; reject floating-number
  representations, including `1.0` and `1e0`, recursively. Do not call floating
  conversion APIs. Test primitive fields through their typed representations.
- `canonical_json` is an encoding utility, not a campaign validator. It may
  encode null, booleans, strings, arrays, and objects for schema generation.
  The document reader enforces the top-level object and schema contract.
- Use a duplicate-key-rejecting JSON parse visitor before converting input to
  an ordinary Value; last-key-wins would silently discard author content.
  Byte APIs reject a BOM and trailing non-whitespace input. Noncanonical
  whitespace is accepted and normalized on output.
- Byte stability is `write(read(write(value))) == write(value)`. Arbitrary
  noncanonical input need not survive unchanged; checked-in fixtures must be
  canonical already. Typed ULID/semver normalization happens before writing.

### Fixed validation order

This is fail-fast structural acceptance, not T011's semantic validation pass.
All compound-invalid tests must assert the first error by enum variant.

**`read_document`:** (1) UTF-8/JSON syntax, duplicate keys, and integer-only
number acceptance; (2) top-level object and string `schema` field; (3) supported
schema id; (4) typed decoding with unknown-field rejection; (5) lock-local
invariants if it is a lock. Phase 1 scans source order; the custom parse visitor
implements integer visits and leaves floating visits at serde's rejecting
default, so no float type declaration is needed in data. This also rejects
JSON `-0` when serde_json classifies it as a floating representation; canonical
integer zero is `0`. Malformed syntax or numeric representation necessarily
wins over an unsupported tag. Within typed
decoding, traverse object keys in lexical order; serde_json detail text is not
a stable public diagnostic contract. Standalone errors have `path: None`.

**`load_campaign`:** perform each phase for the whole input before the next:

1. Check ASCII-case path collisions in lexical path order; report the second
   colliding path as `Layout`. Check presence of `campaign.json`,
   `campaign.lock`, and `assets/assets.lock` in that order (`Layout`).
2. Read documents in lexical `SourcePath` order with `read_document`, attaching
   the current path to `Malformed`/`UnsupportedSchema` errors.
3. Enforce the layout below in lexical path order (`Layout`). Exactly one
   Campaign, CampaignLock, and AssetsLock must exist at their required paths.
   Their duplicate placements elsewhere are layout errors, not index errors.
4. Check `campaign.engine.matches(engine_version)`, else
   `EngineIncompatible`. Never compare against the data crate's package version
   or detect a running engine version internally.
5. Build the ULID index in lexical document-path order. Within a document,
   insert the root entity first, then identified array entries in authored
   order (graph before its nodes, dialogue before nodes, quest before states).
   Aggregate order is placements or graphs followed by each graph's nodes.
   A repeated id yields `DuplicateId`, even if both entries share a file or
   have identical contents. Never overwrite the first entry.
6. Check locked package coverage/kinds/ranges against campaign requirements
   in package-id order (`InvalidLock`), then compare the recomputed assets-lock
   digest (`AssetsLockMismatch`, expected = campaign lock, actual = computed).
7. Return all documents and the complete index. Do not check dangling object
   references, referenced kinds, slugs, graph reachability, locale coverage,
   variable default types, asset existence, or geometry consistency here.

Index pointers are RFC 6901 pointers to the containing object, not to its `id`
field: `""` for an entity root, `/placements/0`, `/graphs/0`,
`/graphs/0/nodes/0`, `/nodes/0`, `/states/0`. No fake ids for aggregate wrappers,
edges, variable names, or locale keys. Typed reference fields stay as ULIDs;
index construction does not resolve them to runtime entities.

`serialize_campaign` checks required files and case collisions as in phase 1,
then layout, document-local invariants, duplicate ids,
and lock consistency in the same relative order as phases 3, 5, 6, then emits
all files. Shared private functions must implement these checks; do not
maintain an independent write-side policy. It does not mutate the input.

### Resolver and lock invariants

- `resolve_packages` is pure. It consumes a flat supplied candidate catalog,
  never a filesystem, environment variable, network registry, or another
  package's requirements. No diamond/transitive resolution or vendoring.
- Repeated requirements for a package are intersected, not overwritten.
  Check requirement kind conflicts first, by ascending package id. Multiple
  kinds for one package produce `PackageKindConflict`.
- Next normalize the candidate catalog by package id, kind (Campaign, Module,
  Ruleset order), and exact version string. Repeated identical entries collapse;
  the same package/exact-version with different kind or checksum produces
  `CandidateConflict`, including unused candidates. Report the first conflicting
  package/version in lexical order, independently of input permutation.
- Then resolve required packages by ascending package id. Eligible candidates
  have the required kind and match **every** requirement using semver 1.x
  `VersionReq::matches`, including its prerelease rules. Choose highest semver
  precedence; if precedence ties because of build metadata, choose the
  lexically greatest complete version string. This is a deterministic tie
  rule, not a claim that build metadata changes semver precedence.
- With no eligible candidate, return `UnresolvedPackage` with the package and
  sorted, deduplicated normalized requirement strings. Empty requirements and
  a valid catalog produce an empty result. Unused valid candidates are ignored.
- Output is a unique package-id-sorted `Vec<ResolvedPackage>`. No checksum is
  fabricated; it is copied from the selected candidate.
- Campaign locks must already contain unique packages in strictly ascending
  package-id order. Both read and write reject unsorted/duplicate lists with
  `InvalidLock`; the canonical writer never silently sorts arrays. Empty is
  valid. Against a campaign, the lock must cover exactly its unique required
  packages, with matching kinds and versions satisfying all ranges. It need
  not be the newest possible resolution; loading a lock never re-resolves it.
- Asset paths are campaign-relative, begin with `assets/`, and cannot be
  `assets/assets.lock`. ASCII-case collisions and invalid asset roots are
  `InvalidLock`, checked in lexical asset-key order. SourcePath syntax is
  enforced during decoding before these lock-local checks.
- Lock readers require the correct document kind; another supported schema is
  `Layout`. `make_campaign_lock` validates the asset lock first, then resolves,
  then hashes the canonical asset lock. Writers reject malformed lock values
  even when constructed directly through public fields.
- `assets.lock` owns per-source-asset hashes and import settings. `campaign.lock`
  owns resolved package versions/checksums and exactly one `assets_lock` digest.
  It contains no duplicate asset table. Packaged `manifest.json` is a third,
  separate authority over final packaged bytes; T010 neither models nor emits
  that manifest and never uses its future semantics to validate source assets.
