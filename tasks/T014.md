## Approved decisions and sequencing

1. **Kernel first.** Rules owns typed in-memory definitions. No filesystem,
   JSON ruleset loader, campaign schema, or `crpg-data` dependency is added.
   The existing data stats (`BTreeMap<String, Fx16_16>`) do not become this
   task's complete authoring format. A future data task supplies the adapter.
2. **Staged value model.** T014 implements Int, Fixed, Bool, Enum, and Tags.
   Dice-valued stats and DiceExpr land together in T015; no opaque string or
   placeholder Dice variant. This is an explicit staging of spec §3.2, not
   a claim that its entire value model is finished.
3. **Pure queries over borrowed input.** No effect store or mutation of base
   values. Stable caller-supplied modifier IDs, explicit policies, canonical
   folds, and complete breakdowns establish the behavioural baseline.
4. **Typed derived expressions.** References read fully modified values on
   the same entity. Conditions read only supplied tags, so they cannot add
   hidden stat dependencies. Reject cycles before constructing the pipeline.
5. **Lifecycle hook contracts first.** Implement the five concrete lifecycle
   variants below and a pure-handler signature. Roll/DC modifier targets and
   BeforeRoll/AfterRoll/BeforeDamage/AfterDamage wait for T015's resolution
   vocabulary; effect/action/movement hooks wait for their owning capability.
   No empty catch-all hook, placeholder payload, or dispatch implementation.

These choices preserve the kernel's intended generality while keeping the
implementation within one crate. Follow-up obligations are recorded here;
do not edit T015, the engine spec, or status files during this task.

the pipeline validates that at query time. Invalid insert leaves it unchanged.

### Modifiers and query input

```rust
    StackAll,
    HighestBonusWorstPenalty,
    HighestPriorityPerName,

    pub entity: EntityId,
    pub stats: &'a StatBlock,
    pub tags: &'a TagSet,

pub struct ModifierPipeline { /* immutable validated definitions/policies */ }

impl ModifierPipeline {
    pub fn new(
        definitions: Vec<StatDefinition>,
        policies: BTreeMap<ModTypeId, StackingPolicy>,
    ) -> Result<Self, RulesError>;

    pub fn query(
        &self, entity: EntityId, stat: StatId, context: &QueryContext<'_>,
    ) -> Result<(StatValue, ModifierBreakdown), RulesError>;

```

Pipeline is Debug/Clone; QueryContext need only be Debug/Clone/Copy. The context
is a borrowed view for exactly one entity. All modifiers in it belong to that
entity; no owner inference from source IDs. Entity IDs come from core arenas,
not fabricated integers. Rules checks equality to `context.entity`, not arena
liveness or authority. Those remain the host's responsibility.

Caller owns active modifier membership and lifetime. To remove a source,
filter all modifiers whose entire SourceRef equals it and query again against
the same base block. There is no subtract-to-undo method or hidden mutable
cache. Distinct source kinds with the same ULID are distinct sources.

### Breakdown

```rust
pub enum ContributionStatus {
    ConditionFalse,
    ZeroAdd,
    Suppressed { winner: Ulid },
    Applied { before: StatValue, after: StatValue },
}

pub struct Contribution {
    pub modifier: Modifier,
    pub status: ContributionStatus,
}

pub struct StatTrace {
    pub base: StatValue,
    pub value: StatValue,
    pub dependencies: Vec<StatId>,
    pub contributions: Vec<Contribution>,
}

pub struct ModifierBreakdown {
    pub entity: EntityId,
    pub stat: StatId,
    pub traces: BTreeMap<StatId, StatTrace>,
}
```

Every success includes the root trace; returned value equals its `value`.
`base` is the stored base or evaluated derived expression before that stat's
modifiers. `dependencies` is the sorted/deduplicated list of direct references
in its formula. The flat traces map includes each transitively evaluated stat
exactly once (diamonds do not duplicate subtrees). It excludes unqueried stats.
No persistent breakdown format or serde is introduced for runtime handles.

Contributions include all supplied modifiers targeting that trace's stat,
even false conditions and stacking losers. Other targets have no contribution
in that trace. Order every contribution by phase then ascending `(priority,
id)`, including excluded contributions. Applied before/after follows that
same order with excluded entries skipped. Saturated, overwritten Set, and
numerically unchanged selected operations are still Applied. An empty
modifier list returns an empty contribution list, never an absent breakdown.

## Behaviour

### Definition validation and resource bounds

Expose these `pub const usize` limits and use them at every applicable entry:

| Constant | Value | Meaning |
|---|---:|---|
| `MAX_STATS` | 1024 | definitions, StatBlock entries, persisted entries |
| `MAX_TAGS` | 1024 | one tag set, including query tags/literals/persisted tags |
| `MAX_ENUM_VARIANTS` | 1024 | variants in one enum domain |
| `MAX_POLICIES` | 1024 | stacking-policy entries |
| `MAX_MODIFIERS` | 4096 | modifiers in one context, before target filtering |
| `MAX_EXPR_NODES` | 4096 | nodes in one derived expression |
| `MAX_TOTAL_EXPR_NODES` | 65536 | expression nodes in one definition set |
| `MAX_EXPR_DEPTH` | 32 | root counts as depth one |
| `MAX_DERIVED_DEPTH` | 128 | longest stat dependency path, endpoints included |
| `MAX_CONDITION_NODES` | 256 | nodes in one condition |
| `MAX_CONDITION_DEPTH` | 32 | condition root counts as depth one |

Limits are bounded-kernel contracts, not configurable gameplay constants or a
claim to bound allocations callers have already made. Check tree depth/count
iteratively before recursively evaluating or cloning trees. Never process
unbounded dependency recursion or expand all paths in a diamond graph.

`new` validates limits, unique stat IDs, valid enum domains, policy names,
all expression references/types, and the whole dependency graph. Reusing an
enum_id with different variant sets is invalid; equal domains may be shared.
Enums require a nonempty name and 1..=MAX_ENUM_VARIANTS nonempty variants.
Enum literals must name a declared domain and member. No implicit defaults.
Literal and Stat nodes can produce any supported kind; all six binary
operators require two Ints or two Fixed values, with that same result kind.
The final expression kind must exactly match its declaration. No implicit
Int/Fixed conversion, enum ordering, or tag/bool arithmetic.

Forward references are legal. Reject unknown references, self-cycles,
multi-node cycles, disconnected cycles, and excessive acyclic depth at `new`.
Traverse stat roots/neighbours in ascending StatId order. A reported cycle is
the DFS cycle with its repeated closing vertex, rotated to its smallest
StatId; use that structured path in the error. An empty definition set is
valid. `new` takes no interner and cannot prove handle provenance.

### Query validation and conditions

Validate in this order: entity equality; requested stat exists; top-level
context limits (stats, tags, modifier counts);
all stored base entries by ascending StatId; modifier ID uniqueness; all
modifiers by ascending ID; then evaluate the requested dependency closure.
Stored entries must be declared, exactly typed, and not derived. A derived
stat with a stored base is an error, not an override. Missing base values are
errors only when evaluated; an unrelated undeclared or malformed stored entry
still invalidates the context. Duplicate modifier IDs are rejected across the
entire context, not just one target or phase. Arbitrary ULIDs, including zero,
are accepted as identities; T014 does not generate IDs.

Validate every modifier, even an unrelated target or false condition: declared
target, known nonempty mod_type, nonempty source kind, valid optional name,
operation/kind/policy compatibility, value/domain membership and limits, and
condition shape/limits. Nested value/tree limits are checked in this per-object
phase before traversing/cloning that object. Set accepts exactly the target
kind. Add accepts only a same-kind Int or Fixed. Multiply accepts either numeric target, with its
explicit fixed factor. Clamp requires numeric bounds of the target kind and
`min <= max`. No coercion, silently ignored invalid candidate, or fallback
policy. A missing name is legal except under HighestPriorityPerName.

Condition None means true. HasTag reads only `context.tags`, never a stat's
Tags value or a recursive stat query. Empty All is true; empty Any is false.
Evaluate All/Any left-to-right with short circuit after full shape validation.
Missing tags are false. Tags/conditions use the caller's issuing namespace;
query has no interner with which to validate individual handle provenance.

### Stacking and order

Filter false conditions first. Group remaining candidates by `(target stat,
mod_type, operation phase)`. Policies are looked up by mod_type; phase groups
prevent a Set and an Add from suppressing each other merely by sharing a name.

| Policy | Allowed ops | Selection within each group |
|---|---|---|
| StackAll | all supported ops | Keep all candidates. |
| HighestBonusWorstPenalty | Add only | Keep largest strictly positive amount and smallest strictly negative amount, independently. Zero amounts are ZeroAdd. |
| HighestPriorityPerName | all supported ops | Require a nonempty name; keep the greatest `(priority, id)` for each exact name, regardless of source. |

For equal positive/negative magnitudes, choose greatest `(priority, id)`.
Each suppressed nonzero candidate records the selected same-sign winner;
name-policy losers record the winner for that name in the phase. ZeroAdd is
exclusive to HighestBonusWorstPenalty; StackAll/per-name may apply zero Add.
False condition takes precedence over all stacking statuses. A policy being
selected per type is ruleset data; no stat/type/source names have special
meaning in production code.

Apply retained operations globally across all types in phase order
`Set -> Add -> Multiply -> Clamp`, then ascending `(priority, id)` within
each phase. Higher priority runs later. Equal-priority larger ID runs later
and wins repeated Sets. Selection ties use the same greater-ID convention.
No fold by mod_type, insertion order, or hash order. Multiple clamps apply
sequentially; contradictory intervals are allowed across separate modifiers
and the later clamp controls the result. Each individual interval must be valid.

### Arithmetic and derived evaluation

- Int Add/Subtract/Multiply use i64 intermediates and saturate to i32 after
  each operation. Int Divide floors toward negative infinity, not toward zero;
  MIN / -1 saturates to MAX. Any expression division by zero returns a typed
  RulesError, for Int and Fixed alike (check before calling core division).
- Fixed arithmetic uses the existing saturating/floor Fx16_16 methods; no
  new rounding policy or reimplementation of core arithmetic.
- ModOp::Multiply on Int is `floor(i64(value) * i64(factor.to_raw()) / 65536)`
  clamped to i32. Do not pass the integer through Fx16_16::from_int. On Fixed,
  use core multiplication. Negative and zero factors are legal.
- Min/Max and Clamp compare numeric values within their declared kind. Set
  replaces exactly; Bool/Enum/Tags support Set only. No stat-level bounds or
  hidden final clamp. All rounding/saturation is per operation, not once after
  regrouping additions or multiplications.
- Evaluate expression operands left before right, using the authored tree
  grouping. Stat references query that entity's fully modified value.
  Compute each referenced stat once per query using local memoization, then
  apply the current stat's modifiers. No cache survives a query.
- Example oracle: base Int(10), Add(Int(3)), Multiply(1.5), Clamp(Int(0),
  Int(18)) yields 18 with transitions 10->13->19->18. Int(-3) multiplied by
  0.5 yields -2. Int(100000) multiplied by 1 yields 100000, not 32767.
- Canonical saturation oracle: base Int(MAX), priority-zero IDs 1 and 2 with
  Add(1) then Add(-1) yields MAX-1 for either input ordering. Removing ID 1
  restores the result of the original base plus the remaining ID 2; removing
  both restores MAX. Never try to invert the previously computed result.

### Errors

Use an owned, structured error (Debug/Clone/PartialEq/Eq), implementing std
Display/Error without new dependencies:

```rust
pub enum RulesErrorCode {
    InvalidName, LimitExceeded, DuplicateStat, DuplicateModifier,
    DuplicateTag, InvalidEnum, UnknownStat, UnknownModifierType,
    UnresolvedHandle, TypeMismatch, InvalidOperation, InvalidClamp,
    DerivedBase, MissingBase, EntityMismatch, Cycle, DivisionByZero,
}

pub struct RulesError {
    pub code: RulesErrorCode,
    pub location: String,
    pub cycle: Vec<StatId>,
}
```

Only Cycle has a nonempty `cycle`; location is an owned diagnostic path, not
a persisted identity. Use `/definitions/<stat-index>`, `/policies/<escaped-name>`,
`/stats/<stat-index>`, `/modifiers/<canonical-ULID>`, `/context`, or
`/persisted/entries/<array-index>` as the relevant root; append field names and
zero-based child indices as needed. Definition paths use `StatId::index()`,
not the input vector position. Escape symbolic path components with RFC6901
`~0`/`~1`. For an unknown queried stat use `/stats/<stat-index>`; entity
mismatch uses `/context/entity`. Display is exactly `<Code> at <location>`,
where Code is the enum's spelling. Cycle details remain available structurally.
Human consumers must not persist these runtime-index paths as stat identities.
Collection-wide errors use the collection root without an element suffix;
cycles use `/definitions/<smallest-cycle-stat-index>/derived`. For duplicate
IDs choose the smallest duplicated ID; for duplicate persisted strings report
the second occurrence in authored array order, before sorting.

Use LimitExceeded for every stated bound, InvalidName for empty symbolic
strings, InvalidEnum for unknown domain/member or inconsistent domains,
TypeMismatch for incompatible value/expression kinds, InvalidOperation for
unsupported op/policy or required-name absence, and the specifically named
codes for other failures. Check whether an operation is supported on the target
kind before checking its operand kinds: Add on Bool is InvalidOperation, while
Add(Fixed) on Int is TypeMismatch. Empty names remain InvalidName (distinct
from a missing required name). Query-error ordering follows the validation phases
above. New validates limits, duplicate IDs, declaration/domain/policy shape,
references, cycles/depth, then expression types in that order; roots are sorted
by ID (policy names lexically). Within one object, use declaration field order
and expression preorder. No panic on a well-formed Rust input's domain errors.

## Symbolic persistence

```rust

```

Derive serde only for these DTOs and EnumValue (and hooks as specified below).
Use closed structs (`deny_unknown_fields`); SerializableStatValue is adjacently
tagged with `type` and `value`, lowercase variant names, unknown fields denied.
Fixed stores core's raw i32. Entries are an array to preserve duplicate-key
evidence for validation; never deserialize stat entries into a map first.

`to_serializable` resolves each key/tag through the supplied issuing Interners,
rejects unresolved or empty names, sorts entries lexically by stat string and
tags lexically by tag string, and preserves all value kinds. Enum names/members
remain strings. `from_serializable` accepts unsorted entries/tags, rejects
duplicates instead of merging them, validates all standalone values/names and
limits before any interner mutation, then interns in canonical lexical entry
order (tags lexical within each value). A returned error leaves Interners
unchanged. No requirement to recover from allocator failure or core's exhausted
u32 namespace panic. Enum domain membership is checked later against pipeline
definitions; this standalone conversion knows only nonempty enum strings.

No production JSON writer is needed. Tests pin `serde_json::to_string` on the
DTO (compact JSON, no LF); representative exact bytes are:

```json
{"entries":[{"stat":"alpha","value":{"type":"int","value":7}},{"stat":"beta","value":{"type":"fixed","value":32768}}]}
```

Unknown/duplicate struct fields are rejected by direct DTO deserialization;
duplicate entry names/tags are rejected by conversion with DuplicateStat or
DuplicateTag. Do not decode through serde_json::Value first. EnumValue field
order is enum_id then variant. StatBlock/StatValue/StatId/TagId remain runtime
only; serialization must never reveal numeric interned handles.

The caller must supply the issuing interner. A valid index in the wrong
interner cannot be detected by existing core handles; document that limitation
rather than promising provenance checking. Tests compare symbolic meanings
after restoration into an interner with different handle assignments.

## Lifecycle hook boundary

```rust
pub enum KernelHook {
    OnDeath { entity: EntityId },
    OnTurnStart { entity: EntityId },
    OnTurnEnd { entity: EntityId },
    OnRoundStart { round: u32 },
    OnEncounterStart { encounter: Ulid },
}

pub enum HookMutation {
    SetBaseStat { entity: EntityId, stat: StatId, value: StatValue },
    RemoveSource { entity: EntityId, source: SourceRef },
}

pub type HookHandler = fn(&KernelHook) -> Result<Vec<HookMutation>, RulesError>;
```

KernelHook is a rules-owned vocabulary with only core-closed fields. Give it
serde using `#[serde(tag = "type", rename_all = "snake_case", deny_unknown_fields)]`;
pin every variant's round trip and one EventQueue<KernelHook> round trip in
rules-owned tests. This consumes the existing core API without altering core.
Round zero and zero ULIDs are valid; event meaning/liveness belongs to the host.

HookMutation is runtime-only command data, never an EventQueue payload or
persisted record. It intentionally contains runtime handles and rules values.
It proposes a base-stat update or removal; it does not mutate anything itself.
The eventual host validates declarations, liveness, permissions and ordering
before applying proposals. Handler purity is a documented convention, not a
claim the fn type prevents external side effects. No host/world reference is
passed. Returning Err produces no mutation list and applies nothing in rules.

There is no handler registry or dispatcher here. Caller-provided handler and
returned-vector order must be preserved by future dispatch work; T014 tests
direct sample handler calls only and must not claim production dispatch.

### Table and properties

`modifier_table` must execute at least 100 named, genuinely distinct rows and
assert its row count is >=100. Each row has independently specified expected
value and exact trace/contribution statuses and ordering, or error code and
location. A Cartesian product of irrelevant labels or repeated cases does
not meet this requirement. Expected numbers must not be computed by the
pipeline under test. Include:

- Every legal policy/op/kind combination and each illegal combination.
- Phase precedence independent of input order; cross-type global ordering;
  priority and greatest-ID ties for both selection and application.
- Independent positive/negative selection; zero status; same-name suppression
  across sources; distinct names; phase isolation; false winner candidates.
- Conditions None/HasTag/Not/All/Any, empty groups, missing tags, and malformed
  false-condition modifiers still failing before evaluation.
- Positive/negative/zero factors, fixed precision edges, full-range Int
  multiplication, intermediate saturation, repeated Sets, sequential disjoint
  clamps, invalid bounds, wrong kinds, no implicit conversion.
- Numeric and nonnumeric Set; enum domain/member validation; Tags replacement;
  empty modifiers; derived bases; unrelated targets and unknown mod types.
- Every RulesErrorCode across the full suite; exact validation precedence for
  representative multi-fault inputs and no context mutation on error.

`modifier_properties` uses proptest with at least 1024 cases per property:

1. Permuting a valid modifier slice preserves both result and the entire
   breakdown, including stacking winners and canonical applied order. Include
   multiple types/phases and duplicate priorities; shrinkers preserve valid
   unique identities or explicitly reject invalid generated inputs.
2. Starting with a valid context and a fresh SourceRef, add one or more
   modifiers from that source, query, remove exactly that source, and require
   exact equality of returned values/breakdowns with the original query.
   Assert the augmented query succeeds; include cases that actually alter the
   result, trigger saturation/rounding, and compete for stacking selection.
   Surviving modifiers must remain unchanged. This is membership reversal,
   not a claim that arithmetic inverses exist.
3. Int scaling matches a separate i64 floor/clamp oracle across the i32 range
   and raw fixed factors, without floats. Fixed edge vectors use independent
   raw-integer expectations rather than calling the same arithmetic helper.

Preserve any proptest regression files produced while fixing failures.
