# T139 — persistent creature state; join and leave (`crpg-sim`, with the `crpg-data` prerequisite T139d)

**Status: approved with changes by the user 2026-10-30 (D39a); revised to
those answers here. Awaits one Claude `reviewer` pass (D39); the user is
asked again only for the "Open questions" below.**

## Task
ADR-0029 Follow-on 6 (`docs/adr/0029-kernel-range-and-time-model.md:485`):
persistent creature state outside encounters (stats, pools, effects, tags),
and the journaled join and leave operations of T13 and T14 (`:256-264`),
under T16's rule that every World change is a journaled operation
(`:273-277`). It closes three hand-offs:
- `tasks/T137.md:815-818`: T139 owns non-`Int` stats and creature tags
  outside encounters.
- `tasks/T138.md:602-603` (B31): T138 added no join operation.
- `tasks/T138.md:851-858`: the T14 join rules, and two open decisions. One is
  whether a join into a terminal RT encounter is rejected. The other is how
  `OnTick` pools refresh outside an encounter.

D39a adds three rule hooks that the ruleset (and, for one of them, the
encounter) can set, and changes the default so that survivors persist.

Today no creature state exists outside an encounter. `World`
(`crates/crpg-sim/src/world.rs:68-99`) has no creature store.
`start_encounter` mints one fresh entity per authored participant
(`crates/crpg-sim/src/combat.rs:1946-1947`) and builds its `Combatant` from
the prefab. `end_encounter` strips every combatant (`:3736-3741`), so the
entities stay live but carry no stats, pools, effects or tags.

## Decision
- **D1. Persistent state is one new `World` store,
  `creatures: ComponentStore<CreatureState>`.** An entity holds a
  `CreatureState` (a *record*) or a `Combatant`, never both. Outside an
  encounter the record is the only copy of the creature; while it fights,
  the `Combatant` is the only copy. *Rejected:* fields on `EntityMeta`
  (`world.rs:45-59`), which change every entity's bytes and have no absence
  form; keeping the record during a fight, which leaves a stale second
  health value readable through `World::creatures()`.
- **D2. Survivors persist by default (D39a OQ1).** Every combatant that
  leaves or outlives an encounter becomes a record, alive or dead. A start
  enters each authored participant from the record that holds its
  placement, skips it if that record is dead (the dead stay dead), and
  spawns it fresh only when no record holds its placement. An encounter
  *respawns* when its authored `respawns` is `true` or its ruleset's
  `creature_persistence` is `registered`. Then its authored participants
  always spawn fresh, the store is not read for them, and a spawned
  combatant is never written back. A combatant that *entered* from a record
  is always written back, whatever the encounter. *Rejected:* the
  proposal's registered-only default (changed by D39a). Also rejected:
  reading the store in a respawning encounter, which would let a
  repeatable fight consume a survivor's record.
- **D3. A record is found by its placement, and a placement has at most one
  record** (load check K10; registration check R5). A dead record is a
  record with `health == 0`. A start in which every authored participant is
  skipped and no member enters fails `NoEntrants`. `despawn` removes a
  record with the rest of the entity (AGENTS invariant 1), so a despawned
  placement spawns fresh at its next start (open question 2).
- **D4. Three ways to enter from a record.** An authored participant enters
  at start (D2). A *member* enters at start through
  `start_encounter_with_members` (D39a OQ2). A *joiner* enters later through
  `join_encounter`. Members and joiners are `Entrant`s, which carry the
  entity, a base initiative key, and the placement and prefab documents.
  Members compete for the first turn as authored participants do.
  *Rejected:* matching members to authored participants, which cannot bring
  a party member into another area's encounter; a field on `EncounterSpec`,
  whose literals sit in four other crates (T138 D3).
- **D5. A record stores no tags; every entry reads the prefab's tags.**
  T137 B19 carries a combatant's tags only when an effect of its encounter
  grants tags. The shipped `combat_basic` and `combat_srd` prefabs have tags
  and no granting effect, so their spawned combatants carry none. Writing
  back their tags would mean carrying them, which moves the unapproved
  `crpg-testkit` goldens. Base tags are authored constants: no operation
  adds or removes a creature's own tags, and grants live on attachments. So
  the prefab is the one copy, and the B19 rule holds for every combatant.
  This is why an `Entrant` carries its prefab (open question 3).
- **D6. Non-`Int` persistent stats are the base `Fixed` values (D39a OQ6),
  stored on the record and carried by every combatant.** The prefab's `stats`
  is a `BTreeMap<String, Fx16_16>` (`crates/crpg-data/src/document.rs:117-119`),
  and data checks completeness only for non-derived `Int` and `Fixed`
  (`crates/crpg-data/src/validation.rs:829-835`). Carrying `fixed` on every
  combatant changes bytes only for rulesets with a base `Fixed` stat. No
  shipped ruleset has one; only the `surface_v1` schedule does
  (`tests/support/surface_schedule.rs:90`), and that golden is approved.
- **D7. Join placement follows T14; the ruleset picks the round-0 late case
  (D39a OQ3).**
  - TB, round 0, a key that sorts after the active head: inserted at once.
  - TB, round 0, otherwise: by default it *waits* (no timeline entry). The
    next rollover inserts it, because `tb_round_start` re-inserts every
    alive combatant (`combat.rs:3261-3269`). Under `late_join:
    after_active` it goes on `CombatState.pending_joins`. The next
    `advance_tracked` inserts every alive pending joiner at its own key
    before it picks a head. Each pending joiner sorted before the departed
    head, and every remaining entry sorts after it, so the joiners act next
    in key order. No key is clamped, and "active is the timeline head"
    (`world.rs:600-611`) holds.
  - TB, round 1 or later: it always waits.
  - RT: keyed at `elapsed` with `order: None` (T138 B11).
- **D8. A terminal encounter refuses joins (D39a OQ4)** with
  `EncounterTerminal`. Terminal stays absorbing; an encounter journals
  `EncounterEnded` at most once.
- **D9. Nothing happens to a creature outside an encounter; the ruleset
  picks what effects become at exit (D39a OQ5).** No pool refreshes
  (`OnTick` included), no attachment counts down, and `tick` leaves the
  store alone. At exit, by default (`suspend`) each attachment is stored as
  its remaining rounds. `strip` stores none at leave or at release.
  `strip_at_release` stores none at release and suspends at leave. Entry
  always resumes a suspended entry as `round + remaining` if the new
  encounter's definition has that effect, and drops it otherwise.
- **D10. Join and leave are free functions plus `HistoryWorld` methods, not
  `CombatAction` variants.** A join has no acting combatant, and AI
  enumeration must not offer either one (T138 D7). `legal_actions` and
  `crpg-script` are unaffected.
- **D11. Leave mirrors `despawn`, but the entity survives.** One
  crate-private helper, `World::remove_combatant_tracked`, settles the
  encounter for both. It is extracted from `despawn_tracked` without
  change, plus one line that drops the id from `pending_joins`.
- **D12. History stays at version 2 (D39a OQ7), and records do not trigger
  the upgrade.** Under D2 every TB-only release writes records. A
  record-based trigger would therefore upgrade every TB-only history at its
  first release, which breaks the R18 assertions
  `tests/history_v2.rs:614` and `tests/history_v2_contract.rs:492`.
  `commit`'s upgrade condition and the loader's v1 block are unchanged; a
  version-1 wrapper may hold records. `Joined` and `Left` (T139c) are v2
  events. A start journals nothing for a combatant that entered from a
  record: the history differential tests
  (`src/history/tests.rs:159-183`, `:540-545`) compare
  `HistoryWorld::start_encounter` with a reference body that journals only
  the drained legacy events and `TurnStarted`.
- **D13. The lifecycle rules are copied at start into
  `CombatState.lifecycle`.** That struct is skipped when every rule is at
  its default, so default worlds keep their bytes. It is not on
  `CombatDefinition`, whose literal sits in an existing unit test
  (`combat.rs:3960`).
- **D14. The rule hooks are additive optional fields at the current
  versions (D39a; D32c rule).** `Ruleset` gains `creature_persistence`,
  `late_join` and `effects_on_exit`; `Encounter` gains `respawns`. There is
  no version bump, no migration edge, and every existing document decodes
  and re-encodes byte for byte (T139d).
- **D15. Golden impact.** The four files D39a approved move (`history_v1.*`
  and `surface_v1.*`). Three existing tests need a one-line `respawns`
  marker, because they replay an authored fight in the same world and
  expect fresh entities (open question 1). Nothing else moves.

/// Which placed creatures keep their state after an encounter.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, JsonSchema)]
#[serde(rename_all = "snake_case")]
pub enum CreaturePersistenceWire {
    /// Every placed creature that leaves or outlives an encounter keeps its state, and the dead stay dead.
    Survivors,
    /// Only creatures that entered from a kept state keep it; authored participants spawn fresh at every start.
    Registered,

/// Where a turn-based first-round joiner acts when its initiative slot has passed.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, JsonSchema)]
#[serde(rename_all = "snake_case")]
pub enum LateJoinWire {
    /// It waits for the next round.
    NextRound,
    /// It acts right after the current turn.
    AfterActive,
}

/// What a creature's attached effects become when it leaves an encounter or the encounter ends.

#[serde(rename_all = "snake_case")]
pub enum EffectsOnExitWire {
    /// They keep their remaining rounds and resume at the next entry.
    Suspend,
    /// They are removed at leave and at release.
    Strip,
    /// They are removed at release and kept at leave.
    StripAtRelease,
}

    pub fn ruleset(&self) -> Ulid;
    /// Base non-health, non-derived `Int` stats in authored stat order.
    pub fn attributes(&self) -> &[(String, i32)];

    pub fn dead(&self) -> bool;
    /// Pool balances in ruleset template order, primary first.
    pub fn pools(&self) -> &[ResourcePool];
    /// Suspended attachments, ascending effect identity.
    pub fn suspended(&self) -> &[SuspendedEffect];
}

    /// The placement's prefab.
    pub creature: &'a AuthoredCreature,

### T139d — the authored hooks
1. **B-D1 (decode) [d].** Each new key is absent or present. A present enum
   key must be a JSON string naming one variant. Any other JSON form fails
   with `creature_persistence must be a policy name`, `late_join must be a
   policy name` or `effects_on_exit must be a policy name`. An unknown
   string fails `unknown variant` and lists every variant. A present
   `respawns` must be a JSON boolean. An explicit `null` decodes as absent
   for all four (the `natural_die` precedent). Unknown keys are still
   rejected.
2. **B-D2 (encode) [d].** An absent field writes no key. A present field
   writes its key where the canonical key sort places it, explicit defaults
   included (`"survivors"`, `"next_round"`, `"suspend"`, `false`). The
   canonical encoding of every existing document is unchanged.
3. **B-D3 (no rule) [d].** No read-time check, no semantic rule and no
   diagnostic is added for any value or mix of the four fields.
4. **B-D4 (versions) [d].** The tags stay `crpg.ruleset/2` and
   `crpg.encounter/1`. The registry, edges, `schema_versions()` and every
   step are byte-unchanged. A `/1` ruleset migrates as today, and its result
   has all three ruleset fields absent.
5. **B-D5 (schemas) [d].** After `cargo run -p crpg-data --example

   types, and nothing else. `encounter.schema.json` gains exactly
   `respawns`. None of them is in `required`. The other 20 schema

6. **B-D6 (consumers) [d].** No crate outside `crpg-data` builds a
   `Ruleset` or `Encounter` by struct literal (checked: only four

   authored constants that no operation changes, the record names its
