## Decisions (binding for this contract; reviewable, no waiver granted)

1. **Four new document families, generic schema, minimal content.** New
   families `crpg.ruleset/1`, `crpg.ability/1`, `crpg.outcome-table/1`,
   `crpg.encounter/1` (registry `crpg.ruleset`, `crpg.ability`,
   `crpg.outcome-table`, `crpg.encounter`, all current version 1, no edges).
   Schemas are generic (any count, any `i64`/`u32` in range, all outcome
   labels, all refresh triggers); the minimal-d6 *content* pins exactly
   three attributes plus health, two bands, empty naturals, one pool, one
   ability, two participants. Counts are content tests, never validation.
   T017 extends content (or migrates schemas) without touching this logic.
2. **No wire change to existing families.** `Creature.stats` stays
   `BTreeMap<String, Fx16_16>`. Existing fixtures keep their meaning; their
   stats remain fixed-point values with no integer reinterpretation.
3. **Checked Fixed→Int conversion (adapter contract for T016b).**
   For each encounter participant, the sim adapter resolves placement →
   prefab creature and converts only the ruleset's declared stat names:
   each value must have zero fractional bits (`raw % 65536 == 0`); the
   integer part (`raw / 65536`, range `-32768..=32767`) always fits `i32`.
   Non-whole values fail validation here (`invalid_stat_value`); the
   adapter rejects them without truncation. Non-combat stats and existing
   campaigns are never converted.
4. **Resource template embedded in the ruleset.** One action pool template
   `{id, max, refresh}` lives in `Ruleset.action_pool`; `Ability.cost`
   spends from it. Pool `id` is a shared template identity (per-combatant
   runtime pools share it, distinguished by entity). No separate resource
   document. `current` is never authored; sim initializes to `max`.
5. **Self-contained fixture, empty package requires.** `combat_basic`
   embeds its ruleset/ability/table documents (same ULIDs as the canonical
   source) and declares no package requirements, so gate 8 stays standalone
   with its existing three roots. The package mechanism is already covered
   by resolver tests; duplicating it here buys nothing. `Ruleset.package`
   (`minimal-d6`) and `version` (`0.1.0`) still self-identify the ruleset.
6. **Orphan abilities allowed but unchecked.** Attribute/cost checks run per
   owning ruleset (each ruleset validates the abilities it lists). An
   ability listed by no ruleset keeps only its generic outcome-table
   reference check. Minimal content has no orphans (tested).
7. **Same-area consistency is T016b's init check, not data validation.**
   Data checks references, kinds, distinctness, stats, and costs; the
   adapter rejects multi-area encounters before publishing state.
8. **No new dependencies, no ADR, no downstream authorization.** This task
   follows the T010/T011a/T012a data-owned precedent (additive types,
   shared inventory, collected diagnostics). T016b still needs its own
   dependency approval (`sim → data`, `sim → rules`) and reviewed ADR for
   public API/state representation; nothing here grants either.

## Required ruleset semantics (from T016; content-pinned, never engine branches)

- Exactly three named attributes plus a separately declared health stat.
  Content: attributes `might`, `guile`, `resolve`; health `health`.
  All kind `int`. Initial values and the checked attribute are authored.
- One targeted attack: dice `2d6`, inclusive roll-under
  (`roll_total <=` actor's `might`), positive flat damage on success,
  none on failure. Content: damage `{success: 2, failure: 0}`, cost `1`,
  `requires_target: true`, `allow_self_target: false`.
- Kernel margin `roll_total - against_value` is unchanged. Authored bands:
  `{min_margin: i64::MIN, outcome: success}`,
  `{min_margin: 1, outcome: failure}`. No natural rules.
- One action per turn: pool `{max: 1, refresh: on_turn_start}`, cost `1`.
  Failed attacks still consume the action (sim); malformed/rejected actions
  consume neither resources nor randomness (sim; data authors the values).
- Names, thresholds, damage, costs, and policy are content. Production
  code holds no minimal-d6 identifier, attribute name, die count,
  threshold, or damage value.

## Interface (exact public shapes; re-export at the crate root)

New module `combat.rs`. All public items have rustdoc. Ordered collections
and integer/core values only; no floats, hash maps, OS branches, clocks,
or id generation. New `ObjectKind` variants `Ruleset`, `Ability`,
`OutcomeTable`, `Encounter` (in this declaration order after `QuestState`).

```rust
pub enum StatKindWire { Int }

pub struct StatDecl { pub name: String, pub kind: StatKindWire }

pub enum RefreshWire {
    OnTurnStart,
    OnRoundStart,
    OnRest(RestId),
    OnTick(TickPeriod),
    Never,
}

/// Opaque rest identity for authored refresh triggers.
pub struct RestId(pub Ulid);

/// Nonzero tick period for authored refresh triggers.
pub struct TickPeriod(pub u64);

pub struct ActionPoolTemplate {
    pub id: Ulid,
    pub max: u32,
    pub refresh: RefreshWire,
}

pub struct Ruleset {
    pub id: Ulid,
    pub slug: String,
    pub name: String,
    pub note: Option<String>,
    pub package: PackageId,
    pub version: Version,
    pub stats: Vec<StatDecl>,
    pub health_stat: String,
    pub attributes: Vec<String>,
    pub action_pool: ActionPoolTemplate,
    pub abilities: Vec<Ulid>,
}

pub enum OutcomeWire {
    CriticalSuccess, Success, Failure, CriticalFailure, Custom(u8),
}

pub struct DamageEntry { pub outcome: OutcomeWire, pub amount: u32 }

pub struct Ability {
    pub id: Ulid,
    pub slug: String,
    pub name: String,
    pub note: Option<String>,
    pub dice: String,
    pub attribute: String,
    pub outcome_table: Ulid,
    pub damage: Vec<DamageEntry>,
    pub cost: u32,
    pub requires_target: bool,
    pub allow_self_target: bool,
}

pub struct OutcomeBandWire { pub min_margin: i64, pub outcome: OutcomeWire }

pub enum NaturalEffectWire { Shift(i16), Override(OutcomeWire) }

pub struct NaturalRuleWire { pub face: u32, pub effect: NaturalEffectWire }

pub struct OutcomeTable {
    pub id: Ulid,
    pub slug: String,
    pub name: String,
    pub note: Option<String>,
    pub bands: Vec<OutcomeBandWire>,
    pub natural_rules: Vec<NaturalRuleWire>,
}

pub struct EncounterParticipant { pub placement: Ulid, pub initiative: i32 }

pub struct Encounter {
    pub id: Ulid,
    pub slug: String,
    pub name: String,
    pub note: Option<String>,
    pub ruleset: Ulid,
    pub participants: Vec<EncounterParticipant>,
}
```

Serde: structs `deny_unknown_fields`; `_note` optional-missing, other
nullable fields required-nullable with matching schema annotations;
`StatKindWire` snake-case string (`"int"`); `OutcomeWire`,
`RefreshWire`, `NaturalEffectWire` mirror the T015 adjacent `type`/`value`
snake-case shapes with hand-written `Deserialize` impls enforcing exact key
sets per variant (the unit-variant unknown-field trap: derived
`deny_unknown_fields` ignores trailing fields on unit variants, so keep the
manual impls plus unknown-field tests, exactly as for
`Trigger`/`NodeBody`/`Port`/`DialogueBody`). `Serialize`/`JsonSchema` stay
derived. Never serialize interned handles; stat references are strings,
table/pool/ruleset/ability/encounter identities are ULIDs.

`Document` gains `Ruleset(Ruleset)` (`crpg.ruleset/1`),
`Ability(Ability)` (`crpg.ability/1`), `OutcomeTable(OutcomeTable)`
(`crpg.outcome-table/1`), `Encounter(Encounter)`
(`crpg.encounter/1`).

- Document loop additions: new kinds contribute slugs (uniqueness within

  locale table, as for existing names). No reachability/completion logic.
- Combat semantic checks (after generic refs; at most one diagnostic per
  site; sorted by the existing six-field order):
  - For each ruleset, for each listed ability: `attribute` must name one
    of that ruleset's `attributes`, else `unknown_stat` at
    `<ability-file>/attribute`; `cost` must be `<= action_pool.max`,
    else `invalid_cost` at `<ability-file>/cost`. (Orphan abilities skip
    both; their outcome-table ref is still checked generically.)
  - For each encounter, resolve its ruleset (generic ref first; skip the
    rest on dangling/wrong-kind). For each participant placement, resolve
    placement → prefab creature: prefab must be a Creature, else
    `wrong_reference_kind` at `<encounter-file>/participants/<i>/placement`.
    The creature's `stats` must contain every ruleset stat name, else one
    `missing_stat` per absent name at the same pointer naming creature and
    stat. Every present ruleset-stat value must be whole (`raw % 65536 ==
    0`), else `invalid_stat_value`; the `health_stat` value must also be
    `> 0`, else `invalid_stat_value`. Attribute values accept any whole
    `i32` (no range policy in data).
- `campaign_document_path` accepts the four new families; classifier
  rejections stay `invalid_path`; `io` remains caller-owned.
- Introspection (`explain_object`) needs no logic change (generic
  navigate/inventory); extend `kind_spelling` with `ruleset`, `ability`,
  `outcome_table`, `encounter` and the spelling test.
