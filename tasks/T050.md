## Task

The next demo (brief, 2026-11-21): **the player clicks the ground in the
Godot client, their character walks there, and other entities move
smoothly**, through the embedded single-player server (the same authoritative
host on its run loop; no client-side stand-in for a server duty).

What exists: the v4 bridge session (T151) opens an encounter on the run loop,
shows positions (`CrpgView.positions()` and friends) and sends lane-1
`move_to`/`halt` with receipts (`crates/crpg-godot/src/shell.rs:60–100`). What
is missing, found in code:

1. **Every bridge encounter is turn-based.** `open_prefix` calls
   `history.start_encounter` (`crates/crpg-godot/src/core/mod.rs:584`), which is
   `start_encounter_in_mode(spec, TurnBased)` (`crates/crpg-sim/src/history.rs:875–877`).
   Lane 1 refuses a combatant of a turn-based encounter with `WrongMode`
   (`crates/crpg-server/src/host.rs:4061–4068`; the sim's own check,
   `crates/crpg-sim/src/movement.rs:785–791`), so today `move_to` can never
   walk a combatant (T151 B5 pins that rejection).
2. **No campaign can walk.** The only campaigns are `campaigns/fixtures/*`,
   and none may declare `movement` (`crates/crpg-data/tests/movement_fields.rs:111–140`);
   real time also needs the ruleset's `round_ticks`
   (`crates/crpg-sim/src/combat.rs:1533–1535`). `combat_basic`'s area is one
   metre square (`campaigns/fixtures/combat_basic/areas/start/area.json`).
3. **GDScript cannot tell which rows it may move**, and nothing draws a proxy
   at its position: `SceneSync.sync` lays proxies out by side and rank
   (`apps/client/scripts/SceneSync.gd:61`), and there is no input handling
   (`docs/architecture/crpg-godot.md:259–260`).

## Readings
Design decisions this contract makes. Each needs approval with the contract.

1. **The walk demo is a real-time encounter (D77a).** The sim already starts
   an encounter in a host-chosen mode (`HistoryWorld::start_encounter_in_mode`,
   `crates/crpg-sim/src/history.rs:882–905`; ADR-0029 T11), so a new
   `open_v4_rt` passes `EncounterMode::RealTime` where `open_v4` passes
   `TurnBased`. In real time lane 1 walks combatants
   (`crates/crpg-server/src/host.rs:4061–4096`). Consequence the user must
   accept: in this build nobody gets combat options in real time, because
   `legal_intents` is empty without an active turn
   (`crates/crpg-server/src/host.rs:1107–1114`); the Goblin stands still and
   the HUD offers nothing. *Rejected:* exploration with no encounter (movers
   are built only at encounter start, `crates/crpg-sim/src/movement.rs:653–688`,
   so it needs a sim task); a turn-based walk with `DeclareMove` (one metre per
   action and nothing else moves; D77a (b)); `request_mode` after open (the
   switch waits for a turn-based round to roll over,
   `crates/crpg-sim/src/combat.rs:4366–4372`).
2. **The walk campaign is checked in outside `fixtures` (D77b).** A copy of
   `combat_basic` with movement, `round_ticks`, a 16 × 12 m floor and a second
   Hero placement, under `campaigns/demo/walk/`, so a player can launch it and
   the fixture rule (`absent_movement_is_unchanged` walks only `rulesets/` and
   `campaigns/fixtures`, `crates/crpg-data/tests/movement_fields.rs:124–125`)
   still holds. Every identifier is the fixture's, except one new placement;
   reusing them keeps every cross-reference valid. Two Heroes, because a
   creature with no faction is its own side
   (`crates/crpg-godot/src/core/authority.rs:442–448`), so the player controls
   both and can watch one walk while moving the other ("other entities move
   smoothly"). Speed 6,554 raw per tick (0.1 m, so 2 m/s at 20 Hz) is within
   `1..=MAX_SPEED_PER_TICK_RAW` (`crates/crpg-sim/src/movement.rs:672–673`).
   `round_ticks` 100 (5 s): rounds mean nothing in this sandbox, and each one
   journals a `RoundStarted` (`crates/crpg-sim/src/history.rs:811–817`).
3. **`controlled()` is a session list, not a view column.** The player's
   control grant is fixed at open (`prefix.player_actors`,
   `crates/crpg-godot/src/core/mod.rs:454–458`); `open_v4*` maps it to the
   player's replica ids with `Host::replica_id`
   (`crates/crpg-server/src/host.rs:1151–1164`) and keeps the sorted list in
   `LiveV4`. A view column would change `SessionView`, the v2 `Client`'s
   literal and every view equality, for a fact that never changes. Rows that
   die or leave stay in the list; GDScript intersects with `net_ids()`, and the
   host still decides every move (`NotAuthorized`, T151 Reading 15).
4. **`render_positions()` is on the session, and smoothing lives in the core.**
   ADR-0033 planned `CrpgView.previous_positions()` for GDScript to interpolate
   (`docs/adr/0033-godot-bridge.md:519–521`). Rejected: the interpolated point
   changes every frame without a new revision (a view is immutable and bumps at
   most once per poll, `crates/crpg-godot/AGENTS.md` invariant 6), and
   GDScript interpolation can be tested only in Godot runs, which CI does not
   run for movement. So `BridgeCore::render_positions()` returns three raw
   integers per row of `view()`: in T050a the view's positions; T049a replaces
   its v4 body with the smoothed positions at the last poll's time, with no
   shell or GDScript change. ADR-0033 amendment: Manager edits.
5. **The scene is a new `Walk.tscn` (D77d).** `Main.tscn` stays the default
   scene and the combat demo: `smoke.gd` plays it to the end and CI's artifact
   ships only `campaigns/fixtures/combat_basic`
   (`.github/workflows/ci.yml:342–346`). `Walk.gd` reuses `SceneSync.gd` and
   `CombatHud.gd` unchanged and draws proxies itself after `sync`, because
   S13 allows `SceneSync.gd` to call only `view.net_ids/names/sides/dead`
   (`apps/client/tests/scene_sync_cases.gd:571–579`): a `place(view, ..)` there
   would fail it.
6. **Input:** left click on the ground selects a controlled proxy within
   0.6 m of the hit point, otherwise moves the selected actor there; right
   click halts it. The ground is the plane `y = 0` (ADR-0036 U1,
   `docs/adr/0036-movement-and-navigation.md:89–90`); the click is sent raw
   (`round(m × 65536)`); the host snaps and clamps it to the mesh (H2, `:426–432`;
   `snap` is the identity in v1). No path preview: that needs a client mesh and
   the unapproved `crpg-godot → crpg-nav` path edge (G3, `:460–464`); Out of
   scope.
7. **One fixed camera**, aimed with `look_at_from_position((8, 12, 16),
   (8, 0, 6), UP)` at the floor's centre. Pan, zoom and the free camera T104
   recommends (`docs/research/T104/R16-deep.md:15–18`) are a later T050c.
8. **No settings change.** The bridge's host keeps `HostSettings::default()`,
   which is multiplayer: no auto-pause (`crates/crpg-server/src/host.rs:508–522`).
   With single-player auto-pause on `RoundStarted` (`:5054`) the walk would
   pause every round.

## Behaviour
Normative. "Refused" means the stated code and no state change. **First
failure wins** in every list.

### T050a
W-1. **`open_v4_rt_with`** is `open_v4_with` (T151 B-B1, as amended by
T151-E1–E3) with exactly one difference: `open_prefix` starts the encounter
with `history.start_encounter_in_mode(&parts.spec(encounter), mode)`, where
`mode` is `EncounterMode::RealTime` for `open_v4_rt*` and
`EncounterMode::TurnBased` for `open` and `open_v4*`. Because
`start_encounter` is `start_encounter_in_mode(spec, TurnBased)`
(`crates/crpg-sim/src/history.rs:875–877`), no v2 or v4 turn-based byte
changes. A ruleset without `round_ticks` refuses the real-time start with
`ModeUnsupported` (`crates/crpg-sim/src/combat.rs:1533–1535`), so
`open_v4_rt*` returns 25 and `last_error() == "START_FAILED: ModeUnsupported
at combat/mode"` (`:1222`), state `Closed`, no runner. *Tests:* W1, W3.

W-2. **`controlled()`.** Every `open_v4*` (turn-based and real-time), after
`presentation_tables` and before `LocalHost::new`, maps each of the player's
actors with `host.replica_id(player, entity)`: `Ok(Some(id))` →
`client::wide(id.get())`; `Ok(None)` → 25 `"no player replica id"`;
`Err(e)` → 25 with `e`'s text. The list is sorted ascending and stored in
`LiveV4.controlled`. `controlled()` returns a copy in `OpenV4`, and an empty
`Vec` in `Closed`, `Open` (v2) and `Fenced`. *Tests:* W1, W4.

W-3. **`render_positions()`** returns `self.view.positions().to_vec()` in
every state. (T049a replaces the `OpenV4` arm; its other arms keep this.)
*Tests:* W1, W4.

W-4. **Nothing else changes.** `open`, v2 `poll`, `open_v4`, the move entry
points, the error table and every existing test keep their bytes and
behaviour.

### T050b
B-W1. **Open.** `_ready`, in order: aim `$Camera3D` with
`look_at_from_position(CAMERA_AT, LOOK_AT, Vector3.UP)`;
`session = ClassDB.instantiate("CrpgSession")` (null → `open_code = 2`,
`$Hud.show_error("CrpgSession is not available")`, return);
`code = session.open_v4_rt(_campaign_dir(), "", "", OPEN_SEED)` (non-zero →
`open_code = code`, `$Hud.show_error(session.last_error())`, return);
`controlled = session.controlled()`; `selected = controlled[0]` if
`controlled.size() > 0`, else 0; `view = session.view()`. `_campaign_dir()`
is `CRPG_CAMPAIGN` when set and non-empty, else
`res://../../campaigns/demo/walk` globalized and simplified (as
`Main.gd:55–59` builds its path).

B-W2. **Each frame** (`_process`), when `session` is not null and both codes
are 0: `code = session.poll()`; 30 → `$Hud.show_notice(session.last_error())`
and continue; any other non-zero → `stop_code = code`,
`$Hud.show_error(session.last_error())`, return. Then `view =
session.view()`; if `view.revision() != seen`: `seen = view.revision()`,
`$Proxies.sync(view)`, `$Hud.sync(view)`. Then **draw** (B-W3), then the
**marker** (B-W4).

B-W3. **Draw.** `drawn = session.render_positions()`; if `drawn.size() != 3 *
view.net_ids().size()`, draw nothing this frame. Otherwise for each row `i`
with `view.position_known()[i] == 1` whose node
`$Proxies.get_node_or_null("proxy_%d" % id)` exists: `node.position =
Vector3(drawn[3i] / RAW, drawn[3i+1] / RAW, drawn[3i+2] / RAW)` (each a
`float`). Rows with `position_known` 0 keep `SceneSync`'s layout. This runs
after `sync` in the same `_process`, so a revision's layout write never
reaches a rendered frame.

B-W4. **Marker.** If `selected != 0` and `proxy_<selected>` exists:
`$Marker.visible = true`, `$Marker.position = Vector3(node.position.x, 0.02,
node.position.z)`; otherwise `$Marker.visible = false`.

B-W5. **`click_ground(point)`**: `session == null` or `open_code != 0` → 1.
Among `controlled` ids in ascending order whose proxy exists, take the first
with the smallest horizontal distance `Vector2(node.position.x -
point.x, node.position.z - point.z).length()`; if that distance is
`<= PICK_RADIUS`: `selected = id`, return `SELECTED` (nothing is sent).
Otherwise `code = session.move_to(selected, to_raw(point.x), 0,
to_raw(point.z))`; a non-zero code → `$Hud.show_notice(session.last_error())`;
return `code`. (`selected` 0 reaches the bridge, which answers 3
`"bad actor"`; the client decides no rule.)

B-W6. **`halt_selected()`**: `session == null` or `open_code != 0` → 1;
otherwise `code = session.halt(selected)`, a non-zero code shows a notice as
B-W5, return `code`.

B-W7. **`ground_point(screen)`**: `origin =
$Camera3D.project_ray_origin(screen)`, `dir =
$Camera3D.project_ray_normal(screen)`; `abs(dir.y) < 1e-6` → null; `t =
-origin.y / dir.y`; `t < 0` → null; else `origin + dir * t` with `y` set to
exactly 0.0.

B-W8. **`_unhandled_input(event)`**: only an `InputEventMouseButton` with
`pressed == true` acts; `p = ground_point(event.position)`; null → nothing;
`MOUSE_BUTTON_LEFT` → `click_ground(p)`; `MOUSE_BUTTON_RIGHT` →
`halt_selected()`; any other button → nothing. A held button sends nothing
more (one press, one call), so lane-1 rate limits (20 per second, 8 in
flight, `crates/crpg-net/src/movement_v4.rs:67–71`) are not a frame-rate
matter.

B-W9. **`_exit_tree`** closes the session and sets it to null, as
`Main.gd:50–53`.

B-W10. **Shell.** Each new `#[func]` makes exactly one core call and does no
arithmetic, indexing or unwrap on GDScript values (`crates/crpg-godot/AGENTS.md`
invariant 15); `open_v4_rt` sets `opened_at` exactly as `open_v4` does
(`crates/crpg-godot/src/shell.rs:60–80`). The crate keeps exactly one
`unsafe` (K32).
