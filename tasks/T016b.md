## Decisions (proposed ADR-0013 content; binding only once the ADR is approved)

1. **Combat state lives in `World` as three appended fields, all behavior
   hashed.** `combatants: ComponentStore<Combatant>`, `combat:
   Option<CombatState>`, `interners: Interners`. Every behavior-affecting field
   — health, dead flag, attributes, resource balances, round, active turn,
   timeline order, RNG, the referenced immutable combat definition, and the
   issuing interner — serializes into `state_hash` with no exclusions.
2. **Compatibility by absence-skip, never by excluding combat state.** The
   three new fields are serialized only when meaningful:
   `#[serde(default, skip_serializing_if = "ComponentStore::is_empty")]` on
   `combatants`, `#[serde(default, skip_serializing_if = "Option::is_none")]`
   on `combat`, and a private `#[serde(default, skip_serializing_if =
   "interners_empty")]` on `interners`. A non-combat world therefore
   serializes byte-identically to the T007/T008a skeleton and every existing
   non-combat golden is preserved. A combat world serializes its full
   definition and state; no behavior-affecting combat field is ever omitted to
   keep an old hash. Old goldens are not re-baselined.
3. **The issuing interner is world-owned and persisted symbolically.** `World`
   owns one `Interners`; the only runtime handle it interns for minimal-d6 is
   the roll tag (see decision 6). Stat references in combat state remain
   symbolic `String`s (ADR-0006 Decision 4 satisfied — the persisted form is
   the string, never a numeric handle), so no `StatId`-keyed map derives serde
   and the E014 trap stands.
4. **The immutable combat definition is hashed in full, symbolically.**
   `CombatDefinition` holds only serializable symbolic/ULID/integer fields:
   dice as a `DiceExpr` (string form), outcome table as a rules
   `OutcomeTable`, damage as `Vec<(Outcome, u32)>`, pool template as
   `{pool_id: Ulid, pool_max: u32, pool_refresh: RefreshTrigger}`, ability
   `{ability: Ulid, attribute: String, cost: u32, requires_target: bool,
   allow_self_target: bool}`, and content identity `{encounter: Ulid,
   ruleset: Ulid}`. No `StatId`/`TagId`/`StatBlock`/`Modifier`/`QueryContext`
   in `World`.
5. **Turn policy: `Timeline` stays a container.** `end_turn` keeps its
   pop-only semantics. The combat controller owns round structure: at
   round start the timeline holds one entry per live participant at its
   authored `InitiativeKey` (ties broken by `EntityId` ascending); an accepted
   action pops the actor and advances to the next head, rolling the round over
   when the timeline empties (see *Turn lifecycle*). Dead participants are
   removed from scheduling but retain their entity and zero-health terminal
   state.
6. **Resolution uses `Against::Dc` with the actor's authored attribute, one
   named stream, one interned roll tag, and no modifiers.** `resolve` runs over
   an empty `ModifierPipeline` and transient empty `StatBlock`/`TagSet`/
   `&[Modifier]` views. The actor's attribute value (data) is the constant DC;
   the ability's `dice`/`attribute`/`outcome_table`/`damage` (data) drive the
   rest. Named stream constant `combat.roll`; roll-tag symbol `roll` interned
   into the world interner. No hook dispatcher, no effect interpreter, no
   ruleset identifiers in production.
7. **The only new event is `SimEvent::Died { entity }`, core-closed.** It is
   produced exactly once on the positive-health-to-zero transition and consumed
   by the terminal-state assertions (tests, then T016c) and future AI/effect
   systems. No rules `KernelHook` is emitted or dispatched, so no correlation
   ULID is required in this task; hook payloads remain core-closed and this
   task adds none.

## Public interface (exact shapes; re-export at the crate root)

New module `combat.rs`. All public items have rustdoc. Ordered collections and
integer/core values only; no floats, hash maps, OS branches, clocks, or id
generation. The rules types named (`DiceRoll`, `Outcome`, `OutcomeTable`,
`DiceExpr`, `ResourcePool`, `RefreshTrigger`, `RestId`) are consumed read-only
from `crpg-rules`; the data types named (`Encounter`, `Ruleset`, `Ability`,
`Placement`, `Creature`) are consumed read-only from `crpg-data`. Both
dependencies require the approval above.

Name collisions to disambiguate in the implementation (not a semantic choice):
`crpg_data::combat::OutcomeTable` (authored) vs `crpg_rules::OutcomeTable`
(runtime), and `crpg_data::combat::RestId` vs `crpg_rules::RestId`. The adapter
imports these through type aliases (e.g. `AuthoredOutcomeTable`,
`AuthoredRestId`) so the public shapes stay unambiguous; the field names below
name the runtime rules types unless prefixed.

```rust
/// Maximum participants in one encounter.
pub const MAX_COMBATANTS: usize = 1024;
/// Maximum stat declarations in one encounter ruleset.
pub const MAX_COMBAT_STATS: usize = 1024;
/// The named RNG stream used for all combat resolution draws.
pub const COMBAT_ROLL_STREAM: &str = "combat.roll";
/// The tag symbol interned for the resolution roll tag.
pub const COMBAT_ROLL_TAG: &str = "roll";

/// One combatant's authoritative mutable state, keyed by entity in a
/// [`ComponentStore`](crate::ComponentStore). Insertion order is authored
/// participant order, giving the deterministic placement-to-entity mapping.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct Combatant {
    placement: Ulid,
    initiative: i32,
    attributes: Vec<(String, i32)>, // non-health attributes, authored order
    health: u32,
    max_health: u32,
    dead: bool,
    action_pool: ResourcePool,
}

impl Combatant {
    pub fn placement(&self) -> Ulid;
    pub fn initiative(&self) -> i32;
    pub fn attributes(&self) -> &[(String, i32)];
    pub fn health(&self) -> u32;
    pub fn max_health(&self) -> u32;
    pub fn dead(&self) -> bool;
    pub fn action_pool(&self) -> &ResourcePool;
}

/// The immutable, symbolically-serialized combat definition.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct CombatDefinition {
    pub encounter: Ulid,
    pub ruleset: Ulid,
    pub ability: Ulid,
    pub dice: DiceExpr,
    pub attribute: String,         // ability-checked attribute name
    pub health_stat: String,
    pub attribute_names: Vec<String>,
    pub damage: Vec<(Outcome, u32)>,
    pub cost: u32,
    pub requires_target: bool,
    pub allow_self_target: bool,
    pub outcome_table: OutcomeTable,
    pub pool_id: Ulid,
    pub pool_max: u32,
    pub pool_refresh: RefreshTrigger,
}

/// Encounter-level state; `None` when no encounter is active.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct CombatState {
    pub definition: CombatDefinition,
    pub round: u32,
    pub active: Option<EntityId>,
}

/// One authored participant's resolved references for the adapter.
pub struct PlacementAndArea<'a> {
    pub placement: &'a Placement,
    pub area: Ulid,
}

/// Resolved references one encounter adapter consumes.
pub struct EncounterSpec<'a> {
    pub encounter: &'a Encounter,
    pub ruleset: &'a Ruleset,
    pub abilities: &'a BTreeMap<Ulid, &'a Ability>,
    pub outcome_tables: &'a BTreeMap<Ulid, &'a AuthoredOutcomeTable>,
    pub placements: &'a BTreeMap<Ulid, PlacementAndArea<'a>>,
    pub creatures: &'a BTreeMap<Ulid, &'a Creature>,
}

/// One player/authoritative action.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum CombatAction {
    UseAbility { actor: EntityId, ability: Ulid, target: EntityId },
}

/// The observed result of one accepted action (never persisted).
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ActionOutcome {
    pub actor: EntityId,
    pub target: EntityId,
    pub ability: Ulid,
    pub roll: DiceRoll,
    pub margin: i64,
    pub outcome: Outcome,
    pub damage: u32,
    pub target_died: bool,
}

/// Every combat failure, with pinned multifault precedence (see below).
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum CombatError { /* variants + Display below */ }
```

`CombatError` variants (each with a stable `Display` of the form `<Code> at
<location>`), in the exact precedence order the controller checks them:

| Precedence | Variant | Meaning |
|---|---|---|
| 1 | `NoEncounter` | `world.combat` is `None` (action without an active encounter) |
| 2 | `EncounterActive` | `start_encounter` while an encounter is already active |
| 3 | `NotParticipant { entity }` | actor/target is live but not a combatant |
| 4 | `AbsentActor { actor }` | actor id does not address a live combatant |
| 5 | `AbsentTarget { target }` | target id does not address a live combatant |
| 6 | `DeadActor { actor }` | actor combatant has `dead == true` |
| 7 | `DeadTarget { target }` | target combatant has `dead == true` |
| 8 | `OutOfTurn { actor, active }` | actor is not the active turn entity |
| 9 | `UnknownAbility { ability }` | ability not in the encounter's loaded ability set |
| 10 | `SelfTarget` | `target == actor` and the ability disallows self-target |
| 11 | `InsufficientAction { cost, current }` | pool cannot afford the cost |
| — (init only) | `MissingPlacement { placement }` | participant placement not in the spec |
| — (init only) | `MixedArea { area_a, area_b }` | participants span more than one area |
| — (init only) | `MissingCreature { prefab }` | placement prefab not a supplied creature |
| — (init only) | `MissingStat { stat }` | creature lacks a ruleset stat |
| — (init only) | `InvalidStatValue { stat }` | fractional stat, or health not positive |
| — (init only) | `InvalidCost { cost, max }` | ability cost exceeds the pool maximum |
| — (init only) | `InvalidDice` | ability dice notation fails to parse |
| — (init only) | `InvalidOutcomeTable` | outcome table fails rules construction |
| — (init only) | `ValueOverflow` | a checked conversion overflowed |
| — (init only) | `TooManyParticipants` | participants exceed `MAX_COMBATANTS` |
| — (init only) | `TooManyStats` | ruleset stats exceed `MAX_COMBAT_STATS` |

Free functions (the two controller entry points):

```rust

pub fn start_encounter(world: &mut World, spec: &EncounterSpec) -> Result<(), CombatError>;

/// Applies one validated action transactionally; rejected actions leave
/// `world` unchanged (resources, RNG, events, and event sequence included).
pub fn perform_action(world: &mut World, action: &CombatAction)
    -> Result<ActionOutcome, CombatError>;
```

`World` gains read accessors: `combatants() -> &ComponentStore<Combatant>`,
`combat() -> Option<&CombatState>`, `interners() -> &Interners`. `despawn`
additionally strips the combatant component and clears `combat.active` when the
despawned entity was active, preserving the no-dangling invariant for the new

## Data-to-runtime initialization

`start_encounter` validates **everything** before publishing any partial state;
any init error leaves `world` unchanged (no entities spawned, no `combat` set).

1. Reject `EncounterActive` if `world.combat.is_some()`.
2. Reject `TooManyParticipants` / `TooManyStats` at the collection bounds.
3. Resolve each participant's `placement` in the spec (`MissingPlacement`),
   check all resolved areas agree (`MixedArea`), then each `placement.prefab`
   against the supplied creatures (`MissingCreature`).
4. For each creature, for each ruleset stat name in authored order: require the
   stat present (`MissingStat`); require the fixed value whole
   (`raw % 65536 == 0`, else `InvalidStatValue`); convert the integer part
   (`raw / 65536`, always fits `i32` per T016a decision 3) through a checked
   conversion (`ValueOverflow` is the defensive arm). The `health_stat` value
   must be positive (`InvalidStatValue` if not) and converts to `u32`.
5. Resolve the ruleset's abilities into `CombatDefinition`: dice parse
   (`InvalidDice`), outcome-table construction (`InvalidOutcomeTable`), damage
   entries `OutcomeWire -> Outcome` + amount (`u32`), cost
   (`<= pool_max`, else `InvalidCost`), pool template and refresh conversion.
6. Only after all checks pass: spawn one entity per participant in authored
   order (arena ids are the deterministic placement-to-entity mapping),
   insert each `Combatant` (pool initialized `current = max`), populate the
   timeline, set `round = 0`, `active = timeline head`, intern `COMBAT_ROLL_TAG`
   into `world.interners()`, refresh the active combatant's pool with
   `TurnStart`, and store `combat = Some(CombatState { definition, round,
   active })`. The placement-to-entity order is recorded by combatant-store
   insertion order and asserted by test.

Conversion overflow is checked with `checked_div`/`i32::try_from`/`u32::try_from`
and reported as `ValueOverflow`; the `Fx16_16 -> i32` path cannot actually
overflow (whole values lie in `-32768..=32767`) and is documented as such.

## Turn lifecycle, action completion, and event ordering

Timeline order is ascending `(InitiativeKey, EntityId)`. Round zero is
established by `start_encounter`. `perform_action` on a valid action runs this
fixed order, all-or-nothing:

1. Validate in the pinned precedence order (table above). Any error returns
   before any mutation, including before any RNG stream is created.
2. Build the `ResolutionRequest`: `RollSpec::Dice(def.dice)`, `natural_die:
   None`, stream `COMBAT_ROLL_STREAM`, empty `TagSet`, `bonus_target`/DC
   `modifier_target` both `RollTag(interners.tag(COMBAT_ROLL_TAG))`, `target:
   Some(target)`, `Against::Dc { value: actor_attribute, owner: actor,
   modifier_target }`, `outcome_table: def.outcome_table.id()`. Build an empty
   `ModifierPipeline` and two transient empty views and call
   `resolve(&request, &context, world.rng_mut())`. `resolve` stages the RNG and
   commits only on success, so a resolution failure (unreachable after
   preflight, but handled) leaves the world unchanged.
3. Look up the `decision.outcome` in `def.damage` (an outcome with no entry
   applies `0` damage, documented) to get the nonnegative `u32` amount.
4. Spend the actor's pool (`action_pool.spend(cost)`, infallible after the
   affordability check).
5. If the target is alive and `damage > 0`: `health = health.saturating_sub(
   damage)` (floors at zero, never overflows). On the positive-health-to-zero
   transition, set `dead = true` and enqueue exactly one
   `SimEvent::Died { entity: target }`. Overkill and zero damage are valid and
   produce no additional event.
6. Advance the turn: remove any dead participants from the timeline; pop the
   actor via `end_turn` (the actor is the head by the out-of-turn check);
   then
   - if the timeline is non-empty: set `active` to the new head and refresh
     that combatant's pool with `TurnStart`;
   - if the timeline is empty and at least two combatants are alive: roll the
     round over — `round += 1`, refresh every alive `OnRoundStart` pool, re-add
     every alive participant at its `InitiativeKey`, set `active` to the new
     head, refresh it with `TurnStart`;
   - if the timeline is empty and fewer than two combatants are alive:
     terminal — `active = None`, no rollover, no refresh.
7. Return the `ActionOutcome`.

Refresh happens exactly once per logical turn start (the incoming actor's pool
on `TurnStart`, idempotent because `ResourcePool::refresh` returns true only
when the balance changed). A rejected action consumes no resource and no
randomness and advances nothing. Ordinary no-input `tick`/`end_turn` never
invent an action or a refresh: combat turn logic lives only in the two combat
operations, never in `tick` or `run_systems`. Death is distinct from arena
despawn: a dead combatant keeps its entity, `Combatant` (with `health == 0`,
`dead == true`), and terminal state, and is only removed from scheduling
(timeline).

## Persistence, events, and hashing

- `World` serde extends the skeleton: `WorldRepr` gains the three fields with
  `#[serde(default)]`; deserialization additionally rejects (a) a combatant
  store id that is not live, (b) `combat = Some` with an empty combatant store,
  (c) `combat = None` with a non-empty combatant store, and (d) an `active` id
  that is not a live combatant. The rules types (`DiceExpr`, `OutcomeTable`,
  `ResourcePool`, `Outcome`) validate on decode through their own constructors,
  so a malformed saved combat definition is rejected at load.
- Save/load is symbolic: no interned handle is persisted. The world interner
  persists as its ordered string list; the roll tag is re-resolved by name on
  use, so identical remaining inputs behave identically after load even when a
  differently-ordered interner was used to build the world (pinned by test).
- `state_hash` keeps its empty exclusion list. The compatibility decision
  (absence-skip, decision 2) is not an exclusion: when combat is active, every
  field of `CombatState`, `CombatDefinition`, `Combatant`, and the interner is
  hashed. A test proves health, resource balance, round, active turn, timeline,
  event queue, and definition fields each change the hash.

## Tests (reserved by T016: `combat` and `combat_persistence`)

`crates/crpg-sim/tests/combat.rs`:

- Initialization: valid spec publishes both combatants, deterministic
  placement-to-entity order, correct initiative/timeline order, pools at max,
  round 0, active = initiative-first; `validate` on the source is not re-run
  (data owns that). Reference/type/conversion failures: `MissingPlacement`,
  `MixedArea`, `MissingCreature`, `MissingStat`, `InvalidStatValue`,
  `InvalidCost`, `InvalidDice`, `InvalidOutcomeTable`, `ValueOverflow`,
  `TooManyParticipants`, `TooManyStats` — each leaves `world` unchanged
  (assert no combatants, no `combat`, empty timeline, empty events, unchanged
  RNG streams).
- Inclusive roll-under neighbors through the existing rules kernel: a fixed
  seed with independently computed (or recorded) faces pins total == attribute
  (success), attribute - 1 (success), attribute + 1 (failure), asserting the
  returned `roll`, `margin`, `outcome`, and `damage` against independent
  expectations, never against a second evaluator.
- Successful and failed attacks with independently expected traces; a failed
  attack consumes its action (pool `current` decremented) but applies no
  damage.
- Turn order, initiative ties (id tiebreak), round rollover, per-turn resource
  refresh, and terminal behavior (`active = None`, no rollover once one side is
  dead).
- Rejected actions with full-state rollback: for each error code, the world
  (health, pools, timeline, `round`/`active`, event queue/sequence, RNG) is
  byte-identical after the attempt, and no new RNG stream was created.
- Zero damage, overkill (`health` floors at zero), integer boundaries, and
  exactly-once death (a subsequent rejected `DeadTarget`/`DeadActor` action
  emits no second `Died`).
- Despawn cleanup: despawn of a combatant strips its component and timeline
  entry and clears `active`, without weakening the existing `assert_no_dangling`
  no-dangling test.
- Hash sensitivity: health, resource balance, `round`, `active`, timeline, and
  event queue each independently change `state_hash`; mutating a definition
  field (e.g. a damage amount) changes the hash.
- Existing sim tests (`world`, `tick`) pass unchanged (non-combat worlds
  serialize byte-identically, per the compatibility decision).

`crates/crpg-sim/tests/combat_persistence.rs`:

- Mid-combat save/load: serialize a world partway through a fight, deserialize
  it, then apply the same remaining inputs; the hash sequence and behavior are
  identical to the unsaved run.
- Malformed saved-state rejection: dangling combatant id, `combat = Some` with
  empty combatants, `combat = None` with non-empty combatants, invalid `active`,
  and a malformed definition (bad dice/table) each fail to load.
- Differently-ordered interner: a world built with an interner whose symbol
  insertion order differs still resolves the roll tag and reproduces identical
  behavior and hashes.
