## Task
Give the authoritative `World` the state that lets script, dialogue and
quest progress survive save/load and a server restart (spec §5.2 "Serializable
mid-execution", `docs/CRPG_ENGINE_SPEC.md:624`; MVP "Save. Quit. Load. State
is identical.", `:1526`). Three things are stored: a running event graph paused
in `Wait` (an entity holding a `ScriptContinuation`, as `:624` says), a
participant's open dialogue, and each quest's current state. The sim counts
waits down once per tick and says which are due; it never interprets a
graph, walks a dialogue or transitions a quest. That is T053's and T054's
(`docs/IMPLEMENTATION_PLAN.md:283–284`), from `crpg-script`, which depends on
`crpg-sim` and never the reverse (`tools/lint/deps.py`, unedited). No Lua
state is ever stored (D17, `tasks/POST-T018-DECISIONS.md:381`).

## Readings
Design decisions this contract makes. Each needs approval with the contract.

1. **Storage and counting are the sim's; execution is above it.** D17 asks
   for "world-owned serializable IR continuations in a separate earlier sim
   task" (`tasks/POST-T018-DECISIONS.md:381`). The sim stores, counts down,
   validates on load and reports due continuations; `crpg-script` resumes
   them. Both drafts. *Rejected:* a sim stage that runs graphs (spec §10
   stage 6, `docs/CRPG_ENGINE_SPEC.md:952`, needs `crpg-sim → crpg-script`,
   an upward edge).
2. **Three shapes, one per kind of thing.** (a) A running graph is its own
   entity holding a `ScriptContinuation` in a `ComponentStore`, minted by
   `spawn_continuation` (spec `:624` "running graphs as entities"; draft
   B's minting, not draft A's attach-to-any-entity, so a creature never
   carries a graph's state). (b) An open dialogue is a `ComponentStore<OpenDialogue>`
   keyed by the **participant** (the entity whose player chooses), so a
   participant has at most one and several players may talk at once in one
   area (neither draft: draft A's single `Option` allows one conversation
   per area, which multiplayer breaks; draft B's own entity with a `speaker`
   field dangles when the speaker despawns, because nothing strips it, and
   then the save no longer loads). The speaking NPC is not stored: each
   `NpcLine` names its speaker (`crates/crpg-data/src/document.rs:193–197`),
   and T054 may add a runtime speaker later as a last field. (c) Quest
   progress is a `Vec<QuestProgress>` strictly ascending by `quest`, not an
   entity: quests are campaign facts, not things in the area. Draft A's
   keying, in the crate's sorted-`Vec` idiom (creature tags,
   `crates/crpg-sim/src/world.rs:249–253`) rather than a `BTreeMap` with
   string keys. *Rejected:* draft B's quest entities (any `despawn` would
   erase progress, and each quest would journal a `Spawned` that only the
   host's grant keeps from clients); one merged enum (draft A rejected it
   too).
3. **The continuation is the resume point only: graph, node, ticks left.**
   Draft B. The authored `Trigger` carries no subject (`crates/crpg-data/src/ir.rs:44–75`),
   locals have no runtime value type yet, and nested `CallGraph` frames
   depend on T053's interpreter design, whose contract waits on T101. A
   field no reader reads is hashed state to maintain (`crates/crpg-sim/AGENTS.md:518`).
   If T053 needs frames, locals or a subject it adds them as last fields
   with absence defaults, in its own `crpg-sim` part. *Rejected:* draft A's
   `TriggerContext` (payloads invented beyond the authored type) and
   `ContinuationValue` (an unbounded mirror of `DataValue` with no reader).
4. **The countdown is spec §10 stage 2, directly after the encounter
   clock.** Stage 2 is "advance timers, effect durations, resource
   refreshes" (`docs/CRPG_ENGINE_SPEC.md:948`), and a `Wait` is a timer.
   `run_systems` becomes clock, **wait countdown**, timeline, movement
   (`crates/crpg-sim/src/tick.rs:64–71`). The countdown reads and writes
   only its own store, so no other stage's output can depend on its
   position; the position is chosen so the stage comments stay in spec
   order. Draft A. *Rejected:* draft B's "stage 5" (spec stage 5 is AI
   decisions, which ADR-0029 T15 moved out of the tick; placing a timer
   there mislabels it); an absolute due tick with no stage (each area world
   has its own tick counter, so an absolute tick is meaningless once
   continuations move between areas or to the campaign; the spec says a
   `Wait` stores a relative count, `:625`).
5. **Due means `remaining == 0`; the sim never removes or emits.** The
   countdown saturates at zero; `due_continuations` lists due holders in
   ascending `EntityId`, not store order (draft B; store order changes when
   an index is reused). No `SimEvent` and no `HistoryEvent` variant: a new
   variant needs a consumer (`crates/crpg-sim/AGENTS.md:349`) and would
   raise the history version. Both drafts.
6. **Writes are operations that validate first; no store escapes.** Public
   `World` methods mutate only after their checks pass; the stores have
   read-only getters only (the crate's rule, `crates/crpg-sim/AGENTS.md:353`).
   Draft A's validate-then-mutate shape with draft B's operations, and one
   change to both: a second `Wait` in the same graph moves the node too, so
   the rewrite is `set_continuation` (whole record), not draft B's
   `set_remaining`. A finished graph is despawned with the existing `despawn`.
7. **`HistoryWorld` gets the same operations, journaling only identity.**
   The host's authority is a `HistoryWorld`, so without wrappers T053 could
   never write this state on a server. `spawn_continuation` journals one
   `Spawned` (it mints an entity; `HistoryWorld::spawn`'s shape,
   `crates/crpg-sim/src/history.rs:627–641`); every other operation commits
   zero events, as `place` and `set_route` do (`:519–545`); none changes the
   version. Draft B. *Rejected:* draft A (no wrappers); a spawn that journals
   nothing (every allocation is journaled, and client disclosure of the
   spawn is the host's per-entity grant, `crates/crpg-net/src/projection_v2.rs:16–17`).
8. **No save-version change; absence means empty.** Each field is skipped
   when empty and defaulted on load, as `creatures`, `movers` and `nav` were
   (`crates/crpg-sim/src/world.rs:100–115`, `:138–145`), so every existing
   save loads as "nothing running, no dialogue, no quest". T052 is
   `crpg-sim` only and cannot touch `HOST_SAVE_VERSION`
   (`crates/crpg-server/src/save.rs:43`), which a test pins as "2 is refused"
   (`crates/crpg-server/tests/host_save.rs:1017–1030`). Draft A. The
   downgrade gap (an older build silently drops the new keys) is real and
   already exists for creatures and movement: **D69a** asks the user.
9. **Load checks are structural and one message per check.** Liveness of
   each store key and the quest order, after every existing check, so no
   existing input changes its error (`crates/crpg-sim/src/world.rs:150–916`).
   Whether an id names authored content is the host's and T053/T054's
   (the sim holds no campaign). Draft A's scope, the crate's per-check
   messages. *Rejected:* draft A's nil-id checks (nil is one of many ids
   that name nothing).
10. **Transfer refuses a holder with one variant.** A continuation entity or
    a dialogue participant could otherwise be moved and silently lose its
    state (transfer carries only meta, transform, creature and mover,
    `crates/crpg-sim/src/area.rs:9–16`). One `AreaError::ScriptState { entity }`
    for both stores, placed after `PlacementInUse` and before
    `SourceHistory` and checked last in `preflight`, as T139 placed its
    variant (`tasks/T139.md:593–596`). Draft B's single error, settled.
11. **Equivalence is proved at both levels, each in its own crate.** The
    spec's 500 + 500 versus 1000 run (`docs/CRPG_ENGINE_SPEC.md:853`) for the
    new state is in T052's `crpg-sim` suite over `World` and `HistoryWorld`
    JSON. A restart through the real host file save cannot be tested from
    `crpg-sim` (an upward edge), so it is T052b, a test-only `crpg-server`
    part that adds a file and edits none; gate 10's `host_save.rs` stays
    frozen. *Rejected:* draft B's G2 "in T052's suite with the host save
    helpers" (impossible from `crpg-sim`); editing `host_save.rs`.
12. **No new golden.** The equivalence and countdown cases compare in one
    process with exact values; every existing golden staying byte-identical
    proves absence. *Rejected:* draft B's `continuation_v1` golden (a
    review-gated baseline for a shape T053 may extend).

### `crates/crpg-sim/src/continuation.rs`
```rust
use crpg_core::{EntityId, Ulid};
use serde::{Deserialize, Serialize};

/// A running event graph paused in `Wait` (Reading 3).
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(deny_unknown_fields)]
pub struct ScriptContinuation {
    /// Authored `EventGraph.id`.
    pub graph: Ulid,
    /// The authored `Wait` node the graph resumes after.
    pub node: Ulid,
    /// Ticks left; `0` is due.
    pub remaining: u64,
}

/// One participant's open dialogue (Reading 2b).
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(deny_unknown_fields)]
pub struct OpenDialogue {
    /// Authored `Dialogue.id`.
    pub dialogue: Ulid,
    /// The current `DialogueNode.id`.
    pub node: Ulid,
}

/// One quest's current state (Reading 2c).
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(deny_unknown_fields)]
pub struct QuestProgress {
    /// Authored `Quest.id`.
    pub quest: Ulid,
    /// The current `QuestState.id`.
    pub state: Ulid,
}

/// A refused script-state operation; the world is unchanged.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ContinuationError {
    /// The entity holds no continuation (absent, dead or never one).
    NotContinuation { entity: EntityId },
    /// The participant is not live.
    NotLive { entity: EntityId },
    /// The participant already has an open dialogue.
    DialogueOpen { entity: EntityId },
    /// The participant has no open dialogue.
    NoDialogue { entity: EntityId },
}
// `Display`: "<VariantName> at script/state", no fields (the AreaError form,
// crates/crpg-sim/src/area.rs:74–90). `impl std::error::Error`, `source` None.

/// Spec §10 stage 2: every positive `remaining` decreases by exactly one.
pub(crate) fn wait_system(world: &mut World);
```

## Behaviour
Normative. "Unchanged" means `state_hash` (or `history_hash`), the legacy
queue and every store as before the call. First failure wins.

B-1. **Absence.** A world whose three stores are empty serializes exactly as
today: none of the keys `continuations`, `dialogues`, `quests` appears, and
every existing golden is byte-identical. *Tests:* C1, every existing suite.

B-2. **Spawn.** `spawn_continuation(c)` mints an entity exactly as `spawn`
does (one `Spawned` at the current tick) and stores `c` on it; it holds no
other component. *Tests:* C2, C12.

B-3. **Countdown** (Reading 4). Each `tick` (and `tick_with_movement`, and
`HistoryWorld::tick`), after the encounter clock and before the timeline
stage, sets every record with `remaining > 0` to `remaining − 1`; records at
`0` stay `0`. Nothing is enqueued, no fact is reported, nothing is removed.
`end_turn` never touches the stores. A record holding `r` when `world.tick()`
is `t` holds `0` first when `world.tick()` is `t + r`. *Tests:* C2, C11, C13.

B-4. **Due** (Reading 5). `due_continuations()` returns exactly the holders
with `remaining == 0`, in ascending `EntityId`, and changes nothing. *Tests:* C2, C3.

B-5. **Rewrite.** `set_continuation(e, c)`: `e` holds no continuation →
`Err(NotContinuation { entity: e })`, unchanged; else the record becomes `c`,
the old one is returned, nothing is enqueued. *Tests:* C4.

B-6. **Dialogues.** `open_dialogue(p, d)`: `p` not live → `NotLive`; `p`
already holds one → `DialogueOpen`; else stored. `set_dialogue_node(p, n)`
and `close_dialogue(p)`: none held → `NoDialogue`; else the node is
replaced (old returned) or the record removed (returned). Every error leaves
the world unchanged; nothing is ever enqueued. *Tests:* C5.

B-7. **Quests.** `set_quest_state(q, s)` inserts `{q, s}` at its ascending
position and returns `None`, or replaces the state of `q` and returns the old
one (`Some(s)` and no change when equal). `remove_quest(q)` removes and
returns the state, or `None`. Nothing is enqueued; liveness is not involved.
*Tests:* C6.

B-8. **Despawn is total.** `despawn(e)` strips `e`'s continuation and
dialogue with the rest and enqueues one `Despawned`; quests are untouched.
*Tests:* C7.

B-9. **Transfer refuses holders** (Reading 10). `transfer_entity` and
`transfer_history_entity` of an entity that holds a continuation or a
dialogue fail `ScriptState { entity }` after every existing check and
publish neither side. *Tests:* C8.

B-10. **Load checks** (Reading 9), after every existing check, in this order,
each a `serde::de::Error::custom` with exactly this text:
L1 a continuation key not live: `dangling continuation for non-live {id:?}`;
L2 a dialogue key not live: `dangling dialogue for non-live {id:?}`;
L3 two adjacent quests with `quest[i] >= quest[i+1]`: `quest progress breaks ascending order`.
*Tests:* C9.

B-11. **Round trip.** World JSON → `World` gives an equal value, equal
`state_hash` and equal `due_continuations`; the same for `HistoryWorld` and
`history_hash`. *Tests:* C10, C11.

B-12. **History** (Reading 7). `HistoryWorld::spawn_continuation` commits
exactly `[Spawned { entity }]`; the six other wrappers commit zero events and
need no free journal slot; none changes `version()`. A refusal returns
`Err(HistoryError::Script(e))` with `history_hash` unchanged; a full journal
fails `spawn_continuation` with the commit's own error and commits nothing,
including the entity allocation. *Tests:* C12, C13.

B-13. **Host restart** (T052b). A host saved to a file and reloaded keeps the
three kinds of state exactly, and its countdown continues as an uninterrupted
host's. *Tests:* H1.

## Tests
`crates/crpg-sim/tests/continuation.rs` (implementer) and
`continuation_contract.rs` (two-keys writer, from this contract alone). Every
case has a control that flips one input and a "fails if". Worlds are built
in code from `World::new(seed)` or `HistoryWorld::new(seed)`.

- **C1 `absent_state_is_not_serialized`.** The JSON object of `World::new(0)`
  has exactly the keys `entities, transforms, timeline, events, rng, tick`.
  `spawn_continuation(k(1))` → the JSON has a `continuations` key; `despawn`
  it → the key is gone again. Same for `open_dialogue`/`close_dialogue`
  (`dialogues`) and `set_quest_state`/`remove_quest` (`quests`). *Fails if:* an
  empty store writes its key.
- **C2 `wait_counts_down_and_becomes_due`.** `W0 = World::new(1)`:
  `a = spawn_continuation(k(3))`, `b = spawn_continuation(k(0))` (`e(0)`,
  `e(1)`); the queue holds exactly `Spawned{e(0)}, Spawned{e(1)}` at tick 0.
  `due_continuations() == [b]`. After ticks 1, 2, 3: `a`'s `remaining` is 2,
  1, 0; `b`'s stays 0; after tick 3 due is `[a, b]`; tick 4 changes neither.
  The queue still holds only the two `Spawned`. *Control:* `k(u64::MAX)`
  after one tick holds `u64::MAX − 1`. *Control:* `end_turn(&mut W0)` between
  ticks leaves both records as they were. *Fails if:* a tick moves a record
  by other than one, a zero underflows, an event is enqueued, or a due record
  is removed.
- **C3 `due_order_is_entity_order`.** Spawn three `k(0)` (`e(0)`, `e(1)`,
  `e(2)`), `despawn(e(0))`, spawn one more `k(0)` (index 0, generation 2,
  last in store order): `due_continuations()` has indices `[0, 1, 2]`.
  *Fails if:* store order (`[1, 2, 0]`) is returned.
- **C4 `set_continuation_replaces`.** `a = spawn_continuation(k(5))`;
  `set_continuation(a, ScriptContinuation { graph: G, node: W2, remaining: 9 })`
  returns `Ok(k(5))` and the record is the new one; the queue is unchanged.
  On a plain `spawn`ed entity, on `e(7)` (never live) and on `a` after
  `despawn(a)`: `Err(NotContinuation { entity })`, `state_hash` unchanged.
  *Fails if:* a non-holder gains a record or the old value is wrong.
- **C5 `dialogue_lifecycle`.** `p = spawn(EntityMeta {})`,
  `open_dialogue(p, {D, N1})` → `Ok`; again → `Err(DialogueOpen { entity: p })`;
  `set_dialogue_node(p, N2)` → `Ok(N1)`; `close_dialogue(p)` → `Ok({D, N2})`;
  then `close_dialogue(p)` and `set_dialogue_node(p, N1)` →
  `Err(NoDialogue { entity: p })`; `open_dialogue(e(7), ..)` →
  `Err(NotLive { entity: e(7) })`. Two participants `p`, `p2` hold dialogues
  at once. Every `Err` leaves `state_hash` unchanged; the queue holds only the
  two `Spawned`. *Fails if:* a second dialogue opens for one participant, an
  error mutates, or anything is enqueued.
- **C6 `quests_stay_ascending`.** `set_quest_state(Q2, S1)` → `None`;
  `set_quest_state(Q, S1)` → `None`; `quests() == [{Q, S1}, {Q2, S1}]`;
  `set_quest_state(Q, S2)` → `Some(S1)`; same again → `Some(S2)` and the hash
  is unchanged; `quest_state(Q) == Some(S2)`; `remove_quest(Q2)` → `Some(S1)`;
  `remove_quest(Q2)` → `None`. *Fails if:* the order follows insertion, or a
  replace adds an entry.
- **C7 `despawn_strips_script_state`.** One entity holding a continuation and
  a dialogue (open one on a continuation holder), plus `{Q, S1}`:
  `despawn` → both stores empty, `quests()` unchanged, exactly one
  `Despawned` appended. *Control:* `despawn(e(7))` → `false`, nothing
  appended. *Fails if:* a record survives its entity or a quest is removed.
- **C8 `transfer_refuses_holders`.** `World::new_in_area(0, u(1))` and
  `(0, u(2))`. A continuation holder → `Err(ScriptState { entity })`; a
  dialogue participant with a transform → the same; both worlds unchanged.
  *Precedence:* a participant whose transform position holds `f32::NAN` gets
  `InvalidTransform`. *Control:* after `close_dialogue` the participant
  transfers. Repeat with `transfer_history_entity` on two `HistoryWorld`s.
  *Fails if:* state is dropped by a move or an earlier error is replaced.
- **C9 `load_rejects_incoherent_state`.** From a valid world's JSON
  (`serde_json::Value` edits): a `continuations` pair naming `e(9)` → error
  containing `dangling continuation for non-live`; a `dialogues` pair naming
  `e(9)` → `dangling dialogue for non-live`; `quests` swapped to `[Q2, Q]` →
  `quest progress breaks ascending order`; `quests` with `Q` twice → the same;
  a record with an extra key `x` → refused. *Control:* the unedited JSON loads
  and equals the original. *Fails if:* any edit loads.
- **C10 `round_trip_keeps_everything`.** `World::new(5)` with `k(4)`, `k(0)`,
  one dialogue, `{Q, S1}`, `{Q2, S2}` → JSON → equal value, equal
  `state_hash`, equal `due_continuations`. *Control:* the same with `k(5)`
  hashes differently. *Fails if:* any field is lost or reordered.
- **C11 `split_run_equals_uninterrupted`** (spec `:853`). `World::new(42)`
  with `k(600)`, `k(0)`, one dialogue, `{Q, S1}`. Run A: 1000 ticks,
  recording `state_hash` after each. Run B: 500 ticks, serialize, deserialize,
  500 more. The 1000 hashes are equal pairwise; in both runs the `k(600)`
  holder is first due after tick 600. The same with a `HistoryWorld` built by
  the wrappers, `history_hash` per tick and a `HistoryWorld` JSON round trip
  at 500. *Control:* `k(601)` is first due after tick 601. *Fails if:* any
  pair differs.
- **C12 `history_journals_only_spawns`.** `h = HistoryWorld::new(3)`:
  `spawn_continuation(k(2))` journals exactly `[Spawned { entity: e(0) }]`,
  `version() == 1`. Each of the six other wrappers (valid inputs) adds no
  envelope, keeps `version() == 1` and changes `history_hash`. A refused
  `set_continuation(e(7), ..)` → `Err(Script(NotContinuation { entity: e(7) }))`,
  `history_hash` unchanged. *Full journal:* after 4096 `spawn` calls with
  nothing acknowledged, `spawn_continuation` → `Err(EventLimit)` with the hash
  unchanged; after `acknowledge(4096)` it mints index 4096 (the refused
  call allocated nothing); `set_quest_state` on the full journal succeeds. *Fails if:* a
  set journals, the version moves, or a failure commits.
- **C13 `history_tick_journals_nothing`.** A `HistoryWorld` holding `k(2)`
  (journal acknowledged): `tick()` twice → `pending_len() == 0`,
  `version() == 1`, the record holds 0. *Fails if:* the countdown journals.
