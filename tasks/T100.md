## Task
Build the benchmark T101's authoring UX ADR needs as its baseline: five
authoring briefs of rising size (one of them "define a small rule system")
are given to several models inside a bare directory with only the `crpgc`
command, the JSON Schema files and a list of today's commands; each run is
scored on **validity** (`crpgc validate --json`), **completeness** (the
documents the brief asked for exist), **playability** (the campaign's own
first encounter starts under `crpgc play` with scripted answers), **steps**
and **errors** (failed `crpgc` calls), from the model's event log and from
`crpgc` itself. The same tool re-runs on each candidate command design and
compares it to the baseline. Nothing today measures any of this; the closest
tool is the bake-off harness (`tools/agents/bakeoff/bakeoff.py`), whose shape
(setup, run, score, all; fixtures as data; scratch outside the repository)
this tool follows and whose `oc.py` helpers it reuses.

Two facts shape the design, and the contract states them instead of working
around them:

1. **`crpgc run` never opens a campaign.** It calls `run_hash_sequence` once
   over an empty world and prints sampled hashes
   (`crates/crpg-cli/src/main.rs:2518–2519`; `docs/architecture/crpg-cli.md:765–768`).
   A campaign that validates cannot be told from one that does not by `run`.
   The T100 row's "playability (`crpgc run`)" therefore cannot be literal
   (Reading 4, D72a). `crpgc play --campaign <root>` does load the campaign,
   start its first encounter and run the real rules, and it reads its choices
   from standard input one line at a time, with end of input ending the run
   (`crates/crpg-cli/src/play.rs:165–168`, `:118`), so it is scriptable today.
2. **`crpgc schema` prints 17 of the 23 schema files.** `ability`, `effect`,
   `encounter`, `outcome-table`, `ruleset` and `ui` have no stem
   (`crates/crpg-cli/src/main.rs:558–579`; `schemas/` holds 23 files), and a
   playable campaign needs four of them. The row says "with only `crpgc` and
   the schemas", so the agent's directory holds a copy of `schemas/` (Reading 3).

## Readings
Design decisions this contract makes. Each needs approval with the contract.
Each names the draft it follows, or neither, in one line.

1. **Where it lives and what it reuses.** `tools/agents/authorbench/`, shaped
   like `tools/agents/bakeoff/` (`bakeoff.py` `setup`/`run`/`score`/`all`,
   `tools/agents/bakeoff/bakeoff.py:1–9`), its `oc.py` helpers
   (`oc.opencode_prefix`, `oc.opencode_major`, `oc.model_flag`,
   `oc.wait_start_gap`, `oc.run_worker`, `oc.env_float`, `oc.Exit`;
   `tools/agents/oc.py:215`, `:251`, `:279`, `:518`, `:1070`, `:149`, `:132`),
   its sandbox file and its "locked database" retry (`bakeoff.py:310–326`,
   `:739–749`). *Follows draft A.* *Rejected:* draft B's `tools/author_bench/`
   package launched through `oc.py run --brief`: `oc.py run` prepares a git
   worktree slot of this repository and runs the verifier, so the model would
   work inside the repository and read `campaigns/fixtures/` (the answer),
   and the verifier is not an experiment's scorer.
2. **Two modules, so each part is one run.** `authorbench_scoring.py` (T100a)
   holds everything that judges a run and imports only the standard library;
   `authorbench.py` (T100b) holds the command line, the sandbox and the
   worker launch, and imports `oc` and the scoring module. *Neither draft*
   (each is one file; both exceed one run with their tests).
3. **What the agent has: `crpgc`, a copy of `schemas/`, a tool list, a brief.**
   The run directory outside the repository holds `brief.md`, `schemas/` (the
   23 checked-in files, copied) and, for the first brief only, `campaign/`
   (a copy of `campaigns/fixtures/combat_basic`). The harness puts a copy of
   the `crpgc` build under test first on `PATH`. The brief carries a list of
   the six authoring commands with today's usage lines (`crpgc` itself prints
   no help: `crates/crpg-cli/src/main.rs:256–259`), kept in one replaceable
   file (`tools-baseline.txt`) so a candidate design is a different file and
   a different binary. The brief states no folder layout (D72b). *Neither
   draft:* A rejected copying `schemas/` on a misreading of
   `docs/AGENTIC_WORKFLOW_PLAN.md:327–330` (that is about instruction files);
   B allowed `schemas/` but gave no way to hand over the tool list.
4. **"Playable" is `crpgc play` with scripted answers; `crpgc run` is kept as
   a health check (D72a).** `play` loads the campaign, collects findings,
   binds the first encounter and plays it; the harness feeds it 400 lines of
   `1` (option 1 each time), so a fight either ends (`== Summary ==`) or the
   input runs out (`Quit.`); both exit 0, and a campaign that cannot start
   its fight exits 1 (`crates/crpg-cli/src/play.rs:55–90`; contract
   `docs/architecture/crpg-cli.md:341–390`). `playable` means: valid,
   complete, the fight started (header printed, exit 0) with at least the
   brief's number of combatants. `finished` (a summary printed) is recorded,
   not required: option 1 need not win. `crpgc run --ticks 100 --hash-every 50
   --seed 0` is run once per `score` and recorded as `smoke`, so a broken
   `crpgc` build is visible and the row's literal command is kept; it never
   enters a verdict. Only combat can be played today, so the large brief's
   item, dialogue and quest are validated and counted, not played. *Neither
   draft:* both made `run` the playability gate (A said so itself and left it
   to a question; B recorded the gap); A rejected `play` as "interactive: no
   non-interactive mode", which is wrong, since stdin may be a pipe.
5. **Five briefs, one from a starter and four from nothing.** In size order:
   `campaign-extend` (add a creature to a copy of a 15-file valid campaign),
   `campaign-small` (`combat_basic` scale, 15 files), `campaign-medium`
   (`combat_srd` scale, 18 files, effects and a second table),
   `campaign-large` (adds a second area and encounter, an item, a faction, a
   dialogue and a quest, about 25 files) and `ruleset-small` (the "define a
   small rule system" brief: a new ruleset with its own ability and outcome
   table, plus the smallest campaign that plays it). Sizes come from
   `campaigns/fixtures/combat_basic/` (15 files, 262 lines),
   `campaigns/fixtures/combat_srd/` (18 files, 408 lines) and
   `rulesets/minimal-d6/` (4 files, 89 lines), counted again at `2d2617d`.
   *Follows B* for a small first rung that is the spec's literal test
   (`docs/CRPG_ENGINE_SPEC.md:1569`) done inside a campaign, and A for the
   rest of the ladder; *neither* for the ruleset brief, which is scored by
   the new ruleset's slug, not by "is not a reference ruleset".
6. **Completeness floors.** An empty or near-empty directory that validates
   is not an authored campaign, and a copy of the starter validates. Each
   brief therefore lists the document kinds it must end with
   (`minimum`, counted from the `schema` field of every `*.json` under
   `campaign/`) and the combatants its fight must start with. *Neither draft.*
7. **Separate fields, no composite score.** Each run records `valid`,
   `complete`, `playable`, `steps`, `errors` as they are; the table counts
   and averages them. *Follows A.* *Rejected:* B's 0–100 composite (weights
   50/30/20 have no basis and hide which stage failed, which is what T101
   reads).
8. **Steps and errors come from the model's event log.** `steps` is the
   number of `step_finish` events (A's and the repository's count, the same
   as `bakeoff.parse_log`, `bakeoff.py:107–139`). `errors` is the number of
   `bash` tool calls that ran `crpgc` and failed (the tool call's status is
   `error`, or its `metadata.exit` is a non-zero integer; the event shape was
   read from real worker logs (local, untracked `.agents/runs/*/*.jsonl`): `part.tool == "bash"`,
   `part.state.input.command`, `part.state.metadata.exit`); `commands` counts
   the subcommands used. A provider or process error stays in `err`, apart.
   *Neither draft:* A's 0-or-1 "any error event" cannot separate a model that
   hit one bad command from one that hit forty; B's list of diagnostics is
   unbounded and mixes campaign errors with command errors.
9. **A design is a label, a binary and a tool list.** `--design NAME` labels
   a run (default `baseline`); `--crpgc PATH` picks the build under test;
   `--tools PATH` picks the tool list shown to the agent. The baseline is
   `crpgc` as built today with `tools-baseline.txt`. Results of one design
   live in `<scratch>/<out>/scores.json` (`--out` defaults to the design).
   `compare` reads two of them and reports, per brief and model, `better`,
   `same` or `worse` by three exact success rates in this order: playable,
   complete, valid; step and error means are shown as differences and never
   decide, because they move with model variance. *Follows A* for the design
   key and *B* for comparing two stored files; *rejected:* A's strict tuple
   that includes steps (a regression from noise) and exit 1 on regression
   (the table is for T101, not a gate).
10. **Repeats, and runs that never started.** `--repeat N` runs each pair N
    times and the table gives counts out of N. A run with a non-zero exit
    code and zero steps (quota, 402, a locked database, a missing model)
    never reached the model; it is recorded as `excluded` and left out of
    every count (`tools/agents/README.md:153–158`: such causes never count
    against a model). A run that timed out with steps counts. *Neither draft*
    (A has no repeats; B propagates `oc.py` causes it never runs).
11. **Privacy.** The repository is public and free models may train on
    prompts. Every byte given to a model is repository content (the five
    prompts, the tool list, `schemas/`, the starter campaign). Scores hold
    model ids, counts and `crpgc` diagnostics only: no absolute path, no
    prompt, no model output; `err` is scrubbed of the scratch and home paths
    (B-9). Run metadata stores paths relative to the output directory.
    *Neither draft* (A's meta copies `bakeoff`'s absolute `dir` and `log`).
12. **Tests never call a model.** The suites run `authorbench_scoring.py`
    against a fake `crpgc` and `authorbench.py` against the existing
    `tools/tests/fake_opencode.py` and the same fake `crpgc`, in temporary
    directories. They are picked up by `python -m unittest discover -s
    tools/tests -p "test_*.py"`, which is what `verify_task.py` runs for a
    change under `tools/` (`tools/agents/verify_task.py:536–539`). CI runs only
    `test_preflight.py` from that directory (`.github/workflows/ci.yml:418`),
    as it does for the bake-off's suite; this contract does not touch the
    workflow ("Manager edits"). *Follows A* (B's suite greps source text for
    `subprocess`, which proves nothing).
13. **The real baseline is a manager step after both parts merge**
    ("Definition of done" gives the exact commands). It spends Go quota
    outside `oc.py`'s spend guard (`tools/agents/README.md:84–101`;
    `run_worker` is below it), so the manager runs `oc.py spend` first and
    starts with one brief and one model.

#### The fake `crpgc` (T100a writes this file exactly; it is the only `crpgc` any test runs)
`tools/tests/fixtures/authorbench/fake_crpgc.py`:
```python
#!/usr/bin/env python3
"""Fake crpgc for tools/tests/test_authorbench*.py.

Behaviour is read from the text of <campaign>/campaign.json (a marker word
anywhere in it) and from environment variables; it never touches the network.
"""
import json
import os
import sys
import time

DIAG_ERR = {"file": "campaign.json", "pointer": "/name", "severity": "error",
            "code": "missing_field", "message": "campaign name is required",
            "suggested_fix": "add a name"}
DIAG_WARN = {"file": "campaign.json", "pointer": "", "severity": "warning",
             "code": "unused_asset", "message": "asset is unused",
             "suggested_fix": None}
DIAG_IO = {"file": None, "pointer": "", "severity": "error", "code": "io",
           "message": "cannot read campaign.json: not_found", "suggested_fix": None}


def campaign_text(root):
    path = os.path.join(root, "campaign.json")
    if not os.path.isfile(path):
        return None
    with open(path, encoding="utf-8") as handle:
        return handle.read()


def validate(args):
    text = campaign_text(args[0])
    if text is None:
        print(json.dumps([DIAG_IO]))
        return 1
    if "BADOUT" in text:
        print("not json")
        return 0
    if "BROKEN" in text:
        print(json.dumps([DIAG_ERR, DIAG_WARN]))
        return 1
    if "WARN" in text:
        print(json.dumps([DIAG_WARN]))
        return 0
    print("[]")
    return 0


def play(args):
    root = args[args.index("--campaign") + 1]
    lines = len(sys.stdin.buffer.read().splitlines())
    print(f"stdin_lines={lines}", file=sys.stderr)
    text = campaign_text(root)
    if text is None:
        print("crpgc play: cannot read campaign", file=sys.stderr)
        return 1
    if "NOENC" in text:
        print("crpgc play: campaign has no encounter", file=sys.stderr)
        return 1
    try:
        count = int(json.loads(text).get("fake_combatants", 2))
    except (ValueError, AttributeError):
        count = 2
    print("== Combat demo: Fake ==")
    print("Encounter: Fake Fight")
    print("Combatants:")
    for i in range(count):
        print(f"  Unit{i} | side Unit{i} | 10/10 hp")
    print()
    if "QUITS" in text:
        print("Quit.")
        return 0
    print("== Summary ==")
    print("Rounds played: 3")
    print("Final health:")
    print("  Unit0 10/10 hp")
    print("Survivors: Unit0")
    print("Winner: Unit0")
    return 0


def run(args):
    forced = os.environ.get("FAKE_CRPGC_SMOKE_RC")
    if forced is not None:
        return int(forced)
    ticks = int(args[args.index("--ticks") + 1])
    every = int(args[args.index("--hash-every") + 1])
    for tick in range(every, ticks + 1, every):
        print(f"{tick} " + "ab" * 32)
    return 0


def main():
    argv = sys.argv[1:]
    delay = float(os.environ.get("FAKE_CRPGC_SLEEP", "0"))
    if delay:
        time.sleep(delay)
    if not argv:
        print("crpgc: missing subcommand", file=sys.stderr)
        return 2
    table = {"validate": validate, "play": play, "run": run}
    if argv[0] not in table:
        print(f"crpgc: unknown subcommand '{argv[0]}'", file=sys.stderr)
        return 2
    return table[argv[0]](argv[1:])


if __name__ == "__main__":
    sys.exit(main())
```

line each, a blank line; the summary is `demo.rs:497–537`).

### Command line (exit codes the `oc.py` convention: 0 ok, 1 a run failed, 2 usage or infrastructure)
```text
python tools/agents/authorbench/authorbench.py setup <scratch>
python tools/agents/authorbench/authorbench.py run <scratch> --models <m1,m2|@file>
        [--briefs <all|a,b>] [--design NAME] [--out NAME] [--variant V]
        [--repeat N] [--par N] [--crpgc PATH] [--tools PATH]
python tools/agents/authorbench/authorbench.py score <scratch>
        [--design NAME] [--out NAME] [--crpgc PATH] [--json]
python tools/agents/authorbench/authorbench.py compare <scratch> <base-out> <cand-out> [--json]
python tools/agents/authorbench/authorbench.py all <scratch> [--models ...] [the run flags]
```
Defaults: `--briefs all`; `--design baseline`; `--out` = the design;
`--repeat 1`; `--par 3`; `--tools tools/agents/authorbench/tools-baseline.txt`;
`--models` for `all` only: `@tools/agents/authorbench/models.txt` (required
for `run`). `--models @file`: one id per line, blank lines and lines starting
`#` ignored, a relative path resolved against the current directory.
`<scratch>` is any directory outside the repository.
`--models` is checked by the command (B-12's order), not marked required in
`argparse`, so a scratch inside the repository is refused first. `--tools` is
relative to the current directory unless absolute; the default is the file
beside the script. `score` and `compare` take `--design` only to choose the
default `--out`.

### Brief data (T100b; loaded by `load_brief`)
`briefs/<name>/brief.json`, one object with exactly the `KEYS`:
```json
{"name": "campaign-small", "kind": "campaign", "starter": null,
 "minimum": {"creature": 2, "ability": 1, "outcome-table": 1, "ruleset": 1, "encounter": 1},
 "ruleset_slug": null, "min_combatants": 2, "timeout_s": 1800}
```
`minimum` maps a document kind (the word between `crpg.` and `/` in a
document's `schema` field: `crpg.outcome-table/1` is `outcome-table`) to the
fewest documents of that kind the finished `campaign/` must hold.
`starter` is a repository-relative directory copied to `campaign/` at setup
(`extend` only). `ruleset_slug` is the slug a `ruleset` document must carry
(`ruleset` only). `min_combatants` is the fewest combatants the fight must
start with. `prompt.txt` holds the brief text with `{{TOOLS}}` once.

### T100a
B-1. **`load_brief(dir)`** reads `<dir>/brief.json` and `<dir>/prompt.txt`
(UTF-8) and returns the object plus `"prompt"`. It raises
`BriefError("brief {dir name}: {text}")` for the first of, in order:
1. `brief.json` missing, not JSON, or not an object → `brief.json is not a JSON object`;
2. a key outside `KEYS`, first in sorted order → `unknown key {k}`; then a
   missing `KEYS` entry, first in `KEYS` order → `missing key {k}`;
3. `name` not equal to the directory's name → `name must equal the directory name`;
4. `kind` not in `KINDS` → `kind must be one of extend, campaign, ruleset`;
5. `starter`: for `extend` a non-empty string that does not start with `/`,
   contains no `\` and no `..` segment, else `starter must be a repository-relative path`;
   for the other kinds not `null` → `starter must be null`;
6. `minimum` not a non-empty object whose keys match `^[a-z][a-z0-9-]*$` and
   whose values are integers `>= 1` (a boolean is not an integer) → `minimum must map kinds to integers >= 1`;

*Tests:* SC1.

B-2. **`read_log(path)`** returns
`{"steps","tools","crpgc_calls","crpgc_failures","commands","tok","cost","err"}`
and never raises; a missing file gives zeros, `{}`, `""`. Each line is parsed
as JSON; a line that is not JSON and contains `rror` sets `err` to the line
stripped and cut to 160 characters if `err` is still empty; a JSON line that
is not an object is skipped. Per event `type`:
`step_finish` → `steps += 1` and `tok`/`cost` accumulate from
`part.tokens.input|output|reasoning|cache.read` and `part.cost` (a missing or
`null` value is 0); `error` → if `err` is empty, `err =
json.dumps(event.get("error"))[:200]`; `tool_use` → `tools += 1`, and when
`part.tool == "bash"` and `part.state.input.command` is a string `c`: let
`names = re.findall(r"\bcrpgc(?:\.exe)?\s+([a-z][a-z-]*)", c)`; if `names`
is non-empty, `crpgc_calls += 1`, each name is counted once in `commands`,
and the call is a failure when `part.state.status == "error"` or
`part.state.metadata.exit` is an integer other than 0 (a boolean is not an
integer): `crpgc_failures += 1`. `tok` is `{"input","output","reasoning",
"cache_read"}`; `commands` has its keys sorted. *Tests:* SC2. *Amended by erratum T100-E1 (before "Manager edits"): the tool may be `shell`, and the exit code may be one level deeper.*

B-3. **`crpgc_prefix(path)`** is `[sys.executable, path]` when `path` ends in
`.py`, else `[path]`. **`call_crpgc(prefix, args, stdin_bytes, timeout_s)`**
runs `prefix + args` with `subprocess.run` (no shell; `stdin=DEVNULL` when
`stdin_bytes is None`, else `input=stdin_bytes`; stdout and stderr captured as
bytes; the environment is `os.environ`) and returns `{"rc": int | None,
"stdout": str, "stderr": str, "timeout": bool}`. On `TimeoutExpired`: `rc`
`None`, `timeout` `True`, both texts `""`. On `OSError`: `rc` `None`,
`timeout` `False`, `stdout` `""`, `stderr` the error's text. It never raises.
*Tests:* SC3.

B-4. **`scan_campaign(dir)`** walks `dir` in sorted order without following
symbolic links and returns `{"files": n, "json": n, "kinds": {...},
"ruleset_slugs": [...], "unreadable": n}`: `files` counts every regular file;
for each `*.json` file `json += 1`; a file that is not UTF-8 JSON or not an
object counts in `unreadable`; an object whose `schema` is a string matching
`^crpg\.([a-z][a-z0-9-]*)/[0-9]+$` adds one to `kinds[group 1]`, and when the
kind is `ruleset` and its `slug` is a string, that slug joins
`ruleset_slugs`. `kinds` has sorted keys and `ruleset_slugs` is sorted.
*Tests:* SC4.

B-5. **Output readers.**
- `parse_diagnostics(text)`: the parsed JSON when it is a list whose every
  element is an object, else `None` (empty text is `None`).
- `count_samples(stdout)`: the number of lines matching `^[0-9]+ [0-9a-f]{64}$`.
- `parse_play(stdout, rc)` returns `{"started","finished","combatants","rounds"}`:
  `started` is `rc == 0` and the first line starts `== Combat demo: `;
  `finished` is `started` and some line equals `== Summary ==`;
  `combatants` counts the lines after the line `Combatants:` and before the
  next empty line that match `^  .+ \| side .+ \| [0-9]+/[0-9]+ hp$` (0 when
  there is no such line); `rounds` is the integer of the first line
  `Rounds played: N`, else `None`. When `started` is false, `finished` is
  false and `combatants` is 0.
*Tests:* SC5.

B-6. **`smoke_check(prefix)`** calls `SMOKE_ARGS` and returns `{"rc", "samples",

SMOKE_SAMPLES`. *Tests:* SC6.

B-7. **`score_run(brief, run_dir, prefix)`** returns, in this key order,
`campaign_present`, `files`, `kinds`, `valid`, `validate`, `complete`,
`play`, `playable`, `first_error`:
1. `campaign_present` is `(run_dir / "campaign").is_dir()`. `files` and
   `kinds` come from `scan_campaign` (zeros and `{}` when absent).
2. When present, call `["validate", <campaign>, "--json"]`. `validate` is
   `{"rc": rc, "errors": e, "warnings": w, "codes": c, "unparsable": u}`:
   `diags = parse_diagnostics(stdout)`; `u` is `rc is not None and diags is
   None`; `e` and `w` count diagnostics whose `severity` is `"error"` and
   `"warning"`; `c` is the sorted distinct `code` strings of the error
   diagnostics, at most the first 10. `first_error` is the first diagnostic
   with severity `error`, as `{"file": d.get("file"), "code": d.get("code"),
   "message": str(d.get("message", ""))[:160]}`, else `None`. When absent:
   `{"rc": None, "errors": 0, "warnings": 0, "codes": [], "unparsable": false}`.
3. `valid` is `rc == 0 and diags is not None` (`False` when absent). A
   warning does not make a campaign invalid.
4. `complete` is true when every `minimum` kind has at least that many
   documents in `kinds` and, when `ruleset_slug` is not `null`, it is in
   `ruleset_slugs`. It does not depend on `valid`.
5. `play` is `{"rc": None, "started": false, "finished": false, "combatants":
   0, "rounds": None}` unless `valid`; when `valid`, call `["play",
   "--campaign", <campaign>, "--seed", "0"]` with `stdin_bytes = b"1\n" *
   PLAY_INPUT_LINES`, and `play = {"rc": rc} | parse_play(stdout, rc)`.
6. `playable` is `valid and complete and play["started"] and
   play["combatants"] >= brief["min_combatants"]`.
7. The campaign path passed to `crpgc` is `str(run_dir / "campaign")`.
8. `empty_score()` returns the nine keys with the values of a run whose
   `campaign/` is absent: `False`, `0`, `{}`, `False`, the not-run `validate`

*Tests:* SC7, SC8.

B-8. **`aggregate(rows, brief_order)`** returns one cell per (brief, model)
present, ordered by `brief_order` index then model name. A row is

rows, `excluded` the excluded ones; `valid`, `complete`, `playable` count
rows where the flag is true; `finished` counts `play.finished`;
`steps_mean`, `errors_mean`, `secs_mean` are `round(sum / n, 1)` over the

`{"brief","model","base": {"n","playable","complete","valid"}, "cand":
{"n","playable","complete","valid"}, "d_steps": round(cand.steps_mean - base.steps_mean, 1), "d_errors":

## Errors
| Condition | Result |
|---|---|
| scratch inside the repository (`setup`, `run`, `score`, `compare`, `all`) | exit 2, `{cmd}: scratch directory is inside the repository; refused` |
| malformed brief (`setup`, `run`) | exit 2, `{cmd}: brief {name}: {text}` (B-1's text) |
| `run` without models, an unknown brief, a missing template, `--repeat`/`--par` below 1, an unreadable `--tools` | exit 2, `run: {text}` (B-12's order) |
| no `crpgc` | exit 2, `authorbench: no-crpgc: build it or pass --crpgc` |
| no OpenCode | exit 2, `authorbench: no-exe: …` (from `oc`) |
| `score` with no runs / an unknown brief in a meta | exit 2, `score: no runs in {out}` / `score: unknown brief {name}` |
| `compare` with a missing scores file | exit 2, `compare: no scores in {out}` |
| a run timed out or exited non-zero (`run`, `all`) | exit 1 after every run finished |
| a model that never started (non-zero exit, zero steps) | not an error: `excluded` in the score |
| a run with no `campaign/`, an invalid campaign, a fight that does not start | not an error: scored false |

No new `crpgc` behaviour, exit code or message. The scorer never raises on
a run's content: every failure to run `crpgc` is a recorded field.

## Questions for the user
Two; both are answered by recommendation unless you say otherwise, and neither
blocks building (the answers change `playable` in B-7 and
`tools-baseline.txt`, not the rest). Also written as `tasks/DECISIONS-D72.md`.

1. **D72a — what does "playable" mean for a campaign an agent wrote?** The
   plan row says playability is checked by `crpgc run`. That command does not
   open a campaign at all: it runs an empty world and prints fingerprints of
   it, so every campaign, good or bad, would pass.
   (a) **Keep it literal: `crpgc run`.** No information: the score would not
   depend on what the agent wrote.
   (b) **Use `crpgc play` with scripted answers (recommended).** The tool loads
   the agent's campaign, starts its first fight with the real rules and
   presses "1" up to 400 times. "Playable" means the fight starts with the
   right number of combatants. `crpgc run` still runs once as a health check
   of the build. Limit: only fights can be played today, so dialogue, quests
   and items are checked for validity and counted but not played.
   (c) **Both must pass.** Same as (b) in practice, since `run` does not
   depend on the campaign.
   *Recommend (b).* If you choose (a) or (c), `playable` in B-7 changes and
   the benchmark loses its only measure of "does it start".
2. **D72b — what does the agent get to start with?** The baseline measures
   "today's tools", so what the agent is told decides what the numbers mean.
   (a) **`crpgc`, a copy of the 23 schema files, and a plain list of the six
   commands' usage lines; no folder layout (recommended).** `crpgc` prints no
   help of its own, so the list stands in for it. Six document types
   (ability, effect, encounter, outcome-table, ruleset, ui) have no `crpgc
   schema` command, so the schema files are handed over. The agent must find
   out where each file goes mostly by trying and reading the validator's messages. This shows how
   discoverable the layout is today, which is probably the biggest agent
   problem; the numbers for the four from-nothing briefs may be low, and the
   first brief (a copy of a valid campaign) still shows what works when the
   layout is visible.
   (b) **As (a), plus a short cheat-sheet of the folder layout.** Higher
   success, but it hides the discoverability gap that the authoring ADR most
   needs to measure.
   (c) **`crpgc` only, no schema files.** Closest to the plan row's words if
   "the schemas" meant `crpgc schema`, but an agent could then never learn the
   shape of an ability, an outcome table, a ruleset or an encounter, so every
   brief but the first would fail for a reason no UX change in the authoring
   commands could fix.
   *Recommend (a).* If the baseline comes out near zero everywhere, (b) is
   one more run with another `--tools` file and no code change.
