## Task
Make the host run the MVP AI. `crpg_ai::decide` (T056a,
`crates/crpg-ai/src/mvp.rs:40–45`) is read-only and says what one creature
should do next; nothing but tests calls it today: the one crate that depends
on `crpg-ai` is `crpg-testkit`, as a dev-dependency for the T056b suite
(`crates/crpg-testkit/Cargo.toml:18`, `:28–32`; no other `Cargo.toml` names
it), and `docs/architecture/crpg-ai.md:109–110` lists the host driver as a
later consumer.
T153 adds one trusted host operation, `Host::drive_ai`, that the embedding
calls between ticks: it picks the AI-controlled combatants that may act now,
calls `decide` with the caller's `Sides` and the host's own bound mesh,
applies each `Decision` through the host operations that already exist —
`host_action` (T141a, `crates/crpg-server/src/host.rs:3268–3273`),
`host_move`, `move_to`, `halt` (T037a, `:3502–3527`, `:3457–3471`,
`:3478–3487`) — caps the work per turn and per call, and reports what it did.
It also proves that `crpg_ai::host_route` (`crates/crpg-ai/src/route.rs:77–100`)
equals T037a's `plan_route` (`crates/crpg-server/src/nav.rs:102–132`) on the
bound mesh.

T153 depends on **T037a only** (`bind_nav_mesh`, `plan_route`, `move_to`,
`halt`, `host_move`; on `master`) and on T141a's `host_action`. It uses
nothing from T037b–T037d (v4 sessions, `DeclareMove`, lane 1), which keep
working unchanged around it. It needs T056a's `crpg-ai` on its base, so it is
built after the T056 PR merges.

For the demo: T153 is what the AI hook of T154's run loop will call in
place of the Godot slice's NPC driver (`crates/crpg-godot/src/core/authority.rs:1`,
`:34–77`, `:515–568`; ADR-0033 "When real AI arrives the driver is replaced
behind the host", `docs/adr/0033-godot-bridge.md:222`); T151 (revised) runs
that NPC driver as the hook until then. The terminal game `crpgc play`
does not use the host at all (`crates/crpg-cli/src/play.rs:1–8`, its own
`npc_action`, `:205–228`), so making the terminal creatures use the AI is a
separate small `crpg-cli` task ("Manager edits").

## Readings
Design decisions this contract makes. Each needs approval with the contract.

1. **The driver is a trusted host operation the embedding calls between
   ticks.** ADR-0029 T15 puts AI "in the host between ticks", submitting
   ordinary commands, and its output enters the World only through journaled
   operations (`docs/adr/0029-kernel-range-and-time-model.md:266–271`). So
   `drive_ai` sits beside `host_action`, `request_mode` and `advance`. The
   loop that calls it is T154's run-loop cycle (D65a,
   `task/T154-c1:tasks/T154.md`, Reading 2): intake (every waiting frame, then
   one `pump`), the AI hook, `advance`, deliver. The embedding calls
   `drive_ai` from its AI hook (`LocalHost::set_ai`'s `AiHook` in single
   player, `QuicHosting::set_ai`'s `QuicAiHook` through `QuicHost::drive_ai`
   on a dedicated server), at most once per cycle unless the hook itself
   loops. T153 adds no loop and no hook; it only provides the operation the
   hook calls. Both drafts.
   *Rejected:* a step inside `advance` (`AdvanceReport` is public and built by
   existing tests and `crpg-godot`, `crates/crpg-server/src/host.rs:470–477`;
   T037d already adds its own step there, `tasks/T037.md:765–766`); a step
   inside `pump` (peer commands, not host operations); a sim tick stage
   (T15 removed spec §10 stage 5).
2. **One step per call in turn-based play.** A turn-based call makes at most
   one decision for the head (or the cap's forced `EndTurn`, Reading 5); the
   embedding calls again for the next step. T056 already makes a turn a
   sequence of single steps (`tasks/T056.md:228–237`), and pacing is the
   hook's choice, not the server's: the hook gets the cycle's `now_ms`
   (T154 Reading 5), so a visible embedding may keep the Godot NPC driver's
   600 ms delay between steps (`crates/crpg-godot/src/core/authority.rs:29`,
   `:515–528`) and a headless one may call again within the same cycle while
   the head is AI-controlled. The server does not pace the AI. *Rejected:*
   both drafts' "loop until the turn ends" (a move and its attack land in the
   same frame, so the player cannot see the creature walk before it strikes;
   and the per-turn cap would be per call, so a paced embedding calling with
   one step per call could never use it).
3. **The controlled set and `Sides` cross per call; the host stores neither.**
   "Which combatants are AI-controlled is the caller's fact" and the host
   holds no controller list (`crates/crpg-server/AGENTS.md:183–187`); the
   caller builds `Sides` from authored data because neither `crpg-server`
   nor `crpg-ai` may read `crpg-data` (`crates/crpg-server/AGENTS.md:103`,
   `tools/lint/deps.py:53`). `drive_ai(sides, actors, budget)` takes
   `&crpg_ai::Sides` exactly as T056 defines it (`crates/crpg-ai/src/sides.rs:22`,
   `:55`). Draft B's choice. *Rejected:* draft A's stored `set_ai` (host
   state lost on every restore that the embedding must re-send anyway, and a
   new public setter); draft B's `ai_sides(Vec<(EntityId, u32)>)` (the same
   thing as `Sides::new(… SideId(u32) …)`, `crates/crpg-ai/src/sides.rs:15`,
   `:55`); inferring the controlled set from `Sides` (the player's creatures
   are in `Sides` too).
4. **The mesh `decide` sees is the host's own, or none.** `decide` gets
   `Some(&mesh)` exactly when the host holds a `HostNav`
   (`crates/crpg-server/src/host.rs:836–838`), else `None`, which `decide`
   turns into its no-move fallbacks (`tasks/T056.md:484–498`). A restored
   host has no mesh until the embedding binds it again (`tasks/T037.md:145–152`).
   Both drafts. *Rejected:* a mesh argument (a mesh other than the host's
   would make the AI's routes differ from the host's).
5. **The turn cap counts decisions across calls and then ends the turn.**
   Every ability costs at least 1 from a pool (a save with an empty or zero
   cost is refused, `crates/crpg-sim/src/world.rs:473–486`), and every
   accepted turn-based move costs at least one unit (`tasks/T056.md:230–233`),
   so today a turn is bounded by its pools; but a pool may be large and an
   ability may keep the turn, and `decide` is pure, so the same state repeats
   the same answer. The host therefore counts the `decide` calls of the
   current turn, identified by `(round, head)` (`crates/crpg-sim/src/combat.rs:844–846`),
   in a private, never-saved field; once the count reaches the budget the call
   ends the head's turn with `host_action(EndTurn { head })` instead of
   deciding (an `EndTurn` the head may always submit,
   `crates/crpg-sim/src/combat.rs:3512–3530`). `MVP_AI_BUDGET.decisions_per_turn`
   is 16: an MVP turn is two steps (move, attack), and 16 leaves room for
   rulesets with several non-ending actions while ending a runaway turn after
   16 calls. Both drafts force the `EndTurn`; draft A capped at 8, draft B at
   64, both per call. *Rejected:* stopping and reporting without ending the
   turn (a stuck AI head stalls the fight); no cap.
6. **Real time decides for every live controlled combatant, not only the
   "due with no order" ones.** ADR-0029 T15 says the AI runs in real time
   "when one is due with no order" (`:266–268`), which is what
   `awaiting_orders` lists (`crates/crpg-server/src/host.rs:3323–3360`). But
   T056's real-time rules were written to be asked about walking and ordered
   creatures: hold while a walk still ends in range, halt before striking,
   hold on its own standing order, re-plan when the target moved
   (`tasks/T056.md:238–257`, M-4, M-6). And an order whose target walks out
   of range is kept and retried every tick forever (X3,
   `crates/crpg-sim/AGENTS.md:633`): a driver that skips ordered creatures
   would leave that creature standing still for the rest of the fight. So the
   real-time candidates are the controlled combatants that are live and not
   dead, under `awaiting_orders`' own fight gate (`:3333–3344`). Neither draft
   (both used `awaiting_orders`). A dated note in ADR-0029 records it
   ("Manager edits").
7. **The real-time cap rotates by the world tick.** One call decides for at
   most `actors_per_drive` candidates (8 in `MVP_AI_BUDGET`, spec §6.2 item 2
   "at most N entities re-evaluate per tick", `docs/CRPG_ENGINE_SPEC.md:724`).
   With more candidates than that, the call starts at `server_tick() % n`
   (`crates/crpg-server/src/host.rs:932–934`, journaled world state) and wraps,
   so every candidate is reached within `ceil(n / k)` consecutive ticks and a
   restore keeps the rotation with no stored cursor. Draft B's choice.
   *Rejected:* draft A's "the first eight, ascending" (creatures nine and up
   never think); a stored cursor (saved host state).
8. **The budget is a call argument with an MVP constant.** `drive_ai` takes
   an `AiBudget`; embeddings pass `MVP_AI_BUDGET`. Tests pass small budgets,
   so the caps and the rotation are proved on the three-combatant fixture.
   Draft B's `AiCaps`. *Rejected:* constants only (the real-time cap of 8
   cannot be reached with three combatants, so the rotation would be
   untested).
9. **Refusals and `decide` errors are report steps; `Closed` is the only
   `Err`.** A host operation that refuses (`CaptureFull` is the reachable one)
   or a `decide` error (only `TooManyOptions` can reach a live controlled
   combatant) becomes a step and changes nothing; real time goes on with the
   next candidate; a turn-based call has made its one step. No retry and no
   forced `EndTurn` after a refusal: under `CaptureFull` it would refuse too.
   Draft B's choice. *Rejected:* draft A's "return the `HostError` and drop
   the report" (an embedding then cannot tell which earlier real-time steps
   committed).
10. **The decision maps by kind and mode, with no special turn-based arms.**
    `Act(a)` → `host_action(&a)`; `Move { destination, .. }` → `host_move`
    in turn-based play, `move_to` in real time; `Halt` → `halt`; `Hold` →
    nothing (`crates/crpg-ai/src/mvp.rs:13–16`). `decide` never returns
    `Halt` or `Hold` in turn-based play (`tasks/T056.md:233–236`); were it to,
    `halt` clears nothing and the turn cap ends the turn, so the driver needs
    no unreachable arm. *Rejected:* draft A's `Invariant` error arm (a branch
    no test can reach).
11. **No re-validation in the driver; the operations validate.** Every
    `Act` is an element of `legal_actions(world, actor)`
    (`crates/crpg-ai/src/mvp.rs:20`), and `host_action` revalidates with
    `validate_action` (`crates/crpg-server/src/host.rs:3285`); `host_move`
    checks the turn, routes with `plan_route` and runs `validate_move`
    (`:3513–3521`); `move_to` routes with `plan_route` and `set_route`
    validates (`:3467–3468`). So the AI does nothing a player's own command
    for that creature could not, and only for creatures the caller listed.
12. **Route parity is a unit test plus a compile-time tag check, not a
    per-move runtime query.** The two computations are the same expression
    (`crates/crpg-ai/src/route.rs:83–100`; `crates/crpg-server/src/nav.rs:110–131`)
    with tags `AI_ROUTE_TAG` and `HOST_ROUTE_TAG`, both `RouteTag(0)`
    (`crates/crpg-ai/src/route.rs:16`, `crates/crpg-server/src/host.rs:103`).
    A `#[cfg(test)]` case compares them directly (`plan_route` is
    `pub(crate)`), and the integration suite mirrors every AI move with
    `crpg_ai::host_route`'s route, so a divergence changes the authority hash.
    Both drafts. *Rejected:* recomputing and comparing on every move (a second
    navigation query per move, against T037's one-computation rule,
    `tasks/T037.md:168–177`).
13. **Pause does not stop the driver** (Question 2, answered: D65g). ADR-0029 P2: while
    paused "the host still admits and executes commands: TB actions resolve
    and RT orders … are stored. Only ticks stop" (`:283–285`), and
    `host_action` already runs while paused (`crates/crpg-server/src/host.rs:3267`).
    Single-player hosts auto-pause on `EncounterStarted`
    (`SINGLE_PLAYER_AUTO_PAUSE_BITS`, `:423–425`) and a restored host starts
    paused (`:901`); a driver that idled while paused would stall a
    turn-based fight at its start until someone unpaused. An embedding that
    wants the AI to wait simply does not call. Draft B's choice; draft A was
    silent.
14. **One `crpg-server` part; its tests use the server's saved-game fixture.**
    The behaviour of `decide` over authored encounters is T056b's
    (`crates/crpg-testkit/tests/ai_mvp.rs`); what T153 adds — the gate, the
    mapping, the counter, the rotation — is proved on
    `tests/fixtures/three_combatants.json` edited in memory, as
    `host_nav.rs` does (`crates/crpg-server/tests/host_nav.rs:116–203`). Draft
    A's shape. *Rejected:* draft B's second part in `crpg-testkit` (a second
    implementer run and a `crpg-testkit → crpg-server` line that T037e also
    adds, `tasks/T037.md:1375`, for no behaviour the server suite cannot
    reach).
15. **A child module keeps `host.rs` untouched but for six lines.** The
    driver lives in `crates/crpg-server/src/host/ai.rs` (`mod ai;` in
    `host.rs`), which may read `Host`'s private fields; its public types are
    re-exported as `crpg_server::host::{AiBudget, AiReport, AiStep, MVP_AI_BUDGET}`.
    T037b–T037d edit `host.rs` heavily (`tasks/T037.md:96–114`).
    *Rejected:* a crate-level `ai` module (cannot reach `Host`'s fields
    without widening them).

### `crates/crpg-server/src/host/ai.rs`
```rust
//! The MVP AI driver (T153): `Host::drive_ai`.
use crpg_core::EntityId;
use super::{Host, HostError, HOST_ROUTE_TAG};

// Reading 12, at compile time.
const _: () = assert!(crpg_ai::AI_ROUTE_TAG.0 == HOST_ROUTE_TAG.0);

/// How much one `drive_ai` call may do (Readings 5, 7, 8).
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct AiBudget {
    /// Turn-based: `decide` calls allowed in one turn, counted across calls;
    /// at the count the driver ends the head's turn instead of deciding.
    pub decisions_per_turn: u32,
    /// Real time: the most controlled combatants one call decides for.
    pub actors_per_drive: u32,
}

/// The MVP budget: 16 decisions per turn, 8 creatures per call.
pub const MVP_AI_BUDGET: AiBudget = AiBudget { decisions_per_turn: 16, actors_per_drive: 8 };

/// One thing a `drive_ai` call did for one actor (Readings 9, 10).
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum AiStep {
    /// The decision was applied by its host operation (`Hold`: by nothing).
    Applied { actor: EntityId, decision: crpg_ai::Decision },
    /// The host operation refused the decision; it changed nothing.
    Refused { actor: EntityId, decision: crpg_ai::Decision, error: HostError },
    /// `decide` returned an error, unchanged; nothing was applied.
    Undecided { actor: EntityId, error: crpg_sim::LegalActionsError },
}

/// What one `drive_ai` call did.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct AiReport {
    /// In the order they happened.
    pub steps: Vec<AiStep>,
    /// A budget limited the call: turn-based, the turn cap was reached, so the
    /// call's one step is the forced `EndTurn`, applied or refused (D-5(1));
    /// real time, some candidates were left for a later call.
    pub capped: bool,
}

/// The current AI turn and its decision count (D-5). Crate-private.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) struct AiTurn {
    pub(crate) round: u32,
    pub(crate) head: EntityId,
    pub(crate) decisions: u32,
}

impl Host {
    /// One AI drive (D-1..D-12): `Closed` first; otherwise always `Ok`.
    pub fn drive_ai(
        &mut self,
        sides: &crpg_ai::Sides,
        actors: &[EntityId],
        budget: AiBudget,
    ) -> Result<AiReport, HostError>;
}
```
Each public field and variant field carries its own doc comment in the
implementation (`#![warn(missing_docs)]`); the comments above are their
meaning. Private helpers are the implementer's.

## Behaviour
Normative. Each item names the tests that prove it. "Unchanged" means
`authority_hash`, `last_capture`, `executions`, `nav_revision`, `paused` and
every peer's delivery entries as before the call. **First failure wins** in
every ordered list. `world` is the host's world as the previous step left it.

D-1. **Closed.** A shut-down host: `Err(HostError::Closed)`, unchanged, the
turn counter untouched. Otherwise `drive_ai` returns `Ok`. *Tests:* H10.

D-2. **No fight.** `world.combat()` is `None`: `R([], false)`. *Tests:* H10.

D-3. **The controlled set.** `ctl` is `actors` sorted ascending with
duplicates removed; the input order never matters. `mesh` is
`self.nav.as_ref().map(|nav| &nav.mesh)` (Reading 4). *Tests:* H1, H7.

D-4. **Turn-based gate.** Mode `TurnBased`: `head = combat.active`; `None`,
or `head ∉ ctl`: `R([], false)` and the counter untouched. *Tests:* H1, H3.

D-5. **Turn-based step** (Readings 2, 5). If `ai_turn` is not
`Some(AiTurn { round: combat.round, head, .. })`, it becomes
`Some(AiTurn { round: combat.round, head, decisions: 0 })`. Then:
(1) `decisions ≥ budget.decisions_per_turn`: the call runs
`host_action(&EndTurn { head })` and returns `R([step], true)`, where `step`
is `Ap(head, Act(EndTurn { head }))` or `Rf(head, Act(EndTurn { head }), e)`;
`capped` is true in both (it says the cap was reached, not that the turn
ended; the step says which), and the counter is not incremented.
(2) Otherwise `decisions += 1` (saturating), then
`crpg_ai::decide(world, head, sides, mesh)`: `Err(e)` gives `R([Ud(head, e)], false)`;
`Ok(d)` is mapped (D-7) and gives `R([Ap(head, d)], false)` or
`R([Rf(head, d, e)], false)`. Exactly one step per call. *Tests:* H1, H2, H3,
H4, H8, H9.

D-6. **Real-time step** (Readings 6, 7). Mode `RealTime`: the fight gate of
`awaiting_orders` (`crates/crpg-server/src/host.rs:3333–3344`): `clock` is
`None`, fewer than two combatants are alive, or `clock.elapsed ≥ RT_CLOCK_MAX`
(`crates/crpg-sim/src/combat.rs:86`): `R([], false)`. Otherwise the
candidates `cand` are the entries `e` of `ctl` with
`world.combatants().get(e)` present and not `dead()`, ascending; `n =
cand.len()`, `k = budget.actors_per_drive`. If `n ≤ k`, the order is `cand`
and `capped` is false; else `s = server_tick() % n` and the order is
`cand[s], cand[s+1], …` wrapping, `k` entries, and `capped` is true. For each
actor in order: `decide(world, actor, sides, mesh)`; `Err(e)` appends
`Ud(actor, e)`; `Ok(d)` is mapped (D-7) and appends `Ap` or `Rf`; the next
actor's `decide` reads the world as this one left it. The turn counter is not
read or written. *Tests:* H5, H6, H7.

D-7. **Mapping** (Reading 10). `Act(a)` → `host_action(&a)`;
`Move { destination, .. }` → `host_move(actor, destination)` in turn-based
play, `move_to(actor, destination)` in real time; `Halt` → `halt(actor)`;
`Hold` → no call (always `Ap`). `Ok(_)` of the operation gives `Ap(actor, d)`;
`Err(e)` gives `Rf(actor, d, e)`, and that operation changed nothing (its own
contract: T141a, T037a A-7..A-9). The operation's own `Ok` value is not
reported. *Tests:* H2 (`host_move`), H5 (`move_to`, `host_action` storing an
order, `Hold`), H6 (`halt`), H8 (`Rf`).

D-8. **Errors are steps, never retries** (Reading 9). No call retries a
decision, re-decides after a refusal, or issues an `EndTurn` other than
D-5(1)'s. *Tests:* H8.

D-9. **Pause** (Reading 13; D65g). `paused()` is not read: a paused
host drives exactly as a running one, and stays paused. *Tests:* H9.

D-10. **Authority** (Reading 11). Every step's actor is in `ctl`; every
applied `Act` is an element of `legal_actions(world, actor)` at the moment it
is applied and names that actor; every effect goes through `host_action`,
`host_move`, `move_to` or `halt`, so it is recorded and published exactly as
those operations already are (`host_action` and `host_move` as one
`HostOp::Action` host record when they journal anything; `move_to`, `halt`
and a real-time order as zero-event operations,
`crates/crpg-server/src/host.rs:3573–3586`). `executions()`, sequences,
receipts and `last_combat_error` never move. *Tests:* H1, H2, H5.

D-11. **State and determinism.** The only new state is `ai_turn`: `None`
from `new`, `from_history` and `load_checkpoint` (`restore` calls
`assemble`, `:892–901`), never saved, so a restore mid-turn restarts the
count. Two hosts with equal authority, mesh and call history give equal
reports and equal hashes; the driver reads no clock and no RNG beyond what
the operations it calls already draw. *Tests:* H2 (twin host), H3, H11
(restore).

D-12. **Route parity** (Reading 12). For a host with `HostNav { mesh,
revision }` bound to the world: `crpg_ai::host_route(&mesh, world, actor, d)`
equals `plan_route(Some(&nav), world, actor, d, HOST_ROUTE_TAG)` for every
`actor` and `d`, with `RouteError::{AbsentEntity, NotMover, Nav}` matching
`RouteRefusal::{Move(AbsentEntity), Move(NotMover), Nav}` field for field
(`NavUnbound` cannot occur: `bind_nav_mesh` binds the world, `host.rs:3374–3405`).
*Tests:* U1, U2, and every mirrored move of H2, H3, H5.

D-13. **No other change.** A host that never calls `drive_ai` is
byte-identical to today in every delivery, capture, checkpoint and hash.
*Tests:* every existing suite.

   shared turn limits. *Recommend (a).*
2. **Should computer-controlled creatures keep acting while the game is
   paused?** The engine's pause stops the clock but still lets players give
   orders; single-player games pause automatically when a fight starts, and
   a loaded save starts paused. (a) **Yes, the AI ignores pause
   (recommended):** in turn-based fights the enemy takes its turn as soon as
   the front-end asks, even if the player never unpaused; in real time the
   AI only gives orders, which wait until the clock runs again. (b) **No, the
   AI waits while paused:** every fight would sit still until the player
   unpauses, including the first enemy turn after the automatic pause at the
   start of a fight, so the demo front-end must unpause or the enemy never
   moves; D-9 and H9 flip. *Recommend (a);* a front-end that wants (b) can
   simply not call the driver while paused.
