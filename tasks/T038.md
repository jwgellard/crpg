# T038 — Versioned save envelope and atomic file store (`crpg-persist`)

Status: **Contract draft — awaiting user approval (H-contract).** Nothing
here is approved until the user says so. The dependency request in
[§9](#9-dependency-audit-and-approval-request-h-dep) also needs H-dep approval
before any source is written.

## Task

Build the first `crpg-persist` code. It wraps caller-supplied payload bytes in
a versioned, checksummed, `zstd`-compressed save envelope, enforces the S001
input-size and decompressed-size caps, and adds an atomic-replace file store.

## Crate(s)

`crpg-persist` (only). This task opens the crate.

## Purpose

D10 and T022 §7 leave production persistence (filesystem, compression,
separate compressed and decompressed caps) to a persist-owned task. T039, a
`crpg-server` adapter, will then put T022's checkpoint bytes on disk and turn
on gate 10. D27b approved `zstd` for this crate, on condition that both S001
caps hold, with the decompressed cap enforced *while* decompressing.

## 1. Payload decision: opaque bytes, no typed helpers

The envelope carries **opaque caller bytes**. `crpg-persist` does not encode,
decode or inspect a `World`, `HistoryWorld` or checkpoint, and T038 adds **no
workspace path dependency** (no `crpg-core`, `crpg-data` or `crpg-sim` edge),
although `ALLOWED` would permit them.

Why:

1. **T022 §7 owns the unit of save.** Gate-10 continuation needs the whole
   host checkpoint: the `HistoryWorld` wrapper plus the capture journal, its
   watermark, the incarnation and the protocol selection. That is compact JSON
   built in `crpg-server`. Persist cannot import server or net (T022 §8), so
   it cannot build that unit. It can only carry it.
2. **A typed `World`/`HistoryWorld` helper would be a bypass.** T022 says a
   `World`-only round trip is not evidence of continuation. A helper that saves
   only the sim wrapper would invite exactly that use, and would skip the
   capture journal.
3. **E014 and the sim serializers already exist.** `World` serde is the
   skeleton plus symbolic string conversions (ADR-0006 D4). `HistoryWorld` has
   its own strict JSON with streaming bounded visitors, and the *host* applies
   the mandatory pre-parse byte cap. A second encoding here would copy those
   rules and could drift from them.
4. **Payload-neutral is the smallest stable surface.** The envelope adds
   integrity, versioning, compression and caps. What it carries is the
   caller's contract.

Spec §8 says "serialized with `postcard`". T038 deliberately does not do this.
The payload encoding belongs to the caller, and T022 chose compact JSON.
§12 Q7 records this deviation from the spec.

### 2.1 `envelope`

```rust
/// Envelope magic, offsets 0..8: ASCII "CRPGSAVE".
pub const SAVE_MAGIC: [u8; 8] = *b"CRPGSAVE";
/// The only format version this build writes or reads.
pub const SAVE_FORMAT_VERSION: u16 = 1;
/// Fixed v1 header length in bytes (see §3).
pub const HEADER_BYTES: usize = 68;
/// Flag bit 0: the body is one zstd frame. Clear: the body is the raw payload.
pub const FLAG_ZSTD: u16 = 0x0001;
/// Decompressed-size ceiling: 16 MiB (16 * 1024 * 1024 bytes) of payload.
/// Equal to T022's `MAX_CHECKPOINT_BYTES`, so every checkpoint the host accepts fits.
pub const MAX_PAYLOAD_BYTES: usize = 16_777_216;
/// Input-size ceiling: header plus the largest body (bytes). 16_777_284.
pub const MAX_ENVELOPE_BYTES: usize = HEADER_BYTES + MAX_PAYLOAD_BYTES;
/// zstd compression level used by the encoder.
pub const ZSTD_LEVEL: i32 = 3;
/// Decoder window ceiling, as log2 bytes: 2^24 = 16 MiB.
pub const ZSTD_WINDOW_LOG_MAX: u32 = 24;
/// BLAKE3 derive-key context for the envelope digest (hard-coded, never derived).
pub const DIGEST_CONTEXT: &str = "crpg-persist 2026-10-04 save envelope v1";

/// Caller-chosen 8-byte payload tag; bytes restricted to `A-Z`, `0-9`, `_`.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct PayloadKind([u8; 8]);

impl PayloadKind {
    /// `Some` iff every byte is in `b'A'..=b'Z'`, `b'0'..=b'9'` or `b'_'`.
    pub const fn new(tag: [u8; 8]) -> Option<Self>;
    /// The tag bytes, as written at header offsets 12..20.
    pub const fn as_bytes(&self) -> &[u8; 8];
}

/// Encode `payload` as a v1 envelope. Pure; deterministic per build (§5).
pub fn encode_envelope(kind: PayloadKind, payload: &[u8]) -> Result<Vec<u8>, EnvelopeError>;

/// Validate a v1 envelope and return its payload. Pure; first failure wins (§4.2).
pub fn decode_envelope(expected: PayloadKind, bytes: &[u8]) -> Result<Vec<u8>, EnvelopeError>;

/// Every envelope failure, with first-failure-wins precedence (§4.2).
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum EnvelopeError {
    /// Input longer than `MAX_ENVELOPE_BYTES` (checked before anything else).
    InputTooLarge,
    /// Input ends before the frozen prefix, the header, or the declared body.
    Truncated,
    /// Offsets 0..8 differ from `SAVE_MAGIC`.
    BadMagic,
    /// Offsets 8..10 hold a version other than `SAVE_FORMAT_VERSION`.
    UnsupportedVersion,
    /// A flag bit other than `FLAG_ZSTD` is set.
    UnknownFlags,
    /// Header kind differs from the expected `PayloadKind`.
    KindMismatch,
    /// Payload longer than `MAX_PAYLOAD_BYTES` (encode input or declared length).
    PayloadTooLarge,
    /// `body_len` is inconsistent with `payload_len` and the flags (§4.2 step 9).
    LengthMismatch,
    /// Input continues past `HEADER_BYTES + body_len`.
    TrailingBytes,
    /// The BLAKE3 digest does not match the header prefix and body.
    ChecksumMismatch,
    /// The zstd frame produced more bytes than the declared `payload_len`.
    DecompressedTooLarge,
    /// The zstd frame ended before producing `payload_len` bytes.
    DecompressedTooShort,
    /// The zstd frame is invalid, needs a window above `ZSTD_WINDOW_LOG_MAX`,
    /// or is followed by further bytes inside the body.
    CorruptBody,
    /// The zstd compressor failed while encoding (context or allocation failure).
    Compressor,
}
```

`EnvelopeError` implements `std::fmt::Display` by hand, and
`std::error::Error` with no source. Display strings follow the `crpg-net`
convention: lowercase, no trailing punctuation, and they never contain input
bytes.

| Variant | Display |
|---|---|
| `InputTooLarge` | `save input exceeds its byte cap` |
| `Truncated` | `save input is truncated` |
| `BadMagic` | `not a save envelope` |
| `UnsupportedVersion` | `unsupported save format version` |
| `UnknownFlags` | `unknown save envelope flags` |
| `KindMismatch` | `save payload kind mismatch` |
| `PayloadTooLarge` | `save payload exceeds its byte cap` |
| `LengthMismatch` | `save envelope lengths are inconsistent` |
| `TrailingBytes` | `save input has trailing bytes` |
| `ChecksumMismatch` | `save checksum mismatch` |
| `DecompressedTooLarge` | `decompressed save exceeds its declared length` |
| `DecompressedTooShort` | `decompressed save is shorter than its declared length` |
| `CorruptBody` | `compressed save body is corrupt` |
| `Compressor` | `save compressor failed` |

Private implementation constant (pinned, not public):
`const DECODE_CHUNK_BYTES: usize = 65_536;`

### 2.2 `file`

```rust
/// Suffix appended to the destination file name to form the temporary file.
pub const TEMP_SUFFIX: &str = ".crpg-tmp";

/// Encode `payload` and atomically replace `path` with the envelope (§6.1).
pub fn save_file(path: &std::path::Path, kind: PayloadKind, payload: &[u8]) -> Result<(), FileError>;

/// Read at most `MAX_ENVELOPE_BYTES + 1` bytes from `path` and decode them (§6.2).
pub fn load_file(path: &std::path::Path, expected: PayloadKind) -> Result<Vec<u8>, FileError>;

/// Read at most `MAX_ENVELOPE_BYTES + 1` bytes from `reader`. Longer input is
/// `Envelope(InputTooLarge)`. The reader is never read past that bound.
pub fn read_capped<R: std::io::Read>(reader: R) -> Result<Vec<u8>, FileError>;

/// Filesystem step that failed.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum FileOp { CreateTemp, WriteTemp, SyncTemp, Rename, SyncDir, Open, Read }

/// Every file-store failure.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum FileError {
    /// Envelope encode or decode failure, including the input-size cap.
    Envelope(EnvelopeError),
    /// The path has no final file-name component (for example `""` or `".."`).
    InvalidPath,
    /// An I/O step failed; `kind` is the OS error's `std::io::ErrorKind`.
    Io { op: FileOp, kind: std::io::ErrorKind },
}

impl From<EnvelopeError> for FileError { /* FileError::Envelope(e) */ }
```

`FileOp` Display: `create-temp`, `write-temp`, `sync-temp`, `rename`,
`sync-dir`, `open`, `read`. `FileError` Display:

- `Envelope(e)` prints `e`'s Display unchanged.
- `InvalidPath` prints `save path has no file name`.
- `Io { op, kind }` prints `save {op} failed: {kind}`, using `io::ErrorKind`'s
  own Display.

`FileError` implements `std::error::Error` with no source, so the inner text
is not printed twice.

No other public item. In particular: no trait, no header struct, no
inspection API, no streaming writer, no configurable level or caps.

## 3. Envelope v1 byte layout (normative)

All integers are fixed-width little-endian. There is no padding and there are
no optional fields.

| Offset | Size | Field | Encoding | Rule |
|---|---|---|---|---|
| 0 | 8 | `magic` | bytes | `43 52 50 47 53 41 56 45` (`CRPGSAVE`) |
| 8 | 2 | `format_version` | u16 LE | `01 00` |
| 10 | 2 | `flags` | u16 LE | bit 0 = `FLAG_ZSTD`; bits 1–15 must be 0 |
| 12 | 8 | `kind` | bytes | `PayloadKind` alphabet |
| 20 | 8 | `payload_len` | u64 LE | uncompressed payload length, `<= MAX_PAYLOAD_BYTES` |
| 28 | 8 | `body_len` | u64 LE | stored body length |
| 36 | 32 | `digest` | bytes | BLAKE3 `derive_key(DIGEST_CONTEXT)` over `bytes[0..36] ‖ body` |
| 68 | `body_len` | `body` | bytes | raw payload (flags 0) or exactly one zstd frame (flags 1) |

**Frozen prefix.** Offsets 0..10 (magic and version) keep this meaning in
every future version. That lets any build refuse a foreign version without
knowing its layout. Everything from offset 10 onward belongs to version 1.

**Digest.** Use `blake3::Hasher::new_derive_key(DIGEST_CONTEXT)`, then
`update(&bytes[0..36])`, then `update(body)`, then take the 32 bytes of
`finalize()`. The digest covers every header field except itself, plus the
*stored* body, so corruption is caught before any byte reaches zstd. This is
an integrity check, not authentication. Anyone who can write the file can
re-sign it. The decompression caps are therefore the safety boundary, not the
digest. Domain separation keeps it distinct from `state_hash` and
`history_hash`, which are plain BLAKE3 over other bytes.

## 4. Behaviour

### 4.1 `encode_envelope` (exact algorithm; canonical output)

1. If `payload.len() > MAX_PAYLOAD_BYTES`, return `PayloadTooLarge`.
2. Create a **fresh** `zstd::bulk::Compressor::new(ZSTD_LEVEL)` and set:
   - `include_checksum(false)`: the BLAKE3 digest covers integrity;
   - `include_dictid(false)`;
   - `include_contentsize(true)`.

   Then call `compress(payload)`. Leave every other parameter at its default:
   no dictionary, no long-distance matching, no window override, no workers
   (the `zstdmt` feature is never enabled). Any zstd error returns
   `Compressor`.
3. If `compressed.len() < payload.len()`, set `flags = FLAG_ZSTD` and
   `body = compressed`. Otherwise set `flags = 0` and `body = payload`. So an
   empty or incompressible payload is stored raw, and **an envelope is never
   longer than `HEADER_BYTES + payload.len()`**. The smallest zstd frame is 9
   bytes, so payloads of 9 bytes or fewer are always raw. The scratch audit
   measured 12 bytes for `abc`.
4. Write the header fields in §3 order, compute the digest, and append the
   body. Allocate the output once with capacity exactly
   `HEADER_BYTES + body.len()`.

**Canonical rules.** For a fixed build, the output is a pure function of
`(kind, payload)`. The build fixes the linked zstd library (1.5.7, checked by
a test), `ZSTD_LEVEL` and the parameters above. The function reads no clock,
environment, randomness, thread count or global state. A zstd context is never
reused across calls.

### 4.2 `decode_envelope` (exact precedence; first failure wins)

1. If `bytes.len() > MAX_ENVELOPE_BYTES`, return `InputTooLarge`. Nothing else is read.
2. If `bytes.len() < 10`, return `Truncated`.
3. If `bytes[0..8] != SAVE_MAGIC`, return `BadMagic`.
4. If `u16::from_le_bytes(bytes[8..10]) != SAVE_FORMAT_VERSION`, return
   `UnsupportedVersion`. This is checked before the header length, flags,
   lengths or digest, so a version-2 file of any length is refused as a
   version mismatch.
5. If `bytes.len() < HEADER_BYTES`, return `Truncated`.
6. If `flags & !FLAG_ZSTD != 0`, return `UnknownFlags`.
7. If `bytes[12..20] != expected.as_bytes()`, return `KindMismatch`. This
   includes header bytes outside the alphabet.
8. If `payload_len > MAX_PAYLOAD_BYTES`, return `PayloadTooLarge`. Compare as
   `u64` with no truncating cast.
9. Check the lengths against the flags; on failure return `LengthMismatch`:
   - flags 0 requires `body_len == payload_len`;
   - `FLAG_ZSTD` requires `1 <= body_len < payload_len`.

   These are exactly the encoder's invariants. Together they imply
   `body_len <= MAX_PAYLOAD_BYTES`.
10. If `bytes.len() < HEADER_BYTES + body_len`, return `Truncated`. If it is
    `>`, return `TrailingBytes`.
11. If the recomputed digest differs from offsets 36..68, return
    `ChecksumMismatch`. Comparing with `==` on `[u8; 32]` is sufficient
    because the digest is not a secret.
12. For flags 0, return `body.to_vec()`. For `FLAG_ZSTD`, run §4.3.

### 4.3 Streaming bounded decompression (S001 bomb defence)

The decompressed-size ceiling is the declared `payload_len`, which step 8
already capped at `MAX_PAYLOAD_BYTES`. It is enforced **during** decompression:

1. Build `zstd::stream::read::Decoder::with_buffer(body)`. `&[u8]` is
   `BufRead`, so there is no second input copy. Call `.single_frame()`, then
   `window_log_max(ZSTD_WINDOW_LOG_MAX)`. A frame that needs a larger window
   fails inside zstd before its window is allocated. Map any setup error to
   `CorruptBody`.
2. Create an empty `Vec<u8>` for the output. **Never** call `with_capacity`
   with `payload_len` or with the frame's content-size field, so a 68-byte
   header cannot reserve 16 MiB. Use one scratch buffer of
   `DECODE_CHUNK_BYTES`.
3. Loop on `decoder.read(&mut chunk)`, retrying `ErrorKind::Interrupted`:
   - any other error returns `CorruptBody`;
   - `Ok(0)` ends the loop;
   - for `Ok(n)`: if `out.len() + n > payload_len`, return
     `DecompressedTooLarge` immediately, before appending. Otherwise append.

   Output memory therefore never exceeds `payload_len`. Total decoder work is
   at most `payload_len + DECODE_CHUNK_BYTES` produced bytes, whatever the
   frame claims.
4. At end of frame, if `out.len() < payload_len`, return `DecompressedTooShort`.
   A lone skippable frame lands here.
5. Call `decoder.finish()` to get the body slice back. If any byte remains (a
   second frame, a skippable frame or garbage after the first frame), return
   `CorruptBody`.
6. Return `out`.

Peak decode memory: the caller's input (at most `MAX_ENVELOPE_BYTES`), plus
output (at most `payload_len`), plus the zstd window (at most 2^24 bytes),
plus one 64 KiB chunk, plus the zstd decoder context. No allocation is sized
from an untrusted field. Legacy zstd formats (v0.1–v0.7) are not compiled in,
because default features are off (§9).

### 4.4 Behaviour on every error

| Error | Raised by | State after |
|---|---|---|
| `InputTooLarge` | decode step 1; `read_capped`/`load_file` after reading cap+1 bytes | no output; nothing beyond cap+1 bytes read; file untouched |
| `Truncated`, `BadMagic`, `UnsupportedVersion`, `UnknownFlags`, `KindMismatch`, `PayloadTooLarge` (decode), `LengthMismatch`, `TrailingBytes`, `ChecksumMismatch` | decode steps 2–11 | no output; zstd never invoked |
| `PayloadTooLarge` (encode) | encode step 1; `save_file` before touching the filesystem | no output; no file created, removed or changed |
| `DecompressedTooLarge`, `DecompressedTooShort`, `CorruptBody` | decode §4.3 | partial output dropped; nothing returned |
| `Compressor` | encode step 2 (not reachable by test; documented) | no output; `save_file` touches no file |
| `InvalidPath` | `save_file` step 1 | nothing created |
| `Io { CreateTemp }` | `save_file` step 3 | destination untouched; no temp file was created |
| `Io { WriteTemp \| SyncTemp \| Rename }` | `save_file` steps 4–6 | destination untouched; temp removed (best effort; removal error ignored) |
| `Io { SyncDir }` (Unix only) | `save_file` step 7 | **new save is already in place**; its directory entry's durability is unconfirmed |
| `Io { Open \| Read }` | `load_file` | nothing written or removed |

No API retries, sleeps or falls back to another path. Every function either
returns the full result or returns an error with no partial result.

## 5. Determinism requirements

- **Byte determinism is exact-build, per target** (ADR-0012). Two calls to
  `encode_envelope` with equal inputs in the same build give identical bytes,
  and so does `encode(decode(encode(x)))`. No claim is made that Windows/MSVC
  and Linux/GNU produce equal compressed bytes, and no test compares them.
- **No per-target goldens.** T038 adds no generated golden, so there is no
  H-golden gate. The one literal test vector (§8, `raw_envelope_matches_hand_built_layout`)
  is a raw (uncompressed) envelope. Its bytes follow from §3 and BLAKE3 alone,
  not from zstd output, so it is a format test vector. It is identical on every
  target by construction, and both targets assert it.
- **The linked zstd must be the bundled 1.5.7.** If the environment sets
  `ZSTD_SYS_USE_PKG_CONFIG`, or the `pkg-config` feature is on, `zstd-sys`
  links a system `libzstd` instead, and compressed bytes can change.
  `zstd_safe::version_number() == 10507` is asserted by a test. CI and
  preflight must not set that variable.
- `crpg-persist` source and tests contain no `HashMap`/`HashSet`,
  `SystemTime`/`Instant`/`std::time`, `std::thread`, `rand::`/`thread_rng`,
  `std::env::var`, `f32` or `f64`. `determinism.py` does not scan this crate
  (its `CRATES` list is core/rules/sim), so the Definition of done carries an
  explicit grep. Test fixtures use the compile-time `env!("CARGO_TARGET_TMPDIR")`,
  not a runtime environment read. Pseudo-random test bytes come from the fixed
  xorshift in §8, not from an RNG crate.

## 6. File store

### 6.1 `save_file` (exact steps)

1. If `path.file_name()` is `None`, return `InvalidPath`.
2. Call `encode_envelope(kind, payload)`. On error return `Envelope(e)`; the
   filesystem has not been touched.
3. The temp path is `path.parent()` (an empty parent means `.`) joined with
   the destination file name plus `TEMP_SUFFIX`. Build it with `OsString`
   push, so the name need not be UTF-8. Open it with
   `OpenOptions::new().write(true).create(true).truncate(true)`. A stale temp
   file from an earlier crash is overwritten. On error return
   `Io{CreateTemp}`.
4. `write_all(&envelope)`; on error return `Io{WriteTemp}`.
5. `sync_all()`, then drop the handle; on error return `Io{SyncTemp}`.
6. `std::fs::rename(&temp, path)` atomically replaces the destination on the
   same volume. On Linux this is POSIX `rename`. On Windows std's rename
   replaces an existing file. On error return `Io{Rename}`.
7. `#[cfg(unix)]` only: open the parent directory with `File::open` and call
   `sync_all()`; on error return `Io{SyncDir}`. On Windows there is no
   directory sync, because std cannot open one for flushing. That residual is
   documented, not worked around. The cfg is a compile-time selection in a
   crate above sim, which root `AGENTS.md` permits for filesystem logic.

Guarantee claimed: **atomic replace** on both targets. A later `load_file` sees
either the previous complete save or the new complete save, never a mix. The
new contents are fsync'd on both targets, and the directory entry is fsync'd
on Unix. **Not claimed:** crash-durable exactly-once on Windows, write-ahead
logging, rolling slots or "never overwrite the only save". Those are T039/host
policy (spec §8, D10). Each path has a single writer, and that is the caller's
obligation: two concurrent `save_file` calls to one path share a temp name.

### 6.2 `load_file` and `read_capped`

`load_file` does three things, in order:

1. `File::open(path)`; on error return `Io{Open}`.
2. `read_capped(file)`.
3. `decode_envelope(expected, &bytes)`, mapping errors with `From`.

It never writes, renames or deletes, and it ignores any temp file.

`read_capped` calls `reader.take(MAX_ENVELOPE_BYTES as u64 + 1).read_to_end(&mut buf)`.
`read_to_end` already retries `Interrupted`. Any other error returns
`Io{Read}`. If `buf.len() > MAX_ENVELOPE_BYTES`, the result is
`Envelope(InputTooLarge)`. File metadata length is never trusted or consulted.

## 8. Test

Three new integration suites. Every rejection has a valid positive control.
Hostile envelopes are built with test-local helpers, never with crate-private
code:

- `build(flags, kind, payload_len, body)` assembles the header literally;
- `resign(&mut bytes)` recomputes the digest using the **literal** context
  string in the test file, not the crate constant, so the oracle is
  independent.

Pseudo-random bytes come from xorshift64: state `s = 0x2545_F491_4F6C_DD1D`;
each byte does `s ^= s << 13; s ^= s >> 7; s ^= s << 17` and emits
`(s >> 24) as u8`. The compressible pattern is byte
`(i % 251) as u8 ^ (i >> 16) as u8` for index `i`.

### `tests/envelope.rs`

- `raw_envelope_matches_hand_built_layout`: the full literal oracle for
  `encode_envelope(TESTKIND, b"abc")` (71 bytes), written in hex:

  ```text
  4352504753415645 0100 0000 544553544b494e44 0300000000000000 0300000000000000
  6cc46ec6f5dd5d790128e477e33004b396f0574fa33cff5796050dc0b3bb3f47 616263
  ```

  The test also recomputes the digest with `blake3` and asserts it equals the
  literal. `decode_envelope` returns `abc`.
- `empty_payload_round_trips_raw`: 68 bytes, flags 0, both lengths 0, and the
  digest equals the literal
  `39afd20fc7950456a211ba0d3a16c9726a20baa99501da8e660ab469719745ea`.
- `compressible_payload_uses_zstd`: an 800,000-byte pattern. Check flags
  `FLAG_ZSTD`, `body_len < payload_len`, `payload_len == 800_000`, body bytes
  0..4 equal the zstd magic `28 b5 2f fd`, and the round trip is exact.
- `incompressible_payload_stored_raw`: 1 MiB of xorshift bytes gives flags 0
  and a body equal to the payload.
- `payload_cap_boundaries`: a `MAX_PAYLOAD_BYTES` pattern round-trips through
  zstd. `MAX_PAYLOAD_BYTES` xorshift bytes produce an envelope of exactly
  `MAX_ENVELOPE_BYTES`, which decodes, so the input-cap boundary is accepted.
  A payload of `MAX_PAYLOAD_BYTES + 1` gives `PayloadTooLarge`.
- `encode_is_deterministic`: for the empty, `abc`, 800 KB pattern and 1 MiB
  xorshift payloads, two encodes are equal, and so is the
  encode → decode → encode fixed point.
- `linked_zstd_is_bundled_1_5_7`: `zstd::zstd_safe::version_number() == 10507`.
- `payload_kind_alphabet`: `HOSTCKPT`, `A_9_____` and `ZZZZZZZZ` are accepted.
  Inputs with one byte of each of `a`, ` `, `0x00`, `0x7f`, `0x80`, `-` are
  rejected. `as_bytes` returns the tag.

### `tests/rejections.rs`

- `input_cap_is_checked_first`: `MAX_ENVELOPE_BYTES + 1` zero bytes (bad magic
  too) give `InputTooLarge`. The positive control is the max-size envelope
  from `payload_cap_boundaries`, rebuilt here.
- `every_prefix_is_truncated`: every strict prefix (length 0 up to len−1) of a
  valid zstd envelope (4096 pattern bytes) and of the raw `abc` envelope gives
  `Truncated`.
- `bad_magic_each_byte`: XOR each of bytes 0..8 with `0x01` → `BadMagic`.
  Separately, 9 bytes of garbage give `Truncated` (step 2 precedes step 3).
- `cross_version_refused_before_layout`: versions 0, 2, 0x0100 and
  `u16::MAX`, each tested both as a bare 10-byte prefix and on a full
  re-signed envelope → `UnsupportedVersion`. The version-2 full case also
  carries unknown flags and a wrong kind, which proves the version wins.
- `unknown_flag_bits`: each bit 1..15 alone, re-signed → `UnknownFlags`.
- `kind_mismatch`: decode with `OTHERKND` gives `KindMismatch`. A header kind
  of `abcdefgh` (outside the alphabet), re-signed, also gives `KindMismatch`.
- `declared_payload_over_cap`: `payload_len` of `MAX_PAYLOAD_BYTES + 1` and
  of `u64::MAX` → `PayloadTooLarge`.
- `inconsistent_lengths`:
  - raw envelopes with `body_len = payload_len ± 1`;
  - zstd envelopes with `body_len` of 0, `== payload_len`, and `> payload_len`.

  Each gives `LengthMismatch`.
- `declared_body_vs_input`: one appended byte gives `TrailingBytes`. Dropping
  the last byte (header unchanged) gives `Truncated`.
- `digest_covers_header_and_body`: on the raw `abc` envelope and on a zstd
  envelope, XOR with `0x01` each digest byte (offsets 36..68) and each body
  byte → `ChecksumMismatch`. Then XOR each `kind` byte with `0x01` and decode
  with the correspondingly flipped expected kind → `ChecksumMismatch`. Every
  `TESTKIND` byte stays inside the alphabet under XOR `0x01`, so this proves
  the digest covers the header and not only the body.
- `corrupt_frame_with_valid_digest`, each case re-signed:
  - middle frame bytes overwritten → `CorruptBody`;
  - a second frame appended inside the body (lengths adjusted) → `CorruptBody`;
  - one trailing byte after the frame inside the body → `CorruptBody`;
  - a frame streamed with `CParameter::WindowLog(27)`, content size off,
    over 2 MiB of the compressible pattern, declared as 2 MiB →
    `CorruptBody`. The scratch audit measured a 3454-byte body, so the
    length check passes and the window cap is what fires. The paired control
    is the same pattern streamed with the default window, which decodes.
- `short_frames`: a frame of 1000 pattern bytes declared as 1001 →
  `DecompressedTooShort`. A lone skippable frame
  `50 2a 4d 18 00 00 00 00` declared as 16 → `DecompressedTooShort`.
- `decompression_bomb_stops_at_declared_length`: stream 256 MiB of zeros
  (`io::repeat(0).take(..)` through `zstd::stream::write::Encoder` at level 3;
  about 8 KiB compressed) into an envelope declaring `MAX_PAYLOAD_BYTES`,
  re-signed → `DecompressedTooLarge`. Boundary pair: a 1024-byte frame
  declared as 1024 decodes; a 1025-byte frame declared as 1024 →
  `DecompressedTooLarge`.
- `decode_is_pure`: each rejection above, decoded twice, returns the same error.
- `error_display_strings_are_pinned`: every `EnvelopeError` and `FileOp`
  Display string equals §2. `FileError::InvalidPath` is exact. `FileError::Io`
  for `Open` starts with `save open failed: `. `FileError::Envelope(e)`
  equals `e.to_string()`.

### `tests/file_store.rs`

- `save_then_load_round_trips`: the payload is equal after the round trip, and
  no `TEMP_SUFFIX` file remains.
- `file_bytes_equal_encoded_envelope`: `std::fs::read(path)` equals
  `encode_envelope(kind, payload)`.
- `save_replaces_existing_file`: save A, then save B; load returns B; no temp
  file.
- `failed_encode_leaves_previous_save`: save A, then save a payload of
  `MAX_PAYLOAD_BYTES + 1` → `Envelope(PayloadTooLarge)`. The file is still
  A's bytes, and no temp file exists.
- `failed_rename_keeps_destination_and_removes_temp`: make the destination an
  existing directory → `Io { op: Rename, .. }`. Assert the op only, because
  the `ErrorKind` differs by OS. The directory still exists and the temp file
  is gone.
- `missing_parent_directory`: `Io { op: CreateTemp, kind: NotFound }`.
- `stale_temp_file_is_replaced`: create a junk temp file first; save succeeds,
  load returns the payload, and the temp file is gone.
- `invalid_paths_refused`: `""` and `".."` → `InvalidPath`; nothing is created
  in the test directory.
- `load_missing_file`: `Io { op: Open, kind: NotFound }`.
- `read_capped_bounds_input`:
  - `io::repeat(0x43)` with no `take` (an endless reader) →
    `Envelope(InputTooLarge)`, and the test terminates;
  - exactly `MAX_ENVELOPE_BYTES` bytes → `Ok` with that length;
  - a `MAX_ENVELOPE_BYTES + 1` file on disk read through `load_file` →
    `Envelope(InputTooLarge)`.
- `load_reports_envelope_errors_and_leaves_file`: save, flip one digest byte
  on disk, then load → `Envelope(ChecksumMismatch)`; the file bytes are
  unchanged by the load.

## 12. Open questions for the user

1. **Approve `zstd =0.14.0` and its tree (§9)?**
   *Recommendation:* approve 0.14.0 with default features off. It is D27b's
   "current stable", all its licences are inside the allow list, and
   `cargo deny check` is clean with `deny.toml` unchanged. Note that it is one
   month old, and that the whole zstd line moved from MIT to BSD-3-Clause at
   this release. If you prefer the longer-lived 0.13.3 (MIT, same zstd 1.5.7
   C), say so; only §9 and the pin change.
2. **Accept new third-party build-time C compilation?** `zstd-sys`'s build
   script compiles C, and on Linux x86_64 also assembly. S001's ban covers
   workspace build scripts only, so `deps.py` passes, but this is new
   arbitrary build-time execution in the sense S001 worries about.
   *Recommendation:* accept, under the same reasoning as `blake3` (pinned
   crates.io source, lock checksums, no network or pkg-config use). Make no
   `deps.py` change.
3. **`deny.toml` comment drift.** No policy change is needed. However, the
   skip-list comment describes `getrandom@0.4.3` as dev-only (via proptest),
   and after T038 it is also reached at build time on Windows hosts
   (`cc → jobserver → getrandom`).
   *Recommendation:* leave `deny.toml` untouched in T038 (it is a serialized
   file and the policy is unchanged). Record the fact in the completion
   record, and correct the comment in a later serialized bookkeeping change.
   Do not let T038 edit it.
4. **Caps.**
   *Recommendation:* the payload cap of 16 MiB (equal to T022's
   `MAX_CHECKPOINT_BYTES`), the input cap of 16 MiB + 68 B and a decoder
   window of 2^24. Raising any of them later is a deliberate change, because
   a build with a smaller cap refuses larger saves.
5. **Spec §8 save metadata** (engine version, campaign id and version, schema
   version). The envelope carries format version and a `PayloadKind` tag
   only.
   *Recommendation:* identity stays inside the caller's payload. T039's
   contract decides what the host checkpoint records (T022's checkpoint
   already carries its own `version`), and the envelope stays engine-neutral.
6. **No `PersistenceBackend` trait yet.**
   *Recommendation:* defer it until a second backend exists. A trait in
   `crpg-contracts` is a human-owned change and a separate task; one
   implementation does not justify it.
7. **Spec §8 says `postcard`.**
   *Recommendation:* accept the deviation (§1) and record it in
   `docs/architecture/crpg-persist.md`. A later documentation task can append
   a dated note to spec §8. T038 does not edit the spec.
8. **Determinism-lint coverage.** `determinism.py` scans core, rules and sim
   only.
   *Recommendation:* T038 relies on its explicit DoD grep. Extending the
   lint's `CRATES` to `crpg-persist` (or to all crates under the simulation
   stack) is a separate tooling task under the S001 guard.
9. **Windows durability residual.** Atomic replace holds on both targets, but
   the directory entry is fsync'd on Unix only.
   *Recommendation:* accept and document it. T039 and gate 10 claim
   save/load equivalence, not crash durability (D10 already disclaims
   WAL/exactly-once).
10. **Compression level 3.**
    *Recommendation:* keep zstd's default level. Checkpoints are written
    synchronously at quiescence, so speed matters more than ratio. Changing
    the level later changes bytes but not the format.
11. **Literal format test vector.** §8 pins two BLAKE3 digests of raw
    envelopes, asserted identically on both targets.
    *Recommendation:* treat them as specification vectors, not goldens. They
    involve no zstd output and are platform-independent by construction, so
    ADR-0012's per-target golden rule does not apply. If you disagree, the
    tests can instead assert only the independently recomputed digest.
12. **BSD-3-Clause attribution.** Binary distributions must reproduce the
    zstd copyright notice.
    *Recommendation:* no T038 action. Add it to the H-release third-party
    notices checklist (Phase 10/12).
