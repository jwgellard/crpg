# T016e — Combat invariant repair (`crpg-sim`)

## Status and purpose

**Specified; implementation and verification pending.** Work package A1 of
the [project gap remediation plan](../docs/reviews/REMEDIATION_PLAN_2026-09-27.md)
(§4, gap G1). Repairs the combat lifecycle/save invariants inside `crpg-sim`
only: invalid saves fail at load before any runtime state is published, and
every valid lifecycle transition (including despawn of any participant class)
leaves a world that reloads through the same implementation.

This file is the implementation contract. It does not claim source changes
or native gates have run.

## Baseline recheck (against actual source, 2026-09-27)

Base `76a48da` plus the uncommitted T016a–d working tree (the plan's reviewed
base). A temporary diagnostic probe (`tests/probe_a1_tmp.rs`, created, run,
deleted; never committed) reproduced all four finding classes on Windows/MSVC,

- Save with the issuing interner stripped (`interners.tags = []`) **loads**,
  and the next `perform_action` **panics** (`the roll tag is interned at
  encounter start`, `combat.rs:729`).
- Save with `combat.definition.attribute` rewritten to an undeclared name
  **loads**, and the next `perform_action` **panics** (`the ability attribute

  (contradictory zero-health/alive state accepted).
- Despawning every combatant serializes to bytes the same implementation
  rejects (`encounter state with an empty combatant store`).

Existing `combat_persistence` (3 tests) passes; it does not cover these cases.
No finding has been fixed since the plan was written. The regressions below
are checked-in permanent coverage, not the deleted probe.

## Decisions (binding for this contract)

1. **No public API change.** All new rejection happens at load with
   `serde::de::Error::custom` strings, the same channel as the existing
   dangling/empty-store guards. `CombatError` gains no variant and no
   function signature changes. Anything that would need a new runtime error
   (notably proactive start-time rejection of a non-empty timeline) is
   recorded as an A2 ADR item, not smuggled in here.
2. **One coherent load invariant** (extends the module doc's "Loading is
   validated" list; check order below is fixed: existing dangling checks,
   then existing empty-store/active-dangling checks, then the new combat
   coherence checks in §Validation order). A save that fails any check never
   publishes a `World`.
3. **Legal combatant state is exact:** `max_health >= 1`,
   `health <= max_health`, and `dead == (health == 0)`. Zero health is dead;
   positive health is alive. There is no wounded-but-dead or zero-but-alive
   state. This pins the plan's "legal zero-health and terminal-state
   semantics": the dead keep entity plus zero-health state and leave
   scheduling; nothing else holds zero health.
4. **Definition/pool/attribute coherence is load-checked** (sites the
   controller currently `expect`s on): the roll tag is interned; the checked
   attribute is declared; costs fit the pool; every combatant's pool identity,
   maximum, and refresh equal the definition template; every combatant's
   attribute names equal the declared list in authored order; placements are
   unique.
5. **Scheduling coherence is load-checked:** with `combat = Some`, every
   timeline entry addresses a live non-dead combatant (this is the treatment
   of preexisting noncombat timeline entries: they are not silently assumed
   away — a mixed scheduling makes the save unloadable); `active = Some`
   additionally names the timeline head. `active = None` is always loadable
   (terminal or post-despawn stranded; recovery semantics belong to A2).
6. **Despawn of the last combatant releases the encounter** (`combat = None`,
   interners/events/RNG/tick retained). This is the minimal change that makes
   "despawn every combatant" reloadable without clearing unrelated world
   state and without a new operation. Despawning a non-last active combatant
   keeps the existing turn-clear behavior. Death retention (keeping results
   past release) is explicitly A2, not this task: release-by-despawn discards
   by existing despawn semantics.
7. **`start_encounter` keeps its signature and caller contract**, documented
   as requiring an empty timeline (fresh world in every production path and
   test). A non-empty timeline at start is caller misuse that now fails fast
   at the next save/load via decision 5 instead of deadlocking or panicking
   later; the proactive start-time error awaits A2's reviewed API decision.

  check 4 plus `start_encounter` validation guarantee every combatant carries
  the declared names in order.
- `combat.rs:729` (roll tag interned) — unreachable: load check 1 plus
  `start_encounter` interning guarantee presence.
- `combat.rs:636/638/859/888` (scheduled entities are combatants) —

  are combatants; `start_encounter` publishes that shape.
- `combat.rs:774/789` (resolution success, affordability) — unchanged reasoning
  (preflight + validated definition); load checks preserve the definition the
  preflight ran against.
- `combat.rs:389` (nonzero tick period), `combat.rs:531/580/613`
  (adapter-supplied abilities/template) — caller-contract asserts on the

preconditions actually hold for every `World` any caller can load or build.

## Validation (new checks, in fixed order, inside the existing `Some` arm)

After the existing empty-store and active-dangling checks:

1. Roll tag: `interners.tag(COMBAT_ROLL_TAG).is_none()` →
   `"combat encounter without its interned roll tag"`. (Import the constant
   from `crate::combat`; never a second literal.)
2. Definition coherence (all against `state.definition`):
   - `attribute` names `definition.attribute` in `attribute_names`, else
     `"combat definition names an undeclared checked attribute"`.
   - `attribute_names` nonempty and unique, else
     `"combat definition declares no attributes"` /
     `"combat definition declares a duplicate attribute"`.
   - `health_stat` nonempty and absent from `attribute_names`, else
     `"combat definition misdeclares its health stat"`.
   - `cost == 0 || cost > pool_max` (hence `pool_max == 0` with any legal
     cost) → `"combat definition cost exceeds its pool maximum"`.
3. Per combatant (via public getters; `ResourcePool::{id,max,refresh_trigger}`
   against the definition template):
   - `max_health == 0` → `"combatant with a nonpositive maximum"`.
   - `health > max_health` → `"combatant health exceeds its maximum"`.
   - `dead != (health == 0)` → `"combatant health disagrees with its dead flag"`.
   - `action_pool.id().0 != definition.pool_id` →
     `"combatant pool identity disagrees with its definition"`.
   - `action_pool.max() != definition.pool_max` →
     `"combatant pool maximum disagrees with its definition"`.
   - `action_pool.refresh_trigger() != definition.pool_refresh` →
     `"combatant pool refresh disagrees with its definition"`.
   - Attribute names (ordered) != `definition.attribute_names` →
     `"combatant attributes disagree with their definition"`.
4. Placements unique across combatants, else
   `"combatants share a placement identity"`.
5. Timeline: every entry addresses a combatant with `dead == false`, else
   `"combat timeline schedules a non-combatant"` (covers outsiders, the dead,
   and — with the pre-existing global liveness check — the non-live).
6. Active: `Some(a)` must address a combatant with `dead == false`, must be
   present in the timeline, and must equal the timeline head, else
   `"combat active turn is not the scheduled head"`. (`None` is always
   accepted.)

`ResourcePool` bounds (`current <= max`, nonzero tick period) and
`DiceExpr`/`OutcomeTable` shape stay owned by their rules constructors on
decode; this task adds no duplicate check for those.

## Despawn change (exact)

In `World::despawn`, after stripping transform/combatant/timeline entries:

```rust
if self.combatants.is_empty() {
    self.combat = None;
} else if self.combat.as_ref().is_some_and(|state| state.active == Some(id)) {
    self.combat.as_mut().expect("active turn is checked above").active = None;
}
```

replacing the current active-only clear. Doc comment records the release
semantic (encounter released, interners/events/RNG/tick retained; death
retention is A2). The existing single-active-despawn test still passes
(non-last path unchanged).

## Tests (`crates/crpg-sim/tests/combat_persistence.rs` only; existing three untouched)

- `corrupt_combat_saves_fail_to_load`: table-driven over a valid
  seed-5 save (plus a terminal save with one death for dead-scheduling
  rows). Each row clones, mutates one JSON site, and asserts
  `serde_json::from_value::<World>` is `Err`. Rows (≥20): empty tag list;
  unknown checked attribute; attribute absent from names; health stat inside
  names; duplicate declared attribute; empty declared attributes; cost zero;
  cost above max; health above max; zero max; zero-health/alive;
  positive-health/dead; pool identity mismatch; pool maximum mismatch; pool
  refresh mismatch; combatant attribute reorder; combatant missing the
  checked attribute; duplicate placements; active naming a dead combatant;
  active naming a live outsider; active absent from the timeline; active not
  the head (swapped timeline keys); timeline scheduling a dead combatant;
  timeline scheduling a live outsider.
- `despawn_transitions_stay_reloadable`: from `start(5)`, despawn the waiting
  combatant → serialize/reload ok (`combat` still `Some`, active still the
  head); despawn the active combatant → reload ok (`combat` `Some`,
  `active` `None`); despawn the last combatant → reload ok with
  `combat == None` and empty combatants; then `start_encounter` again in the
  same world succeeds (round 0, two combatants, active head) and one action
  plays — reentry through existing operations, no new API.
- `terminal_despawns_stay_reloadable`: killing-blow terminal save reloads;
  despawn the corpse → reload ok (one alive combatant, `combat` `Some`,
  `active` `None`, empty timeline); fresh terminal save, despawn the
  survivor instead → reload ok (one dead combatant retained with zero
  health); despawn the remaining one → reload ok with `combat == None`.

Rejected-action byte-identity stays covered by
`tests/combat.rs::rejected_actions_leave_the_world_unchanged` (full
`serde_json::to_vec` snapshots, unchanged RNG streams); cite it, do not
duplicate it.
