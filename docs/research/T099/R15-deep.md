# R15-deep.md — Custom content from module authors (T099, deep pass)

## Recommendations (ranked by expected impact on our asset import/packaging)

1. **Confirmed from pass 1 — Make rig conformance a hard import gate: enforce the `SkeletonProfileHumanoid` rules (T-pose, +Z front, no node Transform, +Y parent→child, +X bends inward) and turn Bone Map warnings into blocking errors.** Why: our single rig and fixed animation slot sets only work if imported clips share Bone Rests; Godot currently only warns, so a broken rig can "import successfully" but fail to share. Evidence: https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/retargeting_3d_skeletons.html — "It does not block the import process, but it warns that animations may not be shared correctly." Strength: vendor doc. Effort: medium.
2. **Confirmed from pass 1 — Reject assets whose skeleton or parent node carries a Transform/Scale and require "Apply Node Transform"/clean glTF at import.** Why: hidden parent scale or orientation corruption survives a good-looking preview and breaks retargeting for every clip that uses it. Evidence: https://github.com/godotengine/godot/issues/63641 — "The problem is very simple and relies on the scale and orientation of the parent of the model being imported being broken." Strength: practitioner report. Effort: small.
3. **Confirmed from pass 1 — Keep `Overwrite Axis` opt-in, previewed and reversible; never make it the default.** Why: it is the key pose-alignment knob, but it rewrites Bone Rest and can destroy externally meaningful rest pose/axis data (fingers, VRM spring constraints). Evidence: https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/retargeting_3d_skeletons.html — "but be aware that this option can produce horrible results if the original Bone Rest set externally is important." Strength: vendor doc. Effort: small.
4. **Confirmed from pass 1 — Impose a hard 16-character maximum on asset IDs/resource names and reject longer names at import.** Why: as in NWN, an over-long name does not merely fail to load; it can crash the runtime, and module authors will not diagnose it. Evidence: https://nwn.wiki/spaces/NWN1/pages/53670235/HAK — "The game fails to load anything that is 17 characters (in fact this can outright crash the game, have fun figuring that one out when it happens!)." Strength: practitioner report. Effort: small.
5. **Confirmed from pass 1 — Run a "Check for Conflicts" validation before packaging and report duplicate IDs, filenames, 2da rows and base-game overrides.** Why: silent overrides produce wrong or missing appearances; authors need the blast radius before shipping. Evidence: https://nwn.wiki/spaces/NWN1/pages/60981970/Introduction+to+Hakpacks — "you can use the Check for Conflicts... button which will list what files are in more than one hakpack and what files override base game content." Strength: practitioner report. Effort: small.
6. **Confirmed from pass 1 — Ship content packs as manifests of content-hashed assets with an explicit control/merge entry for conflicting rows.** Why: NWN's practical lesson is that packs group assets, top-down priority picks winners, and overlapping tabular rows must be merged by hand or one pack's content vanishes. Evidence: https://neverwintervault.org/article/reference/deployment-and-installation-custom-content-nwn2 — "The way resource conflicts between haks are resolved is through the creation of a "master" or "control" hakpak and placing it in the highest priority position." Strength: practitioner report. Effort: medium.
7. **New — Validate portrait specs at import and generate every required variant from one source.** Why: BG3 uses a 152 × 152 portrait atlas and NWN expects size-tagged `po_` sets; mismatched dimensions do not fit the UI. Evidence: https://wiki.bg3.community/Tutorials/Custom_Creatures (text export) — "Tick Custom and set the Icon size to 152 × 152." Strength: practitioner report. Effort: medium.
8. **Confirmed from pass 1 / new texture rule — Validate complete texture map sets per material (base colour + normal + physical/occlusion) and power-of-two dimensions with mipmaps.** Why: NWN needs powers of two; BG3 fails with incomplete physical maps; missing maps are invisible failures. Evidence: https://wiki.bg3.community/Tutorials/Custom_Creatures (text export) — "Every VT needs three maps: `*_BM.DDS` base colour, `*_NM.DDS` normal, `*_PM.DDS` physical." Strength: practitioner report. Effort: small.
9. **New — Make asset validation gate packaging with a non-zero exit status, mirroring glTF validation.** Why: agents and humans need a machine-readable pass/fail before shipping; packaging must not succeed with unresolved asset errors. Evidence: https://github.com/KhronosGroup/glTF-Validator — "Shell return code will be non-zero if at least one error was found." Strength: vendor doc. Effort: medium.

## What the research literature says

- Scacchi, W. (2010) "Computer game mods, modders, modding, and the mod scene," *First Monday* 15(5), https://firstmonday.org/ojs/index.php/fm/article/view/2965: affordances such as customization mechanisms, licenses, tools, team practices and social worlds "serve to organize the actions of the people who develop and share their game mods."
- Aberman, K. et al. (2020) "Skeleton-Aware Networks for Deep Motion Retargeting," arXiv:2005.05732, https://arxiv.org/abs/2005.05732: retargeting works between skeletons "which may have different structure, yet corresponding to homeomorphic graphs."
- Li, Z. (2026) "Motion capture and retargeting for character animation: A Survey," *MMAA* 10(2), https://drpress.org/ojs/index.php/mmaa/article/view/35961: "Traditional geometric retargeting methods are prone to foot sliding, ground penetration, and loss of contact semantics."
- Götz, D. and von Mammen, S. (2023) "Modulith: A Game Engine Made for Modding," FDG, https://api.openalex.org/works/https://doi.org/10.1145/3582437.3582486?select=title,abstract_inverted_index: "A modular game engine facilitates development of game technologies and contents. The latter includes content creation by the player in form of modding."
- Mizerski, D. et al. (2020) "To Mod or Not to Mod—An Empirical Study on Game Modding as Customer Value Co-Creation," *Sustainability* 12(21), https://api.openalex.org/works/https://doi.org/10.3390/su12219014?select=title,abstract_inverted_index: players are driven by "enjoyment" and "social affiliation" while creators are mainly motivated by "enjoyment of creation, pride, creativity, epistemic curiosity."
- Gajda, A. et al. (2020) "Players as Prosumers," *CEBR* 20(3), https://api.openalex.org/works/https://doi.org/10.18267/j.cebr.261?select=title,abstract_inverted_index: modding yields benefits for "mod users (game diversification, better customisation, higher quality games, more realism in game, fun, excitement...), modders/creators (creativity, gaining knowledge about how to create games, social affiliation, pride, career development)."
- Fuller, S. J. (2018) "Modding the Apocalypse," Clemson University dissertation, https://tigerprints.clemson.edu/all_dissertations/2219: mods are "an increasingly common form of participatory engagement that make use of a broad digital skillset" but face "numerous obstacles" in sharing and teaching.
- Elgün, A. (2026) "Game Production through the Lens of Craft," Aalto University master's thesis, https://aaltodoc.aalto.fi/handle/123456789/146013: games made with different engines "are connected to distinct patterns of categorisation," suggesting toolchains leave traces in final content.

## Contradictions

- NWN override behaviour: CEP 2 claims core CEP content "does not override default Neverwinter Nights content" whereas CEP 3 says core content "does override some default Neverwinter Nights content." Sources: https://nwn.wiki (CEP 2 context) and https://www.neverwintervault.org/project/nwnee/hakpak/combined/cep-3-community-expansion-pack.
- Godot retargeting: docs say mapping problems "do not block the import process" while maintainer TokageItLab says the corruption "relies on the scale and orientation of the parent of the model being imported being broken." Sources: https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/retargeting_3d_skeletons.html and https://github.com/godotengine/godot/issues/63641.
- Blender bone direction: scurest argues estimation (`Temperance`) is the better default because raw glTF bones can be unusable, while TokageItLab argues estimation silently destroys original bone data and should not be the default. Source: https://github.com/KhronosGroup/glTF-Blender-IO/issues/1662.
- Mod ordering policy: Owlcat says dependency lists are only "hints" because users can reorder mods, whereas NWN delegates the same problem to an explicit conflict checker/control pack. Sources: https://github.com/OwlcatOpenSource/WrathModificationTemplate and https://nwn.wiki/spaces/NWN1/pages/60981970/Introduction+to+Hakpacks.

## Not applicable

- Solasta's official Dungeon Maker cannot import custom monsters/items on its own (official modders do that work).
- A new NWN weapon model is not recognized unless both the 3D model and 2D icon ship together.
- Godot's humanoid retarget expects T-pose, +Z facing, no node Transform; rigs from Maya often lack bone rest rotations.
- Default Unity shaders do not work in Pathfinder: WotR; materials must use Owlcat shaders.
- BG3's custom-creature workflow requires three VT texture maps per mesh part, with PM black-in-all-channels rendering the mesh black in game.
- Our MVP outruns NWN's 2 GB hak and 65,536-row 2da limits only if we keep IDs short and hashed packs small, but the 16-char limit stays.
